## 一、要解决的问题

headed 缺省模式下，页面右上角有一枚「LAEW Agent 控制中」徽标，左下角有一块静态状态条。
两者都只回答了一半的问题：

| 现状 | 缺陷 |
| ---- | ---- |
| 右上角徽标：固定文案「LAEW Agent 控制中」 | 看不出**是哪个 Agent**（Yolo / Plan / Main-Work / SubAgent-Work / 动态子 Agent 全一样）。多窗口并行（「天猫一窗 + 京东一窗」）时人工无法判断归属 |
| 左下角状态条：三档固定文案 + 注意事项 + `guard_note` | **全是静态文字**，看不到正在干什么、第几轮迭代、任务目标、刚发生过什么 |
| 两者分属两套脚本、两套 shadow host | 语义割裂且都叫「状态条」，排障/文档易混淆 |

## 二、改造后的两条栏

### 2.1 屏蔽页面状态栏（右上角）

**回答**：谁在控制 / 控制成什么样 / 我该怎么配合。四行固定结构：

| 行 | 内容 | 来源 |
| -- | ---- | ---- |
| ① | `🔵 LAEW Agent 控制中 · LsmAgentEmergentWork-SubAgent-Work` | `AgentProfile.name`（经 `web_activity` 台账） |
| ② | `🔒 页面已锁定(仅观看·可滚动)` / `🔓 页面开放 · 人工可直接操作` / `🛡 部分锁定 · 盾区不可操作` | `PageGuardMode` + `LAEW_WEB_LOCKED_SCROLL` |
| ③ | 静态注意事项（如「人工可滚动浏览；点击/键盘/选中已拦截，如需操作请应答『人工介入』弹窗」） | **由原左下角状态条整体迁入**（`browser_status::guard_text`） |

## 三、实现要点

### 3.1 为什么独立于 guard 脚本

`browser_overlay.rs` 的管控脚本有**版本化重装**机制（`%NS%GuardRev` + `%NS%GuardOff`：
高版本先卸载旧实例的监听器/调度/观察器/视觉元素再重装）。两条告知栏必须**跨重装存活**
——重装发生在每个导航/重复 open 之后，闪一下就被拆掉等于信息丢失。故独立注入、独立
生命周期（`ensure` 幂等，`ensure()` 内按 host id 复用）。

行数约束也是原因之一：`browser_overlay.rs` 已接近 1800 行上限（见 `AGENTS.md` 约定）。

### 3.2 活动台账（`web_activity.rs`）

状态栏要显示「哪个 Agent、第几轮、在调什么工具」，这些信息只在 Agent 循环里有。

载体用 `tokio::task_local`（与 `dynamic_subagent::scope`、`mcp_web_use::IN_SEQUENCE` 同款）：
工具执行发生在 Agent 自己的任务树内，task_local 随 `.await` 传递，**并行 SubAgent 各自
读到自己的快照**。若改用全局 `Mutex`，并发子 Agent 会互相覆盖，A 窗口显示 B 子 Agent
的名字，人工据此做的判断全错。

埋点：

| 位置 | 调用 |
| ---- | ---- |
| `agent_loop.rs::run_session_inner` | `begin(profile.name, session.id(), 任务摘要, max_iterations)` + `scope` |
| `for iter in 0..max_iterations` 起始 | `set_iter(iter+1, "第 N/M 轮 · 模型思考")` |
| `tool_exec.rs::exec_tool_call` | `set_tool("<工具名> <参数摘要>")` |
| `mcp_web_use::execute` | `broadcast_start(动作标签)` / `broadcast_done(标签, ok, 耗时)` |

任务摘要取 Session 上下文**第一条非注入块** user 消息（跳过 `<<<LAEW:PROJECT_CONTEXT>>>` /
`<<<LAEW:ATTACHMENTS>>>` / `<<<LAEW:WORKSPACE>>>` / `<<<LAEW:SESSION_HISTORY>>>`），
否则进度栏第一行显示的是工程说明而不是任务。

### 3.3 页面侧 API

全部 ns 随机化 + `Object.defineProperty` 不可枚举（与 guard/highlight 同款，`browser_ns.rs`）：

| API | 作用 |
| --- | ---- |
| `window.{ns}StatusUpdate(payload)` | 全量刷新（Agent / 迭代 / 任务 / 动作 / 档位 / 事件条目） |
| `window.{ns}StatusGuard(mode, notice, note)` | 仅刷新档位段 |
| `window.{ns}StatusVisible(v)` | 显隐（`set_highlight(false)` 联动） |
| `window.{ns}StatusSuspend(v)` | 截图/OCR 取证避让（与 `guard_suspend_visuals` 同步） |
| `window.{ns}StatusProbe()` | 影子树自探（真浏览器回归测试读在场性/显示态） |

耗时行由页面侧 `setInterval(500ms)` 自刷新，Rust 不为「秒数跳动」反复推送。

## 四、设计约束（不可回退）

1. **closed Shadow DOM**：两条栏文本若留在 light DOM，页面一行
   `document.body.innerText` 即可枚举到「LAEW Agent」品牌签名（实测京东风控 JS 据此把
   设备判为自动化，返回「当前页面异常」）。`attachShadow` 不可用时 fail-open 回退 light DOM
   （只损隐身，不损功能）。
2. **只在顶层 frame 渲染（2026-10-14，REV 2）**：`addScriptToEvaluateOnNewDocument` 会注入
   **每个新文档**（含跨域 iframe）——天猫 baxia 滑块挑战 iframe（~390px 宽）内也长出一条
   `max-width:min(50vw,620px)` 的状态栏，把挑战控件右上角罩死，人工核验窗口被屏蔽、滑块
   没法操作（实测 `llaew_20261014_122337.log` 13:09 起，两次 HITL 均无法完成）。状态栏与
   进度栏一律 `window.top === window` 门控，子 frame 零渲染。
3. **HITL 人工核验期间整体挂起（2026-10-14）**：`request_human(unlock_page=true)` 解锁
   页面让人工操作期间，两条栏 `set_suspended(true)`（挂起点 `hitl_ctl::apply_hitl_unlock`
   + 导航重放协程 `spawn_unlock_reassert`；收口恢复 / 弹窗「恢复屏蔽」/ 侵入式中继
   `session_end` 三处 `set_suspended(false)` 复显）。人工核验期间页面里不该有任何 Agent
   视觉元素叠在挑战层上，「页面已解锁」等信息由原生 HITL 弹窗承担（弹窗自带解锁状态行）。
   已知取舍：截图取证的「拍完恢复」若恰逢 HITL 等待中（同页并行截图，罕见），后写者胜出。
4. **`pointer-events:none`**：两条栏纯告知，绝不参与 hit-test；不得遮挡 partial 盾区点击。
5. **长文本截断**：`max-width` + `text-overflow:ellipsis` + `title` 悬浮全量，进度栏
   不允许把页面布局撑破。
6. **导航不丢**：`addScriptToEvaluateOnNewDocument` 保证新文档自动重挂，`apply_page_guard`
   收口时重推内容（导航后新文档内容为空）。
7. **connect 模式零注入**：两条栏只在 headed 非 connect 注入，接管用户已登录浏览器时不碰。
8. **开销**：每次 `MCP_Web_Chrome_Use` 动作多 2 次 `Runtime.evaluate`（毫秒级），无浏览器实例时
   立即返回；`sequence`/`batch` 按批推 2 次，不逐步推。
