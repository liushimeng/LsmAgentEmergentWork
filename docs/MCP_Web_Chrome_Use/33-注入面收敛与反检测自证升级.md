# 注入面收敛与反检测自证升级（第 179 轮）

> 2026-10-17 · 承接 [32-反检测自证判据真机复核与首文档盲区根治](./32-反检测自证判据真机复核与首文档盲区根治.md)
> §六「注入面收敛（下一轮执行）」与 §九.1。
>
> **本轮主线**：把注入层留在页面上的**最大一处自有签名**（`window` 上 30 个
> `__lznXXXXXXXX*` 字符串键）收敛成 **1 个符号键**；同时把 DOM 面的 token 与
> 窗口面解耦，并把「收敛是否生效」做成运行时自证项。两档（非侵入式 `fidelity` /
> 侵入式 `hardened`）共同受益，档位语义与既有边界不变。

## 一、问题：30 个字符串键是我们最独有的一处签名

第 178 轮真机四档复核（`docs/MCP_Web_Chrome_Use/32` §2.3）测到：

| 配置 | `__lznXXXXXXXX*` 字符串键 | `getOwnPropertyNames(window)` 总数 |
| ---- | ------------------------ | ---------------------------------- |
| headed（缺省档） | **30** | 1264 |
| hidden（缺省档） | **1** | 1239 |
| hidden（裸环境，无注入） | 0 | 1238 |

`webdriver`、WebGL 兜底串这些痕迹「别人也有」，而**同前缀 30 键只有我们有**。
站点风控只要一行：

```js
Object.getOwnPropertyNames(window).filter((n) => /^__lzn/.test(n))
```

就能拿到一个高置信度的自动化框架签名。第 168 轮的「不可枚举化」只压掉了
`Object.keys` / `for…in`，**`getOwnPropertyNames` 仍然全见**。

同时还有第二处可关联痕迹：DOM 层的 element id / class / `data-*` 属性同样以
`__lznXXXXXXXX` 开头。即便窗口面收敛了，只要 DOM 面复用同一个 token，
「枚举 id」与「读符号描述」仍能串成同一个签名。

## 二、方案

### 2.1 窗口面：单一符号命名空间对象

所有注入 API 从 `window.<ns>Foo` 迁移到**一个对象**上：

```js
// 每个注入脚本闭包顶部（局部 const，不落 window）
const NS = window[Symbol.for('<ns>')] || (window[Symbol.for('<ns>')] = {});
```

- `getOwnPropertyNames(window)` / `Object.keys(window)` / `for…in`：**0 个字符串键**；
- `getOwnPropertySymbols(window)`：**1 个符号键**（原生基线 0）；
- 命名空间对象内部的键（`GuardMode` / `StatusUpdate` / `StealthRev` …）在脚本末尾
  统一改写成 `enumerable: false` —— 即使有人枚举符号值，`Object.keys(NS)` 也读不到
  注入面清单。

`Symbol.for` 走全局符号注册表，同一文档内四套脚本（guard / status / highlight /
stealth / 可见文本读取）拿到的是**同一个 symbol**，因此符号键恒为 1。

### 2.2 渲染期三步改写（唯一收口 `browser_ns::render_ns`）

模板仍写 `%NS%` 占位符，渲染时：

1. `%NS%` → 窗口面命名空间字符串（`__lzn` + 8 hex）；
2. `window.<ns><Suffix>` → `NS.<Suffix>`（**后缀白名单**，按长度降序匹配，
   防止 `GuardSuspend` 抢 `GuardSuspended`、`agent` 抢 `agent_frame__`）；
3. `<ns><DomSuffix>` → `<dom_ns><DomSuffix>`（DOM 面第二 token）。

白名单是**必须维护**的：新增窗口面 API 若忘了登记，它会退回字符串键形态；
单测 `渲染后窗口面零字符串键且DOM面独立` 与真机冒烟会同时拦住。

Rust 侧拼 eval 表达式统一走 `browser_ns::ns_member_expr("GuardSet")`：

```js
(window[Symbol.for('<ns>')]||{}).GuardSet
```

对象不存在时读到 `undefined`（与旧 `window.<ns>GuardSet` 同语义），不抛错。

### 2.3 DOM 面：独立的第二随机 token

`dom_ns()` 是另一个进程级随机串，形如 `d72729408`（字母开头，可作 CSS
选择器），**不带 `__lzn` 前缀**。element id / class / `data-*` 属性全部改用它：

- `d…guard_ui__`、`d…overlay__`、`d…status_host__` …
- `data-d…agent`
- `d…locked__`

窗口符号描述与 DOM id 之间不再有任何可关联的字符串。

### 2.4 非侵入式 / 侵入式两档的增强

| 档 | 本轮增强 |
| -- | -------- |
| `fidelity`（非侵入式） | 注入面收敛、DOM token 解耦、内部键不可枚举 —— 以上都只是**减少我们自己的痕迹**，不伪造任何身份信息，完全符合「只移除自动化泄漏 + 回填本机真值」的语义 |
| `hardened`（侵入式） | 同上；被改写函数的 `Function.prototype.toString` 原生化与跨档重新认领逻辑不变。命名空间对象让「改过」的入口不再以 30 个字符串键的形式暴露，**可枚举面与可反查面同时收缩** |

档位语义、级联（`open(stealth=…)` > `LAEW_WEB_STEALTH` > 缺省 `hardened`）与
connect 模式零注入契约**均未改变**。

### 2.5 自证升级（`fingerprint.rs`）

新增/加强四项，让「收敛是否真的生效」在运行时可见：

| 字段 / 告警码 | 含义 |
| ------------- | ---- |
| `injected_ns_keys` | 现有自证项，**现在应恒为 0**（收敛前有头档 30） |
| `injected_ns_symbols` | window 自有符号键数，**应为 1**（裸环境 0） |
| `ns_symbol_present` | 存在一个符号键，其值的 `StealthRev` 是数字 —— 正向确认命名空间对象在场 |
| `injected_ns_string_keys`（告警） | `injected_ns_keys > 0` 时命中：渲染链路倒退，附「走 `render_ns` / 登记 `NS_WINDOW_SUFFIXES`」的修法 |
| `outer_equals_inner`（软告警） | `window.outer === inner` 是无头档窗口几何特征（真实有头窗口有标题栏/工具栏）；全屏窗口同样命中，故只作 `warn`，不升 `high` |
| `patched_fn_leak` 扩展 | 补上 `languages` / `pdfViewerEnabled` getter 与 `Function.prototype.toString` 自身，漏检面收全 |

`data.fingerprint.note` 同步改写：字符串键应为 0、符号键应为 1、
`ns_symbol_present` 应为 true；`data.stealth.note` 追加注入面对账说明。

## 五、边界（防回退）

- **不伪造身份信息**：本轮只减少我们自己的可枚举痕迹，没有新增任何回填值；
  回填仍只在兜底值/空值时触发。
- **不改档位语义**：`LAEW_WEB_STEALTH` / `LAEW_WEB_FINGERPRINT` 的既有语义不变；
  connect 模式零注入契约不变。
- **不做 Worker 构造拦截 / `Runtime.enable` 处置 / Canvas 字体伪造 / 代理池 /
  打码 / 协议逆向**（理由见 26 §三、32 §五）。
- **窗口面新增 API 必须登记 `NS_WINDOW_SUFFIXES`**，否则会退回字符串键形态；
  单测与真机冒烟是这条纪律的守门人。
- `Symbol.for('<ns>')` 描述本身仍是可枚举符号（`getOwnPropertySymbols` 可见 1 个）。
  这是**保留 Rust↔页面通信入口**的物理下限：页面侧无法凭空访问一个不落在任何
  可枚举容器里的对象。相对 30 个具名字符串键，符号键不参与任何常规枚举，
  且其内部键已不可枚举。

## 六、遗留与下一步

1. **派生页（`target=_blank` / `window.open` / `new_tab`）的首请求仍可能裸跑**
   （同 32 §九.2）：新 target 由浏览器自己创建，脚本只能在收编后注册。任务关键
   站点优先 `open` 直开目标页。
2. **`automation_globals` 前缀表仍是启发式白名单**（同 31 §九.4）。
3. **`outer_equals_inner` 只作软提示**：全屏的真实窗口同样命中，若将来要升级为
   硬判据，需要先设计出能区分「无头 / 全屏」的判据。
4. 多窗口并行与 open/control/inspect 长链路的既有挂死问题（32 §九.5）与本轮无关，
   仍待单独排查。
