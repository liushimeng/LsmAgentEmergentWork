## 二、四个缺口（代码级证据 + 真机形态判据）

### 缺口 1：Notification/permissions 一致性**覆盖不全** + 语义映射缺失

**现状**（`browser_ns.rs::FIDELITY_JS` ⑤）：

```js
if (... && Notification.permission === 'denied') {
    // 只在 denied 时触发
    if (p && p.name === 'notifications' && st && st.state !== Notification.permission) {
        // 把 st.state 改写成 Notification.permission
    }
}
```

**两个缺口**：

1. **覆盖不全**：只在 `Notification.permission === 'denied'` 时触发。无头环境的
   `Notification.permission === 'granted'` 而 `permissions.query` 返回 `denied`
   （或反过来的不一致）不处理。
2. **语义映射缺失**：`Notification.permission` 的取值是 `default`/`denied`/`granted`，
   而 `permissions.query({name:'notifications'})` 返回的 `state` 是 `prompt`/`denied`/`granted`。
   **`default` 与 `prompt` 语义一致**（都表示「未决定」）。若简单用 `!==` 比较，
   `default` vs `prompt` 会被误判为「不一致」并触发改写，把 `prompt` 改写成 `default`
   —— **反而制造不一致**（真实 Chrome 这两个读数本就自洽）。

**真机形态判据**：真实 Chrome 中两者始终满足映射
`granted↔granted`、`denied↔denied`、`default↔prompt`。任何偏离都是自动化环境的读数。

**修法**：覆盖全部三种 `Notification.permission` 值，用**精确映射**判定不一致：

```
Notification.permission === 'granted' → query state 应为 'granted'
Notification.permission === 'denied'  → query state 应为 'denied'
Notification.permission === 'default' → query state 应为 'prompt'
```

只在**偏离映射**时改写 `st.state`（以 `Notification.permission` 为准，零伪造）。

### 缺口 2：`navigator.languages` 回填的 `Object.freeze` 形态破绽

**现状**（`browser_ns.rs::FIDELITY_JS` ③）：

```js
Object.defineProperty(Navigator.prototype, 'languages', {
    get: reg(function () { return Object.freeze(list); }, 'get languages'),
    ...
});
```

**缺口**：原生 WebIDL `readonly attribute sequence<DOMString>` 返回的数组**不是 frozen** 的
（实测真实 Chrome `Object.isFrozen(navigator.languages) === false`，数组可写）。
我们 freeze 了它 → 严格模式下 `navigator.languages.push(x)` 抛 `TypeError`
（非严格模式静默失败），而真实 Chrome 不抛。这是一条**零成本形态判据**：
风控若做 `try { navigator.languages.push(null) } catch(e) {}` 即可分辨。

**修法**：去掉 `Object.freeze`，返回普通数组（与原生同形）。

### 缺口 3：迭代器**自反性**缺失

**现状**（`browser_ns.rs::FIDELITY_JS` ② `makeArrayLike`）：

```js
Object.defineProperty(proto, Symbol.iterator, {
    value: reg(function () {
        let i = 0;
        return { next: () => i < items.length ? { value: items[i++], done: false }
                                          : { value: undefined, done: true } };
    }, '[Symbol.iterator]'),
    ...
});
```

**缺口**：原生 `Array.prototype[Symbol.iterator]()` 返回的迭代器**本身也是 iterable 的**
（`iterator[Symbol.iterator]()` 返回自身，这是 ECMAScript 规范对 Iterator 的要求）。
我们返回的 `{ next: ... }` 裸对象**没有 `Symbol.iterator` 方法** →
`Array.from(navigator.plugins)` 能用（靠 `Symbol.iterator`），但若风控做
`const it = plugins[Symbol.iterator](); it[Symbol.iterator]` 检测会中招
（原生返回函数，我们返回 `undefined`）。

**修法**：给迭代器补 `Symbol.iterator` 方法，返回自身（自反闭合，与原生同形）。

### 缺口 4：fingerprint 自证项**缺口**（体检层看不见上述三个缺口）

**现状**（`fingerprint.rs`）：PROBE_JS 采 `plugins`/`languages` 的**长度**，
但不采**形态**。三个缺口在 `data.fingerprint` 里**不可见**——只有真机实测或风控打标后
才发现，违背「被拦时第一时间可见」的设计意图。

**修法**：PROBE_JS 新增两个**同步可采**的形态自证项（避免引入异步探针复杂度）：

| 自证项 | 采集 | 判据 |
|--------|------|------|
| `languages_frozen` | `Object.isFrozen(navigator.languages)` | 原生恒 `false`；`true` 说明我们 freeze 了（缺口 2 残留） |
| `iterator_self_iterable` | `typeof navigator.plugins[Symbol.iterator]()[Symbol.iterator]` | 原生恒 `'function'`；非函数说明迭代器不自反（缺口 3 残留） |

classify 新增两条告警码：`languages_frozen` / `iterator_not_self_iterable`，
命中即说明对应根治逻辑失效。build 回报新字段。

> **Notification 一致性自证**：`permissions.query` 返回 Promise，同步 `JSON.stringify`
> 采不到。为避免引入异步探针，体检层**不新增**该自证项；缺口 1 的正确性由**单测锁死**
> （断言注入脚本含精确映射），运行时可见性由现有 `notification_permission` 字段 +
> `notification_denied` 告警保留。
