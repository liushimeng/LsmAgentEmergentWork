## 一、问题：CDP 附着的可检测面

`MCP_Web_Chrome_Use` 通过 CDP 驱动 Chrome。CDP 附着本身会在**页面侧**留下若干可被 JS 读到的痕迹；
站点风控（aplus / um / jdfacter / baxia / 瑞数系）采这些痕迹加权评分，命中高风险即转入反爬分支
（空 HTML / 风控壳页 / 原地 reload / 整页抹除）。实测清单：

| # | 痕迹 | 真实 Chrome | CDP 拉起环境 | 现状 |
|---|------|-------------|--------------|------|
| 1 | `navigator.webdriver` | `false` | `true`（`--enable-automation` / AutomationControlled） | 已压（`browser_ns::CORE_JS`） |
| 2 | WebGL vendor/renderer | `Google Inc. (Apple) / ANGLE (…)` | `WebKit / WebKit WebGL`（自动化兜底串） | 已回填（第 172 轮） |
| 3 | `navigator.plugins.length` | 5（PDF 查看器族） | `0`（无头/受限环境） | **本轮补** |
| 4 | `navigator.languages` | `['zh-CN','zh','en']` | 空 | **本轮补** |
| 5 | `window.chrome.runtime` | 恒有 | 可能缺失 | **本轮补** |
| 6 | `Notification.permission` vs `permissions.query` | 两者一致 | 已知不一致组合（经典无头检测） | **本轮补** |
| 7 | `navigator.userAgent` | `…Chrome/155…` | `…**HeadlessChrome**/155…`（无头档） | **本轮补** |
| 8 | 注入层全局名 / 属性名 | — | 固定 `__laew*` 一行枚举即命中 | 已隐身（第 168 轮，进程级随机命名空间 + 不可枚举化） |

| 15 | `screen.colorDepth` ≠ `screen.pixelDepth` | 恒等 | 视口覆盖改坏一侧 | **第 181 轮体检**（只观测） |
| 16 | `screen.orientation` 缺失 | 恒有 | 无头档可能不暴露 | **第 181 轮体检**（只观测） |

| 19 | `getOwnPropertyDescriptor(navigator,'webdriver')` 非空 | 恒 undefined（只在原型上） | `defineProperty` 落到实例 | **第 181 轮体检**（我们的形态破绽） |

## 二、两档定义：非侵入式（保真）/ 侵入式（原生化）

### 术语澄清

本工程「非侵入式 / 侵入式」有**两处正交用法**，共同判据是同一个 —— **改动离「本机真实浏览器」有多远**：

- **HITL 输入路径**（第 168 轮，`request_human` 弹窗「🎮 侵入式」互切）：
  非侵入式 = 解除屏蔽，让真人在真浏览器里直接操作（页面拿到的是 OS 级真实输入）；
  侵入式 = 弹窗内触控板中继，人工操作经 CDP `Input.dispatch*` 合成回页面（`isTrusted=true`，
  但不依赖浏览器焦点、坐标级穿透跨域 iframe）。
- **反检测档位**（本文）：见下表。

### 档位表（唯一真源 `src/agent/stealth.rs::StealthMode`）

| 档 | 名称 | 语义 | 做什么 |
|----|------|------|--------|
| `off` | 关闭 | 不做任何环境处置 | 不注入任何脚本（回退到第 169 轮之前的裸环境） |
| `fidelity` | **非侵入式**（缺省） | **只移除自动化泄漏 + 回填本机真值** | 表 1/2/3/4/5/6/7/10 —— 全部是「真实浏览器本该有的值」被还原 |
| `hardened` | **侵入式** | 在保真之上，让「我们改过」本身不可被反查 | 保真档全部 + 表 9（`Function.prototype.toString` 原生化） |

**分界线**：非侵入式档只回答"这个环境表面上像不像本机的真 Chrome"；
侵入式档额外回答"**它是不是被动过手脚**"。

**唯一不动摇的边界**（两档共同）：所有回填**只在页面读到自动化兜底值/空值时生效**，
从不覆盖真实值，不伪造任何本机没有的身份信息（不换 UA 品牌、不加 Canvas 噪声、
不改硬件参数）。这是「环境保真」而非「身份伪造」。

### 级联与环境变量

```
open(stealth=…)  >  LAEW_WEB_STEALTH  >  fidelity（缺省）
```
`LAEW_WEB_STEALTH` 接受 `off` / `fidelity` / `hardened` 及别名（`非侵入式` / `侵入式` / `保真`
/ `原生化` / `compatible` / `intrusive` …）。legacy 杀开关 `LAEW_WEB_FINGERPRINT=off`
保留原语义：**只关掉保真档的回填与体检**（`webdriver` 核心覆写仍在）。

## 三、五层技术栈评估（做什么 / 不做什么）

补充要求给出的五层方案，逐层对表：

| 层 | 通行做法 | laew 处置 | 依据 |
|----|----------|-----------|------|
| **1. 前端环境反检测** | stealth 插件：抹 webdriver、模拟插件列表 / WebGL / 字体 / 时区 | **做，但只做「移除泄漏 + 回填真值」**（表 1–8、10），侵入式档加函数身份原生化（表 9） | 泄漏是真的，回填值取自页面自身的真实读数（零伪造）。**不做** Canvas 噪声 / 字体枚举伪造 / UA 品牌改写 —— 那些是主动欺骗检测方，且会在"读数一致性"上引入新破绽 |
| **2. 行为仿真与频率控制** | 随机鼠标轨迹、滚动缓动、1–3s 随机延时 | **导航节奏侧已做**（`browser_pace`：同域最小间隔 2.5s / 频控冷却 6004 / 抹除熔断）；**指针轨迹仿真不做** | 实测反证：BOSS 直聘与猎聘的抹除发生在**静置零动作**期间（30s 无任何交互仍被抹）——行为仿真对本类风控零效果。做了只会让人误以为有效 |
| **3. IP 代理池与轮换** | 住宅代理池 + 动态轮换 + 节点健康剔除 | **不做** | 属规模化绕过 IP 封锁的基础设施；且与本工程「单用户桌面 Agent」定位不符。**实测反证其必要性**：猎聘当日连用户日常 Chrome（真实 IP、真实指纹、无 CDP）也被清成空白，换 IP 不是本场景的杠杆 |
| **4. 会话与验证码处理** | 第三方打码服务 / 稳定会话保活 | **会话侧已做**（`reuse_existing` 接管已登录浏览器、登录态复制、`request_human` 人工介入含侵入式触控板中继）；**打码平台不接入** | 打码服务即规模化绕过人机验证，与"人工介入交还给真人"的设计定位直接冲突 |
| **5. 协议逆向** | 逆向签名 / 加密 token，直调后端接口 | **不做** | 会摧毁本工程的证据根基：QC 对账、`target_anchor` 6001 锚点门、网页取证纪律、`visit_ledger` 遍历台账全部以「浏览器轨迹 = 证据」为前提。绕开页面采集等于让自己无法自证做没做 |

**通用结论**：对多维风控，「绕过」路线（3/4/5）不可持续且越界；
可持续路线是 1/2 层的「**不泄漏自动化特征 + 像人一样低频工作 + 被拦时如实上报并交还人工**」。
本轮把 1 层从"做了但没做全"补到"做完且能自证"，其余各层的取舍写在这里，避免后续反复讨论。

## 四、实现

### 4.1 模式唯一真源 `src/agent/stealth.rs`（新增）

- `StealthMode { Off, Fidelity, Hardened }` + `as_str` / `from_str_loose`（中英文别名）/
  `from_env`（`LAEW_WEB_STEALTH`）/ `mode()`（进程级单例）；
- `fidelity_enabled()`（保真块）/ `hardened_enabled()`（原生化块）/ `fingerprint_kill_switch()`
  （legacy 杀开关）。**指纹体检（`data.fingerprint`）只受杀开关约束、不受档位约束** ——
  它是一次**被动观测**（不改页面），在 `off` 对照档里保留它正好提供了"我们到底改了什么"的
  证据面；
- `status_json(effective)` → 响应 `data.stealth{mode,env_default,fidelity,hardened,kill_switch}`
  （人工/QC 对账）。**UA 是否仍带令牌以 `data.fingerprint.ua_headless` 为准** —— 那是页面
  实测事实，比工具自报更可信；
- UA 清理的纯函数部分：`UA_PROBE_JS`（异步取高熵值）+ `ua_plan()`（**只滤掉品牌里的
  `Headless*` 令牌，其余字段原样取页面自报值**）+ 单测。

### 4.2 `browser_ns.rs`：单块脚本 → 三块按档组合

```
CORE_JS      webdriver 覆写                     （off 之外恒注入）
FIDELITY_JS  描述符形态还原 + WebGL 保真回填
             + plugins/languages/chrome.runtime 空值回填
             + permissions 一致性                （fidelity / hardened）
HARDENED_JS  Function.prototype.toString 原生化
             （含自反：toString.toString 亦报 native） （hardened）
```
`stealth_js()` 按 `stealth::mode()` 组合后经 `render_ns()` 渲染；`inject_stealth(page, mode)` 接管。

**描述符形态还原**（表 10）：`defineProperty` 打补丁时显式补 `enumerable: true`，
与 WebIDL 操作的原生描述符一致（否则 `for…in` 枚举原型链即可发现"这个函数被改过"）。

**`Function.prototype.toString` 原生化**（表 9，侵入式档）：建 `WeakMap<fn, 源串>` 登记
所有被我们替换过的函数（`get webdriver` / `getParameter` / `query` / `toString` 自身），
`toString` 命中登记表即返回 `function <name>() { [native code] }`；`toString` 自身也在表内，
故 `Function.prototype.toString.call(Function.prototype.toString)` 同样报 native（自反闭合）。

### 4.3 `browser.rs`：无头档 UA 清理（表 7）

`HeadlessChrome/155…` 出现在 **UA 字符串 + 网络请求头 + `Sec-CH-UA` 品牌列表**三处，
必须一起改，否则"UA 说 Chrome、Client Hints 说 Headless"是更显眼的新破绽。故用
CDP `Emulation.setUserAgentOverride`（唯一能同时改到网络头的通道，JS 侧改 `navigator.userAgent`
只骗得过页面、骗不过服务器）。取值全部来自页面自身的 `userAgentData.getHighEntropyValues`，
只把品牌列表里的 `HeadlessChrome` 项滤掉 —— **零伪造**。调用点在首航 `goto` 之前
（否则第一个文档的请求头仍带令牌）。

**实测（Chrome 155 / macOS 27，`stealth_headless_ua_destealth_smoke`）**：新无头档的品牌表
本就不含 `HeadlessChrome`（报的是正常 `Google Chrome`/`Chromium`/`Not(A:Brand`），
**令牌只在 UA 字符串里** —— 故品牌过滤是防御性分支，元数据仍按页面自报值原样下发，
保证 UA 串与 Client Hints 继续自洽。两个坑已写进代码注释：① `JSON.stringify` 必须写在
`async` 函数**体内**（写在外面会把 Promise 本身序列化成 `{}`，CDP `await_promise` 无从解包）；
② `navigator.userAgentData` 只在**安全上下文**暴露 —— `data:` URL 上取不到（冒烟因此改走
`http://127.0.0.1` 起服务，见 `spawn_html_server`）。

**残留（如实记录，不夸大）**：页面由 `Target.createTarget(url)` 创建时**已经发出第一个
请求**，覆盖只能赶在随后的主 `goto` 之前下发 —— 因此**极少数情况下第一个请求仍带令牌**，
本次导航之后的全部流量都已干净。要连第一个请求都干净需要 `--user-agent` 启动参数，
但那会重新制造「UA 串改了、Client Hints 没改」的不一致，得不偿失，故不做
（有头档本无此令牌，无头档默认只在无 GUI 会话出现）。

### 4.4 `fingerprint.rs`：体检项补齐

探针新增 `ua_headless` / `webgl_parameter_enumerable` / `patched_functions_native`，
`classify` 相应新增 `headless_ua` / `webgl_descriptor_tampered` / `patched_functions_visible` 三条
（后者仅在**侵入式档**下期望为 native，非侵入式档命中属预期，给的是"可升档"建议而非故障）。
`data.fingerprint.stealth_mode` 回报生效档位。

### 4.5 工具面

- `open(stealth?="fidelity"|"hardened"|"off")`：显式覆盖本会话档位（写入 `BrowserInner.stealth`，
  与 `highlight` 同构；页面创建/复用/自愈/派生四条路径共用）；
- `control(set_stealth, mode=…)`：运行时切档，对全部存活页面重挂脚本；
  **诚实语义**：升档即时生效；降档只能阻止**新文档**注入，已在旧文档执行的覆写无法回退
  （响应附 `note` 说明，不假装已还原）。

## 五、验证

1. 单测：`stealth`（档位解析 / 别名 / 级联 / UA 计划只滤品牌）、`browser_ns`（三块组合与
   关键覆写存在性 / 描述符 enumerable / toString 自反 / 幂等闸）、`fingerprint`
   （新码命中与缺测 fail-open）；
2. **注入 JS 外部行为验证**（`node` + DOM 桩，非仓库产物）：两档脚本各 21 项断言 ——
   webdriver=false、plugins=5、languages 非空、chrome.runtime 在场、WebGL 回填且低熵串不动、
   描述符 `enumerable=true`、侵入式档 `getParameter.toString()` / `toString.toString()` /
   webdriver getter 均报 `[native code]` 而未登记函数原样返回、同档重复注入零叠加；
3. 真浏览器冒烟（`#[ignore]`，需本机 Chrome）：
   - `stealth_selfcheck_smoke` 扩展 ⑥–⑬：保真档字段在场 / WebGL 非兜底串 / 描述符形态 /
     `data.stealth` 与 `data.fingerprint` 对账 / **保真档不得伪装函数身份** / 升侵入式档
     原生化生效（含自反） / 非法档位拒绝 / 切回缺省档；
   - `stealth_headless_ua_destealth_smoke`：无头档 UA 与 `Sec-CH-UA` 双双无令牌（走 loopback
     安全上下文，`data:` URL 取不到 Client Hints）；
4. 文档一致性单测（提示词无轮次标注）+ `cargo test` 全量；
5. `./rebuild_restart_app.sh` 重建二进制。

**已修的既有缺陷**（本轮实测发现，属第 172 轮引入）：原 WebGL 回填把低熵
`VENDOR`/`RENDERER`（7936/7937）也一并改写，而真实 Chrome 这两项**恒报** `WebKit` /
`WebKit WebGL` —— 改写它们反而制造了"自动化环境"以外的第二个不一致信号。现只覆写
`UNMASKED_*`（37445/37446），并有单测禁止代码分支里再出现 7936/7937。

## 六、不改动的部分（防回退）

- 不碰验证码/风控判定逻辑本身，不实现打码、代理池、协议逆向（见 §三）；
- 不覆盖页面读到的**真实值**（回填只在兜底值/空值时触发）；
- `LAEW_WEB_FINGERPRINT=off` 的既有语义不变；
- connect 模式（接管用户浏览器）**零注入契约不变** —— 真实浏览器本无这些痕迹。
