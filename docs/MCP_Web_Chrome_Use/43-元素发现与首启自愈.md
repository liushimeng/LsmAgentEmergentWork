# 43 - 元素发现与首启自愈(2026-10-23)

> 实测驱动:百度地图公交路线规划任务(Chrome 侧)。本轮不是站点适配,而是
> 把「模型找不到可点/可输入元素」「首启标签页瞬态失效」「工具谎报点击成功」
> 三类通用缺陷在工具层根治。总体设计见 `docs/双浏览器工具架构/01-设计与解决方案.md`。

## 一、实测问题与证据

| 现象 | 证据 | 结论 |
|------|------|------|
| `click_text("路线")` / `("公交")` 误命中搜索框 | 返回 `{hit:true, tag:"INPUT", id:"sole-input", text:"", score:105}` | input 的 placeholder「搜地点、查公交、找路线」被当成按钮标签 |
| 点击「路线」没反应 | 页面唯一文本「路线」节点是 `#tooltip-route`(body 直系子节点),点击后无路线面板 | tooltip 标签本身没有点击动作 |
| 模型猜 `#route-inputstart` | `type` 返回 `{hit:false}`,无任何候选 | 真实节点是 `input.route-start-input`(无 id),工具缺少元素发现入口 |
| 首启首个标签页 12s 后失效 | `open` 成功 → `eval_js` 报 `send failed because receiver is gone` → `list` 仍返回 `url:""` | Chrome 155 启动期瞬态 target 销毁;工具无存活校验/自愈,幽灵页常驻 |
| 控制台刷屏 | 3 秒 166 条 `WS Invalid message` | Chrome 155 的 `Network.requestWillBeSentExtraInfo` 无法被 chromiumoxide 0.9.1 反序列化(良性) |
| 临时 profile 残留 | 两轮退出后 `/var/.../laew_chrome_*` 仍在 | shutdown 只删一次;watchdog 的「Chrome 已退出」分支不清理 |

百度地图真实结构(实测):

- 路线入口:`div.searchbox-content-button.right-button.route-button`(39×38,无文字/无 title)
- 起点:`input.route-start-input`(placeholder「输入起点或在图区上选点」)
- 终点:`input.route-end-input`
- 公交标签:`div.tab-item.bus-tab`

## 二、修复

### 2.1 `click_text`:只点真正的可点击元素

- 表单控件不再作为文本按钮候选;`placeholder` 不参与匹配;
  `input[type=button|submit|reset]` 只按 `value` 匹配。
- 完全相等匹配加 20 分(优先于容器包含匹配)。
- 命中 tooltip/label 类节点时,在矩形周边 160px 内按**中心距离最近**选可点击元素
  (距离优先,同距比点击分),点中真实图标按钮。
- 周边无可点击元素时返回 `hit:false + reason:"matched_non_clickable" + hint`,
  **不再谎报成功**。

```
CLICK_TEXT 路线 => {hit:true, via:"neighbor", tag:"DIV",
                    cls:"searchbox-content-button right-button route-button loading-button"}
```

### 2.2 `inspect(info="elements")`:元素发现原语

```json
{"action":"inspect","info":"elements","page_id":"c_00000000",
 "params":{"text":"路线","max":80,"selector":"#app"}}
```

返回 `{elements:[...], count, scope}`;每项:

```json
{"selector":"div.searchbox-content-button.right-button",
 "tag":"DIV","id":"","cls":"...","role":"","type":"","placeholder":"",
 "text":"","label":"","x":349,"y":20,"w":39,"h":38}
```

- `selector` 由 `#id` 或 `tag + 稳定 class + :nth-of-type` 生成,可直接回传给
  `click` / `type`;过滤长度 ≤30 且不含 3 位以上数字的 class,避开构建哈希类名。
- 只列可见元素;可交互判定覆盖 `a/button/input/select/textarea`、`role=button|tab|link|...`、
  `onclick`、显式 `tabindex`、btn/button/tab/item 等类名、`cursor:pointer`。
- 上限 `params.max` 默认 80(夹在 1~200),扫描节点硬上限 40000。

### 2.3 `type`:未命中回候选输入框

`type`/`input_text` 选择器未命中时返回:

```json
{"selector":"#route-inputstart","hit":false,
 "candidates":[{"selector":"input.route-start-input","placeholder":"输入起点或在图区上选点",...}],
 "hint":"..."}
```

模型可直接从候选改选,不再盲猜或绕道 `eval_js`。

### 2.4 Schema 允许动作参数顶层直传

工具运行时 `params_of` 一直兼容「动作参数直接放顶层」,但 Schema 顶层写了
`additionalProperties:false`,模型把 `max_chars`/`max` 放顶层会被参数校验直接拒绝
(复跑实测连吃两轮)。移除该限制,与运行时契约对齐。

### 2.5 首启自愈与幽灵页清理

- `open` 去掉 `new_page(url)` 之后的冗余 `goto`(仅 URL 读空时兜底),缩小启动竞态窗口。
- 建页后做一次存活探测;失效则在同浏览器内**自动重建一次**。
- `list` 逐页探活,剔除 target 已销毁的幽灵页。
- `control`/`inspect` 遇到 `receiver is gone` 时翻译为
  「页面已失效,已从注册表剔除,请 action=open 重新打开」(code=2004),
  并同步剔除注册表条目。

### 2.6 日志与资源

- 控制台 EnvFilter 追加 `chromiumoxide::handler=error`,抑制逐事件 WARN;
  `LAEW_CDP_RAW_LOG=1` 可恢复原始报文。
- `BrowserHolder::shutdown` 改走带重试的 `watchdog::remove_profile`;
  watchdog 的「Chrome 已退出」分支也清理 profile;重试窗口 2.5s → 5s。

## 三、验证

- 单测:`max_elements_arg` 夹取、`elements` schema、死页错误识别、`cap_chars` 边界。
- 真实站点(隐藏档)探针:
  - `click_text("路线")` 不再命中 `#sole-input`,改为点击 `div...route-button`;
  - 点击后出现 `input.route-start-input` / `input.route-end-input` / `div.tab-item.bus-tab`;
  - `inspect(elements, text="路线")` 能列出 route-button;
  - 故意传错选择器 `#route-inputstart`,`type` 回候选 `input.route-start-input`。
- 正常 `close all` 与 SIGTERM 后无 `laew_chrome_*` 目录残留。
- **端到端复跑**(2026-10-23 14:42~14:50,同一提示词):SubAgent 17 轮 / 20 次工具调用,
  `inspect(elements)` 发现 `route-button` → 点击 → 切 `bus-tab` → 填写起终点 →
  `#search-button` → 取得 5 条公交方案 → 截图 3840×1822 → 生成 `出行计划-01.md`;
  QC `pass`,任务耗时 144s,首启无页面失效。

## 四、边界

- 不写死任何百度地图站点选择器;真实任务仍要求模型用 `inspect(elements)` 发现元素。
- 首启瞬态失效为概率事件(5 轮探针 0 复现),修复目标是「一次瞬态不污染任务」,
  而非声称已消除 Chrome 内部竞态。
- 不改 LsmAgentBrowser 内核,不引入新依赖。
