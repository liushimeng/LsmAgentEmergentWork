# Agent 身份与会话管理 —— 设计与解决方案

> 关联需求：AgentName / User-Agent / Authorization / Session ID / X-Session-Id / Anthropic metadata.user_id / TUI `/new` `/clear`。
> 参考抓包：`docs/协议抓包/claude-code-01-RequestBody.json`。

## 1. 目标与范围

当前 `laew` 以单一身份（`LsmAgentEmergentWork`）对外发起 LLM 请求，且没有会话标识。本次改造：

1. **Agent 身份**：引入 `AgentProfile`，为后续「多 Agent（各自独立系统提示词 / 工具 / 记忆）」预留扩展口；默认 AgentName = `LsmAgentEmergentWork`。
2. **请求头**：两协议统一携带 `User-Agent`、`Authorization: Bearer <key>`、`X-Session-Id`。
3. **Session ID**：每次 TUI 启动或 `/new` `/clear` 时生成，格式 = `时间日期 + 本机特征 + 时间戳 + 随机数`；一个 Session 拥有独立的对话上下文（Context）。
4. **Anthropic metadata**：请求体 `metadata.user_id` 内嵌 `device_id / account_uuid / session_id`（与 claude-code 抓包一致）。
5. **TUI 命令**：新增 `/new`，与 `/clear` 语义相同（清空历史 + 新建 Session ID）。

## 2. 产品方案

### 2.1 Agent 身份（多 Agent 预留）

```
AgentProfile {
    name:            "LsmAgentEmergentWork"   // 默认,未来可多份
    system_prompt:   String                    // 独立系统提示词
    tools:           ToolRegistry              // 独立工具集
}
```

- 当前只构造一份默认 profile，但 `Agent::new` 接收 `profile` 参数，后续扩展为「多 profile 切换」时无需再动 Agent 循环。
- `User-Agent` 取值：`{AgentName}/{版本号} {编译时间}`，例：`LsmAgentEmergentWork/0.1.0 2026-09-02 15:30:12 CST`。
- 编译时间复用 `build.rs` 注入的 `LAEW_BUILD_TIME`，版本号复用 `CARGO_PKG_VERSION`。

### 2.2 Session 与 Context

```
Session {
    id:         String,   // 会话标识
    device_id:  String,   // 本机指纹(sha256 hex,稳定)
    created_at: String,   // 创建时间(本地时间)
    context:    Vec<ChatMessage>,   // 独立对话上下文
}
```

- **Session ID 生成规则**：`{YYYYMMDD-HHmmss}-{本机指纹前8位}-{Unix毫秒时间戳}-{6位随机hex}`。
  - 时间日期：本地时区，可读。
  - 本机特征：对 `machine-id + hostname + username` 做 sha256，取前 8 位（device_id 取完整 64 位）。
  - 时间戳：`SystemTime` 毫秒，保证单调。
  - 随机数：基于 `nanos ^ pid ^ 自增计数器` 再哈希取 6 位 hex，避免碰撞。
- **生命周期**：TUI 启动时生成一个 Session；`/new` 或 `/clear` 时丢弃旧 Session、生成新 Session（Session ID 变化，上下文清空）。`-p` / `-f` 单轮模式每次调用生成一个独立 Session。
- **独立 Context**：`Session` 持有 `context: Vec<ChatMessage>`，Agent 循环直接操作 `session.context`，不再由 TUI 单独维护 `history`。

### 2.3 请求头（两协议统一）

| Header | 取值 | 说明 |
|--------|------|------|
| `User-Agent` | `{AgentName}/{版本} {编译时间}` | 客户端标识 |
| `Authorization` | `Bearer {api_key}` | 鉴权（Anthropic 保留 `x-api-key` 作为主鉴权，`Authorization` 作为补充） |
| `X-Session-Id` | `{Session ID}` | 会话追踪 |

> Anthropic 仍保留 `x-api-key` + `anthropic-version` 以兼容官方 SDK 风格；`Authorization` 与 `X-Session-Id` 作为通用头追加。

### 2.4 Anthropic metadata.user_id

```json
"metadata": {
    "user_id": "{\"device_id\":\"<64位hex>\",\"account_uuid\":\"\",\"session_id\":\"<Session ID>\"}"
}
```

- `device_id`：本机指纹完整 sha256 hex（64 位），与 claude-code 抓包一致。
- `account_uuid`：预留，当前为空字符串。
- `session_id`：当前 Session ID。

### 2.5 TUI 命令变更

| 命令 | 行为 |
|------|------|
| `/new` | 清空对话历史，生成新 Session ID（Session 重置） |
| `/clear` (`c`) | 同 `/new` |
| 其他命令 | 不变 |

横幅新增一行显示当前 `Session ID`。

### 3.2 关键接口

```rust
// agent/profile.rs
pub const DEFAULT_AGENT_NAME: &str = "LsmAgentEmergentWork";
pub struct AgentProfile { pub name: String, pub system_prompt: String, pub tools: ToolRegistry }
impl AgentProfile { pub fn default_profile() -> Self; pub fn user_agent() -> String }

// session.rs
pub struct Session { id, device_id, created_at, context }
impl Session {
    pub fn new() -> Self;
    pub fn id(&self) -> &str;
    pub fn device_id(&self) -> &str;
    pub fn context(&self) -> &Vec<ChatMessage>;
    pub fn context_mut(&mut self) -> &mut Vec<ChatMessage>;
    pub fn meta(&self) -> RequestMeta;
}
pub fn device_id() -> &'static str;        // 本机指纹(缓存)
fn generate_session_id(device: &str) -> String;

// llm/mod.rs
pub struct RequestMeta { pub session_id: String, pub device_id: String }
#[async_trait]
pub trait LlmClient {
    async fn complete(&self, system: &str, messages: &[ChatMessage], tools: &[ToolDef], meta: &RequestMeta) -> Result<Completion>;
}
```

### 3.3 协议层改造

- `AnthropicClient` / `OpenAiClient` 构造时注入 `user_agent: String`。
- `complete()` 新增 `meta: &RequestMeta` 参数，用于：
  - 写 `X-Session-Id` 头。
  - Anthropic 写 `metadata.user_id`。
- 公共头构造抽成 `llm::mod` 的辅助函数 `build_common_headers(api_key, meta) -> HeaderMap`（含 `User-Agent` / `Authorization` / `X-Session-Id` / `Content-Type`），两协议复用。
- Anthropic 额外追加 `x-api-key` + `anthropic-version`。

### 3.4 Agent 循环改造

```rust
// 旧: run_with_history(&mut Vec<ChatMessage>)
// 新: run_session(&mut Session) -> Result<String>
pub async fn run_session(&self, session: &mut Session) -> Result<String> {
    let meta = session.meta();
    loop {
        let completion = self.llm.complete(&self.profile.system_prompt, session.context(), &tool_defs, &meta).await?;
        ...
    }
}
```

- `run_once(user_input)` 内部构造临时 `Session` 后调用 `run_session`，保持 `-p/-f` 语义。
- `Agent` 持有 `profile: AgentProfile`，循环内使用 `profile.system_prompt` 与 `profile.tools`。

### 3.5 TUI 改造

- `TuiSession { paths, db, agent, session: Session }`（去掉独立 `history` 字段）。
- `handle_user_input` 普通提示词：`session.context_mut().push(user)` → `agent.run_session(&mut session)`。
- `/new` / `/clear`：`self.session = Session::new()`，打印新 Session ID。
- 横幅增加 `Session ID` 行。
- `completion.rs` 注册 `/new`（描述「清空对话历史并开启新会话」）。
- `print_help` 增加 `/new` 行。

### 3.6 本机指纹与 Session ID 实现要点

- `device_id()`：用 `OnceCell` 缓存；读取 `/etc/machine-id`（Linux）或 `hostname + username` 兜底，拼接后 sha256 取 64 位 hex。
- `generate_session_id(device)`：
  - 本地时间：通过 `time` crate 的 `OffsetDateTime` 本地偏移获取（仅用于可读前缀），毫秒用 `SystemTime`。
  - 随机：`nanos() ^ process::id() ^ 原子计数器`，再经 sha256 取前 6 位 hex。
- 依赖：新增 `sha2 = "0.10"`（纯 Rust，无系统依赖），`time = "0.3"`（已有间接依赖，显式引入以用本地时间格式化）。

### 3.7 测试策略

- **单元测试**：
  - `session.rs`：Session ID 格式正则校验；两次生成不重复；`device_id` 稳定且为 64 位 hex。
  - `agent/profile.rs`：`user_agent()` 格式为 `{name}/{version} {build_time}`。
  - `llm`：构造 `RequestMeta` 校验 `build_common_headers` 输出含三个目标头；Anthropic 请求体序列化后含 `metadata.user_id` 且可解析。
- **e2e**：`mock_llm_server.py` 记录请求头；`run_e2e.sh` 增加断言：
  - 两协议请求头含 `User-Agent` / `Authorization: Bearer` / `X-Session-Id`。
  - Anthropic 请求体 `metadata.user_id` 可解析出 `device_id` 与 `session_id`。
  - TUI 冒烟增加 `/new` 输入后仍正常退出。

## 4. 兼容性

- Anthropic 保留 `x-api-key` 主鉴权，新增 `Authorization` 不影响现有接入。
- `Agent::new` 签名变化：所有构造点（main.rs / tui/mod.rs / NoopLlm）同步更新。
- `LlmClient::complete` 增加 `meta` 参数：两协议实现 + NoopLlm + 测试 mock 同步更新。
- 数据库 schema 不变（Session 不持久化，仅进程内）。
