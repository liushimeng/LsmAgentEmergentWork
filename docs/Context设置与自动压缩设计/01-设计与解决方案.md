## 3. ContextMaxSize 全链路设计

### 3.1 数据模型

- `providers` 表新增列:`context_max_size INTEGER NOT NULL DEFAULT 800000`(单位:tokens)。
- 语义:`0` = 不限制(关闭自动压缩);`>0` = 上下文估算 token 数达到 80% 阈值时触发 Compact。
- `ProviderRecord` 增加 `pub context_max_size: u64`。
- 常量:`database::models::DEFAULT_CONTEXT_MAX_SIZE = 800_000`。

### 3.2 存量记录自动补全(需求 2)

`schema.rs` 在 `init_schema` 后追加 `migrate()`:

1. `PRAGMA table_info(providers)` 探测 `context_max_size` 列;
2. 缺失则 `ALTER TABLE providers ADD COLUMN context_max_size INTEGER NOT NULL DEFAULT 800000`
   —— SQLite 对带常量 DEFAULT 的 ADD COLUMN **自动回填全部存量行**,无需逐行 UPDATE;
3. 同时执行 CHECK 约束迁移(§4.4,Compact 角色入库需要)。

### 3.3 CLI

- `laew provider add --context-max-size <值>`:可选,缺省 800000;支持 `800000` / `800K` / `1M` 写法(`parse_context_size`,K/M 大小写不敏感)。
- `laew provider list`:每行追加 `ctx=800K` 人类可读显示。
- 非法值(0 以外的非正数、非数字)报错;`0` 合法(关闭压缩)。

### 3.4 导入 / 导出(往返兼容)

- 导出:`ExportRecord` 增加 `context_max_size` 字段;信封 `version` 由 `1.0` 升至 `1.1`。
- 导入:`ProviderImport` 增加 `#[serde(default)] context_max_size: Option<u64>`:
  - 旧版 1.0 导出文件 / 手写配置**无此字段** → 导入时补默认值 800000(向后兼容);
  - 新版文件带字段 → 原样恢复(往返无损);
  - 值非法(如负数)→ 按无效记录跳过。

### 3.5 TUI

- **ProviderForm**(`/provider add`):5+1 Tab → 6+1 Tab,新增 Tab 6 `context_max_size`(文本,默认 `800000`,支持 K/M 后缀;Enter 编辑)。
- **ProviderList**(`/provider list`):只读字段 6 → 7,追加 `context_max_size`(显示原始值 + 人类可读,如 `800000 (800K)`)。

## 4. Compact Agent(第 8 角色)设计

### 4.1 身份档案

- 名称:`LsmAgentEmergentWork-Compact`;`AgentRole::Compact`(`as_str() = "compact"`)。
- 工具集:**无工具**(与 SessionContext / Debug 一致,纯文本摘要,不修改系统状态)。
- 系统提示词:身份 + 三档压缩指令 + 四段式摘要格式(目标 / 进展与关键结论 / 重要上下文 / 待办)。
- User-Agent / 请求头走统一链路,`-debug` 模式下 LLM 调用自动被 DebugCollector 采集(装饰器模式,无需新增事件类型)。

### 4.2 三档压缩率

| 档位 | 目标(压缩后 / 压缩前) | 信息保留策略 | 适用 |
|------|----------------------|--------------|------|
| **Light(轻度)** | ≤ 80% | 仅折叠工具结果与冗长输出,对话几乎原样保留;摘要最详细 | 刚越过阈值 |
| **Medium(中度)** | ≈ 50% | 保留主要流程、关键结论、文件/命令清单;丢弃寒暄与重复 | 明显超出 |
| **Aggressive(激进)** | ≤ 20% | 只保留目标、当前状态、关键决策与待办;信息丢失最多 | 严重超出(≥1.5× 上限) |

**自动选档**(`CompactTier::for_ratio`,ratio = est_tokens / context_max_size):

- `ratio < 1.0` → Light
- `1.0 ≤ ratio < 1.5` → Medium
- `ratio ≥ 1.5` → Aggressive

### 4.3 触发时机与压缩流程

接入点:`MultiAgentOrchestrator::handle()` 在「项目上下文注入 + 历史摘要注入」之后、Yolo 分类之前(TUI 多轮与 `-p`/`-f` 单轮全覆盖)。

```
est = estimate_tokens(session.context())          # 字符数/4
max = db.get_active().context_max_size            # 每次现读,provider 切换即生效
若 max == 0 或 est < max × 0.8 → 跳过
否则:
  tier = CompactTier::for_ratio(est / max)
  1) 划分保护段:带 PROJECT_CONTEXT / SESSION_HISTORY / COMPACTED_CONTEXT 标记的消息
     + 最近 4 条消息(tail)
  2) 压缩段 = 其余消息,渲染为纯文本交给 Compact Agent(LLM 摘要,按 tier 给指令)
  3) LLM 失败 → 降级硬截断(每条消息保留前 200 + 后 100 字符拼接)
  4) 用一条 user 消息替换压缩段:
     <<<LAEW:COMPACTED_CONTEXT>>> [Compact 压缩 | 档位 | est 前→后] 摘要文本 <<<LAEW:COMPACTED_CONTEXT_END>>>
  5) 写 agent_memory(role=compact) 与 session_memory(role=compact, event_type=summary)
```

### 4.4 数据库 CHECK 约束迁移

`session_memory.role` CHECK 现有值域不含 `compact`;`agent_memory.agent_role` CHECK 现有值域
**连 `session` 都没有**(导致 SessionContext 的 agent_memory 写入一直静默失败 —— 顺带修复)。

SQLite 不支持修改 CHECK,采用表重建迁移(仅当旧 CHECK 不含 'compact' 时执行):

```
ALTER TABLE session_memory RENAME TO session_memory_old;
CREATE TABLE session_memory (... role CHECK(role IN ('yolo','plan','main','subagent','quality','session','user','compact','debug')) ...);
INSERT INTO session_memory SELECT * FROM session_memory_old;
DROP TABLE session_memory_old;
-- agent_memory 同理,CHECK 扩为 ('yolo','plan','main','subagent','quality','session','debug','compact')
```

迁移在 `Db::open` 内幂等执行;`INSERT SELECT` 前用事务包裹,失败回滚。

### 4.5 压缩消息渲染

压缩段消息渲染规则(喂给 Compact Agent):
- `Text` 块原样;`ToolUse` 块渲染为 `[工具调用] name(args 截断 200)`;`ToolResult` 块渲染为 `[工具结果] 截断 500`(Medium/Aggressive 档位在提示词中要求进一步折叠)。
