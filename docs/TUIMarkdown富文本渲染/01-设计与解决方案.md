# TUI Markdown 富文本渲染 — 设计与解决方案

> 轮次:2026-09-15。目标:大模型输出的 Markdown 文本在 laew TUI 界面以
> **多颜色富文本**呈现(标题 / 粗斜体 / 行内码 / 列表 / 引用 / 表格 / 链接 /
> 分隔线 / 围栏代码高亮),提升可读性与美观度; transcript / 导出 / LLM 回填
> 保持**纯文本同源**,不混入 ANSI。
> 对应知识库缺口:D5 工具输出富文本内容渲染(L1401-L1402 / L1436-L1445 /
> L1500-L1506 / L1550+,`docs/Agent源码调研/专题/专题-laew实现进度对照表.md`)。

## 1. 背景与现状

### 1.1 现有输出链路

TUI 中大模型文本出口收敛在 `src/tui/dispatch.rs`:

| 路径 | 入口 | 现状 |
| ---- | ---- | ---- |
| DirectAnswer(Yolo 直答) | `print_assistant_text_with_agent` → `print_with_optional_highlight` | 仅 ``` 围栏内做语法高亮,围栏外**原样输出**(`#`/`**`/表格线等符号裸露) |
| Executed(任务结果) | `print_task_result` → `format::format_task_result` | 整段纯文本 `println!`,其中 `subflow_outcome`(SubAgent 终答)与 `[session_context 摘要]` 两块是模型生成的 Markdown |
| Failed / 用量 / 结构标签 | 各处 `println!` | 程序自身标签,不需要 Markdown 渲染 |

既有底座:`src/tui/render/`(Span/RenderLines 模型)、`render/highlight.rs`
(8 类 token 语法高亮,围栏内已生效)、`theme.rs` 四主题 Palette 系统、
`input.rs::display_width`(CJK 宽度,表格对齐可用)。

### 1.2 设计约束(来自 CLAUDE.md / 工程约定)

- **不引入新 crate**(自研零依赖 Markdown 子集解析器,对齐 highlight.rs
  「手写 regex tokenizer 避免重依赖」的既有取向);
- 颜色常量集中在 `theme.rs`,禁止渲染层硬编码;新控件类型先在 theme.rs
  注册常量;运行时走 `palette()` 动态取色,四主题一致生效;
- transcript 记录 / `/export` 导出 / LLM 上下文回填必须保持纯文本
  (ANSI 混入会破坏导出与指代);
- 单源码文件 ≤ 1800 行(新模块独立成文件);
- `-p` 单轮模式(main.rs)输出**不改动**(管道/脚本消费场景保持纯文本)。

### 1.3 外部参考

- claudecode(Ink Fork):标题加粗着色、行内码反色、链接下划线、代码块
  边框 + 语法高亮;
- python rich / markdown-it-terminal:列表符替换 `•`、引用竖线 `│`、
  表格盒线绘制 —— 终端 Markdown 的事实标准形态;
- 本方案取两者交集,并保守处理未知语法(见 §4 降级原则)。

## 2. 方案总览

```
                    ┌─ render/markdown.rs(新)────────────────┐
 dispatch.rs ──────►│ render_markdown(text) -> RenderLines     │
  DirectAnswer 打印 │  块级:围栏/标题/hr/引用/列表/表格/段落   │
  Executed 结果打印 │  行内:`code **bold** *em* ~~del~~ [链接]│
                    └──────────────┬──────────────────────────┘
 format.rs(Styled 模式)──────────┘  仅内容块(subflow_outcome/摘要)
                    │
                    ├─ 复用 render/highlight.rs(围栏内语法高亮)
                    ├─ 取色 theme::palette()(新增 md_* 字段组)
                    └─ 输出 render/mod.rs::print_render_lines / span_to_ansi
```

四个改动面:

1. **`src/tui/render/markdown.rs`(新)**:纯函数 Markdown 子集渲染器,
   输入文本 → `RenderLines`;并提供 `print_markdown` /
   `markdown_to_ansi_str` 两个输出助手。
2. **`src/tui/theme.rs`**:`attr` 位掩码补 `ITALIC` / `CROSSED_OUT`
   (`attrs_to_ansi` 同步);注册 `MD_*` 常量 + `Palette` 增 `md_*`
   字段组,四主题各自配色。
3. **`src/tui/dispatch.rs`**:`print_with_optional_highlight` 升级为
   `print_assistant_markdown`(整体走 Markdown 渲染,围栏高亮语义内嵌保留);
   `print_task_result` 改走 `format_task_result(..., styled=true)`。
4. **`src/tui/format.rs`**:`format_task_result` 增加 `styled: bool` 形参 ——
   transcript 调用传 `false`(纯文本,零行为变化),屏幕打印传 `true`,
   仅对 `subflow_outcome` / `summary` 两块模型内容做 ANSI 渲染;结构标签行
   (`[task executed]` / `[QC]` / 用量行)保持纯文本。

一处收敛:transcript 与屏幕**同源构建**(同一函数,仅 styled 分支不同),
延续 D8「屏幕打印与导出同源,避免两处漂移」的既有原则。

## 3. 块级语法支持矩阵

| Markdown 语法 | 识别条件 | 渲染形态(default 主题) |
| ------------- | -------- | ---------------------- |
| ATX 标题 `#`..`######` | 行首 ≤3 空格 + 1-6 个 `#` + 空格 | 前缀 `▍`×级别 + 文本加粗;L1 品红 / L2 青 / L3 蓝 / L4 黄 / L5 绿 / L6 灰;行尾 `###` 剥离 |
| 围栏代码 ```lang / ~~~lang | 与既有 fence 检测一致(``` 行内不再含反引号才算围栏) | 围栏符号本体弱化色保留(不丢字符)、语言名 accent 加粗;内部逐行走 `highlight::highlight_line`(现有能力,零回归) |
| 无序列表 `-`/`*`/`+` | ≤3 空格缩进 + 标记符 + 空格 | 缩进保留,标记符替换为 `•`(cyan 加粗);行内容继续行内解析 |
| 有序列表 `1.`/`1)` | 数字 + `.`/`)` + 空格 | 序号本体着色保留(文本不失真),内容行内解析 |
| 任务列表 `- [ ]` / `- [x]` | 列表 + `[空格/x/X]` | `☐`(灰)/ `☑`(绿)替换,内容行内解析 |
| 引用 `>` | ≤3 空格 + `>` | 每级前缀 `│`(黄),内容斜体弱化 |
| 分隔线 `---`/`***`/`___` | 整行仅同种标记符 ≥3(含空格间隔) | `─`×42 横线(灰);`--- WorkFlow 1 ---` 之类标签行不命中(含其它字符) |
| 表格 `|a|b|` + 分隔行 | 表格行下必须紧跟 `|---|:--|` 分隔行才启用 | 盒线重绘 `┌─┬─┐`,表头加粗着色,列宽按 `display_width`(CJK 双宽)对齐,支持 `:---:` 对齐标记 |
| 段落 / 其它行 | 兜底 | 仅行内解析;无法识别的符号原样透传 |
| **不支持**(有意降级) | setext 标题(`===`/`---` 下划线式)、缩进 4 空格代码块、脚注、HTML 内联、嵌套列表续行重排 | 按普通文本/段落处理 —— LLM 输出极少使用;避免误伤 `  4空格续行` |

## 4. 行内语法与降级原则

行内解析器为**单行、保守回溯式**(自研字符扫描,不引 crate):

| 语法 | 形态 | 降级规则 |
| ---- | ---- | -------- |
| 粗体 `**x**` / `__x__` | BOLD | 同行无闭合 → 原样输出 `**` |
| 斜体 `*x*` / `_x_` | ITALIC(新 attr,`\x1b[3m`) | 同上;`_` 需词边界(防 `snake_case` 误伤:开侧前字符非字母数字) |
| 删除线 `~~x~~` | CROSSED_OUT(新 attr,`\x1b[9m`) | 同上 |
| 行内码 `` `x` `` / ` ``x`` ` | fg=md_code_fg + bg=md_code_bg | 无反引号闭合 → 原样;code 内容不再嵌套其它语法(CommonMark 语义) |
| 链接 `[text](url)` | text 下划线(cyan)+ ` (url)`(灰) | url 与 text 相同(裸链形态)时只显示一次;`](` 断裂 → 原样;text 内部递归行内解析 |
| 图片 `![alt](url)` | 按链接渲染(alt 文本 + url) | 终端不展示图片 |
| 自动链接 `<https://…>` | 同链接 | 非协议前缀的 `<...>` 原样 |
| 转义 `\*` `\`` 等 | 输出字面字符(继承外层样式) | — |

**总降级原则(美观优先于逐字节保真,正确性优先于美观)**:

1. 任何不确定 → 保持原文,绝不吞字符(`**` 未闭合渲染后文本仍在);
2. 只剥离「成对且被识别」的语法标记,可见文字 100% 保留(列表符 `*`→`•`、
   标题 `#`→`▍` 属**符号替换**,文本内容不失真);
3. transcript / 导出 / LLM 回填 / `-p` 模式全部走原文,渲染只发生在
   **屏幕打印的最后一米**;
4. 渲染纯函数零 panic:对任意输入(含畸形 UTF-8 边界 / 超长行 / 嵌套残片)
   输出合法 RenderLines,单测覆盖。

## 6. 模块 API(render/markdown.rs)

```rust
/// 文本 → 渲染行(纯函数,零 IO)。
pub fn render_markdown(text: &str) -> RenderLines;

/// 屏幕直出:渲染 + 每行加缩进打印(2 空格,与 print_* 家族一致)。
pub fn print_markdown(text: &str, indent: &str);

/// 嵌入 String 场景(format_task_result Styled 模式):渲染为带 ANSI 的多行文本。
pub fn markdown_to_ansi_str(text: &str, indent: &str) -> String;
```

实现结构:

- `struct MdCtx { pal: Palette }` 每次渲染取一次 `palette()`(主题实时切换);
- 块级:`Vec<&str>` 行数组 + 索引游标 lookahead(表格/围栏),其余逐行匹配;
- 行内:`parse_inline_spans(s, base_fg, base_attrs) -> Vec<Span>`,
  粗斜体等嵌套用 base_attrs 累积;
- 复用:`highlight::highlight_line`(围栏)、`input::display_width`(表格
  列宽)、`render::span_to_ansi`(输出编码,dispatch 的 diff 打印同步收敛到
  此助手,消除三处重复的 ANSI 拼接)。

## 7. 集成点与回归面

| 集成点 | 变化 | 回归风险 |
| ------ | ---- | -------- |

## 9. 边界与已知取舍

- **setext 标题不支持**:`---` 一律按分隔线(rich/claudecode 终端场景同此
  取舍,避免与「段落下划线」歧义互伤);
- **缩进 4 空格代码块不支持**:列表续行/树形缩进误伤率 > 收益;
- **嵌套列表标记不重排序**:仅统一替换为 `•`(缩进列保留,视觉层级由
  原缩进呈现;终端窄宽下不做悬挂缩进重排);
- **表格超宽不折行**:LLM 输出表格列数普遍 ≤6,保持原样溢出由终端换行;
- **`-p` 模式与子屏(`/provider` 系列)不渲染**:前者是脚本契约,后者是
  结构化表单界面,均无 Markdown 内容;
- 不支持的扩展语法(`$公式$`、mermaid、HTML)按纯文本透传,不报错。
