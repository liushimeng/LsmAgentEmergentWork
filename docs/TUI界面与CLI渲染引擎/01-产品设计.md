## 1. 背景

`laew` 已迭代至 v0.1.2，完成了 rustyline → crossterm 自定义输入的迁移、斜杠命令补全、文件路径补全、`-f` 文件提示词参数。当前实现特点：

- 输入侧（`input.rs` + `completion.rs`）已经是基于 crossterm 原始模式、实时渲染补全列表。
- 命令侧（`mod.rs::TuiSession::handle_slash`）走的是传统的 `print!` + `println!` 静态文本流式输出。
- `/provider add` 走的是 `read_line_prompt` 一问一答 stdin/stdout 风格；没有横向 Tab 切换、没有视觉位置、不能回头修改。

这造成以下产品痛点：

1. **配置管理是「高频+高错」操作**：用户每次重装、新增、轮换 Key 都要写 5 个字段。出错（比如 end_point 写错）要 `/provider del` 整条删掉重录。
2. **斜杠命令被当作命令行 CLI** 而不是 TUI 屏幕：一旦进入 `/provider add`，视图立刻退化为一次性表单，没有回头路（Back / Esc / 切字段）。
3. **`/provider` 单独输入没有意义**：当前如果只输入 `/provider`，什么也不发生或只打印一行帮助。需要把它默认路由到 `/provider list` 这种最常用动作。
4. **API Key 脱敏要求**：list 视图已经做了末 4 位脱敏，但 form 输入回显还是明文。

---

## 2. 设计目标

| 目标 | 说明 |
|------|------|
| **独立渲染引擎** | 把 TUI 屏幕抽成 `engine.rs`，与业务命令解耦，方便新增屏幕（`/settings` `/history` 等）。 |
| **Tab 表单范式** | `/provider add` 与 `/provider list` 都采用"5 个 Tab 位"：4 字段 Tab + 1 确认 Tab，左右键切换 Tab，编辑当前字段后任意键回 Tab 行可随时跳到别的字段修正。 |
| **`/provider` 默认路由** | 单独输入 `/provider` 等价于 `/provider list`，减少用户记忆负担。 |
| **`/provider del` 选择式** | 显示 list（高亮可选项），回车进入"二次确认"Tab 屏，避免误删。 |
| **API Key 全程脱敏** | list 视图末 4 位、Tab 表单编辑态输入时打 `*` 但允许继续输入；确认 Tab 提交前可"明文回显一次"以校对，再点确认写入。 |
| **可访问性** | 全部操作可纯键盘完成，Tab 顺序稳定，Esc 退出当前屏幕回到 REPL 主屏。 |
| **可测试** | 渲染层做纯函数（输入 Frame + State → 输出 ANSI 字节流），不依赖真实终端；命令逻辑（state machine）可单元测试。 |

## 3. 屏幕拓扑（Screen Topology）

启动 `laew` 进入 **REPL 主屏**，按需切换到子屏。

```
                  ┌──────────────────────────┐
                  │       REPL 主屏           │
                  │  - 历史消息 + 输入框       │
                  │  - 斜杠命令下拉补全        │
                  └──────────────────────────┘
                       │           │
        /provider ─────┘           └────── /help /model /clear /exit
        /provider list  ──────►  ProviderList 屏
        /provider add   ──────►  ProviderForm 屏（add 模式）
        /provider list  ──Edit──► ProviderForm 屏（edit 模式）
        /provider del   ──────►  ProviderDelPicker 屏 → ProviderDelConfirm 屏
        /provider use <id> ──► 直接回到 REPL 主屏(并打印切换成功)
```

- REPL 主屏 = 已有功能的最小修改版本（保留行输入 + 斜杠命令补全 + 多轮对话）。
- 子屏是 **Modal（模态）**：进入后独占终端，Esc 退回主屏；屏内不再接受斜杠命令（避免歧义）。

## 4. `/provider` 系列交互规范

### 4.1 路由表

| 输入 | 行为 |
|------|------|
| `/provider` | 等价 `/provider list`，直接进入 ProviderList 屏 |
| `/provider list` (或 `ls`) | ProviderList 屏 |
| `/provider add` | ProviderForm 屏，4 字段全空、`is_active=auto` |
| `/provider use <id>` | 后台 `set_active(id)` + 重建 Agent，回到主屏并打印 `✓ 已切换` |
| `/provider del` (或 `del <id>`) | ProviderDelPicker 屏（高亮 id）；回车进 ProviderDelConfirm 屏 |
| 其他 | 提示未知子命令并给出相似建议 |

### 4.2 ProviderList 屏（Tab 化改造）

**视觉：**

```
╔══════════════════════════════════════════════════════════════════════╗
║  /provider list                                          Esc  返回    ║
╠══════════════════════════════════════════════════════════════════════╣
║  #  Tab  字段           值                                    操作     ║
║  1  [id]         1                                                 ║
║  2  [protocol]   anthropic                                          ║
║  3  [provider]   mockA                                              ║
║  4  [model]      claude-mock                                        ║
║  5  [end_point]  http://127.0.0.1:18899                             ║
║  6  [api_key]    ****abcd      ←末4位                              ║
║  ──────────────────────────────────────────────────────────────── ║
║  Tab: ←→ 切换字段   Enter 编辑   s 设为当前   d 删除   Esc 返回      ║
╚══════════════════════════════════════════════════════════════════════╝
```

- **5 个数据 Tab**（1–5/6）：只读展示当前选中记录。
- **第 6 行 Tab** = "操作"：`[Switch as active]  [Delete]  [Back]`，左右键选，回车执行。
- 多条记录：`/`、`\`（或 `n` / `p`）切换"当前记录"，整张表刷新。
- **API Key Tab 始终脱敏**：永远显示 `****<末尾4位>`。

### 4.3 ProviderForm 屏（add / edit 通用）

5 个 Tab 位固定顺序：

```
┌────────────────────────────────────────────────────────────────────┐
│ Tab 1: protocol      ───▶ 协议选择 (anthropic / openai) ←→ 切换     │
│ Tab 2: provider_name ───▶ 文本输入                                  │
│ Tab 3: model_name    ───▶ 文本输入                                  │
│ Tab 4: end_point     ───▶ 文本输入                                  │
│ Tab 5: api_key       ───▶ 文本输入（编辑时显示明文，确认前再脱敏） │
│ Tab 6: 确认          ───▶ [ 确认 ] [ 取消 ] ←→ 切换                 │
└────────────────────────────────────────────────────────────────────┘
```

**交互：**

- 启动时光标落在 Tab 1（protocol）。
- `←` / `→`：在 Tab 间移动（环回）。
- `Enter`：进入当前 Tab 的"编辑态"：
  - protocol Tab → 切换 `anthropic ⇄ openai`，再 Enter 退出编辑态。
  - 其余文本 Tab → 进入行输入，光标在字段末，可任意编辑；Enter 退出编辑态（保留修改）。
  - 确认 Tab → 执行 `[确认]` 或 `[取消]`。
- `Tab` 键：**保留 0.1.2 的斜杠命令补全语义不变**——只在 REPL 主屏生效；进入子屏后 Tab 由渲染引擎接管（左右切换 Tab）。
- `Esc`：
  - 在 Tab 1–5 且未编辑 → 退回上一屏。
  - 在编辑态 → 退出编辑态（保留已输入内容）。
  - 在确认 Tab → 等价 `[取消]`。

**API Key 编辑态脱敏策略：**

| 状态 | 显示 |
|------|------|
| 未进入当前 Tab | `****<末4位>`（沿用 list 的脱敏格式） |
| 进入 Tab 5 编辑态 | 完整明文（用户必须看到自己输入的内容，否则无法校对） |
| 退出编辑态（点确认前回到浏览态） | 自动恢复 `****<末4位>` |
| 提交后写库 | SQLite 存原文；下一次 list 仍按末 4 位脱敏展示 |

### 4.4 ProviderDelPicker 屏

```
/provider del                                          Esc 返回
┌──────────────────────────────────────────────────────┐
│  请选择要删除的接入记录(↑↓ 选择, Esc 取消):         │
│                                                      │
│    id=1  anthropic  mockA / claude-mock  @ ep       │
│  ► id=2  openai     mockO / gpt-mock    @ ep       │
│    id=3  openai     mockZ / gpt-4       @ ep       │
│                                                      │
│  Enter 删除 (进入确认页)   ←→ 切换记录                │
└──────────────────────────────────────────────────────┘
```

回车 → 进入 **ProviderDelConfirm 屏**：

```
/provider del > 确认删除                              Esc 取消
┌──────────────────────────────────────────────────────┐
│  确认删除以下接入记录?                                │
│                                                      │
│    id=2  openai  mockO / gpt-mock @ http://...       │
│    key=****abcd                                       │
│                                                      │
│  ► [ 确认删除 ]      [ 取消 ]                        │
└──────────────────────────────────────────────────────┘
```

- 左右键切换 `[确认删除] / [取消]`，回车执行。
- `Esc` 或选 `[取消]` → 退回 ProviderDelPicker；ProviderDelPicker 再 `Esc` 退回主屏。

## 5. 主屏斜杠命令（沿用 + 微调）

为减少记忆负担：

| 输入 | 行为 |
|------|------|
| `/` (空) | 弹出全部命令补全列表（已有） |
| `/provider` | **等价 `/provider list`**，进入 ProviderList 屏 |
| `/provider add` / `list` / `del` / `use <id>` | 按 4.1 路由 |
| `/help` / `/model` / `/clear` / `/exit` | 沿用现有实现 |

补全引擎增加以下候选项：
- `/provider`（无子命令）→ 描述"管理大模型接入记录(默认进入 list 屏)"，回车进入 ProviderList 屏。

## 6. 视觉规范

- 标题栏：`╔═...═╗`，居中显示当前屏幕名。
- Tab 高亮：选中 Tab 用 `SetAttribute(Reverse)`，未选中 Tab 用 `DarkGrey`。
- 按钮：`[ 确认 ]` / `[ 取消 ]`：选中态反白，未选中态灰色。
- API Key 永远 `****<末4位>`（脱敏）。
- 错误提示：屏幕底部一行 `! <message>`，红色（`Color::Red`），3 秒后自动消失（按任意键立刻消失）。
- 帮助栏：屏底一行 `Tab ←→ 切换  Enter 编辑  Esc 返回 ...`，灰色。

## 7. 与现有功能的兼容性

- 现有 `--version` / `--help` / `-p` / `-f` / `provider` 子命令 **完全保留**，TUI 子屏只接管 `/provider *` 系列在交互模式下的体验。
- TUI 仍可用 `/provider use <id>` 这种 CLI 风格的快捷路径（不走子屏）。
- 单轮 `-p` / `-f` 模式不受任何影响。
- 现有 18 项 e2e 全部继续 PASS（TUI 冒烟测试的 `/provider list` 在新增 ProviderList 屏后输出格式保持兼容，或在测试里做语义匹配而非精确字符串匹配 —— 见 `02-技术设计` §6 测试策略）。
