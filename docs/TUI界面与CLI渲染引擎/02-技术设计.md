## 2. Screen trait（核心抽象）

```rust
/// 一块独立的 TUI 屏幕(模态)。
pub trait Screen: Send {
    /// 屏幕标题(用于顶部横幅)。
    fn title(&self) -> &str;

    /// 渲染当前帧到 Frame。
    fn render(&self, f: &mut Frame);

    /// 处理 KeyEvent,返回 Outcome 决定下一步。
    fn handle_key(&mut self, key: KeyEvent) -> Outcome;

    /// 进入屏幕时调用(可空)。
    fn on_enter(&mut self) {}

    /// 退出屏幕时调用(可空)。
    fn on_exit(&mut self) {}
}

pub enum Outcome {
    /// 留在当前屏幕,引擎会再触发 render。
    Continue,
    /// 退回调用栈上一屏(主屏收到 Pop 后退出循环)。
    Pop,
    /// 把新屏幕压栈(给主屏用:例如 /provider use 完成后回到主屏 + 打印信息)。
    Push(Box<dyn Screen>),
    /// 永久退出 TUI。
    Quit,
    /// 主屏专用:把这条消息打到主屏,然后退回主屏。
    Toast(String),
}
```

**关键点：** Screen 不直接写 stdout；它只把内容塞进 `Frame`，由 `engine::render` 统一计算 diff 并绘制。

## 3. Frame / Component / Buffer

简化版 ratatui 风格：

```rust
/// 一帧的渲染目标(纯字符串 + ANSI 转义)。
pub struct Frame {
    pub width: u16,
    pub height: u16,
    pub buffer: Vec<Cell>,         // 行优先
}

#[derive(Clone)]
pub struct Cell {
    pub ch: char,
    pub fg: Color,
    pub bg: Color,
    pub attr: Attribute,
}

pub trait Component {
    fn render(&self, area: Rect, frame: &mut Frame);
}
```

`Frame::draw_rect(area)` / `Frame::put_str(area, s, style)` / `Frame::border_box(area, title)` 是三个够用的原语。Screen 的 `render` 内部按区块布局调用这些原语。

**为什么不做完整 diff：** 第一版采用"全量重绘"——子屏在事件后调用 `engine::present(self)`，引擎清屏 + 整体输出 Frame。子屏普遍只占 ~20 行，全量重绘 < 16ms，无闪烁即足够。后续若出现性能问题再升级为 dirty-rect。

## 4. 事件分发（主屏 → 子屏 → 主屏）

```rust
// 主屏循环
loop {
    let screen = stack.last_mut().unwrap();
    screen.render(&mut frame);
    engine.flush(&frame)?;

    let key = read_key()?;
    match screen.handle_key(key) {
        Outcome::Continue => {}
        Outcome::Pop => { stack.pop(); if stack.is_empty() { break; } }
        Outcome::Push(s) => stack.push(s),
        Outcome::Quit => break,
        Outcome::Toast(msg) => { stack.pop(); show_toast(msg); }
    }
}
```

- 主屏自己不实现 Screen trait；它就是 `run()` 内部的那段循环。
- ProviderList / ProviderForm / ProviderDel 都实现 Screen trait。
- Toast 实现：保留主屏的 stdio 输出能力，写一行到屏幕底部，按回车消失。

## 5. Tab 表单状态机（form.rs）

```rust
pub struct TabForm {
    tabs: Vec<Tab>,
    focus: usize,         // 当前 Tab 下标
    editing: Option<usize>, // 当前 Tab 是否在编辑态
}

pub struct Tab {
    pub label: String,
    pub kind: TabKind,
    pub value: String,
    pub options: Vec<String>,  // for Choice
}

pub enum TabKind {
    /// 单行文本输入
    Text { placeholder: String, masked: bool },
    /// 二选一 / 多选一(Enter 切换)
    Choice { choices: Vec<String>, cursor: usize },
    /// 确认按钮组(子 Tab 由左右键切换)
    Confirm { actions: Vec<ConfirmAction> },
}

pub enum ConfirmAction {
    Submit,    // [ 确认 ]
    Cancel,    // [ 取消 ]
    Delete,    // [ 确认删除 ]
}

impl TabForm {
    pub fn handle_key(&mut self, key: KeyEvent) -> FormOutcome {
        match (self.editing, &mut self.tabs[self.focus].kind) {
            // 编辑态：把按键交给文本框或 Choice
            (Some(idx), TabKind::Text { masked, .. }) if idx == self.focus => { ... }

            // 浏览态
            (None, _) => match key.code {
                Left  => { self.focus = (self.focus + self.tabs.len() - 1) % self.tabs.len(); }
                Right => { self.focus = (self.focus + 1) % self.tabs.len(); }
                Enter => match &self.tabs[self.focus].kind {
                    TabKind::Text { .. } => self.editing = Some(self.focus),
                    TabKind::Choice { choices, cursor } => { /* 切到下一个 choice */ }
                    TabKind::Confirm { actions } => return FormOutcome::Action(actions[cursor]),
                },
                Esc   => return FormOutcome::Cancel,
                _ => {}
            }
        }
    }
}
```

**API Key 脱敏** 由 `TabKind::Text { masked: true }` 字段控制：渲染时 `value.chars().map(|_| '*')`，但内部字符串仍是明文（用于 SQLite 持久化）。

## 6. ProviderForm 屏实现要点

```rust
pub struct ProviderForm {
    mode: Mode,                     // Add / Edit(i64)
    form: TabForm,
    error: Option<String>,
    db: Arc<Mutex<Db>>,
    paths: Paths,
    on_done: Box<dyn Fn(i64) + Send>,  // add 完成后回调,主屏用它重建 Agent
}

impl Screen for ProviderForm {
    fn render(&self, f: &mut Frame) { /* 顶栏 + 5 Tab + 帮助栏 */ }
    fn handle_key(&mut self, key) -> Outcome { /* 委托 form */ }
}
```

- 提交时做字段校验：
  - protocol 必须是 `anthropic` 或 `openai`（TabKind::Choice 限定）。
  - provider_name / model_name / end_point / api_key 非空。
- 校验失败 → 在屏底 `! <field>: <reason>`，3 秒后自动消失或任意键消失。
- 校验通过 → 调用 `db.add(...)` / `db.set_*`，回调 `on_done(id)`，返回 `Outcome::Toast("✓ 已新增接入记录 id=…")`。

## 7. ProviderList 屏实现要点

```rust
pub struct ProviderList {
    records: Vec<ProviderRecord>,
    cursor: usize,                 // 当前选中记录
    action_cursor: usize,          // 操作按钮焦点 (0..2)

    paths: Paths,
```

- `←` / `→`：切换"操作按钮"焦点（`Switch / Delete / Back`）。
- `n` / `p` 或 `↓` / `↑`：切换记录。
- `s`：调用 `set_active(cursor_id)`，回到主屏 + Toast。
- `d`：进 ProviderDelPicker。
- `Enter`：触发当前按钮。

## 9. 现有 input.rs 的兼容性

主屏保留 `InputHandler::read_line` + `CompletionEngine`。`engine.rs` 不接管主屏的"行输入 + 行内补全列表"——只接管子屏。这样：

- 0.1.2 的 v0.1.2 全部行为（Tab/行内提示/路径补全）零回归。
- 主屏与子屏的渲染职责清晰：`InputHandler` 负责"行编辑"，`engine.rs` 负责"屏幕"。

---

## 10. 错误处理

- 子屏内部异常（DB / IO）→ 屏底 `!` 行；不退出屏；用户可继续操作。
- 子屏不可恢复错误 → `Outcome::Pop` + Toast(原 main.rs 的错误风格)。
- 主屏异常：保留现有 anyhow 冒泡路径。

## 12. 测试策略

### 12.1 单元测试

- `form.rs` 的状态机：纯函数，输入 `TabForm` + Key 序列，断言 `focus` / `editing` / `value` 的最终状态。无需终端。
- `engine.rs` 的 `Frame` 渲染：纯字符串拼接断言（不调用 ANSI 字节，只断言 `Cell` 数组内容）。
- `provider_*` 屏：用 `tempfile::tempdir` + `Paths::for_test` + `Db::open`，跑 add / list / del 的完整路径。

### 12.2 e2e 兼容

`testReport/run_e2e.sh` 中的 TUI 冒烟（第 7 节）当前测试 `/help`、`/model`、`/provider list`、`/exit` 四个命令的输出包含 `根目录`、`工作目录`、`当前模型`、`provider add` 这些关键字。

新实现下：

- `/help` → 主屏命令列表输出（保持 println! 风格或屏内 print）。
- `/model` → 主屏 println!(沿用旧实现)。
- `/provider list` → 进入子屏，屏内打印 list 内容并写出包含 `provider add` 的关键字。

为保持 e2e 兼容，`/provider list` 子屏在 render 时**追加 1 行**到 stdout（或者直接让 e2e 的"过滤输出后匹配关键字"的逻辑继续工作）—— 由于子屏用 ANSI 绘制，可以确保这 1 行业务信息（`添加 / 切换 / 删除` 提示）出现在输出里，从而 e2e 继续 PASS。如果实现上需要，把 `grep -q "provider add"` 改成对 ANSI 清洗后的字符串做包含检查。

具体实施时：通过 `engine::flush` 把渲染字节写到 stdout，同时子屏在 render 末尾写一行"语义信息"到 stderr 或一个独立 buffer，e2e 通过 `2>&1` 仍可抓到。

## 13. 性能

- 子屏普遍 < 30 行 × 80 列 ≈ 2400 Cell。
- `Frame::present` 全量写入耗时 < 10ms。
- 不需要双缓冲；crossterm 在 Linux 上 alternate screen buffer 已隔离。
