## 1. 背景与目标

### 1.1 上一轮留下的三个口子

D114 把「模型自主委派」装进了 laew:`SubAgent` 单工具 + 6 类内置子 Agent + 三档
`SpawnPolicy` + 深度/并发/预算三重治理 + TUI `/agents`。但它留下的边界很明确:

| 口子 | 现象 | 本轮对策 |
|------|------|---------|
| **类型写死** | 6 类子 Agent 由 `SubAgentType` **枚举**硬编码,用户想加一个「前端审查」「数据库迁移」角色只能改源码重编译 | **F1 自定义子 Agent 类型**(定义文件即插即用) |
| **类型提示写死** | `SubAgent.parameters().agent_type.enum` 是 JSON Schema `enum` 常量,且 `tool_schema_validator` 会按 `enum` 校验 —— 任何外部类型**必然**被拒绝 | 去掉 `enum`,改自由字符串 + 描述列名册 |
| **运行态不落地** | `Governor` 作业表在内存,进程退出即丢;跨任务/跨会话无法回看「上次那个子 Agent 说了什么」,更无法在它结论上接着干活 | **F2 运行持久化 + 续跑**(`subagent_run` 表 + `history` / `resume` + 孤儿标记) |

### 1.2 本轮目标

1. 用户**只写一个 Markdown 文件**(不需要改 Rust、不需要重编译)就能定义自己的子 Agent 类型,
   并在自然语言提示词里直接点名使用(「用 `fe-reviewer` 审一下 `src/tui`」);
2. 自定义类型对模型是**自感知**的:静态提示词段、`action="list"` 快照、TUI `/agents` 三处
   与真实可用面**永不漂移**(延续 D114 的「提示词由注册表/名册程序化生成」原则);
3. 每一次子 Agent 运行**落库**(类型 / 状态 / 用量 / 产物 / 血缘),支持跨任务查询
   (`history`)与**在既有结论上继续**(`resume`),进程崩溃后的残留记录可被识别为
   `orphaned`(对齐 openclaw Restorer + Orphan Recovery 的最小可用子集);
4. 全程**向后兼容**:`LAEW_SELF_SPAWN=off` 时工具面 / 提示词 / DB 写入三者同时归零。

### 1.3 非目标

- 不做跨进程委派(A2A / ACP,知识库 L1701-L1712)—— 重量级协议层,与本轮主题正交;
- 不做真正的「暂停/恢复运行中的子 Agent」(L1739)—— 需要子 Agent 状态机序列化,
  本轮 `resume` 的语义是**基于既有结论重新发起**一个新子 Agent(血缘显式记录),不是
  恢复一个被冻结的 future;
- 不做 Workboard 式的多 Agent 共享工作板(L1745)—— 本轮只做「运行记录 + 血缘」这一层;
- 不引入新 crate(与全仓约定一致)。

## 2. 对标与设计取舍

| 维度 | claudecode | opencode | openclaw | **本轮 laew** |
|------|-----------|---------|---------|--------------|
| 类型定义载体 | 项目级 `.claude/agents/*.md` + 插件 `agents/` | 内置 Agent 列表 + 插件 | Subagent Registry(100+ 文件) | **两级 `.laew/agents/*.md`**(项目级 + 用户级) |
| 定义格式 | YAML frontmatter(13 字段)+ Markdown 正文 | 代码内定义 | 目录 + 清单文件 | **frontmatter 6 字段 + Markdown 正文**(正文 = 专属指令) |
| 工具面 | `tools` 白名单 | `deriveSubagentSessionPermission` 派生 | Registry 声明 | **`tools` 白名单 ∩ `extends` 默认 ∩ 父策略上限**(三重收窄) |
| 类型与命令关系 | agent 与 slash 命令**同一种 Command 抽象** | 分离 | 分离 | 分离但**同源发现约定**(都走 `.laew/`,共享 frontmatter 解析器) |
| 注册/生命周期 | 内存 | 内存 | Registry 持久化 | **内存作业表 + SQLite `subagent_run`**(fail-open 写) |
| 崩溃恢复 | — | — | Restorer + Orphan Recovery | **启动期孤儿标记**(`running` → `orphaned`)+ 自动 trim |
| 结论复用 | `task_id` 复用子 session | `task_id` 复用 | Workboard | **`resume`**(前序任务 + 结论作为种子上下文注入新子 Agent) |

**关键取舍**:

1. **定义文件而不是配置表**:与 D2 自定义斜杠命令(`.laew/commands/*.md`)**同构**,
   用户学一次即会两处;落盘即生效、可随仓库提交(`.laew/agents/feature-reviewer.md`
   与代码同仓演进)。
2. **正文即专属指令**:不引入模板语言。frontmatter 决定「能干什么」(工具面/继承),
   正文决定「怎么干」(提示词),两者职责不重叠。
3. **不做模板渲染**:子 Agent 的系统提示词在**每次运行**构造,正文原样注入 + 运行期
   上下文(工作目录 / 类型 id)由程序追加 —— 保持与 D114 一致的「程序拼装、模型填空」。
4. **持久化只在单一归宿写入**:`run_child` 是全仓**唯一**的子 Agent 运行入口(前台 /
   后台 / batch / resume 全部经它),所以落库钩子只写一处,天然覆盖所有路径。

### 3.1 兼容性总则(必须逐条保住)

| 场景 | 期望行为 |
|------|---------|
| `LAEW_SELF_SPAWN=off` / `LAEW_SUBAGENT_MAX_DEPTH=0` | 工具不注册、提示词不注入、**不建运行时**(DB 写入自然为零) |
| 工作目录下无 `.laew/agents/` | 名册 = 6 内置(与 D114 完全一致) |
| `LAEW_SUBAGENT_PERSIST=off` | 不写不读 `subagent_run`;`history` 返回 code 0 + `persist:false` + 空列表 |
| 老库(无 `subagent_run` 表) | `init_schema` 的 `CREATE TABLE IF NOT EXISTS` 自动补表,零迁移脚本 |
| DB 打开/写入失败 | **fail-open**:`warn!` 一次,任务链路继续(持久化是增强能力) |
| 非委派角色(QC / SessionContext / Debug / Compact) | 工具面、提示词、DB 写入三者零变化 |

## 4. F1:自定义子 Agent 类型

### 4.1 定义文件发现链(两级,对齐 D2 自定义斜杠命令)

| 级别 | 目录 | 优先级 | 用途 |
|------|------|--------|------|
| 项目级 | `{工作目录}/.laew/agents/*.md` | 低 | 随仓库提交,团队共享 |
| 用户级 | `~/.laew/agents/*.md` | **高**(同名覆盖项目级) | 个人跨项目复用 |

- 只扫**顶层**、只认 `.md`,不递归;
- **类型 id = 文件 stem**;合法字符集 = Unicode 字母数字 + `_` + `-`(复用 D2 的
  `valid_command_name` 规则,天然排除空格 / 路径分隔符 / 控制字符);
- 文件名非法 / 读取失败 / frontmatter 未闭合 → **静默跳过**(增强能力,不阻塞主流程);
- **内置类型不可被遮蔽**:`general-purpose` / `explore` / `researcher` / `plan` /
  `code-reviewer` / `operator` 同名(id 相同)文件一律忽略,并在 `/agents` 面板
  以 `skipped` 列出原因(可解释性优先于静默)。

### 4.2 frontmatter 规格

```markdown
---
label: 前端审查
description: 前端专项审查:可访问性 / 状态管理 / 渲染性能
extends: code-reviewer
tools: Read, Glob, Grep
readonly: true
---

## 你的专属职责
1. 先读 `src/tui/` 下的改动点,再对照 `docs/TUI界面与CLI渲染引擎/`;
2. 逐条给出「文件:行 -> 问题 -> 建议」,按 P0/P1/P2 分级;
3. 不修改任何文件,只输出问题清单。
```

| 字段 | 必填 | 语义 | 缺省 |
|------|------|------|------|
| `label` | 否 | 名册中文标签 | `自定义` |
| `description` | 否 | 名册描述 | 正文首个非空行截 60 字符 |
| `extends` | 否 | 继承的内置类型 id(决定默认工具面 + 提示词骨架) | `general-purpose` |
| `tools` | 否 | 工具白名单(逗号 / 空格 / 分号分隔) | `extends` 的默认工具 |
| `readonly` | 否 | `true` = 便捷只读:① `extends` 未显式给出时**默认 explore**(只读侦察骨架);② `tools` 被强制 ∩ `Read/Glob/Grep`(**声明了 `Write`/`Bash` 也会在此被剔除**,不进运行期 `dropped_tools`);③ 子 Agent 提示词追加「只读委派」边界。显式 `extends` 时尊重用户选择 | `false` |
| `name` | 否 | 显示名(日志用) | 类型 id |

未知 key **忽略**(面向未来扩展,不报错)。

### 4.3 统一类型抽象

内置与自定义必须**无差别**地走同一条组装路径,因此引入:

```rust
/// 解析后的子 Agent 类型(内置或自定义)。
pub enum ResolvedAgentType {
    Builtin(SubAgentType),
    Custom(Arc<AgentDef>),
}
```

| 方法 | Builtin | Custom |
|------|---------|--------|
| `id()` | `explore` | 文件 stem(`fe-reviewer`) |
| `label()` | `只读侦察` | frontmatter `label` / `自定义` |
| `role_hint()` | 内置场景说明 | frontmatter `description` |
| `declared_tools()` | 类型默认工具 | `tools` 白名单(缺省取 extends 默认) |
| `base_prompt(name)` | 内置完整提示词 | **extends 的内置提示词骨架** |
| `custom_body()` | `None` | 正文(专属职责段) |
| `pascal()` | `Explore` | snake/kebab -> Pascal 的 ASCII 化(`FeReviewer`;非 ASCII 全丢则回退 `Custom`) |
| `source()` | `None` | 定义文件绝对路径 |

**解析顺序**(`resolve(raw, defs)`):先内置(含历史别名,大小写 / 下划线宽松)-> 再自定义
(精确 id,大小写不敏感)。都未命中 -> `None`。

### 4.4 名册合并与策略过滤

`roster(policy)`(D114)= **内置严格子集过滤**:
`类型默认工具 ⊆ policy.allowed_tools()` 才进名册(否则 Yolo 会看到自己无权授予的
「可写」类型)。自定义类型沿用**同一规则**:

```
可见 <=> declared_tools(自定义) ⊆ policy.allowed_tools()
```

| 父角色 | 策略上限 | 自定义 `fe-reviewer`(Read/Glob/Grep) | 自定义 `patcher`(Read/Write/Bash) |
|--------|---------|--------------------------------------|-----------------------------------|
| Yolo | `Read/Glob/Grep` | 进名册 | **不进名册**(`skipped: 需要写权限`) |
| Plan / Main-Work / SubAgent-Work | 执行层全集 | 进名册 | 进名册 |

> 即便进了名册,**运行期仍会再取一次交集**收窄(防御式,与 D114 一致),
> 被剔除的工具名如实进 `report.dropped_tools`。

### 4.5 自感知三处同步(永不漂移)

| 层 | 载体 | 本轮增量 |
|----|------|---------|
| **静态身份段**(系统提示词) | `self_awareness::prompt_section` | 名册逐行追加自定义类型,标注 `(自定义)`;**关闭态零注入**不变 |
| **运行时快照** | `SubAgent(action="list")` | 新增 `custom_roster[]`(含 `source` 路径)与 `custom_skipped[]`(含原因) |
| **启动记录**(TUI) | `/agents` | 名册表新增「自定义类型」段(路径 + 工具面);`skipped` 单列 |

**prompt cache 保护**:静态段只放「会话内恒定」内容 —— 自定义类型的
`id / label / 描述 / 工具名`(文件不变则不变),**不放**文件绝对路径、剩余额度、
运行中作业等易变值(路径只在 `list` 快照与 `/agents` 面板出现)。文件改名 / 改内容后
系统提示词前缀会变化 -> 触发一次 cache 重建,这是「定义即生效」的必要代价。

### 4.6 工具契约调整(`SubAgent`)

`agent_type` 从 **JSON Schema `enum`** 改为**自由字符串**:

- 原因:`enum` 是编译期常量,无法枚举用户文件;且 `agent::tool_schema_validator`
  会按 `enum` 硬校验,自定义 id **必然**被 1001 拒绝(这是 D114 的隐藏硬编码);
- 替代:`description` 中列全 6 个内置 id + 明确「也可使用 `.laew/agents/` 下自定义
  类型 id;先用 `action="list"` 看名册」;
- 校验前移到**实现层**:`resolve()` 未命中 -> `code=1001`,message 列出**当前可用名册**
  (内置 + 自定义)与自查提示,模型据此自我纠正。

## 5. F2:运行持久化与续跑

### 5.1 表结构(`subagent_run`,`CREATE TABLE IF NOT EXISTS`)

```sql
CREATE TABLE IF NOT EXISTS subagent_run (
    run_id        TEXT PRIMARY KEY,
    session_id    TEXT NOT NULL,
    parent        TEXT NOT NULL,
    name          TEXT NOT NULL,
    agent_type    TEXT NOT NULL,
    depth         INTEGER NOT NULL DEFAULT 0,
    status        TEXT NOT NULL,
    task          TEXT NOT NULL,
    report        TEXT NOT NULL DEFAULT '',
    error         TEXT,
    tools         TEXT NOT NULL DEFAULT '[]',
    dropped_tools TEXT NOT NULL DEFAULT '[]',
    iterations    INTEGER NOT NULL DEFAULT 0,
    tool_calls    INTEGER NOT NULL DEFAULT 0,
    wallclock_ms  INTEGER NOT NULL DEFAULT 0,
    input_tokens  INTEGER NOT NULL DEFAULT 0,
    output_tokens INTEGER NOT NULL DEFAULT 0,
    origin        TEXT NOT NULL DEFAULT 'launch',
    resumed_from  TEXT,
    created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_subagent_run_session ON subagent_run(session_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_subagent_run_type    ON subagent_run(agent_type, created_at DESC);
```

字段语义:
- `status`:`running` / `ok` / `failed` / `timeout` / `cancelled` / `orphaned`;
- `origin`:`launch` / `background` / `batch` / `resume`;
- `resumed_from`:血缘 —— 本次续跑自哪个 `run_id`;
- `agent_type`:类型 id(**存 id 不存指针**),自定义定义文件删掉后历史仍可读。

设计要点:
- **不存 prompt 全文**:系统提示词可由 `agent_type + name` 重新构造,存全文是冗余且
  会放大库体积(与 D114「子 Agent 不写记忆、避免污染既有语义」的克制保持一致);
- **tools / dropped_tools 存 JSON 数组**:与 `report_json` 字段同构,便于 TUI 直接渲染。

### 5.2 写入时序(单一入口 + fail-open)

```
run_child(req, run_id)
   |- (1) insert(running)                <- 仅当 LAEW_SUBAGENT_PERSIST != off
   |- (2) 运行子 Agent(timeout / cancel / 失败语义不变)
   +- (3) update(finish: status/report/用量/工具面/耗时)
            +- DB 任何一步失败 -> warn!(一次) 后继续,绝不影响任务结果
```

- 写 `running` 行的意义:进程被杀后能识别「上次没跑完的是谁」;长任务运行中也能在
  `/agents history` 里看到进行中的作业;
- 并发安全:每次写用独立 `Arc<Db>`(复用 `Db::clone` 的「按路径重开 + PRAGMA」策略,
  避免 `database is locked`),WAL + `busy_timeout` 由既有 `pragma` 层保证;
- 同步 rusqlite 调用在 async 上下文中的代价 = 单条 INSERT/UPDATE(微秒级),
  与既有 `session_memory` 写入同一量级,不需要 `spawn_blocking`。

### 5.3 孤儿标记与自动 trim

| 机制 | 时机 | 语义 |
|------|------|------|
| **孤儿标记** | TUI 启动 bootstrap(每进程一次) | 把 `status='running' AND session_id != 当前会话` 的行改成 `orphaned`(父进程已消失,对齐 openclaw Orphan Recovery 的最小集) |
| **自动 trim** | 同 bootstrap | 保留最新 `500` 行(`LAEW_SUBAGENT_RUN_KEEP`,默认 500,`0` = 不 trim),删除更旧行;失败 fail-open |

> 只标记**非当前会话**的 `running` 行,避免误伤同一 DB 上并行运行的另一实例的活作业。

### 5.3.1 顺带修掉的 D114 缺陷:`run_id` 跨会话重号

D114 的 `run_id = sa-{pid:x}{会话内序号:04x}`,而 `/new` `/clear` 会新建 Session
(= 新建 `Governor`,序号从 1 重来)—— **同一进程内两个会话会生成相同 `run_id`**。
内存作业表各存各的,看不出来;一旦落库(主键)就是后写覆盖先写,`resume` 也可能拿到
别人的前序。

修法:`run_id = sa-{pid:x}{进程级全局序号:04x}-{会话内序号:x}`
(全局自增 `RUN_SEQ`),保证「同进程唯一 + 跨进程靠 pid 区分」。
这是 e2e/单测并行落库时**真实暴露**出来的缺陷,不是理论问题。

### 5.4 两个新 action

#### `history` —— 跨任务工作板视图(只读,零 LLM 成本)

```json
{"action": "history", "limit": 10, "agent_type": "explore", "all_sessions": false}
```

返回(节选):

```json
{"code": 0, "message": "ok", "data": {
  "persist": true, "count": 1, "scope": "session",
  "runs": [{"run_id": "sa-1a2b0003", "agent_type": "explore", "status": "ok",
            "origin": "batch", "resumed_from": null,
            "task": "统计 Cargo.toml 行数……", "report": "……(截断)",
            "wallclock_ms": 1234, "tool_calls": 2, "iterations": 3,
            "usage": {"input_tokens": 7, "output_tokens": 3},
            "created_at": "2026-09-22 12:00:00"}],
  "hint": "如需在该结论上继续,调用 SubAgent(action=\"resume\", run_id=\"…\", task=\"…\")"}}
```

- 用途:让模型在**新任务开头**就知道「上一轮谁干过什么」,从而复用结论而不是重跑
  (省钱、省时);也是 L1745 Workboard 的最小可用子集;
- `persist=false` -> `code=0` + 空列表 + message 说明持久化已关闭(不报错,避免模型
  在关闭态反复重试)。

#### `resume` —— 在既有结论上继续(血缘显式)

```json
{"action": "resume", "run_id": "sa-1a2b0003", "task": "把结论里的 P1 项展开成修复补丁"}
```

流程:(1) 取行(`4003` if 缺失)-> (2) 解析类型 id(`1001` if 类型已失效)->
(3) 治理校验(深度 / 预算 / 并发,**与 launch 同一条 `check_can_spawn` + `try_charge` 路径**)
-> (4) 组装种子上下文 -> (5) 跑新子 Agent -> (6) 落库(`origin="resume"`,
`resumed_from=旧 run_id`)。

种子上下文(user prompt 结构):

```
【任务】
<本轮 task;缺省 = 「基于前序结论,给出下一步可执行的推进(补漏 / 深挖 / 落地)」>

【前序会话(继承自 sa-1a2b0003)】
类型:explore(只读侦察)  状态:ok  完成于:2026-09-22 12:00:00
【前序任务】
<原文,截断 2000 字符>
【前序结论】
<report,截断 8000 字符>

【运行环境】……(与 D114 一致)
```

- **语义边界(写进工具描述)**:`resume` 是「带着前序上下文重新起一个子 Agent」,
  **不是**恢复一个被冻结的进程;它会**消耗一次会话预算**;
- `task` 可省略 —— 省略即「在你上次的结论上继续推进」,这正好覆盖「追问」场景;
- 工具面继承:优先沿用历史行里的 `tools`(仍会 ∩ 当前父策略,防越权),历史为空则用
  类型默认工具。

### 5.5 TUI 可视化

| 命令 | 行为 |
|------|------|
| `/agents` | 既有内容 + **自定义类型段**(id / 标签 / 描述 / 工具面 / 来源文件)+ `skipped` 项与原因 + 持久化开关状态 |
| `/agents history [N\|all]` | 读 `subagent_run` 表格化输出(run_id / 类型 / 状态 / origin / 耗时 / tokens / 时间 + 任务摘要);`all` = 跨会话;末尾给 orphaned 计数与「如何续跑」提示 |

## 6. 工具契约总表(7 action)

| action | 必填 | 语义 | 成本 |
|--------|------|------|------|
| `list` | — | 自感知快照(身份 / 工具面 / 名册(含自定义)/ 深度 / 余额 / 运行中) | 零 |
| `history` | — | 持久化运行记录(跨任务 / 跨会话) | 零(仅 DB 读) |
| `launch` | `task` | 启动 1 个子 Agent(可 `background=true`) | 1 次预算 |
| `batch` | `tasks[]` | 并行启动 ≤8 个子 Agent | N 次预算 |
| `resume` | `run_id` | 在前序结论上继续(血缘记录) | 1 次预算 |
| `result` | `run_id` | 取回后台作业结果 | 零 |
| `cancel` | `run_id` | 取消后台作业 | 零 |

信封 code 沿用 D114 全集:`0 / 1001 / 2000 / 2001 / 2002 / 2003 / 4001 / 4002 / 4003`。
新增字段(`data` 内,均为**增量**,不破坏既有解析):

| 字段 | 出现位置 | 语义 |
|------|---------|------|
| `custom_roster[]` / `custom_skipped[]` | `list` | 自定义类型名册与被忽略项 |
| `origin` | `launch` / `batch.children[]` / `resume` / `history.runs[]` | 启动来源 |
| `resumed_from` | `resume` / `history.runs[]` | 血缘 |
| `persist` | `history` | 持久化是否开启 |

7. **向后兼容**:`LAEW_SUBAGENT_PERSIST=off` 时不产生 `subagent_run` 行(用独立 DB 校验)。

测试基建配套改动(`scripts/mock_llm_server.py`,三处,均已在 e2e 中验证):
1. **`$LAST_RUN_ID` 占位符**:router 规则里可写 `"run_id": "$LAST_RUN_ID"`,mock 从
   **未截断**的最后一条 tool_result 里提取 `sa-…` 回填(截断到 600 字符会切掉 run_id,
   故单独传 `run_id_hint`);未取到则保持原样(laew 返回 `4003`,测试自然红);
2. **父/子实例计数分桶**:动态子 Agent 与发起它的 SubAgent-Work 同属

3. **子 Agent 直答**:router 场景下动态子 Agent 直接返回终答文本 —— 其工具面由

## 11. 已知边界与后续

| 边界 | 说明 | 后续 |
|------|------|------|
| `resume` != 进程恢复 | 不恢复被冻结的 future(工具执行中途的状态不可序列化) | 需要真恢复须先做子 Agent 状态机(L1739/P3) |
| 定义文件无热重载粒度 | 文件改动后**下一次**构造提示词 / 名册即生效,运行中的子 Agent 不受影响 | 已足够;如需显式刷新可加 `/agents reload`(P2) |
| 自定义类型无独立模型覆盖 | claudecode frontmatter 支持 `model` 字段,laew 全仓单 Provider 单模型 | 与 Provider 多模型方案同批(P2) |
| `history` 无全文检索 | 只按 session / type / 时间倒序 | 需要时上 FTS5(P3) |
| 跨进程并发同名会话 | 孤儿标记按 `session_id != 当前` 保守判断,极端下会漏标 | 引入实例心跳(P3) |
| 不做跨进程委派 / Workboard | 与 L1701-L1712 / L1745 同族,属协议层与协作层 | 见知识库第六轮 §11.6 |
