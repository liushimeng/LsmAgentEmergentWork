# MCP_Use 通用 MCP 服务调用工具设计与解决方案

> 关联需求:给 Agent 添加**通用性 MCP(Model Context Protocol)服务调用**工具定义以及相关功能 ——
> 由 MCP 客户端连接外部 MCP server(stdio 子进程 / Streamable HTTP),发现工具(tools/list)、
> 调用工具(tools/call)、读取资源(resources/list、resources/read),把外部服务能力接入 laew 工具面。
> 关联模块:`src/mcp/`(协议客户端层,新增)、`src/agent/tools/mcp_use/`(工具门面,新增)、
> `src/database/schema.rs` + `src/database/mcp_server.rs`(配置表 + DAO,新增)、
> `src/agent/tools/mod.rs`(注册)、`src/agent/system_prompt/`(提示词)、
> `src/agent/orchestrator/usage.rs`(TUI 摘要)、`src/main.rs`(`laew mcp` 子命令)。
> 关联测试:`src/mcp/tests.rs`、`src/agent/tools/mcp_use/tests.rs`、`src/database/mcp_server.rs` 迁移/DAO 测试、
> `testReport/run_e2e.sh` mcp 节 + `scripts/mock_mcp_server.py`。
> 调研基础:`docs/Agent源码调研/专题/专题-MCP架构深度分析.md`(6 工程 MCP 横向对比)、
> `docs/其他Agent工具定义/claude-code/CC_ListMcpResourcesTool.md` 等 MCP 工具定义、
> `docs/Agent源码调研/atomcode.md` MCP 7 子模块(三锁设计 / 命名 sanitize / HTTP 头约束)。

---

## 1. 背景与目标

### 1.1 现状与动机

laew 的工具面目前只有**内置本地工具**(Bash / Read / Write / Edit / Glob / Grep / TodoWrite /
SubAgent / emit 系)与两个 **MCP 风格命名的本地工具**(`MCP_Web_Use` 浏览器、`MCP_Window_Use`
桌面窗口)——后者是「单工具 + action 分发」的本地驱动封装,**并不实现 MCP 协议**:
`src/` 无 JSON-RPC、无 MCP 握手、无外部 MCP server 连接能力(知识库
`专题-MCP架构深度分析.md` laew 现状行:`MCP | 三种 transport + OAuth + Catalog | 无(自建 Bash/Read/Write)`).

这意味着 laew 无法接入 MCP 生态的现成服务(文件系统 / 数据库 / 搜索 / 设计工具 / 企业内部 API 等),
每个外部能力都要在 `src/agent/tools/` 手写一个驱动 —— 扩展成本与生态脱节。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **协议客户端** | 实现 MCP 客户端最小闭环:`initialize` 握手 → `tools/list`(分页)→ `tools/call` → `resources/list` / `resources/read` |
| **双传输** | stdio(本地子进程,覆盖 90%+ 场景)+ Streamable HTTP(远程服务) |
| **通用调用工具** | 单工具 `MCP_Use` + action 枚举分发(对齐 `MCP_Web_Use` / `MCP_Window_Use` 全家惯例),Agent 用一个工具调遍所有已配置 MCP server 的全部工具与资源 |
| **配置持久化** | SQLite `mcp_servers` 表 + `laew mcp add\|list\|del\|test` CLI,与 `providers` 表同等待遇 |
| **生命周期治理** | 懒连接 + 请求超时 + 指数退避重连(稳定性窗口)+ `kill_on_drop` 防子进程泄漏 |
| **结果归一化** | content blocks 四类(text/image/resource/其他)统一投影为文本,永不静默丢弃;大结果截断防护 |
| **安全边界** | http 端点复用 `url_safety` SSRF 校验;stdio command 来源仅限用户 CLI 显式配置(信任模型);敏感 header 落库经 `Vault` 加密 |
| **零回归可回退** | `LAEW_MCP_ENABLED=off` 时工具注册与提示词同时归零,行为与本轮之前完全一致 |

### 1.3 本轮不做(列入后续演进)

| 项 | 原因 |
|----|------|
| **展开式工具**(`mcp__{server}__{tool}` 每工具独立注册) | 需要动态 ToolRegistry 两阶段同步(Fetch→Swap)+ 轮间 `refreshTools`,涉及 agent_loop 工具面热更新重构;网关式 `MCP_Use` 已可完整调用全部 MCP 工具,展开式作为 P1 演进(见 §8) |
| OAuth / 需认证远程 server 自动注册 | 过早引入 OAuth 是知识库风险清单第一条;http 传输先支持静态 header(可含 `Authorization`)注入 |
| MCP prompts → Skill 桥接 | 仅 Claude Code 一家实现,收益待验证 |
| 双向 MCP(server 反向调用 client)/ Elicitation | 协议复杂度高,laew 暂无该场景 |
| tool_result 多模态(image block 注入上下文) | laew 工具结果通道当前是纯文本(`Tool::execute -> Result<String>`),image 降级为文本描述;多模态注入需动统一消息模型,单独立项 |
| SSE 旧版传输(`sse` 独立端点)/ WebSocket | Streamable HTTP 已覆盖新 server;旧 SSE server 少见,按需后补 |

## 2. 协议核心(JSON-RPC 2.0)

MCP 消息全部是 JSON-RPC 2.0 帧(`docs/Agent源码调研/专题/专题-MCP架构深度分析.md:33`):

```jsonc
// 请求
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"read_file","arguments":{"path":"a.txt"}}}
// 成功响应
{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"..."}],"isError":false}}
// 错误响应(JSON-RPC 层)
{"jsonrpc":"2.0","id":1,"error":{"code":-32601,"message":"Method not found","data":null}}
// 通知(无 id,单向)
{"jsonrpc":"2.0","method":"notifications/initialized"}
```

### 2.1 方法清单(本轮实现)

| method | 方向 | 请求 params | 响应 result |
|--------|------|-------------|-------------|
| `initialize` | C→S | `{protocolVersion, capabilities, clientInfo}` | `{protocolVersion, capabilities, serverInfo, instructions?}` |
| `notifications/initialized` | C→S | —(通知) | — |
| `tools/list` | C→S | `{cursor?}` | `{tools:[{name,description,inputSchema,annotations?}], nextCursor?}` |
| `tools/call` | C→S | `{name, arguments}` | `{content:[ContentBlock], isError?}` |
| `resources/list` | C→S | `{cursor?}` | `{resources:[{uri,name,description?,mimeType?}], nextCursor?}` |
| `resources/read` | C→S | `{uri}` | `{contents:[{uri,mimeType?,text?\|blob?}]}` |
| `ping` | C→S | `{}` | `{}`(保活,重连后探测) |

要点(均来自知识库调研):

- **协议版本**:`protocolVersion` 发 `"2025-03-26"`(稳定修订版);initialize 响应回什么就在后续
  HTTP 请求的 `MCP-Protocol-Version` 头里 echo 什么(`atomcode.md:992-1012` 的 negotiate 约束);
- **分页**:`tools/list` / `resources/list` 响应可带 `nextCursor`,客户端 do/while 游标循环取全量
  (DeepSeek `syncTools` 形态,`专题-MCP架构深度分析.md:885-893`);**客户端侧折叠分页**,
  `MCP_Use` 的 `list_tools` 一次返回全量,不让模型处理 cursor;
- **容错解析**:`description` 缺失当空串、`annotations` 全字段可选、未知字段忽略
  (OpenCode `TolerantListToolsResultSchema` 精神,`opencode.md:846`);
- **isError 语义**:工具业务失败是**响应里的 `isError:true`**,不是 JSON-RPC error ——
  两者都归一为 `MCP_Use` 的 2002 信封,附 human-readable content + machine-readable error.code
  (DeepSeek 双信封惯例,`deepseek-harness.md:3723`);
- **ContentBlock 投影**(永不静默丢弃,`专题-MCP架构深度分析.md:954-965`):

| type | 投影 |
|------|------|
| `text` | 原样透传 |
| `image` | 降级文本 `"[image mime={mimeType} bytes≈{n} 已省略 base64]"` |
| `resource` / `resource_link` | 降级文本(取 uri / mimeType / 文本摘要) |
| `audio` / 其他 | 降级文本 `"[unsupported content type: {type}]"` |

### 2.2 传输层

**stdio**(主路径,NDJSON 行帧):

- ⚠️ MCP stdio 传输是**换行分隔 JSON**(每条消息一行,消息内不得含裸换行),
  **不是** LSP 的 `Content-Length` 头帧 —— 与 `atomcode` 的 LSP 参考实现不同,勿抄帧格式;
- `tokio::process::Command` + `Stdio::piped()` ×3,`kill_on_drop(true)` 子进程泄漏兜底;
- **单请求锁**序列化 req/rsp 配对(AtomCode 三锁的简化:laew 无跨任务并发复用同一 server 连接的
  场景,MCP_Use 自身 `parallel_safe=false`,一把 Mutex 足够,`专题-MCP架构深度分析.md:1302-1305`
  的 laew 简化建议);
- stderr 单独收集(上限 4KB 环形)供失败归因,不让子进程因 stderr 管道写满阻塞;
- spawn 失败(命令不存在等)→ 3001 信封 + 引导,不 panic。

**Streamable HTTP**(远程路径):

- `POST {url}` 单请求;`Accept: application/json, text/event-stream`(双 MIME 必备,
  `atomcode.md` 常量 `MCP_HTTP_ACCEPT`);
- `Content-Type: application/json`;initialize 之后每请求 echo `MCP-Protocol-Version`;
- stateful server 在 initialize 响应头给 `Mcp-Session-Id`,之后**每请求 echo**
  (`atomcode.md` `HttpClient.session_id` 形态);
- 响应两种形态:`application/json` 直接是 JSON-RPC 响应帧;`text/event-stream` 则扫描
  SSE `data:` 行,取**第一个 id 匹配**的响应帧(通知帧跳过);
- 复用 `crate::llm::build_http_client(url)`(TLS 三级策略:IP 主机自动放宽自签证书,
  `LAEW_TLS_INSECURE` 全局开关,`llm/mod.rs:51-71`)—— 自建 HTTPS 网关场景零重复实现;
- URL 过 `agent::safety::url_safety::is_safe_endpoint` SSRF 校验(私网默认拦截,
  `LAEW_ALLOW_PRIVATE_ENDPOINT=1` 放行本地 mock / 内网服务);
- 通知类消息 POST 后期待 2xx 即可,无响应体要求。

## 3. 总体架构

```
Agent(SubAgent-Work / Main-Work)
  └── MCP_Use 工具(src/agent/tools/mcp_use/)          ← 工具门面:action 分发 + JSON 信封
        └── McpManager(src/mcp/manager.rs)            ← 连接缓存 + 懒连接 + 退避冷却
              └── McpClient(src/mcp/client.rs)        ← 握手 / 调用 / 分页折叠 / 结果投影
                    └── dyn McpTransport(src/mcp/transport.rs)
                          ├── StdioTransport(子进程 NDJSON)
                          └── HttpTransport(Streamable HTTP + SSE 解析)
        └── SQLite mcp_servers(src/database/mcp_server.rs)  ← server 配置(CLI 维护)
```

**分层原则**(知识库建议,`专题-MCP架构深度分析.md:1415-1422`):MCP 是**可选能力层**,封闭在
`src/mcp/` + `src/agent/tools/mcp_use/`,不侵入 `agent_loop.rs` 核心循环;协议差异、传输差异
全部沉在 `McpClient` 以下,工具层只做参数校验 / action 分发 / 信封组织 —— 与
`MCP_Web_Use`(CDP 封在 `agent::browser`)、`MCP_Window_Use`(AX/UIA 封在 `agent::window`)同构。

### 3.1 工具暴露形态决策:网关式(单工具)

6 工程调研结论(`专题-MCP架构深度分析.md` C 节):**工具用展开式、资源用网关式**是实际共识;
但展开式的三个前提(laew 当前均不满足,或满足成本高)是:

1. **动态工具注册**:`ToolRegistry` 构建后只读(`tools/mod.rs:111-171`),展开式要求
   server 上/下线时两阶段同步(Fetch→Swap)热更新工具面 —— 需要重构 agent_loop 的 tools 注入;
2. **contiguous prefix 保 prompt cache**:Claude Code 教训(`claudecode.md:1341-1343`)——
   动态 MCP 工具插入内置工具之间会让 Anthropic 断点缓存全体失活;laew 第 121 轮刚落
   system 三段式缓存,不能引入随机排序源;
3. **per-tool Schema 精度**是展开式的核心优势(`claudecode.md:1349`:schema 缺失把错误率
   5.4%→51%),但 `MCP_Use` 的 `call_tool` 通过 `list_tools` 先取回**完整 inputSchema 文本**
   再调用,模型同样能看到精确参数定义(两跳发现,一次调用成本略高但 schema 不丢)。

因此本轮采用**网关式 `MCP_Use`**(对齐 laew 既有 `MCP_*_Use` 单工具 + action 全家惯例,
且天然适配 SubAgent 工具白名单 `subset()` 收窄)。展开式列为 P1(§8),前提是先解决
registry 热更新 + cache 前缀守恒两个基建问题。

### 3.2 角色持握面

| 角色 | 是否持 `MCP_Use` | 理由 |
|------|------------------|------|
| **SubAgent-Work**(builtin_registry) | ✅ | 执行层最小单元,外部能力的实际调用方 |
| **Main-Work**(main_work_registry) | ✅ | 编排层可用 `list_tools` / 只读 `call_tool` 探查外部服务形态,再决定怎么拆(对齐第 122 轮 MCP_Web_Use 探查先例) |
| Yolo | ❌ | 入口层信息收集面已含 Read/Glob/Grep/MCP_Web_Use;外部服务调用不做意图判断依据 |
| Plan | ❌ | 规划层读文件即可,不扩大权限面 |
| Quality-Check | ❌ | 判定层不执行外部动作 |
| SessionContext / Debug / Compact | ❌ | 无工具角色不变 |

WorkFlow 角色走 `sub_agent_work_registry()` 自动获得(与 MCP_Web_Use 同路径)。

## 4. `MCP_Use` 工具定义

### 4.1 Schema(json! 内联,对齐 `mcp_web_use/mod.rs:581-656` 风格)

```jsonc
{
  "name": "MCP_Use",
  "description": "通用 MCP 服务调用入口:连接外部 MCP server,发现并调用其工具、读取其资源。…",
  "input_schema": {
    "type": "object",
    "properties": {
      "action": { "type": "string", "enum": ["list_servers","connect","list_tools","call_tool","list_resources","read_resource","close"] },
      "server": { "type": "string", "description": "MCP server 名称(mcp_servers.name);list_servers 可省略" },
      "tool":   { "type": "string", "description": "action=call_tool 必填:目标工具名(用 list_tools 返回的原始 name)" },
      "arguments": { "type": "object", "additionalProperties": true, "description": "action=call_tool 转交 tools/call 的参数对象" },
      "uri":    { "type": "string", "description": "action=read_resource 必填:resources/list 返回的 uri" },
      "timeout_ms": { "type": "integer", "minimum": 1000, "maximum": 600000, "description": "可选,覆盖 server 默认超时" }
    },
    "required": ["action"],
    "additionalProperties": false
  }
}
```

**Schema 硬约束**(踩坑记录,`tool_schema_validator.rs:8` 会在 execute 前预校验):

- 动态值(server 名 / 工具名)一律**自由字符串,禁止进 enum** —— 否则 validator 硬拒
  (SubAgent `agent_type` 先例,`tools/mod.rs:421-425` 单测钉死);
- `arguments` 必须是 `additionalProperties: true` 的自由对象 —— MCP 工具入参是任意 JSON Schema。

### 4.2 action 语义与信封

统一 `{code, message, data}` 信封(与 MCP_Web_Use / SubAgent 同构,模型按 code 机械决策):

| action | 参数 | data 返回 | 说明 |
|--------|------|-----------|------|
| `list_servers` | — | `{servers:[{name, transport, endpoint, enabled, status}]}` | 配置总览 + 当前连接状态,永不失败(读库) |
| `connect` | `server` | `{status, serverInfo, capabilities, tool_count, instructions?}` | 显式握手(懒连接下通常不需要,失败重试前可显式重连) |
| `list_tools` | `server` | `{tools:[{name, description, inputSchema, readOnly}]}` | 自动折叠 nextCursor 分页;未连接自动 connect |
| `call_tool` | `server, tool, arguments?` | `{isError, content:[{type,text}], elapsed_ms}` | 执行外部工具;结果 content 投影 |
| `list_resources` | `server` | `{resources:[{uri, name, description?, mimeType?}]}` | 自动折叠分页 |
| `read_resource` | `server, uri` | `{contents:[{uri, mimeType?, text?}]}` | blob 降级文本标注 |
| `close` | `server` | `{closed:true}` | 显式断开(stdio 杀子进程 / http 清 session) |

**错误码**(独立编码段 5xxx,与 MCP_Web_Use 2xxx / SubAgent 4xxx 不混):

| code | 含义 | 模型对策 |
|------|------|----------|
| `0` | 成功 | — |
| `1001` | 参数错误 / 未知 action | 修正参数(全工具共享) |
| `5001` | server 未配置 / 未找到 | `list_servers` 看名册后重试 |
| `5002` | 连接失败 / 断连 / 冷却中 | `connect` 重连;冷却中按 `retry_after_ms` 等待 |
| `5003` | 握手失败(协议/能力协商不通过) | 换 server 配置或报告用户 |
| `5004` | 超时 | 加大 `timeout_ms` 或改小任务粒度 |
| `5005` | 工具调用失败(isError / JSON-RPC error) | 读 `data.error_code` + content 自修复参数重试 |
| `5006` | 资源读取失败 / uri 不存在 | `list_resources` 重同步 uri |
| `3001` | 环境缺失(command 不存在 / 未装运行时) | 引导安装,不盲重试(对齐 MCP_Web_Use 3001) |

`isError=true` 的 tools/call 归 **5005**(业务失败可见、可修参重试),JSON-RPC `error`
对象同归 5005 并透传 `error.code`;连接层失败归 5002 —— 模型可区分「重连有用」与「重连没用」。

### 4.3 description 与提示词

description 按 `MCP_WEB_USE_PROMPT_SECTION` 先例写全(action 签名 + 错误码对策 + 标准作业顺序
+ 安全红线);详细作业规范单独成 `MCP_USE_PROMPT_SECTION`,挂 `sub_agent_work()` 与
`main_work()` 的 `append_base()`。为遵守「单文件 ≤1800 行」(`system_prompt/mod.rs` 现 1621 行),
提示词段落常量放新子模块 `system_prompt/mcp_use_hint.rs`。`sub_agent_tools_hint()` /
`main_work_tools_hint()` 各加一行工具清单。

标准作业顺序(写入 description):

1. `action=list_servers` 看有哪些 server(或用户已点名 server 时跳过);
2. `action=list_tools` 取工具清单与 inputSchema;
3. 按 inputSchema 组装 `arguments`,`action=call_tool` 调用;
4. 需要只读数据源时用 `list_resources` / `read_resource`;
5. 长会话不再用该 server 时 `close` 释放。

## 5. 数据模型与 CLI

### 5.1 SQLite `mcp_servers` 表(`database/schema.rs` 追加,IF NOT EXISTS 零迁移)

```sql
CREATE TABLE IF NOT EXISTS mcp_servers (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    name          TEXT NOT NULL UNIQUE,
    transport     TEXT NOT NULL CHECK(transport IN ('stdio','http')),
    command       TEXT,                 -- stdio:可执行文件
    args          TEXT NOT NULL DEFAULT '[]',   -- stdio:JSON 数组
    env_json      TEXT NOT NULL DEFAULT '{}',   -- stdio:JSON 对象(注入子进程环境)
    url           TEXT,                 -- http:Streamable HTTP 端点
    headers_enc   TEXT,                 -- http:JSON 对象,经 Vault 加密存储
    enabled       INTEGER NOT NULL DEFAULT 1,
    timeout_ms    INTEGER NOT NULL DEFAULT 30000,
    created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_mcp_servers_name ON mcp_servers(name);
```

约束:`transport='stdio'` 时 `command` 必填(DAO 写入校验);`transport='http'` 时 `url` 必填。
敏感 header(`Authorization` 等)经 `crate::agent::safety::Vault` 加密落 `headers_enc`
(对齐 providers.api_key 的 D9-4 先例,`database/provider.rs:73,88`)。

### 5.2 CLI `laew mcp`

```
laew mcp add --name <n> --transport stdio --command <cmd> [--args '<JSON数组>'] [--env '<JSON对象>'] [--timeout-ms N]
laew mcp add --name <n> --transport http  --url <url> [--header 'K: V']... [--timeout-ms N]
laew mcp list
laew mcp del <id|name>
laew mcp test <id|name>       # initialize 握手 + tools/list 验证连通性后断开
```

与 `laew provider` 子命令并列(`main.rs` 命令枚举),复用 `open_db()`。`--header` 可重复;
落库前整包 Vault 加密。

## 6. 生命周期与容错

### 6.1 连接状态(懒连接)

`McpManager` 进程级单例(`OnceLock`),`HashMap<name, ConnEntry>`:

```
Idle →(首次 use)Connecting → Connected ⇄(传输错)Broken →(退避后重试)Connecting
                              ↓(握手失败)
                            HandshakeFailed(需显式 connect / 改配置)
```

- **懒连接**:`list_tools` / `call_tool` 等在无连接时自动 connect(对模型透明);
  `WaitForMcpServers` 式显式等待工具(暂不需要:网关式单工具每跳都是同步等待);
- **请求锁**:每连接一把 `tokio::sync::Mutex`,串行化 req/rsp 配对,杜绝响应错配;
- **请求超时**:`timeout_ms`(server 配置,默认 30s;`call_tool` 可覆盖),整体
  `tokio::time::timeout` 包裹,超时归 5004 并**销毁连接**(半开连接不可复用)。

### 6.2 重连退避(DeepSeek 稳定性窗口简化版)

```rust
pub struct BackoffPolicy { initial_delay_ms: u64 = 500, max_delay_ms: u64 = 30_000, max_attempts: u32 = 10 }
// delay(n) = min(max_delay_ms, initial_delay_ms * 2^(n-1))  → 500,1s,2s,…,30s 封顶
// 连接存活 ≥ max_delay_ms 后 failed_attempts 归零(稳定性窗口,防长期稳定后的偶发断连被累积放弃)
// failed_attempts > max_attempts → 进入冷却,信封 5002 + retry_after_ms,直到显式 connect 或进程重启
```

`专题-MCP架构深度分析.md:1110-1120`:稳定性窗口重置是 DeepSeek 独有精妙点,laew 采纳。

### 6.3 子进程泄漏防护

StdioTransport 持 `tokio::process::Child`,`kill_on_drop(true)` + `close()` 显式 `start_kill()`
(对齐 OpenCode finalizer 简化版,`专题-MCP架构深度分析.md:725-736`);Drop 时兜底 kill。
`close` action / 进程退出两条路径都保证子进程不残留。

## 7. 安全边界

| 面 | 措施 |
|----|------|
| **stdio 命令注入** | `command` / `args` 仅来自 `laew mcp add` 显式配置(用户信任决策),**不**接受 LLM 运行时传入 —— `MCP_Use` 全 action 无 command 参数;argv 数组直传不经 shell(对齐第 88 轮 osascript argv 教训) |
| **SSRF** | http `url` 过 `url_safety::is_safe_endpoint`(私网/CGNAT/metadata 默认拦,`LAEW_ALLOW_PRIVATE_ENDPOINT=1` 放行) |
| **凭证** | `headers_enc` Vault(AES-256-GCM)加密;日志/TUI 摘要只见 header 名不见值;信封不回显 header |
| **大结果** | 单次 content 投影总文本超 `MAX_RESULT_CHARS`(24000 字符)中间截断(保头尾),标注省略量 —— 防外部 server 返回撑爆上下文 |
| **子进程环境** | `env_json` 显式注入白名单环境变量(叠加在清理后的基础 env 上),不继承多余宿主环境 |
| **权限面** | 工具只进 SubAgent-Work / Main-Work(§3.2);`LAEW_MCP_ENABLED=off` 全关 |

MCP server 本体是**用户配置的可信进程/端点**(与 Claude Code / AtomCode 同信任模型);
LLM 无法新增 server,只能调用已配置 server 暴露的工具 —— 攻击面收敛为「server 自身越权」,
由 server 侧负责(知识库风险清单:信任模型必须显式声明)。

## 8. 可观测与后续演进

- **TUI `[tool]` 摘要**:`usage.rs::tool_args_digest` 加 `MCP_Use` 分支 →
  `action=X server=Y tool=Z uri=U`(值截 ≤30 字符);
- **LoopGuard**:`MCP_Use` 无 wait 类 action,`wait_like()` 保持不变(进展键含结果摘要,
  轮询外部状态合法重复零误伤的设计不受影响);
- **HintRole**:不进 `used_ui`(MCP 调用不是 UI 任务,落 `Execute`,避免收到浏览器文案);
- **`parallel_safe`**:恒 `false`(外部进程/HTTP 会话共享连接,批次内保序串行)。

**P1 演进**(本轮决策不做,理由见 §1.3 / §3.1):

1. 展开式 `mcp__{server}__{tool}` + 两阶段同步 + contiguous prefix 保 cache(需 registry 热更新基建);

3. OAuth / needs-auth 状态机(404 + `-32001` session 过期检测,L1060);
4. tool_result image block 注入(需统一消息模型多模态扩展);
