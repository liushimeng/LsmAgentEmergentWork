# TUI 界面自动化测试方案(tmux control-mode)

## 1. 背景与目标

`laew` 是一个 **TUI 优先** 的 Rust Agent CLI。主屏 `REPL` 与子屏 `/provider *` 系列走
`crossterm` 原始模式 + 全屏重绘(`engine::present`)，存在大量"非文本输入可断言"
的视觉元素：

- 顶部边框 + 屏标题(子屏用,例如 `/provider list`、`/provider add`、`/provider del`)
- 行内提示(hint)、Tab 高亮、按钮聚焦
- API Key 脱敏(`****<末4位>`,仅编辑态显示明文)
- Tab 表单 5+1 步操作、`Esc` 退出子屏回到主屏
- 主屏横幅:`根目录 / 工作目录 / 当前模型 / Session`
- 终端尺寸自适应(`tmux resize-window -x 80 -y 24`)

直接往 stdin 管道喂命令(`printf '...' | laew`)只能验证**主屏的纯文本行读取**回退分支,
**覆盖不到子屏(raw mode / alternate screen)**。本工程在
`src/tui/mod.rs::run` 中已经显式做了 `atty()` 分流:TTY → `InputHandler` 全交互,非 TTY
→ 阻塞式行读取。这意味着管道测试断言子屏(`/provider list`、`/provider add`)只能用
非 TTY 的 print 回退文本,**不是真实渲染结果**,验证效力低。

## 2. 方案对比

| 方案 | 跨语言 | Ubuntu Server 原生 | 子屏渲染可断言 | 输入模拟精度 | 推荐度 |
|------|--------|--------------------|----------------|---------------|--------|
| 管道喂命令 `printf | laew` | ✅ | ❌ 子屏回退 print | 仅文本行 | ⭐ |
| Rust `pty` crate 自测 | ❌ 内嵌 | ✅ | ✅ | ✅ | ⭐⭐ |
| Python `pexpect` | ❌ Python | ✅ | ✅ | ✅ | ⭐⭐ |
| `expect` + `script(1)` | ❌ TCL | ✅(需安装) | ✅ | ✅ | ⭐⭐ |
| **`tmux` control-mode** | ✅ 任何语言调用 shell | ✅ `apt install tmux` | ✅ | ✅(send-keys) | ⭐⭐⭐⭐⭐ |

**结论:使用 `tmux control-mode` 作为 TUI 自动化测试的推荐方案。**

理由:

1. **零依赖注入**:不要求在 laew 工程内引入 `pty`/`expect` 等测试 crate,保持产物精简。
2. **真实渲染**:`tmux` 会话内的 `laew` 处于真实 PTY 之下,`atty()` 为 true,会进入
   `InputHandler` 全交互分支,子屏走 `alternate screen + raw mode + engine::present` 的真实路径。
3. **可视化调试**:失败时直接 `tmux attach -t <sess>` 可肉眼回放,定位效率远高于管道日志。
4. **CI 友好**:`tmux` 是 Ubuntu Server / Debian / macOS / WSL 的标配(或 `apt install tmux`
   即可),CI 容器一条 `apt-get install -y tmux` 就能跑。
5. **跨 Agent 工具可用**:Claude Code / Codex / Hermes / OpenCode 等只要能调用 shell
   都能使用同一套命令,无需绑定特定语言或框架。

## 3. tmux control-mode 命令速查

> `control-mode` 是 tmux 内置的交互协议,允许外部进程以文本命令控制会话。日常脚本
> 用 `send-keys` / `capture-pane` / `resize-window` 这些普通子命令即可,无需启用
> `control-mode` 套接字 —— 这是常见误解。控制台脚本只依赖标准子命令。

| 用途 | 命令 |
|------|------|
| 创建后台会话并启动程序,固定尺寸 | `tmux new-session -d -s laew_e2e -x 100 -y 30 "$LAEW"` |
| 列出所有会话 | `tmux list-sessions` |
| 发送文本按键(整串字面量) | `tmux send-keys -t laew_e2e -l "/provider list"` |
| 发送单键回车 | `tmux send-keys -t laew_e2e Enter` |
| 发送 Esc | `tmux send-keys -t laew_e2e Escape` |
| 发送方向键 | `tmux send-keys -t laew_e2e Down` / `Up` / `Left` / `Right` |
| 发送 Tab | `tmux send-keys -t laew_e2e Tab` |
| 调整尺寸 | `tmux resize-window -t laew_e2e -x 80 -y 24` |
| 抓取面板输出到 stdout(`-p` print) | `tmux capture-pane -p -t laew_e2e` |
| 抓取面板并保留 ANSI 转义 | `tmux capture-pane -p -e -t laew_e2e` |
| 把抓取内容拷贝到 buffer | `tmux capture-pane -t laew_e2e; tmux show-buffer` |
| 判断会话是否还活着 | `tmux has-session -t laew_e2e` |
| 杀会话 | `tmux kill-session -t laew_e2e` |

### 3.1 关键参数说明

- `-d`: detached,不等 TUI 退出立刻返回,适合脚本编排。
- `-s <name>`: 会话名,断言失败/调试都用得到。
- `-x -y`: 启动时的列/行,代替手动 `resize-window`。**建议设一个能装下子屏边框的
  尺寸**(`-x 100 -y 30`),过窄会被自动折行影响断言。
- `send-keys -l <text>`: `-l` 表示把后面的参数当字面量,**多字符文本必须加 `-l`**,
  否则 tmux 会尝试把 `/provider` 当 key 名(通常无害但有 warning)。
- `capture-pane -p`: 把抓取结果直接打到 stdout,**无需 `show-buffer`**。
- `capture-pane -e`: 保留 ANSI;做字符串包含断言时**建议省略 `-e`**,避免颜色码干扰。

## 4. run_e2e.sh 封装设计

新增 "TUI 子屏自动化测试" 小节。封装层级:

```
run_e2e.sh
└── tmux helpers (case 8)
    ├── tnew <name> [size]   # 创建会话,返回会话名
    ├── tsend <text>         # send-keys -l 文本
    ├── tkey <key>           # send-keys 单键(Enter / Escape / Down / ...)
    ├── tresize <w> <h>      # resize-window
    ├── tscreen [-e]         # capture-pane -p
    └── texpect <pat> <label>[timeout]  # 轮询直到 tscreen 包含 pat 或超时
```

### 4.1 上下文与隔离

- **复用既有 `/tmp/laew-e2e-root`**:`LAEW=/tmp/laew-e2e-root/laew`,
  根目录 = `/tmp/laew-e2e-root`,TUI 自动加载这里的 `LsmAgentEmergentWork.db`,
  **不污染真实配置**(沿用 run_e2e.sh 已有的隔离模式)。
- **依赖前置**:tmux TUI 小节放在**管道冒烟(原 7)** 之后、**provider delete(原 8)**
  之前,确保 mockA / mockO 两条记录都还在 → `/provider list` 可断言有 2 条记录。
- **清理 trap**: `trap 'tmux kill-session -t "$TSESS" 2>/dev/null || true' RETURN`,
  保证即使断言失败也会关掉 tmux 会话,不污染系统。

### 4.2 等待策略

子屏渲染是事件驱动:`send-keys` → 事件循环 poll → 重绘。脚本侧必须**轮询断言**而
非"发完立刻读"。

```bash
texpect() {  # $1=pattern $2=label [${3:-timeout_sec}]
  local pat="$1" label="$2" timeout="${3:-3}"
  local deadline=$((SECONDS + timeout))
  while [ "$SECONDS" -lt "$deadline" ]; do
    if tscreen | grep -F -q -- "$pat"; then
      check 0 "$label"; return 0
    fi
    sleep 0.1
  done
  check 1 "$label"; tscreen | sed 's/^/    | /' | tee -a "$REPORT"; return 1
}
```

`grep -F` = 固定串(避免 `.*` 等被解释),`-q` = 静默退出码。失败时把当前面板抓回
报告,便于排查。

### 4.3 用例矩阵

| # | 操作 | 关键 `send-keys` | 关键断言 |
|---|------|------------------|----------|
| 1 | 启动横幅 | `tnew laew_e2e_tui -x 100 -y 30; texpect "根目录" "横幅显示根目录"` | "根目录"、"Session"、"当前模型" |
| 2 | `/model` | `tsend "/model"; tkey Enter` | "当前模型" |
| 3 | `/provider list`(进入子屏) | `tsend "/provider list"; tkey Enter` | "/provider list"(边框标题) |
| 4 | `Esc` 退出子屏 | `tkey Escape` | "/provider list" 消失,主屏 `>>` 提示或"再见"提示之类 |
| 5 | `/provider add`(Tab 表单) | `tsend "/provider add"; tkey Enter` | "/provider add"(标题) + hint "← → 切换 Tab" |
| 6 | `Esc` 退出 add | `tkey Escape` | "/provider add" 消失 |
| 7 | `/provider del` 进入 picker | `tsend "/provider del"; tkey Enter` | "/provider del"(标题) + "请选择要删除" |
| 8 | `Esc` 退出 picker | `tkey Escape` | "/provider del" 消失 |
| 9 | 终端尺寸 80×24 | `tresize 80 24; sleep 0.3` | 仍能抓取到"根目录"或主屏内容 |
| 10 | `/exit` 退出 TUI | `tsend "/exit"; tkey Enter` | `tmux has-session` 失败或一段时间后消失 |

### 4.4 失败容忍与跳过

```bash

else

  # ... 实际用例
fi
```

CI 镜像若未带 tmux,整节 skip,不影响其它 9 节通过。

## 5. 断言策略与常见坑

- **断言必须用 `grep -F` 固定串**,不要用正则;子屏里大量 `│` `─` `║` 等制表符
  容易被 shell 通配解释。
- **断言方向**:先 `texpect` 期望内容,再用 `texpect` 期望它**消失**,双向验证
  避免假阳性(例如标题可能因为重绘时机残留)。
- **resize 之前 `sleep 0.1`**:给 `engine::present` 一次重绘机会。
- **避免在断言里使用 `MOCK_FINAL_ANSWER` 等 mock 关键词**:TUI 测试不依赖 mock LLM,
  是纯客户端 / 渲染层验证。
- **`/provider use <id>` / `/new` 等不需要子屏的操作仍走管道冒烟**(原 7),不要
  重复迁到 tmux,增加维护成本。
- **ANSI 颜色**:默认 `capture-pane -p`(不带 `-e`)输出不含 ANSI,**已自动 strip**,
  无需 `sed 's/\x1b\[[0-9;]*m//g'`。
- **`send-keys` 输入 `/exit`**:确认后 TUI 在 stdout 打印 "再见。" 并退出,
  tmux 检测到子进程退出后自动销毁会话 → `has-session` 失败 → 测试通过。
  这是天然的退出断言,无需额外 sleep。

## 7. 扩展指引

- **新增子屏断言**:在 `src/tui/screen/*` 找到 `fn title() -> &str` 的返回值,
  直接断言该字符串即可(title 字段设计意图就是可断言锚点)。
- **新增交互路径**:用 `tnew` 多个会话隔离场景(例:`tnew t1 ... ; ...; tnew t2 ...`),
  不需要串行复用。
- **录制可视化样例**:`tmux capture-pane -p -e -t laew_e2e_tui > snapshot.txt`,
  失败回放时 `cat snapshot.txt` 即可看到带颜色的真实渲染。
- **改用 control-mode 套接字**(可选):如果将来要驱动更复杂的交互(例如连续按键序列
  录制),可以 `tmux -CC new ...` 或 `tmux new -d -L laew_sock`,本设计不强制。
