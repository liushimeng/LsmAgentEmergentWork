## 1. 背景与问题

laew 当前是**纯中央编排**的多 Agent 架构:`MultiAgentOrchestrator` 持有 10 个 Runner,
按 Yolo 分类的三档链路(simple → SubAgent;medium → Main-Work → SubAgent;
hard → Plan → Main-Work → SubAgent)静态派发,`SubAgentRunner` 的数量、职责、工具集
全部在编译期写死。

对照知识库的横向对比表,缺口集中在四处:

| 缺口 | 现状 | 知识库参照 |
|------|------|-----------|
| **无「模型自主启动子 Agent」通道** | 只有 Orchestrator 能创建执行单元,LLM 循环内没有任何委派工具(claudecode `Agent` / opencode `TaskTool` / atomcode `TaskTool` 均缺失) | claudecode AgentTool、opencode TaskTool、第六轮 §16 对比表「**禁止(无 task 工具)**」 |
| **Agent 无自感知** | 每个角色的系统提示词是**手写常量**:不知道自己实际持有哪些工具、不知道有哪些兄弟角色、不清楚自己还能委派多少 | codex/pi 的 ToolRegistry 自省(CC03)、claudecode `subagent_type` 枚举 |
| **子 Agent 类型单一** | 只有一种「全工具执行者」,没有只读侦察 / 资料研究 / 代码审查等特化角色,用户说「并行调研」时无法按需组建小队 | opencode 6 个内置 Agent、claudecode 4 种 `subagent_type` |
| **动态启动无治理** | 无深度限制 / 无会话级预算 / 无并发信号量 / 无后台作业句柄(第六轮 §2.2 四条缺口全部命中) | atomcode `Semaphore(3)`、openclaw `DEFAULT_SUBAGENT_MAX_SPAWN_DEPTH=1`、deepseek `delegationDepth` |

### 1.1 用户可见的问题(需求原点)

用户输入「启动 3 个 SubAgent,分别调研 A / B / C 三个模块的实现并汇总差异」时:

1. Yolo 把它压成一句 `goal_summary`,「启动 3 个 SubAgent」的指令被静默丢弃;
2. SubAgent 只会单线程地一个个做,三个模块的调研无法并行;
3. 用户看不到「谁被启动、跑了多久、花了多少 token」;
4. 想再追加「再开一个 Agent 查 D」时,系统没有「再启动一个」的入口。

**目标**:让 Agent 具备「自感知 + 按需启动子 Agent」的能力 —— 用户通过**自然语言提示词**
即可让系统动态组建子 Agent 小队并汇总结果,同时把知识库里的调度治理
(深度/并发/预算/取消/用量)一并补齐。

## 2. 设计目标与非目标

### 2.1 目标

1. **自感知(Self-Awareness)**:每个 Agent 明确知道「我是谁 / 我持有哪些工具 /
   我能启动哪些类型的子 Agent / 我还剩多少额度」——静态部分进系统提示词,
   动态部分由工具 `SubAgent(action="list")` 按需查询。
2. **动态启动(Dynamic Spawn)**:新增 Agent Tool `SubAgent`(单工具 + action 枚举,
   与 `MCP_Window_Use` / `MCP_Web_Use` / `TodoWrite` 风格一致),支持
   `launch` / `batch` / `list` / `result` / `cancel` 五个动作。
3. **按提示词自启动**:系统提示词写死「何时该启动、如何启动、如何汇总」的契约,
   用户提示词显式出现「启动 SubAgent / 并行 / 分工 / 分别调研 / 多个 Agent」等
   意图时必须用 `batch` 启动;单步任务禁止启动(防白付成本)。
4. **调度治理**:1 层嵌套默认(可配)、会话级并发信号量(默认 3)、会话级启动预算
   (默认 8)、单子 Agent 迭代上限(默认 12)、超时(默认 300s)、取消级联、
   用量台账(计入 `/cost`)。
5. **可观测**:子 Agent 启动/完成事件环形缓冲 + `tracing` 日志 + TUI `/agents` 命令;
   子 Agent 复用同一 LLM 客户端 → `-debug` 模式的 trace 采集**零改动自动覆盖**。

### 2.2 非目标(本轮明确不做)

| 项 | 原因 |
|----|------|
| 跨进程 SubAgent(ACP / A2A / SDK) | 第六轮 §11.6 P3,与外部协议绑定,非本需求 |
| 崩溃后 resume / 持久化调度表 | 第六轮 §11.5 P2,需要 `workflow_run` 表迁移,独立轮次 |
| 子 Agent 独立模型 / 独立 Provider | 当前架构 llm 客户端单例注入,扩 provider 见后续轮次 |
| 子 Agent 结果直接写 Session 主流 | 会污染主上下文,与 SessionContext 摘要机制冲突 |
| Shell/写文件的额外沙箱层 | 复用现有 `sandbox_hook` + 工具集交集策略(见 §5.4) |

## 4. 架构总览

```
                       ┌──────────────── 自感知三层 ────────────────┐
                       │ ① 静态身份(系统提示词)                     │
profile.rs ────────────┤   由注册表**程序化生成**:身份 / 工具清单 /  │
  spawn_policy         │   可启动子 Agent 名册 / 启动规则 / 上限     │
                       │ ② 运行时快照(SubAgent action="list")       │
self_awareness.rs      │   深度 / 剩余额度 / 并发上限 / 运行中作业   │
                       │ ③ 启动记录(事件环形缓冲 + /agents)         │
                       └────────────────────────────────────────────┘

用户提示词
   │
   ▼
Yolo(入口层,ReadOnly 子)| Plan / Main-Work(编排层,Full 子)| SubAgent-Work(执行层,Full 子)
   │  LLM 循环内出现 tool_use{ name: "SubAgent", input: {action: ...} }
   ▼
tools/subagent.rs::SubAgentTool.execute()
   │  ① 从 tokio task-local 取本次运行的 SubAgentRuntime(无 → 4001,不静默降级)
   │  ② 解析 + 校验请求(action / 类型 / 工具收窄 / 上限)
   ▼
dynamic_subagent.rs::SubAgentRuntime
   │  ③ 治理:深度检查 → 预算扣减 → 信号量取槽 → 取消 token 派生
   │  ④ 组装子 profile:类型提示词 + 工具集(交集)+ 叶子自感知段 + UA 名
   │  ⑤ 运行:Agent::run_session_cancellable(全新 Session,父 session_id 复用)
   │  ⑥ 回收:usage 计入会话台账 / 事件入环形缓冲 / 报告回填 tool_result
   ▼
SubAgentReport(JSON 信封)→ 父 Agent 汇总 → 最终回答
```

### 4.1 与既有链路的关系

- **不改变** Orchestrator 三档主链路,不动 `SubAgentRunner` 的单元执行语义;
- 动态子 Agent 是「**执行层内部再拆一层**」的能力,失败**不触发** Yolo 失败回流
  (子 Agent 失败由父 Agent 就地处理:自己补做或改派);
- `-debug` / `-f` / `-p` / TUI 四种入口共用同一实现,无需分支;
- 子 Agent 与工作目录、沙箱、工具行为**完全一致**(同一 `builtin_registry_with_work_dir`)。

## 5. 详细设计

### 5.1 自感知模型(`src/agent/self_awareness.rs`)

#### 5.1.1 配置(环境变量,全部带默认值,零配置即生效)

| 变量 | 取值 | 默认 | 语义 |
|------|------|------|------|
| `LAEW_SELF_SPAWN` | `off`/`0`/`false`/`no` | 开 | 关闭动态启动:不注册 `SubAgent` 工具、不注入自感知段、不建运行时(完全零开销) |
| `LAEW_SUBAGENT_MAX_DEPTH` | 0..=3 | 1 | 允许的嵌套层数;0 = 完全禁止启动 |
| `LAEW_SUBAGENT_MAX_PARALLEL` | 1..=8 | 3 | 会话级并发槽位(对齐 atomcode `Semaphore(3)`) |
| `LAEW_SUBAGENT_MAX_TOTAL` | 1..=64 | 8 | 会话级累计启动预算(防失控) |
| `LAEW_SUBAGENT_MAX_ITERATIONS` | 4..=32 | 12 | 单个子 Agent 的迭代上限 |
| `LAEW_SUBAGENT_TIMEOUT_SECS` | 10..=3600 | 300 | 单个子 Agent 墙钟超时 |

#### 5.1.2 子 Agent 类型名册(6 种)

| id | 定位 | 类型默认工具 | 典型场景 |
|----|------|-------------|---------|
| `general-purpose` | 通用执行者 | 全套执行层工具 | 写代码 / 跑命令 / 多步改造 |
| `explore` | 只读侦察 | Read / Glob / Grep | 定位文件、搜索符号、读代码给结论(只读,零副作用) |
| `researcher` | 资料研究 | Read / Glob / Grep / MCP_Web_Use | 网页检索 + 资料整理 |
| `plan` | 方案设计 | Read / Glob / Grep / Write | 产出实施步骤 / 风险清单(落盘方案) |
| `code-reviewer` | 代码审查 | Read / Glob / Grep | 审查实现问题、给出 P0-P2 清单 |
| `operator` | GUI / 浏览器操作 | Bash / Read / MCP_Web_Use / MCP_Window_Use | 需要真实操控浏览器或桌面窗口 |

#### 5.1.3 静态身份段(注入系统提示词,**由注册表程序化生成**)

> 关键设计:**工具清单不是手写常量,而是从 `ToolRegistry::names()` 读取**——
> 对齐知识库 CC03「ToolRegistry 自省」,提示词与实际工具面永不漂移。

```markdown
## 自感知:你的身份与可启动的子 Agent
- 你的身份:<profile.name>(<角色定位>)
- 你当前持有的工具:<ToolRegistry::names() 实时拼接>
- 你可启动的子 Agent 类型:<roster,受 SpawnPolicy 过滤>
- 启动规则:<6 条契约,见 §6>
- 硬上限:本会话最多 8 个 / 并发 3 / 深度 1 层 / 单子 Agent 12 轮
```

**prompt cache 友好性**:该段落**只含会话内恒定内容**(不含「剩余额度」等易变值),
因此整个 run 内 system 前缀稳定,不触发 `cache_control` 断点失效;
易变值只在 `action="list"` 的返回值里给出。

> 实现注记:启动规则文案与名册渲染**同处一地**(`self_awareness::prompt_section`),
> 不另设 `system_prompt` 内的重复常量 —— 单一事实源,避免「提示词说了、工具没做」的漂移。
> `system_prompt/mod.rs` 只负责给 4 个角色的**工具说明**补一行 `SubAgent` 入口,
> 以及给 Yolo 补「decomposition_plan 必须原样保留用户的多 Agent 要求」。

### 5.2 `SubAgent` 工具协议(`src/agent/tools/subagent.rs`)

单工具 + `action` 枚举分发。Schema 见下表(与 `MCP_*` 单工具风格一致)。

| 字段 | 适用 action | 说明 |
|------|------------|------|
| `action`(必填) | 全部 | `launch` / `batch` / `list` / `result` / `cancel` |
| `task` | launch / batch.tasks[] | 子 Agent 任务描述(**必须自包含**) |
| `agent_type` | launch / batch.tasks[] | 6 种类型之一,默认 `general-purpose` |
| `name` | 同上 | 子 Agent 名称(日志/报告/UA 用,默认由类型派生) |
| `system_prompt` | 同上 | 追加到子 Agent 系统提示词的额外指令(可选) |
| `tools` | 同上 | 限定工具名(**只能收窄**,超出父能力自动剔除并在报告里提示) |
| `expected_output` | 同上 | 期望产出(拼进子任务 prompt) |
| `max_iterations` | 同上 | 4..=32,默认取全局配置 |
| `background` | launch | `true` = 立即返回 `run_id`,稍后用 `result` 取回 |
| `tasks` | batch | 子任务数组(≤8),每项字段同上 |
| `max_concurrency` | batch | 1..=3,默认会话并发上限 |
| `run_id` | result / cancel | 目标作业句柄 |

#### 5.2.1 统一 JSON 信封(对齐 `MCP_Window_Use` / `MCP_Web_Use`)

| code | 语义 | 处理建议(写进 `message`) |
|------|------|--------------------------|
| 0 | 成功 | — |
| 1001 | 参数非法(缺 task / 未知 action / 未知类型) | 修正参数后重试 |
| 2000 | 子 Agent 执行失败(LLM 错误 / 早终止 / 超时) | 报告含 `status` 与失败摘要,父 Agent 决定补做或改派 |
| 2001 | 会话级启动预算耗尽 | 停止委派,自己完成剩余工作 |
| 2002 | 深度超限(叶子 Agent 尝试再启动) | 停止委派 |
| 2003 | 并发槽位等待超时 | 减少并行数或稍后重试 |
| 4001 | 当前上下文不支持动态启动(无运行时 / 功能被关闭) | 不要重试,直接用现有工具完成任务 |
| 4002 | 已取消 | 立即停止 |
| 4003 | `run_id` 不存在 | 用 `action="list"` 查有效句柄 |

#### 5.2.2 成功报告(`launch` 单子 Agent)

```json
{"code":0,"message":"ok","data":{
  "run_id":"sa-3f2a11","name":"侦察-A","agent_type":"explore","status":"ok",
  "tools":["Read","Glob","Grep"],"dropped_tools":["Write"],
  "text":"<子 Agent 最终回答,截断到 8000 字符>",
  "usage":{"input_tokens":1200,"output_tokens":340},
  "iterations":3,"tool_calls":5,"wallclock_ms":4210}}
```

`batch` 在 `data.children[]` 给出逐子报告,`data.text` 为**带小标题的合并文本**
(每个子 Agent ≤4000 字符,合计 ≤12000 字符,防上下文爆炸)。

### 5.3 运行时(`src/agent/dynamic_subagent.rs`)

#### 5.3.1 运行时如何到达工具:task-local 作用域

`Tool::execute(&self, args)` 没有 llm / session / cancel 句柄,而**工具对象是共享的**
(并行 WorkFlow 单元共享 `Arc<SubAgentRunner>` → 共享同一 `AgentProfile` 与
`ToolRegistry`),因此**不能把运行时可变地绑到工具实例上**(会跨任务串味)。

方案:用 `tokio::task_local!` 承载 `Arc<SubAgentRuntime>`,在
`Agent::run_session_inner` 外层建立作用域:

```rust
async fn run_session_inner(&self, session, cancel) -> Result<(String, Usage, ExecutionTrace)> {
    match dynamic_subagent::runtime_for(self, session, cancel) {
        Some(rt) => dynamic_subagent::scope(rt, self.run_session_body(session, cancel)).await,
        None => self.run_session_body(session, cancel).await,
    }
}
```

- 原循环体**原样**改名为 `run_session_body`(纯机械改名,零语义变更);
- `tokio::task_local` 随任务隔离:并行单元各自 `tokio::spawn` → 各自作用域,互不干扰;
- 测试路径 / 未开启功能 → `runtime_for` 返回 `None`,**零开销直通**。

#### 5.3.2 运行时继承(子 → 孙的治理共享)

```rust
// 顶层:无父作用域 → 新建会话级治理器
Governor::global(session_id, cfg)   // Semaphore + 预算 + 作业表 + 事件环 + usage 台账
// 子 Agent:run_session_body 内再次进入 run_session_inner → 命中父作用域 → derive_child
SubAgentRuntime::derive_child(llm, profile, cancel)  // depth + 1,共享同一 Governor
```

深度为 0 的运行时 `can_spawn = max_depth >= 1`;深度 ≥ `max_depth` 时:

1. **组装期**:子 profile 的注册表**剔除** `SubAgent` 工具(叶子模型根本看不到该工具);
2. **运行期**:即使模型幻觉出 `SubAgent` 调用,运行时二次校验直接返回 2002(双重防御,
   对齐 opencode「`subagent_depth` + task deny 兜底」)。

**depth 不重复自增**:`run_child` 会为子 Agent 显式建立作用域(名字 = 作用域属主),
`runtime_for` 命中「属主同名」时**原样复用**该作用域(而非再派生一次),
否则 `max_depth=2` 时子 Agent 的可见深度会变成 2 → 明明有工具却永远 2002。
实现见 `dynamic_subagent::runtime_for` 的两个分支,并有 `runtime_inherits_governor_and_increments_depth` 单测钉死。

#### 5.3.3 治理与回收

| 环节 | 实现 |
|------|------|
| 并发 | `Governor.sem: Arc<Semaphore>(max_parallel)`;`launch` 取槽(60s 超时 → 2003);`batch` 用 `futures::stream::buffer_unordered(max_concurrency)` |
| 预算 | `AtomicUsize` CAS 扣减,`>= max_total` → 2001;报告里明示「已用 N / 上限 M」 |
| 嵌套 | `depth + 1 > max_depth` → 2002 |
| 超时 | `tokio::time::timeout(timeout_secs, child_run)` → `status:"timeout"` |
| 取消 | 父 `CancelToken` 的 `child_token()` 传给子 Agent;父循环取消 → 子 `run_session_cancellable` 即时返回(既有 H9 链路) |
| 后台 | `tokio::spawn` + 作业表 `HashMap<run_id, JobEntry>`(状态槽 + JoinHandle + 子 token) |
| 用量 | `Governor.usage: Mutex<Usage>`;子 Agent 汇总 usage 后累加;任务边界 `drain_usage(session_id)` 计入任务总用量 |
| 事件 | `Governor.events: Mutex<VecDeque<SubAgentEvent>>`(上限 64),供 `list` / TUI `/agents` 读取 |
| 日志 | 每次启动/完成 `tracing::info!`(agent / run_id / type / status / ms / tokens),与既有运行日志同格式 |

### 5.4 能力边界与权限(安全设计)

新增 `AgentProfile.spawn_policy: SpawnPolicy` 三档:

| 角色 | SpawnPolicy | 子 Agent 可用工具(**上限**) |
|------|-------------|---------------------------|
| Yolo(入口,只持 Read) | `ReadOnlyChildren` | Read / Glob / Grep |
| Plan / Main-Work / SubAgent-Work / WorkFlow | `FullChildren` | 全套执行层工具 |
| Quality-Check / SessionContext / Debug / Compact | `Disabled` | 不注册 `SubAgent` 工具 |

**收窄规则**(对齐 opencode `deriveSubagentSessionPermission`):

```
child_tools = (请求 tools ∩ 类型默认 tools) ∩ 策略上限      // 交集,只能收窄
if child_tools.is_empty() { child_tools = 策略上限 }        // 地板:不会造出零工具 Agent
剔除项写入报告 dropped_tools,让父 Agent 知道「能力被削」而不是静默失败
```

同时:

- 子 Agent **不继承**父的对话上下文(全新 Session),避免信息越界与上下文爆炸;
- 子 Agent 复用父 `session_id`(仅用于追踪/日志),但**不写** `session_memory` / `agent_memory`;
- 写操作仍走既有 `sandbox_hook` 白名单(工作目录 + 临时目录),**不新增**任何绕过路径;
- `SubAgent` 工具**不注册**给 Quality-Check / SessionContext / Debug / Compact —— 质检与会话
  收口角色必须保持单线程语义。

## 6. 提示词触发契约(用户提示词 → 自动启动)

写进 4 个角色的系统提示词(`SELF_SPAWN_RULES`):

1. **触发条件**:任务可分解为 2+ 个**相互独立**子任务,或用户提示词显式出现
   「启动 SubAgent / 多开几个 Agent / 并行 / 分工 / 分别调研 / 同时处理 / 各写一份」等意图;
2. **禁止条件**:单步任务、有严格前后依赖的任务、需要你自己看中间结果再决策的任务
   —— 直接自己做,不要启动(启动 = 多付一次 LLM 成本);
3. **批量优先**:多个独立子任务**一次** `SubAgent(action="batch", tasks=[...])`,批内自动并行;
   有依赖关系则分次 `launch`;
4. **任务自包含**:子 Agent 看不到你的上下文,`task` 必须写明「目标 + 输入路径 + 期望产物 + 验收口径」;
5. **结果必汇总**:子 Agent 的输出只是中间产物,必须由你整合成面向用户的最终回答,
   禁止只回答「已委派给若干 SubAgent」;
6. **失败不掩盖**:子 Agent 失败时如实说明失败子任务与原因,并给出你自己补做或改派的结果。

### 6.1 三个典型提示词 → 行为映射

| 用户提示词 | Agent 行为 |
|-----------|-----------|
| 「启动 3 个 SubAgent 分别调研 A/B/C 模块并汇总差异」 | `batch` + `agent_type=explore` ×3 → 合并文本 → 汇总回答 |
| 「并行让两个 Agent 各写一份实现 + 一份测试」 | `batch` + `agent_type=general-purpose` ×2 |
| 「你现在有哪些能力?能启动哪些 Agent?」 | `action="list"` → 如实转述身份/工具/名册/额度 |

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 模型滥用启动 → token 成本失控 | 会话预算 8 + 并发 3 + 深度 1 三重上限;提示词明确「单步任务禁止启动」;`LAEW_SELF_SPAWN=off` 一键关闭 |
| 并行子 Agent 同时写同一文件 | 与既有同层并行 WorkFlow 同级风险;提示词要求 batch 子任务「相互独立、不写同一路径」;写操作仍受沙箱约束 |
| 子 Agent 递归爆炸 | 叶子不注册工具 + 运行时 2002 双重防御 |
| 子 Agent 结果撑爆父上下文 | 单子报告 text ≤8000 字符、batch 合并 ≤12000 字符,超长截断并标注 |
| 用量统计漏记 | 会话级台账 + 单元/任务两级 drain;`/cost` 自动包含 |
| 作用域泄漏到非目标 Agent | `task_local` 按任务隔离;QC/SessionContext/Debug/Compact 策略 Disabled 且不注册工具 |
| 与既有 e2e mock 冲突 | mock 的 prompt-router 已支持任意工具名透传(非白名单工具不改写参数),新增用例用独立规则 + 独立 session |
| Yolo 因 forced tool_choice 当轮无法委派 | 已披露的边界(§11):Yolo 声明了 `emit_tool`,forced 生效时模型必须直接返回分类;仅在 `LAEW_FORCED_TOOLS=off` 或 Provider 拒绝 forced 自动降级 auto 时才可先侦察再分类 |

## 11. 已知边界与后续

| 边界 | 说明 | 后续 |

| Yolo 的 forced tool_choice | Yolo 声明 `emit_tool` → forced `tool_choice` 生效时模型必须当轮返回 `submit_task_classification`,**无法**同轮调用 `SubAgent`;仅在 `LAEW_FORCED_TOOLS=off` 或 Provider 拒绝 forced 自动降级 auto 时可用 | 需要「先侦察再分类」时应改为两轮预算(P2) |
