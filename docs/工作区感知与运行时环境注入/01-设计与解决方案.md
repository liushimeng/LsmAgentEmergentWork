## 1. 背景与问题

laew 原本唯一的「环境感知」是 `src/agent/project_context.rs`：按五级链找说明文件
（CLAUDE.md → AGENTS.md → README.md → 自动生成 → 空），把「工作目录 + 说明文件正文」
注入成一条 `<<<LAEW:PROJECT_CONTEXT>>>` 消息，插在会话上下文 index 0。

对照知识库横向对比表，缺口有五：

| 能力 | claudecode | openclaw | pi | laew 改造前 |
|------|-----------|----------|-----|------------|
| 平台 / OS / 日期 / 架构 | ✅ 系统提示词内置 | ✅ | ✅ | ❌ |
| Git 分支 / HEAD / 最近提交 | ✅ | ✅ | ✅ 三路冗余 | ❌ |
| 工作区未提交变更 | ✅ | ✅ | ✅ | ❌ |
| 工程类型 / 工具链推断 | ✅ | ✅ | ✅ | ❌ |
| 顶层结构 / 最近改动文件 | ✅ | ✅ | ✅ | ❌ |

且**注入只到 Yolo 入口层**：真正调用 Bash 的 SubAgent-Work 拿不到任何环境信息，
只能靠 `ls` / `cat` 试探工程类型，常猜错构建命令（`npm test` vs `cargo test`），
也不知道「今天几号、平台是 Linux 还是 macOS」，易生成跨平台不兼容命令。

## 2. 设计原则：懒刷新派，零新增 crate

知识库给出的三派分歧与结论（第十八轮合集 §维度 4）：

- **hot watcher 派**（claudecode / openclaw / pi）：chokidar / fs.watch 主动监听；
- **事件总线派**（deepseek-harness）：工具结果驱动 `invalidate()`，无 watcher 依赖；
- **lazy refresh 派**（atomcode 主动放弃 hot refresh、opencode 被动检测）。

laew 取**懒刷新 + 进程级 TTL 缓存**：不做文件监听（不引入 `notify`，遵守工程依赖约定），
采集结果同时服务三类消费方；磁盘真相以「工具调用」为准（快照显式声明可能滞后）。

## 3. 架构

```
workspace::snapshot(work_dir)      真实采集:git CLI + walkdir + 顶层 read_dir
        │
        ├─ cached_snapshot()       进程级 TTL 缓存(默认 5s / LAEW_WORKSPACE_TTL_SECS)
        │      └─ hint_block()     → agent/mod.rs::run_session_inner 拼到 system 末尾
        │                            8 角色(含 SubAgent)每次 LLM 调用可见
        │
        ├─ render_section()        → project_context::build_message 会话级注入(Yolo)
        │                            <<<LAEW:PROJECT_CONTEXT>>> 内新增「工作区快照」段
        │
        ├─ change_marker()         → tui/dispatch.rs 任务前后对比,打印 [工作区] 变更 N → M
        └─ snapshot()              → tui/mod.rs 横幅状态行 + /workspace 命令
```

### 3.1 采集字段

| 字段 | 来源 | 约束 |
|------|------|------|
| `platform` / `today` | `std::env::consts` / `time` crate 本地时区 | 零子进程 |
| `is_git` / `branch` / `head` | `git status --porcelain=v1 -b` + `git log -3 --format=%h %s` | 2s 超时；非零退出码 = 非仓库 |
| `staged` / `modified` / `untracked` | porcelain 首两列分类（`??` / `X ` / ` Y`） | 逐行解析 |
| `projects` | 顶层标记文件表（11 类：Rust / Python / Node / Go / Maven / Gradle / Make / CMake / Ruby / PHP / 容器） | 每类带建议构建 / 测试命令 |
| `dirs` / `file_count` / `notable_files` | 顶层 `read_dir`（跳过 `.git`） | 目录 ≤12，文件 ≤6 |
| `recent_files` | `walkdir` depth ≤2 + mtime 6h 窗口 | 忽略 16 类构建 / 依赖目录，扫描条目 ≤4000，展示 ≤5 |

### 3.2 子进程安全：`run_capture`

std 无 `wait_timeout`，而「先 `try_wait` 再读管道」在输出超过管道缓冲（64KB）时
会死锁。实现用**独立线程持续排空 stdout** + 主线程每 5ms 轮询 + 到期 `kill`：

```rust
pub fn run_capture(program, args, cwd, timeout) -> Option<(bool, String)>
pub fn run_with_timeout(...) -> Option<String>   // 仅退出码 0 时返回
```

超时 / 启动失败 / 非 UTF-8 一律 `None`，调用方静默降级（`is_git=false` 等），
绝不阻塞 TUI。超时路径**不 join 读取线程**（kill 后句柄 drop 即 detach），
避免孙进程持有管道时永久阻塞。

### 3.3 注入点一：会话级（Yolo）

`project_context::build_message` 在说明文件正文之后追加：

```
### 工作区快照(系统自动采集)
- 工作目录: /path/to/proj
- 平台 / 日期: linux/x86_64 / 2026-09-13
- 工程类型: Rust(标记 Cargo.toml;构建 `cargo build` / 测试 `cargo test`)
- Git: 分支 main @48e5bc5 · 未提交 3 个(暂存 1 / 修改 1 / 未跟踪 1)
- 最近提交:
  - 48e5bc5 test(提示词库): ...
- 顶层结构: src/ docs/ (共 42 个文件)
- 最近改动(6 小时内):
  - src/tui/mod.rs (12 分钟前)
- 说明: 以上为系统自动采集的工作区状态,可能略滞后于磁盘;涉及精确状态请用工具核对。
```

**触发条件放宽**：由「有说明文件」改为「有说明文件 **或** 工作区非空」——
无 Markdown 但为 git 仓库 / 有工程标记的目录也会注入（`is_trivial()` 定义空目录：
非 git 且无工程标记且无任何顶层条目）。空目录语义保持不变（不注入）。

### 3.4 注入点二：全角色运行时 brief（执行层首次可见）

`agent/mod.rs::run_session_inner` 组装 system 的位置：

```rust
let workspace_hint = crate::agent::workspace::hint_block();   // TTL 缓存,空目录为空串
let runtime_hints  = build_runtime_hints(&trace, consecutive_failures);
let system = if workspace_hint.is_empty() && runtime_hints.is_empty() { base_system }
             else { format!("{base_system}{workspace_hint}{runtime_hints}") };
```

brief 形如（约 120 字符 ≈ 35 token）：

```
<<<LAEW:WORKSPACE>>>
[系统注入·运行环境快照](非用户输入,可能略滞后于磁盘)
工作区: /path | 工程: Rust | git: main @48e5bc5 · 3 未提交
建议命令: 构建 `cargo build` / 测试 `cargo test` | 平台: linux/x86_64 | 日期: 2026-09-13
<<<END>>>
```

- 与既有 `<<<LAEW:RUNTIME_HINTS>>>` 同一位置（system 末尾），不破坏 cache_control 前缀策略；
- **不修改** `build_runtime_hints()` 本体，其「全 0 返回空串」单测契约保持；
- 8 角色（Yolo / Plan / Main-Work / SubAgent-Work / QC / SessionContext / Debug / Compact）全生效。

### 3.5 注入点三：TUI 状态显示与变更感知

1. **横幅**新增一行：`工作区 : [Rust] git:main · 3 未提交`（空目录显示「空目录(不注入环境信息)」）。
2. **`/workspace [refresh]`**（别名 `/ws`）：打印完整快照段；`refresh` 强制失效 TTL 缓存重采集，
   便于用户核对「模型看到的运行环境」。
3. **任务前后自动对比**：`dispatch_prompt` 执行前取 `change_marker`，任务结束后再取一次，
   分支切换 / 未提交数变化 / 新增变更文件三种情况才打印，例如：

   ```
   [工作区] 未提交变更 2 → 3(+1): sandbox-ok.txt
   ```

   同时 `invalidate()` 缓存，让下一轮注入的 brief 反映任务后的真实状态（自动感知闭环）。
