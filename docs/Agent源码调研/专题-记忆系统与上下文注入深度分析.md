## 2. 记忆分层架构

### 2.1 TencentDB-Agent-Memory：L0-L3 四层管线模型

TencentDB-Agent-Memory 是 5 个仓库中**分层最清晰、抽象最完整**的记忆系统：

```
┌──────────────────────────────────────────────────────────────────┐
│ L3 Persona Generator — 渐进式画像（增量分析变化场景）           │
│   └── Trigger: 50 条记忆 / L2 完成 / [PERSONA_UPDATE_REQUEST]    │
│   └── Output: persona.md（全局用户/项目画像）                    │
├──────────────────────────────────────────────────────────────────┤
│ L2 Scene Extractor — 场景块抽取 + LLM 沙箱直写                  │
│   └── 八阶段流水线：备份 → 索引 → prompt → LLM 执行 → 软删除   │
│   └── 三档容量警告（MERGE / 禁止 CREATE / 建议 UPDATE）          │
│   └── workspaceDir 物理隔离（scene_blocks/）                     │
├──────────────────────────────────────────────────────────────────┤
│ L1 Writer — 结构化记忆 + 7 种类型 + DedupDecision 4 态决策      │
│   └── DedupDecision { store/update/merge/skip } + target_ids[]   │
│   └── Vec dual-write（JSONL 主 + vec0 向量从，graceful degrade）│
│   └── version 乐观锁递增（maxVersion + 1）                       │
├──────────────────────────────────────────────────────────────────┤
│ L0 Recorder — 对话录制（JSONL 按日分片）                        │
│   └── 双保护：originalUserMessageCount 位置切片 + afterTimestamp │
│   └── 污染消息替换（originalUserText → 被污染的 user 消息）     │
│   └── 消毒三重过滤：sanitizeText + stripCodeBlocks + shouldCapture │
└──────────────────────────────────────────────────────────────────┘
```

#### 2.1.2 DedupDecision 四态决策

```typescript
// l1-writer.ts:154-163
export interface DedupDecision {
  record_id: string;
  action: "store" | "update" | "merge" | "skip";
  target_ids: string[];   // 多目标合并支持
  merged_content?: string;
  merged_type?: MemoryType;
  merged_priority?: number;
  merged_timestamps?: string[];
}
```

| action | 行为 | 向量存储 |
|--------|------|---------|
| `store` | 追加新记录 | `upsertL1(record, embedding)` |
| `update` | 删除 target + 写新记录 | 先 `deleteL1Batch` 再 `upsertL1` |
| `merge` | 删除多 target + 写合并记录 | 同上 |
| `skip` | 什么都不做 | 无操作 |

#### 2.1.3 Version 递增算法

```typescript
// l1-writer.ts:191-200
let nextVersion = 0;
if ((decision.action === "update" || decision.action === "merge") && decision.target_ids.length > 0 && vectorStore) {
  try {
    const existing = await vectorStore.queryL1Records({ recordIds: decision.target_ids });
    const maxVersion = existing.reduce((max, row) => Math.max(max, row.version ?? 0), 0);
    nextVersion = maxVersion + 1;
  } catch (err) {
    logger?.warn?.(`Failed to read existing memory version, defaulting to v0`);
  }
}
```

**关键设计**：基于已有 target_ids 的 maxVersion + 1，update/merge 后版本递增，store 从 0 起。

#### 2.1.4 Vec Dual-Write 与 Graceful Degradation

```typescript
// l1-writer.ts:313-351
if (vectorStore) {
  try {
    let embedding: Float32Array | undefined;
    if (embeddingService) {
      try {
        embedding = await embeddingService.embed(record.content);
      } catch (embedErr) {
        logger?.warn(`[vec-dual-write] Embedding FAILED for id=${record.id}`);
        // 不抛错, 仅写 metadata + FTS, 跳过 vec0
      }
    }
    const upsertOk = await vectorStore.upsertL1(record, embedding);
  } catch (err) {
    logger?.warn?.(`[vec-dual-write] FAILED (JSONL already written)`);
    // 向量写失败不阻塞 JSONL 已写入的记录
  }
}
```

**核心原则**：JSONL 追加先行（source of truth），向量写入异步重试；embedding 失败时仅写 metadata + FTS，跳过 vec0——保证记忆可写性与一致性。

**关键设计**：
- **`is_active(at_time)`**：时序有效性窗口，通过比较 `at_time` 与 `valid_from`/`valid_until` 判断节点/边在特定时间是否有效——这是 BiTemporalFact 模型的应用

#### 2.3.2 双删除语义

```python
# semantica/context/context_graph.py:569-590
# 双删除语义：
# - retraction: 仅关闭实体的 valid_until 窗口（可恢复，保留实体）
# - tombstone: 彻底清除（保留清除记录，不保留内容）
self._retractions: Dict[Tuple[str, str], Dict] = {}  # (entity_kind, entity_id)
self._tombstones: Dict[Tuple[str, str], Dict] = {}
```

| 模式 | 行为 | 可恢复 | 数据保留 |
|------|------|--------|---------|
| **retraction** | 仅设置 `valid_until` | ✅ 是 | 实体完整保留，仅关闭时间窗口 |
| **tombstone** | 清除内容 | ❌ 否 | 仅保留清除记录（who/when/why），不保留内容 |

**laew 借鉴价值**：当前 SQLite 的 `DELETE` 等同于 tombstone 但丢失清除记录。借鉴 retraction 模式可让 laew 的工具调用结果在「用户撤回」时保留历史（agent_memory.artifacts 已存）。

#### 2.3.3 时序解析函数

```python
# semantica/context/context_graph.py:203-231
def _parse_iso_dt(value: str) -> Optional[datetime]:
    """Parse an ISO datetime string into a tz-naive UTC datetime.

    Supported formats (in priority order):
        - Year-only shorthand:  "1990"  → "1990-01-01"
        - Date-only:            "1990-06-15"
        - Full ISO (with tz):   "1990-06-15T00:00:00+00:00" / "...Z"
        - Full ISO (naive):     "1990-06-15T00:00:00"

    Returns None on failure; callers must treat the node as Always-Active.
    """
```

**设计要点**：4 种 ISO 格式逐层尝试，失败时返回 None，调用方将其视为"始终有效"——**优雅降级**而非崩溃。

### 2.4 jiuwenswarm：渐进树 + Evolution Overlay

jiuwenswarm 的 Symphony 记忆系统采用**离线 + 在线双层架构**：

```
Symphony 离线构建                                Symphony 在线检索
─────────────────                                ──────────────────
SymphonyGraphBuilder                             Progressive Tree Retrieval
├── scan skills_root                             ├── apply tag filters
├── compute capability_hashes                    ├── start visible subtree
```

#### 2.4.2 Progressive Tree 检索算法

```markdown
## Progressive Tree Retrieval
Input: query, tree root, top_k

Process:
1. apply request tag filters to catalog leaves and prune empty tree branches
2. start from the resulting visible subtree
3. if the structure is trivial, use deterministic shortcuts
4. otherwise ask the LLM to choose among the current visible boundary nodes
5. recurse into selected branches or terminate on selected items
6. reduce branch results to the requested top_k

Important rules:
- every LLM routing decision sees only the current visible subtree
- the model outputs the visible boundary node display names only
- display names are uniquified automatically if collisions exist
- single-candidate situations do not call the LLM
```

**关键设计**：分层递进——tag 过滤剪枝 → LLM 在 visible subtree 中选择 → 递归。`single-candidate situations do not call the LLM` 是 LLM 成本优化关键：只有一个候选时直接返回，省去 LLM 调用。

#### 3.1.2 Warm-up 指数阈值

```typescript
// pipeline-manager.ts:362-387
private getEffectiveThreshold(state: PipelineSessionState): number {
  if (!this.enableWarmup) return this.everyNConversations;
  if (state.warmup_threshold <= 0) return this.everyNConversations;
  return Math.min(state.warmup_threshold, this.everyNConversations);
}

private advanceWarmupThreshold(state: PipelineSessionState): void {
  if (!this.enableWarmup) return;
  if (state.warmup_threshold <= 0) return;
  
  const next = state.warmup_threshold * 2;
  if (next >= this.everyNConversations) {
    state.warmup_threshold = 0;  // 毕业,切换到稳态
  } else {
    state.warmup_threshold = next;
  }
}
```

**算法**：`warmup_threshold` 从 1 开始指数增长（1→2→4→8→...→`everyNConversations`）。保证早期对话被快速处理（第 1 轮就触发 L1），随会话成熟逐步降低频率。这是**自适应处理频率**的精妙设计。

#### 3.1.3 L1 触发三路径

```typescript
// pipeline-manager.ts:399-449
async notifyConversation(sessionKey: string, messages: CapturedMessage[]): Promise<void> {
  if (this.destroyed) return;
  if (this.sessionFilter.shouldSkip(sessionKey)) return;

  const state = this.getOrCreateState(sessionKey);
  state.conversation_count += 1;
  state.last_active_time = Date.now();

  const timers = this.getOrCreateTimers(sessionKey);
  timers.l1RetryCount = 0;

  const buffer = this.messageBuffers.get(sessionKey) ?? [];
  buffer.push(...messages);
  this.messageBuffers.set(sessionKey, buffer);

  const effectiveThreshold = this.getEffectiveThreshold(state);
  
  // Path A: threshold → trigger L1 immediately
  if (state.conversation_count >= effectiveThreshold) {
    this.enqueueL1(sessionKey);
    return;
  }

  // Path B: idle timeout → reset debounce timer
  timers.l1Idle.schedule(this.l1IdleTimeoutMs, () => this.onL1IdleTimeout(sessionKey));

  // Periodic GC: evict cold sessions
  this.notifyCounter += 1;
  if (this.notifyCounter >= this.SESSION_GC_EVERY_N_NOTIFICATIONS) {
    this.notifyCounter = 0;
    this.gcStaleSessions();
  }
}
```

| 触发路径 | 条件 | 行为 |
|---------|------|------|
| **Path A** (threshold) | `conversation_count >= effectiveThreshold` | 立即 `enqueueL1()` |
| **Path B** (idle_timeout) | 用户停止 `l1IdleTimeoutMs` 后 | `onL1IdleTimeout()` 触发 |
| **Path C** (flush) | graceful shutdown / `flushSession()` | 排空缓冲区 |

#### 3.1.4 L2 向下_only_ Timer

```typescript
// pipeline-manager.ts:795-820
private advanceL2Timer(sessionKey: string): void {
  const now = Date.now();
  const timers = this.getOrCreateTimers(sessionKey);
  const lastL2 = this.l2LastRunTime.get(sessionKey) ?? 0;

  // T_desired = max(now + l2DelayAfterL1, lastL2 + l2MinInterval)
  const desiredDelay = Math.max(
    now + this.l2DelayAfterL1Ms,
    lastL2 + this.l2MinIntervalMs,
  );

  // 仅当 desiredDelay 早于当前调度时才推进（向下_only_ 语义）
  if (timers.l2Schedule.fireAt === null || desiredDelay < timers.l2Schedule.fireAt) {
    timers.l2Schedule.schedule(desiredDelay, () => this.onL2Fire(sessionKey));
  }
}
```

**核心设计**：
- `delayAfterL1` 让远程 L1 完成异步记录生成
- `minInterval` 防止 L2 过于频繁
- `maxInterval` 由 `armL2MaxInterval()` 在 L2 完成后无条件设置（`now + l2MaxInterval`）
- **向下_only_**：调度时间只能向前推，不能向后延——保证 maxInterval 不被 L1 高频触发破坏

```typescript
// checkpoint.ts:156-179
const fileLocks = new Map<string, Promise<void>>();

async function withFileLock<T>(filePath: string, fn: () => Promise<T>): Promise<T> {
  const prev = fileLocks.get(filePath) ?? Promise.resolve();
  let release!: () => void;
  const gate = new Promise<void>((r) => { release = r; });
  fileLocks.set(filePath, gate);

  await prev;
  try {
    return await fn();
  } finally {
    release();
    if (fileLocks.get(filePath) === gate) {
      fileLocks.delete(filePath);
    }
  }
}
```

**Promise 链序列化**：`fileLocks` map 按文件路径维护 Promise 链，多个 `CheckpointManager` 实例共享同文件路径时自动共享锁。零争用时只有一个 `await Promise.resolve()` 的开销。

```typescript
  getId: (item: T) => string,
  k: number = RRF_K,
): Array<T & { rrfScore: number }> {
  const map = new Map<string, { item: T; rrfScore: number }>();

  for (const list of lists) {
    for (let rank = 0; rank < list.length; rank++) {
      const item = list[rank];
      const id = getId(item);
      const score = 1 / (k + rank + 1);
      const existing = map.get(id);
      if (existing) {
        existing.rrfScore += score;   // 同 item 多列表累加
      } else {
        map.set(id, { item, rrfScore: score });
      }
    }
  }

  return [...map.values()]
    .sort((a, b) => b.rrfScore - a.rrfScore)
    .map(({ item, rrfScore }) => ({ ...item, rrfScore }));
}
```

**RRF 公式**：`score = Σ 1/(k + rank + 1)`，k=60 是标准常数，平滑低排名项权重。

**算法步骤**：
1. 多列表（如 FTS 结果 + 向量结果）按 rank 遍历
2. 每个 item 计算 `score = 1 / (k + rank + 1)`
3. 累加同 id item 的分数（跨列表去重合并）
4. 按 RRF score 降序排序

**RRF 原理图**：

```
Lists[0] = [a, b, c, d, e]
Lists[1] = [c, a, f, g]
                 ↓ RRF Merge
        ┌────────────────┐
        │ a: 1/61 + 1/62 │ = 0.0325
        │ b: 1/61       │ = 0.0164
        │ c: 1/63 + 1/61 │ = 0.0322
        │ d: 1/65       │ = 0.0154
        │ e: 1/66       │ = 0.0152
        │ f: 1/64       │ = 0.0156
        │ g: 1/65       │ = 0.0154
        └────────────────┘
                 ↓ sort
        Final = [a, c, b, f, g, d, e]
```

### 4.4 先例搜索算法（semantica）

semantica 的 `find_precedents_by_scenario()` 采用**内容相似度 + 结构相似度加权融合**：

```python
# semantica/context/context_graph.py:4434-4510
def find_precedents_by_scenario(
    self, scenario, category=None, limit=10,
    similarity_threshold=0.5, include_superseded=False,
    as_of=None, **filters
):
    """Find similar decisions (precedents) using hybrid search."""
    
    candidates = set()
    if category:
        candidates.update(self._decision_index.get(category, set()))
    else:
        candidates.update(self._decisions.keys())
    
    # 实体过滤
    if "entities" in filters:
        entity_candidates = set()
        for entity in filters["entities"]:
            entity_candidates.update(self._entity_index.get(entity, set()))
        candidates = candidates.intersection(entity_candidates)
    
    precedents = []
    for decision_id in candidates:
        decision = self._decisions[decision_id]
        if not self._decision_matches_temporal_filters(...):
            continue
        
        # 内容相似度（embedding 余弦 / 字符串）
        content_sim = self._calculate_decision_content_similarity(scenario, decision)
        
        # 结构相似度（图结构）
        structural_sim = 0.0
        if self.config.get("advanced_analytics"):
            structural_sim = self._calculate_structural_similarity_for_decision(decision_id, scenario)
        
        # 混合相似度公式: content_sim 主导, structural_sim 辅助
        combined_sim = 0.7 * content_sim + 0.3 * structural_sim
        
        if combined_sim >= similarity_threshold:
            precedents.append({
                "decision": decision,
                "similarity": combined_sim,
                "content_similarity": content_sim,
                "structural_similarity": structural_sim,
            })
    
    precedents.sort(key=lambda x: x["similarity"], reverse=True)
    return precedents[:limit]
```

**关键公式**：`combined_sim = 0.7 × content_sim + 0.3 × structural_sim`. 内容相似度（embedding 余弦 / 字符串相似度）+ 图结构相似度（共享实体、共享边类型）的加权融合。

```markdown
1. apply request tag filters to catalog leaves and prune empty tree branches
```

```rust
pub const RRF_K: usize = 60;

pub fn rrf_merge<T: Clone>(
    lists: &[Vec<T>],
    get_id: impl Fn(&T) -> &str,
    k: usize,
) -> Vec<(T, f64)> {
    let mut map: HashMap<String, (T, f64)> = HashMap::new();
    for list in lists {
        for (rank, item) in list.iter().enumerate() {
            let id = get_id(item).to_string();
            let score = 1.0 / (k + rank + 1) as f64;
            map.entry(id).and_modify(|(_, s)| *s += score).or_insert((item.clone(), score));
        }
    }
    let mut result: Vec<_> = map.into_values().collect();
    result.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap());
    result
}
```

### 5.3 三态缓存策略

```typescript
// pipeline.ts:269-282
private async resolveHookBlocks(
  hook: InjectionHook,
  ctx: AgentContext,
  spaceId: string, userId: string, agentSource: string, sessionId: string | null,
): Promise<ContextBlock[]> {
  const strategy = hook.cacheStrategy ?? "none";

  // Fast path: no cache configured, or no session_id available — legacy.
  if (!this.hookCacheRepo || !sessionId || strategy === "none") {
    return await hook.execute(ctx);
  }

  if (strategy === "session_init") {
    const cached = await this.hookCacheRepo.get(spaceId, userId, agentSource, sessionId, hook.id);
    if (cached !== null) {
      console.log(`[hook-cache] session=${sessionId} hook=${hook.id} hit blocks=${cached.length}`);
      return cached;
    }

    // Cache miss safety net: Fall back to hook.execute() and self-heal the cache
    if (ctx.metadata.custom?.readOnly !== true) {
      const blocks = await hook.execute(ctx);
      // 回填缓存（self-heal）
      return blocks;
    }
    return await hook.execute(ctx);
  }

  if (strategy === "hybrid") {
    // 预热 + 实时执行并集去重
    const cached = await this.hookCacheRepo.get(...);
    const fresh = await hook.execute(ctx);
    return unionDedup(cached ?? [], fresh);
  }

  return await hook.execute(ctx);
}
```

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| **`none`** | 每次执行 `hook.execute(ctx)`（legacy 行为） | 每次都变化的（如当前时间） |
| **`session_init`** | session 初始化时预热一次，后续从 `HookCacheRepo` 读取 | 项目说明、agent_memory 检索结果 |
| **`hybrid`** | 预热 + 实时执行并集去重（按 `metadata.cacheKey ?? content`） | 会话历史 + 实时 L1 召回 |

**Self-heal 例外**：`metadata.readOnly === true` (FORK 请求) 时 cache miss 不 self-heal put。因为 fork 请求的目的是复用 MAIN 已建的 cache 命中；如果 miss 时 self-heal，写入内容可能跟 MAIN 那次不 byte-level 一致，反而破坏 MAIN session 的 cache 命中。

```rust
pub enum InjectionPoint {
    SystemPrefix,
    SystemBeforeTools,
    SystemAfterTools,
    SystemSuffix,
    UserFirstTurn,
    UserBefore,
}

#[async_trait]
pub trait InjectionHook: Send + Sync {
    fn id(&self) -> &str;
    fn point(&self) -> InjectionPoint;
    fn cache_strategy(&self) -> CacheStrategy { CacheStrategy::None }
    async fn execute(&self, ctx: &mut AgentContext) -> Result<Vec<ContextBlock>>;
}

pub enum CacheStrategy {
    None,
    SessionInit,  // 预热 + 缓存
    Hybrid,       // 预热 + 实时并集
}

pub struct InjectionPipeline {
    hooks: HashMap<InjectionPoint, Vec<Arc<dyn InjectionHook>>>,
    cache: Option<Arc<HookCache>>,
}

impl InjectionPipeline {
    pub async fn process(&self, ctx: &mut AgentContext) -> Result<()> {
        let points = [
            InjectionPoint::SystemPrefix,
            InjectionPoint::SystemBeforeTools,
            InjectionPoint::SystemAfterTools,
            InjectionPoint::SystemSuffix,
            InjectionPoint::UserFirstTurn,
            InjectionPoint::UserBefore,
        ];
        for point in points {
            if let Some(hooks) = self.hooks.get(&point) {
                for hook in hooks {
                    let blocks = match hook.cache_strategy() {
                        CacheStrategy::None => hook.execute(ctx).await?,
                        CacheStrategy::SessionInit => {
                            if let Some(cached) = self.cache.as_ref()
                                .and_then(|c| c.get(ctx, hook.id())) {
                                cached
                            } else {
                                let blocks = hook.execute(ctx).await?;
                                if let Some(cache) = &self.cache {
                                    cache.put(ctx, hook.id(), blocks.clone());
                                }
                                blocks
                            }
                        }
                        CacheStrategy::Hybrid => {
                            let cached = self.cache.as_ref()
                                .and_then(|c| c.get(ctx, hook.id())).unwrap_or_default();
                            let fresh = hook.execute(ctx).await?;
                            union_dedup(cached, fresh)
                        }
                    };
                    ctx.inject_blocks(point, blocks)?;
                }
            }
        }
        Ok(())
    }
}
```

### 6.3 SkillVersioning 跨系统事务

```typescript
// MemoryCore/src/core/skill/skill-versioning.ts:117-205
async createNewSkill(
  skillId, ownerAgentId, ctx, mut
): Promise<Skill> {
  const newVersion = 1;
  const storageDir = this.resources.versionDir(skillId, newVersion);

  // 整 skill 总大小聚合校验（设计 ≤ 50MB）
  if (mut.resourcesToWrite && mut.resourcesToWrite.length > 0) {
    this.resources.assertTotalSize([], mut.resourcesToWrite, []);
  }

  // ── Step 1: 写 COS（最脆的一步先做，失败零副作用）───────────────────
  let manifest: SkillManifestEntry[] = [];
  if (mut.resourcesToWrite && mut.resourcesToWrite.length > 0) {
    try {
      for (const p of mut.resourcesToWrite) {
        const entry = await this.resources.writeResource(skillId, newVersion, p);
        manifest.push(entry);
      }
    } catch (e) {
      // 部分文件可能已写，best-effort 清理整个版本目录
      await this.cleanupVersionDir(storageDir).catch(() => {});
      throw e;
    }
  }

  // ── Step 2: 写 skill DB（本地事务，几乎不会失败；失败反向清 COS）───
  let row: Skill;
  try {
    row = await this.store.appendVersion({...});
  } catch (e) {
    await this.cleanupVersionDir(storageDir).catch(() => {});
    throw e;
  }

  // ── Step 3: 登记 meta_assets（agent/team 校验 + createAsset + bind）───
  if (this.onSkillCreated) {
    try {
      await this.onSkillCreated({...});
    } catch (assetErr) {
      // 反向删 skill DB
      try {
        await this.deleteSkill(skillId, ctx.team_id, { reportVdbDelta: false });
      } catch (rollbackErr) {
        this.logger?.error(`[skill-tx] rollback deleteSkill failed for ${skillId}`);
      }
      await this.cleanupVersionDir(storageDir).catch(() => {});
      throw assetErr;
    }
  }

  this.onSkillVdbChanged?.(1);
  return row;
}
```

**关键设计原则**（注释 line 107-110）：
> "为什么这个顺序：跨 3 个系统没有真事务，只能靠"顺序 + 补偿"。原则是**最容易失败的先做、失败零副作用的先做、可靠的收尾**。"

```
COS（最脆）+  skill DB（本地事务）+  meta_assets（多表写）
   ↓              ↓                          ↓
 Step 1         Step 2                     Step 3
   │ 失败零副作用  │ 失败反向清 COS            │ 失败反向删 DB + 清 COS
   ▼              ▼                          ▼
 抛业务错       cleanupVersionDir()         deleteSkill() + cleanupVersionDir()
```

### 7.4 verify_chain() 哈希链验证

```python
# semantica/provenance/manager.py:1450-1520
def verify_chain(self) -> Dict[str, Any]:
    """Verify the hash chain across all provenance entries."""
    
    entries = sorted(
        (e for e in self.storage.retrieve_all() if e.sequence_id is not None),
        key=lambda e: e.sequence_id,
    )
    
    broken_links: List[Dict[str, Any]] = []
    expected_previous: Optional[str] = None
    expected_sequence: Optional[int] = None
    
    for entry in entries:
        if not verify_checksum(entry):
            broken_links.append({"entity_id": entry.entity_id, "sequence_id": entry.sequence_id, "reason": "checksum_mismatch"})
        else:
            sequence_gap = (
                expected_sequence is not None
                and entry.sequence_id != expected_sequence + 1
            )
            checksum_break = entry.previous_checksum != expected_previous
            if sequence_gap or checksum_break:
                broken_links.append({...})
        
        # 关键: 即使 entry 被标记为 broken, 仍然用它推进 expected_*
        expected_previous = entry.checksum
        expected_sequence = entry.sequence_id
    
    return {"valid": len(broken_links) == 0, "total_entries": len(entries), "broken_links": broken_links}
```

**三重检测**：
1. **checksum_mismatch**：单条 entry 内容被篡改
2. **sequence_gap**：sequence_id 不连续（说明有行被硬删除）
3. **checksum_break**：previous_checksum 与前一行的 checksum 不匹配（哈希链断裂）

```python
def get_causal_chain(
    self, decision_id, direction="upstream", max_depth=10
) -> List["Decision"]:
    if direction not in ["upstream", "downstream"]:
        raise ValueError("Direction must be 'upstream' or 'downstream'")
    
    # BFS 遍历
    visited = set()
    queue = deque([(decision_id, 0)])
    decisions = []
    
    while queue:
        current_id, depth = queue.popleft()
        if current_id in visited or depth > max_depth:
            continue
        visited.add(current_id)
        
        # 沿 edge 遍历
        for edge in self.edges:
            if direction == "upstream":
                if edge.target_id == current_id and edge.edge_type.upper() in _CAUSAL_TRAVERSAL_TYPES:
                    if edge.source_id not in visited and depth < max_depth:
                        queue.append((edge.source_id, depth + 1))
            else:  # downstream
                if edge.source_id == current_id and edge.edge_type.upper() in _CAUSAL_TRAVERSAL_TYPES:
                    if edge.target_id not in visited and depth < max_depth:
                        queue.append((edge.target_id, depth + 1))
    
    if direction == "upstream":
        decisions.sort(key=lambda d: d.metadata.get("causal_distance", 0), reverse=True)
    return decisions
```

### 8.6 SQLite 三维隔离索引

```sql
CREATE INDEX IF NOT EXISTS idx_l1_user_agent_session ON l1_records(user_id, agent_id, session_id);
CREATE INDEX IF NOT EXISTS idx_l1_user_updated ON l1_records(user_id, updated_time);
CREATE INDEX IF NOT EXISTS idx_l1_agent_updated ON l1_records(agent_id, updated_time);
```

三个复合索引支撑三维隔离查询：`(user_id, agent_id, session_id)` 精确匹配 + `(user_id, updated_time)` / `(agent_id, updated_time)` 时间范围扫描。

laew 当前单用户单设备，可简化为 `(user_id, agent_id)` 二维；在 `Session` 中增加 `agentId` 字段，记忆查询强制带 agentId 过滤。

## 9. 设计模式提炼

### 模式 1：四层管线模型（L0-L3）

**定义**：记忆按抽象层次分为 4 层，从原始对话逐步抽象到用户画像。

**采用者**：TencentDB-Agent-Memory（L0 Recorder → L1 Writer → L2 Scene → L3 Persona）

**laew 借鉴**：将 SessionContext 升级为 4 阶段：
- L0：原始消息持久化（已有 session_memory）
- L1：结构化记忆（agent_memory 升级 7 类型）
- L2：场景块（SubAgent-Work 输出归档）
- L3：Persona（跨 session 用户画像）

### 模式 2：5 类型正交分层

**定义**：记忆类型与存储后端正交，按类型自动选后端。

**采用者**：agent-core（5 类型 × 4 后端）

**laew 借鉴**：agent_memory 借鉴 USER_PROFILE / EPISODIC / SEMANTIC / VARIABLE / SUMMARY 5 类型；存储后端由 SQLite 统一承担。

### 模式 3：Context Graph + BiTemporalFact

**定义**：节点/边带 `valid_from`/`valid_until` 时序窗口，支持历史回溯。

**采用者**：semantica

**laew 借鉴**：session_memory 增加 `valid_until` 字段；retraction 模式替代硬删除。

### 模式 4：Background Auto-Extraction

**定义**：每轮对话停止后，后台 forked agent 自动提取关键信息。

**采用者**：TencentDB（extractMemories + MemoryPipelineManager）、Claude Code（extractMemories）、atomcode（无，靠 MemoryTool）

**laew 借鉴**：SessionContext Agent 扩展为后台自动抽取（warm-up 指数阈值 + idle timer + GC）。

### 模式 5：Hybrid Retrieval（BM25 + 向量 + RRF）

**定义**：关键词检索与语义检索融合，RRF 公式统一加权。

**采用者**：TencentDB（BM25 + vec0 + RRF k=60）、OpenClaw（sqlite-vec + FTS5）

**laew 借鉴**：agent_memory 增加 vec0 虚拟表 + FTS5 索引 + RRF 融合函数。

### 模式 6：Progressive Tree Retrieval

**定义**：树形分层的渐进式检索，每层 LLM 选择分支。

**采用者**：jiuwenswarm Symphony

**laew 借鉴**：未来 Skill 调度时可借鉴 tag filter → keyword → LLM 三路递进。

### 模式 7：Hybrid Memory Structure（RRF + content+structural）

**定义**：内容相似度与结构相似度加权融合。

**采用者**：semantica（0.7×content + 0.3×structural）

**laew 借鉴**：未来 agent_memory 检索可加「时间新鲜度」维度（0.7×content + 0.3×recency）。

### 模式 8：9 个内置注入点 + 三态缓存

**定义**：标准化的 9 个注入点 + 3 种缓存策略（none/session_init/hybrid）。

**采用者**：TencentDB（InjectionPipeline）

**laew 借鉴**：将一次性注入升级为 Hook 注册机制，支持 Self-heal。

### 模式 9：协议适配器模式

**定义**：Anthropic / OpenAI 协议由统一 AgentContext 抽象承载，注入逻辑与协议解耦。

**采用者**：TencentDB（MemoryProxy）、laew（llm/anthropic.rs + llm/openai.rs）

**laew 借鉴**：现有设计已采用。

### 模式 10：URL Path 快速 Agent 识别

**定义**：通过 URL path 前缀快速识别 Agent 类型，零字符串扫描。

**采用者**：TencentDB（MemoryProxy agentProfiles.get(metadata.agentSource)）

**laew 借鉴**：在 TUI/CLI 入口处根据 `/provider use <id>` 缓存 agent profile，启动时零成本加载。

### 模式 11：Hybrid Cache Strategy + Self-heal

**定义**：cache miss 时回退到 execute() 并回填缓存。

**采用者**：TencentDB（InjectionPipeline session_init）

**laew 借鉴**：Yolo 注入历史摘要可加缓存，首次查询后 cache 24 小时。

### 模式 12：6 写 4 读 Skill 操作

**定义**：CRUD + 资源操作完整覆盖，乐观锁版本控制。

**采用者**：TencentDB（SkillCore）

**laew 借鉴**：未来 Skill 系统可借鉴 6 写（create/update/patch/delete/writeFiles/removeFiles）。

### 模式 13：跨系统"顺序 + 补偿"事务

**定义**：最容易失败的先做、失败零副作用的先做、可靠的收尾。

**采用者**：TencentDB（SkillVersioning createNewSkill）

**laew 借鉴**：当前仅 SQLite 单库，不需跨系统事务；但「幂等保证」可借鉴（content_hash 校验避免重复写入）。

### 模式 14：W3C PROV-O 溯源 + SHA-256 哈希链

**定义**：W3C PROV-O 标准字段映射 + SHA-256 哈希链保证审计完整性。

**采用者**：semantica（ProvenanceEntry + compute_checksum + verify_chain）

**laew 借鉴**：session_memory 增加溯源字段 + SHA-256 链，工具调用可审计。

### 模式 15：双删除语义（retraction + tombstone）

**定义**：retraction 仅关闭时间窗口（可恢复），tombstone 彻底清除（不可恢复）。

**采用者**：semantica

**laew 借鉴**：引入 retraction 模式，工具调用结果可撤回但不丢失历史。

### 模式 16：三级警告 + 物理沙箱

**定义**：在 prompt 中嵌入容量计数器 + 物理沙箱隔离 LLM 可访问文件。

**采用者**：TencentDB（SceneExtractor 三档警告 + workspaceDir 隔离）

**laew 借鉴**：未来 L2 场景块引入时建设权限管控。

### 模式 17：Vec Dual-Write + Graceful Degradation

**定义**：JSONL 追加先行，向量写入异步重试，embedding 失败时仅写 metadata + FTS。

**采用者**：TencentDB（l1-writer）

**laew 借鉴**：未来 sqlite-vec 引入时采用相同模式。

### 模式 18：三维隔离 + 5 级可见性 + 6 类权限

**定义**：(team_id, user_id, agent_id) 三维 + visibility × permission 矩阵。

**采用者**：TencentDB

**laew 借鉴**：当前单用户，简化二维（user_id, agent_id）；未来多用户扩展时再加 team_id。

### 模式 19：AES 加密 + Scope 独立配置

**定义**：每个 scope 独立配置 + AES 加密 API Key。

**采用者**：agent-core（AesStorageCodec + set_scope_config）

**laew 借鉴**：providers 表 api_key 字段加密。

### 模式 20：Evolution Overlay + Evidence ID 去重

**定义**：根据 plan outcome 历史重建 dynamic overlay，evidence_id 防止重试风暴污染统计。

**采用者**：jiuwenswarm（SwarmSymphonyEvolutionService）

**laew 借鉴**：MultiAgentOrchestrator 失败回流时使用 evidence_id 去重。

## 10. 对 laew 的综合建议

### 10.1 laew 现状分析

laew 当前的记忆与注入状态：

| 模块 | 现状 | 差距 |
|------|------|------|
| **session_memory** | 5 种 event_type × SQLite | 缺溯源、缺类型化 |
| **agent_memory** | 4 字段（input/output/error/artifacts） | 缺 7 类型、缺加密、缺版本 |
| **SessionContext Agent** | 每任务完成后生成摘要 | 缺后台自动抽取、缺结构化 |
| **Yolo 注入** | `<<<LAEW:SESSION_HISTORY>>>` 最近 3 条 | 缺三态缓存、缺 Self-heal |
| **项目发现** | 5 级链（CLAUDE.md→AGENTS.md→README→自动生成→空） | ✅ 已有 |
| **多租户** | ❌ 单用户单设备 | 需简化 2 维隔离 |
| **加密** | ❌ 明文 api_key | 缺 AES |
| **Skill 系统** | ❌ 无 | 缺 6 写 4 读 |
| **检索** | 纯 SQL 过滤 | 缺 RRF、缺向量 |

### 10.2 关键借鉴原则

1. **不要过度设计**：TencentDB 的 6 子系统对 laew 过重；先做 **L1 结构化记忆 + RRF 检索 + 三态缓存注入**三个核心能力。
2. **警惕 LLM 沙箱逃逸**：TencentDB 的 "LLM 直写文件" 需要严格 workspaceDir 限制；laew 引入 L2 时需同步建设权限管控。
3. **向量维度漂移检测**：embedding provider/model/dimensions 变化时需 reindex；借鉴 `VectorStoreInitResult.needsReindex`。
4. **防止注入污染**：借鉴 TencentDB 的 `sanitizeText` + `stripCodeBlocks` 防止 `<<<LAEW:PROJECT_CONTEXT>>>` 被 LLM 重复输出。
5. **避免跨系统事务**：laew 仅有 SQLite，不要为 Skill 版本化引入 COS + asset；v1 仅 SQLite + 乐观锁。
6. **Rust 实现优先**：AtomCode 的 memory/store.rs 是最直接的 Rust 借鉴对象。

### 10.6 特别注意事项

1. **Rust 实现参考 AtomCode**：laew 是 Rust 项目，AtomCode 的 `memory/store.rs` 是最直接的参考。MemoryStore、MemoryHook、MemoryTool 三个结构可以直接借鉴。

2. **多 Agent 架构的独特挑战**：laew 有 6 个 Agent 角色，每个角色有独立的 Agent-Context。记忆系统需要考虑：
   - SubAgent-Work 的工具调用经验应写入哪个 agent_memory？
   - SessionContext 的摘要与 Consolidation Agent 的整合如何协调？
   - Plan Agent 的输出在压缩后如何重新注入？

3. **SQLite 持久化**：laew 已有 SQLite 基础设施（`LsmAgentEmergentWork.db`），记忆状态可以复用现有表结构。

4. **不要过度工程化**：先从最简单的 P0（结构化摘要 + 加密）开始，逐步升级。

5. **RRF 比单纯语义检索更适合多类型记忆**：单一向量检索会混淆不同类型（persona/episodic/instruction 等）的相关性，RRF 融合多个信号源（BM25 + 向量 + 时间衰减）能给出更准确的排序。

```rust
// src/agent/memory/rrf.rs
use std::collections::HashMap;

pub const RRF_K: usize = 60;

pub struct RankedItem<T> {
    pub item: T,
    pub rrf_score: f64,
}

pub fn rrf_merge<T>(
    lists: &[Vec<T>],
    get_id: impl Fn(&T) -> &str,
    k: usize,
) -> Vec<RankedItem<T>> {
    let mut map: HashMap<String, RankedItem<T>> = HashMap::new();
    
    for list in lists {
        for (rank, item) in list.iter().enumerate() {
            let id = get_id(item).to_string();
            let score = 1.0 / (k + rank + 1) as f64;
            
            map.entry(id)
                .and_modify(|entry| entry.rrf_score += score)
                .or_insert(RankedItem {
                    item: item.clone(),  // 需 T: Clone
                    rrf_score: score,
                });
        }
    }
    
    let mut result: Vec<_> = map.into_values().collect();
    result.sort_by(|a, b| b.rrf_score.partial_cmp(&a.rrf_score).unwrap());
    result
}
```

### C.3 三态缓存注入

```rust
// src/agent/injection/cache.rs
use std::sync::Arc;
use std::collections::HashMap;

pub enum CacheStrategy {
    None,
    SessionInit,
    Hybrid,
}

#[async_trait]
pub trait InjectionHook: Send + Sync {
    fn id(&self) -> &str;
    fn cache_strategy(&self) -> CacheStrategy { CacheStrategy::None }
    async fn execute(&self, ctx: &mut AgentContext) -> Result<Vec<ContextBlock>>;
}

pub struct HookCache {
    inner: tokio::sync::RwLock<HashMap<String, Vec<ContextBlock>>>,
}

impl HookCache {
    pub async fn get(&self, session_id: &str, hook_id: &str) -> Option<Vec<ContextBlock>> {
        let key = format!("{}::{}", session_id, hook_id);
        self.inner.read().await.get(&key).cloned()
    }
    
    pub async fn put(&self, session_id: &str, hook_id: &str, blocks: Vec<ContextBlock>) {
        let key = format!("{}::{}", session_id, hook_id);
        self.inner.write().await.insert(key, blocks);
    }
}

pub async fn resolve_hook_blocks(
    hook: &dyn InjectionHook,
    ctx: &mut AgentContext,
    session_id: &str,
    cache: Option<&HookCache>,
) -> Result<Vec<ContextBlock>> {
    let strategy = hook.cache_strategy();
    
    match strategy {
        CacheStrategy::None => hook.execute(ctx).await,
        CacheStrategy::SessionInit => {
            if let Some(cache) = cache {
                if let Some(cached) = cache.get(session_id, hook.id()).await {
                    return Ok(cached);
                }
            }
            let blocks = hook.execute(ctx).await?;
            if let Some(cache) = cache {
                cache.put(session_id, hook.id(), blocks.clone()).await;
            }
            Ok(blocks)
        }
        CacheStrategy::Hybrid => {
            let cached = cache.map(|c| /* blocking */ futures::executor::block_on(c.get(session_id, hook.id())))
                .flatten()
                .unwrap_or_default();
            let fresh = hook.execute(ctx).await?;
            Ok(union_dedup(cached, fresh))
        }
    }
}
```

```rust
pub fn encrypt_api_key(api_key: &str, crypto_key: &[u8; 32]) -> Result<String> {
    let cipher = Aes256Gcm::new(Key::<Aes256Gcm>::from_slice(crypto_key));
    let nonce = Aes256Gcm::generate_nonce(&mut OsRng);
    let ciphertext = cipher.encrypt(&nonce, api_key.as_bytes())
        .map_err(|e| anyhow!("Encrypt failed: {}", e))?;
    
    let mut result = Vec::with_capacity(12 + ciphertext.len());
    result.extend_from_slice(&nonce);
    result.extend_from_slice(&ciphertext);
    
    Ok(format!("aes256:{}", hex::encode(result)))
}

pub fn decrypt_api_key(encrypted: &str, crypto_key: &[u8; 32]) -> Result<String> {
    let encrypted = encrypted.strip_prefix("aes256:")
        .ok_or_else(|| anyhow!("Invalid prefix"))?;
    let bytes = hex::decode(encrypted)?;
    
    if bytes.length() < 12 {
        return Err(anyhow!("Too short"));
    }
    
    let (nonce_bytes, ciphertext) = bytes.split_at(12);
    let nonce = Nonce::from_slice(nonce_bytes);
    let cipher = Aes256Gcm::new(Key::<Aes256Gcm>::from_slice(crypto_key));
    
    let plaintext = cipher.decrypt(nonce, ciphertext)
        .map_err(|e| anyhow!("Decrypt failed: {}", e))?;
    
    Ok(String::from_utf8(plaintext)?)
}
```

```rust
// src/agent/memory/provenance.rs
use sha2::{Sha256, Digest};

#[derive(Debug)]
pub struct ProvenanceEntry {
    pub entity_id: String,
    pub entity_type: String,
    pub activity_id: String,
    pub agent_id: String,
    pub agent_type: String,  // "person" | "software_agent" | "organization"
    pub source_document: String,
    pub source_location: Option<String>,
    pub source_quote: Option<String>,
    pub timestamp: String,
    pub confidence: f64,
    pub parent_entity_id: Option<String>,
    pub previous_version_id: Option<String>,
    pub derived_from_id: Option<String>,
    pub used_entities: Vec<String>,
    pub previous_checksum: Option<String>,
    pub checksum: Option<String>,
    pub sequence_id: Option<i64>,
    pub invalidated: bool,
    pub invalidated_at_time: Option<String>,
    pub invalidated_by: Option<String>,
    pub invalidation_reason: Option<String>,
}

pub fn compute_checksum(entry: &ProvenanceEntry) -> String {
    let mut hasher = Sha256::new();
    hasher.update(entry.entity_type.as_bytes());
    hasher.update(entry.activity_id.as_bytes());
    hasher.update(entry.agent_id.as_bytes());
    hasher.update(entry.agent_type.as_bytes());
    hasher.update(entry.source_document.as_bytes());
    hasher.update(entry.timestamp.as_bytes());
    hasher.update(entry.confidence.to_le_bytes());
    if let Some(ref s) = entry.parent_entity_id {
        hasher.update(s.as_bytes());
    }
    if let Some(ref s) = entry.previous_version_id {
        hasher.update(s.as_bytes());
    }
    if let Some(ref s) = entry.derived_from_id {
        hasher.update(s.as_bytes());
    }
    for e in &entry.used_entities {
        hasher.update(e.as_bytes());
    }
    if let Some(ref s) = entry.previous_checksum {
        hasher.update(s.as_bytes());
    }
    hasher.update(&(entry.invalidated as u8).to_le_bytes());
    if let Some(ref s) = entry.invalidated_at_time {
        hasher.update(s.as_bytes());
    }
    if let Some(ref s) = entry.invalidated_by {
        hasher.update(s.as_bytes());
    }
    if let Some(ref s) = entry.invalidation_reason {
        hasher.update(s.as_bytes());
    }
    format!("{:x}", hasher.finalize())
}

pub struct BrokenLink {
    pub entity_id: String,
    pub sequence_id: Option<i64>,
    pub reason: String,  // "checksum_mismatch" | "chain_break"
}

pub fn verify_chain(entries: &mut Vec<ProvenanceEntry>) -> Vec<BrokenLink> {
    entries.sort_by_key(|e| e.sequence_id.unwrap_or(0));
    
    let mut broken_links = Vec::new();
    let mut expected_previous: Option<String> = None;
    let mut expected_sequence: Option<i64> = None;
    
    for entry in entries.iter() {
        if let Some(stored) = &entry.checksum {
            let computed = compute_checksum(entry);
            if stored != &computed {
                broken_links.push(BrokenLink {
                    entity_id: entry.entity_id.clone(),
                    sequence_id: entry.sequence_id,
                    reason: "checksum_mismatch".to_string(),
                });
            } else {
                let sequence_gap = expected_sequence.map(|s| entry.sequence_id != Some(s + 1)).unwrap_or(false);
                let checksum_break = entry.previous_checksum != expected_previous;
                if sequence_gap || checksum_break {
                    broken_links.push(BrokenLink {
                        entity_id: entry.entity_id.clone(),
                        sequence_id: entry.sequence_id,
                        reason: "chain_break".to_string(),
                    });
                }
            }
        }
        expected_previous = entry.checksum.clone();
        expected_sequence = entry.sequence_id;
    }
    
    broken_links
}
```

```rust
// src/agent/memory/extractor.rs
use std::time::Instant;

pub struct BackgroundExtractor {
    warmup_threshold: u32,         // 1 → 2 → 4 → 8 → graduated (0)
    every_n_conversations: u32,   // 稳态阈值
    conversation_count: u32,
    tokens_at_last_extract: u32,
    tool_calls_at_last_extract: u32,
    l1_idle_timeout_ms: u64,
    l1_max_retries: u32,
    l1_retry_count: u32,
}

impl BackgroundExtractor {
    pub fn new(every_n: u32, idle_timeout_ms: u64, max_retries: u32) -> Self {
        Self {
            warmup_threshold: 1,
            every_n_conversations: every_n,
            conversation_count: 0,
            tokens_at_last_extract: 0,
            tool_calls_at_last_extract: 0,
            l1_idle_timeout_ms: idle_timeout_ms,
            l1_max_retries: max_retries,
            l1_retry_count: 0,
        }
    }
    
    pub fn should_extract_now(&self) -> bool {
        if self.warmup_threshold <= 0 {
            return self.conversation_count >= self.every_n_conversations;
        }
        self.conversation_count >= std::cmp::min(self.warmup_threshold, self.every_n_conversations)
    }
    
    pub fn should_extract_idle(&self, tokens: u32, tool_calls: u32) -> bool {
        let token_growth = tokens.saturating_sub(self.tokens_at_last_extract);
        let tool_call_growth = tool_calls.saturating_sub(self.tool_calls_at_last_extract);
        token_growth >= 4000 && tool_call_growth >= 2
    }
    
    pub fn advance_warmup(&mut self) {
        if self.warmup_threshold <= 0 { return; }
        let next = self.warmup_threshold * 2;
        if next >= self.every_n_conversations {
            self.warmup_threshold = 0;  // 毕业
        } else {
            self.warmup_threshold = next;
        }
    }
    
    pub fn record_extracted(&mut self, tokens: u32, tool_calls: u32) {
        self.tokens_at_last_extract = tokens;
        self.tool_calls_at_last_extract = tool_calls;
        self.l1_retry_count = 0;
        self.advance_warmup();
    }
    
    pub fn record_failure(&mut self) -> bool {
        self.l1_retry_count += 1;
        self.l1_retry_count <= self.l1_max_retries
    }
}
```
