## 一、概述与调研范围

### 1.1 调研背景

流式输出与上下文窗口管理是 Agent CLI 工程的**核心用户体验支柱**。流式输出决定了用户感知的响应速度（TTFT, Time-To-First-Token），上下文窗口管理决定了 Agent 能处理多长的对话历史。第十轮已覆盖 CrashDump/WebUI/OAuth/i18n/Release/WebSocket/容器/CRDT 8 个维度，本轮聚焦：

2. **partial JSON 解析**（atomcode streaming parser、openclaw line buffering）
3. **Token 计数与预估**（tiktoken-rs / GPT-2 BPE / char/4 启发式 / OpenAI tokenizer API）
4. **Context 压缩管线**（claudecode 四级压缩、atomcode L1 三段式、opencode 三档压缩）

6. **流式渲染 cell-diff**（claudecode Ink diff、openclaw 行级 diff、pi cell-based）
7. **16ms 帧率节流**（pi requestAnimationFrame + setImmediate 兜底）
8. **Thinking 块处理**（reasoning_content / thinking_blocks / signature 字段）
9. **流式暂停 / 续传 / 取消**（AbortController、取消令牌、超时清理）
10. **Tool call 流式聚合**（Anthropic stream tool_use blocks、OpenAI delta accumulation）

## 二、SSE chunk 边界处理

### 2.1 SSE 协议基础

SSE 协议（HTML5 标准）格式规范：

```
event: message_start
data: {"type": "message_start", "message": {...}}

event: content_block_delta
data: {"type": "content_block_delta", "delta": {"type": "text_delta", "text": "Hello"}}

data: [DONE]
```

关键边界问题：
1. **多字节 UTF-8 跨 chunk 分割**（如中文 3-byte 字符被 TCP 包边界切断）
2. **SSE 事件块双 delimiter**（`\n\n` vs `\r\n\r\n`）
3. **data: 前缀可选空格**（`data: {...}` vs `data:{...}`）
4. **event: / id: / retry: 字段**（非 data 字段处理）
5. **[DONE] sentinel**（OpenAI 流结束标记）

### 2.2 cc-switch：工业级 SSE 解析器

cc-switch 的 `src-tauri/src/proxy/sse.rs` 实现了最完整的 SSE 边界处理，是整个 15 个工程中 SSE 解析的标杆实现。

#### 2.2.1 双 delimiter 支持

SSE 标准定义事件块以空行分隔，但实际实现中存在两种 delimiter：
- `\n\n`（LF+LF，Unix 风格，大多数 provider 使用）
- `\r\n\r\n`（CRLF+CRLF，HTTP 风格，部分 provider 如 Azure 使用）

cc-switch 的 `take_sse_block` 函数同时支持两种 delimiter，并选择最早出现的位置作为分割点：

```rust
pub(crate) fn take_sse_block(buffer: &mut String) -> Option<String> {
    let mut best: Option<(usize, usize)> = None;
    for (delimiter, len) in [("\r\n\r\n", 4usize), ("\n\n", 2usize)] {
        if let Some(pos) = buffer.find(delimiter) {
            if best.is_none_or(|(best_pos, _)| pos < best_pos) {
                best = Some((pos, len));
            }
        }
    }
    let (pos, len) = best?;
    let block = buffer[..pos].to_string();
    buffer.drain(..pos + len);
    Some(block)
}
```

**设计要点**：
- 使用 `find` 而非 `split`，避免不必要的内存分配
- 选择最早出现的位置，确保最小延迟
- `drain` 而非 `slice + clear`，保证内存安全

#### 2.2.2 data: 前缀可选空格

SSE 标准允许 `data: value` 和 `data:value` 两种格式，cc-switch 的 `strip_sse_field` 同时支持：

```rust
pub(crate) fn strip_sse_field<'a>(line: &'a str, field: &str) -> Option<&'a str> {
    line.strip_prefix(&format!("{field}: "))
        .or_else(|| line.strip_prefix(&format!("{field}:")))
}
```

**注意**：这里使用 `or_else`（惰性求值）而非 `or`（立即求值），避免不必要的字符串格式化。

#### 2.2.3 UTF-8 安全拼接

这是 cc-switch SSE 解析器最复杂也最重要的部分。TCP 包边界可能切断 UTF-8 多字节字符，需要特殊处理：

```rust
pub(crate) fn append_utf8_safe(buffer: &mut String, remainder: &mut Vec<u8>, new_bytes: &[u8]) {
    // remainder 累积上一 chunk 末尾不完整的 UTF-8 序列（最多 3 字节）
    // 防御性守卫：remainder 超过 3 字节时 lossy 刷新
    if remainder.len() > 3 {
        buffer.push_str(&String::from_utf8_lossy(remainder));
        remainder.clear();
    }
    // 解码循环：消费所有有效 UTF-8，只保留末尾不完整序列到 remainder
    loop {
        match std::str::from_utf8(&input[pos..]) {
            Ok(s) => { buffer.push_str(s); return; }
            Err(e) => {
                let valid_up_to = pos + e.valid_up_to();
                buffer.push_str(std::str::from_utf8(&input[pos..valid_up_to]).unwrap());
                if let Some(invalid_len) = e.error_len() {
                    buffer.push('\u{FFFD}');  // 真正无效字节 → U+FFFD
                    pos = valid_up_to + invalid_len;
                } else {
                    *remainder = input[valid_up_to..].to_vec();  // 末尾不完整序列
                    return;
                }
            }
        }
    }
}
```

### 2.3 Switchyard：NVIDIA 网关 SSE 帧封装

Switchyard 的 `crates/switchyard-server/src/sse.rs` 实现了**协议无关 → SSE 帧**的转换：

```rust
pub(crate) fn frame_stream(
    stream: RawEventStream,
    target_format: WireFormat,
) -> Sse<SseFrameStream> {
    let framed = async_stream::stream! {
        while let Some(item) = stream.next().await {
            let event = match item {
                Ok(value) => match frame_event(target_format, value) {
                    Ok(event) => event,
                    Err(error) => error_event(target_format, error.to_string())
                },
                Err(LlmStreamError::Upstream(value)) => {
                    // 上游错误原样转发，保留 code 和 type
                    frame_event(target_format, value.clone())
                        .unwrap_or_else(|_| error_event(target_format, value.to_string()))
                }
                Err(LlmStreamError::Client(error)) => {
                    error_event(target_format, error.to_string())
                }
            };
            yield Ok(event);
            if failed { break; }
        }
        // [DONE] 只在成功流结束时发送
        if !failed && target_format == WireFormat::OpenAiChat {
            yield Ok(Event::default().data("[DONE]"));
        }
    };
    Sse::new(Box::pin(framed))
}
```

**关键设计**：
- OpenAI 格式：`Event::default().json_data(value)`（无 event: 字段）
- Anthropic/Responses 格式：`Event::default().event(event_type).json_data(value)`
- 错误终止后不发 `[DONE]`，避免把失败伪装成成功

### 2.6 SSE 解析器实现模式总结

通过对 15 个工程的分析，可以总结出 4 种 SSE 解析器实现模式：

#### 模式 1：手动解析（cc-switch, jiuwenswarm）

**优点**：
- 完全控制解析逻辑
- 可以处理边缘情况（如 UTF-8 跨 chunk 分割）
- 无外部依赖

**缺点**：
- 实现复杂（cc-switch 的 sse.rs 有 345 行）
- 容易出错（jiuwenswarm 的解析器不支持 UTF-8 安全）

**适用场景**：
- 需要协议转换（cc-switch 的 OpenAI → Anthropic）
- 需要处理非标准 SSE 响应（jiuwenswarm 的 SSE-only 网关）

#### 模式 2：SDK 封装（claudecode, openclaw, opencode）

**优点**：
- 实现简单（依赖 SDK 内部实现）
- 经过充分测试
- 自动处理边缘情况

**缺点**：
- 依赖特定 SDK
- 难以定制

**适用场景**：
- 单一协议（只走 Anthropic 或只走 OpenAI）
- 无协议转换需求

#### 模式 3：框架封装（Switchyard）

**优点**：
- 与 Web 框架集成（axum）
- 类型安全
- 自动处理 SSE 帧封装

**缺点**：
- 依赖特定框架
- 灵活性受限

**适用场景**：
- 需要作为 HTTP 服务端（Switchyard 是 NVIDIA 网关）

#### 模式 4：二进制协议（pi）

**优点**：
- 最低延迟（无文本解析开销）
- 无 UTF-8 问题（CBOR 二进制编码）
- 精确帧边界（4-byte length prefix）

**缺点**：
- 实现复杂
- 需要自定义客户端

**适用场景**：
- 对延迟极度敏感
- 控制客户端和服务器

|------|---------|------|

## 三、partial JSON 解析

### 3.1 问题定义

流式 tool call 的 arguments 以增量 JSON 片段（partial JSON）形式到达：

```
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"{\\"q\\":"}}]}}]}
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"\\"rust\\"}"}}]}}]}
```

需要把多个片段拼接后解析为完整 JSON。难点：
1. **片段边界可能切断 UTF-8 字符**
2. **片段边界可能切断 JSON 转义序列**（如 `\"` 被切断）
3. **空 arguments**（`""`）需返回空对象 `{}`
4. **非 JSON 内容**（纯文本）需 fallback 为字符串

### 3.2 cc-switch：partial JSON 聚合

```rust
struct ToolBlockState {
    anthropic_index: u32,
    id: String,
    name: String,
    started: bool,
    pending_args: String,          // 累积 arguments
    consecutive_whitespace: usize, // 无限空白 bug 检测
    aborted: bool,
}

// arguments 增量聚合
let args_delta = tool_call.function.as_ref().and_then(|f| f.arguments.clone());
let immediate_delta = if let Some(args) = args_delta {
    // 无限空白 bug 检测：跟踪连续空白字符
    for ch in args.chars() {
        if ch.is_whitespace() { state.consecutive_whitespace += 1; }
        else { state.consecutive_whitespace = 0; }
    }
    if state.consecutive_whitespace >= INFINITE_WHITESPACE_THRESHOLD {
        state.aborted = true; None  // 中止此 tool call
    } else if state.started { Some(args) }
    else { state.pending_args.push_str(&args); None }
} else { None };
```

**无限空白 bug 检测**：当 function call 参数中的连续空白字符达到 500 时强制终止流（防御 Copilot 无限换行 bug）。

#### 3.2.1 Late start 处理

cc-switch 处理 arguments 先于 id/name 到达的边缘场景：

```rust
// Late start for blocks that accumulated args before id/name arrived.
let mut late_tool_starts: Vec<(u32, String, String, String)> = Vec::new();
for (tool_idx, state) in tool_blocks_by_index.iter_mut() {
    if state.started { continue; }
    let has_payload = !state.pending_args.is_empty() || !state.id.is_empty() || !state.name.is_empty();
    if !has_payload { continue; }
    // 使用 fallback id/name
    let fallback_id = if state.id.is_empty() { format!("tool_call_{tool_idx}") } else { state.id.clone() };
    let fallback_name = if state.name.is_empty() { "unknown_tool".to_string() } else { state.name.clone() };
    state.started = true;
    let pending = std::mem::take(&mut state.pending_args);
    late_tool_starts.push((state.anthropic_index, fallback_id, fallback_name, pending));
}
```

#### 3.2.2 message_delta 去重

### 3.3 Switchyard：ResponseAccumulator

Switchyard 的 `ResponseAccumulator` 实现了类型安全的 partial JSON 聚合：

```rust
struct PartialToolCall {
    id: Option<String>,
    name: Option<String>,
    arguments: String,  // 累积 arguments 字符串
}

impl ResponseAccumulator {
    pub fn push(&mut self, chunk: LlmResponseChunk) {
        match chunk {
            LlmResponseChunk::ToolCallDelta { index, id, name, arguments_delta } => {
                let call = self.tool_calls.entry(index).or_default();
                if id.is_some() { call.id = id; }
                if name.is_some() { call.name = name; }
                if let Some(delta) = arguments_delta {
                    call.arguments.push_str(&delta);
                }
            }
            // ...
        }
    }

    pub fn finish(self) -> AggLlmResponse {
        for call in self.tool_calls.into_values() {
            content.push(ContentBlock::ToolCall(ToolCall {
                arguments: parse_tool_arguments(&call.arguments),
                // ...
            }));
        }
    }
}

fn parse_tool_arguments(arguments: &str) -> Value {
    if arguments.is_empty() { return Value::Object(serde_json::Map::new()); }
    serde_json::from_str(arguments)
        .unwrap_or_else(|_| Value::String(arguments.to_string()))  // fallback 为字符串
}
```

### 4.3 claudecode：tokenCountWithEstimation（规范函数）

```typescript
/**
 * 这是测量上下文大小的规范函数（CANONICAL）。
 * 使用最后一次 API 响应的 token 数 + 估算新增消息的 token 数。
 * 
 * 处理并行 tool call 的 split assistant records：
 * 当模型发出多个 tool call 时，流式代码会为每个 content block 发出独立的
 * assistant 记录（共享相同的 message.id 和 usage），并且每个 tool_result
 * 紧跟在对应的 tool_use 之后。消息数组看起来像：
 *   [..., assistant(id=A), user(result), assistant(id=A), user(result), ...]
 * 如果只停在最后一个 assistant 记录，会低估所有交错的 tool_result。
 * 因此需要回走到第一个具有相同 message.id 的 sibling。
 */
export function tokenCountWithEstimation(messages: readonly Message[]): number {
    let i = messages.length - 1;
    while (i >= 0) {
        const message = messages[i];
        const usage = message ? getTokenUsage(message) : undefined;
        if (message && usage) {
            // 回走 split sibling
            const responseId = getAssistantMessageId(message);
            if (responseId) {
                let j = i - 1;
                while (j >= 0) {
                    const prior = messages[j];
                    const priorId = prior ? getAssistantMessageId(prior) : undefined;
                    if (priorId === responseId) { i = j; }
                    else if (priorId !== undefined) { break; }
                    j--;
                }
            }
            return getTokenCountFromUsage(usage)
                + roughTokenCountEstimationForMessages(messages.slice(i + 1));
        }
        i--;
    }
    return roughTokenCountEstimationForMessages(messages);
}
```

```typescript
export class Stream<T> implements AsyncIterator<T> {
    private readonly queue: T[] = []
    private readResolve?: (value: IteratorResult<T>) => void
    private isDone: boolean = false

    [Symbol.asyncIterator](): AsyncIterableIterator<T> {
        if (this.started) { throw new Error('Stream can only be iterated once') }
        this.started = true;
        return this;
    }

    next(): Promise<IteratorResult<T>> {
        if (this.queue.length > 0) {
            return Promise.resolve({ done: false, value: this.queue.shift()! });
        }
        if (this.isDone) { return Promise.resolve({ done: true, value: undefined }); }
        return new Promise<IteratorResult<T>>((resolve, reject) => {
            this.readResolve = resolve;
            this.readReject = reject;
        });
    }

    enqueue(value: T): void {
        if (this.readResolve) {
            const resolve = this.readResolve;
            this.readResolve = undefined;
            resolve({ done: false, value });
        } else {
            this.queue.push(value);
        }
    }
}
```

#### 12.10.3 无限空白 bug 检测

```rust
const INFINITE_WHITESPACE_THRESHOLD: usize = 500;

// arguments 增量聚合
let immediate_delta = if let Some(args) = args_delta {
    for ch in args.chars() {
        if ch.is_whitespace() { state.consecutive_whitespace += 1; }
        else { state.consecutive_whitespace = 0; }

    if state.consecutive_whitespace >= INFINITE_WHITESPACE_THRESHOLD {
```

#### 12.10.4 message_delta 去重

OpenRouter 某些 provider 会在 tool_use 后发送多个带 finish_reason 的 SSE chunk，重复会导致 Claude Code abort 连接：

```rust
// 1) has_emitted_message_delta: 去重，只处理第一个 finish_reason
// 2) pending_message_delta: 缓存延迟到 [DONE] 发送，确保 usage 完整
if has_emitted_message_delta {
    // 更新缓存的 message_delta usage（如果有更完整的 usage）
    if let (Some((_, ref mut usage)), Some(uj)) = (&mut pending_message_delta, usage_json) {
        *usage = Some(uj);
    }
    continue;
}
has_emitted_message_delta = true;
// 缓存 message_delta，等到 [DONE] 时发送
pending_message_delta = Some((stop_reason, usage_json));
```

### 14.4 gap 详细分析与修复建议

#### L166：SSE chunk 边界安全处理

**问题描述**：
laew 当前使用 `reqwest` 直接接收 SSE 流，未处理 UTF-8 多字节字符跨 TCP chunk 分割的场景。当中文（3字节 UTF-8）或 Emoji（4字节 UTF-8）被 TCP 包边界切断时，会导致乱码。

**影响范围**：
- 中文内容显示乱码
- 日文/韩文内容显示乱码
- Emoji 显示异常

**修复方案**：
1. 实现 `append_utf8_safe` 函数（参考 cc-switch）
2. 使用 `bytes` crate 处理字节缓冲
3. 维护 `remainder` 向量（最多 3 字节）
4. 防御性守卫：remainder 超过 3 字节时 lossy 刷新

**参考实现**：
```rust
pub fn append_utf8_safe(buffer: &mut String, remainder: &mut Vec<u8>, new_bytes: &[u8]) {
    // 合并 remainder 和新数据
    let input = if remainder.is_empty() {
        new_bytes.to_vec()
    } else {
        let mut combined = std::mem::take(remainder);
        combined.extend_from_slice(new_bytes);
        combined
    };
    
    let mut pos = 0;
    loop {
        match std::str::from_utf8(&input[pos..]) {
            Ok(s) => { buffer.push_str(s); return; }
            Err(e) => {
                let valid_up_to = pos + e.valid_up_to();
                buffer.push_str(std::str::from_utf8(&input[pos..valid_up_to]).unwrap());
                if let Some(invalid_len) = e.error_len() {
                    buffer.push('\u{FFFD}');
                    pos = valid_up_to + invalid_len;
                } else {
                    *remainder = input[valid_up_to..].to_vec();
                    return;
                }
            }
        }
    }
}
```

#### L167：partial JSON 聚合

**问题描述**：
流式 tool call 的 arguments 以增量 JSON 片段形式到达，laew 当前未实现片段拼接和解析逻辑。

**影响范围**：
- tool call 参数解析失败
- 流式 tool call 无法使用

**修复方案**：
1. 实现 `ToolCallAggregator` 结构（参考 Switchyard）
2. 按 index 聚合 tool call 片段
3. 处理 Late start（arguments 先于 id/name）
4. 空 arguments fallback 为 `{}`
5. 非 JSON fallback 为字符串

**参考实现**：
```rust
struct PartialToolCall {
    id: Option<String>,
    name: Option<String>,
    arguments: String,
}

struct ToolCallAggregator {
    tool_calls: BTreeMap<usize, PartialToolCall>,
}

impl ToolCallAggregator {
    fn push_delta(&mut self, index: usize, id: Option<&str>, name: Option<&str>, args_delta: Option<&str>) {
        let call = self.tool_calls.entry(index).or_default();
        if let Some(id) = id { call.id = Some(id.to_string()); }
        if let Some(name) = name { call.name = Some(name.to_string()); }
        if let Some(delta) = args_delta { call.arguments.push_str(delta); }
    }
    
    fn finish(self) -> Vec<ToolCall> {
        self.tool_calls.into_values().map(|call| {
            let args = if call.arguments.is_empty() {
                Value::Object(serde_json::Map::new())
            } else {
                serde_json::from_str(&call.arguments)
                    .unwrap_or_else(|_| Value::String(call.arguments))
            };
            ToolCall { id: call.id.unwrap_or_default(), name: call.name.unwrap_or_default(), arguments: args }
        }).collect()
    }
}
```

#### D.2.1 Stream 单消费者队列

`src/utils/stream.ts` 实现的 Stream 类是一个异步单消费者队列，核心设计：

```typescript
export class Stream<T> implements AsyncIterator<T> {
    private readonly queue: T[] = []
    private readResolve?: (value: IteratorResult<T>) => void
    private readReject?: (error: unknown) => void
    private isDone: boolean = false
    private hasError: unknown | undefined
    private started = false

    // 只能迭代一次（单消费者保证）
    [Symbol.asyncIterator](): AsyncIterableIterator<T> {
        if (this.started) {
            throw new Error('Stream can only be iterated once')
        }
        this.started = true;
        return this;
    }

    next(): Promise<IteratorResult<T>> {
        if (this.queue.length > 0) {
            return Promise.resolve({ done: false, value: this.queue.shift()! });
        }
        if (this.isDone) { return Promise.resolve({ done: true, value: undefined }); }
        if (this.hasError) { return Promise.reject(this.hasError); }
        // 挂起等待新数据
        return new Promise<IteratorResult<T>>((resolve, reject) => {
            this.readResolve = resolve;
            this.readReject = reject;
        });
    }

    enqueue(value: T): void {
        if (this.readResolve) {
            const resolve = this.readResolve;
            this.readResolve = undefined;
            this.readReject = undefined;
            resolve({ done: false, value });  // 直接交付，无排队延迟
        } else {
            this.queue.push(value);
        }
    }
}
```

**设计要点**：
- 单消费者保证（迭代一次后抛出异常）
- 零等待交付（消费者等待时直接 resolve）
- 错误传播（hasError 状态）
- 优雅关闭（done() 方法）

```typescript
    let i = messages.length - 1;
    while (i >= 0) {
        const message = messages[i];
        const usage = message ? getTokenUsage(message) : undefined;
        if (message && usage) {
            // 回走 split sibling（并行 tool call 场景）
            const responseId = getAssistantMessageId(message);
            if (responseId) {
                let j = i - 1;
                while (j >= 0) {
                    const prior = messages[j];
                    const priorId = prior ? getAssistantMessageId(prior) : undefined;
                    if (priorId === responseId) { i = j; }  // 更早的 split
                    else if (priorId !== undefined) { break; }  // 不同 API 响应
                    j--;
                }
            }
            return getTokenCountFromUsage(usage)
                + roughTokenCountEstimationForMessages(messages.slice(i + 1));
        }
        i--;
    }
    return roughTokenCountEstimationForMessages(messages);
}
```

```rust
pub(crate) fn append_utf8_safe(buffer: &mut String, remainder: &mut Vec<u8>, new_bytes: &[u8]) {
    // remainder 累积上一 chunk 末尾不完整的 UTF-8 序列（最多 3 字节）
    let (owned, bytes): (Option<Vec<u8>>, &[u8]) = if remainder.is_empty() {
        (None, new_bytes)
    } else {
        if remainder.len() > 3 {
            // 防御性守卫：remainder 超过 3 字节时 lossy 刷新
            buffer.push_str(&String::from_utf8_lossy(remainder));
            remainder.clear();
            (None, new_bytes)
        } else {
            let mut combined = std::mem::take(remainder);
            combined.extend_from_slice(new_bytes);
            (Some(combined), &[])
        }
    };
    let input = owned.as_deref().unwrap_or(bytes);
    let mut pos = 0;
    loop {
        match std::str::from_utf8(&input[pos..]) {
            Ok(s) => { buffer.push_str(s); return; }
            Err(e) => {
                let valid_up_to = pos + e.valid_up_to();
                buffer.push_str(std::str::from_utf8(&input[pos..valid_up_to]).unwrap());
                if let Some(invalid_len) = e.error_len() {
                    buffer.push('\u{FFFD}');  // 真正无效字节 → U+FFFD
                    pos = valid_up_to + invalid_len;
                } else {
                    *remainder = input[valid_up_to..].to_vec();  // 末尾不完整序列
                    return;
                }
            }
        }
    }
}
```

```rust
pub(crate) fn frame_stream(stream: RawEventStream, target_format: WireFormat) -> Sse<SseFrameStream> {
    let framed = async_stream::stream! {
        let mut stream = stream;
        let mut failed = false;
        while let Some(item) = stream.next().await {
            let event = match item {
                Ok(value) => match frame_event(target_format, value) {
                    Ok(event) => event,
                    Err(error) => error_event(target_format, error.to_string())
                },
                Err(LlmStreamError::Upstream(value)) => {
                    // 上游错误原样转发，保留 code 和 type
                    frame_event(target_format, value.clone())
                        .unwrap_or_else(|_| error_event(target_format, value.to_string()))
                }
                Err(LlmStreamError::Client(error)) => {
                    error_event(target_format, error.to_string())
                }
            };
            yield Ok(event);
            if failed { break; }
        }
        // [DONE] 只在成功流结束时发送
        if !failed && target_format == WireFormat::OpenAiChat {
            yield Ok(Event::default().data("[DONE]"));
        }
    };
    Sse::new(Box::pin(framed))
}

fn frame_event(target_format: WireFormat, value: Value) -> Result<Event, axum::Error> {
    match target_format {

            let event_type = value.get("type").and_then(Value::as_str).unwrap_or("message").to_string();
            Event::default().event(event_type).json_data(value)
```

```python
    """合并写入的 Token 后台写入器。"""
    
    def queue_token_counts(self, session_id: str, **kwargs) -> None:
        """后台写入器入队 token/cost delta。"""
        with self._token_queue_cond:
            self._token_queue.append((session_id, kwargs))
            if not writer_alive:
                thread = threading.Thread(
                    target=self._token_writer_loop,
                    name="session-db-token-writer", daemon=True)
                thread.start()
            self._token_queue_cond.notify_all()

    def _coalesce_token_deltas(self, batch):
        """合并相邻的相同 route 增量 delta，保持跨 session 和 /model 切换的顺序。"""
        for session_id, kwargs in batch:
            key = (session_id, *(kwargs.get(f) for f in self._TOKEN_DELTA_ROUTE_FIELDS))
            if groups and key is not None and groups[-1][0] == key:
                merged = groups[-1][2]
                for f in self._TOKEN_DELTA_SUM_FIELDS:
                    merged[f] = merged.get(f, 0) + kwargs.get(f, 0)
                for f in self._TOKEN_DELTA_COST_FIELDS:
                    value = kwargs.get(f)
                    if value is not None:
                        merged[f] = (merged.get(f) or 0.0) + value
            else:
                groups.append((key, session_id, dict(kwargs)))

    def _token_writer_loop(self) -> None:
        while True:
            with self._token_queue_cond:
                idle_deadline = time.monotonic() + self._TOKEN_WRITER_IDLE_SECONDS
                while not self._token_queue and not self._token_writer_stop:

                    if remaining <= 0:

                    self._token_queue_cond.wait(remaining)
                if not self._token_queue:
                    self._token_writer_thread = None; return
                self._token_writer_busy = True
                batch = list(self._token_queue)
                self._token_queue.clear();
```

## 附录 M：流式输出常见问题排查指南

### M.1 中文乱码问题

**症状**：流式输出中中文显示为乱码或问号

**排查步骤**：
1. 检查 SSE chunk 边界是否切断 UTF-8 多字节字符
2. 检查是否使用 `String::from_utf8_lossy` 而非安全拼接
3. 检查 remainder 缓冲是否正确维护

**修复方案**：
```rust
// 使用 append_utf8_safe 替代直接 String::push_str
append_utf8_safe(&mut buffer, &mut remainder, &bytes);
```

### M.2 tool call 参数解析失败

**症状**：流式 tool call 的 arguments 解析失败

**排查步骤**：
1. 检查 partial JSON 片段是否正确拼接
2. 检查是否处理了 Late start（arguments 先于 id/name）
3. 检查空 arguments 是否 fallback 为 `{}`

**修复方案**：
```rust
// 使用 ToolCallAggregator 聚合片段
let mut aggregator = ToolCallAggregator::new();
aggregator.push_delta(index, id, name, args_delta);
let tool_calls = aggregator.finish();
```

### M.3 上下文窗口溢出

**症状**：长对话中 API 返回 400 错误（context_length_exceeded）

**排查步骤**：
1. 检查 Token 估算是否准确
2. 检查 Context 压缩是否正常触发
3. 检查并行 tool call split record 是否被正确处理

**修复方案**：
```rust
// 使用 tiktoken-rs 精确计数
let token_count = tiktoken_rs::count_tokens(&text, "cl100k_base");
if token_count > window_size * 3 / 4 {
    // 触发压缩
    compress_context(&mut messages);
}
```

### M.4 流式渲染卡顿

**症状**：流式输出时终端卡顿或闪烁

**排查步骤**：
1. 检查是否每 chunk 全量重绘
2. 检查是否实现帧率节流
3. 检查是否使用 cell-diff 渲染

**修复方案**：
```rust
// 实现 16ms 帧率节流
let mut interval = tokio::time::interval(Duration::from_millis(16));
loop {
    interval.tick().await;
    if !frame_buffer.is_empty() {
        render_frame(&frame_buffer);
        frame_buffer.clear();
    }
}
```

### M.5 无法中断流式响应

**症状**：用户按 Ctrl+C 无法中断正在进行的流式响应

**排查步骤**：
1. 检查是否实现 CancellationToken
2. 检查取消信号是否传播到所有异步操作
3. 检查资源是否正确清理

**修复方案**：
```rust
// 使用 CancellationToken
let token = CancellationToken::new();
let child_token = token.child_token();

// 传播到异步操作
tokio::select! {
    _ = token.cancelled() => {
        // 清理资源
        cleanup().await;
    }
    result = async_operation(child_token) => {
        // 正常完成
    }
}
```
