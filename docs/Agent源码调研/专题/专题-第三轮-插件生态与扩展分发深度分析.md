## 一、各仓逐个深挖

### 1. opencode — 双轨插件 API 与 Effect 抽象

opencode 的插件系统以独立包 `@opencode-ai/plugin`(v1.18.26)发布,提供**双轨 API 设计**:v2/promise 轨(简单异步)与 v2/effect 轨(Effect 函数式效果系统)。这是本轮调研中**类型密度最高**的插件表面。

#### 1.1 插件模型与 API 表面

核心入口 `packages/plugin/src/index.ts:74` 定义插件函数签名:

```ts
// packages/plugin/src/index.ts:74
export type Plugin = (input: PluginInput, options?: PluginOptions) => Promise<Hooks>

export type PluginInput = {
  client: ReturnType<typeof createOpencodeClient>
  project: Project
  directory: string
  worktree: string
  experimental_workspace: {
    register(type: string, adapter: WorkspaceAdapter): void
  }
  serverUrl: URL
  $: BunShell
}
```

插件接收 `PluginInput`(SDK 客户端/项目/工作目录/BunShell),返回 `Hooks` 对象。`Hooks` 接口(`index.ts:222-335`)是**本轮最宽的 hook 表面**,共 20+ 个 hook 点:

| Hook | 能力 |
|------|------|
| `event` | 监听所有 SDK 事件 |
| `tool` | 注册自定义工具(`{[key: string]: ToolDefinition}`) |
| `auth` / `provider` | 自定义认证流程与 Provider 模型扩展 |
| `chat.message` / `chat.params` / `chat.headers` | 拦截/修改 LLM 消息、参数、请求头 |
| `permission.ask` | 介入权限决策(`ask`/`deny`/`allow`) |
| `command.execute.before` / `tool.execute.before`/`after` | 命令与工具执行前后 hook |
| `shell.env` | 注入 shell 环境变量 |
| `experimental.chat.messages.transform` / `experimental.chat.system.transform` | 变换消息流与系统提示词 |
| `experimental.session.compacting` / `experimental.compaction.autocontinue` | 自定义压缩 prompt 与自动续写 |
| `tool.definition` | 修改发送给 LLM 的工具定义 |

工具定义(`packages/plugin/src/tool.ts:45-54`)使用 Zod schema:

```ts
// packages/plugin/src/tool.ts:45
export function tool<Args extends z.ZodRawShape>(input: {
  description: string
  args: Args
  execute(args: z.infer<z.ZodObject<Args>>, context: ToolContext): Promise<ToolResult>
}) { return input }
```

`ToolContext`(`tool.ts:3-20`)携带 `sessionID`/`messageID`/`agent`/`directory`/`worktree`/`abort`/`metadata`/`ask`,为工具提供完整的会话上下文与权限询问能力。

#### 1.2 v2 双轨架构

v2 目录(`packages/plugin/src/v2/`)提供两套等价抽象:

- **promise 轨**(`v2/promise/plugin.ts:1-16`):极简 `Plugin` 接口
  ```ts
  export interface Plugin {
    readonly id: string
    readonly setup: (context: PluginContext) => Promise<void> | void
  }
  ```
- **effect 轨**(`v2/effect/plugin.ts:1-16`):Effect 函数式版本
  ```ts
  export interface Plugin<R = Scope.Scope> {
    readonly id: string
    readonly effect: (context: PluginContext) => Effect.Effect<void, never, R>
  }
  ```

`PluginContext`(`v2/promise/context.ts:12-22`)聚合所有子域 hooks:

```ts
export interface PluginContext {
  readonly options: PluginOptions
  readonly agent: AgentHooks & Reload
  readonly aisdk: AISDKHooks
  readonly catalog: CatalogHooks & Reload
  readonly command: CommandHooks & Reload
  readonly integration: IntegrationHooks & Reload
  readonly plugin: PluginDomain
  readonly reference: ReferenceHooks & Reload
  readonly skill: SkillHooks & Reload
  }
```

每个子域(如 `CatalogHooks`/`IntegrationHooks`)都暴露 `transform` hook 与 `reload` 能力,形成**可组合的插件域模型**。`Registration` 接口(`v2/promise/registration.ts:1-7`)统一 dispose 语义:

```ts
export interface Registration {
  readonly dispose: () => Promise<void>
}
export interface Reload {
  readonly reload: () => Promise<void>
}
```

#### 1.3 生命周期

opencode 的生命周期是**隐式**的:插件函数调用即注册,返回 Hooks 即激活;`dispose` 钩子(`Hooks.dispose`)用于清理;`reload` 通过子域 `Reload` 接口触发。没有显式的「PENDING→ACTIVE」状态机,依赖 Promise  settle 判定就绪。

#### 1.4 安装与分发

- **npm 安装**:`v2/effect/npm.ts:1-11` 暴露 `Npm.add(pkg)` Effect,返回 `{directory, entrypoint}`
- **配置驱动**:`Config.plugin?: Array<string | [string, PluginOptions]>`(`index.ts:70-72`)声明要加载的插件
- **Catalog 域**:`v2/effect/catalog.ts:1-29` 提供 `CatalogDraft` 让插件增删改查 Provider/Model 目录,`model.default` 可设置默认模型

#### 1.5 原子化程度

opencode 是**插件一等公民**:核心功能(工具/Provider/认证/压缩)都通过 Hooks 暴露给插件。但宿主本身不是「一切皆插件」——SDK/会话/总线是内建的,插件是「扩展点」而非「构成单元」。

#### 1.6 第三方生态

官方包 `@opencode-ai/plugin` 提供 `example.ts`(`packages/plugin/src/example.ts:1-18`)与 `example-workspace.ts` 示范;v2/effect 有 `PLAN.md` 与 `README.md` 设计文档。社区生态处于早期,未见独立插件注册表。

### 2. deepseek-harness — Cordis「一切皆插件」三原语

deepseek-harness 的插件哲学是**极致原子化**:整个应用是 Cordis 上下文上的插件树,80+ npm 包每个都是 Cordis 插件。核心在 `vendor/cordis/src/`,仅 ~9 个文件构成完整插件框架。

#### 2.1 三原语:Context / Service / Plugin

**Context**(`vendor/cordis/src/context.ts:42-146`)是代理对象,承载隔离映射与拦截映射:

```ts
// vendor/cordis/src/context.ts:16-33
export interface Context {
  [symbols.isolate]: Dict<symbol>   // 服务名 → 作用域标签
  [symbols.intercept]: Dict          // 服务名 → 拦截配置
  root: this
  baseUrl?: string
  events: EventsService
  logger: LoggerService
  reflect: ReflectService
  registry: RegistryService
}
```

`Context.extend()`/`isolate()`/`intercept()`创建子上下文,原型继承 + 符号键隔离,实现**命名空间隔离**。

**Service**(`vendor/cordis/src/service.ts:11-115`)是暴露命名 API 的基类:

```ts
export abstract class Service<out T = never> {
  static readonly init: unique symbol      // 初始化方法
  static readonly check: unique symbol     // 可用性谓词
  static readonly config: unique symbol    // 拦截配置类型
  static readonly invoke: unique symbol    // 可调用体
  constructor(protected ctx: Context, name: string) {
    // 立即注册,name 默认取 static provide
    self.ctx.reflect.provide(name, self, this[symbols.check])
  }
}
```

Service 注册即生效,自动随所属 Fiber 卸载。

**Plugin**(`vendor/cordis/src/registry.ts:92-146`)支持三种形态:

```ts
export type Plugin<T = any> =
  | Plugin.Function<T>       // (ctx, config) => any
  | Plugin.Constructor<T>    // new (ctx, config) => any
  | Plugin.Object<T>         // { apply(ctx, config) }

export namespace Plugin {
  export interface Base<T = any> {
    name?: string
    Config?: StandardSchemaV1<any, T>   // 配置校验 schema
    inject?: Inject                      // 依赖声明
    provide?: string | string[]          // 提供的服务名
    intercept?: Dict<boolean>            // 消费拦截配置
  }
}
```

#### 2.2 依赖注入与 Fiber 生命周期

`@Inject` 装饰器(`registry.ts:37-60`)声明服务依赖,支持类级别与方法级别。`Inject.resolve()`(`registry.ts:71-89`)统一归一化依赖映射。

**Fiber**(`vendor/cordis/src/fiber.ts:184-754`)是插件运行时实例,拥有**六态生命周期**:

```ts
// vendor/cordis/src/fiber.ts:147-154
export const enum FiberState {
  PENDING,    // 等待依赖服务可用
  LOADING,    // 插件回调执行中
  ACTIVE,     // 已加载并提供服务
  FAILED,     // 配置校验或启动失败
  DISPOSED,   // 已销毁,不可重启
  UNLOADING,  // disposers 执行中
}
```

状态转换由 `_setEpoch()`(`fiber.ts:625-639`)驱动:epoch 是依赖 fiber uid 的拼接串,依赖变化触发 `_reload()`/`_unload()`。`Fiber.await()`(`fiber.ts:704-710`)等待稳定态并 rethrow 启动错误。

**Effect 系统**(`fiber.ts:415-561`)是 Cordis 的清理原语:

```ts
// vendor/cordis/src/fiber.ts:73-93
export type Effect<T = any> =
  | SyncEffect<T>    // Disposable | Iterable<Disposable>
  | AsyncEffect<T>   // Promise<Disposable> | AsyncIterable<Disposable>

export type Disposable<T = any> = () => T
```

`ctx.effect(execute, label)` 注册效果,返回 disposer;disposers 在 fiber 卸载时**逆序执行**,支持异步。这是**显式资源管理**的典范。

#### 2.3 配置校验

`resolveConfig()`(`fiber.ts:50-62`)使用 Standard Schema(V1)校验配置:

```ts
export function resolveConfig(runtime: Plugin.Runtime, config: any) {
  if (!runtime.Config) return config
  const result = runtime.Config['~standard'].validate(config)
  if ('then' in result) throw new TypeError('Async config validation is not supported')
  if (result.issues) throw new ValidationError(result.issues)
  else return result.value
}
```

#### 2.4 动态插件沙箱

`packages/extensions/cordis-host-runner/src/sandbox.ts:1-80` 为动态 Cordis 包提供 **node:vm 沙箱**:

```ts
// sandbox.ts:18-43
export const HOST_BUILTIN_INSPECTION = [
  { name: 'ctx', description: 'Restricted Cordis Context...' },
  { name: 'harness', description: 'Host helpers for RPC and Tools',
    signatures: [
      'harness.handle(method, handler)',
      'harness.defineTool(definition)',
```

沙箱注释明确声明「**is not containment: host-realm helper functions remain an escape route**」——这是合作性沙箱,文件系统/网络/进程通过 `ctx.fs`/`ctx.web`/`ctx.bash` 陷阱重定向。

#### 2.5 原子化程度

**极致原子化**:Context 本身也是 Service 树,`registry`/`events`/`logger`/`reflect` 都是服务。应用 = 插件组合,没有「内核 vs 插件」的边界。80+ 包每个独立版本化、独立加载。

#### 2.6 第三方生态

`packages/extensions/` 含 `cordis-host-runner`/`cordis-client-runner`/`tool-cordis`/`ui-cordis`,是 Cordis 的「动态插件」运行时。`preset/agent-presets/presets/cordis` 提供预设。生态以内部包为主。

#### 3.3 生命周期与 Epoch 机制

#### 3.4 版本管理:semver API 兼容

`src/plugins/package-compat.ts:1-126` 实现 **pluginApi 版本兼容检查**:

```ts
// package-compat.ts:83-114
export function resolvePackagePluginApiRange(packageMetadata: unknown): PackagePluginApiRangeResult {
  // 读取 package.json openclaw.compat.pluginApi 字段

  const pluginApi = compat.pluginApi
```

### 4. atomcode — Rust 编译期 feature gating + 运行时市场

atomcode 代表**Rust 特有的插件范式**:编译期 feature gating 控制能力边界,运行时 marketplace 安装外部插件。

#### 4.1 编译期 feature gating

`crates/atomcode-capabilities/src/lib.rs:105-116` 是核心特征门控:

```rust
// lib.rs:105-116
/// Ported from `atomcode-core`'s `fs_atomic` for the `plugin` feature (trust store).
#[cfg(any(feature = "plugin", feature = "mcp"))]
pub mod fs;

/// Faithful port of `core::plugin` as a v2 migration target for the front-ends.
/// Opt-in behind `feature = "plugin"`.
#[cfg(feature = "plugin")]
pub mod plugin;
```

`crates/atomcode-cli/Cargo.toml:46` 显式启用:
```toml
atomcode-capabilities = { path = "../atomcode-capabilities",
  features = ["notify", "setup", "plugin", "mcp", "atomgit", "cc-hooks"] }
```

**设计含义**:插件子系统(加载器/安装器/市场/清单/信任存储)整个 behind `feature = "plugin"`,不启用则零编译开销。这是 Rust 的**零成本抽象**在插件边界的应用。

## 三、6-10 个可复用设计模式

### 模式 1:双轨 API(promise + effect)

**代表**:opencode v2

**描述**:提供简单异步轨(promise)与函数式效果轨(effect)两套等价 API,让开发者按复杂度选择。

**适用场景**:当宿主生态有函数式编程传统(Effect/Haskell)时,可兼顾简单用例与高级组合。

### 模式 2:Fiber 六态生命周期

**代表**:deepseek-harness Cordis

**描述**:PENDING→LOADING→ACTIVE→FAILED→UNLOADING→DISPOSED 六态 + epoch 驱动依赖追踪,实现**热重载与依赖感知卸载**。

**代码锚点**:`vendor/cordis/src/fiber.ts:147-154`(状态枚举),`fiber.ts:625-639`(epoch 驱动)

**适用场景**:插件有复杂依赖关系、需要热更新而不重启宿主的场景。

### 模式 3:Epoch 世代防护

**代表**:openclaw

**描述**:每个激活的注册表拥有不透明世代对象,退役后旧操作被拒绝,防止 stale 运行时调用污染新状态。

**代码锚点**:`src/plugins/registry-lifecycle.ts:8-21`(全局单例),`registry-lifecycle.ts:49-61`(世代捕获与验证)

**适用场景**:长运行服务中插件热替换、Gateway 重启后旧插件实例清理。

### 模式 4:编译期 Feature Gating

**代表**:atomcode

**描述**:整个插件子系统 behind `#[cfg(feature = "plugin")]`,不启用则零编译开销;运行时市场安装外部插件。

**代码锚点**:`crates/atomcode-capabilities/src/lib.rs:105-116`

**适用场景**:Rust 项目需要「核心稳定 + 可选扩展」的物理边界,如 CLI 工具的能力分级。

### 模式 5:策略 fail-closed

**代表**:openclaw plugin-sdk

## 四、laew 借鉴路线与 Rust 运行时插件路径评估

### 4.1 laew 现状

laew 是 Rust 多 Agent CLI,当前**零插件机制**:
- 6 角色 Agent(Yolo/Plan/Main-Work/SubAgent-Work/Quality-Check/SessionContext)编译期内置
- 3 工具(Bash/Read/Write)编译期内置
- 能力边界 = 二进制边界

### 4.2 Rust 运行时插件路径评估

| 路径 | 机制 | ABI 稳定 | 生态 | 适用场景 | 推荐度 |
|------|------|---------|------|---------|--------|
| **dylib(load)** | 动态链接 `.so`/`.dylib` | 需 `abi_stable` | 弱 | 同机器、同编译器版本 | ⭐⭐ |
| **abi_stable** | `#[sabi(StableAbi)]` trait object | ✓ | 中 | 跨版本插件 | ⭐⭐⭐ |
| **WASM** | wasmtime/wasmer 沙箱 | ✓(WASI) | 强 | 安全隔离 + 多语言 | ⭐⭐⭐⭐ |
| **子进程 IPC** | stdin/stdout JSON-RPC | ✓(进程边界) | 强 | 最大隔离、异构语言 | ⭐⭐⭐⭐ |
| **WASM + 子进程** | WASM 沙箱内运行 + 进程隔离 | ✓✓ | 中 | 最高安全 | ⭐⭐⭐ |

**推荐路径**:**子进程 IPC**(短期)→ **WASM**(中期)。

**理由**:
- **子进程 IPC** 实现最简单:插件是独立二进制,通过 JSON-RPC/NanoMsg 通信,崩溃不影响宿主,语言无关。laew 已有 Bash 工具,可复用进程管理。
- **WASM** 提供更强隔离:wasmtime 沙箱限制文件系统/网络访问,适合不可信第三方插件。但 Rust→WASM 的工具链成熟度与 laew 的 Rust 核心集成成本需评估。
- **dylib/abi_stable** 风险高:Rust 无稳定 ABI,编译器版本/标准库版本不一致即崩溃,不适合第三方分发。

### 4.3 分阶段借鉴路线

#### P0(1-2 周):插件契约定义 + 子进程加载

借鉴 **pi 的 ExtensionAPI 形状** + **atomcode 的 manifest 格式**:

```rust
// 插件 manifest: laew-plugin.json
{
  "name": "my-tool",
  "version": "0.1.0",
  "laew": { "compat": ">=0.1.0" },
  "entry": "index.ts",  // 或 "my-plugin.wasm" / "my-plugin"
}

// 插件接口(子进程 IPC)
pub trait Plugin {
    fn name(&self) -> &str;
    fn tools(&self) -> Vec<ToolDefinition>;
    fn on_event(&mut self, event: Event) -> Result<()>;
}
```

- 定义 `PluginManifest` + `PluginSource`(git/local/path)
- 实现 `PluginLoader`:从 `~/.laew/plugins/` 发现,spawn 子进程,JSON-RPC 握手
- 复用现有 `Tool` trait,插件工具与内置工具统一注册到 `ToolRegistry`

#### P1(2-4 周):生命周期 + 配置校验

借鉴 **Cordis Fiber 六态** + **openclaw semver compat**:

```rust
enum PluginState { Pending, Loading, Active, Failed, Unloading, Disposed }

struct PluginRuntime {
    manifest: PluginManifest,
    process: Child,
    state: PluginState,
    epoch: u64,  // openclaw 世代防护
}
```

- `laew.compat` semver 范围校验
- 插件崩溃不影响宿主(进程隔离天然保证)
- `PluginJobEvent`(atomcode 风格)异步安装结果

#### P2(1-2 月):安全沙箱 + 市场

借鉴 **claudecode 策略 fail-closed** + **pi 项目信任**:

- 子进程权限限制(可选 WASM 沙箱)
- `policy.json` 企业白名单/黑名单
- `project_trust` 事件让用户确认插件权限
- marketplace manifest 格式(兼容 CC 降低迁移成本)

#### P3(3-6 月):WASM 沙箱 + 第三方生态

- wasmtime 运行时,插件编译为 WASM
- 标准化 `wasi-nn` 或自定义 host function 暴露 laew 能力
- 官方插件市场 + 第三方注册

### 4.4 关键设计决策

1. **插件能拿到什么?**
   - 短期:子进程无特殊权限,通过 host function 请求(读文件/网络需审批)
   - 中期:WASM 沙箱默认无权限,manifest 声明所需能力

2. **插件间依赖?**
   - laew 初期应**禁止插件间依赖**,保持隔离;如需通信,通过宿主事件总线

3. **版本兼容?**
   - 采用 openclaw 的 `compat.semver` 范围,宿主版本不满足则拒绝加载

4. **命名空间?**
   - 工具名/命令名加插件前缀(`plugin__tool`),避免冲突

## 五、核心发现

1. **Cordis 的 Fiber 六态 + epoch 依赖追踪是「热重载」的最强范式**:`vendor/cordis/src/fiber.ts:147-154` 定义 PENDING→LOADING→ACTIVE→FAILED→UNLOADING→DISPOSED 状态机,epoch 字符串(依赖 fiber uid 拼接)驱动 `_reload()`/`_unload()`,实现依赖感知的热更新而不重启宿主。

2. **openclaw 的 epoch 世代防护解决了「stale 运行时」难题**:`src/plugins/registry-lifecycle.ts:8-21` 通过全局单例的 `WeakMap<PluginRegistry, object>` 为每个激活创建不透明世代,退役后旧操作被拒绝,是工业级插件热替换的关键机制。

3. **claudecode 的策略 fail-closed + 同形字防护是分发安全的底线**:`src/utils/plugins/schemas.ts:19-101` 通过白名单保留官方名称、阻止非 ASCII 字符(防 Cyrillic 同形字)、模式匹配冒充名称,三层防护品牌钓鱼。

4. **pi 的 ExtensionAPI 是「开发者体验」的标杆**:`packages/coding-agent/src/core/extensions/types.ts:1252-1506` 提供 30+ 事件 + `ctx.ui.*` 交互 + `registerProvider` + `ToolCallEvent` 按工具名区分联合,配合 79 个示例扩展,是第三方上手最友好的系统。

5. **Rust 做运行时插件应选「子进程 IPC」而非 dylib**:atomcode 的 `#[cfg(feature = "plugin")]`(`crates/atomcode-capabilities/src/lib.rs:105-116`)证明编译期 gate 适合能力边界,但第三方分发需进程/WASM 隔离——Rust 无稳定 ABI,dylib 跨编译器版本必崩。
