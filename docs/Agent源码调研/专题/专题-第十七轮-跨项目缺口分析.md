## 二、最佳实践提炼

### 2.1 崩溃恢复与取证 → **claudecode 五层防御**

```
Layer 1: 进程级信号处理（SIGINT/SIGTERM/SIGHUP/SIGCONT/SIGUSR2）
Layer 2: 优雅关闭协调器（failsafe 定时器 + 分层清理 + 超时保护）
Layer 3: Heap Dump 服务（V8 snapshot + 诊断 JSON + 1.5GB 自动触发）
Layer 4: 会话恢复（Bridge Pointer 4h TTL + 交互式会话选择）
Layer 5: 清理注册表（全局 Set<cleanupFn> + Promise.all + 2s 超时）
```

**最佳设计**：`gracefulShutdown.ts`（529 行）的 failsafe 定时器 + 分层清理顺序（终端模式 → 会话数据 → Hook → Analytics → 强制退出），每一层都有超时保护，确保进程**一定退出**。

### 2.2 多租户隔离 → **openclaw Session Work Admission**

```
准入控制：lifecycleGeneration 检测旧进程 + 排他写入
恢复状态机：reserved → attempted → consumed → accepted → abandoned
中断传播：MAX_INTERRUPTION_AGE_MS = 2h
退避重试：1s → 2s → 4s → 8s → 16s（最多 5 次）
```

**最佳设计**：`subagent-registry-restart-recovery.ts`（551 行）的幂等键 + 恢复阶段机 + 退避策略，确保崩溃恢复不重复、不遗漏。

### 2.3 RRF 混合检索 → **opencode 多信号融合**

```
统一检索 Bus：多策略融合（全文 + 向量 + 语义）
多 Provider：filesystem / bundled / custom
候选合并排序：project-dsh(100) > user-agents(500)
```

**最佳设计**：opencode 的检索 Bus 抽象允许插拔多种检索策略，虽非标准 RRF，但架构最可扩展。

### 2.4 LLM 网关路由 → **openclaw Failover 16 种原因分类**

```
402 billing 细分：billing / rate_limit / quota
多层分类器：Provider 级 → Model 级 → Request 级
结构化错误：错误码 + 错误消息 + 重试建议
```

**最佳设计**：`failover-classifier.ts` 的 16 种故障原因分类 + 多层分类器 + 结构化错误输出，是 7 工程中最完整的故障处理体系。

### 2.5 Pregel 图执行 → **openclaw SubAgent 图执行模型**

```
消息传递：announce / steer / collect 三种消息类型
收集器启动：Collector 模式收集 SubAgent 结果
通道序列化：8 通道 Command Queue 保证消息有序
```

**最佳设计**：openclaw 的 SubAgent 图执行模型（announce/steer/collect）是最接近 Pregel 消息传递语义的实现。

### 2.6 Skill 生命周期 → **openclaw Skill Workshop**

```
5 级发现链：workspace → agents → personal → managed → bundled
提案状态机：pending → applied / rejected / quarantined / stale
版本演进：SkillSnapshot 注入 SubAgent 启动
```

**最佳设计**：openclaw 的 Skill Workshop 提案状态机 + 5 级发现链 + 版本演进，是 7 工程中最完整的 Skill 生态。

### 2.7 Agent 预热池 → **deepseek-harness Warm Pool**

```
WarmKey 多维匹配：多维度键值匹配预热 Agent
WarmRevision 配置指纹：配置变更时自动失效预热
健康检查：自动替换不健康 Agent
```

**最佳设计**：deepseek-harness 的 `agent_warm_pool.py`（30KB）的 WarmKey + WarmRevision 机制，实现了配置感知的 Agent 池化管理。

### 2.8 Turn 锁 → **deepseek-harness Durable Turn Lease**

```
跨进程 Turn 锁：Durable Turn Lease（跨进程排他）
Session Checkpoint：llm/stream + tools/execute + agent/pre-step 三层检查点
Torn-tail 修复：检测并截断崩溃时的不完整写入
```

**最佳设计**：deepseek-harness 的 Durable Turn Lease + 三层语义检查点 + Torn-tail 修复，是 7 工程中最完整的 Turn 级一致性保证。

### 2.9 HTTP 客户端 → **openclaw Guarded Fetch + SSRF 防护**

```
DNS 钉扎：防止 DNS 重绑定攻击
IP 验证：阻止内网 IP 请求
策略合并：多策略组合防护
本地起源绕过：localhost/127.0.0.1 白名单
```

**最佳设计**：openclaw 的 Guarded Fetch（DNS 钉扎 + IP 验证 + 策略合并）是 7 工程中最完整的 SSRF 防护实现。

### 2.10 安全加固 → **claudecode 22 层 bash 防御 + openclaw Prompt 注入防护**

```
claudecode：bashSecurity 22 层防御（命令替换检测 / Zsh 危险命令 / ...）
openclaw：外部内容 Prompt 注入防护（14 种可疑模式 + 随机边界 + LLM Token 剥离）
openclaw：Secret Sentinel 内存加密 + Docker 沙箱安全验证
```

**最佳设计**：claudecode 的 22 层 bash 防御 + openclaw 的 Prompt 注入防护 + Secret Sentinel 共同构成了最完整的安全加固体系。

## 五、跨项目架构交叉点

第十七轮 10 个维度存在 **7 个关键交叉点**（与 openclaw 的 6 个交叉点互补）：

1. **崩溃恢复 × 多租户**：openclaw 的 `lifecycleGeneration` 同时服务于崩溃恢复（检测旧进程）和多租户隔离（排他写入）——**laew 两个维度都缺失**

2. **LLM 路由 × 安全加固**：openclaw 的 Failover 分类器 402 billing/rate_limit 细分依赖安全审计的暴露矩阵检测——**laew 的 Provider 管理无故障分类**

3. **Skill 生命周期 × Agent 预热池**：openclaw 的 SkillSnapshot 被 SubAgent 启动时注入，影响预热池的 prompt 构建——**laew 两个维度都缺失**

4. **Turn 锁 × Pregel 图执行**：openclaw 的 Command Queue 8 通道序列化保证 SubAgent 图执行的消息传递有序性——**laew 的 Orchestrator 无通道序列化**

5. **HTTP 客户端 × 安全加固**：openclaw 的 Guarded Fetch SSRF 防护是安全审计框架的网络层基础——**laew 的 reqwest 无防护**

6. **RRF 检索 × Skill 生命周期**：openclaw 的 Link Understanding 链接提取结果可触发 Skill Workshop 提案生成——**laew 两个维度都缺失**

7. **可观测性 × 崩溃恢复**：atomcode 的 Telemetry health.json + claudecode 的 Heap Dump 共同构成崩溃前的预警体系——**laew 无健康快照**

## 六、总结

### 6.1 7 工程共性结论

1. **分层崩溃恢复是标配**：6/7 工程实现了从进程级到会话级的分层恢复，laew 完全缺失
2. **多租户是共性短板**：7 工程中仅 openclaw 有初步 RBAC，整个领域薄弱
3. **RRF 检索是空白**：无工程实现标准 RRF，claudecode 的 Sonnet 选择器是最实用方案
4. **熔断器是稀缺能力**：仅 openclaw 有完整故障分类 + 熔断，laew 需优先补齐
5. **Pregel 图执行是盲区**：7 工程均无完整 Pregel 实现，openclaw 的 SubAgent 图最接近
6. **Skill 生态是趋势**：所有工程都有 Skill 能力，openclaw 的 Workshop 是最完整实现
7. **安全加固是最大 gap**：Prompt 注入防护、密钥管理、沙箱隔离在 7 工程中普遍薄弱
