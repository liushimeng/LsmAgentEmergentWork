## 八、关键工程洞察

### 8.1 HTTP 客户端成熟度

- **atomcode（Rust 同技术栈）**：是最直接的参考对象，但 `SwappableClient` 的池毒化机制需要自己实现
- **undici**：Node.js 官方库，`RetryHandler 548 行` + `Dispatcher compose` 是教科书级实现
- **openclaw**：`DNS pinning + PinnedDispatcherPool LRU` 是 SSRF 防御最完整

### 8.2 安全防御金标准

- **jiuwenswarm JiuwenBox**：BubbleWrap + Landlock + Seccomp + netns + cgroup 五层防御
- **claudecode**：27 Hook + Permission 5 态 + Platform-specific Keychain
- **atomcode**：双 pass scrub + `<system-reminder>` 边界 + capabilities 分层

### 8.3 模型路由最佳实践

- **Switchyard 8 种路由算法** + **Prometheus** + **JSONL 路由日志** = 最完整的 LLM 网关
- **openclaw 16 种 FailoverReason** + **时间驱动冷却** = 最复杂 failover 状态机
- **claudecode 429 三层决策** + **Fast Mode 熔断** = 最完整配额感知路由

### 8.4 数据迁移关键模式

| 模式 | 优点 | 缺点 | 代表 |
|------|------|------|------|
| 链式迁移（cc-switch） | 易理解、可回滚 | 多步冗长 | cc-switch |
| 声明式列补齐（hermes-agent） | 自动处理加列 | 不支持删列 | hermes-agent |
| Per-domain（openclaw） | 模块化、隔离 | 跨域复杂 | openclaw |
| 幂等函数式（claudecode） | 简单、安全 | 需手动实现幂等 | claudecode |
| Effect 数组式（opencode） | 类型安全 | TS 限定 | opencode |
| 文件迁移（pi） | 适合文件重组 | 不适合数据库 | pi |

### 8.5 性能优化关键模式

- **atomcode 内容寻址**：sha256 修订号 + artifact 缓存
- **claudecode `_CACHED_MAY_BE_STALE`**：缓存命名约定 + 主动失效
- **openclaw LRU-with-pinning**：三态保护（fresh / stale / pinned）
- **opencode Scope-driven eviction**：按作用域淘汰（替代 LRU）
- **pi Lane 三态 + Writer Lease**：并发隔离 + 乐观锁
- **TencentDB PipelineWorker 60 协程**：高并发处理 + 锁冲突指数退避
