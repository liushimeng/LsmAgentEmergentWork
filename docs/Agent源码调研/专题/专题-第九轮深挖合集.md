## 四、第九轮 8 维度的核心借鉴链

1. **Crash / Recovery（最热的「急需补」项）**：atomcode 的 `panic::set_hook` 双阶段（简易版 + telemetry 升级版）+ claudecode 的 graceful shutdown（5s failsafe + Bun-bug hack）+ opencode 的 `t("retry_after")` 头优先退避 + Switchyard 的 `RouteErrorKind` 12 类稳定分类 —— 4 工程范本拼出 laew 错误处理全景。

2. **OAuth / Keyring（最重要的「安全网」项）**：atomcode 的 0o600 + atomic rename + fs2 跨进程锁 + agent-studio 的 AES-GCM-256 + KMS 可选 + Switchyard 的 Debug 永远 REDACTED + openclaw 的 90+ token 前缀正则 + UTF-16 安全 —— 5 工程范本拼出 laew 凭证管理路径。

3. **Release 工程化（最稳的「流程升级」项）**：atomcode 的 `crates/atomcode-updater` 自研 updater 6 步流程 + 三段式 rename + openclaw 的 `validate_release_identity` 强制正则 + 不可变 tag + 全 SHA 双锁 + cc-switch 的 Tauri updater + Ed25519 + 双 endpoint fallback + pi 的 `scripts/release.mjs` 10 步自动化 —— 4 工程范本拼出 laew CI / 发布 / Auto Update 路径。

4. **Web UI / Desktop（最值的「前端扩展」项）**：openclaw 的 5 端齐全（Web/Desktop/Mobile/Bridge/TUI）+ opencode 的 Electron 42 + sidecar Node + atomcode 的 2 端 TUI+Web + agent-studio 的 i18next 标准栈 + cc-switch 的 Tauri 2 —— laew 应从"独立 CLI 渲染引擎"扩展到"Axum + Web 远控"。

5. **i18n（最严的「质量门」项）**：openclaw 的自研 I18nManager + lazy chunk + LLM 翻译 pipeline + opencode 的 63 语言 + parity.test.ts + deepseek-harness 的 bilingual hash gate —— laew 是 8 工程中 i18n 最少的，必须从 0 开始（`rust-i18n` + YML + parity test）。

6. **WS / SSE（最深的「协议升级」项）**：undici 的 RFC 6455 完整握手 + claudecode 的双层 keepalive + sleep detection + atomcode 的 SSE keep_alive 15s + opencode 的 WebSocketTracker 1s 优雅关闭 —— laew 当前 LLM 单次 request-response 升级到 SSE 流式是关键。

7. **Dev Container（最干净的「环境一致」项）**：openclaw 的 SHA256 digest 钉死 + Dependabot 刷新 + 7 阶段多阶段构建 + Switchyard 的两阶段 builder+slim + `force-frame-pointers` —— laew 是 9 工程中唯一零容器化，加 3 阶段 Dockerfile + compose 即可补齐。

8. **CRDT / 协同（最稳的「企业级」项）**：openclaw 的 lifecycleRevision CAS + endedAt timestamp merge + semantica 的 BiTemporal + Allen interval + TencentDB 的双层锁 + 409 retry + Switchyard 的 Unknown 透传 —— laew 当前单进程无需 CRDT，但 `lifecycle_revision` CAS + JSONL append 是未来多端协同的最小路径。
