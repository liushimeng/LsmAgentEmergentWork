## 四、第八轮 8 维度的核心借鉴链

1. **Telemetry（最热的「急需补」项）**：claudecode 的 OTel 三栈 + atomcode 的双 pass scrub + openclaw 的 OWNED SDK 隔离 + pi 的类型化 schema —— 4 工程范本拼出 laew 的 OTel 集成路径。

2. **Session 持久化（最重要的「安全网」项）**：pi WriterLease 的乐观锁范式 + opencode 的 6 PRAGMA 单文件配置 + claudecode tail-tombstone 行级修复 + atomcode 的 `temp+fsync+rename+fsync(parent_dir)` 4 步原子写 —— 4 工程范本拼出 laew 的 WAL 实现。

3. **Tool 权限（最危险的「放任」项）**：atomcode 16 种 destructive 模式 + claudecode 三层防御（用户态/进程级/OS 系统调用）+ deepseek `wider_modes` widening algebra + opencode `Wildcard.match` Win32 `si` flag —— laew 应先实现 3 态状态机，再加 bwrap+landlock 双层沙箱。

4. **LSP / IDE 集成（最值得抄的「CodeIntel 七件套」）**：atomcode 的 8 个 CodeIntel 工具（list_symbols/read_symbol/find_references/...）是唯一完整的「LSP → LLM 工具」转译范式 —— laew 应直接照搬其架构。

5. **Hook / Extension（最干净的「拦截」抽象）**：claudecode 27 种 Hook + 4 种执行器（command/http/prompt/agent）+ openclaw 153 个 bundled 插件 + atomcode `plugin_hook_set_hash`（SHA-256 + 长度前缀防冲突）—— laew 应先实现 8 个最常用 Hook 事件。

6. **Skill（最严的「质量门」项）**：jiuwenswarm 12 阶段 SkillDevPipeline + openclaw Workshop 5×4 状态机 + TencentDB SKILL_ID_COLLISION 防御（CSPRNG base62 12 字符） —— laew 是 8 工程中唯一零 Skill 系统的，必须从 0 开始。

7. **多租户 / 团队记忆（最稳的「企业级」项）**：TencentDB-Agent-Memory L0-L3 管线 + RRF 公式 (k=60) 混合检索 + 9 个 InjectionPoint —— laew 当前 SQLite 单机本地，团队记忆暂不急，但 5 元组隔离列应预留。

8. **TUI 渲染管线（最深的「终端协议」项）**：atomcode `screen.rs` 嵌套抑制 sync_suppressed + pi DESIRED_KITTY_KEYBOARD_PROTOCOL_FLAGS = 7 + openclaw RESET_SEQUENCE 完整 RESET —— laew 当前 `present()` 全量重绘，需要升级为 cell-based retained。
