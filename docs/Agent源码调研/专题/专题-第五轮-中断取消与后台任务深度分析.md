## 2. 用户中断的完整传播链

### 2.1 atomcode:Rust 三件套传播

```
TUI 按键 → (推断) AgentCommand::Cancel (cmd_rx)
       ↓
session_loop select! 收到 Cancel
       ↓
internal_cancel.store(true, Ordering::Release)   // 协作信号
turn_token.cancel()                                // CancellationToken 协作信号
self.rt.cancel_pending()                           // 强解 oneshot 等待
       ↓
run_turn 的 tokio::select! 内:
  - turn_token.cancelled() 立即触发
  - tool.execute 内 tokio::select! biased; cancel 分支
       ↓
工具返回 ToolResult { content: "(cancelled — side effects unknown)", is_error: true }
       ↓
message::backfill_cancelled_tool_results(convo) // 补回所有缺失 tool_result
       ↓
finish_turn(convo, StopReason::Cancelled, ctx)
```

**关键设计**:`message.rs:438-439` 的 `backfill_cancelled_tool_results` —— 协议一致性是硬约束,anthropic/openai 都拒绝 orphan tool_use。

### 2.2 claudecode:AbortController 全链路

```
TUI 按 Esc/Ctrl-C → AbortController.abort(reason='interrupt')
       ↓
QueryEngine.this.abortController.abort()  // L1159
       ↓
toolUseContext.abortController 透传所有工具
       ↓
Bash 工具:
  exec(command, abortController.signal, ...) → 子进程 SIGTERM
       ↓
子代理:
  runAgent.ts:524 agentAbortController = override?.abortController ?? new AbortController()
       ↓
query.ts:1500-1515:
  if (signal.reason !== 'interrupt') yield createUserInterruptionMessage
  return { reason: 'aborted_tools' }
```

**特殊点**:`GrepTool.ts:438` 注释「We don't use AbortController for timeout to avoid interrupting the agent loop」——超时与取消解耦,避免工具超时把 agent loop 拽下来。

### 2.3 openclaw:turn-interruption 显式模块

```
agent-loop.ts 收到中断命令
       ↓
turn-interruption.ts::appendInterruptedTurnMessage
       ↓
合成一条 user 消息注入下一轮(instead of 静默截断)
       ↓
后续轮次从这条 user 消息开始,协议上下文连续
```

**与 atomcode 的差异**:openclaw 用「合成 user 消息」(协议连续),atomcode 用「backfill tool_result」(协议补全)——两种策略都解决了「协议一致性」,但语义不同:openclaw 显式标记"用户打断了";atomcode 仅补回"工具已尝试"。

### 2.4 deepseek-harness:钩子可扩展

```
abortController.abort() → signal.throwIfAborted()
       ↓
agent.ts:269 turn() while(true) 入口检查
       ↓
agent.ts:346 step() 内 finish.kind === 'aborted' →
  await this.dispatch.waterfall('agent/request-error', { agent, failure, signal })
       ↓
钩子链决定:retry / 改 prompt / 放弃
       ↓
如果放弃 → throw new LlmError(..., finish.failure.code, finish.failure)
```

**关键设计**:`agent/request-error` 钩子可决定下一步——不只是「重试到 N 次放弃」,而是「让插件决策」。

### 2.5 opencode:Effect 三态 + Stream.takeUntil

```ts
stream.pipe(Stream.tap(handleEvent),
            Stream.takeUntil(() => ctx.needsCompaction),
            ...)
Effect.retry(SessionRetry.policy({ ... }))
Effect.catch(halt)
```

- `takeUntil` 优雅终止流
- `Effect.retry` 是声明式重试
- `Effect.catch(halt)` 处理可恢复错误
- 三态 `compact / stop / continue` 返回主循环,主循环 switch

### 2.6 pi:AbortController + 双层 while(true)

```
agent.abort() → this.activeRun?.abortController.abort()
       ↓
executor(abortController.signal) 协作传播
       ↓
工具内:
  signal?.addEventListener("abort", onAbort, { once: true })
       ↓
agent-loop.ts:215 短路:
  if (message.stopReason === "error" || === "aborted") {
    emit turn_end + agent_end; return
  }
```

**特殊点**:无 maxTurns 上限,纯靠 stopReason/pendingMessages 退出。

### 2.7 undici:fetch 中断语义

```
controller.abort(reason)   // L221 / L1979 / L2036
       ↓
this.state = 'aborted'
       ↓
this.connection?.destroy(error)
       ↓
this.emit('terminated', error)
```

## 3. 取消原语的设计对比

### 3.1 三大原语家族

| 原语家族 | 代表仓库 | 优势 | 劣势 |
|---|---|---|---|
| `tokio_util::sync::CancellationToken` | atomcode | 支持父子派生(`child_token()`),可树形传播 | 仅限 Rust 生态 |
| `AbortController` + `AbortSignal` | claudecode / deepseek / pi / openclaw(TS)/ undici(Node) | Web 标准,跨运行时 | 不支持父子派生,需手写 `{ signal, child }` 包装 |
| Effect `halt` + Stream `takeUntil` | opencode | 与 Effect 生态整合,声明式 | 仅在 Effect 上下文有效 |

### 3.2 atomcode 的双路信号(CancellationToken + AtomicBool)

```rust
internal_cancel.store(true, Ordering::Release);  // ① AtomicBool 协作信号
turn_token.cancel();                              // ② CancellationToken 协作信号
self.rt.cancel_pending();                         // ③ 强解 oneshot 等待
```

**为什么需要 AtomicBool?** Token 是引用计数的协作原语,**不保证立即**——某些热路径会先检查 `AtomicBool.load(Acquire)` 而不 await `cancelled()` future,减少一次 await 开销。

**为什么需要 cancel_pending(强解 Null)?** oneshot 的等待者被 cancel_token 触不到(token 是新概念)——必须手工 flush `Value::Null`(JSON-RPC 语义,fail-closed)。

### 3.3 TS 仓库的 AbortController + signal 协作

```ts
// claudecode runAgent.ts
const agentAbortController = override?.abortController ?? new AbortController()
// ...
await executor(abortController.signal)
// ...
if (abortController.signal.aborted) yield createUserInterruptionMessage
```

**注意**:signal 是只读的,真正控制的是 controller。要传递"可被父取消 + 可取消子" 需要手写包装:

```ts
class CompositeAbortSignal {
  private _aborted = false
  private _reason?: unknown
  private _children: AbortController[] = []
  constructor(public parent?: AbortSignal) {
    if (parent) parent.addEventListener('abort', () => this.abort(parent.reason))
  }
  abort(reason?: unknown) { /* 递归取消 children */ }
}
```

**没有仓库手写这个包装**——都是简单传 `parent.signal` + 让每个 controller 独立监听 parent。这是个潜在改进点。

## 4. 后台任务系统

### 4.1 claudecode:LocalShellTask(最完整)

`src/tools/BashTool/BashTool.tsx:904` 后台任务走 `spawnShellTask(...)`(`src/tasks/LocalShellTask/LocalShellTask.ts`):

- 进度回调 `onProgress(lastLines, allLines, totalLines, totalBytes, isIncomplete)` —— generator 持续唤醒
- 持久化文件 64MB 上限
- 独立 task channel,与主 agent loop 解耦
- `MAX_SUBCOMMANDS_FOR_SECURITY_CHECK = 50`

### 4.2 openclaw:placement 三态(active/draining/reconciling)

不是真正的「后台任务」抽象,而是会话迁移的状态机:

- `active`:正常服务
- `draining`:正在迁移,新请求不发,但允许在飞请求完成
- `reconciling`:新 worker 接管,核对状态

通过 `runWithConcurrency`(`memory-host-sdk/src/host/concurrency.ts:6-32`)实现 stop-and-drain 语义:

```ts
await pMap(tasks, run, { concurrency, stopOnError: true })
// p-map stops dequeuing on error, but active memory writes must drain before callers recover.
await Promise.allSettled(inFlight);
```

### 4.3 atomcode:daemon 模式 + bg_runtime

daemon 模式本身就是后台任务系统。具体调度见第四轮文档的 daemon 与 coding 核心章节。

### 4.4 pi / opencode / deepseek

- pi:无独立后台任务抽象,extensions/自定义命令可注册
- opencode:background bash 任务,plan mode 显式
- deepseek:`subagent-spawn-in-process` / `subagent-fork-in-process` —— 子代理本身就是后台任务

## 5. 中断后的消息一致性修复

### 5.1 orphan tool_use 是什么?

模型发出 `tool_use` block 但用户中断导致没有 `tool_result` 回复。Anthropic / OpenAI 都拒绝——下次请求会 400。

### 5.2 5 种修复策略

| 仓库 | 策略 | 代码位置 |
|---|---|---|
| **atomcode** | backfill `"(cancelled)"` | `message.rs:438-439` |
| **claudecode** | yield `UserInterruptionMessage` | `query.ts:1500-1515` |
| **openclaw** | turn-handoff 合成 user 消息 | `turn-interruption.ts` |
| **deepseek** | `compaction/start`/`compaction/end` 事务 | `region.ts:191-218` |
| **opencode** | processor `return "stop"` | `processor.ts:641-696` |
| **pi** | emit `turn_end` + `agent_end` | `agent-loop.ts:215-218` |

### 5.3 tool-call-repair(openclaw)

如果 LLM 输出 plain-text 工具调用乱码(没匹配 `tool_use` schema),openclaw 的 `tool-call-repair` 五阶段管线(grammar → payload → protection fast-path → stream-normalizer → promote)会试图修复:

```ts
// protection-fast-path.ts:17-103
export function resolveProtectionFastPath(...) {
  // 识别 fenced code、缩进块、`>`、`-/*/+`、`1.` 等行级保护范围
  // 只在保护范围外扫描工具调用
}
```

这是另类的"中断修复"——不是中断,LLM 输出损坏,仍然要保持协议一致。

## 6. 共性模式总结

### 6.1 取消必须级联到进程组

atomcode 的 `kill_on_drop` + claudecode 的 `exec(command, signal, ...)` + pi 的 `once: true abort listener` —— 取消信号必须传到子进程,不能只断网络流。

**laew 现状**:`src/agent/tools/bash.rs` 用 `tokio::process::Command`,但**无 `kill_on_drop(true)` 配置**,也没有从 abort signal 触发 kill 的代码。中断后子进程可能成孤儿。

### 6.2 中断消息也是一条 user 消息

claudecode `UserInterruptionMessage` + openclaw `appendInterruptedTurnMessage` + atomcode `backfill_cancelled_tool_results` —— 三种方式都遵循「协议一致性」:

- 用户的打断是有语义的(可能是「算了」「不」「再想想」)
- 工具的中断是协议的(必须配对 tool_result)

### 6.3 LLM 错误由钩子决策,不止于重试

deepseek-harness 的 `agent/request-error` 钩子可决定:
- retry
- 改 prompt(下次重发不同内容)
- 放弃(fail-closed)

比"内置 retry N 次后放弃"灵活得多。

### 6.4 abort controller 与 timeout 解耦

claudecode 的 GrepTool 注释「We don't use AbortController for timeout」——超时是工具内部事务,取消是 agent loop 事务,二者解耦可避免「工具超时把整个 loop 拽下来」。

### 6.5 失败必须留痕迹

atomcode 的 `compact/start` + `compact/end` 事务 + deepseek 的 `TransactionFailure['stage']` —— 任何压缩/迁移/写入失败必须留下 error 标记,避免 abandoned 中间态永久污染 session。

## 7. 对 laew 的借鉴路线

### 7.1 P0(立即)

| 项 | 当前 laew 现状 | 借鉴内容 |
|---|---|---|
| **AbortController 通路** | `run_session`(`src/agent/mod.rs:78`)无 abort 信号 | 引入 `CancellationToken` 或 `tokio::sync::Notify`,TUI 按 Esc/Ctrl-C 触发 |
| **Bash 子进程 kill** | `src/agent/tools/bash.rs:7` `use tokio::process::Command;` 但无 `kill_on_drop(true)` | 加 `kill_on_drop(true)` + 把 abort signal 接到 `child.wait()` 的 select! |
| **消息层 backfill** | 无 backfill,中断后直接 break | 引入 `repair_pairing()` 在 abort 时把已发出的 tool_call 补 `(cancelled)` |

### 7.2 P1(中期)

| 项 | 借鉴内容 |
|---|---|
| **Steering queue** | 用户中途消息入 steer 队列(下一轮 fold),不打断当前 turn —— 区分"取消"与"新增问题" |
| **maxTurns 传递** | SubAgent-Work 也独立 maxTurns(目前无限) |
| **压缩摘要 anchor** | `<previous-summary>` 提示让模型续写而非重写 |
| **后台任务** | Long-running bash 任务走 `LocalShellTask` 模式,独立 channel 与 64MB 上限 |
| **失败熔断** | 连续 N 次压缩失败 / 工具失败后停止重试 |

### 7.3 P2(长期)

| 项 | 借鉴内容 |
|---|---|
| **钩子决策** | 不只内置 retry,允许注册 `agent/request-error` 等钩子 |
| **tool-call-repair** | LLM 输出 plain-text 工具调用时五阶段修复(当前 laew 直接 error) |
| **placement 三态** | 会话迁移(active/draining/reconciling)—— 仅当 laew 上 server 模式时需要 |
| **GC 泄漏防护** | 长流期间 AbortController 引用链 hint |
