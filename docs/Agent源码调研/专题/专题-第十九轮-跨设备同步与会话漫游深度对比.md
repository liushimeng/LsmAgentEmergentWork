## 1. 摘要与导读

laew 当前是**单进程单用户单设备**模型，**无任何跨设备同步/会话漫游能力**。前 18 轮在 CRDT/协同编辑（第九轮 L74-L78）、分布式部署（第十四轮）、多租户（第八轮）等维度有涉及，但**从未专门深挖"跨设备同步与会话漫游"**这一用户交互体验层核心维度。

第十九轮 **D14 共 50 个 gap（L1881-L1930）**：

| Gap 范围 | 子维度 | 紧急数 | 重要数 | 进阶数 |
|---------|--------|--------|--------|--------|
| L1881-L1890 | D14-1 设备发现与配对 | 3 | 4 | 3 |
| L1891-L1900 | D14-2 会话漫游（Session Handoff） | 3 | 4 | 3 |
| L1901-L1910 | D14-3 同步协议 | 3 | 4 | 3 |
| L1911-L1920 | D14-4 加密与隐私 | 3 | 4 | 3 |
| L1921-L1930 | D14-5 状态合并与冲突 | 3 | 4 | 3 |

**关键发现**：
1. **openclaw 是最完整的跨设备同步实现**：Ed25519 设备身份 + 配对审批 + Tailscale 集成 + AES-256-GCM 内存加密 + Gateway 多端接入，**合计 2894 行**核心代码。
2. **opencode 的 share-next.ts EventV2 是会话共享的范本**：1 秒批 flush + 双 base URL 鉴权 + "steal" 会话抢占机制。
3. **claudecode 的 Bridge 远程控制是"远程接管"范本的唯一实现**：WebSocket 长连接 + 可信设备 token + 4h TTL 崩溃恢复指针。
4. **deepseek-harness 的 Typert Remote 协议是"服务端推送事件流"范本**：generation 单调递增 + 自动重连 + waterfall/emit 双模式。
5. **atomcode 的 LiveViewHub 是"同设备多视图实时同步"范本**：broadcast::channel(1024) + generation 防 stale binding。
6. **pi 的 `pi.share` trailing entry 是"轻量导出分享"范本**：JSONL + Radius→Gist fallback。
7. **undici 不参与本维度**（纯 HTTP 客户端，无 Agent 会话层）。

```typescript
export function generateStoredDeviceIdentity(now = Date.now()): StoredDeviceIdentity {
  const { publicKey, privateKey } = crypto.generateKeyPairSync("ed25519");
  const publicKeyPem = publicKey.export({ type: "spki", format: "pem" });
  const privateKeyPem = privateKey.export({ type: "pkcs8", format: "pem" });
  return {
    deviceId: fingerprintPublicKey(publicKeyPem),  // SHA-256 指纹
    publicKeyPem,
    privateKeyPem,
    createdAtMs: now,
  };
}
```

```rust
    req: axum::extract::Request,
    next: Next,
```

### 3.2 opencode 范本：share-next.ts EventV2 + steal

**核心文件**：`packages/opencode/src/share/share-next.ts:1-371`

**架构**：
```
Session Event → EventV2 Bridge → ShareNext.sync() → 1s 批 flush → POST /api/shares/{id}/sync

                                                    双 base URL 鉴权切换
```

**1 秒批 flush 机制**（`share-next.ts:124-146`）：

```typescript
function sync(sessionID: SessionID, data: Data[]) {
  return Effect.gen(function* () {
    if (disabled) return
    const share = yield* getCached(sessionID)
    if (!share) return
    const s = yield* InstanceState.get(state)
    const existing = s.queue.get(sessionID)
    if (existing) {
      for (const item of data) { existing.set(key(item), item) }
      return
    }
    const next = new Map(data.map((item) => [key(item), item]))
    s.queue.set(sessionID, next)
    yield* flush(sessionID).pipe(Effect.delay(1000), Effect.forkIn(s.scope))
  })
}
```

**范式要点**：
- **Map-based 去重**：同 key 后写覆盖前写（session/message/part/session_diff/model 五类）
- **1 秒延迟批处理**：`Effect.delay(1000)` 合并高频事件
- **forkIn 隔离**：每个 share 独立 Scope，失败不影响其他

**steal 会话抢占**（`handlers/sync.ts:61-70`）：

```typescript
const steal = Effect.fn("SyncHttpApi.steal")(function* (ctx: { payload: typeof SessionPayload.Type }) {

  if (!workspaceID) return yield* new HttpApiError.BadRequest({})
  yield* session.setWorkspace({ sessionID: ctx.payload.sessionID, workspaceID })
```

**RemoteStream 自动重连**（`remote-stream.ts:38-149`）：

```typescript
export class RemoteStream<Item> implements AsyncIterable<RemoteStreamItem<Item>> {
  private revision = 0
  private async * read(): AsyncGenerator<RemoteStreamItem<Item>> {
    let attempt = 0
    let generation = 0
    while (!isAborted(this.lifetime.signal)) {
      const generationAbort = new AbortController()
      const signal = AbortSignal.any([this.lifetime.signal, generationAbort.signal])
      const generationId = ++generation
      let accepted = false
      try {
        for await (const value of this.options.open(signal)) {
          yield {
            generation: generationId, value, signal,
            accept: () => { accepted = true; attempt = 0 },
          }
        }
        throw this.options.ended(accepted)
      } catch (error) {
        if (!(error instanceof RemoteStreamCarrierError)) throw error
        attempt++
        await waitForRemoteStreamRetry(this.connection, error, attempt, signal)
      }
    }
  }
}
```

**范式要点**：
- **物理 generation 单调递增**：每次重开 +1
- **accept() 确认机制**：消费者验证 opening baseline 后才确认
- **revision 重启**：`restart()` 立即中断当前 generation
- **carrier 错误分类**：`RemoteStreamCarrierError` 可重试 vs 业务错误不可重连

### 5.2 openclaw 范本：Secret Sentinel AES-256-GCM

**核心文件**：`src/secrets/sentinel.ts:1-125`

```typescript
export const SECRET_SENTINEL_PREFIX = "oc-sent-v2.";
export const SECRET_SENTINEL_SUFFIX = ".end";
const SECRET_SENTINEL_CIPHER = "aes-256-gcm";
const SECRET_SENTINEL_NONCE_BYTES = 12;
const SECRET_SENTINEL_SCOPE_BYTES = 8;
const SECRET_SENTINEL_TAG_BYTES = 16;

export function sealSecretSentinel(value: string, meta: { label: string }): string {
  const scope = secretSentinelScope(meta.label);
  const nonce = createHmac("sha256", secretSentinelNonceKey)
    .update(scope).update(value).digest()
    .subarray(0, SECRET_SENTINEL_NONCE_BYTES);
  const cipher = createCipheriv(SECRET_SENTINEL_CIPHER, secretSentinelCipherKey, nonce);
  cipher.setAAD(scope);
  const ciphertext = Buffer.concat([cipher.update(value, "utf8"), cipher.final()]);
  const sealed = Buffer.concat([scope, nonce, cipher.getAuthTag(), ciphertext]);
  return `${SECRET_SENTINEL_PREFIX}${sealed.toString("base64url")}${SECRET_SENTINEL_SUFFIX}`;
}
```

**范式要点**：
- **进程全局密钥**：`Symbol.for("openclaw.secretSentinel.keys")` 64 字节随机（前 32 加密，后 32 nonce HMAC）
- **HMAC 确定性 nonce**：`HMAC-SHA256(scope, value)` 截断 12 字节，同明文+同 label 产生同 nonce（稳定脱敏）
- **AAD scope**：`SHA256(label)` 前 8 字节，防跨 label 密文移植
- **64 KiB 上限**：`SECRET_SENTINEL_MAX_LENGTH` 限制扫描内存
- **自动脱敏注册**：`registerSecretValueForRedaction` 防日志泄露

## 13. 结语

7 工程调研后，我们看到 laew 在跨设备同步与会话漫游上是**空白但有清晰路径**：

- **L1881-L1890**（设备配对）是 P0：Ed25519 设备身份 + 配对审批是多设备安全接入的基础。
- **L1891-L1900**（会话漫游）是 P0：steal 机制 + 崩溃恢复指针是用户体验的核心。
- **L1901-L1910**（同步协议）是 P0：generation + accept() 是实时同步的基础设施。
- **L1911-L1920**（加密隐私）是 P0：AES-256-GCM 内存加密是安全底线。
- **L1921-L1930**（状态合并）是 P0：lifecycleRevision CAS 是多端一致性的保障。

**重要洞察**：
1. **openclaw 是最完整的实现**（2894 行核心代码），其 Ed25519 + 6 种审批 + Tailscale + Secret Sentinel 是 laew 的完整参考路径。
2. **opencode 的 share-next.ts 是最精简的会话共享实现**（371 行），其 1 秒批 flush + steal 机制适合 laew 快速落地。
3. **deepseek-harness 的 Typert Remote 协议是最严谨的同步协议**，其 generation + accept() 机制适合高可靠场景。
4. **atomcode 的 LiveViewHub 是最轻量的同设备多视图同步**，其 broadcast::channel + generation 防 stale 适合 TUI/WebUI 共享。

**一句话总结**：「**Ed25519 设备身份 + 1 秒批 flush + generation 单调递增 + AES-256-GCM 内存加密 + lifecycleRevision CAS**」是 laew 从单设备升级到跨设备协同的最小落地路径。
