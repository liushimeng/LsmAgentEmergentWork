### 1.2 跨项目三大共性模式

1. **匹配策略瀑布是 2026 主流**：opencode 8 级 → atomcode 3 级 → claudecode 2 级 → pi 1 级 + fuzzy opt。直接严格匹配已不足以应对 LLM 把 CRLF 当 LF、把 tab 当 4 space、把 curly quote 当 straight quote 的常见错位。
2. **错误文案 = LLM 自愈接口**：每个项目都把"修复方法"用 `behavior: 'ask'` / `cause: '...; re-read the file, then retry'` / `no-match + "请先 Read"` 形式注入返回体。claudecode、opencode、deepseek-harness、atomcode 都有结构化 errorCode。
3. **路径级互斥 vs 整文件版本化互斥**：pi/atomcode 走"同文件串行"（promise 链 / tokio Mutex），opencode 走"gitdir 信号量 + git 快照"（天然原子 + 跨进程），claudecode 走"per-message 备份 + readFileState mtime 校验"（事后回滚），deepseek-harness 走"FsBackend 观察者 + 脏读检测"。

### 1.3 laew 现状（要点）

`src/agent/tools/edit.rs:66-167` 实现的是**claudecode 1.0 极简版**：
- ✅ 沙箱拦截（`check_write_path`）`src/agent/tools/edit.rs:101` `src/agent/sandbox_hook/mod.rs:41`
- ✅ unique 校验 + replace_all（`count==0/count>1`）`edit.rs:135-149`
- ✅ 同内容拒绝 `edit.rs:93-98`
- ❌ 无 EOL/quote/fuzzy 容错，模型给 CRLF 文件贴 LF 必失败
- ❌ 无 mtime/stale 校验，Read 后文件被外部改仍可改
- ❌ 无 fsync/rename，崩溃可能半文件
- ❌ 无并发互斥，多个并行 SubAgent 编辑同文件会全成功或全失败（race）
- ❌ 无 undo / 快照
- ❌ 无 diff 回灌，返回仅 `"[Edit] 已替换 N 处匹配;文件 /path"`（`edit.rs:163-166`）

```ts
// claudecode/src/tools/FileEditTool/utils.ts:73-95
export function findActualString(
  fileContent: string,
  searchString: string,
): string | null {
  // First try exact match
  if (fileContent.includes(searchString)) {
    return searchString
  }
  // Try with normalized quotes
  const normalizedSearch = normalizeQuotes(searchString)
  const normalizedFile = normalizeQuotes(fileContent)
  const searchIndex = normalizedFile.indexOf(normalizedSearch)
  if (searchIndex !== -1) {
    return fileContent.substring(searchIndex, searchIndex + searchString.length)
  }
  return null
}
```

#### 2.1.5 原子写（tmp+rename + fsync）

```ts
// claudecode/src/utils/file.ts:385-440
const tempPath = `${targetPath}.tmp.${process.pid}.${Date.now()}`
// ...

chmodSync(tempPath, targetMode)  // 保留原文件权限

```

**关键细节**：
- 临时文件后缀含 `pid + Date.now()`，**多进程同时写**也不冲突
- `flush: true` 触发 Bun 的 `fsync`
- 权限保留：先 `statSync` 拿 mode，临时文件写完 `chmodSync` 同 mode，再 rename（`file.ts:388-436`）
- 符号链接：`fs.readlinkSync` 检出后**穿透写 target** 但保留 symlink 本身（`file.ts:367-380`）
- 失败 fallback：rename 失败时降级到 `fsWriteFileSync(targetPath, content)` 走非原子路径（`file.ts:439-475`），并打 `tengu_atomic_write_error` 事件

#### 2.2.2 匹配策略瀑布（**8 个 Replacer**）

```ts
// opencode/packages/opencode/src/tool/edit.ts:682-728
export function replace(content: string, oldString: string, newString: string, replaceAll = false): string {
  if (oldString === newString) {
    throw new Error("No changes to apply: oldString and newString are identical.")
  }
  if (oldString === "") {
    throw new Error(
      "oldString cannot be empty when editing an existing file. Provide the exact text to replace, or use write for an intentional full-file replacement."
    )
  }
  const replacers: Replacer[] = [
    SimpleReplacer,              // 244
    LineTrimmedReplacer,         // 248  按行 trim 后的 includes
    BlockAnchorReplacer,         // 288  找首行 + 末行锚点（仅两端严格匹配）
    WhitespaceNormalizedReplacer,// 427  把所有空白 run 折叠成单空格
    IndentationFlexibleReplacer, // 471  独立匹配每行缩进
    EscapeNormalizedReplacer,    // 499  unescape 字符串字面量
    TrimmedBoundaryReplacer,     // 562  头尾空白 + 中间空白折叠
    ContextAwareReplacer,        // 588  按行相似度
  ]
  for (const search of replacers[replacerIndex](content, oldString)) {
    if (isDisproportionateMatch(search, oldString)) {
      throw new Error("Refusing replacement because the matched span is much larger than oldString...")
    }
    if (replaceAll) return content.replaceAll(search, newString)
    return content.substring(0, index) + newString + content.substring(index + search.length)
  }
  throw new Error("Could not find oldString in the file. It must match exactly, including whitespace, indentation, and line endings.")
  throw new Error("Found multiple matches for oldString. Provide more surrounding context to make the match unique.")
}
```

8 个 Replacer 的核心差异（按精确度从高到低）：

| # | 名称 | 行号 | 行为 |
|---|------|------|------|
| 1 | SimpleReplacer | 244 | 原样 `indexOf` |
| 2 | LineTrimmedReplacer | 248 | 按 `line.trimEnd()` 后 `includes` |
| 3 | BlockAnchorReplacer | 288 | 找首行锚点 + 末行锚点，**中间行用 fuzzy Levenshtein** |
| 4 | WhitespaceNormalizedReplacer | 427 | 多个连续空白折叠为单空格 |
| 5 | IndentationFlexibleReplacer | 471 | 把每行前导空白去掉，单独匹配 |
| 6 | EscapeNormalizedReplacer | 499 | `\\n` → `\n`、`\\t` → `\t` |
| 7 | TrimmedBoundaryReplacer | 562 | 头尾 + 中间空白容错 |
| 8 | ContextAwareReplacer | 588 | 每行独立算相似度（diff lib） |

外加 `MultiOccurrenceReplacer`（548）做 `replaceAll=true` 时的特殊处理；`isDisproportionateMatch`（732）防止「你说 5 字符我匹配 500 字符」的失控：

```ts
// opencode/packages/opencode/src/tool/edit.ts:731-737
function isDisproportionateMatch(search: string, oldString: string) {
  const oldLines = oldString.split("\n").length
  return search.trim().length > Math.max(oldString.trim().length + 500, oldString.trim().length * 4)
}
```

**8 级瀑布是 7 个项目中最激进的设计**，代价是 LLM 的"用更长 oldString 保证唯一"惯例被打折——必须先读文件再 Edit。

```ts
const writeWithDirs = Effect.fn("FileSystem.writeWithDirs")(function* (
  path: string, content: string | Uint8Array, mode?: number,
) {
  const write = typeof content === "string"
    ? fs.writeFileString(path, content)
    : fs.writeFile(path, content)
  yield* write.pipe(
    Effect.catchIf(
      (e) => e.reason._tag === "NotFound",
      () => Effect.gen(function* () {
        yield* fs.makeDirectory(dirname(path), { recursive: true })
        yield* write
      }),
    ),
  )
  if (mode) yield* fs.chmod(path, mode)
})
```

#### 2.2.5 Snapshot 模块（**git plumbing** + 整实例互斥）

```ts
// opencode/packages/opencode/src/snapshot/index.ts:53-83
const locks = new Map<string, Semaphore.Semaphore>()
const lock = (key: string) => {
  const hit = locks.get(key)
  if (hit) return hit
  const next = Semaphore.makeUnsafe(1)  // 互斥信号量
  locks.set(key, next)
  return next
}

const state = yield* InstanceState.make<State>(
  Effect.fn("Snapshot.state")(function* (ctx) {
    const state = {
      directory: ctx.directory,
      worktree: ctx.worktree,
      gitdir: path.join(Global.Path.data, "snapshot", ctx.project.id, Hash.fast(ctx.worktree)),
      vcs: ctx.project.vcs,
    }
    const args = (cmd: string[]) => ["--git-dir", state.gitdir, "--work-tree", state.worktree, ...cmd]
```

核心设计：
- 每个 worktree 一个**独立 gitdir**：`~/.local/share/opencode/snapshot/{projectId}/{worktreeHash}/.git`
- 真正的 worktree 内容**用 git 管理**，add/rm 走 `git --git-dir X --work-tree Y`
- `Semaphore(1)` 保证同一 worktree 的 track/patch/restore 串行
- `locked = <A,E,R>(fx) => lock(state.gitdir).withPermits(1)(fx)`（187）所有 IO 都进信号量

工作流：
1. 每条 user message → `Snapshot.track()` 把 worktree 文件 add 到 snapshot gitdir
2. Edit 完成 → `Snapshot.patch(hash)` 返回 `FileDiff[]`（每个文件的 unified diff）
3. 撤销 → `Snapshot.revert(patches)` 把所有 patch 倒序回放
4. 全恢复 → `Snapshot.restore(snapshot)` checkout 完整 snapshot

**这是 7 个项目里唯一把"编辑原子性"交给独立 git repo 实现的**——副本写（snapshot）和原写（edit）解耦。

#### 2.3.3 Per-File Promise 队列（最纯粹的互斥实现）

```ts
// pi/packages/coding-agent/src/core/tools/file-mutation-queue.ts:5-25
const fileMutationQueues = new Map<string, Promise<void>>()
let registrationQueue = Promise.resolve()

async function getMutationQueueKey(filePath: string): Promise<string> {
  const resolvedPath = resolve(filePath)
  try { return await realpath(resolvedPath) }  // 关键：用 realpath 归一化
  catch (error) { if (isMissingPathError(error)) return resolvedPath; throw error }
}

export async function withFileMutationQueue<T>(filePath: string, fn: () => Promise<T>): Promise<T> {
  const registration = registrationQueue.then(async () => {
    const key = await getMutationQueueKey(filePath)
    const currentQueue = fileMutationQueues.get(key) ?? Promise.resolve()
    let releaseNext!: () => void
    const nextQueue = new Promise<void>((resolveQueue) => { releaseNext = resolveQueue })
    const chainedQueue = currentQueue.then(() => nextQueue)
    fileMutationQueues.set(key, chainedQueue)
    return { key, currentQueue, chainedQueue, releaseNext }
  })
  registrationQueue = registration.then(() => undefined, () => undefined)
  const { key, currentQueue, chainedQueue, releaseNext } = await registration
  await currentQueue
  try { return await fn() }
  finally {
    releaseNext()
    if (fileMutationQueues.get(key) === chainedQueue) fileMutationQueues.delete(key)
  }
}
```

**设计精华**：
- **Map<key, Promise>** 而不是 Mutex：纯 promise 链，无内核同步原语
- **realpath 归一**：软链、相对路径、`./` 全部归一为 realpath，跨进程不能 hack（realpath 是 syscall）
- **registration queue**：防止两个并发 call 同时 race Map 操作
- **跨文件并行**：不同 key 的 `fn()` 不会互相 block（只 await 自己的 currentQueue）
- **自动清理**：释放时若还是 last chain 才删 Map 项，避免删除未来 chain

这是 7 个项目里**最简洁、最分布式友好**的互斥实现。Write 也用同一个 queue（`write.ts:6-7` import）。

#### 2.4.3 Per-Path Mutex（canonical key + Weak 清理）

```rust
// atomcode/crates/atomcode-capabilities/src/tools/edit.rs:15-36
type PathLock = AsyncMutex<()>;

fn edit_path_locks() -> &'static Mutex<HashMap<PathBuf, Weak<PathLock>>> {
    static LOCKS: OnceLock<Mutex<HashMap<PathBuf, Weak<PathLock>>>> = OnceLock::new();
    LOCKS.get_or_init(|| Mutex::new(HashMap::new()))
}

fn edit_path_lock(path: &Path) -> Arc<PathLock> {
    let key = std::fs::canonicalize(path).unwrap_or_else(|_| path.to_path_buf());
    let mut locks = edit_path_locks().lock().unwrap_or_else(|p| p.into_inner());
    locks.retain(|_, lock| lock.strong_count() > 0);  // GC
    if let Some(lock) = locks.get(&key).and_then(Weak::upgrade) { return lock; }
    let lock = Arc::new(AsyncMutex::new(()));
    locks.insert(key, Arc::downgrade(&lock));
    lock
}
```

```rust
// atomcode/crates/atomcode-capabilities/src/tools/edit.rs:91-93
// Serialize AtomCode edits to the same canonical file. The byte-for-byte
// pre-commit check also catches external changes that happen before the check.
let path_lock = edit_path_lock(&path);
let _path_guard = path_lock.lock().await;
```

设计：
- `OnceLock<Mutex<HashMap<PathBuf, Weak<PathLock>>>>`：全局单例 HashMap
- `Weak` + `strong_count > 0` 清理：Arc 没人引用时 GC 掉锁本身
- `canonicalize`：realpath-like 归一（同 pi 思路，但用 std 而非 fs.realpath）
- **byte-for-byte 校验**：lock 拿住后**再读一次文件**，与 mtime/hash 比对，捕获 lock 期间外部修改

**比 pi 更强**：lock 不是 promise 链（无 retry 语义的让步），是真正阻塞；且写入前还做 pre-commit check（注释行 92 明确指出）。

## ④ 8 个设计模式 + 4 个反模式

### 4.1 模式

#### 模式 1：匹配策略瀑布 + 比例失配护栏

**来源**: opencode `edit.ts:682-737` 8 级瀑布 + `isDisproportionateMatch` 护栏
**要点**: 严格匹配失败后逐级放宽，但有「匹配 span / oldString > 4×」硬上限，防止"换一行匹配整文件"
**laew 借鉴**: P0 引入 `similar` crate，3 级瀑布 + 4× 比例护栏

#### 模式 2：Per-Path Promise 队列（Map<key, Promise>）

**来源**: pi `file-mutation-queue.ts:5-58`
**要点**: 纯 promise 链做互斥，无内核同步原语；realpath 归一；registration queue 防 Map race；自动 GC
**laew 借鉴**: P1 用 `tokio::sync::Mutex<HashMap<PathBuf, Arc<Mutex<()>>>>` + `Weak` 清理，匹配 atomcode 但更分布式

#### 模式 3：tmp.pid.ts + fsync + rename + chmod 保留

**来源**: claudecode `file.ts:385-440`
**要点**: 临时文件后缀含 pid+时间戳；写入时 flush；保留原 mode（chmod 临时文件）；失败降级非原子路径并打事件
**laew 借鉴**: P0 用 `tempfile::NamedTempFile::new_in(parent_dir) + persist_noclobber + fsync` 实现

#### 模式 4：per-message 增量快照（FileHistory）

**来源**: claudecode `fileHistory.ts:230-300`
**要点**: 按 message 节奏；只追踪被改文件；dedup（同字节复用旧版本）；delete 语义（`backupFileName: null`）
**laew 借鉴**: P2 在 `session_memory` 表加 `file_snapshots` 字段，每条 user message 关联被改文件 + 全文 backup

#### 模式 5：独立 gitdir 做 Snapshot（worktree 副本）

**来源**: opencode `snapshot/index.ts:53-300`
**要点**: 副本写和原写解耦；git plumbing 天然原子；Semaphore(1) 互斥；revert 倒序回放
**laew 借鉴**: P2（成本高，需额外 Git 子进程）

#### 模式 6：Stale-Read byte-equal 校验

**来源**: claudecode `FileEditTool.ts:455-470`
**要点**: Edit 前与最近 Read 缓存 byte-equal 比对，O(n) 但避免 mtime 漂移
**laew 借鉴**: P0（实现成本低，效果立竿见影）

#### 模式 7：错误文案 = 自愈接口（cause/remedy）

**来源**: deepseek-harness `error.ts:13-29`、claudecode `FileEditTool.ts:331-345`
**要点**: 每条错误都带「下一步动作」：`— re-read the file, then retry`、`Did you mean ...?`、建议加上下文
**laew 借鉴**: P0 重写 `edit.rs:135-149` 错误文案，对齐 claudecode

#### 模式 8：LSP didChange + didSave 同步通知

**来源**: claudecode `FileEditTool.ts:495-520`
**要点**: Edit 写盘后**主动推** LSP 服务（`lsp.changeFile` + `lsp.saveFile`），TS 编译器立即重新拉 diagnostics；VSCode 同步打开 diff 视图
**laew 借鉴**: P2（需要集成 LSP 客户端）

### 4.2 反模式

#### 反模式 1：openclaw 把"文件改"完全外包给 bash

> 没有任何原子性 / 唯一性 / undo 保障；LLM 用 `sed -i` 时一个 `\\` 转义错就毁文件

#### 反模式 2：claudecode 早期"没有 fuzzy"

> 8 级瀑布的瀑布是 opencode 答案；claudecode 只做 2 级，CLRF 文件 + tab 误植就 fail

#### 反模式 3：Write 无大文件缩警示

> laew `write.rs:87-90` 和 deepseek-harness `write.ts` 都是 `fs.writeFile` 盲写——LLM 误传短 content 覆盖大文件，**只能恢复**（如果有快照）

> atomcode 给出范本（`write.rs:88-105`）：`was 100 lines, now 5 lines, ⚠ WARNING: file shrank by 95%`

#### 反模式 4：把"快照"和"互斥"二选一

> opencode 用 Snapshot（独立 gitdir）但**不**显式路径锁——意味着两个并发 Edit 可能都 track 到同一个 pre-state，revert 时第二个抢先生效
> pi/atomcode 用 promise/Mutex 但**只**在文件层，互斥外面崩溃一致性靠 session 兜底

> **正确做法**: 快照 + 锁 + pre-commit byte-check 三件套（claudecode）

```rust
async fn write_atomic(path: &Path, content: &str) -> Result<()> {
  let parent = path.parent().unwrap_or(Path::new("."));
  let mut tmp = NamedTempFile::new_in(parent).map_err(|e| ...)?;
  tmp.write_all(content.as_bytes()).map_err(|e| ...)?;
  tmp.as_file().sync_all().map_err(|e| ...)?;  // fsync
  tmp.persist(path).map_err(|e| ...)?;          // rename
  Ok(())
}
```

```rust
fn match_edit(content: &str, old: &str, replace_all: bool) -> Result<(String, usize, MatchStrategy)> {
  // 1. exact
  let exact_count = content.matches(old).count();
  if exact_count > 0 {
    return Ok((if replace_all { content.replace(old, new) } else { content.replacen(old, new, 1) }, exact_count, MatchStrategy::Exact));
  }
  // 2. EOL coerce（仅当文件含 CRLF 时启用）
  if content.contains("\r\n") {
    let old_crlf = old.replace("\r\n", "\n").replace("\n", "\r\n");  // 双向 coerce
    let new_crlf = new.replace("\r\n", "\n").replace("\n", "\r\n");
    let count = content.matches(&old_crlf).count();
    if count > 0 {
      return Ok((content.replacen(&old_crlf, &new_crlf, 1), count, MatchStrategy::EolCoerced));
    }
  }
  // 3. fuzzy（用 similar 库的缩进归一）
  if let Some((replaced, count)) = try_fuzzy_replace(content, old, new, replace_all) {
    return Ok((replaced, count, MatchStrategy::Fuzzy));
  }
  Err(EditError::NotFound)
}
```

- EOL coerce：和 atomcode 思路一致，但用「先归一再回填」避免 atomcode 的"中间步骤字符串"问题
- Fuzzy：`similar` crate 的 `capture_diff_slices` 算行级相似度，> 0.8 视为命中

```rust
use std::sync::Arc;
use tokio::sync::RwLock;

#[derive(Default)]
pub struct ReadStateCache {
  inner: Arc<RwLock<HashMap<PathBuf, String>>>,  // 路径 → Read 时的全文
}

impl ReadStateCache {
  pub async fn check_unchanged(&self, path: &Path) -> Result<()> {
    let cached = self.inner.read().await.get(path).cloned();
    if let Some(old) = cached {
      let current = fs::read_to_string(path)?;
      if current != old {
        return Err(AgentError::ToolExecution {
          tool: "Edit".into(),
          reason: format!("文件自上次 Read 后已变更(共 {} 字节 vs {} 字节),请重新 Read 后再编辑",
                          old.len(), current.len()),
        });
      }
    }
    Ok(())
  }
  pub async fn mark(&self, path: &Path, content: String) { self.inner.write().await.insert(path.to_path_buf(), content); }
}
```

- 集成点：`ReadTool::execute` 调 `read_state.mark(path, content)`；`EditTool::execute` 调 `read_state.check_unchanged(path)?`

```rust
// src/agent/tools/edit.rs: 加模块
use std::sync::{Arc, Weak, Mutex as StdMutex};
use std::path::PathBuf;
use std::collections::HashMap;

type PathLock = Arc<tokio::sync::Mutex<()>>;

static LOCKS: once_cell::sync::Lazy<StdMutex<HashMap<PathBuf, Weak<tokio::sync::Mutex<()>>>>> =
  once_cell::sync::Lazy::new(|| StdMutex::new(HashMap::new()));

async fn edit_path_lock(path: &Path) -> PathLock {
  let key = std::fs::canonicalize(path).unwrap_or_else(|_| path.to_path_buf());
  let mut map = LOCKS.lock().unwrap();
  map.retain(|_, l| l.strong_count() > 0);
  if let Some(w) = map.get(&key) { if let Some(arc) = w.upgrade() { return arc; } }
  let arc = Arc::new(tokio::sync::Mutex::new(()));
  map.insert(key, Arc::downgrade(&arc));
  arc
}
```

- 与 atomcode 等价，但用 `once_cell::Lazy` 替代 `OnceLock`（更稳）
- 集成：`EditTool::execute` 开头 `let _g = edit_path_lock(&path).lock().await;`

## ⑦ 附：完整错误文案对照表（5 项目 × 5 场景，逐字摘录）

> 5 项目：claudecode / opencode / pi / atomcode / deepseek-harness
> openclaw（bash） / hermes-agent（Python 异常）不参与此表

| 场景 | claudecode | opencode | pi | atomcode | deepseek-harness | laew 现状 |
|------|-----------|----------|---|----------|------------------|----------|
| **old 未找到** | `String to replace not found in file.\nString: ${old}` | `Could not find oldString in the file. It must match exactly, including whitespace, indentation, and line endings.` | (内置生成) `Edit could not find oldText: ...` | `edit_file: old_string not found in <path>` (走 fuzzy 失败后) | `FS_NOT_OBSERVED — read the file, then retry` | `未找到匹配的 old_string;可能文件内容已变更,请先 Read 该文件确认内容。` |
| **匹配多处** | `Found ${matches} matches of the string to replace, but replace_all is false. To replace all occurrences, set replace_all to true. To replace only one occurrence, please provide more context to uniquely identify the instance.` | `Found multiple matches for oldString. Provide more surrounding context to make the match unique.` | (内置生成) `Edit oldText matched multiple places: ...` | (内置生成) `edit_file: found ${count} matches; either add more context or set replace_all=true` | `found ${count} matches` | `old_string 在文件中匹配了 {count} 次;请扩大上下文使其唯一,或设置 replace_all=true。` |
| **old==new** | `No changes to apply: old_string and new_string are identical` | `No changes to apply: oldString and newString are identical.` | (允许 0 长度 replace) | `edit_file: old_string and new_string are identical — nothing to change.` | `old_string and new_string must differ` | `new_string 必须与 old_string 不同` |
| **old==""** | 允许（=新建文件） | `oldString cannot be empty when editing an existing file. Provide the exact text to replace, or use write for an intentional full-file replacement.` | 拒 | `edit_file: old_string is empty — provide the exact text fragment to replace.` | `old_string must be a non-empty string` | (允许) |
| **文件被外部改** | `FILE_UNEXPECTEDLY_MODIFIED_ERROR` (FileEditTool.ts:460) | (无对应检查) | (无对应检查) | pre-commit check byte-equal | `FS_STALE_VERSION — re-read the file, then retry` | (无) |

> **laew 的 `old==""` 当前允许是潜在 bug**：模型可能误传空字符串"删除"实际想"清空"，claudecode 把它解读为"建新文件"，opencode/atomcode/deepseek 都拒——**P0 应拒绝**。
