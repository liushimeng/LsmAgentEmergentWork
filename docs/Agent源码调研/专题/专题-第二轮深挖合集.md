## 3. 三大共性模式汇总

### 模式 A：分层契约 + Capability Cross Type（OpenClaw、opencode、pi）

```
┌─────────────────────────────────────┐
│  渠道(WhatsApp / CLI / Web)         │  ← 用户面
└─────────────────┬───────────────────┘
                  │ JSON-RPC over WS / HTTP
┌─────────────────▼───────────────────┐
│  Gateway 层（SSOT 协议版本）         │  ← 服务端协议治理
└─────────────────┬───────────────────┘
                  │ Capability Cross Type
┌─────────────────▼───────────────────┐
│  Harness 层（可插拔执行器契约）       │  ← Agent Runtime
└─────────────────┬───────────────────┘
                  │ StreamFn（永不抛异常）
┌─────────────────▼───────────────────┐
│  Adapter 层（Provider 协议转换）     │  ← LLM Provider
└─────────────────────────────────────┘
```

**对 laew 价值**:TUI / daemon / 单轮 `-p` 各自维护独立控制面，缺中立序列化协议；引入三层契约后 wire 统一。

### 模式 B：插件/服务容器 + Hot Swap（atomcode、Cordis、opencode）

```
Plugin/Service 三大原语:
- register(全集) → mount(子集) → MountedTools{current: Arc<RwLock<Snapshot>>}
- hook chain 扇出（first Some wins / 第一个 Err 短路）
- 服务就绪 → 自动激活；dispose → 自动反向清理
```

**对 laew 价值**:把 Yolo / SessionContext / Verify / Todo / Datadog 各自实现 `LifecycleHooks`，用 `HookChain` 组合。

### 模式 C：分层压缩 + 防截断 Fence（claudecode、hermes-agent、opencode、openclaw）

```
Level 1: Tool Result Budget（per-message 字符上限）
Level 2: Microcompact（单工具结果摘要）
Level 3: Cached MC（cache_edits API 远程删缓存）
Level 4: Auto-Compact（LLM 全文摘要）
Plus: Watermark Fence + Generation Counter 防晚 commit 覆盖
Plus: Quarantine 隔离 + retry-after 退避
```

**对 laew 价值**:零压缩 → 引入时间触发型微压缩(P0) → 后续升级到完整管线(P1)。
