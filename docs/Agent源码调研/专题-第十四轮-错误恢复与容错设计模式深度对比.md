### 2.1 atomcode — 分层错误分类 + 可重试性标记

atomcode 在 `provider/retry.rs` 中实现了一套精细的错误分类体系：

**文件：`crates/atomcode-capabilities/src/provider/retry.rs`**

```rust
/// 可重试的 HTTP 状态码
pub(crate) fn is_retryable_status(code: u16) -> bool {
    matches!(code, 408 | 425 | 429 | 500 | 502 | 503 | 504 | 529)
}

/// 可重试的 reqwest 错误判定（含 source chain 遍历）
pub(crate) fn is_retryable_reqwest_error(error: &reqwest::Error) -> bool {
    if error.is_timeout() || error.is_connect() { return true; }
    // 遍历 source chain 寻找 transient io::Error
    let mut source = error.source();
    while let Some(e) = source {
        if let Some(io_err) = e.downcast_ref::<std::io::Error>() {
            match io_err.kind() {
                std::io::ErrorKind::ConnectionReset |
                std::io::ErrorKind::ConnectionRefused |
                std::io::ErrorKind::TimedOut |
                std::io::ErrorKind::UnexpectedEof => return true,
                _ => {}
            }
        }
        source = e.source();
    }
    false
}
```

**关键设计点：**
- **source chain 遍历**：不只检查表层错误，而是遍历整个 `source()` 链寻找 `io::Error`
- **stale connection 检测**：统一处理 hyper `IncompleteMessage` 和 `ConnectionReset` 两种形式
- **429 所有权分离**：通过 `RateLimitRetryOwner` 枚举区分 provider 自有重试和 kernel 生命周期重试

### 2.3 undici — 符号化错误层级体系

**文件：`lib/core/errors.js`**

undici 使用 Symbol 实现了严格的错误类型层级：

```javascript
// 基础错误
class UndiciError extends Error {
  constructor(message, options) {
    super(message, options)
    this.name = 'UndiciError'
    this.code = 'UND_ERR'
  }
  static [Symbol.hasInstance](instance) {
    return instance && instance[kUndiciError] === true
  }
}

// 超时类错误
class ConnectTimeoutError extends UndiciError { this.code = 'UND_ERR_CONNECT_TIMEOUT' }
class HeadersTimeoutError extends UndiciError { this.code = 'UND_ERR_HEADERS_TIMEOUT' }
class BodyTimeoutError extends UndiciError { this.code = 'UND_ERR_BODY_TIMEOUT' }

// 内容类错误
class RequestContentLengthMismatchError extends UndiciError { this.code = 'UND_ERR_REQ_CONTENT_LENGTH_MISMATCH' }
class ResponseContentLengthMismatchError extends UndiciError { this.code = 'UND_ERR_RES_CONTENT_LENGTH_MISMATCH' }

// 协议类错误
class RequestRetryError extends UndiciError { /* 重试专用 */ }
class RequestAbortedError extends AbortError { /* 请求中止 */ }
```

**关键设计点：**
- **Symbol.hasInstance**：每个错误类有独立的 `Symbol` 标识，`instanceof` 跨 realm 安全
- **错误码常量**：所有错误码以 `UND_ERR_` 前缀统一命名
- **继承层级**：`UndiciError → AbortError → RequestAbortedError` 三级继承

```typescript
function shouldRetry(error: APIError): boolean {
  // 1. Mock 错误永不重试
  if (isMockRateLimitError(error)) return false;
  // 2. 持久化模式：429/529 始终可重试
  if (isPersistentRetryEnabled() && isTransientCapacityError(error)) return true;
  // 3. CCR 模式：401/403 可重试（基础设施 JWT 瞬时失效）
  if (isEnvTruthy(process.env.CLAUDE_CODE_REMOTE) && (error.status === 401 || error.status === 403)) return true;
  // 4. overloaded_error 消息检查
  if (error.message?.includes('"type":"overloaded_error"')) return true;
  // 5. max_tokens context overflow 可重试
  if (parseMaxTokensContextOverflowError(error)) return true;
  // 6. x-should-retry 头尊重
  const shouldRetryHeader = error.headers?.get('x-should-retry');
  if (shouldRetryHeader === 'true' && (!isClaudeAISubscriber() || isEnterpriseSubscriber())) return true;
  if (shouldRetryHeader === 'false') { /* 仅 ant 用户 5xx 可忽略 */ }
  // 7. 连接错误可重试
  if (error instanceof APIConnectionError) return true;
  // 8. 状态码兜底
  if (error.status === 408 || error.status === 409) return true;
  if (error.status === 429) return !isClaudeAISubscriber() || isEnterpriseSubscriber();
  if (error.status === 401) { clearApiKeyHelperCache(); return true; }
  if (error.status && error.status >= 500) return true;
  return false;
}
```

**关键设计点：**
- **QuerySource 感知**：`FOREGROUND_529_RETRY_SOURCES` 集合区分前台/后台查询，后台查询不重试 529（避免网关放大）
- **订阅者类型感知**：ClaudeAI 订阅用户不重试 429（rate limit 是配额限制），企业 PAYG 用户可重试
- **持久化模式**：无人值守会话启用无限重试 + 心跳保活
- **认证缓存联动**：401 时清除 API key 缓存，403 token revoked 时触发 OAuth 刷新

  if (connectedAt !== undefined && Date.now() - connectedAt >= policy.maxDelayMs) {
    failedAttempts = 0;

  connectedAt = undefined;
  failedAttempts += 1;
  if (failedAttempts > policy.maxAttempts) {
    // 耗尽预算 → 注销工具，停止重连

      disposers = new Map();

### 4.2 Switchyard — Escalation 升级路由（智能熔断）

**文件：`crates/libsy/src/algorithms/escalation.rs`**

```rust
struct EscalationClassifier {
    judge: JudgeClassifier<EscalationJudge, EscalationPolicy>,
    capable: ModelId,
    efficient: ModelId,
    confirmations: u32,  // 连续升级确认次数阈值
}

#[async_trait]
impl Classifier<State> for EscalationClassifier {
    async fn score(&self, state: &mut State, request: &mut Request, driver: Option<&Driver>)
        -> Result<(Classification, Option<Response>)> {
        // 已锁定的会话直接走 capable，不再调用 judge
        if streak(state) >= self.confirmations {
            return Ok((decisive(&self.capable), None));
        }
        // 调用 efficient model，judge 评估其回答质量
        let efficient_response = match driver.call_model(request.clone(), vec![self.efficient.clone()]).await {
            Ok(r) => r,
            // Context window 超限 → 直接降级到 capable
            Err(LibsyError::ClientCall { source: LlmClientError::ContextWindowExceeded { .. }, .. }) => {
                return Ok((decisive(&self.capable), None));
            }
            Err(e) => return Err(e),
        };
        // 传输失败 → 降级到 capable
        let agg = match efficient_response.llm_response.into_agg().await {
            Ok(agg) => agg,
            Err(LlmClientError::Transport { .. }) => {
                return Ok((decisive(&self.capable), None));
            }
            Err(source) => return Err(LibsyError::client_call(self.efficient.clone(), source)),
        };
        // judge 评估 → 决定是否升级
        // ...
    }
}
```

**关键设计点：**
- **连续确认机制**：需要 `confirmations` 次连续升级判决才锁定到 capable（防止抖动）
- **错误类型感知降级**：ContextWindowExceeded 和 Transport 错误直接降级，其他错误保持类型化
- **Streak 状态跟踪**：`STREAK_KEY` 记录连续升级次数，实现「锁定」语义

## 7. 优雅降级与背压

### 7.1 undici — RetryController 背压代理

**文件：`lib/handler/retry-handler.js`**

```javascript
class RetryController {
  #onAbort
  constructor(onAbort) {
    this.#onAbort = onAbort;
    this.target = null;
  }
  pause() { this.target?.pause() }    // 背压传递到当前连接
  resume() { this.target?.resume() }  // 恢复传递到当前连接
  abort(reason) {
    this.target?.abort(reason);
    this.#onAbort(reason);  // 通知 handler 取消 backoff
  }
}
```

**设计原理注释（原文）：**
> A stable controller handed to the downstream handler for the lifetime of the request. Each transparent retry/resume is a *separate* dispatch with its *own* connection controller. Without a stable proxy the downstream body keeps flow-controlling the original (now-dead) controller while data flows on the new one.

pub fn decide_from_windows(windows: &[RateLimitWindow], hint: &RateLimitHint) -> RateLimitDecision {
  if hint.terminal { return RateLimitDecision::from_hint(hint); }
  // 仅当窗口被标记为 quota_exhausted 时才暂停
  let w = windows.iter()
    .filter(|w| w.window_size_seconds > 0 && w.window_size_seconds <= 18_000 && w.quota_exhausted)
    .min_by_key(|w| w.window_size_seconds);
  let Some(w) = w else { return RateLimitDecision::from_hint(hint); };  // 瞬态 429 → 使用 hint
  if w.seconds_until_reset <= RATE_LIMIT_AUTO_WAIT_SECS {
    RateLimitDecision::WaitAndRetry { secs: w.seconds_until_reset }
  } else {
    RateLimitDecision::Pause { reset_at_display: w.reset_at_display.clone(), secs_until_reset: Some(w.seconds_until_reset) }
  }
}

### 9.2 laew 核心差距总结

5. **无舱壁隔离**：单一连接池，无资源分区
6. **无背压机制**：无请求排队、无流量整形
7. **无安全遥测**：错误信息可能包含敏感数据
