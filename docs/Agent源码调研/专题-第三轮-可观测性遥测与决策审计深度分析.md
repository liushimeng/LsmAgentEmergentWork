### 2.1 atomcode(Rust)—— 独立遥测 crate 的教科书

atomcode 的可观测性集中在独立 crate `atomcode-telemetry`(8 模块),与业务 crate 物理隔离,是 Rust Agent 可观测性的最佳参考。

#### 2.1.1 遥测配置与 5 级 opt-out

`crates/atomcode-telemetry/src/config.rs:44-81` 定义了业界最完整的遥测开关优先级:

```rust
/// Resolve the 5-level telemetry opt-out: offline → env×2 → cli → config.
pub fn resolve(cfg, cli, atomcode_dir, env, offline) -> ResolvedConfig {
    let state = if offline {
        TelemetryState::Disabled("offline")
    } else if env.var("ATOMCODE_TELEMETRY").as_deref() == Some("0") {
        TelemetryState::Disabled("env:ATOMCODE_TELEMETRY=0")
    } else if env.var("DO_NOT_TRACK").as_deref() == Some("1") {
        TelemetryState::Disabled("env:DO_NOT_TRACK=1")
    } else if cli.disabled {
        TelemetryState::Disabled("cli:--no-telemetry")
    } else if matches!(cfg.enabled, Some(false)) {
        TelemetryState::Disabled("config")
    } else {
        TelemetryState::Enabled
    };
    ...
}
```

**设计模式 A:分级 opt-out 链**。offline → env(ATOMCODE_TELEMETRY)→ env(DO_NOT_TRACK)→ CLI → config,每级都有稳定字符串 reason,方便排查"为什么这次没上报"。

#### 2.1.3 敏感信息脱敏:双层 regex + 路径 scrub

`crates/atomcode-telemetry/src/scrub.rs:23-44` 是业界最精细的源码级脱敏:

```rust
pub fn redact_secrets(s: &str) -> String {
    // 第一遍:key/value 凭证 — authorization:/api_key=/password: … 保留 key,redact value
    let kv = Regex::new(r#"(?i)(\b(?:authorization|x-api-key|api[-_]?key|...)\b\s*[:=]\s*"?(?:bearer\s+|token\s+)?)([^"'\s,;)]{6,})"#);
    // 第二遍:独立 token 形状 — GitHub/GitLab/AWS/Google/Slack/OpenAI/JWT
    let tokens = Regex::new(r#"\b(?:gh[opsru]_[A-Za-z0-9]{20,}|github_pat_...|sk-[A-Za-z0-9\-_]{16,}|AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z\-_]{35}|eyJ...)\b"#);
    let step1 = kv.replace_all(s, "${1}<REDACTED>");
    tokens.replace_all(&step1, "<REDACTED>").into_owned()
}
```

`scrub.rs:46-59` 还提供 **路径 scrub**(`<HOME>`/`<CWD>` 替换)和 `backtrace_top_k` 截取:

```rust
pub fn scrub_path(s: &str, home: Option<&Path>, cwd: Option<&Path>) -> String {
    let mut out = s.to_string();
    if let Some(h) = home { out = out.replace(h, "<HOME>"); }
    if let Some(c) = cwd { out = out.replace(c, "<CWD>"); }
    out
}
```

> **设计模式 B:backstop 脱敏**。工具参数在进 telemetry 前过一遍 regex,即使上游忘记脱敏也能兜底。laew 的 Bash 工具可注入 `curl -H "Authorization: token ghp_xxx"` 这类命令,必须有此兜底。

## 4. 可复用设计模式(6-10 个)

### 模式 A:分级 opt-out 链(atomcode)

offline → env×2 → CLI → config,每级有稳定 reason 字符串。**适用**:laew 加遥测时,默认关闭,通过 `--telemetry` 或 `LAEW_TELEMETRY=1` 开启。

### 模式 B:backstop 脱敏(atomcode/openclaw)

工具参数进 telemetry 前过 regex,即使上游忘记脱敏也兜底。**适用**:laew Bash 工具可注入任意命令,必须在 `track()` 前 scrub。

### 模式 C:track / track_durable 双通道(atomcode)

普通事件非阻塞(背压丢),关键事件同步 fsync。**适用**:laew 的 session 摘要 / panic 走 durable,普通工具调用走 track。

### 模式 D:opt-in OTEL + runID(opencode)

默认不上报,env 开;每次进程启动生成短 runID。**适用**:laew 加 tracing 时用 `uuid::new_v4()` 生成 run_id,所有日志携带。

### 模式 E:schema-first + 编译期校验(pi)

span 属性用 TS 类型系统校验,`cardinality:"low"` 标注高基数。**适用**:laew 用 Rust enum 定义 `SpanKey`,避免手写字符串。

### 模式 F:prefilter 加速(openclaw)

先过轻量 regex,不命中则跳过完整脱敏。**适用**:laew 高频日志场景(每轮多次工具调用),避免每条都跑全量 pattern。

### 模式 G:never 类型 PII 门卫(claudecode)

`AnalyticsMetadata_IS_NOT_CODE = never` 强制编译期确认。**适用**:laew 用 `PII<T>` newtype + `Scrubbed<T>` 区分。

### 模式 H:精确性优先(deepseek)

"无法证明精确"时返回 `undefined`,绝不估算。**适用**:laew 的 billing 统计,缺失字段显示"—"而非 0。

### 模式 I:双源拼接 + GROUPING SETS(opencode)

legacy/live 源 handoff 避免重叠;一条 SQL 同时产出多级聚合。**适用**:laew 的 `session_memory` 统计。

### 模式 J:轨迹回放 cell(deepseek)

每轮对话渲染成可展开 cell,点击展示 TTFT/token/耗时。**适用**:laew TUI 调试模式。

## 6. 反模式警示

### 反模式 1:直接打印 API key 到日志

laew 的 `build_common_headers` 构造 `Bearer {api_key}`,若加日志时直接 `debug!("{headers}")` 就泄漏。**必须**:日志里只出现 `Bearer ****末4位`,参考 atomcode `redact_secrets`。

### 反模式 2:panic 不恢复 TUI 终端

laew 是 TUI,`set_hook` 里若不调用 `restore_terminal_if_tui()`,终端残留在原始模式,用户需 `reset`。参考 atomcode `main.rs:1355`。

### 反模式 3:遥测阻塞主线程

若 laew 的 LLM 调用路径内同步写日志/遥测,会阻塞 agent 循环。**必须**:走 atomcode 的 `mpsc` 异步通道或 opencode 的 Effect 异步 Logger。

### 反模式 4:高基数字段进 metric label

`session_id`/`turn_id` 是高基数,进 Prometheus label 会炸。参考 pi `cardinality:"low"` 标注,高基数字段只放 log 属性,不放 metric label。

### 反模式 5:估算 token 当精确值

参考 deepseek `deriveTurnToken_usage` —— 无法证明精确时返回 `undefined`,显示"—"。laew 的 `Usage` 字段为 0 时需区分"上游未提供"和"确实为 0"。

## 7. 结论

1. **laew 可观测性几乎为零,但骨架良好** —— `Usage` 字段、`session_memory`/`agent_memory` 表、`agent_role` 枚举都已就位,缺的是"把字段串成可查阅链路"的基础设施。

2. **atomcode 是 laew 的最佳参考** —— 同为 Rust CLI,其 `atomcode-telemetry` crate 的 5 级 opt-out、双通道(track/durable)、NDJSON 队列、双层脱敏、panic 双 hook,几乎可以"翻译成 Rust 版"直接落地。

3. **opencode 的 stats 包展示"统计面板"全链路** —— 从客户端发射到 Firehose/R2/Athena/PlanetScale 的完整路径,laew 虽不需要这么重,但 **GROUPING SETS 多维聚合** 和 **双源拼接** 思路可直接用于 SQLite 端。

4. **pi 的 schema-first 思路值得 Rust 化** —— 用 Rust enum + struct 定义 `SpanDef`,编译期保证 `agent_role`/`tool_name`/`error_kind` 不写错,`cardinality` 标注高基数。

5. **隐私与采样是底线** —— atomcode 5 级 opt-out + openclaw 1200 行脱敏 + claudecode never 类型 PII 门卫,三者结合是 laew 加遥务的"最低合规线"。
