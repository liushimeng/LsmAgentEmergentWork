## 1. 横向对比总览表

### 1.1 核心机制对比

| 维度 | Claude Code | AtomCode | OpenClaw | OpenCode | DeepSeek-Harness | Pi |
|------|-------------|----------|----------|----------|-----------------|-----|
| **记忆分层** | 4 层（Session/Auto/Agent/Team） | 2 轨（Project + Global） | 插件化（Memory Host SDK） | 无独立记忆层 | 无独立记忆层 | 无独立记忆层 |
| **持久化介质** | 文件系统 Markdown | 文件系统 Markdown | SQLite + 向量索引 + Markdown | 无（仅 session 内） | JSONL / SQLite | 内存态（InMemorySessionStorage） |
| **写入时机** | 每轮停止后（extractMemories）+ 用户显式 | 用户显式（MemoryTool） | 工具调用后（memory flush） | 无 | 事件提交时（projection fold） | 压缩时（compaction） |
| **检索时机** | 每次请求（findRelevantMemories）+ 系统提示注入 | 会话开始（MemoryHook） | 每次请求（memory search） | 无 | 无 | 无 |
| **记忆压缩** | Session Memory Compact + Auto Dream | 无（仅 64KB 截断） | 无（依赖插件） | Compaction Agent 摘要 | BasicCompactionEngine | Compaction + Branch Summary |
| **项目记忆** | CLAUDE.md 五级链（Managed/User/Project/Local/AutoMem） | AGENTS.md / .atomcode.md | MEMORY.md（root-memory-files.ts） | 无 | 无 | 无 |
| **记忆类型分类** | 4 类（user/feedback/project/reference） | 无（纯文本条目） | 无（依赖插件） | — | — | — |
| **跨 Session 复用** | ✅（Auto Memory 跨会话） | ✅（Global 跨项目） | ✅（rememberAcrossConversations） | ❌ | ❌ | ❌ |
| **语言** | TypeScript | Rust | TypeScript | TypeScript (Effect) | TypeScript | TypeScript |
| **核心代码量** | ~3500 行（记忆相关） | ~500 行 | ~2000 行（含 SDK） | ~200 行（仅摘要） | ~800 行（投影） | ~600 行（压缩+分支） |

### 1.2 记忆丰富度光谱

```
无独立记忆层                                          完整记忆体系
←─────────────────────────────────────────────────────────────────────────→
OpenCode       DeepSeek-Harness       Pi       AtomCode       OpenClaw       Claude Code
(仅压缩摘要)    (事件源折叠)          (Lane内存)  (双轨文件)     (插件+向量)     (四层+梦境)
```

laew 的 session_memory + agent_memory 双表位于光谱的**中段**，与 AtomCode 的双轨文件记忆接近，但缺乏跨 Session 自动复用与项目记忆发现机制。

### 1.3 对 laew 的适用度排名

```
AtomCode (Rust 同源 + 双轨近似) > Claude Code (最完整) > OpenClaw (插件化参考) > Pi (压缩模式) > DeepSeek (事件源) > OpenCode (最简)
```

## 2. Claude Code：四层记忆体系 + 自动梦境整合

> **来源文件**: `claudecode-核心机制深度分析.md`
> **核心文件**: `src/services/SessionMemory/sessionMemory.ts` (495 行) / `src/services/extractMemories/extractMemories.ts` / `src/memdir/memdir.ts` / `src/memdir/findRelevantMemories.ts` / `src/services/autoDream/autoDream.ts` / `src/services/MagicDocs/magicDocs.ts` / `src/tools/AgentTool/agentMemory.ts` / `src/services/teamMemorySync/index.ts`

### 2.1 架构总览

Claude Code 拥有 6 个项目中**最完整、最复杂**的记忆体系，分为 4 层 + 2 个后台整合机制：

```
Layer 1: Session Memory      ─→  单会话笔记（~/.claude/projects/<slug>/memory.md）
Layer 2: Auto Memory         ─→  跨会话持久化（~/.claude/projects/<slug>/memory/*.md）
Layer 3: Agent Memory        ─→  单 Agent 持久化（按 scope: user/project/local）
Layer 4: Team Memory         ─→  团队共享（team/*.md + 服务端同步）

Background: extractMemories  ─→  每轮停止后自动提取
Background: autoDream        ─→  后台跨会话整合（时间门控 + 会话门控）
Background: MagicDocs        ─→  自动维护 # MAGIC DOC: 标记的文档
```

### 2.2 Layer 1：Session Memory（会话记忆）

**文件**: `src/services/SessionMemory/sessionMemory.ts`

Session Memory 是**单会话**的笔记文件，存储在 `~/.claude/projects/<slug>/memory.md`。

**写入时机**：通过 `registerPostSamplingHook(extractSessionMemory)` 注册后采样钩子，在每轮模型输出完成后触发。

**触发条件**（`shouldExtractMemory`）：

```typescript
// sessionMemory.ts:134
export function shouldExtractMemory(messages: Message[]): boolean {
  const currentTokenCount = tokenCountWithEstimation(messages)
  if (!isSessionMemoryInitialized()) {
    if (!hasMetInitializationThreshold(currentTokenCount)) return false
    markSessionMemoryInitialized()
  }
  const hasMetTokenThreshold = hasMetUpdateThreshold(currentTokenCount)
  const toolCallsSinceLastUpdate = countToolCallsSince(messages, lastMemoryMessageUuid)
  const hasMetToolCallThreshold = toolCallsSinceLastUpdate >= getToolCallsBetweenUpdates
  const hasToolCallsInLastTurn = hasToolCallsInLastAssistantTurn(messages)
  const shouldExtract = (hasMetTokenThreshold && hasMetToolCallThreshold) ||
    (hasMetTokenThreshold && !hasToolCallsInLastTurn)
  return shouldExtract
}
```

**配置常量**（`SessionMemoryConfig`）：

```typescript
// sessionMemoryUtils.ts:32
export const DEFAULT_SESSION_MEMORY_CONFIG: SessionMemoryConfig = {
  minimumMessageTokensToInit: 10000,    // 会话达到 10K token 才初始化
  minimumTokensBetweenUpdate: 5000,     // 两次更新间至少增长 5K token
  toolCallsBetweenUpdates: 3,           // 或至少 3 次工具调用
}
```

**写入方式**：使用 `runForkedAgent` 创建隔离子 Agent，仅允许 `FileEditTool` 编辑 memory.md 文件。

### 2.6 后台整合：Auto Dream（自动梦境）

**文件**: `src/services/autoDream/autoDream.ts`

Auto Dream 是**跨会话记忆整合**机制，在时间门控（默认 24h）和会话门控（默认 5 个会话）满足后，后台触发 `/dream` prompt，将多个会话的日志整合为结构化记忆：


门控顺序（cheapest first）：
1. Time gate：距上次整合 ≥ 24h
2. Session gate：≥ 5 个会话有活动
3. Lock gate：无其他进程正在整合

```rust
pub fn append_deduped(&self, content: &str) -> io::Result<bool> {
    let trimmed = content.trim();
    let dup = self.load().iter().any(|e| e.trim().eq_ignore_ascii_case(trimmed));
    if dup { return Ok(false); }
    self.append(trimmed)?;
    Ok(true)
}
```

```rust
pub fn merged_for_prompt(global: &MemoryStore, project: &MemoryStore, project_name: &str) -> String {
    let mut result = String::from(
```

### 3.4 MemoryHook（记忆注入钩子）

**文件**: `crates/atomcode-capabilities/src/memory/hook.rs`

MemoryHook 在 `session_start` 生命周期注入合并记忆：

```rust
// hook.rs:70
async fn session_start(&self, convo: &mut Conversation, resumed: bool) {
    let merged = MemoryStore::merged_for_prompt(&self.global, &self.project, &self.project_name);
    if !resumed {
        if !merged.is_empty() { convo.push(Message::system(merged)); }
        return;
    }
    // RESUME: 刷新快照中的旧记忆
    let existing = convo.messages.iter().position(|m| m.role == Role::System && m.text.starts_with(MEMORY_HEADER));
    match existing {
        Some(i) if merged.is_empty() => { convo.messages.remove(i); }
        Some(i) => { convo.messages[i] = Message::system(merged); }
        None if !merged.is_empty() => { /* 插入新记忆块 */ }
        None => {}
    }
}
```

**关键设计**：Resume 时**原地刷新**快照中的 `=== MEMORY ===` 消息，保持 cache 稳定。

### 3.5 关键设计亮点

1. **双轨文件存储**：Project + Global 简单清晰，与 laew 双表结构最接近
2. **去重写入**：`append_deduped` 避免重复条目
3. **64KB 截断**：大文件只读尾部，避免 token 爆炸
4. **Hook 注入**：session_start 时注入，resume 时原地刷新
5. **Rust 实现**：对 laew 最具参考价值

**retainedTail 设计**：它不是摘要的一部分，而是**完整保留的最近消息**。压缩后的上下文 = compaction summary + retainedTail。

### 7.4 Branch Summarization（分支摘要）

**文件**: `packages/agent/src/harness/compaction/branch-summarization.ts`

## 8. 设计提炼

### 模式 1：双轨文件记忆（Dual-Track File Memory）

**定义**：记忆按作用域分为 Project（项目级）和 Global（全局级）两个文件存储。

**采用者**：AtomCode（`.atomcode/memory.md` + `$ATOMCODE_HOME/memory.md`）、Claude Code Auto Memory（private + team）

**laew 借鉴**：laew 的 session_memory + agent_memory 双表可借鉴此模式，增加 project_memory 文件作为项目级持久化记忆。

### 模式 2：类型化记忆分类（Typed Memory Taxonomy）

**定义**：记忆按内容类型分类，每类有明确的保存/不保存清单。

**采用者**：Claude Code（user/feedback/project/reference 4 类）

**laew 借鉴**：agent_memory 表可增加 `memory_type` 字段（preference/convention/error/artifacts），并增加"不保存清单"。

### 模式 3：后台自动提取（Background Auto-Extraction）

**定义**：在每轮对话停止后，后台 forked agent 自动提取关键信息写入记忆。

**采用者**：Claude Code（extractMemories）

**laew 借鉴**：SessionContext Agent 可扩展为后台自动提取模式，在每任务完成后自动提取关键经验。

### 模式 4：侧查询检索（Side-Query Retrieval）

**定义**：使用轻量模型（Sonnet）做相关性选择，从大量记忆中筛选最相关的子集。

**采用者**：Claude Code（findRelevantMemories 使用 Sonnet side-query）

**laew 借鉴**：Yolo 处理时可增加"记忆检索"步骤，从 agent_memory 表中按相关性筛选。

### 模式 5：跨会话整合（Cross-Session Consolidation）

**定义**：后台定期将多个会话的经验整合为结构化记忆。

**采用者**：Claude Code（Auto Dream，时间门控 + 会话门控）

**laew 借鉴**：可增加"整合 Agent"，定期将多个 session_memory 整合为长期经验。

### 模式 6：Hook 注入（Hook Injection）

**定义**：在会话开始的生命周期钩子中注入记忆，Resume 时原地刷新。

**采用者**：AtomCode（MemoryHook.session_start）

**laew 借鉴**：laew 的 `<<<LAEW:SESSION_HISTORY>>>` 注入可改为 Hook 模式，在 Session 启动时注入。

### 模式 7：入口文件索引（Entrypoint Index）

**定义**：使用单一索引文件（MEMORY.md）作为入口，指向多个 topic 文件。

**采用者**：Claude Code（MEMORY.md 索引 + topic 文件）

**laew 借鉴**：project_memory 可使用索引文件 + topic 文件的结构，避免单文件过大。

### 模式 8：向量 + 全文混合检索（Hybrid Vector + FTS Retrieval）

**定义**：同时支持语义向量检索和全文关键词检索。

**采用者**：OpenClaw（sqlite-vec + FTS5）

**laew 借鉴**：agent_memory 表可增加向量列，支持语义检索（需引入 sqlite-vec 扩展）。

### 模式 9：追加写保护（Append-Only Write Guard）

**定义**：记忆写入只能是追加，不能修改已有条目，保证幂等性。

**采用者**：OpenClaw（MEMORY_FLUSH_ALLOWED_TOOL_NAMES = read/write）

**laew 借鉴**：agent_memory 表天然是追加写，可增加"forget"机制按关键词删除。

### 模式 10：项目记忆五级链（Project Memory 5-Level Chain）

**定义**：项目记忆按优先级从低到高分为 5 层发现。

**采用者**：Claude Code（Managed/User/Project/Local/AutoMem）

**laew 借鉴**：laew 当前是 CLAUDE.md → AGENTS.md → README.md → 自动生成 → 空 五级链，可参考增加 User（`~/.laew/CLAUDE.md`）和 Local（`CLAUDE.local.md`）层。

### 模式 11：Resume 原地刷新（Resume In-Place Refresh）

**定义**：会话恢复时，记忆块在快照中原地更新，不改变消息结构。

**采用者**：AtomCode（MemoryHook resume 分支）

**laew 借鉴**：laew 的 Session 恢复时可原地刷新 `<<<LAEW:SESSION_HISTORY>>>` 块。

### 模式 12：结构化摘要（Structured Summary）

**定义**：压缩摘要使用预定义的结构化字段，而非自由格式。

**采用者**：Pi（Goal/Constraints/Progress/Key Decisions/Next Steps）

**laew 借鉴**：SessionContext Agent 的摘要可改为结构化格式，提高后续检索质量。

### 9.5 特别注意事项

1. **Rust 实现参考 AtomCode**：laew 是 Rust 项目，AtomCode 的 `memory/store.rs` 是最直接的参考。MemoryStore、MemoryHook、MemoryTool 三个结构可以直接借鉴。

2. **多 Agent 架构的独特挑战**：laew 有 6 个 Agent 角色，每个角色有独立的 Agent-Context。记忆系统需要考虑：
   - SubAgent-Work 的工具调用经验应写入哪个 agent_memory？
   - SessionContext 的摘要与 Consolidation Agent 的整合如何协调？
   - Plan Agent 的输出在压缩后如何重新注入？

3. **SQLite 持久化**：laew 已有 SQLite 基础设施（`LsmAgentEmergentWork.db`），记忆状态可以复用现有表结构。

4. **不要过度工程化**：先从最简单的 P0（结构化摘要）开始，逐步升级。参考 AtomCode 的双轨文件记忆思路，每升一级都是对前一级的补充而非替换。

```rust
// src/agent/memory_hook.rs
pub fn inject_memory_at_session_start(
    cwd: &Path, messages: &mut Vec<Message>,
) {
    let user = load_memory(&user_memory_path());
    let project = load_memory(&project_memory_path(cwd));
    let merged = merge_memories(&user, &project);
    if !merged.is_empty() {
        // 注入到系统消息之后
        let at = messages.iter().take_while(|m| m.role == Role::System).count();
        messages.insert(at, Message::system(format!("{}\n{}", MEMORY_HEADER, merged)));
    }
}
```

- **Claude Code** 是唯一拥有完整四层记忆体系的项目，所有维度均满分

- **laew** 当前约 **15/40**（双表 + 历史注入 + 项目上下文），处于 AtomCode 与 OpenClaw 之间
