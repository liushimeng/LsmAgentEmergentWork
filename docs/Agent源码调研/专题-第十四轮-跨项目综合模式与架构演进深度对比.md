## 1. 设计模式应用

### 1.1 工厂模式（Factory Pattern）

#### atomcode — `provider_factory` + `build_coding_agent`

atomcode 的工厂模式体现在 **两层分离**：`ProviderFactory` 负责构造 LLM Provider，`build_coding_agent` 负责组装完整 Agent。

```rust
// crates/atomcode-coding/src/lib.rs
pub fn build_coding_agent(config: CodingAgentConfig) -> Result<Agent, BuildError>
pub fn build_coding_agent_with(factory: impl CodingProviderFactory) -> Result<Agent, BuildError>
pub fn try_build_coding_agent_with(...) -> Result<Agent, BuildError>

// provider_factory.rs — trait 抽象
pub trait CodingProviderFactory {
    fn build(&self, config: &CodingAgentConfig) -> Result<Box<dyn LlmProvider>, ProviderBuildError>;
}
pub struct DefaultCodingProviderFactory;
pub struct AtomGitProviderAuthenticator;
```

**设计要点**：`build_coding_agent` 是最小同步组装（仅 tools + codeintel），完整 Agent 通过 `prepare` → `assemble` 两阶段构造（`parts.rs`），实现了**建造者模式 + 工厂模式**的复合。

### 1.2 策略模式（Strategy Pattern）

#### atomcode — `ToolMiddleware` trait

```rust
// crates/atomcode-kernel/src/middleware.rs
#[async_trait]
pub trait ToolMiddleware: Send + Sync {
    async fn before(&self, _call: &mut ToolCall, _tool: &Arc<dyn Tool>, _rt: &RequestCtx) -> BeforeOutcome
    async fn after(&self, _result: &mut ToolResult, _tool: Option<&Arc<dyn Tool>>) -> AfterOutcome
}

pub enum BeforeOutcome {
    Proceed, Allow{reason}, Ask{reason}, Deny{reason}, DenyTurn{reason}, DenyTurnWithIntervention{reason, intervention}
}
```

**关键设计**：中间件按注册顺序执行，`before` 链中第一个 `Deny` 阻断，`Allow` 短路跳过后续。这是**策略模式 + 责任链**的复合。

#### Switchyard — `Algorithm` trait 作为策略核心

```rust
// crates/libsy/src/core/algorithm.rs
pub trait Algorithm: Send + Sync {
    fn name(&self) -> &str;
    fn run_stream(&self, request: Request, driver: Driver) -> StepStream;
}

// Driver 作为算法的"卸载通道"
pub struct Driver {
    step_tx: mpsc::Sender<Result<Step>>,
    algorithm: String,
}

impl Driver {
    pub async fn call_model(&self, request: Request, models: Vec<ModelId>) -> Result<Response>
}
```

Switchyard 的策略模式是**完全正交**的：7 种 `Algorithm` 实现可任意切换，`Driver` 作为算法与宿主之间的解耦通道。

claudecode 的策略模式是**函数式**的：`CanUseToolFn` 是一个可注入的函数，不同模式（default / bypass / plan）注入不同实现。

### 1.3 观察者模式（Observer Pattern）

#### atomcode — `AgentEvent` + `LifecycleHooks`

```rust
// crates/atomcode-kernel/src/event.rs
pub enum AgentEvent {
    SessionStart, TurnStart, TurnComplete,
    ToolCall, ToolResult, ToolError,
    StreamChunk, Stop, Error,
}

// LifecycleHooks trait — 8 个生命周期钩子
#[async_trait]
pub trait LifecycleHooks: Send + Sync {
    async fn session_start(&self, convo: &mut Conversation, resumed: bool) {}
    async fn user_prompt_submit(&self, text: &mut String) -> Result<(), String> { Ok(()) }
    async fn turn_start(&self, convo: &mut Conversation) {}
    async fn pre_request(&self, messages: &mut Vec<Message>, ctx: &TurnCtx) {}
    async fn on_request(&self, messages: &[Message], tools: &[ToolDef], options: &ChatOptions, ctx: &TurnCtx) {}
    async fn on_model_response(&self, message: &mut Message, ctx: &TurnCtx) {}
    async fn offer_continuation(&self, ctx: &TurnCtx) -> Option<Continuation> { None }
    async fn on_error(&self, error: &ProviderError, ctx: &TurnCtx) {}
}
```

**关键设计**：atomcode 的观察者分两层 — **TURN 级**（`LifecycleHooks`）和 **TOOL 级**（`ToolMiddleware`），严格隔离。

### 1.6 状态机模式（State Machine Pattern）

#### deepseek-harness — `Phase` 枚举

```typescript
// packages/core/agent-loop/src/agent.ts
type Phase =
  | { kind: 'idle'; lastTurn: number }
  | { kind: 'maintenance'; abort: AbortController; lastTurn: number; wakeRequested: boolean }
  | { kind: 'running'; abort: AbortController; turn: number; step: number; wakeRequested: boolean }

private setPhase(next: Phase): void {
  const previousStatus = this.status
  this.phase = next
  const status = this.status
  if (status !== previousStatus) {
    this.dispatch.emit('agent/status', { status })
  }
}
```

**关键设计**：`Phase` 是**穷举式状态机**，TypeScript 编译器保证所有状态转换都被处理。`wakeRequested` 字段实现**延迟唤醒**：维护模式或中止的 driver 无法交付唤醒时，延迟到收敛后重放。
