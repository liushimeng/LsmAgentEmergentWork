## 1. SQLite 深度优化

### 1.1 WAL 模式配置

#### pi — 最精简的 WAL 配置

`packages/session-backends/sqlite-node/src/sqlite/repo.ts` (L172-175):

```rust
fn configureSqliteDatabase(db: SqliteDatabase): void {
    sql`PRAGMA journal_mode=WAL`.exec(db);
    sql`PRAGMA synchronous=FULL`.exec(db);
    sql`PRAGMA busy_timeout=5000`.exec(db);
}
```

**关键设计**：
- `synchronous=FULL` — 最严格持久性，每次事务提交都等待 fsync 完成
- `busy_timeout=5000` — 5 秒锁等待，避免瞬时锁冲突
- 无 `cache_size` / `mmap_size` 配置 — 依赖 SQLite 默认值

#### opencode — Effect + Drizzle 的 WAL 配置

`packages/core/src/database/database.ts`:

```typescript
yield* db.run("PRAGMA journal_mode = WAL")
yield* db.run("PRAGMA synchronous = NORMAL")
yield* db.run("PRAGMA busy_timeout = 5000")
yield* db.run("PRAGMA cache_size = -64000")  // 64MB
yield* db.run("PRAGMA foreign_keys = ON")
yield* db.run("PRAGMA wal_checkpoint(PASSIVE)")
```

**关键设计**：
- `synchronous=NORMAL` — WAL 模式下的合理折中（WAL 模式本身已足够安全）
- `cache_size = -64000` — 显式 64MB 缓存（负值表示 KB 单位）
- 启动时执行 `wal_checkpoint(PASSIVE)` — 回收已提交页面

#### openclaw — 最完整的 WAL 生命周期管理

`src/infra/sqlite-wal.ts` (全文 ~740 行):

```typescript
const DEFAULT_SQLITE_WAL_AUTOCHECKPOINT_PAGES = 1000;
const DEFAULT_SQLITE_WAL_CHECKPOINT_INTERVAL_MS = 30 * 60 * 1000;  // 30 分钟
const DEFAULT_SQLITE_WAL_JOURNAL_SIZE_LIMIT_BYTES = 64 * 1024 * 1024;  // 64MB
const INCREMENTAL_VACUUM_MAX_PAGES_PER_PASS = 512;
```

**关键设计**：
- **文件系统感知**：检测 NFS/SMB/virtiofs/9p 等网络/跨 VM 文件系统，自动回退到 rollback journal
- **WAL split-brain 检测**：通过 `/proc/self/fd` 比对设备号+inode，检测到 WAL 文件被替换时直接终止进程
- **增量 VACUUM**：每次最多释放 512 页（~2MB），避免阻塞事件循环
- **定期 checkpoint**：30 分钟间隔 + 关闭时 TRUNCATE
- **journal_size_limit**：WAL 文件上限 64MB

#### deepseek-harness — 会话持久化的 WAL 配置

### 1.5 批量写入优化

async appendBatch(meta, events, isMaterialized): Promise<void> {
  this.db.exec(sql('begin-immediate'))
  try {
    for (const record of packChunkRuns(events)) {
      this.insertRecord(insert, sessionKey, bindRecord(record))
    }
    this.incrementRevision(meta.id)

## 3. 数据模型设计

### 3.1 pi — 会话持久化模型

`packages/session-backends/sqlite-node/src/sqlite/migrations/001_initial.sql`:

```sql
-- 会话表
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    created_at INTEGER NOT NULL,
    cwd TEXT NOT NULL,
    parent_session_id TEXT NULL,
    metadata TEXT NULL
) WITHOUT ROWID;

-- 条目表（消息/工具调用/结果）
CREATE TABLE entries (
    session_id TEXT NOT NULL,
    seq INTEGER NOT NULL,
    id TEXT NOT NULL,
    parent_id TEXT NULL,
    type TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    payload TEXT NOT NULL,
    PRIMARY KEY (session_id, id),
    UNIQUE (session_id, seq)
);

-- 分支缓存（派生自 entries.parent_id）
CREATE TABLE branch_entries (
    session_id TEXT NOT NULL,
    branch_id TEXT NOT NULL,
    entry_id TEXT NOT NULL,
    entry_seq INTEGER NOT NULL,
    entry_type TEXT NULL,
    custom_type TEXT NULL,
    PRIMARY KEY (session_id, branch_id, entry_id)
) WITHOUT ROWID;

-- Lane 状态机
CREATE TABLE lanes (
    session_id TEXT NOT NULL,
    lane TEXT NOT NULL,
    leaf_id TEXT NULL,
    open_operation_id TEXT NULL,
    PRIMARY KEY (session_id, lane)
) WITHOUT ROWID;

-- Writer Lease（乐观锁）
CREATE TABLE writer_leases (
    session_id TEXT PRIMARY KEY,
    owner_id TEXT NOT NULL,
    fence INTEGER NOT NULL,
    expires_at_ms INTEGER NOT NULL
) WITHOUT ROWID;
```

**关键设计**：
- `WITHOUT ROWID` — 主键即行号，减少 B-tree 查找
- `seq` 单调序列 — 保证事件顺序
- `parent_id` 链 — 构建消息树
- `branch_entries` — 派生缓存，加速分支扫描
- `writer_leases` — 乐观并发控制（fence 计数器）

## 6. 备份与恢复

### 6.1 deepseek-harness — 原子文件写入

`packages/storage/storage-json/src/atomic.ts`:

```typescript
export async function writeAtomic(path: string, data: string): Promise<void> {
  const tmp = join(dirname(path), `.${randomUUID()}.tmp`)
  try {
    const handle = await open(tmp, 'wx', 0o600)
    try {
      await handle.writeFile(data, 'utf8')
      await handle.sync()  // fsync 数据
    } finally {
      await handle.close()
    }
    await rename(tmp, path)  // 原子替换
    await fsyncDirectory(dirname(path))  // fsync 目录项
  } catch (error) {
    await rm(tmp, { force: true })
    throw error
  }
}
```

**关键设计**：
- temp → fsync → rename → fsync(dir) 四步协议
- `wx` 标志：独占创建，防止覆盖
- `0o600` 权限：仅所有者可读写
- 目录 fsync：保证重命名操作持久化
