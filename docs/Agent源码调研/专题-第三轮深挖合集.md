## 3. 共性模式与反模式汇总

### 模式 A:独立计数器 + 分层熔断（atomcode、opencode、Switchyard）

```
每种失败模式独立预算:
  provider_retry / stream_retry / empty_retries / rate_limit_waits / overflow_attempts / repeat_rounds
各计数器独立上限、独立重置语义,避免单一上限"误杀"。
```

### 模式 B:增量渲染"稳定边界"（opencode、pi、atomcode）

```
未闭合围栏 → 当单 token 的副作用,只 lex 不稳定后缀,不重扫全文。
节流:5ms/16ms 脏标记聚合 + Resize75ms 防抖。
```

### 模式 C:双后端 + WriterLease fence（pi、atomcode）

```
JSONL(追加写,高性能,单写者) + SQLite(并发读,多写者需 fence 互斥)
acquireWriterLease: INSERT ... ON CONFLICT DO UPDATE WHERE expires_at_ms <= now
续租必须匹配 owner_id + fence,10s 心跳 + 30s TTL
```

### 模式 D:设置优先安装 + 失败回滚（claudecode、openclaw）

```
Settings-first:先声明 intent(enabledPlugins)再物化
失败回滚简单,用户看到的"已安装"是逻辑态而非物理态
```

### 模式 E:类型化遥测 Schema（pi、atomcode）

```
TelemetrySchemaDefinition:编译期保证 span 属性不写错
cardinality:"low" 标注高基数,防止指标爆炸
UnionToIntersection 类型合并让编译器在调用点校验 span name+属性
```

### 反模式警示

| # | 反模式 | 来源 | 后果 |
|---|--------|------|------|
| 1 | promise 风暴 | claudecode pluginLoader | 上千 plugin 无节制并行 → 内存/文件描述符爆炸 |
| 2 | 跨市场依赖不可传递 | claudecode | 企业理解成本高,文档需明确"A 允许 B ≠ B 的依赖被允许" |
| 3 | strict 模式二义性 | claudecode marketplace | strict=true/false 影响 plugin.json 是否必须 — marketplace 作者易混淆 |
| 4 | O(n²) partial JSON | claudecode(已规避) | 每个 input_json_delta 都调 partialParse → 长工具参数二次方增长 |
| 5 | "倒金字塔"测试 | laew | tmux 真 PTY e2e 强,但单测=0, Eval=0, CI=0 |
