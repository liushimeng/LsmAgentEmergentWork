## 概述

本文档综合 wf-1、wf-2、wf-3 的分析结果，从 TUI 输入到 SessionContext 收口，梳理 LsmAgentEmergentWork 项目的完整调用链。

## 完整调用链（6 大环节）

### 环节 1: TuiSession 生命周期与 TUI 输入层

**核心结构**: `TuiSession` 是会话外壳，持有以下关键字段:
- `Paths`: 工作区路径配置
- `Db`: 持久化存储
- `MultiAgentOrchestrator`: 多 Agent 编排器（含 6 角色 Agent）
- `Session`: 当前会话状态
- `调试采集器`: 运行时诊断数据收集
- `transcript`: 对话转录记录
- `token 用量`: 资源消耗追踪
- `分支存储`: Git 分支状态
- `连接状态跟踪器`: 网络连接监控
- `离线队列`: 断网时任务缓存

**入口函数**:
- `bootstrap()` / `bootstrap_with_debug()`: 装配 orchestrator 和共享状态
- `run()` / `run_with_debug()`: TUI 主入口

**执行流程**:
1. 打印 banner
2. 进入 REPL 循环
3. 分发用户输入（支持 TTY 交互与非 TTY 管道两种模式）
4. 斜杠命令处理（`switch_provider`、`reset_session`、`add_provider_interactive`、`list_providers`）

---

### 环节 2: Yolo 任务分类层

**职责**: 接收 TUI 输入，进行任务类型分类，决定后续执行路径。

**分类结果映射**:
- 简单查询 → 直接响应
- 编码任务 → 进入 WorkFlow 拆分
- 系统管理 → 调用对应工具链
- 自动化测试 → 启动测试流程

**关键机制**:
- 输入解析与意图识别
- 任务复杂度评估
- 路由决策

---

### 环节 3: Main-Work 拆 WorkFlow 层

**职责**: 将复杂任务拆解为可执行的 WorkFlow 单元。

**拆分策略**:
1. 分析任务目标
2. 识别依赖关系
3. 划分执行步骤
4. 分配 SubFlow 给 SubAgent-Work

**输出产物**:
- WorkFlow DAG（有向无环图）
- 各 SubFlow 的依赖声明
- 执行优先级排序

---

### 环节 4: SubAgent-Work 执行层

**核心入口**: `run_session`(行170) → `run_session_cancellable`(行144) → `run_session_inner`(行178)

**三层嵌套入口结构**:
```
run_session (行170)
  └── run_session_cancellable (行144)
        └── run_session_inner (行178)
```

**核心循环机制**:
1. 调用 `complete_with_overflow_recovery`(行693)
2. 执行 `self.llm.complete(...)` 获取 Completion
3. 若含 `tool_calls`:
   - 逐个经 `tool.execute(args)` 执行
   - 结果由 `session.context_mut().push(ChatMessage::tool_result(...))` 回填上下文
   - 进入下一轮迭代

**保护机制**:
- 截断续接: 网络中断时自动重连
- 上下文溢出三级恢复:
  - 一级: 排水（丢弃旧消息）
  - 二级: 折叠（摘要压缩）
  - 三级: 暴露（完整保留）
- 重复失败短路: 连续失败时快速终止
- 无文本收敛短路: 无输出时提前退出

**关键字统计**:
- `run_session` / `tool_calls`: 65 处匹配
- `complete`: 16 处匹配
- 总行数: 1862 行

### 环节 6: SessionContext 收口层

**职责**: 汇总所有执行结果，更新会话状态，完成最终收口。

**收口流程**:
1. 收集各 SubFlow 产出
2. 更新 `Session.context`（ChatMessage 上下文）
3. 记录 `transcript` 对话转录
4. 更新 `token 用量` 统计
5. 同步 `分支存储` 与 `连接状态跟踪器`
6. 持久化到 `Db`

**关键方法**:
- `session.context_mut().push(...)`: 上下文更新
- 离线队列 flush: 网络恢复后批量提交
