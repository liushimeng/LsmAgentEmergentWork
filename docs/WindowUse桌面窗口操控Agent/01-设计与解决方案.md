# WindowUse 桌面窗口操控 Agent —— 设计与解决方案

> 2026-09-14 新增。第 9 角色 `LsmAgentEmergentWork-WindowUse`（桌面操控层）。
> 目标：让 laew 具备「读取、操作电脑上各种软件和窗口」的能力 ——
> Windows 走 HWND / UI Automation，macOS 走 Accessibility（AXUIElementRef），
> 由多 Agent 架构中的其他 Agent（Main-Work）按 `delegate_to` 委派任务给它。

## 1. 需求分析

| 需求             | 说明                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| Windows 窗口操控 | 枚举 HWND 顶层窗口，UIA / `EnumChildWindows` 遍历控件树，SendMessage / UIA 读写控件（点击按钮、输入文本、读取文本） |
| macOS 窗口操控   | Accessibility API（`AXUIElementRef`）读取/操作按钮、输入框、文本；需系统无障碍权限                                  |
| 统一抽象         | 抽象统一控件操作 Trait，隔离 Windows UIA 与 macOS AX 底层                                                           |
| 权限检测         | macOS `AXIsProcessTrustedWithOptions` 权限检测与引导提示；Windows UIA 可用性检测                                    |
| 架构融合         | 新角色挂入 8 角色编排链路，其他 Agent 可委派；QC / Memory / Debug / Cancel 全链路生效                               |

### 平台现实约束（设计前提）

1. **HWND 只能覆盖原生 Win32 控件**。WPF / Qt / Electron / 自绘 UI 没有子级 HWND，
   必须走 **UI Automation（UIA）**。因此 Windows 后端以 UIA 为主、Win32 消息为辅
   （UIA 对原生控件同样生效，`EnumChildWindows` 仅作为 UIA 不可用时的降级）。
2. **macOS AX 仅对实现了无障碍属性的应用生效**，且必须用户授予「辅助功能」权限
   （系统设置 → 隐私与安全性 → 辅助功能）。未授权时 API 返回 `kAXErrorAPIDisabled`，
   工具层要把「如何开权限」作为可读错误返回给 LLM，而不是裸错误码。
3. **Linux 等非目标平台**：本工程主要运行环境之一，不能编译失败、不能运行时崩溃。
   提供「尽力而为」后端：检测 `wmctrl` / `xdotool` 存在则用其列举/激活窗口；
   否则返回结构化「当前平台不支持窗口操控」错误，让 QC / Yolo 能正确失败回流。
4. **GUI 调用可能阻塞**（COM 套间、AX IPC 往返），工具执行必须 `spawn_blocking`，
   不得阻塞 tokio 运行时。

## 2. 总体设计

### 2.1 新角色定位（第 9 角色）

```
用户输入 → 项目上下文注入 → Yolo 分类(simple/medium/hard)
  → simple: SubAgent-Work 直执（保持现状）
  → medium/hard: Main-Work 拆 WorkFlow 列表
       ├─ delegate_to = "subagent"  → SubAgent-Work（Bash/Read/Write/Edit/Glob/Grep）
       └─ delegate_to = "windowuse" → WindowUse（Read + WindowList/WindowInspect/WindowAction）  ★新增
  → Quality-Check → SessionContext 收口
```

- **Agent 名**：`LsmAgentEmergentWork-WindowUse`
- **角色枚举**：`AgentRole::WindowUse`，`as_str() = "windowuse"`
- **层级**：执行层（与 SubAgent-Work 平级的「专项执行单元」），不直接面向用户输入，
  由 Main-Work 在拆解时按任务性质委派。
- **为什么 simple 档不直接路由 WindowUse**：Yolo 的分类协议（forced tool_choice
  `submit_task_classification`）不携带委派目标字段，改协议会波及全部 mock 测试与
  降级解析链。设计决策：**Yolo 系统提示词增补指引** —— 「涉及操作桌面软件窗口 /
  点击按钮 / 向窗口输入文本的任务，最低按 medium 档分类」，使其必经 Main-Work，
  由 Main-Work 决定委派 WindowUse。simple 链路零改动。

### 2.2 委派路由（架构融合关键点）

`WorkFlowSpec.delegate_to` 已有宽松反序列化（`lenient_delegate_to`），扩展：

| LLM 填写（大小写/连字符不敏感）                    | 解析为                                  |
| -------------------------------------------------- | --------------------------------------- |
| `subagent` / `subagent-work` 等                    | `AgentRole::SubAgent`（默认，现状不变） |
| `windowuse` / `window-use` / `window_use` / `窗口` | `AgentRole::WindowUse` ★                |

Main-Work 编排提示词中 `delegate_to` 的说明从「固定填 subagent」改为：
「桌面软件窗口操控类流程填 `windowuse`，其余填 `subagent`」。

编排器 `run_wf_unit` 按 `delegate_to` 选择 Runner：

- `SubAgent` → `SubAgentRunner`（现状）
- `WindowUse` → `WindowUseRunner`（新增，结构与 SubAgentRunner 完全一致：
  独立 sub-Session、`run_session_cancellable`、ExecutionTrace、Agent-Memory 落库）
- 其他角色出现在 delegate_to 视为非法，回退 SubAgent（现状宽松语义不变）

QC / SessionContext / Debug / Compact / 取消传播 / 并行调度对 WindowUse 单元
**完全复用现有链路**（`run_wf_unit` 内部只是换了执行 Runner，QC 仍吃
`outcome.text + trace`）。

### 2.3 窗口操控抽象层（`src/agent/window/`）

```
window/
  mod.rs       数据模型 + WindowDriver trait + 平台工厂 current_driver() + 权限检测
  windows.rs   [cfg(windows)]  UIA 主实现（Win32 降级）
  macos.rs     [cfg(macos)]    Accessibility(AXUIElementRef) 实现
  fallback.rs  [cfg(not(any(windows, macos)))]  wmctrl/xdotool 尽力而为 / 结构化不支持错误
```

**统一数据模型**（协议无关、平台无关）：

```rust
pub struct WindowInfo { id, title, process_name, pid, bounds: Rect }
pub struct ControlNode { path, role, name, value, bounds, actions: Vec<String>, children }
pub struct Rect { x, y, width, height }
pub enum ControlAction { Click, Focus, SetText(String), GetText, SendKeys(String), Invoke }
```

- `ControlNode.path`：控件在树中的稳定定位路径（如 `/0/2/1`，子索引链），
  `WindowAction` 工具凭它定位目标控件，避免 LLM 传句柄等不透明值。
- `actions`：该控件支持的动作名列表（UIA ControlPattern / AX Actions 映射），
  LLM 检视后可决定合法操作，减少盲调。

**WindowDriver trait**（同步方法，工具层 `spawn_blocking` 包裹）：

```rust
pub trait WindowDriver: Send + Sync {
    fn list_windows(&self, filter: Option<&str>) -> Result<Vec<WindowInfo>>;
    fn inspect(&self, window_id: &str, max_depth: usize, filter: Option<&str>) -> Result<ControlNode>;
    fn act(&self, window_id: &str, path: &str, action: ControlAction) -> Result<String>;
    fn permission_hint(&self) -> Option<String>;  // 缺权限/缺依赖时的可读引导
}
```

**Windows 后端**（`windows-rs`，`[target.'cfg(windows)'.dependencies]`）：

1. `EnumWindows` 枚举顶层可见窗口（`IsWindowVisible` + 非空标题），
   `GetWindowThreadProcessId` 取 PID，`GetWindowRect` 取边界；
2. UIA：`CoInitializeEx` → `CoCreateInstance(CUIAutomation)` →
   `ElementFromHandle` → TreeWalker 深度遍历控件树（Name / ControlType /
   BoundingRectangle / 可用 Patterns），深度默认 3（可由工具参数调）；
3. 操作：`InvokePattern.Invoke`（按钮）/ `ValuePattern.SetValue`（输入框）/
   `SetFocus`；UIA 不可用时降级 `SendMessageW(BM_CLICK / WM_SETTEXT / WM_GETTEXT)`；
4. 查找优化：遍历带 `filter`（名称/类型子串）与 `max_depth` 双裁剪，子树命中即剪枝。

**macOS 后端**（`core-foundation` + ApplicationServices 框架 FFI）：

1. 权限：`AXIsProcessTrustedWithOptions`（`kAXTrustedCheckOptionPrompt` 可触发系统弹窗，
   工具默认不弹、只返回引导文案；`LAEW_AX_PROMPT=1` 时允许弹窗）；
2. 窗口枚举：`CGWindowListCopyWindowInfo`（kCGWindowListOptionOnScreenOnly）
   取 layer-0 窗口 → PID → `AXUIElementCreateApplication(pid)`；
3. 控件遍历：`AXUIElementCopyAttributeValue`（`kAXChildrenAttribute` /
   `kAXRoleAttribute` / `kAXTitleAttribute` / `kAXValueAttribute` / `kAXPositionAttribute`
   / `kAXSizeAttribute`），同样深度/过滤裁剪；
4. 操作：`AXUIElementPerformAction`（`kAXPressAction`）/
   `AXUIElementSetAttributeValue`（`kAXValueAttribute` 写文本）/ `kAXFocusedAttribute`。

**Fallback 后端**（Linux 等）：

- `wmctrl -l` 存在 → 可列举窗口；`xdotool` 存在 → 可激活/聚焦；
- 控件级 inspect/act 返回结构化错误：「当前平台不支持控件级操控，
  需要 Windows(UIA) 或 macOS(Accessibility)」—— QC 能据此判定失败并回流，
  Yolo 重分类时可给出「请在 Windows/macOS 上执行」的用户建议。

### 2.4 工具层（`src/agent/tools/window.rs`）

3 个工具（命名沿用 PascalCase 惯例）：

| 工具            | 参数                                   | 行为                                                                                                |
| --------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `WindowList`    | `filter?`                              | 列出全部可见顶层窗口（id/title/进程/PID/位置尺寸），JSON 输出，按标题过滤                           |
| `WindowInspect` | `window_id`, `max_depth?=3`, `filter?` | 枚举指定窗口的控件树（角色/名称/值/边界/支持动作/路径），JSON 输出，超节点数自动截断并标注          |
| `WindowAction`  | `window_id`, `path`, `action`, `text?` | 对 `path` 定位的控件执行 click/focus/set_text/get_text/send_keys/invoke，返回操作结果或读取到的文本 |

- 全部 `spawn_blocking` 执行（UIA COM / AX IPC 可能阻塞）；
- 输出统一 JSON 且带总量截断（控件树最多 500 节点 / 32KB，超出标注 `truncated`），
  防止一次 tool_result 打爆上下文（对齐 overflow.rs 排水策略）；
- 错误信息全部「LLM 可读」：权限缺失给开权限步骤，控件未找到给相近候选路径。

## 3. 安全与边界

1. **无沙箱豁免**：窗口工具不经过 Bash 沙箱，但操作语义等价「代用户点击/输入」，
   系统提示词中明确：禁止对疑似支付/删除/发送类确认按钮做无确认点击（LLM 行为约束），
   后续可接 `agent/permissions` 框架做工具级闸门（留扩展点，本期不做）。
2. **权限 fail-closed**：macOS 未授权 / Windows UIA 初始化失败 / 平台不支持，
   全部返回结构化错误而非 panic；QC 据此判 Fail 回流 Yolo 出用户建议。
3. **只读优先**：`WindowList` / `WindowInspect` 无副作用；`WindowAction` 的
   `get_text` 也无副作用。提示词指引「先检视再操作」。
4. **上下文保护**：控件树输出双重截断（节点数 + 字节数），防止 tool_result 撑爆上下文。
