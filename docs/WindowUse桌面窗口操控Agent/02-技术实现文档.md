## 2. Windows 后端 API 映射(windows-rs 0.58)

| 能力 | API |
| ---- | --- |
| 顶层窗口枚举 | `EnumWindows`(可见 + 非空标题)→ `GetWindowTextW` / `GetWindowThreadProcessId` / `GetWindowRect` / `GetModuleBaseNameW`(进程名) |
| UIA 初始化 | `CoInitializeEx(MTA)`(守卫 Drop `CoUninitialize`)→ `CoCreateInstance(CUIAutomation)` |
| 控件树 | `ElementFromHandle(HWND)` → `RawViewWalker` 的 `GetFirstChildElement` / `GetNextSiblingElement` 递归;属性 `CurrentName` / `CurrentControlType` / `CurrentBoundingRectangle` |
| 动作探测 | `GetCurrentPatternAs::<IUIAutomationInvokePattern/ValuePattern>` 是否可得 → 写入 `actions` 列表 |
| 点击 | `IUIAutomationInvokePattern::Invoke`;无 Invoke Pattern 时 `SetFocus` + 降级 `SendMessageW(BM_CLICK)` |
| 写文本 | `IUIAutomationValuePattern::SetValue`;降级 `SendMessageW(WM_SETTEXT)` |
| 读文本 | `ValuePattern.CurrentValue` → 空则 `CurrentName`;降级 `WM_GETTEXT` |
| 降级树 | `GetWindow(GW_CHILD / GW_HWNDNEXT)` 递归 + `GetClassNameW` 作角色 |
| 窗口 id | HWND 十进制字符串(`HWND.0 as isize`) |

说明:`SendMessageW` 在 windows 0.58 的签名为 `Param<WPARAM>/Param<LPARAM>`(CopyType),
**不能传 `Option<WPARAM>`**,直接传 `WPARAM(0)` / `LPARAM(ptr)`(本工程初版踩坑已修)。

## 3. macOS 后端 API 映射(core-foundation 0.9 + ApplicationServices/CoreGraphics FFI)

| 能力 | API |
| ---- | --- |
| 权限检测 | `AXIsProcessTrustedWithOptions`;默认传 `NULL`(不弹窗),`LAEW_AX_PROMPT=1` 时带 `kAXTrustedCheckOptionPrompt=true` |
| 窗口枚举 | `CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly)`,过滤 `kCGWindowLayer==0`;窗口 id = `"{pid}:{index}"`(index 为同 pid 出现序号,对应 AX 窗口数组下标) |
| 控件树 | `AXUIElementCreateApplication(pid)` → `kAXWindowsAttribute[index]` → 递归 `kAXChildrenAttribute`;属性 Role/Title/Value/Position/Size(AXValue 解码 CGPoint/CGSize) |
| 点击 | `AXUIElementPerformAction(kAXPressAction)` |
| 写文本 | `AXUIElementSetAttributeValue(kAXValueAttribute, CFString)` |
| 聚焦 | `AXUIElementSetAttributeValue(kAXFocusedAttribute, true)` |
| 读文本 | `kAXValueAttribute` → 空则 `kAXTitleAttribute` |
| send_keys | 不支持(AX 无通用按键注入),返回改道提示(用 set_text / click 组合) |

AX 错误码人性化映射:`-25211 APIDisabled` → 开权限步骤引导;`-25212 InvalidUIElement` →
「控件已失效,重新 WindowInspect」;`-25205/-25206` → 属性/动作不支持;`-25204` → IPC 失败。

## 4. 工具层约定

- **阻塞隔离**:三个工具的驱动调用全部 `tokio::task::spawn_blocking` 包裹。
- **输出截断**:窗口列表 ≤ 200 条;控件树 ≤ 500 节点(深度优先保留前序)且 ≤ 32KB,
  截断时追加 `[truncated]` 标注与重试建议(调小 max_depth / 加 filter)。
- **参数校验顺序**:先参数校验(缺参/非法 action),再 `permission_hint()` 预检,
  避免无权限平台遮蔽参数错误(单测锁定该顺序)。
- **路径定位**:`path` 为子索引链(`/0/2/1`,根 `/`),由 `find_by_path` 在模型层定位,
  平台后端各自实现元素级路径遍历(UI 变化导致越界时提示重新检视)。
