### CW01 判题架构与沙箱隔离

- **预期档位**: hard
- **考察维度**: 不可信代码执行 / 资源限制 / 进程组管理
- **对话脚本**:
  1. 判题主流程：拉取提交 → 编译（限时 10s、静态二进制、-O2）→ 在沙箱里逐测试点运行（重定向 stdin/stdout、限时限内存）→ 比对输出 → 汇总判定（AC/WA/TLE/MLE/RE/CE）；用 Rust 或 Python 写出这个管线的主循环与状态枚举。
  2. 沙箱隔离三件套：`setrlimit`（CPU 时间 / 地址空间 / 输出大小 / 进程数）、`seccomp`/`landlock`（只放行 read/write/exit 等白名单系统调用，封 fork/exec/socket 防逃逸）、进程组 + 超时 killpg（防恶意代码 fork 子进程续命）；用 Rust 写一个最小 sandbox runner（克隆子进程 → 设置限制 → exec 用户程序 → waitpid 超时杀组）。
  3. 时间测量的坑：CPU 时间（`RUSAGE_CHILDREN` 的 utime+stime）vs 墙钟时间——判题用 CPU 时间防「sleep 卡墙钟、IO 等待误杀」；浮点限时的边界（题目 1s 限制实际判 1.05s 容差）；讨论 OJ 为什么普遍给 5~10% 的时间宽限。
  4. laew 借鉴：判题沙箱正是 docs 调研里 laew 的 P0 缺口「无沙箱」——对照讨论 BashTool 的最小改造路径：先加超时（tokio timeout + 进程组杀）、再加输出截断（已有 10000 字符策略）、最后才是系统调用过滤，按风险收益排序。

### CW02 测试点、子任务与部分得分

- **预期档位**: medium
- **考察维度**: 测试点组织 / 计分模型 / 数据强度分层
- **对话脚本**:
  1. 测试点模型：每题 N 个测试点各有分值（10 点 × 10 分），判定结果 = 逐点 AC/WA 汇总；设计 `submissions(id, problem_id, code, lang)` + `results(submission_id, case_no, status, time_ms, memory_kb)` 表结构并写「一个提交的得分汇总」查询。
  2. 子任务（subtask）：测试点分组捆绑计分（IOI 风格）——子任务 1（10%）满足 n≤100 暴力可过、子任务 2（30%）满足部分性质、子任务 3（60%）满规模；设计子任务表与「子任务内任一点失败整组 0 分」的计分逻辑，讨论子任务如何引导选手逐步拿分。
  3. 数据强度设计：一个题的数据集要覆盖「样例 / 边界（n=1、n=max、全同、全排反）/ 枚举正确性角落（负数、零、溢出边界）/ 大数据压力」五类；写出你给「最大子段和」设计 20 个测试点的清单与每个点的考察意图。
  4. laew 借鉴：测试点分层对照 Quality-Check 的分层校验——QC 现在是「整体通过/失败」，讨论给 QC 引入「子任务」概念：编译通过 20 分 / 核心功能 50 分 / 边界处理 30 分，失败回流时 Yolo 能看到部分得分定位问题层级。

### CW03 特判 spj 与交互题

- **预期档位**: hard
- **考察维度**: checker 协议 / 交互管道 / 浮点容差
- **对话脚本**:
  1. 特判（spj）：答案不唯一（「输出任意一组合法解」）时 diff 不够——checker 程序读入 (输入, 选手输出, 参考输出)，自行校验合法性后以退出码 + stderr 文本反馈；写一个「最小生成树输出方案合法性」checker（读边集与选手方案，验连通性 + 权值和）。
  2. 浮点容差：checker 里比较 `fabs(a-b) <= 1e-6`（绝对）/ `fabs(a-b) <= 1e-6 * max(1, fabs(b))`（相对）；讨论「输出保留几位小数」与容差的配合（题面说 4 位小数时 1e-4 容差是陷阱，应是 5e-5 级）。
  3. 交互题：选手程序与判题器通过管道对答（如猜数游戏：判题器出数、选手提问、判题器应答）——用两个 pipe 连接（judge ↔ stdio of contestant），IO 交互式刷新（setvbuf 无缓冲）；写一个「二十问题猜数」交互器的完整通信循环，处理选手非法输入与超时。
  4. laew 借鉴：交互题「双向管道 + 逐步应答」对照 Agent 与 LLM 的 tool-call 循环（LLM 发起工具调用 → Agent 执行回填 → LLM 继续）；讨论「判题器的超时与非法输入处理」在 Agent 循环里的等价物（工具执行超时 / 输出 schema 不符时的重试与终止）。

### CW04 防作弊：代码抄袭查重

- **预期档位**: medium~hard
- **考察维度**: 指纹提取 / 相似度比对 / 对抗变形
- **对话脚本**:
  1. 朴素失效：直接文本 diff 被变量重命名 / 加空格 / 调整顺序轻易绕过；先把代码规范化（去注释 / 去空白 / 标识符统一替换为 `V1 V2…` / 统一分号），再比较——讨论规范化后仍能被「等价语句改写」绕过的原因。
  2. winnowing 指纹（MOSS 的核心思想）：代码转 token 流 → k-gram 滚动哈希（联动 CU09）→ 选窗口内最小哈希留指纹 → 两份代码的指纹集 Jaccard 相似度；用 Python 实现全流程并在「复制后改 20% 标识符 + 调换两行」的样本上验证检出。
  3. 对抗与阈值：把 for 改 while、提取函数、内联变量等语义等价变换会降指纹重合——讨论为什么查重只能做「高相似告警 + 人工复核」而不能自动定罪，以及阈值（如 0.6 相似 + 共同罕见指纹）的标定方法。
  4. laew 借鉴：winnowing「最小哈希选择」的抗局部修改思想对照 laew 上下文缓存——若 PromptCaching 断点按「内容指纹」而非位置放置（前缀稳定时缓存命中），讨论会话中插入系统消息对缓存命中的破坏与恢复。

### CW05 数据生成器与对拍验证

- **预期档位**: medium
- **考察维度**: 随机数据生成 / 三方对拍 / 极限构造
- **对话脚本**:
  1. 生成器（generator）：按输入格式随机生成合法数据——受约束随机（树随机：随机父节点 / 随机 PRüfer 序；图随机：先树后加边保连通）；用 C++ 或 Python 写「随机无向连通图 + 随机边权」生成器并支持 `--seed` 复现（联动 CN03 种子确定性）。
  2. 对拍（stress test）：generator → 暴力解（正确但慢）→ 正解（快但可能有 bug）三方循环比对，任一输出不一致即 dump 数据停机；写 shell 循环版与 Rust 版，讨论「暴力解的正确性是前提」与多解题需要 checker（联动 CW03）而非 diff。
  3. 极限与针对性构造：随机覆盖不到的坑要定向造——对抗贪心的反例数据（构造让贪心选错路径的图）、卡常数据（链/菊花/网格三类极端形态）、卡 Hash 的数据（已知 anti-test 思想）；写「构造卡 `unordered_map` 的链状碰撞」的思路说明。
  4. laew 借鉴：对拍「三方可复现随机验证」对照 laew 的提示词回归集（本库 940+ 条）——讨论给 laew 加「随机任务生成器」（按维度 × 难度组合采样）+ 「双实现比对」（新旧编排器跑同任务比对结果一致性）的压力测试设施。

### CW06 赛制与排名：ACM / IOI / Codeforces

- **预期档位**: medium
- **考察维度**: 三种赛制规则 / 排名算法 / 实时榜单
- **对话脚本**:
  1. ACM/ICPC 赛制：按过题数降序、同过题数按罚时（每次失败提交 +20 分钟、过题时刻累计）升序；实现 `rank_row(team) -> (solved, penalty)` 并处理「未过的题不计罚时」；讨论罚时为什么用「提交即计」抑制盲猜乱交。
  2. IOI 赛制：每题取「历史最高分」（可反复提交）、排名按总分；Codeforces 赛制：题目分数随时间衰减（每分钟 -x 分）、错误提交 -50、最终 ranking 与 rating 更新（Elo 变体，联动 CM02 的 ELO 公式）；实现 CF 规则的得分计算函数。
  3. 实时榜单工程：比赛中榜单要「封榜」（最后一小时冻结显示最后状态但继续计分）与「滚榜」（颁奖时逐题揭晓）；设计 `leaderboard(contest_id, frozen: bool)` 的查询与「解冻重放」逻辑（按提交时间重放全部提交重建真实榜）。
  4. laew 借鉴：CF 分数衰减「先交先得」对照 Agent 任务完成度评估——讨论同一任务早完成的 SubAgent 是否应得更高权重（吞吐奖励），以及「失败提交扣分」如何映射到 SubAgent 重试的成本记账（联动 CS02 资源借贷表）。

### CW07 算法可视化：步骤录制与回放

- **预期档位**: medium~hard
- **考察维度**: 执行轨迹捕获 / 步骤回放 / 教学注释
- **对话脚本**:
  1. 排序动画的数据层：不耦合渲染——排序算法每步「swap/compare」输出事件 `Event::Compare(i,j) / Swap(i,j)` 到轨迹数组，回放器消费轨迹逐帧驱动条形图动画；改造快排与归并输出事件流并统计两种排序的事件数差异。
  2. 图算法可视化：BFS/DFS/Dijkstra 的轨迹 = 「节点入队 / 出队 / 松弛边 / 确定」事件序列 + 前驱指针快照；实现 Dijkstra 轨迹捕获并在前端（Canvas，联动 CO 维）回放「 frontier 扩散 + 最短路生长」动画，支持单步 / 倍速 / 拖动进度条。
  3. 教学注释层：关键事件附人话解说（「此时选择了更短的边 relax(v)」）——注释模板化生成（按事件类型 + 参数套模板）+ 算法作者手工覆写关键步骤；讨论「自动生成注释」与「手工标注」的分工边界。
  4. laew 借鉴：轨迹回放正是 Debug 模式的可视化升级——laew 已采集各 Agent trace（输入输出 / 耗时 / token），讨论加一个「任务回放器」：时间轴拖动查看每一步 Agent 决策与工具调用（甘特 + 消息流双视图），对排查失败回流特别有用。

### CW08 题库系统与难度校准

- **预期档位**: medium
- **考察维度**: 题目元数据 / 标签体系 / 通过率校准难度
- **对话脚本**:
  1. 题目模型：`problems(id, slug, 标题, 题面MD, 输入输出格式, 数据范围, 时间内存限制, tags, 难度分, 隐藏)` + 标签多对多（算法标签「动态规划/图论」× 数据结构标签 × 来源标签「CF Round 700」）；设计表并写「按标签 + 难度区间 + 通过状态筛选练习」的查询（联动 CT08 facets 思想）。
  2. 难度校准：人标难度主观——用「提交通过率 + 参与者水平分」回归校准（通过率 80% 且选手平均分 1200 → 实际难度 800）；实现简化版（通过率对数 + 参与者分位数加权）并讨论冷启动（新题无数据时先按人标 + 同类题插值）。
  3. 题单与推荐：按「知识点依赖图」（先学背包再学树形 DP）生成学习路径题单；给用户「能力画像 × 弱项标签」推练习题（联动 CQ 维冷启动与探索思想），写出依赖图的拓扑排序 + 薄弱标签优先的选题函数。
  4. laew 借鉴：难度校准「客观行为数据覆盖主观标注」对照 Yolo 的三档分类——档位判定也可以用「历史同类任务的实际执行结果」（回流率 / QC 通过率）在线校准标签边界，而不是纯靠提示词里的静态描述。

### CW09 判题队列与弹性伸缩

- **预期档位**: medium~hard
- **考察维度**: 消息队列削峰 / 判题机无状态化 / 自动扩缩
- **对话脚本**:
  1. 队列架构：提交高峰（比赛结束前 5 分钟）判题请求堆积——Web 层入队（Redis Stream / RabbitMQ）只返回「排队中」，判题 worker 池消费并回写结果，前端轮询 / WebSocket 推送状态；写提交入队 + worker 消费的主循环（含幂等去重：同 submission 重复入队只判一次）。
  2. 判题机无状态化：worker 不存任何状态（全部回写 DB）、按机器标记健康（心跳 + 探活判题）、坏机器自动摘除重派；讨论「判题必须的本地资源」（编译缓存可丢、测试数据按需拉取）与镜像化部署。
  3. 弹性伸缩：按队列长度扩缩容（队列 > 100 持续 1 分钟 → 起新 worker）——实现一个简单的伸缩控制器（采样队列深度 → 冷却期决策 → 起停命令），并处理缩容的优雅退出（当前判题跑完再退）。
  4. laew 借鉴：队列削峰 + 无状态 worker 对照 laew 的多会话并发——当前 laew 单进程内 Semaphore(3) 限流，讨论若做成常驻服务（多会话排队 + worker 池），`providers` 表与 session_memory 的并发访问要注意什么（SQLite WAL / 写锁粒度）。

### CW10 AI 辅助教学：错因分析与讲解生成

- **预期档位**: medium
- **考察维度**: 错因分类 / 讲解生成 / 防止直接给答案
- **对话脚本**:
  1. 错因分类树：WA 的原因自动归类——边界遗漏（哪个测试点族）/ 算法错误（输出模式分析）/ 精度问题（浮点题）/ 复杂度达标但常数大（TLE 点的 n 规模）；实现「提交 + 失败测试点的特征 → 错因标签」的规则引擎，输出给讲解生成的上下文。
  2. 讲解生成：把「题面 + 选手代码 + 错因标签 + 失败点（脱敏后 10% 片段）」喂给 LLM 生成「不直接给答案」的引导式提示（先指方向「检查 n=1 的情况」再给逐步提示阶梯）；写这个分层提示的 prompt 模板（三层：方向 → 类比 → 接近答案）。
  3. 教学闭环：错题自动入「错题本」（题 + 错因 + 三天/一周/一月复习提醒，间隔重复 SM-2 思想）；实现错题本的复习调度函数并讨论与 8 个学习曲线记忆研究的衔接。
  4. laew 借鉴：「不直接给答案的分层提示」正是 Agent 教学场景的输出形态——讨论 laew 若增加「学习模式」（用户问怎么修 bug 时不代改而是引导），Yolo 的意图识别要新增「教学意图」分支且禁用 Write 工具的编排策略。
