### CW01 判题架构与沙箱隔离

- **预期档位**: hard
- **考察维度**: 不可信代码执行 / 资源限制 / 进程组管理
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 用 Python 写一个判题沙箱脚本 `tmpPlan/agent-test/cw01/sandbox.py`：用 `resource.setrlimit` 限制 CPU 时间（`RLIMIT_CPU`）、地址空间（`RLIMIT_AS`）、输出大小（`RLIMIT_FSIZE`），用 `subprocess.run` + `timeout` 跑用户程序，捕获返回码区分 AC/WA/TLE/MLE/RE；脚本接受 `<程序> <输入文件> <超时秒数> <内存MB>` 四参数，输出一行判定结果。
  2. 用 Bash 编译一个故意死循环的 C 程序（`main.c` 里 `while(1);`），然后 `python3 sandbox.py ./a.out /dev/null 2 64`，断言输出含 `TLE` 且总耗时 < 5 秒（timeout 生效）。
  3. 再写一个 `tmpPlan/agent-test/cw01/submissions/` 下放 3 个测试 C 程序（一个 AC：读两整数输出和；一个 WA：故意输出错误答案；一个 RE：除零），用 Bash 循环跑 sandbox.py 对每题判一次，Read 结果汇总成 JSON。
  4. 最后用 Bash 断言三次判定的 JSON 结果 `status` 字段分别是 `AC`/`WA`/`RE`，全部正确则 echo PASS；用 `grep -c '\"status\":' result.json` 断言恰好 3 条记录。

### CW03 特判 spj 与交互题

- **预期档位**: hard
- **考察维度**: checker 协议 / 交互管道 / 浮点容差
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:

  2. 用 Write 构造 `tmpPlan/agent-test/cw03/graph.txt`：一个 5 节点 7 边的小图（已知 MST 权值），再构造两个选手输出：一个合法 MST（应 AC）、一个非生成树（应 WA）。

  2. 用 Write 构造 `tmpPlan/agent-test/cw04/original.py` 一个 30 行 Python 函数（如快排实现），再构造 `modified.py`：改 20% 标识符名 + 调换两行 + 加注释（应高相似）、`unrelated.py`：一个完全不同的函数（应低相似）。

### CW05 数据生成器与对拍验证

- **预期档位**: medium
- **考察维度**: 随机数据生成 / 三方对拍 / 极限构造
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 用 Python 写 `tmpPlan/agent-test/cw05/gen.py`：随机数据生成器——按输入格式生成合法测试数据（支持 `--seed` 复现、`--n` 规模参数），生成「两整数 a b，0 ≤ a,b ≤ 10^9」的输入文件。
  2. 用 Write 写两个解：`tmpPlan/agent-test/cw05/solve_correct.py`（暴力求和，一定正确）与 `tmpPlan/agent-test/cw05/solve_buggy.py`（故意在 a=b 时输出错答案）。
  3. 用 Bash 写对拍脚本：`for i in $(seq 1 20); do python3 gen.py --seed $i --n 100 > in.txt; python3 solve_correct.py < in.txt > out_correct.txt; python3 solve_buggy.py < in.txt > out_buggy.txt; diff out_correct.txt out_buggy.txt || echo "FAIL at seed $i"; done`，Read 输出应至少有一个 `FAIL`（验证对拍能抓到 bug）。
  4. 用 Bash 统计 FAIL 数 `grep -c 'FAIL' log.txt`，断言 ≥1 则 echo "PASS: 对拍抓到 buggy 解"，否则 exit 1。
