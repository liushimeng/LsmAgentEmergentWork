# 46 形式化方法与软件验证

> 编号段 AU01–AU10 · 聚焦形式化规约、模型检测、定理证明、属性测试、符号执行与软件正确性验证

### AU01 形式化方法入门：从直觉到规约
- **预期档位**: medium
- **考察维度**: 形式化基本概念 + 工程价值
- **对话脚本**:
  1. 形式化方法（Formal Methods）的本质是什么？为什么 Dijkstra 说"测试只能证明错误存在，不能证明错误不存在"？
  2. 形式化方法的两大谱系：轻量级（Model Checking / Property-Based Testing / Static Analysis）vs 重量级（Theorem Proving / Dependent Types）。
  3. 给一个银行账户系统的最小规约：用 Z notation 或 TLA+ 表达"存款 → 余额增加 → 不变量保持"。
  4. 工业界实际使用形式化方法的案例：Amazon TLA+、Microsoft SLAM/Driver Verifier、Facebook Infer、AWS S3 团队。

### AU03 模型检测：原理与局限
- **预期档位**: medium
- **考察维度**: Model Checking + 状态爆炸
- **对话脚本**:
  1. 模型检测（Model Checking）的基本原理：状态空间穷举 + 时序逻辑公式验证，画出流程图。
  2. 状态爆炸（State Explosion）问题怎么缓解？抽象（Abstraction）、偏序归约（Partial Order Reduction）、对称归约（Symmetry Reduction）三种技术的原理。
  3. 用 SPIN / NuSMV / UPPAAL 写一个简单哲学家就餐问题模型：5 个哲学家、状态数约 3^5=243、不变量检查。
  4. 模型检测的实际局限：硬件 vs 软件、有限状态 vs 无限状态、表达能力（LTL vs CTL）的 trade-off。

### AU06 静态分析：编译期的程序推理

### AU07 符号执行：KLEE / angr / Triton
- **预期档位**: hard
- **考察维度**: Symbolic Execution + 路径爆炸
- **对话脚本**:
  1. 符号执行（Symbolic Execution）的原理：用符号值代替具体输入，沿着每条路径求解约束，画出示例程序的控制流图。
  2. 用 KLEE 对一个简单 C 函数（带分支）跑符号执行：生成的测试用例数量、覆盖率、与随机测试的对比。
  3. 路径爆炸（Path Explosion）问题怎么解决？启发式搜索、状态合并、约束求解缓存三个方向。
  4. 符号执行在 CTF 与安全研究中的应用：angr 自动化的二进制逆向、漏洞自动挖掘（Driller / Mayhem）。
