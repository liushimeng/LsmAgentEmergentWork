# 50 软件架构模式与设计系统

> 编号段 AY01–AY10 · 聚焦经典架构模式（DDD/CQRS/Event Sourcing/六边形/Clean/微内核/插件化）与设计决策
> 与现有 22 维度「分布式系统与微服务架构」互补：22 偏分布式基础设施；50 偏架构模式 + 领域建模 + 决策方法论

### AY01 架构模式全景：从分层到事件驱动
- **预期档位**: medium
- **考察维度**: 架构风格谱系 + 选型决策
- **对话脚本**:
  1. 软件架构的五大范式：分层（Layered）、管道-过滤器（Pipe-Filter）、微内核（Microkernel）、事件驱动（EDA）、微服务（Microservices）的拓扑差异。
  2. 架构决策的三大驱动：业务复杂度（CRUD vs 工作流）、团队规模（3 人 vs 30 人）、变更频率（季度 vs 分钟）。
  3. 架构「反模式」清单：分布式单体、大泥球（Big Ball of Mud）、供应商锁定、无目的的微服务化。
  4. 画一个 SaaS 电商平台的架构演进：单体 → 模块化单体 → 微服务 → Serverless 四阶段的真实技术栈选择。

### AY02 领域驱动设计（DDD）：战略与战术
- **预期档位**: hard
- **考察维度**: DDD 战略设计 + 战术模式
- **对话脚本**:
  1. DDD 的核心：通用语言（Ubiquitous Language）+ 限界上下文（Bounded Context）+ 上下文映射（Context Map）。
  2. 子域（Core / Supporting / Generic）的划分方法：用业务价值 × 复杂度二维矩阵定位核心域。
  3. 战术模式：实体（Entity）、值对象（Value Object）、聚合根（Aggregate Root）、领域服务（Domain Service）、仓储（Repository）的职责边界。
  4. 真实案例：电商系统的限界上下文划分（订单/库存/支付/物流），画出 7-8 个 BC 间的集成关系（Conformist / Anti-Corruption Layer / Shared Kernel）。

### AY03 CQRS 与事件溯源（Event Sourcing）
- **预期档位**: hard
- **考察维度**: 读写分离 + 事件溯源
- **对话脚本**:
  1. CQRS（Command Query Responsibility Segregation）的本质：读写模型解耦后，写模型一致性 vs 读模型查询力的对立统一。
  2. Event Sourcing 的核心：用事件流作为唯一真实状态源，aggregate 由事件回放重建，给出订单聚合的状态机。
  3. 快照（Snapshot）机制：每隔 N 个事件持久化一次聚合状态，避免长事件流回放过慢。
  4. 真实挑战与解决：schema 演进（upcasting）、最终一致性、事件版本化、投影（Projection）失效补偿。

### AY04 六边形架构与整洁架构
- **预期档位**: medium
- **考察维度**: 端口-适配器 + 依赖倒置
- **对话脚本**:
  1. 六边形架构（Hexagonal / Ports & Adapters）的本质：业务核心与外部世界通过「端口 + 适配器」解耦，画出完整依赖图。
  2. 整洁架构（Clean Architecture）四层：Entities / Use Cases / Interface Adapters / Frameworks，依赖规则与 Robert C. Martin 的设计意图。
  3. 与「经典三层（Controller / Service / DAO）」的对比：依赖方向、可测试性、替换基础设施的成本差异。
  4. 给一个用 NestJS / Spring Boot 实现六边形架构的最小代码：业务核心不依赖任何框架，数据库通过 Repository 接口注入。

### AY05 微内核与插件化架构
- **预期档位**: medium
- **考察维度**: 核心系统 + 插件生态
- **对话脚本**:
  1. 微内核（Microkernel）架构的核心：最小化核心系统、最大化扩展点。Eclipse IDE / VS Code / Chrome 浏览器各是怎么实现的。
  2. 插件发现与加载机制：静态注册（manifest.json）、动态扫描（classpath / 文件系统约定）、远程拉取（Marketplace）。
  3. 插件沙箱（Plugin Sandbox）的实现：能力声明（Capabilities）、资源限额、生命周期管理、版本兼容性约束。
  4. 设计一个企业 CMS 的微内核：核心提供「内容存储 + 渲染框架」，插件负责「表单校验 / 富文本编辑器 / 国际化」。

### AY06 事件驱动架构（EDA）与反应式系统
- **预期档位**: medium
- **考察维度**: 事件流 + 反应式
- **对话脚本**:
  1. 事件驱动的四种拓扑：发布/订阅、事件流（Kafka）、事件溯源、CQRS+ES，各自的取舍。
  2. 反应式宣言（Reactive Manifesto）的四大特性：响应（Responsive）、韧性（Resilient）、弹性（Elastic）、消息驱动（Message Driven）。
  3. 反应式编程库对比：Reactor / RxJava / Akka Streams / Mutiny / Kotlin Flow 的背压模型与编排能力。
  4. 写一个反应式微服务：Spring WebFlux + R2DBC 的非阻塞数据库访问，连接数从 200 降到 30 的实测收益。

### AY07 API 设计：REST / GraphQL / gRPC 选型
- **预期档位**: medium
- **考察维度**: API 范式 + 协议选型
- **对话脚本**:
  1. REST 的成熟约定：资源建模 + HTTP 动词 + HATEOAS，但实际工程中 HATEOAS 极少被完整实现的原因。
  2. GraphQL 的双刃剑：精确查询 vs N+1 查询复杂度问题，DataLoader 模式如何分批去重。
  3. gRPC + Protocol Buffers 的优势：强类型、HTTP/2 多路复用、流式调用，但浏览器直接调用的不友好与生态桥接（grpc-web / Connect）。
  4. 实际选型决策：内部服务通信（gRPC）、对外开放 API（REST）、移动端多场景聚合（GraphQL）的混合架构设计。

### AY08 架构决策记录（ADR）与权衡分析
- **预期档位**: simple
- **考察维度**: 架构决策文档化
- **对话脚本**:
  1. ADR（Architecture Decision Record）是什么？为什么 Michael Nygard 强调「记录为什么而不是什么」。
  2. ADR 的标准模板：Context / Decision / Status / Consequences，给一个真实决策示例（数据库选型 PostgreSQL）。
  3. MADR / Log4brains / adr-tools 三种 ADR 工具链的对比：Markdown 文件 vs Wiki 系统 vs Git 集成的不同适用场景。
  4. 决策反例：当 ADR 与代码严重脱节，怎么做定期审查与重审？给一份季度架构复盘的会议模板。

### AY09 架构演进与可演化性
- **预期档位**: hard
- **考察维度**: 可演化架构 + 重构路径
- **对话脚本**:
  1. 「构建可演化架构」的三大支柱：模块化、可监控、可实验，怎么把它们内建到系统设计中。
  2. 模块化单体（Modular Monolith）：单一部署单元但内部严格分模块，作为微服务化的中间形态的真实价值。
  3. 演进路径：从单体到模块化单体到微服务的三步走，判断「何时值得走第二步」的三个信号（构建时间、团队冲突、部署瓶颈）。
  4. 给一个 SaaS 产品的 3 年架构蓝图，画出季度里程碑、技术债偿还节奏、关键风险与回退方案。

### AY10 架构评估方法：ATAM 与 SAAM
- **预期档位**: medium
- **考察维度**: 架构质量评估 + 风险识别
- **对话脚本**:
  1. 软件架构质量属性：可用性、可修改性、性能、安全性、可测试性、可部署性的精准定义与衡量指标。
  2. ATAM（Architecture Tradeoff Analysis Method）的九步流程：场景提炼 → 架构分析 → 风险识别 → 折中点列表。
  3. SAAM（Software Architecture Analysis Method）与 ATAM 的差异：SAAM 偏场景驱动的轻量评估，ATAM 偏多质量属性的深度权衡。
  4. 实战演练：对一个「在线考试系统」做 ATAM 评估，列出 5 个关键场景、3 个风险点、2 个折中决策。
