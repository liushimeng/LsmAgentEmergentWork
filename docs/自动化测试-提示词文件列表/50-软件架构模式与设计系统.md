# 自动化测试提示词 — 软件架构模式与设计系统（AY01–AY10）

> 使用说明:聚焦经典架构模式（DDD/CQRS/Event Sourcing/六边形/Clean/微内核/插件化）与设计决策;通过动手写 mini 复刻、运行验证、产物对照来考察 laew Agent 能力（产物落盘 → 命令验证 → 多轮迭代）,不靠堆砌名词与口头讲解。

## 维度说明
考察 laew 把架构概念落成可验证代码与可执行文档的能力:概念→写最小可运行示例(Write)→运行/断言(Bash)→产物回归(Read+Bash);CQRS/事件溯源写 mini 复刻并断言「重放结果=增量结果」,ADR/插件化产文档并用脚本核对每条必备字段。

### AY03 CQRS 与事件溯源(Event Sourcing)
- **测试状态**: 🔄 待重测（2026-09-11 脚本重写）
- **预期档位**: hard
- **考察维度**: 事件存储+投影重放 / 重放等价断言
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/es/bank.py` 用 Python 写一个最小事件存储:append-only `events: list` + `apply(state, event)` 纯函数;支持 `AccountCreated/Deposited/Withdrawn` 三类事件。
  2. `Write` 一段 5 条事件的「增量」脚本 `demo_inc.py`:依次 append 5 条事件后打印当前余额,`Bash` 跑出基准值(假设存款 100/50/30,取款 20,余额 160)。
  3. `Write` 一段「重放」脚本 `demo_replay.py`:清空 state、从空余额开始只调用 `apply` 遍历同一批事件,`Bash` 跑得余额必须等于 demo_inc 的基准值。
  4. `Bash` 跑 `diff <(python3 demo_inc.py | tail -n 1) <(python3 demo_replay.py | tail -n 1)`,空 diff 证明「重放结果等于增量结果」,非空则修正事件定义并重跑直到一致;再加 snapshot 测试:append 1000 条事件后存快照,从快照+后续事件重放,断言最终余额正确且耗时 < 重放 1000 条的 50%。
