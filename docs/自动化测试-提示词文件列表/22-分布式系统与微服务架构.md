# 自动化测试提示词 — 分布式系统与微服务架构（V01–V10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**单进程多协程（python `threading`/`asyncio`）模拟节点通信**前提下，把"服务注册与健康检查 / 负载均衡 / 2PC 与 Saga 事务 / 文件队列 / Raft 选举与日志复制 / 一致性哈希缓存 / 服务网格金丝雀 / 熔断限流 / 分布式追踪 Context 传递 / Event Sourcing + CQRS"等分布式任务，做成可 Read 可 Bash 的真实可执行产物——Bash 断言、多轮修复闭环、无外网无真集群。

### V01 服务注册与健康检查：单进程模拟 etcd 注册中心
- **预期档位**: medium
- **考察维度**: 注册中心 / 心跳 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v01/` 下写 `registry.py`：单进程 `threading` 模拟 etcd，暴露 `POST /register {name, addr, ttl}`、`POST /renew {name}`、`GET /services`（只返回未过期的）；每条注册带 `expires_at = time.time() + ttl`，过期自动删除；后台起在 21001。
  2. 写 `verify_basic.sh`：`curl -sf -XPOST http://127.0.0.1:21001/register -H 'content-type: application/json' -d '{"name":"svc-a","addr":"1.2.3.4:80","ttl":5}'` → `curl -sf http://127.0.0.1:21001/services | tee out.json`，`jq -e '.[] | select(.name=="svc-a")'` 必须通过；等 6 秒不 renew，`curl` 再查，期望列表变空（`jq -e 'length == 0'` 通过）。
  3. 加心跳续约 `heartbeat.py`：每 1 秒调一次 `/renew`；`verify_ttl.sh`：起 registry + 起 heartbeat，等 15 秒，期间 `curl -sf http://127.0.0.1:21001/services | jq -e '.[] | select(.name=="svc-a")'` 应持续命中，一旦断链马上 fail。
  4. 写 `verify_dead.sh`：起 registry + 注册 svc-a（ttl 3）后**不**起 heartbeat → sleep 4 → 应过期；故意在 `registry.py` 把 `time.time()` 写错（用 `ttl` 直接当 expires）时，等 6 秒仍不过期，暴露 bug 后请 Read `registry.py` 修 expires_at 重跑。最后 `kill` 进程。

### V02 负载均衡器：轮询 + 一致性哈希 + 健康感知
- **预期档位**: medium
- **考察维度**: 路由算法 / 健康检查 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v02/` 下写 `balancer.py`（127.0.0.1:21101）：后端池含 3 个 `{"host":"127.0.0.1","port":21102..21104}`，提供 `/route` 接口返回 `{"target":...}`，先实现轮询（`self._idx = (self._idx+1) % len(pool)`）。
  2. 跑 `verify_round_robin.sh`：连发 6 次 `curl -sf http://127.0.0.1:21101/route | jq -r .target`，期望出现 3 个不同 target、且第 1 次与第 4 次 target 相同（周期 3）；用 `sort | uniq -c` 验证每个 target 出现 2 次。
  3. 加一致性哈希：`route` 接 `?key=foo` 用 python `hashlib.md5(key).hexdigest()` 哈希环（每个 backend 3 个虚拟节点）选 backend；`verify_consistent.sh`：`for k in foo bar baz; do curl -sf "http://127.0.0.1:21101/route?key=$k" | jq -r .target; done | sort | uniq -c`，断言同一个 key 每次请求都落在同一 backend（多次 curl 同一 key 全相等）。
  4. 加健康检查：`balancer.py` 每 2 秒探一次 `GET /health` 后端，连续 2 次失败从池移除；写一个后端 `backend.py` 启动后 5 秒自己死掉，`verify_health.sh`：前 4 秒 3 个 backend 都参与轮询，5 秒后只剩 2 个（`grep -c 'target' out.out` 数不同 target 数 = 2）。

  2. 写 `verify_success.sh`：三个 `do` 都成功 → `saga.run()` 返回 `"order_created"` 且执行顺序日志 `out.log` 含 `deduct_stock,deduct_ok,charge_wallet,charge_ok,create_order,create_ok`（`grep -F` 命中）。

  4. 加幂等与悬挂防护：同一订单第二次跑 `place_order` 时 `deduct_stock` 发现已扣过应跳过；`verify_idempotent.sh`：跑两次 `saga.run()`，`out.log` 里 `deduct_stock` 只应出现 1 次（`grep -c 'deduct_stock'` = 1）；失败请 Read `saga.py` 加 step 状态机（`started/done/compensated`）重跑。

### V04 消息队列：基于本地文件的 FIFO 队列
- **预期档位**: medium
- **考察维度**: FIFO / 持久化 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v04/` 下写 `queue.py`：用 `queue/` 目录实现 FIFO——`enqueue(item)` 写 `queue/msg_<ts>_<seq>.json`，`dequeue()` 按文件名排序取最早一条、读后 `os.remove`；多生产者用 `threading.Lock` 保护 `seq`。后台起消费者 `python consumer.py &`。
  2. 写 `verify_basic.sh`：`python producer.py --n 20`（20 条 "msg-<i>"） → 跑完后 `ls queue/ | wc -l` 应逐步降到 0；sleep 5 后 `grep -c 'consumed' out.log` ≥20，且消息按文件名顺序消费（`grep consumed out.log | awk '{print $2}'` 单调不减）。
  3. 加"至少一次"语义：`dequeue` 失败（中途 kill consumer）应能在重启后重消费；`verify_atleastonce.sh`：起 producer 发 10 条 → 起 consumer 跑 3 秒 kill → 再起 consumer 继续 → `grep -c consumed out.log` 应 ≥10；加"手动 ACK"：`dequeue` 把文件移到 `queue/ack/`，`os.rename` 后才算消费。
  4. 加崩溃恢复：`consumer.py` 故意第 7 条消息 `raise`，应自动把该条移到 `queue/dead/` 继续消费；`verify_crash.sh`：发 10 条，consumer 重启 3 次后 `queue/ack/` 与 `queue/dead/` 条目数之和 = 10，`queue/` 原目录条目数 = 0；失败请 Read `consumer.py` 加重试/死信重跑。

### V05 Raft 协议：单进程多线程领导者选举
- **预期档位**: hard
- **考察维度**: 选举 / 任期 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v05/` 下写 `raft.py`：`Node` 三态 `follower/candidate/leader`，`term` 自增、`heartbeat_timeout` 随机 0.3~0.6 秒，`request_vote` RPC 由 `threading` 模拟（简单函数调用）；单进程起 5 个 Node 线程。后台起 `python raft.py` 日志写到 `raft.log`。
  2. 写 `verify_election.sh`：`sleep 3; grep -c 'became leader' raft.log` 应 ≥1；同一 term 下应只有 1 个 leader（`grep 'term' raft.log | awk '{print $2}' | sort | uniq -c` 某 term 对应 leader 行数 = 1）；若出现同 term 多 leader 请 Read `raft.py` 修 request_vote 规则（每个 term 每个节点只投一票）重跑。
  3. 加日志复制：leader 收到客户端 `command` 时把 `log.append({term, command})`、`nextIndex` 跟踪每个 follower 进度、`commitIndex` 过半更新；`verify_replicate.sh`：leader 收 5 条 command，sleep 2 → 所有 follower `log length == 5`（`grep 'log_len' raft.log` 全部 5）。
  4. 加 leader 宕机：`verify_failover.sh`：raft 稳定后 `kill` 当前 leader 线程 → 新 leader 在 ≤2 秒内产生（`grep -c 'became leader' raft.log` 从 1 变 2）；故意把 `heartbeat_timeout` 改成无随机（相同值）跑，应出现"活锁分裂"（`grep -c 'split vote' raft.log` ≥1），加回 jitter 后分裂次数归零。

### V06 分布式缓存：一致性哈希 + 虚拟节点 + 防雪崩
- **预期档位**: medium
- **考察维度**: 哈希环 / 虚拟节点 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v06/` 下写 `cache.py`：实现 `ConsistentHashRing`，每个 backend 加 150 个虚拟节点（`md5(backend+":"+vn)`）；`get_node(key)` 在环上顺时针找最近虚拟节点；起一个带 `expire` 的 `Cache` 类（`data[key]=(value, expires_at)`）。
  2. 跑 `verify_ring.sh`：100 个 key 用 `python -c` 调 `get_node` 统计分布，期望 3 个 backend 各分得 ≥20 个、≤45 个（均匀）；`sort | uniq -c` 断言最大值 - 最小值 ≤ 25。
  3. 加"缩容再平衡"：`verify_rehash.sh`：4 个 backend 加 150 vnode，统计 key→backend 映射，**移除 1 个 backend** 后重新统计，期望迁移率（映射变动的 key / 总 key）在 15%~30% 之间；过低（<10%）说明 vnode 数不够，过高（>50%）说明哈希环有 bug。
  4. 加缓存雪崩防护：`set(key, value, ttl, jitter=True)` 加 ±10% 随机抖动；`verify_jitter.sh`：对同一 key 连续 `set` 100 次（ttl=100），用 `python -c "..."` 收集每次 ttl，标准差应 ≥1（有抖动）；把 `jitter=False` 后标准差应为 0，对比验证抖动生效。

### V07 服务网格金丝雀：单进程模拟 Envoy 权重路由
- **预期档位**: medium
- **考察维度**: 权重路由 / 灰度 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v07/` 下写 `gateway.py`：后端池含 `v1`(权重 95) `v2`(权重 5)，`route()` 用 `random.randint(1,100)` 按累积权重选版本；起 127.0.0.1:21401 后台，日志 `route.log` 每条 `{ts, version, latency_ms}`。
  2. 写 `verify_weight.sh`：`for _ in $(seq 1 1000); do curl -sf http://127.0.0.1:21401/route; done > out.out`，`grep -c 'v1' out.out` ∈ [920, 980]、`grep -c 'v2' out.out` ∈ [20, 80]（5%±3% 容忍）；若不在此区间请 Read `gateway.py` 修权重算法重跑。
  3. 加"渐进放量"：`promote(target_pct, steps=5, interval=1)` 每 1 秒把 v2 权重 +`(target_pct - current_pct)/steps`；跑 `verify_promote.sh`：从 5% 提到 50%，每步末尾 curl 100 次测 v2 占比，用 `awk` 验证占比单调不减且末步接近 50%。
  4. 加"错误率回滚"：`monitor.py` 每 2 秒读 `route.log` 统计 v2 最近 50 次请求的错误率（从响应里读 "error" 字样），若 ≥10% 立即把 v2 权重回滚到 5%；`verify_rollback.sh`：故意让 v2 后端返回 30% 错误，起 `monitor.py` 后 `grep -c 'rollback' route.log` 应 ≥1，`grep -c 'weight 5%' route.log` 也应 ≥1。

### V09 分布式追踪：W3C traceparent 上下文传递
- **预期档位**: medium
- **考察维度**: 上下文传递 / Span / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/v09/` 下写 `trace.py`：实现 `Span(trace_id, span_id, parent_id, op, start_ns, end_ns)`，`Tracer.start_span(op)` 生成 16 字节随机 trace_id、8 字节 span_id；W3C `traceparent = "00-<trace32hex>-<span16hex>-01"` 解析/生成。
  2. 写 `verify_format.sh`：`python -c "from trace import Tracer; s=Tracer().start_span('op'); print(s.traceparent)" | tee tp.out`，`awk -F'-' 'NF==4 && length($2)==32 && length($3)==16 && $1=="00" && $4=="01"' tp.out` 必须通过；故意构造错格式，`Tracer.parse("00-xyz-bad-01")` 应抛 ValueError。
  3. 加"服务间传递"：`svc_a.py` 127.0.0.1:21501 收到请求时解析 `traceparent` 头、`start_span`、再调 `svc_b.py`（21502）注入新的 `traceparent`；`verify_propagate.sh`：`curl -sf -H "traceparent: $(cat tp.out)" http://127.0.0.1:21501/work | jq -e '.trace_id == $(cut -d- -f2 tp.out)'` 必须通过（trace_id 跨服务一致）。
  4. 加"采样决策"：`sampler.py` 按 trace_id 后 8 字节对 10000 取模，≤ `sample_rate*10000` 才采样；`verify_sample.sh`：起 `svc_a` 连续发 1000 次，统计 `sampled` 比例应在 `sample_rate ± 3%` 内；若比例超差请 Read `sampler.py` 修取模逻辑重跑。

### V10 Event Sourcing + CQRS：银行账户聚合
- **预期档位**: hard

- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:

  2. 跑 `verify_events.sh`：跑 `python -c "..."` 依次 apply Open(1)→Deposit(100)→Withdraw(30)→Deposit(50)，最终 `account.balance == 120`，`grep -c 'Deposited' events.jsonl` = 2，`grep -c 'Withdrawn'` = 1。
