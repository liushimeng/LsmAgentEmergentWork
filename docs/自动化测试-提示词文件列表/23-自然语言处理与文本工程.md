### W01 中文分词：手写最大匹配 + 词典
- **预期档位**: medium
- **考察维度**: 分词算法 / 词典 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/w01/` 下写 `dict.txt`（至少 50 个词，含 "大语言模型/人工智能/自然语言处理/研究/生命/起源" 这类测试串）和 `seg.py`：实现**前向最大匹配** `fmm(text, dict_set, max_len=5)` 切词；入口 `echo "研究生命的起源" | python seg.py` 应输出 `研究/生命/的/起源`（或合理切分）。
  2. 跑 `echo "研究生命的起源" | python seg.py | tr '/' '\n' | tee out.out`，`wc -l out.out` 必须 ≥3；`grep -c '研究\|生命\|起源' out.out` 应 ≥2；故意改 `max_len=1` 跑，期望每字都切——`wc -l out.out` 等于 `len("研究生命的起源")=7`；还原 `max_len=5` 后应恢复短语。

  4. 写 `verify.sh`：跑 3 个测试串（基础/领域/歧义如"使用户满意"），每串断言切分后词数与期望相等；任意一串不符 exit 1 并打印期望 vs 实际；通过写 `OK` 到 `final.out`。

### W03 TF-IDF 新闻分类器：纯 python 实现

- **考察维度**: TF-IDF / 朴素贝叶斯 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/w03/` 下写 `gen_data.py` 生成 `data.jsonl`（3 类 × 100 条，每类含强特征词，如"科技"类含"芯片/AI/量子"，"体育"类含"进球/冠军"，"财经"类含"股市/央行"）；写 `tfidf.py` 实现 `Tokenizer`（分词按空格或按单字）、`TFIDFVectorizer`（`tf=count/total, idf=log(N/df)`）、`NaiveBayesClassifier`（拉普拉斯平滑 `alpha=1`）。
  2. 跑 `python train.py --data data.jsonl --model model.pkl`，期望 stdout 含 "train_acc >= 0.85"（因特征词强，准确率应较高）；故意把强特征词从 gen_data.py 删掉（让三类共享同义词），期望 train_acc 掉到 <0.7，记录 `weak.out`。

  4. 加"单条预测"：`python predict.py "科学家发现新型芯片"` 应输出 `科技`，`python predict.py "球队夺冠"` 输出 `体育`；`verify_predict.sh`：两行都对才 exit 0，否则 exit 1；任意误判请 Read `tfidf.py` 修平滑参数或特征词权重。

### W06 文本相似度：TF-IDF 余弦 + 欧氏距离对比
- **预期档位**: medium

- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:

### W07 BLEU 评估：手写 n-gram 精度 + 简短惩罚
- **预期档位**: medium

- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/w07/` 下写 `bleu.py`：实现 `sentence_bleu(ref, hyp, max_n=4)` = `BP * exp(sum(w_n * log(p_n)))`，`BP = min(1, exp(1 - ref_len/hyp_len))`，n-gram 计数 `clip(min(count, ref_count))`；写 `test_bleu.py` 跑 6 组（完美翻译/全错/简短惩罚/部分匹配/单字/空字符串）。
  2. 跑 `cd tmpPlan/agent-test/w07 && python -m unittest test_bleu -v 2>&1 | tee run.out`，期望 `OK Ran 6 tests`；"完美翻译"bleu==1.0、"全错"bleu==0.0、"简短惩罚"bleu < 匹配但不为 0。

### W09 模型推理加速：numpy 模拟 KV Cache 加速 Decode
- **预期档位**: medium
- **考察维度**: KV Cache / 量化 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/w09/` 下写 `llm_sim.py`：用 numpy 模拟一个"玩具 LLM"——`prefill(seq)` 把输入 seq 编码成 `KV[seq_len, d]`（`d=64`），`decode_step(KV, x)` 用 softmax attention + 线性层生成下个 token logits；无 cache 版每步重算全量 KV，有 cache 版只 append 新 token 的 KV。
  2. 跑 `python bench.py --len 200 --steps 50 | tee bench.out`，期望 `cache_time < no_cache_time * 0.5`（cache 至少快 2 倍）；故意把 cache 版的 `KV.append` 写成"覆盖首行"，期望 cache_time 反超 no_cache_time 或结果错，记录 bug。
  3. 加 INT8 量化：`quantize(w)` 用 `scale=max(|w|)/127`，`dq=clip(round(w/scale))*scale`，decode 用 `dq` 替代 `w`；`verify_quant.sh`：量化前后输出 token 序列的匹配率应 ≥ 70%（`grep` 统计）。
  4. 写 `verify.sh`：跑 3 步（cache 加速/量化保真/崩溃兜底），结果写 `result.json`，`jq -e '.cache_speedup >= 2 and .quant_match >= 0.7 and .no_crash == true'` 通过；失败请 Read `llm_sim.py` 修 cache 或量化边界重跑。
