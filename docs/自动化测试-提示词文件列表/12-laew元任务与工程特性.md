# 自动化测试提示词 — laew 元任务与工程特性（L01–L10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**自测试、工程特性验证、元任务**等场景中的表现，
涵盖 laew 自身功能测试、多 Agent 编排验证、上下文压缩、协议切换、
TUI 自动化、调试模式、记忆系统、错误恢复、配置管理、版本升级等主题。

---

### L01 laew 自测试：跑通 e2e
- **测试状态**: ✅ 已测试 (L01_q1.md, 通过 — mock 链路 Yolo→SubAgent→QC→SessionContext 完整跑通,详见 `tmpPlan/2026-09-10_03-D03-L01-测试与按钮显示Bug修复方案.md`)
- **预期档位**: medium
- **考察维度**: 工程自验证能力
- **对话脚本**:
  1. 读 `testReport/run_e2e.sh`，总结它包含哪几节测试、每节验证什么。

  4. 讨论：e2e 测试的 mock LLM 是怎么工作的？如果要新增一个测试用例，应该改哪里？

### L03 上下文压缩触发
- **预期档位**: hard
- **考察维度**: Compact Agent 自动触发
- **对话脚本**:
  1. 解释 laew 的上下文压缩机制：什么时候触发、三档压缩率怎么选。
  2. 构造一个长对话场景（连续 20 轮技术讨论），观察上下文 token 估算值。
  3. 当估算值接近 `context_max_size` 的 80% 时，Compact Agent 是否自动触发？
  4. 验证压缩后的上下文是否保留了"保护带"内容（项目上下文、历史摘要、最近 4 条消息）。

### L04 协议切换验证
- **预期档位**: medium
- **考察维度**: Anthropic ↔ OpenAI 切换
- **对话脚本**:
  1. 用 `/provider add` 添加一个 OpenAI 兼容的接入记录（可用 mock endpoint）。
  2. 用 `/provider use` 切换到新接入记录，观察客户端是否重建。
  3. 发一条简单消息，验证请求是否走了 OpenAI 协议格式（`chat/completions` 端点）。
  4. 切回 Anthropic 协议，讨论两种协议在 wire 格式上的关键差异。

### L05 TUI 子屏自动化
- **预期档位**: medium
- **考察维度**: tmux 自动化测试
- **对话脚本**:
  1. 读 `docs/TUI自动化测试/` 文档，总结 tmux control-mode 的测试原理。
  2. 写一段脚本：启动 laew TUI → 进入 `/provider list` 子屏 → 抓取面板 → 断言标题。
  3. 按 `Esc` 退回主屏，再进入 `/provider add`，验证 Tab 切换是否正常。
  4. 讨论：为什么子屏测试必须用 tmux 而不能用管道？atty 分流的原理是什么？

### L06 Debug 模式与报告
- **预期档位**: hard
- **考察维度**: Debug Agent 评估能力
- **对话脚本**:
  1. 用 `./laew -debug -p "实现一个简单的计算器功能"` 启动调试模式。
  2. 任务结束后，检查 `DebugReport/` 目录下是否生成了报告文件。
  3. 读报告内容，验证是否包含"任务评估/质量报告/问题报告/优化建议"四章节。
  4. 讨论 Debug Agent 的 trace 采集机制：它怎么拿到各 Agent 的输入输出？

### L07 SessionContext 记忆系统
- **预期档位**: medium
- **考察维度**: 跨任务记忆注入
- **对话脚本**:
  1. 完成一个简单任务（如"解释什么是 Agent"），观察 SessionContext 是否生成摘要。
  2. 用 sqlite3 查看 `session_memory` 表，确认摘要是否写入。
  3. 开一个新 Session，发一条相关任务（如"基于上次讨论，深入讲 Agent 架构"），验证历史摘要是否被注入。
  4. 讨论：`<<<LAEW:SESSION_HISTORY>>>` 标记的作用是什么？为什么要隔离？

### L08 错误恢复与溢出处理
- **预期档位**: hard
- **考察维度**: 三级恢复机制
- **对话脚本**:
  1. 读 `src/agent/overflow.rs`，总结"排水/折叠/暴露"三级恢复的触发条件。
  2. 构造一个会触发"prompt is too long"的场景（如超大 tool_result），观察恢复流程。
  3. 验证恢复后的请求是否能正常完成，还是最终暴露错误给用户。
  4. 讨论：4 次恢复预算用完后，系统行为是什么？用户看到什么提示？

### L09 配置管理与迁移
- **预期档位**: medium
- **考察维度**: SQLite 迁移 + 配置兼容
- **对话脚本**:
  1. 模拟一个旧版 laew 数据库（缺少某个字段），打开新版 laew 观察迁移是否自动执行。
  2. 用 sqlite3 检查迁移后的 schema 是否符合预期。
  3. 讨论：laew 的迁移策略是"打开时自动迁移"还是"显式迁移命令"？各自的优劣？
  4. 如果要回滚一个迁移（如新增的列有问题），应该怎么设计回滚机制？

### L10 版本升级与兼容性
- **预期档位**: medium
- **考察维度**: 升级流程 + 兼容性保证
- **对话脚本**:
  1. 读 `build.rs`，总结 `--version` 输出了哪些信息（版本号/编译时间/git hash）。
  2. 设计一个"从 0.1.x 升级到 0.2.0"的用户指南：哪些兼容、哪些不兼容、怎么迁移。
  3. 讨论：语义化版本（semver）在 laew 中怎么应用？什么情况下该升 major？
  4. 如果要实现"自动检查更新"功能，设计一个最小方案（检查频率/提示方式/更新命令）。
