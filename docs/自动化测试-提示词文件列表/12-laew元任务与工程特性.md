# 自动化测试提示词 — laew 元任务与工程特性（L01–L10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在 **laew 元任务（用 laew 测 laew）和工程特性验证**等方面的表现，
涵盖 laew 架构理解、多 Agent 编排、Yolo 分类、Context 压缩、Provider 管理、
Session 记忆、Debug 模式、TUI 交互等 laew 特有功能。

---

### L01 laew 架构解读
- **预期档位**: medium
- **考察维度**: 源码阅读 + 架构理解
- **对话脚本**:
  1. 读 `src/agent/orchestrator.rs`，总结 MultiAgentOrchestrator 的编排流程。
  2. 六 Agent 角色各持有什么工具？它们的协作关系是怎样的？
  3. 如果新增一个 Agent 类型，需要改动哪些文件？列出改动清单。
  4. 把架构解读保存到 `tmpPlan/laew架构解读.md`。

### L02 Yolo 分类验证
- **预期档位**: medium
- **考察维度**: 三档分类机制验证
- **对话脚本**:
  1. 读 `src/agent/yolo.rs`，解释 Yolo 的任务分类逻辑（simple/medium/hard）。
  2. 给出 5 个输入示例，预测它们的分类结果，并说明理由。
  3. 实际测试这 5 个输入，验证分类是否符合预期。
  4. 如果分类不符合预期，分析可能的原因。

### L03 Context 压缩机制
- **预期档位**: medium
- **考察维度**: 上下文管理 + 压缩策略
- **对话脚本**:
  1. 读 `src/agent/compact.rs`，解释 Compact Agent 的三档压缩策略。
  2. 什么情况下会触发自动压缩？阈值是多少？
  3. 压缩时哪些内容会被保护（不被压缩）？
  4. 如何验证压缩后的上下文仍然保持关键信息？

### L04 Provider 管理操作
- **预期档位**: simple
- **考察维度**: 配置管理 + TUI 交互
- **对话脚本**:
  1. 用 TUI 的 `/provider add` 添加一个新的 Anthropic 接入记录。
  2. 切换到新添加的 Provider，验证切换是否成功。
  3. 列出所有 Provider，确认新记录在列表中。
  4. 删除测试用的 Provider，清理现场。

### L05 Session 记忆验证
- **预期档位**: medium
- **考察维度**: 记忆系统 + 跨 Session 复用
- **对话脚本**:
  1. 在第一个 Session 中讨论一个话题（如"我喜欢用 Vim"），然后 `/new` 开新 Session。
  2. 在新 Session 中问"我喜欢用什么编辑器"，验证 SessionContext 是否注入了历史摘要。
  3. 查看 `session_memory` 表，确认摘要是否正确写入。
  4. 讨论 SessionContext 摘要的格式和注入时机。

### L06 Debug 模式体验
- **预期档位**: medium
- **考察维度**: 调试功能 + 报告生成
- **对话脚本**:
  1. 用 `-debug` 模式运行一个简单任务，观察 Debug Agent 的 trace 采集。
  2. 任务完成后，找到生成的 DebugReport，阅读报告内容。
  3. 报告包含哪些章节？各章节的作用是什么？
  4. 如果要新增一个 trace 采集点，应该改哪里？

### L07 TUI 斜杠命令测试
- **预期档位**: simple
- **考察维度**: TUI 交互 + 命令补全
- **对话脚本**:
  1. 在 TUI 中输入 `/help`，验证帮助信息是否正确显示。
  2. 测试命令补全：输入 `/pro` 后按 Tab，观察补全行为。
  3. 测试 `/model` 命令，验证是否显示当前模型信息。
  4. 测试 `/clear` 命令，验证是否清空对话历史并开启新 Session。

### L08 溢出恢复机制
- **预期档位**: hard
- **考察维度**: 错误处理 + 自动恢复
- **对话脚本**:
  1. 读 `src/agent/overflow.rs`，解释上下文溢出检测的三级恢复机制。
  2. 什么情况下会触发溢出恢复？有哪些 provider 错误码会被识别？
  3. 设计一个测试场景，模拟上下文溢出，观察恢复行为。
  4. 讨论溢出恢复的局限性和改进方向。

### L09 工具调用链路
- **预期档位**: medium
- **考察维度**: 工具系统 + 调用流程
- **对话脚本**:
  1. 读 `src/agent/tools/mod.rs`，总结 Tool trait 的定义和 ToolRegistry 的工作方式。
  2. Bash 工具执行一条命令，观察完整的调用链路（从 LLM 输出 tool_use 到 tool_result 回填）。
  3. 如果要新增一个工具（如 Grep），需要实现哪些步骤？
  4. 讨论工具权限控制的设计，如何防止危险命令执行。

### L10 端到端回归测试
- **预期档位**: hard
- **考察维度**: 完整工程验证
- **对话脚本**:
  1. 运行 `bash testReport/run_e2e.sh`，观察端到端测试的执行过程。
  2. 测试覆盖了哪些场景？哪些场景缺失需要补充？
  3. 如果测试失败，如何定位失败原因？
  4. 讨论如何扩展 e2e 测试，覆盖更多 laew 功能点。
