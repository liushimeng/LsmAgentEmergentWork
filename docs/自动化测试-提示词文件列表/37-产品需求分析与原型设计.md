# 37 产品需求分析与原型设计

> 编号段 AL01–AL10 · 聚焦需求分析、用户故事、原型设计与产品规划

### AL01 需求访谈：从模糊想法到清晰需求
- **预期档位**: medium
- **考察维度**: 需求挖掘 + 结构化表达
- **对话脚本**:
  1. 一个创业者说"我想做一个类似 Notion 但更简单的文档工具"，你怎么把这句话拆成可执行的需求列表？
  2. 用 5W1H 方法分析这个需求：Who（目标用户）、What（核心功能）、When（使用场景）、Where（平台）、Why（痛点）、How（实现路径）。
  3. 把这个需求写成一份 PRD 大纲：背景、目标、用户画像、功能列表、非功能需求、里程碑。
  4. 识别需求中的矛盾点："类似 Notion"（功能多）vs"更简单"（功能少），怎么平衡？给出 MVP 范围建议。

### AL02 用户故事与验收标准
- **预期档位**: medium
- **考察维度**: 用户故事 + 验收条件
- **对话脚本**:
  1. 为一个在线学习平台写 5 个用户故事：作为学生/教师/管理员三种角色，遵循"作为…我希望…以便…"格式。
  2. 为其中一个用户故事写验收标准（Given-When-Then）：至少覆盖正常路径、异常路径、边界条件。
  3. 用 INVEST 原则检查这些用户故事：Independent、Negotiable、Valuable、Estimable、Small、Testable，哪条不满足？
  4. 把这些用户故事拆成开发任务：前端、后端、测试分别需要做什么？估算工时。

### AL03 竞品分析：从对标到差异化
- **预期档位**: medium
- **考察维度**: 竞品研究 + 定位策略
- **对话脚本**:
  1. 选一个你熟悉的产品（如 Figma），找出它的 3 个直接竞品和 2 个间接竞品，画出竞争矩阵。
  2. 从功能、定价、目标用户、技术架构四个维度对比这些竞品，写一份竞品分析报告。
  3. 找出 Figma 的一个未被满足的需求或痛点，提出你的差异化功能点。
  4. 用 SWOT 分析评估你这个差异化方向：优势、劣势、机会、威胁分别是什么？

### AL04 信息架构与导航设计
- **预期档位**: medium
- **考察维度**: IA 设计 + 导航模式
- **对话脚本**:
  1. 为一个电商 App 设计信息架构：用卡片分类法组织商品类目，画出层级结构图。
  2. 这个 App 需要支持"搜索"和"浏览"两种找商品方式，怎么在导航设计上同时满足？
  3. 移动端底部 Tab 最多放 5 个入口，如果业务需要 7 个，怎么取舍或合并？给出设计原则。
  4. 用 sitemap 工具（如 Dynomapper）或手绘方式输出完整的页面清单与跳转关系。

### AL05 原型设计：从线框到高保真
- **预期档位**: medium
- **考察维度**: 原型工具 + 交互设计
- **对话脚本**:
  1. 用 Figma 画一个登录页面的线框图（Wireframe）：标注关键元素、交互状态、响应式断点。
  2. 把线框图升级成高保真原型：配色、字体、图标、图片，遵循一个设计系统（如 Material Design）。
  3. 用 Figma 的 Prototype 功能给登录流程加交互：输入校验、加载状态、成功/失败跳转。
  4. 对比 Figma、Sketch、Axure、墨刀四款原型工具在协作、保真度、学习曲线上的差异。

### AL06 用户流程与体验地图
- **预期档位**: medium
- **考察维度**: 流程设计 + 体验度量
- **对话脚本**:
  1. 为一个外卖 App 画用户从"打开 App"到"收到外卖"的完整流程图：包括异常分支（退款、催单、投诉）。
  2. 用用户体验地图（Experience Map）标注每个接触点的情绪曲线：高峰、低谷、痛点。
  3. 找出情绪曲线最低的两个点，提出改进方案并重新绘制改进后的曲线。
  4. 怎么度量改进效果？设计一个包含任务完成率、耗时、NPS 的评估方案。

### AL07 数据驱动产品：指标体系设计
- **预期档位**: medium
- **考察维度**: 指标建模 + A/B 测试
- **对话脚本**:
  1. 为一个内容社区设计 AARRR 指标体系：Acquisition、Activation、Retention、Revenue、Referral 各举 2 个指标。
  2. 定义"激活（Activation）"这个模糊概念：什么行为算激活？怎么设定阈值（如"发布第一条内容"）？
  3. 设计一个 A/B 测试：验证"首页推荐算法改版"对用户停留时间的影响，写出假设、指标、样本量计算。
  4. 这个 A/B 测试跑了 7 天，实验组停留时间提升 5% 但 p=0.08，你怎么决策？

### AL08 需求评审与优先级排序
- **预期档位**: medium
- **考察维度**: 优先级框架 + 利益相关者管理
- **对话脚本**:
  1. 用 RICE 框架（Reach、Impact、Confidence、Effort）对 10 个需求排序，给出评分过程。
  2. 用 MoSCoW 方法（Must/Should/Could/Won't）重新排序，对比与 RICE 的差异。
  3. CEO 要求一个"Must"需求，但技术评估认为成本极高且价值不确定，怎么沟通？
  4. 画一个价值-复杂度四象限图：把所有需求落到图上，解释每个象限的处理策略。

### AL09 产品路线图：从愿景到迭代
- **预期档位**: medium
- **考察维度**: 路线图规划 + 里程碑管理
- **对话脚本**:
  1. 为一个新成立的 SaaS 产品写一年路线图：Q1-Q4 的主题、关键里程碑、交付物。
  2. 路线图里的"主题"和"功能"有什么区别？为什么推荐按主题而非功能列表来组织？
  3. 中期市场变化（如竞品发布新功能），怎么调整路线图？给出变更管理流程。
  4. 用 Notion、Linear 或 Productboard 之一管理这个路线图，说明工具选型的理由。

### AL10 设计思维工作坊：从同理心到原型
- **预期档位**: medium
- **考察维度**: 设计思维 + 共创方法
- **对话脚本**:
  1. 设计一个 2 小时的设计思维工作坊流程：Empathize → Define → Ideate → Prototype → Test 每阶段的活动。
  2. Empathize 阶段：设计一份用户访谈提纲，目标是理解"远程团队的协作痛点"。
  3. Ideate 阶段：用"疯狂 8 分钟"（8 个创意 8 分钟）快速发散，怎么引导不批判？
  4. Prototype 阶段：用最低的保真度（纸面、Keynote、Figma）快速验证一个创意，说明为什么"快比好重要"。
