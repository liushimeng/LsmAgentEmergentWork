# 自动化测试提示词 — 系统编程与底层开发（U01–U10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**内存管理、线程同步、信号处理、文件系统、
系统调用、内核模块、驱动开发、零拷贝、内存映射、
锁-free 编程**等"系统级编程"场景中的实战表现，
与 E 维度（通用编码调试）和 Q 维度（趣味编程）互补：
E 考察"应用层开发"，Q 考察"特定编程范式"，
本维度考察"贴近硬件与操作系统底层的编程"。
所有主题都以"动手写系统级代码"为核心，强调底层工程能力。

---

### U01 内存管理：堆与栈的深层理解
- **预期档位**: medium
- **考察维度**: 内存布局 + 所有权 + 生命周期
- **对话脚本**:
  1. 解释 Rust 中栈（Stack）和堆（Heap）的区别：哪些数据在栈上、哪些在堆上、函数调用时栈帧怎么变化。
  2. 用代码示例说明 `Box<T>`、`Rc<T>`、`Arc<T>` 分别在堆上分配什么，引用计数存在哪里。
  3. 实现一个自定义分配器（`#[global_allocator]`）：统计所有堆分配的次数和总字节数，在程序退出时打印。
  4. 讨论：内存碎片（内碎片/外碎片）是怎么产生的？Rust 的所有权机制能在多大程度上缓解内存碎片？

### U2 线程同步：Mutex、RwLock 与 Condvar
- **预期档位**: hard
- **考察维度**: 并发原语 + 死锁避免 + 条件变量
- **对话脚本**:
  1. 解释 Mutex、RwLock、Condvar 三者的语义差异，各适合什么场景。
  2. 用 Rust 实现一个有界阻塞队列（BoundedBlockingQueue）：多个生产者、多个消费者，队列满时生产者阻塞，队列空时消费者阻塞。
  3. 加上超时机制：`push_timeout` 和 `pop_timeout`，超过指定时间返回错误而不是无限等待。
  4. 讨论：死锁的四个必要条件是什么？你的实现中如何破坏"循环等待"条件？

### U03 信号处理：Unix 信号与异步安全
- **预期档位**: hard
- **考察维度**: 信号处理 + 异步安全 + 优雅关闭
- **对话脚本**:
  1. 解释 Unix 信号（SIGINT/SIGTERM/SIGHUP）的用途，为什么信号处理函数里不能调用 `println!` 或 `malloc`？
  2. 用 Rust 的 `signal-hook` crate 实现一个优雅关闭：收到 SIGTERM 后，完成当前任务、刷盘、释放资源，然后退出。
  3. 加上 `SIGHUP` 处理：收到 SIGHUP 时重新加载配置文件，不中断正在运行的任务。
  4. 讨论：什么是"异步信号安全（async-signal-safe）"函数？为什么 `write()` 是安全的而 `printf()` 不是？

### U04 文件系统：inotify 与文件监控
- **预期档位**: medium
- **考察维度**: 文件事件监控 + 热加载 + 事件驱动
- **对话脚本**:
  1. 解释 Linux 的 inotify 机制：它能监控哪些事件（创建/修改/删除/移动）？和 polling 相比有什么优势？
  2. 用 Rust 的 `notify` crate 实现一个文件监控工具：监控指定目录，当 `.rs` 文件变化时自动打印变化的文件路径。
  3. 加上防抖（debounce）：短时间内多次修改只触发一次事件，避免重复处理。
  4. 讨论：inotify 的 watch descriptor 数量有上限吗？怎么查看和调整？大规模文件监控（百万级）该用什么方案？

### U05 系统调用：从 libc 到 Rust 的封装
- **预期档位**: medium
- **考察维度**: 系统调用 + FFI + 底层 API
- **对话脚本**:
  1. 什么是系统调用（syscall）？用户态到内核态的切换过程是什么？开销主要在哪？
  2. 用 Rust 的 `libc` crate 直接调用 `open`/`read`/`write`/`close` 系统调用，实现一个最小版的 `cat` 命令。
  3. 对比标准库 `std::fs::read_to_string` 和手动 syscall 的性能差异，解释为什么标准库通常更快（缓冲区）。
  4. 讨论：`io_uring` 是什么？它解决了传统异步 IO 的什么问题？Rust 有没有成熟的 `io_uring` 封装？

### U06 内存映射（mmap）：零拷贝与共享内存
- **预期档位**: hard
- **考察维度**: mmap + 零拷贝 + 进程间通信
- **对话脚本**:
  1. 解释 `mmap` 的工作原理：文件和内存怎么关联？"缺页中断"在其中扮演什么角色？
  2. 用 Rust 的 `memmap2` crate 实现一个基于 mmap 的文件读取器：读取大文件（1GB+）时不会把整个文件加载到内存。
  3. 用 mmap 实现进程间共享内存：两个进程通过同一块共享内存通信，写入端写数据，读取端读数据。
  4. 讨论：mmap 和传统 `read`/`write` 相比，在什么场景下更快？什么场景下更慢（小文件/随机访问）？

### U07 锁-free 编程：Atomic 与内存序
- **预期档位**: hard
- **考察维度**: 原子操作 + 内存序 + 无锁数据结构
- **对话脚本**:
  1. 解释 CPU 缓存一致性（MESI 协议）和"内存屏障（Memory Barrier）"的作用。
  2. 用 Rust 的 `AtomicUsize` 实现一个无锁的引用计数：对比 `Arc<T>` 的引用计数实现。
  3. 实现一个无锁的 Treiber Stack（栈结构）：用 `AtomicPtr` + CAS 操作实现 push/pop。
  4. 讨论：内存序（Ordering）的 `Relaxed`/`Acquire`/`Release`/`SeqCst` 分别是什么意思？选错了会导致什么问题？

### U08 内核模块入门：Linux Kernel Module
- **预期档位**: hard
- **考察维度**: 内核编程 + 模块加载 + 内核 API
- **对话脚本**:
  1. 解释 Linux 内核模块是什么：它和用户态程序有什么区别？为什么内核模块崩溃会导致整个系统崩溃？
  2. 用 C 写一个最简内核模块：加载时打印 "Hello, Kernel!"，卸载时打印 "Goodbye, Kernel!"。给出完整代码和 Makefile。
  3. 加上 `/proc` 接口：创建一个 `/proc/hello` 文件，用户读取时返回 "Hello from kernel!"。
  4. 讨论：Rust 写内核模块可行吗？`rust-for-linux` 项目的现状如何？和 C 写模块相比有什么优劣？

### U09 字符编码与 Unicode 处理
- **预期档位**: medium
- **考察维度**: Unicode + UTF-8 + 字符宽度
- **对话脚本**:
  1. 解释 ASCII、UTF-8、UTF-16、UTF-32 的区别，为什么 UTF-8 是 Web 的事实标准？
  2. 用 Rust 实现一个函数：计算字符串的"显示宽度"（中文字符算 2，英文算 1，emoji 算 2），处理组合字符和零宽字符。
  3. 实现 NFC/NFD 规范化：把 "é"（单个字符）和 "é"（e + 组合重音）统一为同一种形式。
  4. 讨论：为什么终端显示中文时容易错位？`unicode-width` crate 是怎么解决这个问题的？

### U10 网络编程：从 Socket 到 epoll
- **预期档位**: hard
- **考察维度**: 网络 IO + 事件驱动 + 高性能服务器
- **对话脚本**:
  1. 解释 TCP Socket 编程的基本流程：`socket()` → `bind()` → `listen()` → `accept()` → `read()`/`write()`。
  2. 用 Rust 实现一个多线程 TCP 回声服务器：每个连接一个线程，收到什么就回什么。
  3. 改写成 `epoll` 事件驱动版本（单线程处理多个连接），对比两版本的并发能力和资源消耗。
  4. 讨论：`select`/`poll`/`epoll`/`kqueue`/`IOCP` 各自的适用场景？为什么高并发服务器都用事件驱动而不是多线程？
