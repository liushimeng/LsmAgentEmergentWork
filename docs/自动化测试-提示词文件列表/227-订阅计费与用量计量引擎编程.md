>

> - `102-电商交易与营销系统编程`（CT 维）聚焦**一次性交易**（购物车/秒杀/优惠券/订单状态机）；本文件聚焦**周期性订阅**（续期/升降级折算/计量计费），订单模型的核心矛盾从"库存"变成"时间"。

  3. Read 源码，再 Bash 断言：含幂等表、含周期尾自动取消、含乐观锁版本。

### HN03 按比例计费 proration

- **预期档位**: hard
- **考察维度**: 日折算 / 升降级策略 / 残分处理
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hn03_proration.py`：折算引擎：(a) **日粒度折算**：`日单价 = 周期价 / 周期实际天数`（月有 28~31 天，**按实际天数**而非固定 30——写两种口径对比说明差异）；未用部分 credit = 剩余天数 × 日单价；(b) **立即升级**：新计划立即生效，本周期补收 `新价 - 旧价折算 credit`；**周期末生效**：只记账下周期收新价（用户友好默认）；(c) **降级**：credit 入余额账户抵扣未来账单（**不自动退款**——退款走独立流程合规要求）；(d) **decimal**：全程用 `decimal.Decimal`（float 演示 0.1+0.2 陷阱对比输出）；**残分处理**：分摊到多行时最后一行承担残分使合计精确相等（写断言：3 行分摊 100 分合计必须 = 100）；(e) 输出折算明细单（旧退/新收/净额三行）。
  2. Bash：月中升级样例断言：credit 精确到分、净额 = 新价 − credit；31 天月与 28 天月同操作折算额不同；float 陷阱演示输出 `0.30000000000000004` 字样；残分合计断言通过。
  3. Read 源码，再 Bash 断言：含 Decimal、含实际天数口径、含残分兜底行。
