### BO01 Windows PowerShell 日常：从 cmd 思维切换
- **预期档位**: simple
- **考察维度**: PowerShell 核心 cmdlet + 管道对象化
- **对话脚本**:
  1. PowerShell 与 cmd 的本质差异：cmd 是「字符串命令」逐行执行，PowerShell 是「面向对象管道」传递结构化数据；用 `Get-Process | Where-Object {$_.CPU -gt 100} | Select-Object Name, CPU` 演示对象流。
  2. 必知 cmdlet：`Get-Help`、`Get-Command`、`Set-Alias`（`ls` 实际是 `Get-ChildItem` 的别名）、`Select-String`（grep 等价）、`Get-Service`/`Start-Service` 服务管理、`Get-NetIPAddress` 网络查询、`Get-EventLog` 日志查看。
  3. 远程管理三件套：`Enter-PSSession` 远程交互、`Invoke-Command -ComputerName` 批量执行、`New-PSSession` 多会话管理；WinRM 配置（`Enable-PSRemoting -Force`）与 SSH 模式（PowerShell 7+ 原生支持 SSH 协议）。
  4. laew 的 e2e 测试在 Windows 上跑时，`testReport/run_e2e.sh` 的等价物可改成 PowerShell 脚本：用 `Start-Process` 替代 `&` 后台启动、用 `Get-Content -Wait` 替代 `tail -f` 看日志、用 `Test-Path` 替代 `[ -f path ]`。

### BO02 WSL2 工程实战：文件互访、网络与性能
- **预期档位**: medium
- **考察维度**: WSL2 架构 + 跨系统互通
- **对话脚本**:
  1. WSL1 vs WSL2 的本质差异：WSL1 是微软自研的 Linux syscall 翻译层（兼容慢、文件 IO 快），WSL2 是真实 Hyper-V 虚拟机跑完整 Linux 内核（IO 慢但 100% 兼容）。什么时候选哪个？
  2. 文件互访的「性能坑」：从 Windows 访问 `\\wsl$\Ubuntu\home\user` 极慢（NTFS 与 ext4 跨文件系统），工程上推荐「代码放 Linux 文件系统，IDE 在 Windows 打开远程项目」（VSCode Remote-WSL、JetBrains Gateway）。
  3. 网络互通：WSL2 内部服务（如 MySQL 3306）在 Windows 访问用 `localhost` 即可（WSL2 自动端口转发）；外部网络访问 WSL2 服务需要 `netsh interface portproxy` 转发；Windows 服务给 WSL2 访问需要 Windows 防火墙放行。
  4. laew 项目如果在 Windows + WSL2 环境下开发，建议源码放在 `/home/user/project`（Linux ext4），从 Windows 侧用 VSCode Remote-WSL 编辑，避免 `git status` 在 Windows 路径下的换行符与权限位问题。

### BO03 macOS 使用与命令行：Homebrew、Spotlight 与权限授权
- **预期档位**: simple
- **考察维度**: macOS 工具链 + 权限体系
- **对话脚本**:
  1. Homebrew（macOS 缺失的包管理器）：`brew install`、`brew services`（管理后台服务）、`brew cask`（图形应用）、`brew --prefix`（Apple Silicon 默认 `/opt/homebrew` 而 Intel 是 `/usr/local`）、Formula 与 Tap 的关系。
  2. Spotlight / mdfind / Alfred 三件套：Spotlight 命令行 `mdfind -name "report.pdf"` 全盘文件名搜索（比 `find /` 快得多）、内容搜索用 `mdimport` + `mdls` 提前索引、Alfred 配合 Workflow 实现快捷启动。
  3. macOS 权限体系：TCC（Transparency, Consent, and Control）数据库 `~/Library/Application Support/com.apple.TCC/TCC.db`、Full Disk Access（备份软件需要的权限）、Automation 授权（AppleScript 控制其他 App）、`codesign` 签名与公证（Gatekeeper）。
  4. laew 在 macOS 上打包发布时，需要 `codesign --deep --sign "Developer ID" laew` 签名 + `notarytool submit --wait` 公证，否则 Gatekeeper 会拦截用户首次启动。

### BO04 虚拟机实战：VirtualBox 与 UTM 的快照和共享
- **预期档位**: medium
- **考察维度**: 虚拟化类型 + 快照与共享文件夹
- **对话脚本**:
  1. 虚拟化类型三档：Type 1 裸金属（VMware ESXi / Hyper-V Server / Proxmox）、Type 2 托管型（VirtualBox / VMware Workstation / Parallels / UTM）、容器型（Docker / Podman — 共享内核，不是真虚拟机）。
  2. 快照（Snapshot）的正确用法：升级前快照一次做回滚点、安装未知软件前快照做隔离环境；VirtualBox 的「当前状态」与「已保存状态」区别；Apple Silicon 只能用 UTM（QEMU 后端）跑 ARM Linux，不能跑 x86 Linux。
  3. 共享文件夹的三种实现：VirtualBox Guest Additions（双向、慢、路径 `/media/sf_xxx`）、VMware Tools（更快）、`sshfs` / `rsync` over SSH（最灵活、性能接近原生）。网络模式选「桥接」让虚拟机与宿主机同网段。
  4. laew 的 e2e 测试若需要隔离环境跑 SQLite 兼容性矩阵（macOS / Linux / Windows），可以在 UTM 里启三个 VM + Vagrant/Ansible 编排，每 VM 跑一遍 `cargo test` 取日志，避免污染开发机。

### BO05 远程桌面与远程开发：RDP、VNC 与 SSH 端口转发
- **预期档位**: medium
- **考察维度**: 远程协议对比 + 隧道技术
- **对话脚本**:
  1. RDP（Remote Desktop Protocol，Windows 默认）vs VNC（Virtual Network Computing，跨平台但只传位图）vs SSH（命令行 + X11/SFTP 转发）：体验 RDP > VNC（支持音频、剪贴板、双向剪贴板、双向文件传输、多显示器），带宽 RDP < VNC。
  2. SSH 三种端口转发：本地转发（`ssh -L 8080:internal:80 gateway` 把远端服务映射到本地）、远程转发（`ssh -R 8080:local:80 server` 把本地服务暴露到公网，natapp/花生壳本质）、动态转发（`ssh -D 1080` SOCKS 代理）。
  3. SSH 跳板机（JumpHost）配置：OpenSSH 7.3+ 的 `ProxyJump`（`ssh -J user@jump user@target`）、老版本的 `ProxyCommand` 用 `nc` 转发、`~/.ssh/config` 的 `Host *` 段统一配置。
  4. laew 的 `-p` 单轮模式想远程跑在大模型 API 后端机器上时，可以把 Provider end_point 配成内网地址，配合 `autossh -M 0 -fN -L 8443:api-internal:443 jump` 做反向隧道，开发机本地 `https://localhost:8443` 即可调用。

### BO06 家用 NAS 与文件共享：SMB、NFS 与权限
- **预期档位**: medium
- **考察维度**: NAS 协议 + 跨平台权限
- **对话脚本**:
  1. SMB（Server Message Block，Windows 原生，CIFS 是旧名）vs NFS（Network File System，Linux 原生）vs AFP（Apple Filing Protocol，macOS 旧）：跨平台用 SMB（macOS / Linux 都支持），纯 Linux 高性能场景用 NFS v4，macOS 时间机器备份用 SMB 或 AFP。
  2. 家用 NAS 选购与部署：群晖（Synology DSM）/ 威联通（QTS）/ Unraid / TrueNAS Scale（基于 Linux + ZFS）/ 自组装（Debian + Samba）。RAID 级别实战：RAID 1（镜像，2 盘）、RAID 5（单盘容错，3+ 盘）、RAID 6（双盘容错，4+ 盘）、RAID 10（先镜像再条带）。
  3. 权限模型踩坑：SMB 的 NTFS ACL vs NFS 的 Unix mode + Kerberos 认证、macOS 用户名大小写敏感（`Alice` ≠ `alice`）、Linux 的 UID/GID 在 SMB 上要映射到虚拟用户、Time Machine 备份的 `tmux` 假脱机。
  4. laew 的 SQLite 数据库 `LsmAgentEmergentWork.db` 想多机共享时，不要直接放 SMB 共享（SQLite 锁文件跨网络会出问题），可以放本地让 laew 启动时通过 SSH 拉取，或迁移到 PostgreSQL/MySQL。

### BO07 打印机、扫描仪与外设排障
- **预期档位**: simple
- **考察维度**: 驱动模型 + 排障套路
- **对话脚本**:
  1. 打印机连接三方式：USB 直连（最稳定，需驱动）、网络打印机（IP 直连或 Bonjour/mDNS 发现）、共享打印机（连接宿主机的共享队列）。驱动模型：Windows 用厂商 INF/EXE、macOS 用 AirPrint / PPD、Linux 用 CUPS + Gutenprint。
  2. 经典排障清单：打印机离线（重启服务 `print spooler` / 删打印任务 `purge print jobs`）、打印乱码（驱动不匹配 / 字体缺失 / 编码错误）、卡纸（取纸前先关电源避免传感器误判）、墨盒不识别（接触不良 / 第三方芯片被屏蔽）。
  3. 扫描仪三模式：平板扫描（单页）、馈纸式 ADF（多页连续）、胶片扫描（底片专用）；OCR 用 Tesseract（开源）、Adobe Acrobat（商业）、扫描全能王（移动端）；扫描件命名规范 `YYYYMMDD_主题_来源.pdf`。
  4. laew 在做 TUI 自动化测试时，如果环境里有 USB 打印机或扫描仪，注意 `tmux` 子进程可能占用 stdin/stdout 影响设备检测；测试前用 `lsof /dev/usb/lp0` 确认设备空闲。

### BO08 磁盘分区、格式化与数据恢复
- **预期档位**: medium
- **考察维度**: 分区表 + 文件系统 + 恢复手段
- **对话脚本**:
  1. 分区表两派：MBR（Master Boot Record，老旧，2TB 上限，4 主分区）vs GPT（GUID Partition Table，新标准，128 分区，UEFI 原生）。转换工具：`gdisk`（Linux）、`diskpart`（Windows）、`diskutil`（macOS）。
  2. 文件系统对比：NTFS（Windows 日志式、ACL、压缩）、exFAT（跨平台 U 盘首选，无 4GB 单文件限制）、FAT32（兼容所有设备但单文件 4GB 上限）、ext4（Linux 日志式、XFS（RHEL 默认，大文件优秀）、Btrfs（CoW、快照、压缩）、APFS（苹果默认，克隆与快照）。
  3. 数据恢复思路：误删文件（ext4 用 `extundelete`、NTFS 用 `Recuva`/专业软件，立即 umount 减少覆盖）、磁盘坏道（`smartctl -t long /dev/sda` 检测 + `ddrescue` 镜像后修复）、SSD 掉盘（FTL 损坏时基本无解，要靠定期备份）。
  4. laew 的 `LsmAgentEmergentWork.db` 落在根目录，重要数据建议每周 `sqlite3 .backup` 一次到外置硬盘；不要直接 `cp`（可能复制到不一致快照）。

### BO09 系统重装与迁移：驱动、激活与配置还原
- **预期档位**: medium
- **考察维度**: 系统迁移策略 + 激活保留
- **对话脚本**:
  1. 微软账户绑定：Win10/11 重装后用同一微软账户登录，自动恢复大部分 UWP 应用设置（开始菜单布局、Edge 收藏夹、Office 激活）；驱动从「另一台同型号电脑」或厂商官网下，「驱动总裁 / 鲁大师」是国内的便利工具。
  2. macOS 迁移助理（Migration Assistant）：同 Wi-Fi 下两台 Mac 可有线或无线迁移用户账户、应用、数据；Time Machine 恢复到新机器；Apple Silicon 启动到恢复模式用 `asr restore` 走 ASR 镜像恢复。
  3. dotfiles 管理：`.bashrc` / `.zshrc` / `.gitconfig` / `.ssh/` / IDE 配置（IntelliJ `.config/JetBrains`、VSCode `~/.vscode/extensions`）。推荐版本化：GitHub 仓库 `dotfiles` + 软链接脚本（GNU Stow）或 chezmoi 加密敏感字段。
  4. laew 的 SQLite 配置 + TUI 主题 + Provider 列表建议做导出命令（`./laew provider export > providers.json`），重装后 `import` 恢复，省去重新录入 5 元组（protocol/provider_name/model_name/end_point/api_key）+ API Key。

### BO10 双系统与启动引导：UEFI、GRUB 与引导修复
- **预期档位**: hard
- **考察维度**: UEFI 引导链 + GRUB 配置 + 修复工具
- **对话脚本**:
  1. BIOS vs UEFI 的本质：BIOS 是 16 位实模式（寻址 1MB、MBR 引导）、UEFI 是 32/64 位保护模式（GPT 分区、Secure Boot、安全启动链 `UEFI → Boot Loader → Kernel`）。
  2. Linux + Windows 双系统引导链：UEFI 固件 → ESP 分区（FAT32，`/boot/efi`）→ `EFI/ubuntu/grubx64.efi` 或 `EFI/Microsoft/Boot/bootmgfw.efi` → GRUB 加载 Linux 内核 / Windows Boot Manager 加载 Windows。`efibootmgr` 查看与调整启动顺序。
  3. GRUB 2 配置：`/etc/default/grub`（`GRUB_TIMEOUT`、`GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"`）、`update-grub` 自动探测系统、手动 `/etc/grub.d/40_custom` 自定义菜单项；GRUB rescue 模式（`set root=`、`linux /boot/vmlinuz...`、`initrd /boot/initrd...`、`boot`）手救。
  4. 引导修复工具链：Windows 用启动修复（`bcdedit /fixmbr` + `bootrec /fixboot`）、Linux 用 `boot-repair` 一键工具、Live USB 启动后 `chroot` 修复 / 重装 GRUB；UEFI 启动项丢失用 `efibootmgr -c` 重建。
