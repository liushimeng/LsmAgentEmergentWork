# 自动化测试提示词 — 数据工程与 ETL 管线实战（AE01–AE10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**数据工程基础设施**上的实战能力：ETL 管线设计、数仓分层建模、
CDC 增量同步、数据质量、调度编排、列式存储、流式 ETL、元数据血缘、数据脱敏、
日志数据管道。与 M 维度（分析统计方法）和 G 维度（单机文件加工脚本）互补：
M 关注"数据怎么分析"，G 关注"单机文件怎么处理"，
本维度关注"数据怎么稳定、高质量地流动"——管线与平台工程。

---

### AE01 ETL 管线：从多源 CSV 到入库
- **预期档位**: medium
- **考察维度**: 管线设计 + 脏数据治理
- **对话脚本**:
  1. 设计一条 ETL 管线：三个业务方每日投递格式不一的 CSV，清洗合并后入 SQLite。先画流程图与中间层设计。
  2. 逐项处理脏数据：编码混杂（GBK/UTF-8）、表头漂移、重复行、金额格式（千分位/全角字符），各自给策略。
  3. 断点续跑：记录已处理文件清单保证重跑幂等不重复入库；失败文件进隔离区等人工复核。
  4. 写运维脚本：每日跑批后输出吞吐量、脏行率、各阶段耗时的运行报告，落到 testReport/ 目录。

### AE02 数仓分层：ODS/DWD/DWS/ADS
- **预期档位**: medium
- **考察维度**: 数仓建模 + 口径治理
- **对话脚本**:
  1. 讲清数仓四层（ODS/DWD/DWS/ADS）各自的职责与"一层只做一件事"的意义；用一笔订单数据的流转举例。
  2. 维度建模：星型与雪花模型的差异；为订单场景设计事实表与维度表。
  3. 缓慢变化维（SCD）：Type 1/2/3 的语义差异，为"用户收货地址变更"选型并实现。
  4. 讨论口径治理：同一个 GMV 指标在多层被重复定义的乱象，怎么用"指标字典"管起来？

### AE03 CDC 增量同步：捕获业务库变更
- **预期档位**: hard
- **考察维度**: 增量同步 + 一致性语义
- **对话脚本**:
  1. 全量定时拉取 vs 增量捕获：凌晨时间窗不够用时为什么 CDC 是答案？对比触发器、双写、binlog 解析三条路线。
  2. 基于 binlog 的方案：怎么保证变更"至少一次"不丢？offset 管理与断点恢复怎么设计？
  3. 乱序与重复：同一行的多次变更乱序到达怎么处理？幂等 upsert 的主键与版本号怎么定？
  4. 最终一致下业务侧的坑：报表读到"过去的数据"怎么向业务解释？同步延迟监控怎么建？

### AE04 数据质量：校验、对账与告警
- **预期档位**: medium
- **考察维度**: 质量规则体系 + 门禁
- **对话脚本**:
  1. 设计数据质量规则体系：完整性（非空/行数波动）、一致性（外键/跨表对得上）、准确性（值域/业务规则）三类各举例。
  2. 实现校验引擎：规则用 YAML 配置化，跑批后输出违规明细报告。
  3. 对账：源库与数仓侧的行数、金额汇总核对，差异超过阈值的分级告警怎么分级？
  4. 强弱规则分级：哪些违规要阻断下游任务、哪些只告警旁路？"质量门禁"应该挂在调度的哪个环节？

### AE05 调度编排：DAG 依赖与幂等重跑
- **预期档位**: hard
- **考察维度**: 调度器实现 + 失败恢复
- **对话脚本**:
  1. 用 DAG 描述任务依赖：调度系统要解决的三个问题——时间触发、依赖触发、失败重试——分别怎么建模？
  2. 实现一个极简调度器：解析 YAML 里的任务依赖、拓扑排序执行、无依赖任务并发跑。
  3. 失败处理：重试次数与退避策略、下游任务是级联跳过还是继续（SLA 视角）、人工补数接口怎么留？
  4. 幂等设计：为什么每个任务必须可安全重跑？以"按分区覆盖写"为例讲实现要点。

### AE06 列式存储：Parquet 与分区策略
- **预期档位**: medium
- **考察维度**: 存储格式 + 分区治理
- **对话脚本**:
  1. 行存 vs 列存：点查与聚合两种 IO 模式的差异；编码（字典/RLE）与压缩为什么在列存里更有效？
  2. 把一批 CSV 转成 Parquet：对比转换前后的文件大小与典型聚合查询的耗时。
  3. 分区设计：按日期/业务线分区，粒度太细与太粗各自的代价；小文件问题怎么用合并任务治理？
  4. Schema 演进：加列、改类型在 Parquet 上的兼容性表现如何？存量分区怎么平滑迁移？

### AE07 流式 ETL：Kafka 到实时看板
- **预期档位**: hard
- **考察维度**: 流计算 + 状态与背压
- **对话脚本**:
  1. 讲清批流一体的动机；Kafka 在流式管线里的角色：分区、消费者组、位点提交分别解决什么？
  2. 实现流式聚合：滚动窗口与滑动窗口的 UV/PV 统计；乱序事件怎么用事件时间 + 水位线处理？
  3. 去重与状态：流上做精确去重为什么需要状态存储？窗口状态的过期清理怎么避免无限膨胀？
  4. 削峰与背压：上游流量洪峰时，消费者怎么扩容（分区数与消费者的关系）、怎么保护下游不被打挂？

### AE08 元数据与数据血缘
- **预期档位**: medium
- **考察维度**: 元数据体系 + 血缘采集
- **对话脚本**:
  1. 元数据分三类：技术元数据（表结构/分区）、业务元数据（口径/负责人）、血缘元数据，各自服务于谁？
  2. 血缘采集：解析 SQL 提取表级/字段级依赖的思路；动态 SQL、临时表这些难点怎么绕？
  3. 实现一个最小血缘工具：解析目录下的 SQL 文件，输出表级 DAG 并生成 mermaid 图。
  4. 变更影响分析：上游要改掉一个字段，下游哪些报表会挂？血缘图谱怎么自动回答这个问题？

### AE09 数据脱敏与合规
- **预期档位**: medium
- **考察维度**: 脱敏技术 + 访问治理
- **对话脚本**:
  1. 脱敏技术盘点：遮蔽、哈希、加密、置换、k 匿名各自保护什么、又破坏了什么（可用性 vs 安全性）？
  2. 实现脱敏函数库：手机号/身份证/姓名/地址的规则实现，要求保格式以保留统计可用性。
  3. 差分隐私的直觉版：在聚合结果上加噪的思路与"隐私预算"概念，什么场景适合用它？
  4. 访问治理：开发查生产数据的审批流、最小权限、查询审计日志，设计一套完整流程。

### AE10 日志数据管道实战
- **预期档位**: medium
- **考察维度**: 端到端管道 + 排障
- **对话脚本**:
  1. 设计日志数据管道：应用 stdout → 采集 → 解析 → 入库 → 看板，画出架构图并约定日志数据格式。
  2. 解析层三大难题：多行日志（异常堆栈）合并、时间戳归一（时区/毫秒精度）、解析失败的兜底字段。
  3. 入库选型讨论：Elasticsearch 与 ClickHouse 在日志检索/聚合场景的取舍；保留与降采样策略怎么配？
  4. 实战排障：一次"日志延迟 30 分钟"的故障，从采集积压、入库吞吐、查询慢三个层面给出排查步骤。
