### DK01 放置挂机游戏：离线收益与指数增长

- **预期档位**: medium~hard
- **考察维度**: 游戏数值 / 大数表示 / 离线结算
- **对话脚本**:
  1. 放置游戏（Cookie Clicker 类）的核心循环：产出 = 建筑数量 × 每建筑产出 × 增益乘区；解释为什么这类游戏的数值曲线必须用指数而不是线性，以及"指数爆炸"如何反噬普通浮点数（f64 到 1e308 就溢出）。
  2. 针对上面的数值问题，选型大数方案：分段表示法（尾数 double + 指数 int，`1.23e45` 存成 `1.23, 45`）vs 十进制字符串 vs 对数空间运算；从加减乘除实现成本与显示格式化（中文单位"万/亿/兆"接不上怎么办）三个角度对比。
  3. 基于上面的数值层，设计离线结算：玩家 8 小时没上线，回来要补多少资源？公式 `Σ 产出速率 × 时间 × 离线系数`，两个反作弊约束——上限封顶（防改系统时间刷收益）与断点续算（防精度丢失）；讨论"为什么离线收益要打折"这一设计动机。
  4. 动手：用 Rust 实现 `BigNum`（尾数+指数，支持 `add/mul/pow` 与比较）与 `settle_offline(state, elapsed) -> gained`，写单测覆盖 1 秒 / 8 小时 / 100 年三种 elapsed，以及"改时间到未来又改回来"的钳制用例。

### DK02 卡牌效果引擎：触发、堆叠与结算顺序

- **预期档位**: hard
- **考察维度**: 事件驱动 / 效果栈 / 结算时序
- **对话脚本**:
  1. 炉石式卡牌引擎的核心难点是"触发链"：「当你召唤一个随从时，召唤一个 1/1」自己又触发自己吗？设计事件模型：事件类型（召唤/死亡/受伤/回合开始…）+ 监听器（卡牌注册的触发器）+ 触发时机（前/时/后）三层结构。
  2. 针对上面的模型，定义结算顺序规则：同事件多个监听器按什么顺序触发（入场序/战场位置序）、触发器执行中又产生新事件怎么办（递归深度上限）、死亡结算为什么必须在"队列排空"后统一处理（"亡语连锁"的坑）。
  3. 基于上面的规则，设计效果 DSL：把"抽一张牌""对所有敌方随从造成 2 点伤害""获得+1/+1 若其受伤"写成数据而不是硬编码；讨论数据驱动效果（JSON 定义）与硬编码效果在扩展性/平衡性热更上的取舍。
  4. 动手：用任意语言实现事件总线 + 触发器注册 + 队列排空结算的最小引擎，编码三张牌验证：A"召唤时抽牌"、B"友方召唤时+1/+1"、C"亡语召唤 1/1"；写一个"A→触发B→B触发C死亡→C亡语再召唤"的连锁测试并断言最终战场状态。

### DK03 万智牌式回合结构：阶段、优先权与堆

- **预期档位**: hard
- **考察维度**: 状态机 / 优先权传递 / 堆结算
- **对话脚本**:
  1. 万智牌比炉石"硬"在规则引擎：回合被切成阶段与步骤（重置→维持→抽牌→战斗前 main→战斗→战斗后 main→结束），每一步切换都有状态动作；画出这个状态机，说明为什么"每步切换都要清空伤害"这类规则必须挂在转移边而不是散在动作里。
  2. 针对上面的状态机，讲优先权（priority）：任一时刻只有一名玩家有施放权，双方连续让过才推进；实现"施放咒语→对方有响应窗口→响应再响应"的传递协议（`pass/respond` 消息对），说明它如何天然支持人机对弈与网络对战同一套代码。
  3. 基于上面的优先权，实现堆（stack）：后进先出的结算序、结算时目标合法性复检（目标已死则被"反制"）、结算完的卡进墓地；对比 DK02 的"队列排空"，解释为什么卡牌的响应模型必须用栈而触发链用队列。
  4. 动手：实现 `Game::advance(state, action)` 纯函数化的回合引擎骨架（action = Pass/Play/Activate/Choose），跑一个脚本对局：双人对拍让过到战斗、响应对方瞬移、目标被解掉结算失败三条路径，输出每步的状态 trace 供断言。

### DK04 国际象棋规则引擎：走法生成与合法性

- **预期档位**: hard
- **考察维度**: 棋盘表示 / 走法生成 / 重复检测
- **对话脚本**:
  1. 棋盘表示三选一：8×8 二维数组 vs 0x88 vs 120 格 mailbox，从"出界检测成本/滑动棋子步进/内存局部性"对比；解释 0x88 用 `(rank<<4)|file` 后 `sq & 0x88` 一条指令判出界的巧思。
  2. 针对上面的表示，实现走法生成：兵（前进/首动两格/斜吃/吃过路兵/升变）、马象车后的滑动与跳跃、王的入堡（长/短城堡的四个前置条件：未动过/路径空/不经过被攻击格/不吃过路兵的特殊性）；说明"伪合法"（pseudo-legal）与"合法"（自己不被将）的两段式生成。
  3. 基于上面的走法生成，实现终局判定：将军（走完后自己的王是否被攻击——攻击检测函数 `is_attacked`）、将死与逼和（无合法走法 + 是否被将）、三次重复与 50 回合规则（为什么必须记 zobrist 历史而不是局面数组）。
  4. 动手：实现 zobrist hashing（每格×每棋子类型随机数、黑白走子方一个数、入堡权与吃过路兵列也要有键），写"走子增量更新哈希 vs 全盘重算"的正确性对拍测试；用 perft（从初始局面数 3 层内叶子数=8902）验证走法生成零 bug。

### DK05 引擎对弈协议：negamax 与 UCI 通信

- **预期档位**: hard
- **考察维度**: 搜索算法 / 置换表 / 进程间协议
- **对话脚本**:
  1. 把 DK04 的规则引擎变成会下棋的引擎：negamax 搜索框架（`-max(depth, -search(-beta,-alpha))` 取负对称）+ α-β 剪枝 + 走法排序（吃子优先 MVV-LVA）；解释走法排序为什么直接决定剪枝效率（PVS 与朴素 α-β 的节点数差一个数量级）。
  2. 针对上面的搜索，加两个加速器：置换表（用 DK04 的 zobrist 键缓存深度足够的局面评估）、迭代加深（先搜 2 层用结果排序再搜 3 层，时间到即停）；讨论静态搜索（quiescence）为什么是"防水平线效应"的必需品而非优化项。
  3. 基于上面的引擎，接 UCI 协议：`uci`/`isready`/`position startpos moves e2e4 ...`/`go depth 10`/`bestmove` 的文本行协议；设计"引擎进程 + 界面进程"分离架构（stdin/stdout 通信、`uciok`/`readyok` 握手），说明为什么所有主流界面与引擎都坚持这条 20 年的老协议。
  4. 动手：实现 UCI 前端 `parse_position`/`parse_go` 与主循环（读行→分发→后台线程搜索→随时响应 `stop` 立即返回当前最优），对接任意开源 GUI（如 cutefish/arena）对弈一局；用"固定深度+固定 zobrist"验证搜索确定性便于回归测试。

### DK06 Wordle 猜词：信息熵策略与词频

- **预期档位**: medium
- **考察维度**: 信息论 / 候选过滤 / 策略评估
- **对话脚本**:
  1. Wordle 规则形式化：答案 5 字母、反馈三态（绿/黄/灰），猜一次的反馈本质是"把候选集切成若干桶"；解释为什么最优首猜的目标是"让最大桶尽可能小"，并手算 `slate` 与 `aaaaa` 两种首猜的期望桶大小差异。
  2. 针对上面的分桶思想，实现信息熵评分：对每个候选猜测词，枚举所有可能反馈（3^5=243 种），计算 `-Σ p·log2(p)` 的期望信息量，选熵最大的词；说明"答案表 vs 合法词表"两张词表的用途差异。
  3. 基于上面的熵策略，实现反馈过滤：给定 `(guess, pattern)` 把候选集精确过滤（灰色的字母在别处出现过的排除规则、黄色"不含于此位置"、绿色"锁定"）；讨论 hard mode（已得提示必须复用）对策略空间的约束。
  4. 动手：写一个 CLI 双模式——solver（输入已猜词与反馈，输出 top5 推荐猜词）与 autplay（用熵策略对全部答案表跑一遍，统计平均猜测次数与最差词）；对比"首猜固定 slate + 熵后续" vs "全熵"两策略的平均轮次差异。

### DK07 模拟经营游戏经济系统：生产链、供需与通胀

- **预期档位**: medium~hard
- **考察维度**: 经济建模 / 供需平衡 / 存档演化
- **对话脚本**:
  1. 模拟经营（异星工厂/城市天际线类）的经济骨架：资源 → 生产建筑（配方：输入资源×速率 → 输出资源）→ 消耗（人口/维护）；用一条三级生产链（铁矿→钢材→汽车）写出稳态方程，求解"每分钟 10 辆汽车需要多少矿场与钢厂"。
  2. 针对上面的稳态，加供需价格：价格函数 `p = base × (demand/supply)^elasticity` 的简化模型，弹性系数决定价格对缺口的敏感度；解释为什么玩家的"囤积居奇"行为会在这个模型下自我修正（高价刺激增产→价格回落）。
  3. 基于上面的价格，讨论通胀与货币回收（sink）：任务奖励不断印发货币、没有回收就通胀，列出回收口子（维护费/税/升级消耗/土地购买）；给一个小型城镇模型算"月度货币净增发"，设计一个让净增发为 0 的回收组合。
  4. 动手：实现可存档的离散时间经济模拟器（tick=分钟）：配方表 JSON 驱动、价格随供需滑动、货币总量统计；跑 10000 tick 画出钢材价格与货币总量曲线，验证注入"一次性大额补贴"事件后通胀回落时间，调一个弹性系数让回落时间 <2000 tick。

### DK08 抽卡保底与伪随机分布

- **预期档位**: medium
- **考察维度**: 概率建模 / PRD / 保底设计
- **对话脚本**:
  1. 真随机（每抽独立 1.6%）的玩家体验问题：有人 300 抽不出金，有人 10 抽双黄；用几何分布算"350 抽不出金的概率"，说明为什么商业游戏普遍上保底（90 抽必出）——把最差体验从无界变有界。
  2. 针对上面的无界问题，实现两类保底：硬保底（计数器到 90 强制触发）与软保底（50 抽后每抽概率递增 6%，即原神式"期望 62.5 抽"）；推导软保底的期望抽数公式并验证。
  3. 基于上面的保底，讲刀塔式 PRD（伪随机分布）：暴击概率 p 实际是"起始 c、每次未触发递增 c"的序列（P(n) = n×c），保证连续不暴击有上界且手感平滑；给出 c 与等效概率 p 的对照推导（p = c×(1+2+…+N) 近似）。
  4. 动手：写模拟器对拍三种机制（裸随机/软保底/PRD）各 100 万次，输出分布直方图（首次触发抽数分布）、期望与 P95；再实现"歪了再定轨"（50% 概率出 UP，非 UP 重置计数）的完整抽卡状态机并验证长跑概率收敛到标称值。

### DK09 游戏模组加载与兼容治理

- **预期档位**: medium~hard
- **考察维度**: 加载器架构 / 补丁冲突 / 版本门禁
- **对话脚本**:
  1. 游戏模组（Minecraft Forge/织、RimWorld Harmony）如何注入一个已编译的程序：三个层级——数据替换（资源包覆盖）、运行时插件（宿主暴露 API + 反射钩子）、IL/字节码补丁（加载前改写方法体）；解释各层对游戏更新的脆弱度排序。
  2. 针对上面的补丁层，讲 Harmony 式方法补丁的三种挂法：Prefix（前置拦截可跳过原方法）、Postfix（后处理返回值）、Transpiler（改 IL 指令）；说明为什么 Transpiler 最强也最脆（游戏一更新指令序列变化即失效）。
  3. 基于上面的机制，处理模组间冲突：两个模组都改同一方法时的补丁链顺序（优先级+依赖拓扑排序）、方法签名变更的预检（加载前扫描目标方法存在性做 fail-fast）、版本门禁（`GameVersion` 区间声明，不满足直接拒载）。
  4. 动手：实现一个玩具级模组加载器：清单文件声明（名称/依赖/目标版本/补丁目标）、拓扑排序加载、冲突检测（两个模组 Transpiler 同一方法报错并列出双方）、补丁目标缺失时的降级告警；构造三个模组（一个依赖环、一个签名失配、一个正常链）验证加载器的三种处置。

### DK10 热座本地多人与回合制框架

- **预期档位**: medium
- **考察维度**: 输入路由 / 回合管理 / 共享视角
- **对话脚本**:
  1. 热座（hotseat）多人 = 一台机器轮流操作：核心是"当前玩家"概念要贯穿输入系统与渲染系统——输入层只路由给当前玩家、信息层要做"传递屏幕"（上一位玩家的手牌在切换瞬间必须隐藏）；列出这个"隐藏-传递-确认"流程的状态机。
  2. 针对上面的状态机，实现回合管理器：`TurnManager { order, index, skip_log }` 支持跳过（被眩晕）、逆序（特殊效果）、额外回合（压栈弹出语义）；讨论为什么"额外回合"用栈而"逆序"要持久改 order（一次性与持续性的区别）。
  3. 基于上面的管理器，设计观战与回放友好的架构：每个回合记录 `(player, action, visible_state_snapshot)`，回放时按玩家过滤可见性；说明这套日志如何同时服务于"悔棋""断线续玩"与"赛后复盘"三个功能。
  4. 动手：实现一个四人大富翁骨架（格子环+地产+过路费），跑通"传递屏幕 3 秒确认→掷骰→买地决策→下一家"循环，接入 DK02 的事件总线实现"经过起点发钱"与"破产清算"两条规则，写一局自动对打脚本输出每回合账本。
