### CL01 套接字编程基础：BSD Socket API

- **预期档位**: medium
- **考察维度**: 套接字 API + TCP/UDP + 客户端/服务器
- **对话脚本**:
  1. 套接字（Socket）是「网络通信的端点抽象」。BSD Socket API 核心函数：(a) `socket()`（创建套接字）；(b) `bind()`（绑定地址 + 端口）；(c) `listen()`（监听连接）；(d) `accept()`（接受连接）；(e) `connect()`（发起连接）；(f) `send()` / `recv()`（收发数据）；(g) `close()`（关闭套接字）。请解释为什么「套接字」是网络编程的统一抽象（文件描述符 + 读写接口）。
  2. TCP 服务器流程：(a) `socket(AF_INET, SOCK_STREAM, 0)`（创建 TCP 套接字）；(b) `bind(sock, addr, port)`（绑定地址）；(c) `listen(sock, backlog)`（开始监听）；(d) `accept(sock)`（接受新连接）；(e) `recv(sock)`（接收数据）；(f) `send(sock)`（发送数据）；(g) `close(sock)`（关闭连接）。请写一个最简单的 TCP Echo 服务器（接收什么返回什么）。
  3. TCP vs UDP：(a) TCP（面向连接 / 可靠 / 有序 / 流）；(b) UDP（无连接 / 不可靠 / 无序 / 数据报）；(c) TCP 适用场景（HTTP / FTP / SSH）；(d) UDP 适用场景（DNS / 视频流 / 游戏 / QUIC）。请解释为什么「视频流」倾向用 UDP（丢帧比延迟好）。
  4. laew 的套接字编程：laew 如何用 Rust 实现 TCP 服务器：(a) `std::net::TcpListener`（标准库）；(b) `tokio::net::TcpListener`（异步）；(c) 处理多连接（`tokio::spawn`）；(d) 优雅关闭（Graceful Shutdown）。讨论 laew 的网络通信需求（如 LLM API 调用）。

### CL02 IO 多路复用：select / poll / epoll

- **预期档位**: hard
- **考察维度**: IO 多路复用 + epoll + 高性能网络
- **对话脚本**:
  1. IO 多路复用（IO Multiplexing）是「一个线程监控多个文件描述符」的技术。演进：(a) `select()`（O(n) 遍历 + 1024 限制）；(b) `poll()`（O(n) 遍历但无限制）；(c) `epoll()`（Linux，O(1) 事件通知）；(d) `kqueue()`（macOS / BSD）；(e) `io_uring`（Linux 5.1+，异步 IO）。请解释为什么「epoll」比「select」更高效（事件驱动而非轮询）。
  2. epoll 深入：(a) `epoll_create()`（创建 epoll 实例）；(b) `epoll_ctl()`（添加 / 修改 / 删除监控的 fd）；(c) `epoll_wait()`（等待事件）；(d) 触发模式（Level-Triggered vs Edge-Triggered）。请解释「水平触发」（LT）vs「边缘触发」（ET）的区别（LT 持续通知直到处理 / ET 只通知一次需一次性处理完）。
  3. epoll + 非阻塞 IO：(a) 非阻塞 fd（`O_NONBLOCK`）；(b) epoll ET + 非阻塞（经典高性能组合）；(c) 事件循环（Event Loop，`epoll_wait` → 处理事件 → 继续等待）；(d) Reactor 模式（事件驱动架构）。请描述 Reactor 模式的完整流程（注册事件 → 事件循环 → 事件触发 → 回调处理）。
  4. laew 的 IO 多路复用：laew 如何用 `tokio` 实现高性能网络：(a) `tokio::net::TcpListener`（基于 epoll/kqueue）；(b) `tokio::spawn`（异步任务）；(c) `tokio::select!`（多路复用异步操作）；(d) 背压（Backpressure）。讨论 laew 的异步运行时选择（tokio vs async-std）。

### CL03 TCP 状态机：连接的生命周期

- **预期档位**: hard
- **考察维度**: TCP 状态转换 + 三次握手 + 四次挥手
- **对话脚本**:
  1. TCP 状态机描述连接的完整生命周期：(a) 客户端状态（CLOSED → SYN_SENT → ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED）；(b) 服务器状态（CLOSED → LISTEN → SYN_RCVD → ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED）。请解释为什么「TCP 状态机」对网络编程至关重要（理解连接状态 → 调试网络问题）。
  2. 三次握手（Three-way Handshake）：(a) 客户端发送 SYN（SEQ=x）；(b) 服务器回复 SYN+ACK（SEQ=y, ACK=x+1）；(c) 客户端发送 ACK（ACK=y+1）；(d) 连接建立。请解释为什么需要「三次握手」（确认双方收发能力 + 防止历史连接初始化）。
  3. 四次挥手（Four-way Handshake）：(a) 主动方发送 FIN；(b) 被动方回复 ACK；（半关闭状态）(c) 被动方发送 FIN；(d) 主动方回复 ACK；（TIME_WAIT 等待 2MSL）。请解释为什么「TIME_WAIT」需要等待 2MSL（确保最后一个 ACK 到达 + 让旧连接数据报过期）。
  4. laew 的 TCP 状态机应用：laew 如何诊断网络问题：(a) `netstat` / `ss` 查看连接状态；(b) TIME_WAIT 过多（连接池配置问题）；(c) CLOSE_WAIT 过多（连接未正确关闭）；(d) SYN 队列溢出（SYN Flood 攻击）。讨论 laew 的网络诊断能力。

### CL06 QUIC 与 HTTP/3：下一代 Web 协议

- **预期档位**: hard
- **考察维度**: QUIC + HTTP/3 + 0-RTT
- **对话脚本**:
  1. QUIC（Quick UDP Internet Connections）是 Google 设计的「基于 UDP 的可靠传输协议」。特点：(a) 基于 UDP（绕过 TCP 中间盒限制）；(b) 内置 TLS 1.3（连接 + 加密一起建立）；(c) 0-RTT / 1-RTT 连接建立；(d) 无队头阻塞（独立流）；(e) 连接迁移（Connection ID）。请解释为什么「QUIC 比 TCP + TLS」更快（减少握手往返）。
  2. QUIC 核心机制：(a) Stream（流，类似 TCP 连接）；(b) Frame（帧，最小传输单位）；(c) Packet（包，UDP 数据报）；(d) ACK（确认机制）；(e) 拥塞控制（类似 TCP Cubic / BBR）。请描述 QUIC 如何解决「TCP 队头阻塞」（独立流，一个流丢包不影响其他流）。
  3. HTTP/3：(a) 基于 QUIC 的 HTTP；(b) 帧格式（HEADERS 帧 / DATA 帧）；(c) QPACK（头部压缩，替代 HPACK）；(d) Server Push（服务器推送）。请解释为什么「HTTP/3 头部压缩用 QPACK 而非 HPACK」（HPACK 依赖有序交付，QUIC 流独立）。
  4. laew 的 HTTP/3 应用：laew 是否可以升级到 HTTP/3：(a) `quinn`（Rust QUIC 实现）；(b) `h3`（Rust HTTP/3 实现）；(c) 优势（连接迁移 + 0-RTT）；(d) 挑战（UDP 被防火墙限制）。讨论 HTTP/3 对 laew 的适用性。

### CL09 高性能网络：C10K / C10M 问题

- **预期档位**: hard
- 考察维度**: 可扩展网络 + C10K + 架构演进
- **对话脚本**:
  1. C10K 问题（Concurrent 10K Connections）是「单台服务器处理 10000 个并发连接」的挑战。演进：(a) 每个连接一个进程（Apache prefork，资源消耗大）；(b) 每个连接一个线程（Apache worker，线程切换开销）；(c) IO 多路复用（Nginx / Redis，单线程处理多连接）；(d) 异步 IO + 多核（tokio + 多线程运行时）。请解释为什么「IO 多路复用」能解决 C10K（一个线程监控所有连接）。
  2. C10M 问题（Concurrent 10M Connections）是「单台服务器处理 1000 万个并发连接」的挑战。技术：(a) 内核旁路（DPDK / netmap，跳过内核协议栈）；(b) 零拷贝（`sendfile` / `splice`）；(c) 无锁数据结构（Ring Buffer）；(d) CPU 绑核（避免上下文切换）。请描述如何用 DPDK 实现 C10M（用户态驱动 + 轮询 + 大页内存）。
  3. 高性能网络架构：(a) Reactor 模式（事件驱动）；(b) Proactor 模式（异步 IO）；(c) 主从 Reactor（主 Reactor 接受连接 + 从 Reactor 处理 IO）；(d) 每个 CPU 一个事件循环（SO_REUSEPORT）。请描述 `tokio` 的主从 Reactor 实现（`tokio::net::TcpListener` 默认行为）。
  4. laew 的高性能网络：laew 是否需要高性能网络：(a) 当前单用户模式不需要（C10K 足够）；(b) 多用户部署需要（IO 多路复用 + 异步）；(c) 边缘部署需要（低延迟 + 高并发）。讨论 laew 的网络架构演进路线。

### CL10 网络安全基础：TLS / 证书 / 握手

- **预期档位**: medium
- **考察维度**: TLS 协议 + 证书 + 握手流程
- **对话脚本**:
  1. TLS（Transport Layer Security）是「加密 + 认证 + 完整性」的协议。版本演进：(a) SSL 2.0 / 3.0（已废弃）；(b) TLS 1.0 / 1.1（已废弃）；(c) TLS 1.2（当前主流）；(d) TLS 1.3（最新，更快更安全）。请解释为什么「TLS 对网络安全至关重要」（防止窃听 + 篡改 + 伪造）。
  2. TLS 1.2 握手流程：(a) Client Hello（客户端随机数 + 支持的密码套件）；(b) Server Hello（服务器随机数 + 选择的密码套件）；(c) Certificate（服务器证书链）；(d) Server Hello Done；(e) Client Key Exchange（预主密钥）；(f) Finished（握手完成）。请解释为什么「TLS 1.3」把握手从 2-RTT 减少到 1-RTT（减少往返）。
  3. 证书体系（PKI）：(a) 证书（公钥 + 身份 + CA 签名）；(b) 证书链（根 CA → 中间 CA → 叶子证书）；(c) 证书验证（签名验证 + 有效期 + 域名匹配 + 吊销检查）；(d) Let's Encrypt（免费证书 + ACME 协议）。请描述浏览器如何验证网站的 TLS 证书（证书链 + OCSP / CRL）。
  4. laew 的 TLS 应用：laew 如何安全调用 LLM API：(a) HTTPS 强制（TLS 1.2+）；(b) 证书验证（防止中间人攻击）；(c) 证书固定（Certificate Pinning，可选）；(d) mTLS（双向 TLS，企业场景）。讨论 laew 的安全通信配置。
