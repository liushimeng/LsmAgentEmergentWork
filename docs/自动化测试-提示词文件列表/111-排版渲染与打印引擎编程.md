### DC01 断行算法：从贪心到 Knuth-Plass

- **预期档位**: medium~hard
- **考察维度**: 排版算法 / 动态规划 / 中英文断行差异
- **对话脚本**:
  1. 一段文字要在固定宽度内折行，最简单的贪心算法（能放就放，放不下换行）有什么问题——最后一行特别短、行尾参差不齐；用一个 10 词英文段落演示贪心排出的丑效果。
  2. Knuth-Plass 断行（TeX 用）：把断行建模成最短路径——每个可行断点是图节点，边的代价是「拉伸/压缩空格的丑陋度」，动态规划找全局最优；手算上面那段文字的最优断行。
  3. 中文断行差异：中文可以在任意字符间断行但有禁则（标点不能行首、开括号不能行尾），英文只能在空格断；讨论 CSS 的 `line-break` 属性与避头尾规则。
  4. 动手：用 Python 实现贪心断行 + 简化版 Knuth-Plass（代价 = 行尾剩余空白的立方），同一段落对比两种输出。

### DC02 字体度量：em、基线与行高

- **预期档位**: medium
- **考察维度**: 字体度量 / 文本测量 / 行高计算
- **对话脚本**:
  1. 字体排版的度量词汇：em 方块、基线（baseline）、x-height、ascender/descender、行距（leading）；为什么 CSS 里 `font-size: 16px` 的字实际高度不是 16px。
  2. 文本测量：渲染前要知道「这行字多宽」——每个字形的 advance width + 字偶距（kerning，如「AV」要靠近）；粗体/斜体怎么合成（伪粗体加描边、伪斜体倾斜矩阵的局限）。
  3. 行高的坑：`line-height: 1.5` vs `150%` vs `1.5em` 的继承差异；中英文混排基线对齐问题（中文按 em 框、英文按基线，混排行高被撑大）。
  4. 动手：用 Python PIL 或 matplotlib 加载一个 TTF 字体，用 freetype 思路读取并打印「Hello 世界」每个字符的 advance 与 bbox，算总宽度。

### DC03 Markdown 渲染管线：从文本到 AST 到 HTML

- **预期档位**: medium
- **考察维度**: 解析器 / AST / 渲染管线
- **对话脚本**:
  1. Markdown 渲染不是正则替换：正确管线是 分块（块级：段落/标题/代码块/列表）→ 行内解析（强调/链接/代码）→ AST → 渲染 HTML；为什么正则处理不了嵌套（`**粗体里有\`代码\`**`）。
  2. 基于上面的管线，讨论 CommonMark 规范的意义：统一各种方言（GFM 表格/删除线/任务列表是扩展）；AST 节点的设计（块节点 vs 行内节点、容器 vs 叶子）。
  3. 渲染目标多样化：同一 AST 可渲染 HTML / 终端 ANSI / PDF；这正是「一份源多目标输出」的架构——讨论 visitor 模式遍历 AST。
  4. 动手：用 Python 写 100 行迷你 Markdown 解析器，只支持 `#` 标题、段落、`**粗体**`、代码块四种语法，输出 HTML；再用同一 AST 输出纯文本。

### DC04 PDF 生成：从 HTML 到打印级文档

- **预期档位**: medium
- **考察维度**: PDF 结构 / HTML 渲染 / 分页控制
- **对话脚本**:
  1. PDF 生成的三条路线：HTML 渲染引擎截图式（wkhtmltopdf/Chrome headless）vs 编程式绘制（reportlab/iText 精确控制坐标）vs 排版语言编译（LaTeX/Typst）；选型权衡（开发效率 vs 版式精度）。
  2. HTML→PDF 的分页控制：CSS Paged Media——`@page` 设置纸张与页边距、`page-break-before/inside` 控制断页、页眉页脚与页码用 running element；讨论表格跨页时表头重复的 `thead` 行为。
  3. 字体嵌入：PDF 必须内嵌字体否则换机器变样；子集嵌入（只打包用到的字形）把 10MB 字体压到几百 KB；中文字体版权与开源替代（思源黑体/宋体）。
  4. 动手：用 Python reportlab 生成一份带中文字体、页码、表格的两页 PDF；再用 Chrome headless `--print-to-pdf` 把同内容 HTML 转 PDF 对比效果。

### DC05 富文本编辑器的撤销与重做栈

- **预期档位**: medium~hard
- **考察维度**: 命令模式 / 操作逆变换 / 快照 vs 增量
- **对话脚本**:
  1. 撤销重做的两种实现：快照法（每步存整个文档副本，撤销=回退副本）vs 逆操作法（每步存操作的逆——insert 的逆是 delete）；内存与性能的权衡，为什么编辑器都用逆操作。
  2. 命令模式落地：每个编辑操作（插入/删除/格式化）封装成含 do/undo 的对象，undo 栈 + redo 栈，新操作清空 redo 栈；讨论操作合并（连续打字合成一条 undo 单位）。
  3. 基于上面的栈模型，讨论协作场景的复杂性：撤销只能撤「自己的操作」，别人插入的文字不能被我的 undo 删掉——这超出单机栈模型（需 OT/CRDT），先讲清边界不深入。
  4. 动手：用 Python 实现一个文本缓冲 + insert/delete 命令 + undo/redo 栈，模拟「打字→删除→undo→redo→新打字」验证 redo 栈清空行为。

### DC06 表格排版：列宽分配与跨页断行

- **预期档位**: medium
- **考察维度**: 表格布局算法 / 约束求解 / 跨页处理
- **对话脚本**:
  1. 表格列宽怎么定：固定布局（table-layout: fixed，按首行分配）vs 自动布局（遍历所有行算内容最大/最小宽度，在容器宽度内按比例分配）；自动布局为什么慢（要两遍扫描）。
  2. 单元格内容的约束：长单词/URL 不换行会撑爆列（`word-break: break-all` vs `overflow-wrap`）；内容最小宽度（最长不可断词）与期望宽度的矛盾求解。
  3. 跨页表格：行太高一页放不下怎么断（行内断 vs 整行推下页）、表头在每页重复、合并单元格（rowspan/colspan）跨页时的语义混乱；讨论 LaTeX longtable 的处理方式。
  4. 动手：用 Python 实现一个终端表格渲染器——给定列内容自动算列宽（内容最大宽，超总宽按比例压缩），支持中文宽度（全角字符算 2 列）。

### DC07 语法高亮引擎：从正则到 Tree-sitter

- **预期档位**: medium
- **考察维度**: 高亮引擎 / 词法分析 / 增量解析
- **对话脚本**:
  1. 语法高亮三代方案：正则规则（TextMate grammar，简单但处理不了上下文）→ 手写词法分析器（准确但每种语言重写）→ Tree-sitter（增量解析真语法树，能处理字符串里嵌代码）。
  2. TextMate 式高亮的实现：作用域栈（scope stack）+ 正则规则表，`"..."` 进入 string 作用域后内部规则切换；讨论它处理不了什么（`{` 匹配、heredoc 结束符是变量）。
  3. 性能工程：大文件（1 万行）每次按键都全量重高亮不可行——按行缓存状态（每行结束时的作用域栈），编辑只从改动行重新扫描；Tree-sitter 的增量解析更进一步（复用未改子树）。
  4. 动手：用 Python 实现一个 JSON 语法高亮器（字符串/数字/关键字/括号四色），终端 ANSI 输出；处理「字符串里的 `{` 不算括号」这个正则容易错的点。

### DC08 打印样式与纸张适配

- **预期档位**: simple~medium
- **考察维度**: @media print / 纸张标准 / 打印工程
- **对话脚本**:
  1. 网页打印为什么丑：屏幕布局（固定宽度/背景图/交互元素）不适合纸张；`@media print` 基础——隐藏导航与按钮、改白底黑字、展开折叠内容、链接后追加 URL。
  2. 纸张标准：A4（210×297mm）vs Letter 的差异导致跨国文档错位；CSS 物理单位（mm/cm/in/pt）与屏幕 px 的换算（96dpi）；出血（bleed）与裁切标记是印刷级要求。
  3. 打印的坑：背景色默认不打印（`-webkit-print-color-adjust: exact`）、大图片跨页被裁、web font 加载时机导致字体替换；讨论「打印预览所见即所得」的验证方法。
  4. 动手：写一份个人简历 HTML + 完整 print 样式（A4、页边距 20mm、隐藏装饰、页码），用 Chrome headless 转 PDF 验证版式。

### DC09 电子墨水屏适配：刷新模式与残影优化

- **预期档位**: medium
- **考察维度**: 墨水屏原理 / 刷新策略 / 低功耗 UI
- **对话脚本**:
  1. 墨水屏（E-ink）原理：带电黑白颗粒在电场下移动显色，断电保持图像（零功耗显示）；三种刷新模式——全刷（闪黑一下清残影）/ 局部刷（快但有残影累积）/ 快速刷（灰度损失换速度）。
  2. UI 设计适配：避免动画与渐变（刷新率 1~10Hz 撑不起）、用抖动算法表现灰度（黑白颗粒模拟 16 级灰）、深色模式对墨水屏无意义（显示不耗电、刷新才耗电）。
  3. 残影与翻页策略：局部刷 N 次后强制一次全刷；阅读类 App 的「快速翻页模式」（降低灰度级数换刷新速度）；讨论墨水屏平板（文石/reMarkable）的手写延迟优化（笔迹先走快速刷通道）。
  4. 动手：用 Python 生成一组模拟墨水屏抖动的图片——把一张灰度图用 Floyd-Steinberg 抖动算法转成纯黑白，对比原始灰度效果。

### DC10 网格系统与版式设计自动化

- **预期档位**: simple~medium
- **考察维度**: 网格系统 / 版式规则 / 程序化排版
- **对话脚本**:
  1. 平面设计的网格系统：12 列网格（960 系统的遗产）、栏间距（gutter）、基线网格（所有文字行底对齐 8px 倍数）；网格为什么让设计「看起来专业」——对齐与节奏。
  2. 程序化排版规则：字号比例（modular scale，如 1.25 倍率：12/15/19/24/30）、留白规则（内容越相关间距越近的格式塔原理）、视觉层级（每页一个视觉焦点）；这些规则可以写成代码约束。
  3. 自动化排版应用：报表自动生成（数据 → 模板 → PDF）、响应式海报（元素按优先级在空间不足时逐级隐藏）、A/B 测试用程序化生成多个版式。
  4. 动手：用 Python + PIL 实现一个「标题+正文+图片」海报生成器——输入文本和图片路径，按 12 列网格与 1.25 字号比例自动排版输出 PNG。
