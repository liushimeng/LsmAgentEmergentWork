# 自动化测试提示词 — 数据库与存储技术（I01–I10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**数据库设计、SQLite 使用、存储优化、数据迁移**等方面的表现，
涵盖 SQL 查询、索引优化、WAL 模式、表结构设计、数据迁移、备份恢复等主题。

---

### I01 SQL 基础查询
- **预期档位**: simple
- **考察维度**: SQL 语法 + 基本查询
- **对话脚本**:
  1. 有一个用户表 users（id, name, email, created_at），写出查询所有用户的 SQL。
  2. 查询 2024 年注册的用户，按注册时间降序排列。
  3. 统计每个邮箱域名的用户数量（如 @gmail.com 有多少用户）。
  4. 解释 WHERE、GROUP BY、HAVING 的区别和使用场景。

### I02 索引优化原理
- **预期档位**: medium
- **考察维度**: 索引机制 + 查询优化
- **对话脚本**:
  1. 什么是数据库索引？用生活化的例子解释 B+ 树索引的工作原理。
  2. 什么情况下索引会失效？列出 5 种常见情况。
  3. 为 laew 的 `session_memory` 表设计合适的索引，说明理由。
  4. 如何用 EXPLAIN 分析一条 SQL 的执行计划？

### I03 SQLite WAL 模式
- **预期档位**: medium
- **考察维度**: SQLite 高级特性
- **对话脚本**:
  1. 什么是 WAL（Write-Ahead Logging）模式？相比默认的 rollback journal 有什么优势？
  2. 如何在 SQLite 中开启 WAL 模式？WAL 模式下有哪些新的文件（.wal、.shm）？
  3. WAL 模式下的读写并发是如何实现的？有没有写写并发？
  4. laew 使用 SQLite 作为配置存储，WAL 模式对它有什么好处？

### I04 表结构设计
- **预期档位**: medium
- **考察维度**: 数据库设计范式 + 实践

  4. 多对多关系（文章-标签）应该怎么设计？写出建表 SQL。

### I05 数据迁移策略
