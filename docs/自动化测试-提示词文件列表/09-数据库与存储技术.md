# 自动化测试提示词 — 数据库与存储技术（I01–I10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**数据库设计、SQL 优化、存储引擎、数据迁移**等场景中的表现，
涵盖 SQL 查询优化、索引设计、事务处理、SQLite 深入、数据迁移、
存储引擎对比、备份恢复、ORM 使用、数据建模、性能调优等主题。

---

### I01 SQL 查询优化
- **预期档位**: medium
- **考察维度**: SQL 性能分析 + 优化策略
- **对话脚本**:
  1. 这条 SQL 查询很慢：`SELECT * FROM logs WHERE created_at > '2024-01-01' AND level = 'ERROR' ORDER BY created_at DESC LIMIT 100;`，请分析可能的原因。
  2. 应该创建什么索引来优化这条 SQL？解释索引列顺序的选择依据。
  3. 如果 `logs` 表有 1 亿条数据，除了索引还有什么优化手段（分区/归档/读写分离）？
  4. 用 `EXPLAIN QUERY PLAN` 验证你的优化思路，解读输出结果。

### I02 数据库索引原理
- **预期档位**: simple
- **考察维度**: 索引数据结构 + 使用原则
- **对话脚本**:
  1. B+ 树索引的结构是什么？为什么数据库不用哈希索引做范围查询？
  2. 什么是聚簇索引和非聚簇索引？SQLite 的主键是哪种？
  3. 索引是不是越多越好？给出 3 个"不该建索引"的场景。
  4. 什么是覆盖索引？举一个能用覆盖索引避免回表的查询例子。

### I03 事务与并发控制
- **预期档位**: medium
- **考察维度**: 事务隔离 + 并发问题
- **对话脚本**:
  1. 什么是脏读、不可重复读、幻读？各举一个具体场景。
  2. SQLite 的 WAL 模式下，读和写可以并发执行，它的实现原理是什么？
  3. 两个事务同时更新同一行数据，会发生什么？乐观锁和悲观锁怎么解决？
  4. laew 的 `agent_memory` 表如果被多个 Session 同时写入，设计一个避免冲突的方案。

### I04 SQLite 深入实战
- **预期档位**: medium
- **考察维度**: SQLite 高级特性 + 工程应用
- **对话脚本**:
  1. SQLite 的 `PRAGMA` 有哪些常用配置？`journal_mode`/`synchronous`/`cache_size` 各影响什么？
  2. 为 laew 设计一份 SQLite 优化配置清单，说明每个 PRAGMA 的设置值和理由。
  3. FTS5 全文索引怎么用？给 laew 的 `session_memory` 表加一个 FTS5 虚拟表的完整 SQL。
  4. SQLite 的 `WITHOUT ROWID` 表是什么场景用的？和普通表有什么性能差异？

### I05 数据迁移方案设计
- **预期档位**: hard
- **考察维度**: 版本化迁移 + 兼容性保证
- **对话脚本**:
  1. 数据库 Schema 变更时，如何做到"应用不停机、数据不丢失"？给出迁移流程。
  2. 设计一个迁移版本管理方案：版本号怎么命名、如何记录已执行的迁移、如何回滚。
  3. 给 laew 设计从"单 provider 表"迁移到"多 provider 表"的完整步骤（含数据迁移 SQL）。
  4. 讨论"扩展/收缩"模式（expand/contract）为什么是大表迁移的最佳实践。

### I06 存储引擎对比
- **预期档位**: simple
- **考察维度**: 技术选型 + 特性对比
- **对话脚本**:
  1. SQLite、PostgreSQL、MySQL 各自的适用场景是什么？各举一个典型用例。
  2. 嵌入式数据库（SQLite/DuckDB/LMDB）和客户端-服务器数据库的根本区别是什么？
  3. DuckDB 和 SQLite 在分析型查询上有什么性能差异？原因是什么？
  4. 如果 laew 未来要支持"多用户共享一个数据库"，SQLite 还合适吗？应该往哪个方向演进？

### I07 备份与恢复策略
- **预期档位**: medium
- **考察维度**: 数据安全 + 灾难恢复
- **对话脚本**:
  1. SQLite 在线备份的几种方法（`.backup` 命令/VACUUM INTO/文件复制）各有什么风险？
  2. 设计一个 laew 数据库的定时备份方案：每天增量、每周全量、保留 30 天。
  3. 如果数据库文件损坏（如磁盘故障），有哪些恢复手段？成功率如何？
  4. 写一个备份验证脚本：备份后自动恢复到临时库并跑完整性检查（`PRAGMA integrity_check`）。

### I08 ORM 与原生 SQL 选择
- **预期档位**: simple
- **考察维度**: 数据访问层设计 + 权衡
- **对话脚本**:
  1. ORM 的 N+1 查询问题是什么？怎么发现和解决？
  2. Rust 的 ORM（如 Diesel）和 SQL 构建器（如 SQLx）各适合什么场景？
  3. laew 目前直接写原生 SQL，如果要引入 ORM，迁移代价和收益分别是什么？
  4. 给出"何时该用 ORM / 何时该用原生 SQL"的决策树。

### I09 数据建模实战
- **预期档位**: medium
- **考察维度**: 关系建模 + 范式应用
- **对话脚本**:
