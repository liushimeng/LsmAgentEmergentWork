### CQ01 协同过滤：UserCF 与 ItemCF

- **预期档位**: medium~hard
- **考察维度**: 相似度计算 + TopN 推荐 + 两种 CF 取舍
- **对话脚本**:
  1. 用 Python 实现显式评分数据（MovieLens 风格）上的 UserCF：用户相似度用余弦（共同评分物品向量），找 TopK 相似用户，把他们高分而目标用户未看的物品加权求和出推荐分；写出完整脚本并解释 TopK 取 50~200 的原因。
  2. ItemCF 实现：物品相似度矩阵（共现用户数归一化），用户历史交互过的物品各取相似 TopK 物品求和；解释「买了 A 的人也买 B」的 ItemCF 为什么在电商更常用（物品数远小于用户数 / 可离线预计算 / 可解释）。
  3. 隐式反馈改造：真实场景没有评分只有点击/购买（0/1）——相似度换 Jaccard 或带流行度惩罚的 `sim = 交集 / sqrt(|U_a| × |U_b|)`（热门物品惩罚）；讨论「时间衰减」（近 30 天行为权重高）对实效性业务的必要性。
  4. laew 借鉴：ItemCF 给 laew 的 `session_memory` 召回思路——「做过 A 类任务的用户接下来常做 B 类」，把历史任务摘要按「任务类型相似度」组织，Yolo 处理新任务时召回最相关的历史经验注入。

### CQ02 矩阵分解与 ALS

- **预期档位**: hard
- **考察维度**: 隐向量模型 + 交替最小二乘 + 正则
- **对话脚本**:
  1. 矩阵分解思想：评分矩阵 R（巨大且稀疏）≈ 用户隐矩阵 P × 物品隐矩阵 Qᵀ，每个用户/物品映射为 k 维（20~100）隐向量，预测分 = 内积；解释为什么这能捕捉「潜在兴趣维度」而 CF 只看显式共现。
  2. ALS 求解：固定 Q 解 P（每行变成独立岭回归有闭式解 `p_u = (QᵀQ + λI)^-1 Qᵀr_u`）、再固定 P 解 Q，交替迭代到收敛；用 NumPy 实现一个玩具版（100 用户 × 200 物品），对比 SGD 训练的收敛速度。
  3. 隐式反馈 ALS（ALS-WR）：把 0/1 交互变成「置信度 c = 1 + αr」加权损失，未观察样本也不是 0 而是低置信度；解释这个改造为什么对点击数据至关重要，并用 implicit 库跑通一个小数据集。
  4. laew 借鉴：隐向量「把稀疏行为压缩成稠密语义」对照 Compact Agent 的摘要压缩——讨论把「用户历史任务」压成定长「任务向量」存 `session_memory`，新任务来了先算向量相似度再决定召回哪些历史。

### CQ03 CTR 预估：从 LR 到 FM 再到 DeepFM

- **预期档位**: hard
- **考察维度**: 特征交叉演进 + 模型结构 + 工程训练
- **对话脚本**:
  1. LR 基线：one-hot 特征 + 逻辑回归预估点击率，损失 logloss，指标 AUC；解释为什么纯 LR 学不到「女性 × 美妆」这种交叉（除非人工做组合特征），引出自动交叉的动机。
  2. FM：每个特征学一个 k 维 embedding，交叉权重 = 两特征 embedding 内积 `w_ij = <v_i, v_j>`，参数量从 n² 降到 n·k；手推 FM 对二次项的化简公式 `ΣΣ<x_i,x_j> = ½Σ[(Σx_i v_i)² - Σ(x_i v_i)²]` 并用 PyTorch 实现。
  3. DeepFM：FM 侧（宽路，记忆交叉）+ DNN 侧（深路，泛化）共享 embedding 并联输出；写模型结构代码，说明 Criteo 数据集上 AUC 从 LR 0.76 → FM 0.79 → DeepFM 0.80 的典型量级与「+0.001 都值得上线」的行业现实。
  4. laew 借鉴：embedding 共享（同一特征两路复用）对照 laew 的统一消息模型——一套消息结构被协议层 / Agent 层 / Debug 层多处消费，讨论「共享表示 + 多视角消费」的设计如何在两者中减少不一致。

### CQ04 多目标排序与融合公式

- **预期档位**: medium~hard
- **考察维度**: 多任务建模 + 融合超参 + 帕累托
- **对话脚本**:
  1. 为什么多目标：短视频推荐要同时优化「点击 / 完播时长 / 点赞 / 关注 / 负反馈」，单目标点击会把标题党排最前；写出你的推荐系统应该有哪些目标、各自的量纲与业务含义。
  2. 融合公式工程：最常见的是乘法融合 `score = p_click^α × f(duration)^β × (1 + like_rate)^γ ...`，α β γ 由运营在线调参；实现一个可热更新的融合配置（DB 表 + 缓存 + 灰度分组），说明为什么不能写死在代码里。
  3. 多任务模型：共享底层 embedding + 多塔输出（MMoE 的专家门控思想——每个目标从多个专家网络加权取用），解释「跷跷板效应」（一个目标涨另一个跌）与如何用帕累托前沿选融合点。
  4. laew 借鉴：多目标融合对照 laew 的任务质量评估——Debug Agent 的报告也是多目标（任务完成度 / token 成本 / 耗时 / 安全性），讨论设计一个可配置权重的综合分用于 Yolo 的档位决策与失败归因。

### CQ05 召回漏斗：多路召回与合并去重

- **预期档位**: medium
- **考察维度**: 召回通道设计 + 合并截断 + 漏斗预算
- **对话脚本**:
  1. 多路召回：ItemCF 召回（500）+ 双塔向量召回（500）+ 标签 / 热门 / 新品 / 地域各一路（各 100~200），每路独立打分；解释为什么单路召回会「信息茧房」（只召回和history相似的）而要多路互补。
  2. 双塔召回：用户塔 / 物品塔各自输出向量，离线把物品向量建 ANN 索引（Faiss / HNSW），在线只算用户向量后近邻检索；说明双塔「训练时交互、推理时独立」的结构为什么注定它表达能力弱但快（毫秒级检索百万库）。
  3. 合并与截断：多路结果按「路配额 + 总量 2000」截断去重，附召回来源标记（埋点分析各路贡献），写 `mergeRecall(channels, quota)` 的实现；讨论新召回路上线时的「探索期配额」灰度策略。
  4. laew 借鉴：多路召回对照 Yolo 的信息收集——项目上下文（一路）/ 历史摘要（一路）/ 用户当前输入（一路）就是三条召回通道，讨论给每路设「配额」防止历史摘要淹没当前任务（现状注入最近 3 条）。

### CQ06 冷启动：新用户与新物料

- **预期档位**: medium
- **考察维度**: 探索策略 + 内容特征兜底 + EE 平衡
- **对话脚本**:
  1. 新用户冷启动：无行为数据——注册时的兴趣选择 + 人口属性 + 热门兜底 + 快速探索（前 20 次曝光刻意多样化并快速捕捉首个正反馈切换策略）；写「兴趣未知期」的状态机（探索 → 半个性化 → 个性化）。
  2. 新物料冷启动：无行为的新物品靠内容特征（类目 / 标题 embedding / 封面图）进「内容召回通道」，并给流量扶持池（保底曝光 N 次）；解释「马太效应」（老物品垄断曝光）与扶持池的关系。
  3. Bandit 探索：ε-greedy / UCB / Thompson Sampling 三种探索算法各写 20 行玩具版（多臂老虎机模拟），说明 Thompson 采样为什么在推荐里最常用（天然按不确定性强弱分配探索流量）。
  4. laew 借鉴：冷启动对照 laew 首次使用——新用户无 session_memory 时 Yolo 只能按提示词字面分类，讨论给 laew 设计「探索期」（前 N 轮用更保守的 medium 档 + 更强的 QC）直到积累足够任务画像。

### CQ07 多样性打散与 MMR

- **预期档位**: medium
- **考察维度**: 类目打散 + 滑窗规则 + MMR 重排
- **对话脚本**:
  1. 业务打散规则：同卖家 / 同类目 / 同品牌在结果里不相邻（滑窗约束「任意连续 5 个里同类 ≤ 2」），写一个贪心插入打散器（按分数降序逐个尝试放入最早不违规的位置）。
  2. MMR（Maximal Marginal Relevance）：每次从候选集选「相关性 λ × 与已选集合的最大相似度 (1-λ)」最优的物品，λ 控制相关性与多样性权衡；用物品 embedding 余弦相似度实现 MMR 重排并调 λ 观察列表形态变化。
  3. 多样性度量：ILD（列表内平均两两距离）/ 类目熵 两个指标量化打散效果，写计算函数；讨论「过度打散伤相关性」的拐点如何用在线实验找到（联动 CQ09 的护栏指标）。
  4. laew 借鉴：MMR 对照 Yolo 历史摘要注入的选择——若注入 3 条摘要彼此高度相似（重复任务），信息增量低；讨论按摘要间相似度做 MMR 选择，最大化注入信息的边际增益。

- **预期档位**: medium~hard
- **考察维度**: 特征体系 + 泄漏检测 + 训练在线一致性
- **对话脚本**:
  1. 特征体系设计：用户侧（静态画像 / 行为统计窗口 1d/7d/30d / 序列特征）、物品侧（静态属性 / 统计 CTR）、上下文侧（时间 / 设备 / 场景）；为「外卖店推荐」列一张 40 个特征清单并标注来源表。
  2. 特征泄漏排查：典型事故——「当日订单数」包含了当前样本引发的订单（用了未来信息）、点击后回填的「是否转化」；给出泄漏排查 checklist（时间对齐 / 因果方向 / 线下 AUC 高得离谱 0.9+ 必有诈），写一个「按时间切分」的训练测试划分防止穿越。

  4. laew 借鉴：训练在线一致性对照 laew 的 mock LLM e2e 与真实 LLM 行为差异——mock 脚本永远理想化，讨论在 Debug 模式记录「真实响应 vs mock 假设」的偏差度量，避免 e2e 全绿但真机翻车。

### CQ09 在线评估：interleaving 与护栏指标

- **预期档位**: medium
- **考察维度**: 在线实验设计 + 灵敏度 + 护栏
- **对话脚本**:
  1. 在线 vs 离线：离线 AUC 涨 0.003 上线可能跌——离线指标只衡量拟合而上线衡量「用户真实行为」；描述一个标准 A/B（分流 hash(user_id) % 100、实验组新模型、观察 1~2 周、主指标人均时长）的关键设计点。
  2. Interleaving：把两个模型的推荐交织进同一个列表给同一用户，统计用户点了哪方更多——灵敏度比 A/B 高 10~100 倍（同等置信度只需 1/10 流量与时长）；写一个-team 交织（ABBA 抵消位置偏差）的实现逻辑。
  3. 护栏指标（guardrail）：主指标涨但崩溃率 / 举报率 / 退货率恶化也要回滚——列出推荐实验的护栏指标集与「护栏破线立即熔断」的自动化流程；讨论 novelty effect（新模型短期占优）为什么要求实验跑满周期。
  4. laew 借鉴：interleaving 的「同用户同场景对比两个策略」思想用于 laew 自测——同一组 940+ 提示词分别跑新旧 Yolo 分类器，逐条对比档位差异（等价于 interleaving 的配对比较），比「分别跑一次看整体分布」灵敏得多。

### CQ10 级联架构：召回-粗排-精排-重排

- **预期档位**: hard
- **考察维度**: 漏斗延迟预算 + 缓存与降级 + 在线服务化
- **对话脚本**:
  1. 级联架构：召回（百万 → 2000，10ms）→ 粗排（2000 → 200，轻量模型 20ms）→ 精排（200 → 50，DeepFM 50ms）→ 重排（多样性 / 业务规则，10ms），总预算 200ms；画出架构图并解释每层「为什么用这个量级的模型」。
  2. 延迟治理：超时降级链——精排超时直接用粗排序（结果略差但可用）、特征服务超时用缺省值填充、极端情况返回缓存的上次结果；写一个带 deadline 传递的 `rank_with_timeout(50ms)` 包装。
  3. 缓存设计：召回结果短缓存（30s，同用户重复请求）、热门物品 embedding 常驻、模型在线推理批合并（攒 10ms 的请求合成 batch）；讨论哪些层缓存安全（召回）、哪些危险（精排受实时上下文影响）。
  4. laew 借鉴：级联漏斗对照 laew 的 Yolo 分类 → Main-Work 拆解 → SubAgent 执行三级漏斗——讨论「越往后越贵越精确」的通用架构原则下，laew 的 Yolo（一次 LLM 调用）是否相当于「粗排」、Plan（hard 才启用）相当于「精排」，以及中间缺不缺一层「粗排」。
