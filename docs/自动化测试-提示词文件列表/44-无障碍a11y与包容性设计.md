# 44 无障碍 a11y 与包容性设计

> 编号段 AS01–AS10 · 聚焦 WCAG 准则、ARIA、屏幕阅读器、键盘导航、色彩对比与无障碍测试

### AS01 WCAG 2.2 四原则与等级
- **预期档位**: simple
- **考察维度**: WCAG 标准 + 等级判定
- **对话脚本**:
  1. WCAG 的四大原则（Perceivable / Operable / Understandable / Robust）各自的核心目标是什么？各举两个具体失败案例。
  2. A / AA / AAA 三个等级在合规上的区别：法律强制（Section 508 / EAA）、行业标准、企业内规分别要求哪个？
  3. 给出一个 HTML 片段，从 WCAG 角度指出所有可访问性问题（缺 alt、缺 label、对比度不足、键盘不可达）。
  4. WCAG 2.2 新增的 9 条准则（如 Focus Not Obscured、Dragging Movements、Target Size）解决什么问题？

### AS02 ARIA：角色、属性与状态
- **预期档位**: medium
- **考察维度**: ARIA 语义 + 渐进增强
- **对话脚本**:
  1. ARIA 的三大类（Roles / States / Properties）分别表达什么？什么时候应该用、什么时候不应该用？
  2. 设计一个完全自定义的"标签页 + 面板"组件（Tab + TabPanel），写出完整 ARIA 属性（role/aria-selected/aria-controls/aria-labelledby）。
  3. aria-live 区域的三种 politeness（off/polite/assertive）使用场景：聊天消息、错误提示、严重警告怎么区分？
  4. ARIA 与原生 HTML 的优先级：第一规则"不要使用 ARIA"是什么意思？举出 3 个滥用 ARIA 的反模式。

### AS03 屏幕阅读器：VoiceOver / NVDA / JAWS
- **预期档位**: medium
- **考察维度**: 屏幕阅读器兼容性 + 实际听感
- **对话脚本**:
  1. VoiceOver（macOS/iOS）、NVDA（Windows）、TalkBack（Android）、Orca（Linux）四款屏幕阅读器支持的 ARIA 有哪些差异？
  2. 用 VoiceOver 朗读一段表单：label、required、错误信息应该按什么顺序朗读？HTML 结构怎么安排？
  3. 用 NVDA 测一个数据表格：表头（scope/headers）、可排序列、当前排序状态、单元格关联怎么实现？
  4. 测试屏幕阅读器的"地标"导航：banner / main / navigation / complementary 四个地标分别对应哪些 HTML 元素？

### AS04 键盘导航与焦点管理
- **预期档位**: medium
- **考察维度**: 焦点可达性 + 焦点陷阱
- **对话脚本**:
  1. Tab 顺序默认按什么规则？给一个"用 div + onClick 模拟按钮"的反例，说明为什么键盘不可达。
  2. 模态对话框（Modal）打开时焦点应该跳到哪里？关闭后焦点应该回到哪？完整焦点流程怎么设计？
  3. roving tabindex 是什么？在一个工具栏（toolbar）里怎么实现上下左右键切换焦点？
  4. 跳过链接（Skip Link）的实现细节：什么时候显示、跳转锚点、避免 SEO 影响，给出完整实现。

### AS05 色彩对比与色盲适配
- **预期档位**: medium
- **考察维度**: 对比度算法 + 色觉模拟
- **对话脚本**:
  1. WCAG 对正文、加大文字、图标、非文字 UI 的对比度要求分别是多少？用 WebAIM Contrast Checker 演示。
  2. 红绿色盲（Deuteranopia / Protanopia）占总人口 8%，图表里"红绿对比"会失真，怎么用色板 + 形状 + 标签三重编码？
  3. 用 Stark / Colour Contrast Analyser 演示一段配色方案，给出 4 种色盲模式下的模拟预览。
  4. 深色模式（Dark Mode）下对比度怎么保证？纯黑背景 + 纯白文字为什么不是好选择？

### AS06 替代文本与多媒体无障碍
- **预期档位**: simple
- **考察维度**: 替代内容 + 媒体可访问性
- **对话脚本**:
  1. `<img alt="">` 什么时候应该空？什么时候应该详细描述？装饰性、信息性、功能性图片各举例。
  2. 复杂图表（柱状图、流程图、思维导图）怎么提供无障碍替代？longdesc、aria-describedby、单独的文本描述各适用什么场景？
  3. 视频字幕（Captions）、音频描述（Audio Description）、转录稿（Transcript）三者的区别与适用法规。
  4. 用 WebVTT 或 SRT 写一段带说话人识别、音效描述的字幕文件示例。

### AS07 表单无障碍：标签、错误与提示
- **预期档位**: medium
- **考察维度**: 表单语义 + 错误恢复
- **对话脚本**:
  1. 用 `<label>` 还是 `aria-label` 还是 `aria-labelledby`？密码输入框的"显示密码"切换按钮怎么无障碍化？
  2. 表单验证错误怎么呈现？错误信息位置（错误位置 vs 顶部汇总）、aria-invalid、aria-describedby 怎么组合？
  3. 必填字段的视觉指示（红色星号）vs 语义指示（required + aria-required）怎么同时实现？
  4. 用 axe DevTools 测一个真实表单，列出所有 a11y 问题并给出修复代码。

### AS08 自动化无障碍测试：axe / pa11y / Lighthouse
- **预期档位**: medium
- **考察维度**: 自动化检测 + CI 集成
- **对话脚本**:
  1. axe-core / pa11y / Lighthouse / WAVE 四款主流无障碍检测工具的检测覆盖率、误报率、CI 友好度对比。
  2. 在 GitHub Actions 里集成 pa11y-ci，每次 PR 自动扫描核心页面，错误阈值怎么设？
  3. axe-core 测不到什么？动态内容、鼠标悬停、复杂交互的可访问性问题为什么自动化难覆盖？
  4. 关键用户流程（登录、结账、表单提交）的手工测试 checklist：每个流程需要用键盘、屏幕阅读器、放大镜各跑一遍。

### AS09 包容性设计：超越 WCAG
- **预期档位**: medium
- **考察维度**: 包容性 + 多样化用户
- **对话脚本**:
  1. WCAG 主要面向视障、运动障碍用户，认知障碍、色盲、听障、暂时性损伤（断臂/白内障术后）用户的特殊需求是什么？
  2. 认知无障碍：简洁的语言、清晰的导航、一致的布局、容错设计，分别给一个具体的 UI 例子。
  3. 老年人用户：字号、按钮大小、操作步骤、动画速度的优化策略，给出 Material Design Accessibility 的推荐。
  4. "无障碍优先"（Accessibility-First）与"渐进增强"（Progressive Enhancement）两种设计哲学的本质区别。

### AS10 无障碍法规与商业实践
- **预期档位**: simple
- **考察维度**: 合规要求 + 商业价值
- **对话脚本**:
  1. 美国 ADA、欧洲 EAA（2025 年生效）、英国 Equality Act、中国 GB/T 37668-2019 等法规的核心条款与处罚力度对比。
  2. 微软、谷歌、苹果、GitHub 在无障碍上的具体实践：Accessibility Insights、Chrome DevTools a11y tab、VoiceOver 官方指南。
  3. 一份无障碍声明（Accessibility Statement）应该包含哪些内容？放在网站哪个位置？法律效力如何？
  4. 商业层面：包容性设计如何扩大用户群体（占人口 15-20% 的残障人士 + 老年用户）？给出 3 个真实案例的 ROI 数据。
