### BP01 Design Token：从设计变量到多端产物
- **预期档位**: medium
- **考察维度**: Token 三层模型 + 多端编译
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下 Write `token_compiler.py`：定义三层 Token——`Reference`（`blue-500: "#3B82F6"`）→ `System`（`action-primary: "{blue-500}"`）→ `Component`（`button-bg: "{action-primary}"`），实现 `resolve(token_path)` 递归展开别名，演示 `button-bg` 最终值 `#3B82F6`。
  2. Bash 跑 `python3 tmpPlan/agent-test/token_compiler.py`，断言 `button-bg == #3B82F6`（grep -F 校验），印证三层模型解析正确。
  3. Read `token_compiler.py` 确认三层 dict 结构存在。再 Write `token_multipaltform.py`：把同一份 System Token 编译为多种产物——CSS Variables (`--color-action-primary: #3B82F6`)、Swift 扩展 (`Color.actionPrimary`)、Android XML (`<color name="action_primary">#3B82F6</color>`)，写到三个独立文件并对拍。
  4. Bash 跑 `python3 tmpPlan/agent-test/token_multipaltform.py` 并 grep -F 校验三种产物都含 `#3B82F6`，断言 `wc -l css.txt swift.txt android.txt` 之和 ≥ 9 行，用输出印证「单源 Token 多端产物」。

### BP03 主题与暗色模式：语义色与对比度
- **预期档位**: simple
- **考察维度**: 暗色模式 + WCAG 对比度 + 语义色
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下 Write `wcag_contrast.py`：实现 WCAG 对比度公式 `((L1+0.05)/(L2+0.05))`，其中 `L` 是相对亮度（`0.2126*R + 0.7152*G + 0.0722*B` 线性化后），计算 `#3B82F6` vs `#FFFFFF` 和 `#777` vs `#FFF` 的对比度。
  2. Bash 跑 `python3 tmpPlan/agent-test/wcag_contrast.py`，断言蓝白对比度 ≈ 4.5（AA 级通过）、`#777` vs `#FFF` ≈ 4.5（边界值，grep -E 校验），印证 WCAG 公式实现正确。
  3. Read `wcag_contrast.py` 确认 `relative_luminance` 函数被调用。再 Write `theme_switch.py`：模拟「暗色模式不是简单反色」——给亮色 token 定义暗色映射（`#FFFFFF→#1A1A1A` 而非 `#000000`、`#3B82F6→#60A5FA` 降饱和度），演示对比度维持。
  4. Bash 跑 `python3 tmpPlan/agent-test/theme_switch.py`，断言暗色模式 `bg=#1A1A1A`（非纯黑）且 `blue_500_dark` 与 `bg` 对比度 ≥ 4.5（grep -E 校验），用输出印证「暗色模式降饱和 + 提亮黑底」原则。
