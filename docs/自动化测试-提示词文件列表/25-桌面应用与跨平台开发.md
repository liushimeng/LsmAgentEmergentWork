# 自动化测试提示词 — 桌面应用与跨平台开发（Y01–Y10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**Electron 跨平台开发、Tauri 轻量级方案、
Qt 框架、GUI 布局管理、事件处理、数据绑定、
多线程 UI、系统托盘、本地存储、自动更新**等"桌面应用"垂直领域中的实战表现，
与 R 维度（Web 全栈）和 F 维度（界面设计）互补：
R 考察"浏览器端 Web 开发"，F 考察"界面设计方法论"，
本维度考察"原生桌面应用的开发与工程化"。
所有主题都以"动手写桌面应用代码"为核心，强调跨平台 GUI 工程能力。

---

### Y01 Electron 入门：用 Web 技术构建桌面应用
- **预期档位**: medium
- **考察维度**: Electron 架构 + 主进程/渲染进程 + IPC
- **对话脚本**:
  1. 解释 Electron 的架构：主进程（Node.js）和渲染进程（Chromium）怎么通信？
  2. 用 Electron + React 实现一个最小桌面应用：一个 Markdown 编辑器，左侧编辑、右侧预览。
  3. 加上文件系统操作：主进程处理文件读写，渲染进程通过 IPC 调用。
  4. 讨论：Electron 的"内存占用高"问题怎么缓解？什么场景下不该用 Electron？

### Y02 Tauri：Rust 构建轻量级桌面应用
- **预期档位**: hard
- **考察维度**: Tauri 架构 + Rust 后端 + Web 前端
- **对话脚本**:
  1. 对比 Tauri 和 Electron：为什么 Tauri 的包体和内存占用更小？两者的架构差异是什么？
  2. 用 Tauri + React 实现一个笔记应用：前端用 React，后端用 Rust 处理 SQLite 存储。
  3. 加上 Tauri 命令（Command）：前端通过 `invoke` 调用后端的 Rust 函数。
  4. 讨论：Tauri 的安全模型是什么？"允许列表（Allowlist）"怎么控制前端能调用哪些后端能力？

### Y03 GUI 布局管理：从绝对定位到响应式布局
- **预期档位**: medium
- **考察维度**: 布局系统 + 约束求解 + 响应式设计
- **对话脚本**:
  1. 解释 GUI 布局的两种范式：绝对定位（如 WinForms）和约束布局（如 Flutter / CSS Flexbox）。
  2. 用 Flutter 实现一个复杂布局：顶部导航栏 + 左侧菜单 + 右侧内容区 + 底部状态栏，支持窗口缩放。
  3. 讨论"布局溢出（Overflow）"的原因：当内容超出容器时，滚动、裁剪、换行三种处理方式各适合什么场景？
  4. 对比 Flutter 的 `Row`/`Column`/`Stack` 和 CSS 的 `flexbox`/`grid`，它们的布局算法有什么异同？

### Y04 事件驱动 UI：事件循环与状态管理
- **预期档位**: medium
- **考察维度**: 事件处理 + 状态管理 + 数据流
- **对话脚本**:
  1. 解释 GUI 事件循环（Event Loop）的工作原理：消息队列、事件分发、回调执行。
  2. 用 React + Redux 实现一个任务管理应用：添加/删除/编辑任务，状态集中存储在 Redux Store。
  3. 加上异步事件处理：点击"保存"后显示 loading，请求完成后更新 UI 或显示错误。
  4. 讨论：Redux 和 Zustand 两种状态管理方案各有什么优劣？什么时候该用全局状态 vs 局部状态？

### Y05 桌面应用的多线程：后台任务与 UI 响应
- **预期档位**: hard
- **考察维度**: 多线程 + Web Worker + 异步任务
- **对话脚本**:
  1. 为什么桌面应用不能在主线程做耗时操作？"UI 卡死"是怎么产生的？
  2. 用 Rust + Tauri 实现一个文件搜索应用：用户在搜索框输入时，后台线程遍历目录，主线程保持响应。
  3. 加上进度通知：后台搜索时，主线程实时显示"已扫描 1234 个文件"。
  4. 讨论：Electron 的 `worker_threads` 和 Web Worker 有什么区别？Tauri 的 `spawn` 是怎么管理后台任务的？

### Y06 系统托盘与通知：桌面集成
- **预期档位**: medium
- **考察维度**: 桌面集成 + 系统托盘 + 原生通知
- **对话脚本**:
  1. 解释系统托盘（System Tray）的作用：为什么很多应用关闭窗口后仍在托盘运行？
  2. 用 Electron 或 Tauri 实现一个托盘应用：最小化到托盘，右键菜单显示"显示主窗口"/"退出"。
  3. 加上桌面通知：定时提醒功能，触发系统原生通知（Windows/macOS/Linux 三平台适配）。
  4. 讨论：跨平台桌面应用在处理"平台差异"时的最佳实践是什么？怎么抽象出统一的 API？

### Y07 本地存储与数据持久化
- **预期档位**: medium
- **考察维度**: 数据存储 + 加密 + 数据迁移
- **对话脚本**:
  1. 桌面应用的本地存储方案有哪些（SQLite / IndexedDB / 文件系统 / LocalStorage）？各适合什么数据类型？
  2. 用 Tauri + SQLite 实现一个密码管理器：存储网站/用户名/密码，主密码加密数据库。
  3. 加上数据导出/导出：支持 JSON 和 CSV 格式，方便用户迁移到其他密码管理器。
  4. 讨论：桌面应用的"数据迁移"怎么设计？Schema 变更时如何兼容旧版本数据？

### Y08 自动更新机制：从检查到升级
- **预期档位**: hard
- **考察维度**: 自动更新 + 增量更新 + 签名验证
- **对话脚本**:
  1. 解释桌面应用自动更新的流程：检查版本 → 下载更新 → 验证签名 → 安装替换。
  2. 用 Tauri 的 `tauri-plugin-updater` 实现自动更新：应用启动时检查 GitHub Releases 是否有新版本。
  3. 加上增量更新：只下载差异部分而不是完整安装包，节省带宽。
  4. 讨论：自动更新的安全风险是什么？怎么防止"中间人攻击"替换更新包？代码签名证书的作用是什么？

### Y09 无障碍访问（Accessibility）：让应用人人可用
- **预期档位**: medium
- **考察维度**: 无障碍设计 + 屏幕阅读器 + 键盘导航
- **对话脚本**:
  1. 解释无障碍访问（a11y）的意义：为什么政府/企业采购常要求应用通过 WCAG 2.1 AA 级？
  2. 用 React 改进一个现有应用的无障碍性：添加 ARIA 标签、支持键盘导航、高对比度主题。
  3. 用屏幕阅读器（如 NVDA/VoiceOver）测试应用：验证所有功能都能不看屏幕完成。
  4. 讨论：Electron 和 Tauri 在无障碍支持上有什么差异？为什么很多桌面应用的无障碍性很差？

### Y10 跨平台构建与分发：打包、签名与发布
- **预期档位**: hard
- **考察维度**: 构建系统 + 跨平台打包 + 应用商店
- **对话脚本**:
  1. 解释桌面应用分发的三种方式：独立安装包（.exe/.dmg/.AppImage）、应用商店（Microsoft Store/Mac App Store）、便携版。
  2. 用 Tauri 的 `tauri-cli` 构建跨平台应用：在 Linux 上构建 Windows 和 macOS 版本（交叉编译）。
  3. 加上代码签名：Windows 的 Authenticode 签名和 macOS 的 Notarization（公证）。
  4. 讨论：为什么 macOS 应用需要"公证（Notarization）"？Windows SmartScreen 的"未知应用"警告怎么消除？
