# 自动化测试提示词 — 技术写作与知识沉淀（BC01–BC10）

> 使用说明:聚焦技术文档工程化:技术博客 / ADR / API 文档 / Runbook / Engineering Wiki / RFC / 技术分享;每条要求 laew 写文件 + 用脚本自动核对必备字段(grep / awk / diff),不用肉眼判断「写得好不好」。写作类必含金字塔原理落盘(结论先行/MECE/归纳演绎),且产出可被 check 脚本校验。

## 维度说明
考察 laew 产出可执行文档(文档+校验脚本)的能力:写作产物(Write)→校验脚本(Write)→运行断言(Bash)→修正重跑(Read+Bash)。金字塔原理、Runbook 章节、API 与签名一致性等「写作质量」必须规则化为可 grep 的结构。

### BC01 技术写作基础:金字塔原理与受众分析
- **测试状态**: 🔄 待重测（2026-09-11 脚本重写）
- **预期档位**: simple
- **考察维度**: 金字塔结构产物 / 受众落点断言
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlanagent-test/write/pyt.md` 写一份「异步编程选型」短文,严格按金字塔原理三段:结论先行(第一段 ≤50 字)+ MECE 分组(三段并列)+ 归纳/演绎(每段尾句加「因此...」)。
  2. `Bash` 跑 `awk 'NR==1{print length}' pyt.md` 断言第一段 ≤50 字符,`grep -cE '^(第一|第二|第三|因此)' pyt.md` 断言 ≥ 6 处 MECE 提示词。
  3. `Read` pyt 后写 `check_pyt.py` 用正则 `^结论|此外|因此` 检测「结论先行、并列连接词、归纳」三要素,`Bash` 跑退出码 0 且输出「PASS pyt pyramid」;任一要素缺失则重写短文后重跑。
  4. `Bash` 跑 `awk 'BEGIN{b=0} /^## (决策者|实现者|维护者)/{b++} END{print b}' pyt.md` 断言受众分层 = 3,缺失补齐三受众小结段后重跑。
