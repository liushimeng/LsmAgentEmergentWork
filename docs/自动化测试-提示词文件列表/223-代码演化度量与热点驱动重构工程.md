### HJ01 变更挖掘管道

- **预期档位**: medium
- **考察维度**: numstat 解析 / 口径治理 / 聚合
- **工具链**: Bash → Write → Bash
- **对话脚本**:
  1. Bash：在本仓库（或任一 git 仓库）采样：`git log --numstat --format=COMMIT:%H|%ad|%an --date=short -50 > tmpPlan/agent-test/hj01_raw.txt`（限制 50 条控制输出），观察格式：每 commit 头 + 若干 `增行\t删行\t路径` 行，重命名形如 `old => new`，二进制为 `-\t-\t`。
  2. Write `tmpPlan/agent-test/hj01_mine.py`：解析器：(a) 逐块归属到 commit（作者/日期）；(b) **口径三开关**：`skip_merge`（跳过合并提交避免双计）/ `follow_rename`（`{old => new}` 归一到新路径）/ `binary_zero`（`-` 记 0 行）；(c) 聚合：每文件 `{commits, added, deleted, churn=added+deleted, touch=commits}` 与每作者活跃度；(d) 排序输出 Top-10 高变更文件 Markdown 表；(e) **口径对比**：同数据开关 vs 不开关各跑一遍，输出差值表（证明合并双计会虚高 20%+ 的常见性）。
  3. Bash：`python3 tmpPlan/agent-test/hj01_mine.py tmpPlan/agent-test/hj01_raw.txt`，断言：解析无崩溃、Top-10 表有 10 行、口径对比表两列数值不全等。

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hj02_complexity.py`：复杂度代理计算器（**不建 AST，逐行启发**，支持 Python/JS/Go 三语）：(a) **分支关键词计数**：`if|elif|for|while|case|catch|&&|\|\|` 每命中 +1，加 1 为基数——即教科书圈复杂度 `M = 判定点 + 1` 的文本近似；(b) **函数切分**：Python 按缩进回落、JS/Go 按大括号深度回落，输出每函数 `{name, lines, branch_count, max_nest}`；(c) **嵌套深度**：括号/缩进层级最大值（深嵌套是可读性杀手，独立于 M 报告）；(d) **长函数与高复杂双阈值**：> 50 行或 M > 10 标 `REVIEW`；(e) 文档注释明确：文本近似与 AST 精确值的偏差来源（字符串里的 if、注释里的 if），并注明生产用 lizard/semgrep 精确实现。
  2. Bash：对自带的 40 行含 6 分支测试文件跑，断言 M = 7（6+1）、REVIEW 标记在构造的 80 行函数上命中；再对 `src/` 下任一真实文件跑不崩溃。
  3. Read 源码，再 Bash 断言：含三语言关键词表、含嵌套深度、含 lizard 生产建议注释。

### HJ03 热点图与重构优先级

- **预期档位**: hard
- **考察维度**: churn×复杂度四象限 / 优先级队列
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hj03_hotspot.py`：热点引擎（输入 = HJ01 churn 表 + HJ02 复杂度表，测试内置 mock 数据）：(a) **归一化**：churn 与复杂度各按 90 分位截断后 min-max 归一（防单点极值压扁全图）；(b) **四象限**：双高 = **热点（优先重构）** / 高churn低复杂 = 频繁小改（抽象候选）/ 低churn高复杂 = 稳定复杂（补测试即可，别动）/ 双低 = 忽略；(c) **优先级评分**：`score = 0.6×churn_n + 0.4×complexity_n` 排序输出队列（附建议动作：拆分/补测试/引入抽象）；(d) **ASCII 散点图**：40×20 字符栅格，`*` 为文件点，`H` 为双高热点，轴标注分位刻度；(e) 输出 Markdown 报告（Top-5 热点 + 各自建议）。

  3. Read 源码，再 Bash 断言：含 90 分位截断、含 0.6/0.4 权重、含四象限标签。
  4. Write `tmpPlan/agent-test/hj03_priority.md`：把 Top-5 整理成"重构提案卡"（文件/证据/动作/预估收益/风险），Bash 断言五卡齐全。

### HJ04 时间耦合与共变规则

- **预期档位**: hard
- **考察维度**: 共变对挖掘 / 候选抽象规则 / 噪声控制
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hj04_coupling.py`：时间耦合分析器（输入 commit→files 映射，mock 100 commits）：(a) **共变计数**：同 commit 同时出现的文件对计数（上三角避免重复）；(b) **支持度/置信度**：`sup = 共同提交数 / 总提交数`，`conf = 共同 / min(文件A提交数, 文件B提交数)`（"改 A 几乎必改 B"）；(c) **噪声控制**：sup ≥ 0.05 且 conf ≥ 0.7 才入榜（孤立提交对剔除）、单文件 commit 不产生对；(d) **规则输出**：`A ⇒ B (conf 0.82, sup 0.11)` 转译为"候选抽象：A 与 B 职责纠缠，考虑合并模块/提取公共层"；(e) **耦合簇**：并查集把高耦合文件聚簇，输出簇清单（簇 = 微服务/包拆分候选）；(f) 大仓性能注记：文件对计数 O(Σ|commit files|²)，超宽 commit（如批量格式化）设单 commit 文件数上限 20 跳过。
  2. Bash：mock 含 3 对强耦合 + 1 次批量格式化 commit（200 文件），断言：强耦合对全部 conf ≥ 0.7 入榜、宽 commit 被跳过、并查集输出正确簇数。
  3. Read 源码，再 Bash 断言：含 0.05/0.7 双阈值、含宽 commit 上限 20、含并查集聚簇。

### HJ05 知识分布与卡车因子

- **预期档位**: medium
- **考察维度**: 作者-文件矩阵 / bus factor / 孤岛知识
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hj05_knowledge.py`：知识分布分析（输入 commit→author,files，mock 5 作者 30 文件）：(a) **矩阵**：author×file 的提交数矩阵；(b) **truck factor 贪心**（Avelino 法）：循环——找覆盖剩余文件最多的作者移除并记数，直至有文件变"无人覆盖"，被移除作者数即 bus factor；(c) **孤岛文件**：仅 1 位作者曾提交的文件清单（**单点知识**）+ 该作者离职影响面（文件数/行数）；(d) **所有权计**：每文件主作者（提交占比 > 50%）与"公地文件"（无主作者）比例；(e) 输出：bus factor 值 + 孤岛 Top-10 + 各作者专注度（熵）表；**公平性注记**：度量用于结对/轮岗决策，不得用于绩效排名（反 Goodhart 注记）。
  2. Bash：mock 中构造 1 人独占 8 文件，断言 bus factor 触发时那 8 文件全在孤岛清单、公地文件比例输出正确。
  3. Read 源码，再 Bash 断言：含贪心循环、含熵计算、含反 Goodhart 注记。
