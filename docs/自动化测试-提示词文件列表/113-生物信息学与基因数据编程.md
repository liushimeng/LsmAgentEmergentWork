### DE01 FASTA/FASTQ 解析与测序质量统计

- **预期档位**: medium
- **考察维度**: 生信文件格式 / 质量值编码 / shell+Python 处理
- **对话脚本**:
  1. 两种核心格式：FASTA（`>` 头 + 序列行，存参考基因组）与 FASTQ（4 行一条：@ID / 序列 / + / 质量值，存测序原始 reads）；质量值是 Phred 分数的 ASCII 偏移编码（Phred+33：字符 '!'=0、'I'=40），Q30 表示千分之一错误率。
  2. 动手第一步：用 Python 写 FASTQ 解析器（注意序列/质量可折行、@ 开头也可能出现在质量行——必须按 4 行块解析），统计 reads 数、总长、N 含量。
  3. 基于上面的解析器，加质量统计：每个位置平均 Q 值画曲线（测序越往后质量越差）、Q20/Q30 碱基占比；讨论为什么 Q30 是二代测序的验收线。
  4. shell 联动：用 awk 单行命令统计 FASTQ 条数（行数/4），用 seqkit（或自写脚本）做长度分布直方图；讨论 GB 级文件为什么不能全读进内存（流式逐条处理）。

### DE02 双序列比对：Smith-Waterman 动态规划

- **预期档位**: medium~hard
- **考察维度**: 序列比对 / DP 填表 / 回溯
- **对话脚本**:
  1. 比对问题：两条 DNA 序列有多像、哪里突变/插入/缺失；先讲全局比对 Needleman-Wunsch vs 局部比对 Smith-Waterman 的区别（找整体相似 vs 找最像的片段）。
  2. Smith-Waterman 填表规则：打分矩阵（匹配 +2 / 错配 -1 / 空位 -2），`H[i][j] = max(0, 对角+match/mismatch, 上+gap, 左+gap)`；用两条 8bp 小序列手算完整 DP 表。
  3. 回溯：从表中最大值出发沿来源方向回退到 0，路径即比对结果；讨论「0 下界」的作用（局部性——负分清零重开）。
  4. 动手：用 Python 实现 50 行的 Smith-Waterman，比对 `ACACACTA` 与 `AGCACACA`，输出 DP 表与比对字符串（含 `-` 空位）；讨论 O(nm) 复杂度对基因组级序列为何不可行（引出 DE03）。

### DE03 BLAST 原理：种子与扩展

- **预期档位**: medium
- **考察维度**: 启发式搜索 / 种子索引 / 统计显著性
- **对话脚本**:
  1. DE02 的精确 DP 在亿级库面前太慢——BLAST 的启发式思路：先找短的精确匹配「种子」（word，DNA 默认 11bp），命中后再向两侧扩展；用「先按关键词定位、再细读上下文」的搜索类比讲清为什么快几个数量级。
  2. 种子索引：把库中所有 11-mer 预建成哈希表（词 → 位置列表），查询序列切词后直接查表；讨论 k-mer 长度权衡（k 大则快但漏、小则慢但全）。
  3. 统计显著性：E-value 的含义（随机库里期望出现这么高分匹配的次数），E < 1e-5 才算可信；讨论为什么原始分数要结合库大小校正。
  4. 动手：实现迷你 BLAST——建一个 100 条随机序列的 11-mer 索引，对一条查询找种子命中并局部扩展，对比 DE02 全比对的速度与结果差异。

### DE04 de novo 组装：de Bruijn 图

- **预期档位**: hard
- **考察维度**: 图算法应用 / k-mer / 欧拉路径
- **对话脚本**:
  1. 组装问题：测序把基因组打成海量短 reads（150bp），要拼回完整序列；de Bruijn 图方案——把每条 read 切成 k-mer，k-mer 是边、首尾 (k-1)-mer 是节点，图中的一条欧拉路径就对应一条组装序列。
  2. 用小例子手算：序列 `ATGCGT`、k=3，列出所有 k-mer 边与节点，画出图并找出路径；讨论 k 值选择（k 小图乱、k 大断点多）与测序深度不均的坑。
  3. 真实组装的困难：重复序列（转座子造成图分叉）、测序错误（产生「气泡」和「尖端」需要图清理）；当代 assembler（SPAdes 用多 k 迭代）怎么缓解。
  4. 动手：用 Python 实现迷你组装器——从模拟 reads 建 de Bruijn 图、清理低覆盖边、找欧拉路径输出 contig；用随机生成 200bp「基因组」+ 模拟 50bp reads 验证能拼回去。

### DE05 变异检测与 VCF 格式

- **预期档位**: medium
- **考察维度**: 变异类型 / VCF 解析 / 比对后处理
- **对话脚本**:
  1. 变异类型：SNP（单碱基替换）、Indel（小插入缺失）、SV（结构变异 >50bp）、CNV（拷贝数变异）；各用什么信号检测（比对不一致 / 插入大小异常 / 覆盖深度变化）。
  2. VCF 格式解剖：头（## 元信息）+ 每行一个变异（CHROM/POS/REF/ALT/QUAL/FILTER/INFO + 样本基因型 0/1）；解释 `0/1`（杂合）与 `1/1`（纯合）、QUAL 的 Phred 含义。
  3. 基于上面的格式，讨论变异检测流程：reads → BWA 比对参考基因组 → BAM（排序+去重）→ GATK/bcftools  calling → VCF → 注释（snpEff 标注变异落在哪个基因、同义/错义）。
  4. 动手：手写 VCF 解析器，统计一个示例 VCF 的 SNP/Indel 数量、转换/颠换比（Ti/Tv，正常人类约 2.0，偏离说明假阳性多）、按染色体分布。

### DE06 系统发育树构建

- **预期档位**: medium
- **考察维度**: 进化距离 / 建树算法 / 可视化
- **对话脚本**:
  1. 系统发育树要回答的问题：这些物种/序列谁和谁亲缘近；输入是多序列比对结果，核心是「距离」——两条序列差异位点占比（p-distance），可加 JC69 模型校正多次突变。
  2. 邻接法（NJ）：从星形树开始，迭代合并使总枝长最小的一对节点；用 4 条序列手算一棵 NJ 树；讨论 NJ（快、近似）vs 最大似然法（慢、准确）的适用规模。
  3. 树的表示与解读：Newick 格式 `((A,B),(C,D));`、分支支持度 bootstrap（重抽样 1000 次看该分支出现比例，>70 可信）；有根树 vs 无根树。
  4. 动手：用 Python 实现 p-distance 矩阵计算 + 简化 NJ，对 5 条人工设计的「进化」序列建树，输出 Newick；用 ete3/Biopython 或 ASCII 画出树形验证聚类是否符合设计。

### DE07 蛋白质结构数据：PDB 与 AlphaFold

- **预期档位**: simple~medium
- **考察维度**: PDB 格式 / 结构可视化数据 / AlphaFold 置信度
- **对话脚本**:

### DE08 单细胞 RNA-seq 分析管线

- **预期档位**: medium~hard
- **考察维度**: 单细胞数据 / 降维聚类 / UMI
- **对话脚本**:
  1. 单细胞测序的特殊性：每个细胞一个 barcode、每个分子一个 UMI（去 PCR 重复）；表达矩阵是「基因 × 细胞」的巨大稀疏矩阵（>90% 是 0）；为什么稀疏矩阵要用稀疏存储（scipy.sparse / CSR）。
  2. 分析管线全貌：质控（去掉基因数太少的死细胞、线粒体比例太高的受损细胞）→ 归一化（测序深度校正）→ 高变基因筛选 → PCA 降维 → 聚类（Louvain/Leiden）→ UMAP 可视化 → 细胞类型注释。
  3. 基于上面的管线，讨论每一步的生物学动机：为什么用 PCA 前先取 log、为什么聚类在 PCA 空间而非原始空间（降噪+加速）、双联体（两个细胞当一个测）怎么识别。
  4. 动手：用 scanpy（或纯 numpy 模拟）跑一个小数据集的质控+归一化+PCA，画出前两个主成分散点；讨论聚类数选择的主观性。

### DE09 生信工作流：Snakemake 规则化管线

- **预期档位**: medium
- **考察维度**: 工作流引擎 / 规则依赖 / 可复现性
- **对话脚本**:
  1. 生信分析几十步（质控→比对→去重→calling→注释），手工跑不可复现——Snakemake 用「rule：输出 ← 输入 + shell 命令」声明依赖，自动推导执行 DAG；写两个 rule 的最小 Snakefile 体会。
  2. 通配符与批量：rule 里的 `{sample}` 通配符让一条规则跑 100 个样本；`expand()` 生成所有目标文件列表；讨论这与 Makefile 模式规则的相似性（构建系统思想复用）。
  3. 工程化：每个 rule 独立 conda 环境（版本锁定可复现）、集群提交（slurm 一行配置）、断点续跑（Snakemake 自动跳过已存在的输出）、失败重试。
  4. 动手：写一个 3-rule 的 Snakefile（模拟：生成数据 → 统计 → 汇总报告），跑两遍验证第二遍全部跳过；删掉中间产物再跑，观察只重跑受影响的下游。

### DE10 基因数据的隐私与合规

- **预期档位**: simple~medium
- **考察维度**: 基因数据敏感性 / 法规 / 技术防护
- **对话脚本**:
  1. 基因数据为什么是最高敏感级：不可更改（泄露终身有效）、可识别个人（即使匿名也能通过亲属网络反推）、可推断疾病风险；2018 年「金赛药业/基因家谱破案」（金州杀手案）说明亲属数据库的连锁暴露。
  2. 法规框架：人类遗传资源管理条例（中国——采集/出境审批）、GDPR（基因数据属特殊类别第 9 条）、HIPAA（美国医疗）；讨论科研机构与商业检测公司（23andMe 类）的合规差异。
  3. 技术防护：数据脱敏的局限（基因无法真正匿名化）、差分隐私在 GWAS 统计中的应用、联邦学习让数据不出院（各医院本地计算只传梯度）、同态加密的前景与性能现状。
  4. 动手设计：给一个「医院基因组研究平台」写数据分级方案——原始 FASTQ/BAM（最高级，本地存储+审计）、VCF（高级，脱敏+审批）、聚合统计（中级，差分隐私后可共享）；列出每级的存储/访问/审计要求。
