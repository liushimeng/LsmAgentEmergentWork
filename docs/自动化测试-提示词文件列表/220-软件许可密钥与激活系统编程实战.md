### HF01 密钥格式与校验位设计

- **预期档位**: medium
- **考察维度**: 密钥编码 / 校验位 / 特性位图
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hf01_keyfmt.py`：密钥格式引擎（纯 Python 3.6 兼容，不用第三方库），实现：(a) **格式定义** `VVVV-CCCC-KKKK-KKKK-KKKK-C`：前 4 位版本+产品码（base32），C 段为**校验位**，K 段 12 位为 60 bit 载荷（随机数 + 特性位图）；(b) **base32 编解码**（RFC 4648 字母表去 0/1/O/L 防混淆）；(c) **校验位算法**：对载荷做 mod 32 加权和（权重 3/7 循环，类似 ISBN/卢恩算法思路），产生 1 字符校验位，能捕获**单字符误输**与**相邻换位**两类常见手输错误（写 4 组故意损坏样例验证）；(d) **特性位图**：60 bit 中低 10 bit 为特性开关（feature_pro/feature_cloud/feature_offline...），`decode_key()` 返回 `{version, product, features, checksum_ok}`；(e) `generate(product, features, seed)` 用 `random.Random(seed)` 可复现生成。
  2. Bash：`python3 -m py_compile tmpPlan/agent-test/hf01_keyfmt.py && python3 tmpPlan/agent-test/hf01_keyfmt.py > tmpPlan/agent-test/hf01_out.txt`，断言：同 seed 两次生成密钥完全一致、对 100 个随机密钥做单字符篡改后 `checksum_ok` 全部为 False、换位篡改检出 ≥ 95%。
  3. Read `tmpPlan/agent-test/hf01_keyfmt.py`，再 Bash 断言：源码含 base32 字母表定义、含 mod 32 加权、含 features 位图解码。

Write `tmpPlan/agent-test/hf02_sign.py`：密钥签名器：(a) **keygen**：用 `hmac` + `hashlib.sha256` 构造演示级"私钥签名"——私钥 `SK = os.urandom(32)`（seed 固定以便测试），派生"公钥指纹" `PK = sha256("pub"||SK)[:16]`；(b) **sign(payload)**：HMAC-SHA256(SK, payload) 截 32 hex；(c) **verify(payload, sig, PK_fp)**：服务端持有 SK 的镜像才能重算——演示"客户端只存公钥指纹 + 服务端验签"的职责分离；(d) 在文档注释里明确写清：**生产环境应使用非对称签名（Ed25519/ed25519-dalek/libsodium/RSA-PSS），客户端可离线验签且私钥永不进客户端**，HMAC 仅用于单机演示对称模型的教学差异；(e) 输出：签名/验签/防篡改（改 1 字节 payload 验签必败）三组演示。

### HF03 机器指纹与软绑定

- **工具链**: Write → Bash → Read → Bash

  1. Write `tmpPlan/agent-test/hf03_fingerprint.py`：机器指纹引擎：(a) **归一化采集**（跨平台、不强依赖真实硬件）：hostname（大小写归一）、platform.system()、CPU 核数、语言环境、用户名（如 `platform.node().lower()`），每项独立 sha256 取 8 hex 成**分量指纹**，共 5 个分量；(b) **注册指纹**：首次激活把 5 分量与权重存盘 `hf03_fp.json`；(c) **k-of-n 软匹配**：当前环境与注册指纹比对，**命中 ≥ 3/5 即认为同机**—— rationale：换网卡/改主机名/升级系统不应把正版用户锁死；(d) **漂移更新策略**：命中但分数 < 5/5 时"顺带刷新"注册表（防渐进漂移），但**连续 30 天内刷新超过 2 次则告警**（疑似克隆部署）；(e) **克隆检测**：同一密钥两份"环境快照"输入，分量完全一致 → 判定克隆；(f) 输出 JSON 判定报告。
