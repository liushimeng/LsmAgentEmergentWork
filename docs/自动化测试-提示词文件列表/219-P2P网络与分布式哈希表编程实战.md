### HE04 分块校验与端游戏

- **预期档位**: hard
- **考察维度**: piece SHA-1 / 请求管线 / 断点续传
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/he04_piece.py`：分块管理器：(a) 文件 → **piece**（256KB）切分，每 piece 的 SHA-1 与 .torrent pieces 串逐一对账；(b) piece → **sub-piece 请求块**（16KB）管线：在途请求数上限 5（经典 pipelining），乱序到达缓冲重组；(c) **校验失败处理**：重组后哈希不符 → 丢弃该 piece 全部块 + 坏 peer 记一次（累计 3 次拉黑）+ 重新向健康 peer 请求；(d) **端游戏（endgame）**：下载仅剩 <3 piece 时对所有拥有者广播请求，先到先用、迟到的直接丢弃（避免最后一块卡在慢 peer 上）；(e) **断点续传**：每 piece 完成/未完成**位图**（bitfield 消息）持久化 + 恢复时跳过已有（校验后入位）；(f) have 消息广播（完成一块通知全部 peer 更新彼此位图）。
  2. Bash：模拟 20 piece 文件含 2 块损坏注入，断言坏块重下成功、坏 peer 被拉黑、endgame 阶段总耗时缩短（对比无端游戏基线）、断点恢复后不重复下载已完成块。
  3. Read 源码，再 Bash 断言：含 16KB 管线、含拉黑计数、含位图持久化。

- **预期档位**: hard
- **考察维度**: 上传槽 / optimistic / anti-snub
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/he06_titfortat.py`：激励引擎：(a) **choked 状态**：每 10 秒重算上传槽——按「对方给我下载的速率」排序取前 **4** 个 unchoke（tit-for-tat：合作换合作，leecher 白嫖被断供）；(b) **optimistic unchoke**：第 5 槽随机轮换给一个 choked 节点（给新来者/被误伤者机会，发现更好的上游）；(c) **anti-snub**：连续 30 秒从对方收不到数据（被冷落）→ 视为 snubbed，主动 choke 并把机会挪给 optimistic；(d) **做种期角色转换**：下载完成后按「历史上传量/稀有贡献」分配（留种激励）；(e) **token bucket 限速**（上传上限 KB/s 与槽位均分 + 突发）；(f) 输出：30 轮模拟的每节点上/下载量报表——断言白嫖者（只下不上）累计下载量被压制、合作者互惠增长。

  3. Read 源码，再 Bash 断言：含 10 秒重算、含 anti-snub、含白嫖压制数据。
