# 自动化测试提示词 — 嵌入式系统与物联网开发（AH01–AH10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度从 Agent 能力视角考察**嵌入式/物联网工程链路**：无硬件可用，python3 模拟寄存器/MQTT broker（本地 socket）/FreeRTOS 调度器（协程模拟），C 代码可 gcc 编译主机跑。覆盖任务调度、传感器采集、协议栈、安全启动、CAN 总线、IoT 平台等主题。所有产物落在 `tmpPlan/agent-test/` 沙盒内，零外网依赖。

### AH01 RTOS 任务调度入门
- **预期档位**: medium
- **考察维度**: 任务模型 / 调度策略
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `rtos_sim.py`：用 `asyncio` 模拟 FreeRTOS 两个任务（读传感器 + 上报数据）+ 队列通信。`task_sensor` 每 100ms 模拟读一次数据入队，`task_uploader` 阻塞等待队列出队上报。Bash 跑 `python3 rtos_sim.py` 期望 1 秒内采集 10 次、上报 10 次。Read 验证 `asyncio.Queue` 实现。
  2. 故意把队列 `maxsize` 设成 1 且 sensor 比 uploader 快 2 倍，期望 sensor 偶发阻塞（不丢数据）。跑 `time` 命令验证总时长仍 ≈ 1 秒（不堆积）。
  3. 优先级反转演示：写 `inversion_sim.py`，三个任务（高/中/低优先级共享互斥锁）。`low_task` 持锁 → `high_task` 等锁被 `mid_task` 抢占 → `high_task` 等待超时。期望输出含 `priority inversion detected`。Read 验证检测分支。
  4. 优先级继承修复：加 `priority_inherit` mutex，期望 `high_task` 等待期间 `low_task` 继承高优先级不被 `mid_task` 抢占。写 `rtos-notes.md` 总结优先级继承三场景（不超过 8 行）。

### AH02 ESP32 物联网节点
- **预期档位**: medium
- **考察维度**: 传感器 + 无线 / 低功耗
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `esp32_sim.py`：模拟 ESP32 + DHT22 温湿度采集（`temperature = 20 + random.gauss(0, 1)`）+ 本地 MQTT broker（`socket` 起 127.0.0.1:1883）+ publish 到 broker。Bash 跑 `python3 esp32_sim.py` 期望输出 `published: temp=.. humidity=..`。
  2. 低功耗周期：写 `power_cycle.py`，模拟深度睡眠 30s → 唤醒 → 采集 → 上报 → 再睡眠的循环。`time.time()` 记录实际 wall 时长，期望总时长 ≈ 30s/cycle。Read 验证 sleep 期间 CPU 占用模拟（`psutil.cpu_percent`）。
  3. OTA 升级：`ota_sim.py` 模拟分两区（A/B）+ 签名验证（`hashlib.sha256`）。构造「下载新固件 → 验签 → 切 B 区启动」流程；故意篡改固件 1 字节，期望验签失败回滚 A 区。Read 验证回滚逻辑。
  4. 写 `iot-node-notes.md`：ESP32 vs STM32WL（LoRa）vs nRF52（BLE）在物联网场景的适用边界（功耗/距离/带宽三维度），表格形式不超过 8 行。

### AH03 嵌入式 C：寄存器操作与位域
- **预期档位**: medium
- **考察维度**: 硬件抽象 / 位操作
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `led_hal.c`（STM32 HAL 库点亮 LED 伪代码，编译时不依赖真实硬件）与 `led_reg.c`（直接寄存器操作 `#define GPIOA_ODR *(volatile uint32_t*)0x40020014`）。`gcc -c -o /dev/null led_hal.c led_reg.c` 期望两者编译通过。
  2. python3 写 `bitfield_equiv.py`：用 `ctypes` 或 `struct` 模拟 STM32 UART 配置寄存器（`bit-field` 模式 + 位掩码模式）。两种方式生成同一组配置（波特率 9600、数据位 8、停止位 1、无校验）并比对最终寄存器值，期望 `==`。
  3. `volatile` 演示：写 `volatile_demo.c`，`uint8_t flag = 0; while(!flag);` 无 volatile 编译器可能优化成死循环；加 volatile 强制每次读内存。`gcc -O2 -S volatile_demo.c` 期望加 volatile 版汇编里有 `movzbl` 每次加载。
  4. UART 波形反推：`python3 -c "import numpy"`（探测）后写 `uart_decode.py`：模拟给定波形（位序列），反推波特率（位宽单位时间）、数据位、停止位、校验位。跑 3 组已知波形期望反推参数与生成参数一致。Read 验证解码算法。

### AH04 物联网协议：MQTT/CoAP/LwM2M
- **预期档位**: medium
- **考察维度**: 协议对比 / QoS 语义
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `mqtt_broker_sim.py`：纯 python 用 `socket` 起 MQTT-like broker（监听 1883 端口，解析 CONNECT/SUBSCRIBE/PUBLISH 帧）。`command -v mosquitto` 探测；若不可用纯 python 模拟。
  2. 客户端：`mqtt_client.py` 发布 QoS 0/1/2 三种消息。QoS 2 流程：`PUBLISH → PUBREC → PUBREL → PUBCOMP`，期望 4 步日志齐全；故意跳过 PUBREL，期望 broker 报错。
  3. 100 个并发设备模拟：`mqtt_load.py` 用 `asyncio.gather` 同时跑 100 个 client publish。期望 broker 接收消息总数 = 100 × msgs_per_client，无丢包。
  4. CoAP 块传输：`coap_sim.py` 模拟大 payload 分块传输（每块 64 字节）+ 重传。构造「丢块 3」场景，期望客户端自动重传并最终拼回完整 payload。写 `iot-protocol-notes.md` 总结 MQTT vs CoAP vs LwM2M 的适用场景，不超过 10 行。

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:

  4. 边缘 vs 云分工：写 `edge_cloud_split.md` 给出延迟/带宽/隐私三维度决策框架；不超过 10 行。

### AH06 嵌入式 Linux：Buildroot/Yocto 静态分析
- **预期档位**: hard
- **考察维度**: 系统构建 / 根文件系统
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `buildroot_config.yml`（最小根文件系统配置：busybox + dropbear + 自定义 app）与 `yocto_config.yml`（含 layer 层级）。python3 `config_diff.py` 对比两者：Buildroot 期望 `BR2_ROOTFS_OVERLAY` 字段、Yocto 期望 `BBMASK` 字段。

### AH07 实时系统：确定性延迟与中断
- **预期档位**: medium
- **考察维度**: 实时性 / 中断管理
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `realtime_sim.py`：模拟硬实时（工业控制 RT ≤ 1ms）、软实时（音视频 RT ≤ 50ms）、非实时（汽车信息娱乐 RT ≤ 1s）。`python3 realtime_sim.py --sim industrial` 期望中断响应延迟分布 P99 < 1ms。
  2. 中断延迟分解：`latency_breakdown.py` 模拟 ARM Cortex-M 中断延迟组成（硬件响应 + 保存现场 + ISR 执行 + 中断返回）。期望总延迟 = 各组件和，误差 < 1%。
  3. FreeRTOS ISR API：`isr_api_sim.py` 区分 `xQueueSend`（任务用）与 `xQueueSendFromISR`（中断用）。故意在 ISR 内调用非 FromISR 版本，跑 `--lint` 期望警告。
  4. GPIO 抖动模拟：`jitter_sim.py` 用 `time.perf_counter_ns()` 测 1000 次 GPIO 翻转间隔，统计抖动（标准差）。故意加 `time.sleep(random)` 模拟中断屏蔽，期望抖动显著增加。写 `realtime-notes.md` 总结抖动来源与改善方案。

### AH08 物联网安全：设备身份与固件保护
- **预期档位**: medium
- **考察维度**: 设备认证 / 安全启动
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `secure_storage_sim.py`：模拟 SE/TPM/TrustZone 三种密钥存储。SE 模拟 `HardwareSecurityElement` 类（`store_key/get_key` 走模拟硬件）、TPM 模拟 `TPM2` 类、TrustZone 模拟 `SecureWorld` 类。跑 `python3 secure_storage_sim.py` 期望三者都能正确存取 256-bit 密钥。
  2. 安全启动链：`secure_boot_sim.py` 模拟 ROM → bootloader → kernel → rootfs 验签（`hashlib.sha256` + RSA 签名校验）。故意篡改 rootfs 1 字节，期望验签失败并阻止启动。Read 验证验签链。
  3. 固件加密：`fw_encrypt_sim.py` 用 AES-GCM 加密固件（AES key 从硬件派生）。跑解密 + 验签期望两步都通过。故意改 firmware 1 字节，期望解密后验签失败。
  4. OTA MITM 防御：`ota_mitm_sim.py` 模拟中间人替换固件攻击。构造「正常下载」「恶意替换」两场景，期望恶意替换触发验签失败 + 回滚到老版本。写 `iot-security-notes.md` 总结 SE/TPM/TrustZone 成本区间与适用产品。

### AH09 CAN 总线与汽车电子
- **预期档位**: hard
- **考察维度**: 车载通信 / 协议栈
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `can_sim.py`：纯 python 模拟 CAN 总线（仲裁 + 错误帧 + 数据帧）。构造 3 节点同时发送场景，期望最低 ID 节点赢得仲裁。Read 验证仲裁算法。
  2. python-can 等价：`can_listener.py` 用 `socket` 起本地 CAN-like 总线（127.0.0.1:1888），监听特定 ID 帧（如 `0x123`）、解析数据场（如第 1-2 字节是 RPM，第 3-4 字节是速度）。跑 `--listen` 期望打印解析后的物理量。
  3. CAN FD 对比：`canfd_sim.py` 与经典 CAN 对比帧格式（CAN FD 数据段最长 64 字节 vs CAN 8 字节）和速率（CAN FD 5Mbps vs CAN 1Mbps）。构造同一 payload 跨两版发送，期望 CAN FD 帧数明显少。
  4. UDS 诊断：`uds_sim.py` 实现 0x22（按 ID 读数据）与 0x2E（按 ID 写数据）服务。跑 `--test read 0xF190` 期望返回 ECU 零件号；写 `0xF190` 期望更新成功。Read 验证 UDS 协议帧格式。

### AH10 物联网平台：从设备到云端

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
