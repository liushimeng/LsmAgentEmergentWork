# 自动化测试提示词 — 综合场景与跨领域实战（K01–K10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**复杂任务、跨领域应用、综合实战**等场景中的表现，
涵盖多工具协作、完整应用开发、自动化工作流、数据分析管道、
DevOps 实践、产品思维、项目管理、跨语言开发等综合性主题。

---

### K01 多工具协作任务
- **预期档位**: hard
- **考察维度**: 工具编排 + 流程串联
- **对话脚本**:
  1. 我要做一个"代码质量日报"：从 Git 拉取最近一天提交 → 统计变更行数 → 找出改动最多的文件 → 生成报告。请设计流程。
  2. 用 Bash 实现这个流程的脚本，要求可重复运行、输出格式统一。
  3. 把报告保存到 `tmpPlan/代码质量日报_20260909.md`，包含关键指标和建议。
  4. 讨论：这个任务中哪些环节可以并行？如果数据量很大，怎么优化性能？

### K02 完整应用开发
- **预期档位**: hard
- **考察维度**: 端到端交付能力
- **对话脚本**:
  1. 开发一个"个人知识管理工具" CLI：支持添加笔记、按标签搜索、导出 Markdown。设计功能列表。
  2. 用 Rust 实现核心功能，包含数据模型、存储层（SQLite）、命令行接口。
  3. 添加单元测试和集成测试，测试覆盖率目标 70% 以上。
  4. 写一份 README 说明安装、使用、贡献方式，把项目保存到 `tmpPlan/knote/`。

### K03 自动化工作流设计
- **预期档位**: hard
- **考察维度**: 流程自动化 + 错误处理
- **对话脚本**:
  1. 设计一个"代码提交前自动检查"工作流：代码格式化 → 静态检查 → 单元测试 → 构建验证。
  2. 用 Git Hooks 或 Makefile 实现这个工作流，要求任一步失败就中止提交。
  3. 如果团队中有人跳过了 hook（`--no-verify`），怎么在 CI 层面兜底？
  4. 讨论"本地检查"和"CI 检查"的分工：哪些该本地做，哪些该 CI 做？

### K04 数据分析管道
- **预期档位**: hard
- **考察维度**: 数据处理全流程
- **对话脚本**:
  1. 我有一份网站访问日志（1GB），要分析"用户留存率"，请设计数据处理流程。
  2. 用命令行工具（awk/sort/uniq）或脚本实现：清洗 → 去重 → 统计 → 输出。
  3. 把分析结果可视化（生成图表或 HTML 报告），保存到 `tmpPlan/留存分析/`。
  4. 讨论：1GB 日志用命令行处理 vs 用数据库加载，各自的性能瓶颈在哪？

### K05 DevOps 实践入门
- **预期档位**: medium
- **考察维度**: 运维自动化 + 基础设施即代码
- **对话脚本**:
  1. 什么是 DevOps 的 CALMS 模型？每个字母代表什么？
  2. 为 laew 设计一个 GitHub Actions CI 工作流：提交 PR 时自动跑 `cargo test` 和 `cargo clippy`。
  3. 如果要自动发布 release（编译多平台二进制 + 上传），工作流应该怎么扩展？
  4. 讨论"基础设施即代码"（IaC）的概念，laew 的部署脚本是否符合 IaC 原则？

### K06 产品思维与需求分析
- **预期档位**: medium
- **考察维度**: 产品视角 + 用户洞察
- **对话脚本**:
  1. 用"用户故事"格式描述 laew 的三个核心功能，遵循"作为…我想要…以便…"模板。
  2. 为"多 Agent 协作"功能画一个用户旅程图：从启动到完成任务的完整体验。
  3. 识别这个旅程中的"痛点时刻"，给出改进建议。
  4. 讨论"技术驱动"和"用户驱动"产品开发模式在 laew 这种开源工具中的平衡。

### K07 项目管理实战
- **预期档位**: medium
- **考察维度**: 项目规划 + 风险管控
- **对话脚本**:
  1. 用"用户故事地图"规划 laew 的下一个版本（0.2.0），列出至少 8 个故事。
  2. 按 MoSCoW 法则（Must/Should/Could/Won't）给故事排优先级。
  3. 识别 Top 3 风险，设计应对预案和触发条件。
  4. 设计一个 4 周的迭代计划，包含每周的交付目标和验收标准。

### K08 跨语言互操作
- **预期档位**: hard
- **考察维度**: FFI + 多语言协作
- **对话脚本**:
  1. Rust 调用 Python 代码有几种方案（PyO3/子进程/IPC）？各有什么权衡？
  2. 如果 laew 要集成一个 Python 写的 NLP 库，推荐哪种方案？给出理由。
  3. 用 PyO3 写一个最小示例：Rust 调用 Python 的 `jieba` 分词。
  4. 讨论"多语言项目"的调试难点：跨语言调用栈怎么追踪？日志怎么统一？

### K09 性能压测与优化
- **预期档位**: hard
- **考察维度**: 系统性性能工程
- **对话脚本**:
  1. 设计一个 laew 的压测方案：模拟 10 个并发用户，每个发 5 轮对话，测量响应时间和错误率。
  2. 用 `wrk` 或 `k6` 写出压测脚本（mock LLM 端点），运行并记录结果。
  3. 分析压测结果：瓶颈在哪（CPU/内存/IO/网络）？给出优化建议。
  4. 讨论"性能优化"的正确顺序：先测量再优化，还是先猜再验证？为什么？

### K10 开源项目运营
- **预期档位**: medium
- **考察维度**: 社区建设 + 项目治理
- **对话脚本**:
  1. 一个健康的开源项目需要哪些文档？（README/CODE_OF_CONDUCT/CHANGELOG 等）各解决什么问题？
  2. 为 laew 设计一个 Issue 模板：bug report 和 feature request 各一份。
  3. 设计一个 PR 审查清单（checklist），确保代码质量。
  4. 讨论"维护者时间有限"的情况下，如何设计社区贡献流程来降低维护成本？
