# 自动化测试提示词 — 综合场景与跨领域实战（K01–K10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**综合场景、跨领域应用、复杂任务**等方面的表现，
涵盖全栈项目开发、数据分析流水线、自动化运维、技术调研、产品原型等复杂场景。

---

### K01 全栈项目开发
- **预期档位**: hard
- **考察维度**: 端到端开发能力
- **对话脚本**:
  1. 我要开发一个"个人记账本"Web 应用，请帮我做技术选型（前端、后端、数据库、部署）。
  2. 设计数据库表结构，包含账户、交易记录、分类、预算。
  3. 实现后端 API：记账、查询月度统计、导出 CSV。
  4. 写一个简单的 HTML 前端页面，能调用 API 展示数据。

### K02 数据分析流水线
- **预期档位**: hard
- **考察维度**: 数据处理全流程
- **对话脚本**:
  1. 我有一份电商销售数据（CSV），请设计一个数据分析流水线：清洗 → 转换 → 分析 → 可视化。
  2. 数据清洗：处理缺失值、异常值、重复记录。
  3. 分析：按时间、地区、品类三个维度做销售分析。
  4. 生成分析报告，包含关键发现和可操作建议。

### K03 自动化运维脚本
- **预期档位**: medium
- **考察维度**: 运维自动化 + 监控告警
- **对话脚本**:
  1. 写一个服务器监控脚本：监控 CPU、内存、磁盘、网络，超过阈值时告警。
  2. 脚本要支持配置文件，可以自定义监控项和阈值。
  3. 添加日志功能，记录每次检查的结果。
  4. 如何把这个脚本部署为 systemd 服务，实现开机自启？

### K04 技术调研报告
- **预期档位**: hard
- **考察维度**: 调研分析 + 方案对比
- **对话脚本**:
  1. 调研 5 个开源的 AI Agent 框架，对比它们的特点和适用场景。
  2. 从架构设计、扩展性、社区活跃度四个维度做评估。
  3. 如果要为 laew 选择一个可参考的框架，你推荐哪个？为什么？
  4. 把调研报告保存到 `tmpPlan/AI_Agent框架调研.md`。

### K05 产品原型设计
- **预期档位**: hard
- **考察维度**: 产品设计 + 原型实现
- **对话脚本**:
  1. 设计一个"AI 辅助写作助手"产品的核心功能和信息架构。
  2. 画出主要页面的线框图（用 ASCII 或文字描述）。
  3. 实现一个可交互的 HTML 原型，包含核心功能演示。
  4. 写一份产品需求文档（PRD）摘要，包含用户故事和验收标准。

### K06 微服务架构设计
- **预期档位**: hard
- **考察维度**: 系统设计 + 服务拆分
- **对话脚本**:
  1. 一个单体应用要拆分为微服务，拆分原则是什么？
  2. 为一个电商系统设计微服务拆分方案：用户、商品、订单、支付、库存。
  3. 服务之间如何通信？对比 REST、gRPC、消息队列的适用场景。
  4. 微服务架构引入了哪些复杂性？如何治理？

### K07 容器化部署方案
- **预期档位**: medium
- **考察维度**: Docker + 部署实践
- **对话脚本**:
  1. 为 laew 编写一个 Dockerfile，使用多阶段构建减小镜像体积。
  2. 编写 docker-compose.yml，包含 laew 和它的依赖服务。
  3. 如何持久化 laew 的数据（SQLite 数据库）？
  4. 生产环境部署需要考虑哪些安全性和可靠性问题？

### K08 CI/CD 流水线设计
- **预期档位**: hard
- **考察维度**: 持续集成 + 持续部署
- **对话脚本**:
  1. 为 laew 设计一个 GitHub Actions CI 流水线：代码检查、测试、构建、发布。
  2. 如何配置多平台构建（Linux/macOS/Windows）？
  3. 自动化测试应该包含哪些环节？如何并行执行？
  4. 发布流程：如何自动生成 CHANGELOG 和 Release Notes？

### K09 性能压测与优化
- **预期档位**: hard
- **考察维度**: 性能测试 + 瓶颈分析
- **对话脚本**:
  1. 如何对 laew 的 API 进行性能压测？介绍压测工具和指标。
  2. 设计一个压测场景：模拟 100 个并发用户同时发送请求。
  3. 压测结果分析：如何识别性能瓶颈（CPU/内存/IO/网络）？
  4. 给出优化建议，按预期收益排序。

### K10 技术选型决策
- **预期档位**: medium
- **考察维度**: 技术评估 + 决策框架
- **对话脚本**:
  1. laew 要新增一个功能，需要在三个技术方案中做选择，你会怎么评估？
  2. 技术选型的评估维度有哪些（性能、成本、复杂度、生态、团队熟悉度）？
  3. 如何避免"因为熟悉而选择"的偏见？
  4. 写一份技术选型报告模板，包含必要的章节和评估标准。
