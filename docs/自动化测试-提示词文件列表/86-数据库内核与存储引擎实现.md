## 与 laew 工程的具体对接点

1. **CD01 → SQLite 索引**：当前 `providers` / `session_memory` / `agent_memory` 表已用 B+ 树索引（SQLite 内置），无需自实现。
2. **CD02 → LSM 评估**：laew 写多读少场景可考虑 RocksDB（嵌入式 LSM），但当前 SQLite 已足够，无需替换。
3. **CD03 → 会话 MVCC**：未来 laew 支持「时间旅行」查看历史 Session 时，可参考 MVCC 版本链 + 软删除。
4. **CD04 → WAL 持久化**：laew 的 SQLite 已开 WAL 模式，但可在 SubAgent 失败时额外写「操作日志」便于事后回放。
5. **CD09 → 多引擎**：laew 当前单 SQLite，未来若做会话数据分析可考虑 DuckDB 嵌入式 OLAP，无需独立服务。
