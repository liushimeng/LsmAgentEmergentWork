### CS01 金额精度：为什么永远不用 float 存钱

- **预期档位**: medium
- **考察维度**: 浮点陷阱 + 整数分存储 + decimal 选型
- **对话脚本**:
  1. 事故复现：用 Python 演示 `0.1 + 0.2 != 0.3`、以及「账户 1000000.00 元反复 +0.1 一万次后再减同量」的累计漂移；解释 IEEE 754 二进制小数无法精确表示十进制小数，金额误差在亿万级流水下不可接受。
  2. 工程解法一：整数化——以「分」为最小单位存 i64（最大 ~9.2 × 10^18 分足够），金额显示层再格式化为元；用 Rust 定义 `Money(i64)` newtype 实现加减乘（乘法带舍入策略 `banker's rounding` 银行家舍入）与除法分摊（remainder distribution：把 10 分摊 3 份得 3/3/4 而不是 3/3/3 丢 1 分）。
  3. 工程解法二：decimal——Python `decimal.Decimal`（上下文精度 28 位）/ Rust `rust_decimal` / 数据库 `DECIMAL(20,4)`；说明汇率、利率计算（连续乘法）更适合 decimal，而账务余额适合整数分，给出混用边界。
  4. laew 借鉴：金额舍入策略「损失必须可解释」对照 laew 的 token 估算（字符/4 + 10%）——估算误差不会丢钱但会导致压缩触发时机漂移，讨论给估算加「保守偏差」（宁可早压不可溢出）的设计取向与银行家舍入的保守性同源。

### CS02 复式记账与分户账

- **预期档位**: hard
- **考察维度**: 借贷平衡 + 科目表 + 试算与月结
- **对话脚本**:
  1. 复式记账原理：每笔交易「有借必有贷、借贷必相等」——用户充值 100 元记两条：`借 现金 100 / 贷 用户余额-用户A 100`；解释为什么这个不变量能天然防「钱凭空出现/消失」，比单式余额表强在哪。
  2. 数据建模：`accounts(id, code, name, type)` 科目表（资产/负债/权益/收入/费用 五类，借贷方向相反）+ `entries(id, txn_id, account_id, direction, amount)` 分录表，一笔交易的多个分录共享 `txn_id`；用 SQLite 建表并写「入参校验：Σ借 == Σ贷 否则整笔拒绝」的触发器或事务代码。
  3. 余额与试算：账户余额 = 该科目全部借贷分录的带方向汇总；写「试算平衡表」查询（全部科目借方合计 == 贷方合计）与月末结转（收入费用科目清零转入权益）的实现。
  4. laew 借鉴：借贷不变量对照 Agent 任务审计——每轮 Agent 循环的「输入 token 与输出 token、工具调用次数」也可以做成「配平」的流水（消耗与产出必须能对账），讨论 Debug 报告加一张「资源借贷表」核对成本流向。

### CS03 账务流水：幂等、冲正与对账内核

- **预期档位**: medium~hard
- **考察维度**: 流水号设计 + 幂等写入 + 冲正模式
- **对话脚本**:
  1. 流水表设计：`ledger(txn_id 唯一键, biz_no 业务单号, entries..., status, created_at)`；同一业务号重复请求靠唯一键冲突返回已有结果（幂等）；写 SQLite 的 `INSERT ... ON CONFLICT(txn_id) DO NOTHING` + 查询回读的幂等写入函数。
  2. 冲正（reversal）：记错账不 UPDATE 原记录，而是追加一笔「方向相反的冲正分录」+ 新的正确分录，账本 append-only；解释为什么审计要求数据不可变，UPDATE 会破坏证据链。
  3. 三方差对账内核：本地账 vs 支付渠道账 vs 银行账——按日期拉三方流水按业务号 join，diff 出「本地有渠道无（掉单）/ 渠道有本地无（漏单）/ 金额不一致」三类差异并输出报告；写出对账 SQL 与差异分类逻辑。
  4. laew 借鉴：append-only 冲正对照 laew 的 `/rewind`——当前实现是「快照 + 截断」，对照账本思想讨论「回退不删除、以标记 + 新分支延续」（`/fork` 已有此意）如何让回退可追溯。

### CS04 K 线聚合与时间对齐

- **预期档位**: medium
- **考察维度**: tick→bar 聚合 + 时区收盘 + 缺口处理
- **对话脚本**:
  1. tick 聚合：原始成交流 `(time, price, volume)` 按时间桶聚合成 OHLCV——open 首价 / close 末价 / high-low 极值 / volume 求和；用 Python（pandas resample 或手写桶循环）把逐笔聚成 1 分钟线，再从 1 分钟滚到 5 分钟 / 60 分钟（注意从原始 tick 聚 vs 从 1 分钟二次聚的 high 丢失问题）。
  2. 时区与交易日历：A股 09:30-11:30/13:00-15:00、美股含盘前盘后、加密 7×24——「日 K 的边界」由交易所日历定义而不是自然日；写一个交易日历模块（节假日表 + 时段表）并处理周一部分地区周日开盘的极端时区案例。
  3. 缺口与对齐：停牌 / 无成交分钟产生空洞——前向填充 close、volume 填 0；多标的对齐做矩阵（按共同时间索引 reindex），讨论「前向填充」对指标计算的污染（联动 CS05 的 RSI 失真）。
  4. laew 借鉴：时间桶对齐对照 Debug trace 的时间统计——多个 Agent 并行执行时各自记录起止时间戳，聚合报告要按统一时间轴对齐（同一墙钟）才能画甘特图，讨论时区 / 单调时钟（monotonic vs wall clock）的选择。

### CS05 技术指标计算：MACD / RSI / 布林带

- **预期档位**: medium
- **考察维度**: 指标公式 + 向量化实现 + 未来函数陷阱
- **对话脚本**:
  1. 用 Python 向量化实现三个经典指标：EMA（递推 `ema = α·price + (1-α)·ema_prev`，α = 2/(N+1)）、MACD（快慢 EMA 差 + 差的 EMA 信号线 + 柱）、RSI（涨幅均值与跌幅均值之比 `100 - 100/(1+RS)`，Wilder 平滑）；禁止 for 循环逐行版，全部用 pandas 滚动窗口。
  2. 布林带：中轨 N 日均线 ± k 倍标准差（注意 ddof=0 还是 1 的差异）；用布林带做一个「触及下轨买入 / 上轨卖出」的朴素策略信号列，统计信号次数。
  3. 未来函数陷阱：检查指标是否在 t 时刻用了 t+1 及以后的数据（典型：`shift(-1)`、中心化移动平均、用全样本归一化）——写一个「因果性检查」断言（任意截断到前 k 行重算，前 k 行结果必须不变）。
  4. laew 借鉴：未来函数 = 「用了不该知道的信息」对照 RAG/上下文注入的信息时序——讨论 laew 多轮对话中若把「本应在后面轮次才出现的结论」提前注入（如压缩摘要泄露后文），会造成的评测失真与因果检查的等价物。

### CS06 回测引擎：事件驱动 vs 向量化

- **预期档位**: hard
- **考察维度**: 事件循环架构 / 前视偏差 / 绩效评估
- **对话脚本**:
  1. 向量化回测：策略信号是全序列布尔列，收益 = `signal.shift(1) * ret`（shift 防前视）；用 pandas 写双均线策略的 30 行向量化回测，统计年化收益与最大回撤——快但难以建模「成交失败 / 部分成交 / 仓位依赖路径」。
  2. 事件驱动回测：bar 事件循环（on_bar 回调里读当前行情、下单、撮合、更新账户），撮合器模拟「下一根 bar 开盘价成交 + 滑点 + 手续费」；用 Python 写 `Backtest { data, strategy, broker, portfolio }` 骨架，解释为什么实盘能平移复用这套事件接口（同一个 strategy 类回测实盘两用）。
  3. 前视偏差三连坑：用当日收盘价成交（应为次日开盘）、用未来才能算出的信号决策、幸存者偏差（股票池只含现存股票）；给出三个坑各自的检测手段（把数据人为截断后重跑对比）。
  4. laew 借鉴：事件驱动接口「回测与实盘同一策略类」对照 laew 的 mock LLM e2e——理想状态是「同一个 Agent 提示词与编排，mock 与真实 LLM 两个执行后端」，讨论当前 mock 按角色分流脚本与真实行为的接口对齐度。

### CS07 交易成本建模：滑点、手续费与冲击

- **预期档位**: medium
- **考察维度**: 成交模型 + 参数敏感性 + 净收益意识
- **对话脚本**:
  1. 手续费模型：A股佣金（万 2.5，最低 5 元）+ 印花税（卖出 0.05%）+ 过户费；加密 taker 0.1% / maker 0.02%；写 `fee(side, notional)` 函数并计算「日线级双均线策略一年 200 次往返的费后收益」——很多策略费前盈利费后亏损。
  2. 滑点模型：固定点差（买入 +0.1% 卖出 -0.1%）、成交量比例模型 `slippage = k × sqrt(order_qty / bar_volume)`；讨论高频小单 vs 低频大单哪种模型更贴近现实，以及流动性差的标的为什么回测必须做「按 bar 成交量限制仓位」。
  3. 冲击成本意识：策略资金量放大后自身推动价格——用「成交额不超过 bar 成交额 10%」的仓位上限模拟，观察策略容量（capacity）拐点；解释为什么漂亮回测在小资金验证后放大就失效。
  4. laew 借鉴：成本敏感性对照 laew 的 token 成本——工具输出长度（截断策略）、上下文压缩档位（Light/Medium/Aggressive）都是「成本旋钮」，讨论做一组「成本-质量」敏感性实验（同任务在不同压缩档下的成功率与 token 消耗曲线）。

### CS08 风控与仓位管理

- **预期档位**: medium~hard
- **考察维度**: 回撤控制 + 凯利公式 + 分层止损
- **对话脚本**:
  1. 最大回撤（MDD）：`min(净值/历史峰值 - 1)` 的实现与滚动回撤序列；写「回撤超过 10% 强制减仓一半、超过 20% 清仓冷却」的规则引擎挂到回测的事件循环里（联动 CS06），对比加风控前后的净值曲线形态。
  2. 凯利公式：`f* = (bp - q) / b`（胜率 p、赔率 b）的最优仓位比例；演示「全凯利波动不可接受、实践用 1/4 凯利」的量化对比，并说明参数估计误差（过拟合的 p 和 b）为什么让全凯利危险。
  3. 分层止损：单笔止损（-5%）/ 组合日止损（-3% 全平当日停交易）/ 策略级熔断（连续 5 笔亏损暂停策略重新评估）；把三层规则实现为有优先级的拦截链。
  4. laew 借鉴：分层熔断对照 Agent 短路——laew 已有「连续相同失败 3 次 / 无文本收敛 8 次」，对照交易风控讨论「单元级熔断（SubAgent）/ 会话级熔断（Session）/ 全局熔断（进程）」三层结构与恢复冷却时间的设计。

### CS09 绩效指标：年化、夏普与胜率族

- **预期档位**: medium
- **考察维度**: 指标计算 + 年化换算 + 指标误用
- **对话脚本**:
  1. 基础指标族：总收益、年化收益 `(1+R_total)^(252/n) - 1`、波动率（日收益 std × sqrt(252)）、最大回撤、Calmar（年化/MDD）；用 Python 写 `perf_stats(returns)` 一次输出全表。
  2. 夏普与索提诺：夏普 = (超额收益均值 / 波动) × sqrt(252)，无风险利率用国债收益率年化后按日折算；索提诺只对下行波动分母；解释「上行波动不是风险」的直觉以及为什么对比策略必须同周期同频率（日频夏普直接和小时频比较是无意义的）。
  3. 指标误用案例：胜率 90% 但一次亏光（卖期权策略）、月夏普直接 ×12 而不是 ×sqrt(12)、回撤期外截断美化；每个误用给出一个构造性反例演示数字如何骗人。
  4. laew 借鉴：绩效指标族对照 Debug Agent 报告的量化章节——讨论给 laew 定义「Agent 夏普」式的复合指标（任务成功率 / token 波动 / 耗时回撤），并警惕同样的误用（截断失败样本美化成功率）。

### CS10 模拟盘：paper trading 与数据管道

- **预期档位**: hard
- **考察维度**: 行情订阅 / 撮合模拟 / 状态恢复 / 日报
- **对话脚本**:
  1. 行情管道：WebSocket 订阅交易所实时 tick（或拉 REST K 线轮询兜底），写 Rust(tokio) 或 Python asyncio 的「订阅 → 解析 → 内部 bar 聚合（联动 CS04）→ 事件总线」管道，处理断线重连与序号去重。
  2. 模拟撮合账户：`PaperBroker` 实现下单/撤单/成交回报，限价单按「盘口穿越」判定成交、市价单按对手价 + 滑点；账户状态（持仓 / 挂单 / 现金）每次变更落盘 JSON 快照 + 事件日志（事件溯源，可重放对账）。
  3. 崩溃恢复：进程重启后从最后快照 + 重放事件日志恢复（联动 CS3 的 append-only 思想），并用「恢复后重算净值 vs 崩溃前净值」自检；讨论行情数据回补（重启期间的缺口按 REST 补齐）。
  4. laew 借鉴：paper trading「先模拟后实盘」对照 laew 的测试策略——mock e2e（模拟盘）→ 真实 LLM 小样本（小额实盘）→ 全量上线，讨论中间层「影子模式」（真实 LLM 跑但不下发工具执行，只对比决策）的价值。
