### HG01 GATT 模型与 profile 设计

- **预期档位**: medium
- **考察维度**: ATT/GATT 层级 / profile 建模
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hg01_gatt.py`：GATT 数据模型：(a) **层级建模**：`Server → Service(UUID) → Characteristic(UUID, props, value) → Descriptor`，props 为位图（READ=0x02/WRITE=0x08/NOTIFY=0x10/INDICATE=0x20）；(b) **句柄分配**：按插入顺序给 handle（0x0001 起，每属性 +1），实现 `find_by_uuid()` / `read(handle)` / `write(handle, bytes)`；(c) **设计一个自定义 profile**：环境传感器（Service UUID 自拟 128 位含厂商段），含温湿度特征（READ|NOTIFY，值打包为 int16×2 除以 100）、校准描述符（WRITE，联动触发重校准）；(d) **标准 UUID 速记**：16 位短 UUID 等价于 `0000xxxx-0000-1000-8000-00805F9B34FB`，实现短↔长互转；(e) 导出属性表（ATT Table）为文本（handle/type/UUID/props 五列对齐）。
  2. Bash：构建上述 profile 跑 `read/write` 断言：温湿度 READ 返回 4 字节、NOTIFY 位在 props 位图中置位、短长 UUID 互转往返一致、属性表行数 = 属性总数。
  3. Read 源码，再 Bash 断言：含 0x02/0x08/0x10 位图常量、含蓝牙基础 UUID、含 int16 打包除以 100。

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hg02_adv.py`：广播包解析器：(a) **AD structure**：`[len][type][data...]` 连续 TLV，解析器按 len 前进直到耗尽或 len=0；(b) **支持类型**：0x01 flags（BR/EDR Not Supported 等位）、0x02/0x03 16 位 UUID 列表、0x06/0x07 128 位 UUID、0x09 完整本地名（UTF-8 截断）、0x16 service data（iBeacon 即此类型 + Apple 厂商码 0x004E + 0x1502 子类型）、0xFF manufacturer specific（前两字节公司码小端）；(c) **31 字节预算器**：给定想广播的元素集合，算总字节数并给出**装不下的裁剪建议**（截名/去 UUID 列表/换 Scan Response）；(d) **构造器**：反向从结构化数据打包字节（含名字含中文时的 UTF-8 字节长度陷阱）；(e) 4 组真实形态样例（心率带/温度计/iBeacon/纯名）往返解析断言。
  2. Bash：跑样例断言：iBeacon 解析出 Major/Minor/TxPower、公司码 0x004C（Apple 小端解析）、超预算时输出裁剪建议、中文名 6 字节占位正确。
  3. Read 源码，再 Bash 断言：含 TLV 循环解析、含 0x16 与 0xFF 分支、含 31 字节预算计算。

### HG05 GATT 读写与订阅流

- **预期档位**: hard

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hg05_client.py`：GATT 客户端状态机（模拟传输层，聚焦协议逻辑）：(a) **连接序列**：connect → MTU 交换（默认 23 → 协商 185，ATT_MTU-3 为单包 payload 上限）→ 服务发现（read by group/type）→ 特征发现 → 句柄定位；(b) **读流**：单读（≤MTU-3）与**长读 prepare write + execute queue**（分段序号拼接）；(c) **写流**：单写 / 无响应写（write without response，速度快无确认）/ 长写队列；(d) **订阅流**：向特征对应 **CCCD（0x2902）写 0x0001 开 NOTIFY / 0x0002 开 INDICATE**，服务端随后推送，INDICATE 需客户端回确认（不回则服务端停发——断言此行为）；(e) **退订与断连清理**：断连后服务端自动清 CCCD（重新连接需重订阅，常见"重连收不到通知"根因）；(f) 事件日志输出完整会话。

  3. Read 源码，再 Bash 断言：含 0x2902/0x0001/0x0002 常量、含 prepare write 拼接、含断连清理。
