### EV01 ELF 动态依赖清单与依赖树

- **预期档位**: medium
- **考察维度**: DT_NEEDED 解析 / 缺失库检测 / 树状结构
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev01_depwalk.py`：解析 `readelf -d` 输出（或模拟 readelf 输出文件 `ev01_sim.txt`），提取 DT_NEEDED 列表；按 name→soname→path 建依赖树；输出 `{binary, missing, tree}` JSON，缺则 missing=true
  2. Bash：`python3 -m py_compile ev01_depwalk.py` 断言语法；`command -v readelf && readelf -d /bin/ls > ev01_real.txt || echo "skip_real"`；以 `/bin/ls` 为输入跑 `python3 ev01_depwalk.py /bin/ls | tee ev01_result.json`；`grep -F '"missing": false' ev01_result.json` 断言无缺失；`grep -F '"binary": "/bin/ls"' ev01_result.json`
  3. Read `ev01_result.json`，再 Write `ev01_broken.txt`：构造 readelf -d 模拟输出，含 `libfoo.so.99 => not found`、`libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6` 两行，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev01_depwalk.py ev01_broken.txt | tee ev01_broken_result.json`；`grep -F '"libfoo.so.99"' ev01_broken_result.json` 命中缺失节点；`python3 -m json.tool ev01_broken_result.json >/dev/null`。

### EV02 glibc 符号版本兼容审计

- **预期档位**: hard
- **考察维度**: GLIBC_2.x 提取 / 平台表对照 / 红绿报告
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev02_symver.py`：从 `readelf --version-info` 输出（或模拟 `ev02_sim.txt`）提取所有 `GLIBC_2.xx` 符号版本需求，取最大版本号；维护目标平台表 `{centos7: 2.17, ubuntu18: 2.27, ubuntu20: 2.31, ubuntu22: 2.35, debian11: 2.31}`；逐平台 PASS/INCOMPATIBLE，输出 `{binary, max_glibc, per_platform}`。
  2. Bash：`python3 -m py_compile ev02_symver.py`；造 ev02_sim.txt（多行 GLIBC_2.xx），`python3 ev02_symver.py ev02_sim.txt | tee ev02_result.json`；`grep -F 'centos7' ev02_result.json` 断言所有平台键出现；`python3 -c "import json;d=json.load(open('ev02_result.json'));assert d['per_platform']['c7']['verdict']==d['per_platform']['u22']['verdict']"` 验证。
  3. Read `ev02_result.json`，Write `ev02_incompat.txt`：模拟一段需要 `GLIBC_2.28` 的 readelf 输出（高于 centos7=2.17），本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev02_symver.py ev02_incompat.txt | tee ev02_incompat_result.json`；`grep -F '"verdict": "INCOMPATIBLE"' ev02_incompat_result.json` 命中且 `grep -F 'centos7' ev02_incompat_result.json`（按平台表断言 centos7 不可用）；`python3 -m json.tool ev02_incompat_result.json >/dev/null`。

### EV03 macOS Mach-O 依赖与 install_name 改写

- **预期档位**: medium
- **考察维度**: @rpath / @loader_path 识别 / install_name_tool 命令草案
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev03_macho.py`：解析模拟 `otool -L` 输出（dylib 模拟），识别 `@rpath/`、`@loader_path/`、`@executable_path/` 前缀；按绝对/@rpath/@executable 分类；`@rpath` 项生成 install_name_tool -change 草案；输出 `{binary, deps, rewrite_plan}` JSON。
  2. Bash：`python3 -m py_compile ev03_macho.py`；`python3 ev03_macho.py ev03_sim.txt | tee ev03_result.json`（sim 含 4 条 dep：1 绝+2 @rpath+1 @loader_path）；`grep -F '"@rpath/libssl.3.dylib"' ev03_result.json` 命中；`grep -F 'install_name_tool -change' ev03_result.json` 断言改写命令生成；`python3 -m json.tool ev03_result.json >/dev/null`。
  3. Read `ev03_result.json`，Write `ev03_plan.md`：列出每条 dep 的绝对化改写路径，原样引用 rewrite_plan 中的 install_name_tool 命令与原 target 名，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`grep -F '@rpath' ev03_plan.md` 命中；`grep -F 'install_name_tool -change' ev03_plan.md`；`test -s ev03_plan.md`。

### EV04 Windows PE 依赖与 DLL 查找顺序

- **预期档位**: medium
- **考察维度**: 模拟 dumpbin /dependents / DLL 查找路径规则化
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev04_pewalk.py`：解析模拟 `dumpbin /dependents` 输出（如 `DLL Name: VCRUNTIME140.dll`）；按 DLL 查找顺序（应用目录→System32→SystemWOW64→PATH）逐目录探测（探测用临时目录模拟：建 `app/`、`sys/`、`syswow/` 三个目录，仅部分放置依赖）；输出 `{binary, missing_in: [], resolved_in: []}` JSON。
  2. Bash：`python3 -m py_compile ev04_pewalk.py`；`mkdir -p ev04_root/app ev04_root/sys ev04_root/syswow`；`cp /bin/true ev04_root/app/MSVCP140.dll && cp /bin/true ev04_root/syswow/VCRUNTIME140.dll`（found 占位）；`python3 ev04_pewalk.py ev04_sim.txt ev04_root | tee ev04_result.json`；`grep -F 'MSVCP140.dll' ev04_result.json` 命中且 `"resolved_in"` 含 `app/`；`grep -F 'VCRUNTIME140.dll' ev04_result.json` 命中且 `"resolved_in"` 含 `syswow/`；`python3 -m json.tool ev04_result.json >/dev/null`。
  3. Read `ev04_result.json`，Write `ev04_miss.txt`：模拟 dumpbin 输出含 5 条 DLL，其中 2 条未放（WS2_32.dll、bcrypt.dll），本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev04_pewalk.py ev04_miss.txt ev04_root | tee ev04_miss_result.json`；`grep -F '"WS2_32.dll"' ev04_miss_result.json`；`grep -F '"bcrypt.dll"' ev04_miss_result.json`；`grep -c '"missing_in"' ev04_miss_result.json` 命中 ≥ 2。

### EV05 rpath/runpath 治理策略

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev05_rpath.py`：解析模拟 ELF 头部 DT_RPATH/DT_RUNPATH 字段；按平台建议生成目标 rpath 列表：本地布局用 `$ORIGIN/lib`、可移植包用 `$ORIGIN/../lib`、系统包留空；输出 `patchelf --set-rpath` 命令草案（不执行）；输出 `{binary, current_rpath, recommended, patchelf_plan}` JSON。

  3. Read `ev05_result.json`，Write `ev05_layout.json`：3 布局 flat/nested/vendor：local=$ORIGIN/lib、portable=$ORIGIN/../lib、vendor=/opt/laew/vendor/lib，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev05_rpath.py --layout ev05_layout.json ev05_sim.txt | tee ev05_plan.json`；`grep -F '$ORIGIN/../lib' ev05_plan.json` 命中 nested 建议；`grep -c 'patchelf --set-rpath' ev05_plan.json` 应 ≥ 3。

### EV06 静态链接决策矩阵

  2.   3. Read `ev06_result.json`，Write `ev06_matrix.md`：决策矩阵 Markdown 表（行=库、列=glibc_used/volume_kb/compat_grade/decision/reason），逐条原样引用 ev06_result.json 字段，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。

### EV07 依赖冲突与多版本共存

- **预期档位**: hard
- **考察维度**: 同库多版本 / 区间求交 / 隔离目录方案
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev07_conflict.py`：解析多二进制依赖清单 `{binary→[lib@ver,...]}`，按 lib 名聚合求所有版本区间；求交：交集为空报 conflict；非空建议采用版本号；输出 `{lib, requested_by, intersection, conflict}` JSON；隔离方案：每版本 lib/<lib>/<ver>/ 独目录 + rpath。
  2. Bash：`python3 -m py_compile ev07_conflict.py`；`ev07_in.json`：app1 需要 libfoo@1.0-1.2、app2 需要 libfoo@1.5-1.8；`python3 ev07_conflict.py ev07_in.json | tee ev07_result.json`；`grep -F '"conflict": true' ev07_result.json` 命中区间空；`grep -F '"lib": "libfoo"' ev07_result.json`；`python3 -m json.tool ev07_result.json >/dev/null`。
  3. Read `ev07_result.json`，Write `ev07_isolated.md`：隔离目录方案——app1 用 `lib/libfoo/1.0/libfoo.so` + rpath=`$ORIGIN/lib/libfoo/1.0`，app2 用 `lib/libfoo/1.5/...`；原样引用 conflict=true 结论，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`grep -F 'lib/libfoo/1.0' ev07_isolated.md`；`grep -F 'lib/libfoo/1.5' ev07_isolated.md`；`grep -F 'rpath' ev07_isolated.md`；`test -s ev07_isolated.md`。

### EV08 CI 门禁

- **预期档位**: hard
- **考察维度**: 门禁脚本 / 红绿报告 / 失败样例
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev08_gate.py`：扫描 `dist/` 下二进制，对每个跑 `ev02_symver.py` 收集 GLIBC 最高版本需求；若任一超过 centos7=2.17 即 fail；输出 `{binary, max_glibc, verdict}` JSON 列表；总退出码 0=全 PASS / 1=有 FAIL。
  2. Bash：`python3 -m py_compile ev08_gate.py`；`mkdir -p dist`；造 2 个模拟 version-info 文件 `dist/bin1.txt`（需 2.17）、`dist/bin2.txt`（需 2.31）；`python3 ev08_gate.py dist/ | tee ev08_pass.json`；`test $? -eq 0` 断言通过；`python3 -m json.tool ev08_pass.json >/dev/null`。
  3. Read `ev08_pass.json`，Write `dist/bin3.txt` 模拟需 GLIBC_2.34 的 readelf 输出，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev08_gate.py dist/ > ev08_fail.json 2>&1; test $? -eq 1` 断言门禁拦截；`grep -F '"verdict": "FAIL"' ev08_fail.json` 命中；`grep -F 'bin3' ev08_fail.json`。

### EV09 最小运行时环境冒烟

- **预期档位**: medium
- **考察维度**: 纯净 env -i 冒烟 / 分级 PASS/FAIL / dry-run 模式
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev09_smoke.sh`：对目标清单逐个以 `env -i PATH=/usr/bin:/bin LD_LIBRARY_PATH=<沙盒>` 纯净环境 `timeout 5` 执行；退出码 0→PASS、124→FAIL_TIMEOUT、127→FAIL_LIB（缺库）、非零→FAIL_GENERIC；`--allow-fail` 只出报告不置错；输出 `smoke_report.json` 与 Markdown 摘要。
  2. Bash：`sh -n ev09_smoke.sh`；造白名单沙盒 `ev09_sandbox/lib` 与坏样例 `ev09_bad.sh`（首行 `#!/nonexistent/loader`，纯净环境必败），`chmod +x ev09_bad.sh`；`test -x ev09_bad.sh`。
  3. Read `ev09_smoke.sh`，Write `ev09_drill.sh`：以目标 `/bin/true`、`/bin/ls`（预期 PASS）与 `ev09_bad.sh`（预期 FAIL_LIB/GENERIC）调 `ev09_smoke.sh --allow-fail`，断言报告含 2 个 PASS 与 ≥1 个 FAIL_*，本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`bash ev09_drill.sh | tee ev09_check.log`；`grep -F '"status": "PASS"' smoke_report.json`（按 smoke_report.json 路径断言）；`grep -F '"status": "FAIL_' smoke_report.json`；`python3 -m json.tool smoke_report.json >/dev/null`。

### EV10 移植性 lint 工具

- **预期档位**: medium
- **考察维度**: 规则带编号 / 坏样例命中 / 修复建议输出
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ev10_portlint.py`：源码移植性 linter，规则带编号：PORT001 硬编码绝对路径（`/usr/local`、`C:\`）；PORT002 手工 `/` 拼接路径；PORT003 文本读写假设 `\n` 换行未抽象；PORT004 dlopen 系调用无平台分支；PORT005 硬编码文件权限位跨平台差异；逐条输出 `{file, line, rule, severity, snippet, fix_suggestion}` JSON；`--format md` 出 Markdown；退出码恒 0（违规与退出码解耦）。
  2. Bash：`python3 -m py_compile ev10_portlint.py` 断言语法。
  3. Read `ev10_portlint.py`，Write `ev10_bad_sample.c`：坏样例源码（每类规则至少一处）：`fopen("/usr/local/share/laew/data.db","r")`（PORT001）；`strcpy(buf,"/var/tmp/");strcat(buf,name);`（PORT002）；`fprintf(out,"a,b\n")` 未抽象（PORT003）；`dlopen("libplugin.so",RTLD_NOW)` 无平台分支（PORT004）；`chmod(path,0755)`（PORT005），本轮必须显式复用第一轮已落字段命名。不允许另起无关主题。
  4. Bash：`python3 ev10_portlint.py --src ev10_bad_sample.c --out ev10_violations.json`；`grep -c 'PORT00' ev10_violations.json` ≥ 5（五类全命中）；`grep -F 'fix_suggestion' ev10_violations.json`；`python3 -m json.tool ev10_violations.json >/dev/null`。
