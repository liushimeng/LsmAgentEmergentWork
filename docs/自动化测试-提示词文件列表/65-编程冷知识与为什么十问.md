### BN01 为什么 0.1 加 0.2 不等于 0.3
- **预期档位**: simple
- **考察维度**: IEEE 754 浮点表示 + 工程应对
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下 Write `float_precision.py`：打印 `0.1 + 0.2`、`0.1 + 0.2 == 0.3`、`0.5 + 0.25 == 0.75` 三行结果，并用 `struct.pack('>d', 0.1)` 输出 0.1 的 8 字节十六进制（注释里标注符号位/指数/尾数域切分）。
  2. Bash 跑 `python3 tmpPlan/agent-test/float_precision.py`，断言 stdout 含 `0.1+0.2=0.30000000000000004` 且含 `eq03=False`、`eq75=True`（grep -F 校验），证明「分母为 2 幂次的小数才能精确表示」。
  3. Read `float_precision.py` 确认 0.1 的 hex 输出是 `3fb999999999999a`（IEEE 754 双精度截断形态）。再 Write 追加 `safe_equal(a, b, eps=1e-9)` 容差比较函数 + 一个金融示例：`total_cents = 10 + 20`（以「分」为单位整数累加）对比 `total_yuan = 0.10 + 0.20`（元单位浮点累加）。
  4. Bash 跑追加后的脚本，断言容差比较 `safe_equal(0.1+0.2, 0.3)=True`，且整数分累加 `total_cents=30` 无任何精度问题；同时断言元单位累加 `total_yuan` ≠ 0.3（grep 校验），用输出印证「金融用定点整数」的结论。

### BN05 随机数为什么不随机，UUID 会重复吗
- **预期档位**: simple

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下 Write `random_lab.py`：用 `random.seed(42)` 生成 3 个伪随机数，再 `random.seed(42)` 重置后再生成 3 个，打印对比两序列；同时用 `uuid.uuid4()` 生成一个 v4 UUID。
  2. Bash 跑 `python3 tmpPlan/agent-test/random_lab.py`，断言两次 seed(42) 的 6 个数字完全一致（grep 校验第一序列 == 第二序列），证明 PRNG 的确定性。
  3. Read `random_lab.py` 确认 `seed(42)` 调用两次。再 Write `birthday.py`：实现生日悖论公式 `p ≈ 1 - exp(-n²/(2d))`，计算 UUID v4（d=2^122）在 n=2^61 时的碰撞概率 ≈ 50%，打印 n 与 p 的对应表（n=2^20/2^40/2^61）。
  4. Bash 跑 `python3 tmpPlan/agent-test/birthday.py`，断言 n=2^61 时 p ≈ 0.5（grep -E '0\.4[0-9]|0\.5[0-9]' 校验），且 n=2^20 时 p ≈ 0（几乎不碰撞），用输出印证「UUID v4 碰撞概率极低，但会话 token 应用密码学安全 RNG」。
