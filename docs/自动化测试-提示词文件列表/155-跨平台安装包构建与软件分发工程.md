# 155 跨平台安装包构建与软件分发工程

> 编号段 EU01–EU10 · 聚焦「把构建产物变成五平台可安装分发物」。
>
> 与现有维度互补说明：
> - `112-构建系统与编译缓存工程`（DD 维）聚焦**构建过程**（Make/Ninja/ccache 依赖图与缓存）；本文件聚焦**构建产物如何变成五平台可安装分发物**。
> - `152-二进制体积与符号膨胀治理`（ER 维）聚焦二进制体积与符号治理；本文件聚焦分发链路。
> - `66-跨平台电脑使用与虚拟化实战`（BO 维）是**用户视角**安装软件；本文件是**开发者视角**制造与分发安装包。
>
> **本文件独特主题**：dpkg-deb 打包 / rpm spec 编写 / macOS pkg·dmg 约定 / Windows 分发脚本 / 自解压安装器 / sha256 清单 / 安装依赖预检 / 升级与配置保留 / 本地软件仓库 / 多平台发布 manifest。
>
> 环境约束：测试机 Linux；rpmbuild/pwsh 等不要求存在——按条目降级为「模拟数据+解析器」或「存在才执行、缺失跳过不算失败」。

### EU01 deb 安装包构建与安装卸载脚本

- **预期档位**: medium
- **考察维度**: 打包目录规范 / control 字段
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `eu01_build_deb.sh`：建 laew-demo 包根 `eu01_pkgroot/`（同目录）：DEBIAN/control 含 Package: laew-demo、Version: 1.2.0-1、Architecture: amd64、Depends: libc6, libssl3、Maintainer、多行 Description（续行空格开头）；preinst/postinst(调 ldconfig)/prerm/postrm 四个 `#!/bin/sh` 维护脚本；载荷 usr/local/bin/laew-demo 等。
  2. Bash：`bash -o pipefail -c 'sh -n eu01_build_deb.sh 2>&1 | tee eu01_syntax.log'` 断言退出码 0；执行后 `test -f eu01_pkgroot/DEBIAN/control` 断言骨架生成。
  3. Read `eu01_build_deb.sh`，Write 同目录 `eu01_control_check.py`：校验七字段齐全、Version 形如 `x.y.z-r`、Description 续行缩进、四维护脚本含 shebang，全过打印 `CONTROL_OK`。本轮必须显式复用第一轮的 `Package: laew-demo` 与 DEBIAN 结构，不允许另起无关主题。
  4. Bash：`python3 eu01_control_check.py eu01_pkgroot` 断言输出含 `CONTROL_OK`；`command -v dpkg-deb` 存在则 `dpkg-deb --build` 真实出包，缺失跳过不算失败。

### EU02 CentOS rpm spec 编写与结构校验

- **预期档位**: hard
- **考察维度**: spec 段落完整性 / 清单匹配
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `eu02_spec_check.py`：spec 校验器（不依赖 rpmbuild）：查 preamble 字段 Name/Version/Release/Summary/License/Source0 与段落 %description/%prep/%build/%install/%files/%changelog 齐全；%install 落盘 `%{buildroot}` 路径与 %files 清单（忽略修饰与宏）双向匹配；%changelog 首条格式校验；输出 JSON，有错打印 `SPEC_FAIL` 退出 1。
  2. Bash：`bash -o pipefail -c 'python3 -m py_compile eu02_spec_check.py 2>&1 | tee eu02_syntax.log'` 断言退出码 0。
  3. Read `eu02_spec_check.py`，Write 同目录 `eu02_laew.spec`：Name: laew-demo、Version: 1.2.0、Release: 1%{?dist}；%install 装 `%{buildroot}/usr/local/bin/laew-demo`、README.md(%doc)、`%{_sysconfdir}/laew-demo.conf`(%config(noreplace))；%post 调 ldconfig；故意在 %files 多登记未安装的 `%{_bindir}/laew-legacy`。本轮必须显式复用第一轮校验器的字段与段落命名，不允许另起无关主题。
  4. Bash：`python3 eu02_spec_check.py eu02_laew.spec --out eu02_report.json` 断言退出码非 0 且输出含 `laew-legacy`；`python3 -m json.tool eu02_report.json >/dev/null` 断言报告有效。

### EU03 macOS pkg 与 dmg 目录约定

- **预期档位**: medium
- **考察维度**: Distribution.xml 结构 / 目录布局
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `eu03_distribution.xml`：macOS 安装器清单：`<installer-gui-script>` 根、title、options、choices（laew-core 必选、laew-cli 可选）、`<pkg-ref id="com.laew.demo.core" version="1.2.0"/>`、installation-check 占位；良构且属性带引号。
  2. Bash：`python3 -c 'import xml.etree.ElementTree as ET; ET.parse("eu03_distribution.xml"); print("XML_OK")' 2>&1 | tee eu03_syntax.log` 断言输出含 `XML_OK`。
  3. Read `eu03_distribution.xml`，Write 同目录 `eu03_layout.json`：pkg 目录清单，每项含 path/type/required/note：`laew-demo.pkgroot/Applications/LaewDemo.app`（dmg 场景为符号链接）、`Resources/scripts/preinstall`（验磁盘与系统版本）、`postinstall`、`Resources/license.rtf`；identifier 取 `com.laew.demo.core`。本轮必须显式复用第一轮 XML 的 pkg-ref id 与 choice 标识，不允许另起无关主题。
  4. Bash：`python3 -m json.tool eu03_layout.json >/dev/null` 断言有效；`grep -F 'com.laew.demo.core' eu03_layout.json`、`grep -F 'Applications/LaewDemo.app' eu03_layout.json` 断言含约定路径。

### EU04 Windows 分发包与 PowerShell 安装脚本

- **预期档位**: medium
- **考察维度**: zip 布局 / 安装卸载对称
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `eu04_install.ps1`：PowerShell 安装脚本：`param([string]$InstallDir = "$env:LOCALAPPDATA\Programs\laew-demo")`；New-Item 建目录、Copy-Item 拷入 bin/config/README.txt；PATH 未含安装目录时 `[Environment]::SetEnvironmentVariable('Path', ..., 'User')` 追加；写卸载键 `HKCU:\Software\...\Uninstall\laew-demo`。
  2. Bash：ps1 本机不可执行，改结构校验：`bash -o pipefail -c 'grep -cE "param\(|Copy-Item|SetEnvironmentVariable|Uninstall" eu04_install.ps1 2>&1 | tee eu04_syntax.log'` 断言计数 ≥ 4。
  3. Read `eu04_install.ps1`，Write 同目录 `eu04_layout.json`：zip 布局，每项含 path/purpose/required：`laew-demo/bin/laew-demo.exe`、`bin/libcrypto-3-x64.dll`、`config/default.toml`、`README.txt`、`install.ps1`、`uninstall.ps1`（对称移除 PATH 项与注册表键）。本轮必须显式复用第一轮默认安装目录与脚本文件名，不允许另起无关主题。
  4. Bash：`python3 -m json.tool eu04_layout.json >/dev/null` 断言有效；`grep -F 'laew-demo/bin/laew-demo.exe' eu04_layout.json`、`grep -F 'uninstall.ps1' eu04_layout.json` 断言载荷与卸载脚本均在。

### EU05 通用自解压安装器

- **预期档位**: hard
- **考察维度**: 载荷拼接 / 内嵌自校验
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `eu05_selfextract.sh`：makeself 精简模板：头部定义 `PAYLOAD_LINE`（载荷起始行号）与 `PAYLOAD_SHA256` 占位；支持 `--check`（仅校验）与 `--target <dir>`（缺省 mktemp -d）；比对 tail 截出载荷的 sha256，不符打印 `SELF_CHECK_FAIL` 退出 2；相符 `tail | tar -x -C "$target"` 并执行载荷内 setup.sh。
  2. Bash：`bash -o pipefail -c 'sh -n eu05_selfextract.sh 2>&1 | tee eu05_syntax.log'` 断言退出码 0。
  3. Read `eu05_selfextract.sh`，Write 同目录 `eu05_make_installer.sh`：建 `eu05_payload/`（setup.sh 输出 `SETUP_HELLO` 并 touch .installed）；tar 打包并算真实 sha256；sed 替换模板占位为真实行号与哈希，cat 拼出 `eu05_installer.run` 并 chmod +x。本轮必须显式复用第一轮的 `PAYLOAD_LINE`/`PAYLOAD_SHA256` 变量与 `--check`/`--target` 参数，不允许另起无关主题。
  4. Bash：`bash eu05_make_installer.sh && bash eu05_installer.run --target eu05_out` 断言退出码 0、`test -f eu05_out/.installed`；再 `printf X >> eu05_installer.run` 篡改后跑 `--check`，断言退出码非 0 且输出含 `SELF_CHECK_FAIL`。

### EU06 发布校验和清单与跨平台校验

- **预期档位**: medium
- **考察维度**: SHA256SUMS 生成 / 篡改检出
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `eu06_gen_sums.sh`：自造 `eu06_dist/`（同目录）三个占位产物：`laew-demo_1.2.0_amd64.deb`、`laew-demo-1.2.0-1.el9.x86_64.rpm`、`laew-demo-1.2.0-linux-amd64.tar.gz`；进目录 `sha256sum * > SHA256SUMS`。
  2. Bash：`bash -o pipefail -c 'sh -n eu06_gen_sums.sh && bash eu06_gen_sums.sh 2>&1 | tee eu06_syntax.log'` 断言退出码 0、`test "$(wc -l < eu06_dist/SHA256SUMS)" -eq 3`。
  3. Read `eu06_gen_sums.sh`，Write 同目录 `eu06_verify.sh`：逐行 `read sum file` 读两列清单，逐文件先 `test -f` 再比 sha256sum 哈希列，分别计数 ok/missing/mismatch，打印 `VERIFY_OK n=3` 或 `VERIFY_FAIL`，退出码 0/1；注释给 verify.ps1 等价思路（Get-FileHash）。本轮必须显式复用第一轮的两列清单格式与三个产物文件名，不允许另起无关主题。
  4. Bash：先 `bash eu06_verify.sh eu06_dist` 断言退出码 0 且输出含 `VERIFY_OK n=3`；再 `printf X >> eu06_dist/laew-demo_1.2.0_amd64.deb` 重跑，断言退出码非 0 且输出含 `VERIFY_FAIL`。

### EU07 安装前置依赖探测

- **预期档位**: medium
- **考察维度**: glibc 探测 / 平台化建议
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `eu07_preflight.py`：预检器（本机真实可跑）：解析 `ldd --version` 得 glibc 版本；shutil.which 探测 apt/yum/dnf/brew/choco；对 sys.executable 跑 ldd 收集 `not found`；`--targets <json>` 读目标机档案（os/glibc_min/package_manager/disk_gb_min）输出逐平台 verdict（ok/too_old/unknown）与建议命令；缺省输出本机体检 JSON。
  2. Bash：`bash -o pipefail -c 'python3 -m py_compile eu07_preflight.py && python3 eu07_preflight.py --out eu07_local.json 2>&1 | tee eu07_syntax.log'` 断言退出码 0 且本机 JSON 含 glibc_version 字段。
  3. Read `eu07_preflight.py`，Write 同目录 `eu07_targets.json`：五机档案：centos7(2.17, yum)、ubuntu1804(2.27, apt)、ubuntu2004(2.31, apt)、ubuntu2204(2.35, apt)、darwin(null, brew)，另加虚构 strict9（glibc_min 9.99）触发 too_old。本轮必须显式复用第一轮 `--targets` 字段名，不允许另起无关主题。
  4. Bash：`python3 eu07_preflight.py --targets eu07_targets.json --out eu07_report.json` 断言退出码 0 且 `grep -F '"too_old"' eu07_report.json`（strict9 判过旧）。

### EU08 升级迁移与配置保留

- **预期档位**: hard
- **考察维度**: 配置合并策略 / 失败回滚
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `eu08_upgrade.sh`：升级脚本：参数 --old-dir/--new-dir；检测旧目录与配置 `config_version = 1`；合并到 v2：新增键补默认（`server.timeout = 30`）、用户已改键保留、废弃键 `legacy_mode` 移入 `config.deprecated.toml` 归档；先备份 `config.bak.<epoch>`，任一步失败恢复并打印 `ROLLBACK_DONE` 退出 1；成功打印 `UPGRADE_OK`。
  2. Bash：`bash -o pipefail -c 'sh -n eu08_upgrade.sh 2>&1 | tee eu08_syntax.log'` 断言退出码 0；bash 内联造 `eu08_old/config.toml`（含 config_version、`log_level = "debug"` 用户改过、`legacy_mode = true`），`test -s` 断言落盘。
  3. Read `eu08_upgrade.sh`，Write 同目录 `eu08_drill.sh`：A 场景调 eu08_upgrade.sh 迁 v2，断言保留 `log_level = "debug"`、补 `server.timeout = 30`、归档含 legacy_mode；B 场景传不存在的新目录触发失败，断言 `config.bak.*` 存在且 `cmp` 比对未破坏。本轮必须显式复用第一轮的 `config_version` 字段与 `ROLLBACK_DONE`/`UPGRADE_OK` 标记，不允许另起无关主题。
  4. Bash：`bash eu08_drill.sh` 断言退出码 0、输出含 `UPGRADE_OK` 与 `ROLLBACK_DONE`、含 `log_level = "debug"`。

### EU09 本地软件仓库索引

- **预期档位**: hard
- **考察维度**: 包名解析 / 数值版本排序
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `eu09_scan_repo.py`：仓库索引器：扫描 `*.deb`/`*.rpm`，按 `name_version_arch.deb` 与 `name-version-release.arch.rpm` 解析 package/version/architecture；记录 size 与 sha256；版本按 major.minor.patch 数值比较；按包名+架构分组降序，输出 apt Packages 风格文本与 `repo_index.json`；`--latest-only` 留每组最新版。
  2. Bash：`bash -o pipefail -c 'python3 -m py_compile eu09_scan_repo.py 2>&1 | tee eu09_syntax.log'` 断言退出码 0。
  3. Read `eu09_scan_repo.py`，Write 同目录 `eu09_seed_repo.sh`：建 `eu09_repo/` 并 printf 造 5 个占位包：`laew-demo_1.2.0_amd64.deb`、`laew-demo_1.10.0_amd64.deb`（验数值排序）、`laew-demo-1.2.0-1.el9.x86_64.rpm`、`demo-tool_2.0.0_all.deb`、`demo-tool_1.9.9_all.deb`。本轮必须显式复用第一轮解析器的命名规则与索引字段名，不允许另起无关主题。
  4. Bash：`bash eu09_seed_repo.sh && python3 eu09_scan_repo.py --repo eu09_repo --latest-only --out eu09_index.json` 断言退出码 0、`grep -F '"1.10.0"' eu09_index.json`、`test "$(grep -cF '"1.9.9"' eu09_index.json)" -eq 0`。

### EU10 多平台发布 manifest

- **预期档位**: medium
- **考察维度**: 产物清点 / 缺产物报错
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `eu10_gen_manifest.py`：清单生成器：扫描发布目录约定 5 产物（deb/rpm/tar.gz/zip/dmg）；逐项生成 `{platform, arch, file, sha256, size, signature: null}`；缺任一产物打印 `MISSING_ARTIFACT <name>` 退出 1；写 manifest.json（顶层 release/date/artifact_count）。
  2. Bash：`bash -o pipefail -c 'python3 -m py_compile eu10_gen_manifest.py 2>&1 | tee eu10_syntax.log'` 断言退出码 0；bash 内联建 `eu10_dist/` 并 printf 生成 5 个占位产物，`test "$(find eu10_dist -type f | wc -l)" -eq 5`；再跑生成器断言退出码 0。
  3. Read `eu10_gen_manifest.py`（及生成的 manifest.json），Write 同目录 `eu10_release_notes.md`：版本日期头；5 产物表（platform/arch/file/size/sha256 前 12 位，取自 manifest.json）；逐平台安装指引一行带过；签名状态 `signature: null`。本轮必须显式复用第一轮 manifest.json 的 file/sha256/size 字段值，不允许另起无关主题。
  4. Bash：`python3 -m json.tool eu10_dist/manifest.json >/dev/null` 断言有效；`grep -F 'laew-demo_1.2.0_amd64.deb' eu10_release_notes.md`；再 `rm eu10_dist/laew-demo-1.2.0-macos.dmg` 重跑生成器，断言退出码非 0 且输出含 `MISSING_ARTIFACT`。
