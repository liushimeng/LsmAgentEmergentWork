# 自动化测试提示词 — 逆向工程与二进制安全分析（AD01–AD10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。
> 边界约定：本维度全部以**合法学习、自有代码、本地 CTF 靶场、授权测试**为语境设计。

## 维度说明

本维度从 Agent 能力视角考察**二进制分析与防御**链路：gcc 现场编译带漏洞的小 C 靶场在本地进程内触发，用 objdump/nm/readelf（用前 `command -v` 探测）分析 ELF，python3 写独立校验脚本核对输出。不 ptrace 系统进程、不碰外网。ROP/加固类可只到「构造 payload + 说明」层面。所有产物落在 `tmpPlan/agent-test/` 沙盒内。

### AD01 ELF 文件结构解剖
- **预期档位**: medium
- **考察维度**: 二进制格式 / 工具链
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 用 Write 产出 `hello.c`（printf("hello\n") + 全局变量 + 静态函数），`gcc -o hello hello.c` 编译。`command -v readelf objdump nm` 探测工具链，期望三者均可用。跑 `readelf -h hello` 与 `readelf -S hello`，把输出存 `elf-headers.txt` 与 `elf-sections.txt`。
  2. 用 python3 写 `elf_parser.py` 解析 ELF 头关键字段（magic/e_type/e_machine/e_entry）与节区清单（名称/类型/地址/大小）。跑 `python3 elf_parser.py hello` 输出 `elf-parsed.json`，与 `readelf` 输出交叉验证：期望 magic=`7f454c46`、节区数与 readelf 一致。Read 验证解析器处理了 32/64 位两种 e_class。
  3. 故意把 `hello.c` 改写成带 `.data`/`.bss`/`.rodata` 三节区的版本（全局已初始化/未初始化/const 字符串），重跑 `elf_parser.py`，期望 `.rodata` 节区 flags 含 `ALLOC` 不含 `WRITE`、`.bss` 节区 size > 0 但 file offset = 0。
  4. 写 `elf-layout.md` 总结：代码段/数据段/堆/栈在 ELF 加载后的虚拟地址布局，附 ASCII 图；列出 PLT/GOT 延迟绑定的 4 步流程（不超过 10 行）。

### AD02 静态逆向：读懂反汇编
- **预期档位**: medium
- **考察维度**: 汇编阅读 / 编译器行为
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `demo.c`（含 if/循环/函数调用），`gcc -O0 -o demo_O0 demo.c` 与 `gcc -O2 -o demo_O2 demo.c` 两版编译。`objdump -d demo_O0 > demo_O0.asm` 与 `objdump -d demo_O2 > demo_O2.asm`。Read 两版 .asm 文件，期望 O0 版有 `push rbp / mov rbp,rsp` 栈帧建立、O2 版无。
  2. python3 写 `asm_diff.py` 对比两版：统计函数内 `call` 指令数（O2 内联后应减少）、`jmp` 指令数（O2 循环展开后应变化）。期望 O2 版 `call` 数 < O0 版。Read 验证 diff 脚本输出具体数字。
  3. 故意在 `demo.c` 里加一个死代码分支（`if (0) { ... }`），重跑 O2 编译，期望 `asm_diff.py` 报告该分支在 O2 版完全消失（死代码消除）。
  4. 写教学 crackme `crackme.c`：输入字符串与硬编码比较，`gcc -O0 -o crackme crackme.c`。`objdump -d crackme > crackme.asm`，用 python3 `find_cmp.py` 定位 `cmp` 指令地址与立即数，期望找到比较值（如 `0x1234`）。写 `crackme-analysis.md` 附推理链。

### AD03 动态调试：gdb 实战
- **预期档位**: medium
- **考察维度**: 调试器操作 / 事后分析
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `segfault.c`（故意越界写 `int a[5]; a[100] = 0`），`gcc -g -o segfault segfault.c`。`command -v gdb` 探测；若可用跑 `gdb -batch -ex run -ex bt segfault` 把 backtrace 存 `gdb-bt.txt`；若不可用降级：用 `python3 -c "import gdb"` 或仅写 `gdb-commands.gdb` 脚本文件。
  2. 写条件断点脚本 `gdb-commands.gdb`：`break main.c:10 if i==50`、`watch a[100]`、`commands / bt / continue`。Read 验证脚本语法正确（`gdb -batch -x gdb-commands.gdb segfault` 跑通）。
  3. 故意把 `segfault.c` 改成带符号版与 strip 版两版：`strip -o segfault_stripped segfault`。跑 `nm segfault` 与 `nm segfault_stripped`，期望 stripped 版输出 `no symbols`。
  4. 事后分析：`ulimit -c unlimited && ./segfault` 触发 core dump，`gdb segfault core.* -batch -ex bt` 把崩溃栈存 `core-bt.txt`。期望栈顶是 `main` 函数、行号指向越界写那行。写 `gdb-cheatsheet.md` 总结断点/观察点/事后分析三场景命令。

### AD04 栈溢出原理与栈保护
- **预期档位**: hard
- **考察维度**: 漏洞原理 / 纵深防御
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `vuln.c`：`gets(buf)` 读入 64 字节栈缓冲区。`gcc -fno-stack-protector -z execstack -no-pie -o vuln vuln.c`（关闭保护便于演示）。`command -v checksec` 探测；若不可用用 `readelf -l vuln` 看 GNU_STACK 行 RWX 标志。跑 `./vuln` 输入 80 个 A，期望段错误（`dmesg` 或 stderr 含 segfault）。
  2. python3 写 `offset_calc.py`：给定 buf 地址与返回地址偏移（通过 `objdump -d vuln` 找 `lea rax, [rbp-0x40]` 之类指令），计算覆盖返回地址需要的 padding 长度。期望输出具体数字（如 72）。Read 验证计算逻辑。
  3. 加栈保护对比：`gcc -fstack-protector-all -o vuln_safe vuln.c`。跑同样超长输入，期望 `__stack_chk_fail` 被调用（stderr 含 `stack smashing detected`）而非 segfault。
  4. 防御视角审查：写 `audit_c.py` 扫描目录下所有 .c 文件，找出 `strcpy`/`sprintf`/`gets` 调用并标记为 unsafe。对 `vuln.c` 跑期望至少 1 处 unsafe；对修复版（改用 `fgets`/`snprintf`）跑期望 0 处。写 `stack-defense.md` 总结 Canary/NX/ASLR/PIE 各自拦住哪一环。

### AD05 ROP 链构造入门
- **预期档位**: hard
- **考察维度**: 利用技术 / 对应防御
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `rop_target.c`：`gets(buf)` + 若覆盖返回地址到 `win()` 函数则打印 "PWNED"。`gcc -fno-stack-protector -no-pie -o rop_target rop_target.c`。`objdump -d rop_target > rop_target.asm`，python3 `find_gadgets.py` 在 .text 段搜索 `pop rdi; ret`（opcode `5f c3`）与 `ret`（`c3`）地址。期望输出至少 2 个 gadget 地址。
  2. 构造 payload：python3 `build_rop.py` 用 struct.pack 拼 `padding + pop_rdi_ret + arg + win_addr`。跑 `python3 build_rop.py | ./rop_target`，期望 stdout 含 "PWNED"。Read 验证 payload 长度与 padding 一致。
  3. 加 ASLR 讨论：`echo 2 | sudo tee /proc/sys/kernel/randomize_va_space`（仅探测，不改系统状态，用 `cat` 读当前值即可）。写 `aslr_impact.md` 说明 ASLR 对 ROP 的影响与绕过思路（信息泄露）。
  4. 防御视角：写 `cfi_defense.md` 总结 CFI、shadow stack、CET 硬件特性如何抬高 ROP 成本；对比 `clang -fsanitize=cfi` 编译选项（仅说明，不要求本机跑）。

### AD06 动态插桩：Frida 等价脚本
- **预期档位**: medium
- **考察维度**: 动态插桩 / 工程应用
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `target.c`（含 `int add(int a,int b){return a+b;}` + `main` 循环调用），`gcc -o target target.c`。`command -v frida` 探测；若不可用降级：写 `frida_script.js`（Frida JS API 伪代码）+ `ptrace_trace.py` 用 `ctypes` 调 `ptrace` 仅做演示（不实际 attach）。
  2. 写 Frida 脚本 `hook_add.js`：`Interceptor.attach(Module.findExportByName(null, "add"), { onEnter: function(args){ console.log("add called with", args[0], args[1]); }, onLeave: function(retval){ console.log("add returned", retval); }})`。Read 验证脚本语法（`frida --no-pause -l hook_add.js target` 期望输出日志）。
  3. hook native 函数：把 `add` 改成 `static` 内联，用 `Module.findBaseAddress("target") + offset` 定位。`objdump -d target` 找 add 地址，写脚本期望 hook 成功。
  4. 写 `frida-beyond-security.md`：除安全测试外，Frida 在性能采样、私有协议抓取、兼容性排查三场景的用法；表格形式不超过 8 行。

### AD07 反混淆：控制流平坦化还原
- **预期档位**: hard
- **考察维度**: 混淆原理 / 还原思路
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `obfuscator.py`：把简单 if/else 代码转成「分发器 + 状态变量大循环」的平坦化版本（python 源码级混淆，不依赖 OLLVM）。输入 `original.py`（含 3 分支 if/else），输出 `flattened.py`。跑 `python3 original.py` 与 `python3 flattened.py` 期望输出完全一致。
  2. python3 写 `flatten_detect.py`：检测 `flattened.py` 是否含「大循环 + 状态变量 + 分发 switch」模式。期望对 `flattened.py` 输出 `FLATTENED`、对 `original.py` 输出 `NORMAL`。Read 验证检测规则。
  3. 静态还原：写 `deflatten.py` 解析 `flattened.py` 的 AST，收集状态转移图、区分真实基本块与无关块，输出 `restored.py`。跑 `python3 restored.py` 期望与 `original.py` 输出一致。
  4. 动态辅助：写 `trace_filter.py` 用 `sys.settrace` 记录执行 trace，过滤未走到的路径。对 `flattened.py` 跑期望输出「未走到的状态编号」列表。写 `deobfuscation.md` 总结静态+动态配合降低分析量的方法。

- **预期档位**: medium

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 用 Write 产出模拟样本 `sample.bin`（含硬编码字符串：`evil-domain.com` / `192.168.1.100` / `Global\Mutex123` / `HKLM\Software\Evil`）。`file sample.bin` 与 `strings sample.bin` 输出存 `sample-strings.txt`。

- **预期档位**: medium
- **考察维度**: 软件保护 / 信任边界
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:

  2. 写 `integrity_self_check.py`：程序启动时计算自身 `.text` 节区哈希（用 `hashlib.sha256(open(sys.argv[0],'rb').read())`）并与硬编码期望值比对。故意改脚本里一个空格，跑期望哈希不匹配报错。Read 验证哈希计算范围。

  4. 写 `protection-checklist.md`：为小型商业工具设计防破解清单——代码签名、线上激活、关键逻辑服务端化如何搭配；表格形式不超过 10 行。

### AD10 CVE 复现方法论
- **预期档位**: hard
- **考察维度**: 漏洞研究流程 / 负责任披露
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 写 `cve_methodology.md`：从 NVD/CVE 公告到本地复现的标准流程（版本锁定、补丁 diff 阅读、漏洞面定位）。选一个已公开多年的教学性漏洞（如经典整数溢出 CVE-2001-0500 类），写 `vuln_poc.c` 复现整数溢出触发条件。
  2. `gcc -o vuln_poc vuln_poc.c`，跑 `./vuln_poc` 期望触发溢出（如 `malloc(size)` 中 size 溢出成小值）。python3 `poc_verify.py` 验证溢出条件：输入 `size=0xFFFFFFFF + 1` 期望 `malloc` 实际分配极小 buffer。
  3. 隔离复现环境：写 `sandbox_env.sh` 用 `chroot` 或 `unshare` 模拟隔离（仅演示，不实际切换根）。`command -v unshare` 探测；若不可用降级：写 `sandbox_plan.md` 描述隔离要点。
  4. 写 `responsible_disclosure.md`：复现后转化为防御收益（检测规则、WAF/EDR 特征、内部培训案例）的流程；负责任披露 5 步流程（报告→确认→修复→披露→公告）。不超过 12 行。
