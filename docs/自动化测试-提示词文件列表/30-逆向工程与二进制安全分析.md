# 自动化测试提示词 — 逆向工程与二进制安全分析（AD01–AD10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。
> 边界约定：本维度全部以**合法学习、自有代码、本地 CTF 靶场、授权测试**为语境设计。

## 维度说明

本维度考察 Agent 在**二进制层面的分析与防御**能力：ELF 结构、静态反汇编阅读、
动态调试、栈溢出与 ROP 原理（本地靶场语境）、Frida 动态插桩、反混淆思路、
恶意样本静态分析（防御视角）、自身软件加固、CVE 复现方法论。
与 J 维度（Web 安全）互补：J 面向 Web 漏洞与密码学应用，
本维度面向二进制与系统层，兼防两面。

---

### AD01 ELF 文件结构解剖
- **预期档位**: medium
- **考察维度**: 二进制格式 + 工具链
- **对话脚本**:
  1. 用 readelf 逐段解析一个自己编译的 Hello World：文件头、程序头表、节区表各自描述什么？
  2. .text/.data/.bss/.rodata 各存放什么内容？加载进内存后的虚拟地址布局（代码段/数据段/堆/栈）是怎样的？
  3. 符号表与重定位：动态链接的 PLT/GOT 机制是什么？延迟绑定（lazy binding）的完整流程讲一遍。
  4. 不依赖 readelf，写一个脚本解析 ELF 头关键字段并打印节区清单，用 readelf 的输出交叉验证正确性。

### AD02 静态逆向入门：读懂反汇编
- **预期档位**: hard
- **考察维度**: 汇编阅读 + 编译器行为
- **对话脚本**:
  1. 用 gcc 以 -O0 编译一个含 if/循环/函数调用的 C 程序，用 `objdump -d` 对照源码逐行讲解关键指令。
  2. 讲清 x86-64 调用约定：参数寄存器、栈帧建立（push rbp / mov rbp,rsp）、返回值如何传递。
  3. 改用 -O2 重新编译对比：编译器做了哪些变换（内联、循环展开、死代码消除）？控制流结构还认得出来吗？
  4. 用同样的方法分析一个自己拿到的教学用 crackme（学习靶）：定位关键比较逻辑并完整解释推理链。

### AD03 动态调试：gdb 实战
- **预期档位**: medium
- **考察维度**: 调试器操作 + 事后分析
- **对话脚本**:
  1. gdb 基础串讲：断点/单步/查看寄存器与内存、`x/i` 反汇编当前指令，配一个示例程序逐命令演示。
  2. 条件断点与观察点：怎么用 watch 监控一个变量被谁改写？适合定位哪类 bug？
  3. 带符号与 strip 后的二进制在调试体验上差在哪？core dump 怎么配合 gdb 做崩溃后的事后分析？
  4. 实战：调试一个自己写的段错误程序，从寄存器与栈回溯一路定位到越界写的那一行源码。

### AD04 栈溢出原理与栈保护
- **预期档位**: hard
- **考察维度**: 漏洞原理 + 纵深防御
- **对话脚本**:
  1. 画图讲解函数栈帧布局；为什么对局部数组的越界写能覆盖到返回地址？
  2. 在自建虚拟机靶场里复现经典栈溢出实验：输入长度与返回地址偏移怎么计算？（仅本地实验环境）
  3. 防御逐层讲清：Canary、NX、ASLR、PIE 各自拦住攻击链的哪一环？现代默认编译选项下还剩哪些攻击面？
  4. 切换防御视角：审查你自己的一段 C 代码，找出所有未检查长度的 `strcpy`/`sprintf` 并全部修复。

### AD05 ROP 链构造入门
- **预期档位**: hard
- **考察维度**: 利用技术 + 对应防御
- **对话脚本**:
  1. NX 开启后为什么不能直接注入 shellcode 执行？ROP 的核心思想——用程序自身的指令片段拼出逻辑——是怎么成立的？
  2. 在本地练习靶上用 ROPgadget 找 gadget，理解 `pop rdi; ret` 这类片段如何配合传参。
  3. 讲清 ret2libc 思路：为什么 PLT/GOT 与库函数地址是关键？ASLR 对它构成什么影响？
  4. 回到防御者视角：控制流完整性（CFI）、shadow stack 类硬件特性是如何抬高 ROP 成本的？

### AD06 Frida 动态插桩：调试自己的 App
- **预期档位**: medium
- **考察维度**: 动态插桩 + 工程应用
- **对话脚本**:
  1. Frida 的架构（注入 agent + JS API）与典型适用场景；它和静态分析如何形成互补？
  2. 对你自己开发的 Android App：hook 一个方法打印入参与返回值，观察业务逻辑流转，写出脚本。
  3. hook 自编译 so 里的 native 函数：`Interceptor.attach` 的 onEnter/onLeave 怎么用？
  4. 讨论：除了安全测试，工程上还能用 Frida 做什么（性能采样、私有协议抓取、兼容性排查）？

### AD07 反混淆：控制流平坦化还原
- **预期档位**: hard
- **考察维度**: 混淆原理 + 还原思路
- **对话脚本**:
  1. 控制流平坦化（OLLVM 类）把结构化代码变成了什么样？讲清"分发器 + 状态变量大循环"的结构。
  2. 静态还原思路：用符号执行收集状态转移图、区分真实基本块与无关块，难点在哪？
  3. 动态辅助：用执行 trace 过滤未走到的路径，和静态分析怎么配合降低分析量？
  4. 平衡讨论：混淆强度、性能损耗、可维护性三者怎么权衡？商业软件应如何选择保护等级？

### AD08 恶意样本静态分析基础（防御视角）
- **预期档位**: medium
- **考察维度**: 样本分析纪律 + IOC 提取
- **对话脚本**:
  1. 隔离环境里拿到一个可疑文件，第一眼看什么？文件类型、哈希、字符串、导入表分别能暴露什么信息？
  2. PE 结构速览：导入表里出现 VirtualAlloc/CreateProcess/WriteProcessMemory 等函数暗示什么行为？为什么？
  3. 提取 IOC：域名、IP、互斥体名、注册表键，整理成一份可共享给防御团队的情报条目。
  4. 强调操作纪律：为什么绝不能在生产机运行样本？沙箱环境（隔离虚拟机、断网、一次性快照）的搭建要点。

### AD09 给自己的程序加防护
- **预期档位**: medium
- **考察维度**: 软件保护 + 信任边界
- **对话脚本**:
  1. 自研软件的 license 校验为什么单靠客户端必被绕过？信任边界应该怎么重新设计（服务端校验 + 签名）？
  2. 实现完整性自校验：程序启动时计算自身关键节的哈希并比对，检测是否被 patch。
  3. 反调试基础：ptrace 自附加、时间差检测的原理；解释这些手段为什么只能"提高成本"而非"绝对防护"。
  4. 综合方案：为一个小型商业工具设计防破解清单——代码签名、线上激活、关键逻辑服务端化如何搭配？

### AD10 CVE 复现方法论
- **预期档位**: hard
- **考察维度**: 漏洞研究流程 + 负责任披露
- **对话脚本**:
  1. 从 NVD/CVE 公告到本地复现的标准流程：版本锁定、补丁 diff 阅读、漏洞面定位分别怎么做？
  2. 搭建隔离复现环境：容器化锁定漏洞版本、快照、确保不影响外网的边界措施。
  3. 选一个已公开多年的教学性漏洞（如经典整数溢出）：讲解从 patch diff 定位根因到写出验证 PoC 的全过程。
  4. 复现之后怎么转化为防御收益（检测规则、WAF/EDR 特征、内部培训案例）？负责任披露的流程是什么？
