# 69 机器人与 ROS2 工程（BR01–BR10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**机器人工程与 ROS2 中间件**领域的实战能力：ROS2 核心通信原语
（话题/服务/动作/参数/QoS）、URDF 机器人建模与 tf2 坐标变换、Navigation2 导航栈、
MoveIt2 运动规划、Gazebo/Ignition 仿真、BT.CPP 行为树控制、Launch 生命周期与多机部署、
ros2_control 硬件接口抽象、Micro-ROS 嵌入式桥接、以及 bag 录制回放与 Rviz/rqt 可视化排障。
与现有维度互补：33（嵌入式/IoT）仅覆盖裸机与微控制器，不涉及 DDS 中间件与机器人算法栈；
28（游戏引擎/图形编程）覆盖渲染与物理，但不覆盖真实机器人的感知-规划-控制闭环与
分布式坐标变换；39（性能调优）与 22（分布式系统）不涉及机器人领域特有的实时约束与
传感器融合。本维度填补"机器人操作系统 + 真实机电系统"这一关键工程场景。

### BR01 ROS2 通信原语：从话题到动作
- **预期档位**: medium
- **考察维度**: ROS2 通信模型 + QoS + 类型系统
- **对话脚本**:
  1. 解释 ROS2 的四种通信原语（话题 publish/subscribe、服务 service、动作 action、参数 parameter）各自语义与适用场景：为什么长时任务必须用动作而非服务？动作的三个反馈通道（goal/result/feedback）分别给谁用？
  2. 用 rclpy 写一个"传感器话题 → 滤波后发布"的流水线节点：订阅 `sensor_msgs/Imu`，做低通滤波后发布自定义的 `FilteredImu` 消息类型。写出 `.msg` 定义、CMakeLists 编译依赖与 `ament` 导出方式。
  3. QoS 调优：激光雷达话题 20Hz 大数据量、里程计话题 100Hz 低延迟、参数事件偶发但必须可靠——三组分别该选哪种 `Reliability` / `Durability` / `History` 组合？给出调参依据与踩坑点（如 volatile durability + 晚到订阅者永远接不到消息）。
  4. 把上面的流水线改成 node composition：用 `rclcpp_components` 动态加载成组件，对比独立进程与进程内 composition 两种部署方式的序列化开销与零拷贝机制（ loaned messages）边界。
  5. 设计一个调试工具节点：用 `ros2 topic echo /info --filter "m.data > 5"` 风格的话题过滤订阅——借助 ROS2 的 Content Filtered Topics 或自定义方案实现，讨论 CDD 下过滤是在订阅端还是发布端做更高效。

### BR02 URDF 机器人建模与 tf2 坐标变换
- **预期档位**: hard
- **考察维度**: 机器人描述 + 运动学链 + 坐标树
- **对话脚本**:
  1. 为一个差速轮移动机器人写完整 URDF：包含 base_link、左右驱动轮（连续关节）、前后万向轮（固定关节）、激光雷达、IMU、摄像头 6 个连杆。注意 `<inertial>` 的惯性矩怎么算（长方体近似）以及 URDF 与 SDF 在仿真导出时的差异。
  2. 在上面模型上加一个 2-DOF 平面机械臂（肩+肘），关节限幅、传动比与 `<mimic>` 关节各写一例。讨论 URDF 无法表达哪些物理（柔性关节、传动间隙、电机电感）——这些要落到哪里？
  3. 用 tf2 讲解静态变换 vs 动态变换的区别：`static_transform_publisher` 放在 launch 文件里与放在 robot_state_publisher 里有什么区别？解释 TF 树不能有闭环链的原因，以及你有闭环四边形机构时怎么办（用 robot_state_publisher 的浮动关节或 URDF 拆分）。
  4. 写一个 tf2 监听器节点：监听 `map → odom → base_link → laser` 的变换链，实现一个 service 输入 3D 点坐标返回它在 map 系下的坐标。讨论 `waitForTransform` 的超时策略与 `lookupTransform(target, source, time)` 在慢传感器（如 5Hz GPS）上的插值陷阱。
  5. 排障场景：Rviz 报错 "Frame [xxx] does not exist"——系统化诊断 TF 树断链的五步 checklist（`ros2 run tf2_tools view_frames` → 检查 parent/child 写反 → 检查时间戳是否 stale → 检查静态 vs 动态重复发布 → 检查命名空间前缀）。

### BR03 Navigation2 导航栈：全局规划与局部控制
- **预期档位**: hard
- **考察维度**: 导航算法栈 + 行为服务器 + 代价地图
- **对话脚本**:
  1. 描述 Nav2 的顶层架构：`NavigateToPose` 动作服务器 → BehaviorTree 导航仪 → Planner Server + Controller Server + Recovery Server 各自职责。为什么 Nav2 用行为树而非普通 FSM 来编排？
  2. 代价地图（Costmap）双层：全局静态层 + 全局障碍层 + 局部障碍层各吃什么话题、怎么更新、膨胀半径参数怎么调（inflation_radius vs cost_scaling_factor 的数学含义，机器人半径与碰撞安全距的关系）。
  3. 替换全局规划器：把 Smac Hybrid-A*（混合 A*，考虑车辆最小转弯半径）替换默认 A*。解释 Dubins vs Reeds-Shepp 路径的差别与适用场景，以及在差速机器人上为什么可以放宽为多项式螺旋线。
  4. 局部控制器调参：DWB 与 MPPI 两种控制器对比——DWB 的轨迹评分函数怎么构造、MPPI 采样噪声协方差对狭窄通道通过性的影响。给出走廊场景与开阔场景两套参数。
  5. 仿真验证：用 Ignition Gazebo 搭一个含动态障碍物的走廊环境，写 Python 脚本循环发送 Nav2 目标点并统计到达率、路径长度与时间，输出一个简明评估报告。讨论 Nav2 的 "cancel navigation" 动作行为（是急停还是先减速到零）。

### BR04 MoveIt2 运动规划：从逆碰撞到抓放
- **预期档位**: hard
- **考察维度**: 运动规划 + 碰撞检测 + 抓取管线
- **对话脚本**:
  1. MoveIt2 的核心求解器架构：OMPL（采样基） / STOMP（优化基） / Pilz（工业节拍）三者在什么场景下选哪个？解释 RRT-Connect 的双树扩展为何在狭窄通道仍会退化。
  2. 用 `moveit_py` 写一段规划脚本：定义规划组 `arm` 与 `gripper`，设置工作空间约束（末端必须保持水平），规划到一个关节目标并执行。讨论 `move_group` 的 `plan()` 与 `go()` 两段式调用为什么必要。
  3. 碰撞环境搭建：用 Planning Scene Interface 动态添加一个 Mesh 障碍物（桌子），讨论 FCL 与 Bullet 两种碰撞检测后端在 Mesh-Mesh 精度与速度上的权衡。什么时候用_primitive 近似？
  4. 抓取管线：用 MoveIt Simple Grasp 规划一个 pick-and-place，讲解 grasp pose 到 IK 解的映射、pre-approach / grasp / lift / 预放置位姿四个 waypoint 的规划顺序。
  5. 真实部署瓶颈：解释 "规划成功但执行抖动" 的三种根因（目标跳变、碰撞检测延迟、控制器跟随误差），以及 MoveIt Servo（实时伺服）怎么用在线视觉反馈做闭环。讨论 Servo 的奇异点规避与关节限幅处理。

### BR05 Gazebo/Ignition 仿真：物理引擎与传感器仿真
- **预期档位**: medium
- **考察维度**: 仿真平台 + 传感器模型 + 插件
- **对话脚本**:
  1. Ignition Gazebo（现重命名 Gazebo Harmonic）与 Classic Gazebo 的关系是什么？列出 ODE、Bullet、DART、Simbody 四种物理引擎在接触稳定性、软体支持、速度三方面的对比。
  2. 写一个激光雷达 SDF 传感器插件配置：16 线、10Hz、带高斯噪声 `noise="gaussian"`，解释 `<min><max>` 角度与 `samples` 的关系，以及为什么仿真中的 ray count 远低于真实 Velodyne 会漏检黑色吸波材质。
  3. 实现一个简单的关节控制器插件（继承 `SystemPlugin`）：订阅速度命令话题，把力矩写入关节，同时读关节编码器并发布里程计。讨论 PID 参数在仿真与真实电机上的差异与迁移策略。
  4. 场景搭建：用 Gazebo 的 Building Editor 或 SDF `<level>` 搭一个含坡道、圆柱障碍、地面纹理的 `world` 文件，启用 `contact` 可视化。讨论仿真随机性——固定随机种子对复现接触异常的意义。
  5. 性能加速：对比 headless 模式（`-s` 无 GUI）+ 录制 vs 带 GUI 仿真的帧率差异；解释 `<real_time_factor>` 与 `<real_time_update_rate>` 的物理含义，以及为什么不能把仿真速率开太快（接触求解器迭代次数不足会穿模）。

### BR06 BT.CPP 行为树：机器人决策控制
- **预期档位**: medium
- **考察维度**: 行为树模型 + Groot 实时调试 + ROS2 集成
- **对话脚本**:
  1. BT.CPP v3/v4 的节点模型：`ControlNode`（Sequence/Fallback/Parallel）与 `ConditionNode`/`ActionNode` 的 tick 返回值语义。解释 Reactive Sequence 与普通 Sequence 的关键差异（父节点每次 tick 都从第一个子节点重新评估），以及为什么"传感器检查"必须用 Reactive 版本。
  2. 实现一个 ROS2 巡逻机器人行为树：`Fallback` 根 → `[低电量？ → 回充]` / `[导航到下一个航点 → 拍照 → 上传]`。给出 XML 文件与对应的 C++ 节点注册（`RosActionNode` 包装 MoveBase 动作）。
  3. 用 Groot 做实时可视化调试：在线查看当前 tick 路径高亮、强制单节点失败、动态修改黑板。解释 `Switch` 节点与 `Fallback` 加多个 `Condition` 的语义差异，以及为什么复杂条件分支更推荐用 `Switch`。
  4. 子树复用与端口：把"回充电"封装成 `SubTree`，通过 `remapping` 把不同场景的充电桩位置注入黑板。讨论 BT.CPP 的 `Any`/`Double`/`geometry_msgs::Pose` 跨节点类型安全是怎么保证的。
  5. 工程化：解析 XML 的行为树工厂与直接 C++ 构建行为树的权衡；BT.CPP 的异步执行模型与 ROS2 callback group 的配合——为什么阻塞动作节点会导致 ROS2 回调饥饿，如何用 `WaitForTick` 或专用 executor 缓解。

### BR07 ROS2 Launch、生命周期与多机部署
- **预期档位**: hard
- **考察维度**: 启动系统 + Lifecycle 状态机 + 分布式部署
- **对话脚本**:
  1. ROS2 Launch 的 Python 描述 vs XML/YAML 描述各有什么优劣？解释 `LaunchDescription` 中条件执行（`IfCondition` / `UnlessCondition`）、替换（`DeclareLaunchArgument`）与 OpaqueFunction 的组合用法。
  2. 实现一个 Lifecycle 节点（继承 `rclcpp_lifecycle::LifecycleNode`）：定义 `on_configure → on_activate → on_deactivate → on_cleanup → on_shutdown` 五个状态，在 `on_configure` 中分配大内存/订阅话题，`on_activate` 后才开始发布。解释为什么传感器驱动节点必须 Lifecycle 化？
  3. Lifecycle 协调：用 `nav2_lifecycle_manager` / `ros2 lifecycle set` 批量控制多个节点的启动顺序。当某个节点在 `on_activate` 卡死（比如等不到硬件），系统应如何优雅降级而非整体挂死？
  4. 多机部署：机器 A（GPU 主机跑 Nav2 + 感知）与机器 B（嵌入式实时控制器跑电机）之间如何通信？讲解 DDS 的发现机制（simple vs discovery server 模式）与多播失败时的 SROS 静态发现配置。
  5. 安全加固：SROS2 启用身份认证与加密后，多机场景下的证书分发流程。给出一个 `gros2` policy XML 示例：只允许 `/cmd_vel` 话题被 B 发布、`/scan` 话题被 A 发布，并且加密所有动作通信。

### BR08 ros2_control：硬件抽象与控制器管理
- **预期档位**: hard
- **考察维度**: 硬件接口抽象 + 控制器管理器 + 真实机电
- **对话脚本**:
  1. ros2_control 的四层架构：`Actuator/Sensor`（URDF `<ros2_control>` 标签） → `HardwareInterface`（实现 `read()`/`write()`） → `ResourceManager` → `ControllerManager`。解释为什么要把硬件抽象与控制器解耦（同一块电机板既能跑位置控制又能跑力矩控制）。
  2. 实现一个自定义 HardwareInterface：用 EtherCAT（soem）或串口（如 Dynamixel SDK）接入一个电机，在 `read()` 中读编码器位置/速度、在 `write()` 中写目标位置。讨论 `rclcpp::Duration` 控制循环周期抖动过大的危害与缓解手段（Linux PREEMPT_RT + 实时调度策略）。
  3. 控制器组合：用 `forward_command_controller` 做简单前馈 + `diff_drive_controller` 做差速轮里程计 + `joint_state_broadcaster` 发布 TF。给出 `ros2_control` 在 URDF 中的 `<command_interface>` 与 `<state_interface>` 定义示例。
  4. 硬件切换与故障诊断：当某个关节 HardwareInterface 返回 `ERROR`，ControllerManager 怎样通过 `deactivate` 仅停掉受影响控制器而不牵连整机？讨论 `gpio` 接口与 `sensor` 接口在错误隔离上的差异。
  5. 迁移对比：ROS1 `ros_control` 与 ROS2 `ros2_control` 的 API 变化——资源句柄从指针变值语义、控制循环从独立线程变 ControllerManager 管理、以及 RealSense 摄像头等"传感器型硬件"如何适配。

### BR09 Micro-ROS：嵌入式微控制器桥接
- **预期档位**: medium
- **考察维度**: 嵌入式 ROS 桥接 + micro-ROS Agent + 实时通信
- **对话脚本**:
  1. Micro-ROS 解决了什么痛点？对比三种传输：串口 / WiFi UDP / BLE。解释 Micro-ROS Agent 作为代理的角色——它把 MCU 上的 micro-ROS Client 翻译为 DDS-XRCE 后接入 ROS2 域，为什么中间必须 Agent 而不能让 MCU 直接跑完整 DDS？
  2. 在 ESP32 / STM32 / Arduino Portuno 上配置一个 micro-ROS 节点：发布超声波测距 + 订阅速度命令。给出 `colcon.meta` 与 `rmw_microxrcedds` 配置中的历史队列长度与内存池大小设定依据。
  3. 实时性讨论：MCU 端 1kHz 控制循环与 ROS2 10Hz 里程计发布之间的同步问题。micro-ROS 的"客户端-代理"模式下，MCU 重启后话题如何自动重连而不让 Agent 崩溃？
  4. 跨域通信：机器人本体（Linux + ROS2 HOA）↔ Micro-ROS MCU ↔ 云端（通过 Micro-ROS Agent 桥接到云 ROS2）。解释 `uros_agent` 的多种串口/UDP/TCP 启动方式，以及如何在多机器人场景下用不同的 `client_keys` 隔离多个 MCU。
  5. 调试工具箱：用 `ros2 topic echo /micro_ros_arduino_node_ping` 检查连通性；micro-ROS Agent 的丢包统计在哪看？讨论在 FreeRTOS 上运行时，堆栈溢出如何表现为"ROS2 话题突然静默"。

### BR10 排障实战：rosbag 录制回放与 Rviz/rqt 可视化
- **预期档位**: hard
- **考察维度**: 数据录制 + 可视化调试 + 系统化排障
- **对话脚本**:
  1. rosbag2 的存储后端选择：默认 mcap vs SQLite3，在录制带宽 500MB/s 点云数据时应选哪个？解释 rosbag2 的存储配置（max_bagfile_size、max_cache_size）与序列化格式（CDR 原生 vs 自定义序列化）对回放保真度的影响。
  2. 录制与过滤：只录制 `/scan`、`/tf`、`/odom`、`/imu` 四个话题并启动录制；回放时用 `ros2 bag play --remap /scan:=/scan_sim`。讨论在循环回放时如何处理时间戳偏移（`--clock` 与 `--use-sim-time` 的区别）。
  3. Rviz2 综合调试：同时显示 `LaserScan`（配 decay_time）、`Map`、`Path`（多条不同颜色对比 A* vs Hybrid-A*）、`RobotModel`、`TF` 五个显示插件。解释 Fixed Frame 设置错误时 Rviz 的表现（"Global Status: Error"），以及如何在有多个 TF 前缀的多机器人场景下隔离显示。
  4. rqt 工具箱组合：`rqt_graph` 看节点连接拓扑 → `rqt_plot` 实时画速度曲线 → `rqt_reconfigure` 动态调参 → `rqt_console` 按节点过滤错误日志。给出一个"导航机器人突然原地转圈"的四步排障流程：先查 TF → 再查代价地图 → 再查 local costmap 障碍层 → 最后查 cmd_vel 频率。
  5. 自动化排障脚本：写一个 ROS2 节点，订阅 `/diagnostics` topic，聚合 `diagnostic_msgs/DiagnosticArray`，当任何节点的 `HardwareStatus` 出现 `ERROR` 或 `STALE` 时自动发布到告警话题并触发一次 rosbag 片段录制（前后各 5 秒）。讨论如何用 `diagnostic_aggregator` 的规则文件聚合同类错误。
