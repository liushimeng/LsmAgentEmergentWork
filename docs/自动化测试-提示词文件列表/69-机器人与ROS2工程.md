# 69 机器人与 ROS2 工程（BR01–BR10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。
>
> 本维度考察 Agent 在**机器人工程与 ROS2 中间件**领域的实战能力。本文件特殊约束：**无机器人硬件、无 ROS2 安装** → 全程 python3 单进程模拟节点话题通信（threading.Queue）、坐标变换（4×4 矩阵）、代价地图（2D 栅格）、行为树（树遍历）。涉及 2D 物理仿真用纯 python 实现，避免依赖 ROS2 / Gazebo / RViz 等。
> 与现有维度互补：33（嵌入式/IoT）仅覆盖裸机与微控制器，不涉及 DDS 中间件与机器人算法栈；28（游戏引擎/图形编程）覆盖渲染与物理，但不覆盖真实机器人的感知-规划-控制闭环与分布式坐标变换；本维度填补"机器人操作系统 + 真实机电系统"这一关键工程场景。
> 每条都落到可执行产物：Write 写节点/规划器/控制器 → Bash 跑断言 → Read 核对关键代码 → Bash 跑多场景验证，产物全部在 `tmpPlan/agent-test/` 沙盒内

### BR01 ROS2 通信原语：从话题到动作
- **预期档位**: medium
- **考察维度**: ROS2 通信模型 + QoS + 类型系统
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下 Write `mini_ros.py`：实现 ROS2 四大原语的最小模拟——`Topic(name, qos)` 含 `publish(msg)`/`subscribe(callback)`（用 Queue 模拟 UDP 多播）、`Service`（req/resp 一次）、`Action`（goal/feedback/result 三通道）、`Parameter`（key/value dict）。演示一个 IMU 节点订阅 `imu_raw`、发布 `imu_filtered`。
  2. Bash 跑 `python3 tmpPlan/agent-test/mini_ros.py`，断言订阅端收到消息计数 ≥ 3（grep -F 校验），且消息内容通过 Queue 正确传递，印证「pub/sub 解耦」模型工作。
  3. Read `mini_ros.py` 确认 Topic 类含 QoS 参数。再 Write `qos_demo.py`：实现 QoS 三维度——`Reliability`（`reliable`/`best_effort`）、`Durability`（`volatile`/`transient_local`）、`History`（`keep_last(N)`/`keep_all`），演示 `best_effort + volatile + keep_last(5)` 在高频 IMU 场景丢弃晚到消息。
  4. Bash 跑 `python3 tmpPlan/agent-test/qos_demo.py`，断言 100Hz 发布 10Hz 订阅 + best_effort 时丢包率 > 50%、reliable 时丢包率 = 0%（grep -E 校验），用输出印证「QoS 选型决定带宽 vs 可靠性」。

### BR04 MoveIt2 运动规划：从逆碰撞到抓放
