# 自动化测试提示词 — 测试自动化与质量工程（T01–T10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent **不靠真框架**，把"单元测试 / Mock / TDD 红绿重构 / 集成夹具 / 契约测试 / 混沌注入 / 覆盖率 / 快照 / 报告生成 / CI 门禁"等测试工程任务，做成可 Read 可 Bash 的真实可执行产物——多文件产物、`unittest`/`assert` 自检、`bash` 串联断言、失败注入与修复闭环。

### T01 用 Python unittest 实现一个注册函数单元测试集
- **预期档位**: simple
- **考察维度**: 单元测试 / 边界覆盖 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t01/` 下写 `register.py`：实现 `register(email, password) -> dict`，规则——email 必须含 `@` 且 `.` 且长度 ≤254，password 长度 ≥8 且含数字与字母；违规抛 `ValueError("...")`。再写 `test_register.py` 用 `unittest.TestCase` 覆盖 6 个用例：合法注册、email 缺 `@`、email 缺 `.`、email 超长、password 太短、password 缺数字。
  2. 跑 `cd tmpPlan/agent-test/t01 && python -m unittest test_register -v 2>&1 | tee run.out`，期望最后一行含 `OK` 且 `Ran 6 tests`，`grep -c '^test_' run.out` 应 ≥6；不通过请 Read `register.py` 修边界条件重跑。
  3. 加一个"参数化"测试 `test_register_params.py`：用一个 `_CASES = [(...合法/非法...)]` 列表 + `subTest` 把 6 条用例循环跑一次，输出形如 `test_params_0 (email_ok) ... ok` 至少 6 行；`python -m unittest test_register_params -v` 必须 0 fail。
  4. 用 `bash verify.sh` 串联：跑 unittest、断言 `grep -E 'Ran 6 tests' run.out`、`grep -E 'OK$' run.out`、退出码恰为 `0`；故意把 `register.py` 的 email 校验删掉再跑一次，期望退出码非 0 且 stderr 含 `FAILED`，然后还原。

### T02 用 Python 手写一个最小 Mock 框架 + 桩验证
- **预期档位**: medium
- **考察维度**: Mock / 行为验证 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t02/` 下写 `email_sender.py`：定义 `EmailSender.send(to, subject, body) -> {"id":...}`，实现 `SmtpEmailSender`（用 `print` 假装发）+ `Notifier` 业务类（依赖 `EmailSender`）。再写 `mock.py` 实现一个最小 Mock：`Mock()` 支持 `.called` `.call_count` `.args` `.return_value`，调用记录到 `calls` 列表。
  2. 写 `test_mock.py`：`Mock(spec=EmailSender)` 注入 Notifier，调用 `notify(...)` 后断言 `mock.send.call_count == 1`、`.args[0][0] == "alice@x"`、`.called is True`；`python -m unittest test_mock -v` 全过写 `mock.out`。
  3. 加"调用次数不匹配"测试 `test_fail.py`：`assertEqual(call_count, 2)` 故意期望 2 次（实际 1 次），跑后 `unittest` 必报 `AssertionError: 1 != 2`，`bash verify_fail.sh` 断言退出码非 0、`stderr` 含 "AssertionError"；改回 1 后退出码 0。
  4. 加"Stub"对比：写 `test_stub.py` 用一个固定返回值桩（不是 Mock）替代依赖，证明"过度 Mock 的副作用"——把桩替换成 Mock 后断言调用次数断言**新增 1 个失败点**，用 `python -m unittest test_stub -v` 跑通 + `wc -l stub.out` 校验产物行数 ≥3。

### T03 TDD 红-绿-重构：括号匹配（多类型）
- **预期档位**: medium
- **考察维度**: TDD 闭环 / 多轮迭代 / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t03/` 下先写**失败的测试** `test_paren.py`：测 `is_balanced("(") is False`、`is_balanced("()") is True`、`is_balanced("(]") is False`；`python -m unittest test_paren -v` 必报 ImportError 或 AttributeError，stdout 含 "ERROR" 或 "FAIL"，写 `red.out` 存证。
  2. 写最小实现 `paren.py`：`is_balanced(s)` 只支持 `()`，跑 `unittest` 必须 `OK Ran 3 tests`，写 `green.out` 存证；请不要提前实现多类型（保持 TDD 节奏）。

  4. 写 `verify_tdd.sh`：`grep -c FAIL red.out` ≥1、`grep -c OK green.out` ≥1、`grep -c FAIL red2.out` ≥1、`grep -c OK green2.out` ≥1，且 `paren.py` 含 `(`、`)`、`[`、`]`、`{`、`}` 全部字符——任何一项不满足视为 TDD 节奏失败。

- **对话脚本**:

### T06 混沌工程：故障注入代理 + 韧性验证
- **预期档位**: hard
- **考察维度**: 故障注入 / 韧性闭环 / Bash 闭环
- **工具链**: Write → Write → Bash → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t06/` 下写 `real_api.py`（127.0.0.1:19601）一个"上游 HTTP 服务"，对 `/work` 返回 `{"ok":true}` 配 50ms `time.sleep`；写 `chaos_proxy.py`（19602）转发到 real_api，但有 30% 概率直接返回 503、10% 概率 sleep 5 秒、剩余 60% 正常转发；两个服务后台起，存 PID，写 `verify_mock.sh` `curl` 探活。
  2. 写 `client.py`：调用 chaos_proxy 的 `/work`，自带指数退避重试（最多 3 次，base 100ms，jitter 50ms）和熔断（连续 3 次 503 熔断 5 秒）；`verify_retry.sh` 跑 20 次调用，统计 `report.json` 至少含 `{retried_calls, succeeded, failed, circuit_opens}`，`jq -e '.succeeded >= 10'`（因 70% 成功率 + 重试应能撑住）。
  3. 写一个"恶意 chaos"测试：把 chaos_proxy 改成 100% 返回 503，期望 client 熔断触发（`jq -e '.circuit_opens >= 1'`），后续调用**立即失败**不浪费 5 秒——用 `time bash verify_chaos.sh` 测总耗时 < 8 秒（4 次调用 × 2 秒内），超时请 Read `client.py` 修熔断判定重跑。
  4. 写 `verify_recover.sh`：恢复正常 mock（0% 故障率），等 6 秒熔断窗口过，期望 client 自愈（`jq -e '.circuit_opens >= 1 and .succeeded_after_open >= 3'`），所有验证通过后 `kill` 两个 PID 并归档 `report.json`。

### T07 测试覆盖率：手写一个最小行/分支覆盖率统计器
- **预期档位**: medium
- **考察维度**: 覆盖率度量 / Bash 闭环 / 多轮产物
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t07/` 下写 `target.py`：实现 `grade(score)` 返回 `"A"/"B"/"C"/"F"`（阈值 90/80/70/0），再写 `runner.py` 用 `sys.settrace` 跟踪 target.py 源文件，记录每行是否被执行过、每个 `if/elif` 分支是否走过，输出 `cov.json` `{file, lines_total, lines_hit, branches_total, branches_hit}`。
  2. 跑 `python runner.py --suite full`（full 跑 90/80/70/0 四档），`jq -e '.lines_hit == .lines_total and .branches_hit == .branches_total'` 必须通过（100%）；故意把 suite 改成只跑一档，期望分支覆盖率 < 100%。
  3. 加 `--report md`：`runner.py --report md` 生成 `cov.md`，含表格 `| file | lines | branches |` 与一行数据；`awk -F'|' 'NR==3{print NF}' cov.md` 必须为 5（首尾空 + 3 字段）。
  4. 写 `verify.sh`：跑 full → 解析 → 必须 `lines_hit == lines_total`；再跑 partial → 必须 `branches_hit < branches_total`；两段结果都写到 `summary.out`，少一段就 exit 1。

### T08 快照测试：手写一个 HTML 输出快照 diff 工具
- **预期档位**: medium
- **考察维度**: 快照 / diff / Bash 闭环
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t08/` 下写 `render.py`：实现 `render_card(title, items) -> str` 返回一段 HTML（`<div class="card"><h2>title</h2><ul><li>items...</li></ul></div>`，**故意每次 `<li>` 加个随机生成的 16 字符 nonce 让输出不稳定**——本次任务要把 nonce 改成"基于输入 hash 稳定"。
  2. 写 `snapshot.py`：调 render 三次（固定输入），保存到 `snapshots/case1.html`，再跑一次比对，新输出与快照**逐字节一致**则 `PASS`，否则写 diff 到 `case1.diff`；`python snapshot.py run` 第一次必生成快照，再次跑必 `PASS`，写 `out.out`。
  3. 故意把 `render.py` 改成把 `<h2>` 改成 `<h3>`，跑 `snapshot.py run` 期望 `FAIL`，`case1.diff` 至少含 `-<h2>` 与 `+<h3>` 两行（`grep -c '<h2>' case1.diff` 与 `grep -c '<h3>' case1.diff` 均 ≥1）；`--update` 参数下应更新快照并 `PASS`。
  4. 加"快照瘦身"：`snapshot.py` 在 `--prune` 时去掉所有空白后比较，验证即使源码加个空行快照仍命中；`verify_prune.sh` 跑后 `out.out` 含 "PRUNED PASS"，失败请 Read `snapshot.py` 规范化逻辑重跑。

- **预期档位**: medium

- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:

  2. 跑 `python report.py && head -1 report.html` 必须是 `<!DOCTYPE html>` 或 `<html`，`grep -c '<table' report.html` ≥1、`grep -c '通过率' report.html` ≥1；`verify_html.sh` 跑通后用 `python -c "import html.parser; ..."` 简单解析校验含关键中文段落。
  3. 加"趋势对比"：手工造 `hist/` 下 5 个 `run_<N>.json`（N=1..5，通过率 0.6→0.95），`trend.py` 生成 `trend.txt` 用 ASCII 字符画通过率折线（每行一个 N + 20 列进度条）；`cat trend.txt` 至少 5 行、每行末位 `█` 数量单调不减。
  4. 写 `verify.sh`：`python report.py && python trend.py && python check.py`（check.py 校验 trend.txt 行数 = 5 且最后一行进度条 ≥ 第一行），任意一段失败 exit 1；通过则 `cat trend.txt` 写到 `final.out`。

### T10 质量门禁：用 bash 脚本串起 "测试+覆盖率+lint"
- **预期档位**: hard
- **考察维度**: 门禁设计 / Bash 闭环 / 失败注入
- **工具链**: Write → Bash → Write → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/t10/` 下写一个最小被测项目 `app/`：`app/add.py` `def add(a,b): return a+b`，`app/divide.py` `def divide(a,b): return a/b`（不处理 ZeroDivisionError）；写 `tests/test_app.py` 用 `unittest` 覆盖 add 4 条 + divide 2 条（其中一条故意 `divide(1,0)` 期望抛异常），`python -m unittest discover -v` 跑——当前因 divide 期望异常而实际未处理，必报 `FAILED`。
  2. 写 `gate.sh`：依次执行 `unittest` → `coverage`（用 T07 的 runner.py）→ `lint`（用 python `compile` 当最小 lint，未通过语法检查 exit 1），任一失败整体 exit 1 并把失败阶段写到 `gate.out`；先跑 `bash gate.sh` 期望 exit 1 且 `gate.out` 含 "STAGE=tests FAIL"。
  3. 修复 `divide.py` 加 ZeroDivisionError，再跑 `bash gate.sh` 期望 STAGE=tests PASS、STAGE=coverage PASS、STAGE=lint PASS；然后在 `add.py` 故意加 `import os`（unused）让 lint 阶段失败，期望 STAGE=lint FAIL 且 exit 1。
  4. 写 `verify_gate.sh`：跑 4 个用例矩阵（`gate.sh` 干净通过 / 缺测试 / 测试失败 / lint 失败），对应 `gate.out` 四种状态，期望矩阵 4/4 通过；任意一种 fail exit 1——失败请 Read `gate.sh` 修阶段判定逻辑重跑。
