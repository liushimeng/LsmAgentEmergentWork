### CX01 图的工程存储：邻接表与 CSR

- **预期档位**: medium
- **考察维度**: 大图存储结构 / 缓存友好 / 构建流程
- **对话脚本**:
  1. 三种存储对比：邻接矩阵（n² 空间，1000 万节点不可行）、邻接表 `Vec<Vec<u32>>`（指针跳跃缓存不友好）、CSR 压缩稀疏行（offsets + edges 两个扁平数组，连续内存）；用 Rust 实现三种并测「随机遍历全图」的耗时差（CSR 通常快 3~10 倍的原因：局部性）。
  2. CSR 构建：边列表先按源点排序（计数排序两遍：统计每点出度 → 前缀和得 offsets → 按序填 edges）；实现 `build_csr(edges: Vec<(u32,u32)>) -> Csr` 并验证无向图要正反各插一次。
  3. 动态图的处理：CSR 难以增删边——「批量重建」（积攒变更定期重排）或「CSR 主体 + 增量边补丁表」的混合结构；讨论社交图「读极多写极少」的特征为什么让 CSR 成为合理选择，以及什么场景必须退回邻接表。
  4. laew 借鉴：CSR「构建一次反复消费」对照 WorkFlow 拓扑分层（`topo_layers` 的 Kahn 算法输出层序列供并行执行）——讨论把「编排准备（图结构构建）」与「执行消费」分离的缓存机会（同一 plan 重试时复用分层结果）。

### CX02 PageRank：从原理到实现

- **预期档位**: hard
- **考察维度**: 幂迭代 / 阻尼系数 / 收敛与工程化
- **对话脚本**:
  1. 直觉与公式：网页重要性 = 「指向它的页面重要性之和 ÷ 出链数」的循环定义，迭代求解 `PR(v) = (1-d)/N + d × Σ PR(u)/outdeg(u)`；d=0.85 的直觉（随机游走 85% 沿链接、15% 随机跳转，解决悬挂点与环路陷阱）；手推 3 节点环 + 1 悬挂点的 5 轮迭代。
  2. 实现与收敛：均匀初值起迭代，收敛判据 `Σ|PR_new - PR_old| < 1e-6`（L1 范数）或固定 20~50 轮；用 Rust（CSR 存储，联动 CX01）实现迭代主循环，处理悬挂点（出度 0 的页面 PR 均匀回流全体），测百万节点可收敛。
  3. 工程变体：personalized PageRank（随机跳转向量非均匀——以用户关注页为起点，用于推荐/采样）、阻尼系数调低（0.5~0.7 收敛更快但更「局部」）；讨论 PageRank 在「社交影响力 / 论文引用 / 反欺诈关联度」三类场景的语义差异。
  4. laew 借鉴：PageRank「节点重要性由邻居重要性决定」对照 Agent 间依赖权重——Plan 生成的 WorkFlow 中，某单元的「关键度」可由其下游依赖数与依赖它的单元关键度递推（PageRank 式），用于失败重试预算分配（关键单元优先重试）。

### CX03 社区发现：Louvain 模块度优化

- **预期档位**: hard
- **考察维度**: 模块度定义 / 贪心局部移动 / 层次凝聚
- **对话脚本**:
  1. 模块度 Q：社区内边占比减去「随机基准下的期望占比」`Q = Σc [ ec/m - (dc/2m)² ]`，Q 越大社区结构越明显（0.3~0.7 为强社区）；用小图手算一个二社区结构的 Q 验证「随机图 Q≈0」。
  2. Louvain 两阶段循环：局部阶段——每个节点尝试移入「收益最大」的邻居社区（ΔQ 公式闭式计算），遍历到无改进；凝聚阶段——把每个社区折叠成超节点建新图，重复直到 Q 不再提升；用 Python 实现这两阶段并在空手道俱乐部图上复现已知二分（验证 Q≈0.42）。
  3. 工程要点：局部阶段节点遍历顺序影响结果（不唯一解）、用「社区内部度 / 与社区连边数」的增量维护避免全量重算 ΔQ、O(n log n) 近线性是它能在亿级图上跑的原因；对比 Leiden（Louvain 后继，保证社区连通性修复了断连缺陷）。
  4. laew 借鉴：社区发现「按连接强度自组织分组」对照任务聚类的无监督形态——session_memory 的任务摘要若按「共现关系」（同文件 / 同工具组合）做 Louvain 聚类，Yolo 召回历史时可按「社区」整体注入（同社区强相关），比逐条相似度更结构化。

### CX04 六度分隔：社交距离查询

- **预期档位**: medium
- **考察维度**: 双向 BFS / 阈值截断 / 真实社交图的直径
- **对话脚本**:
  1. 双向 BFS：从两人同时扩展 frontier（两个 visited 集），首次相遇即距离 = 两边深度和；实现并在「平均度 30」的图上对比单向 BFS 的访问节点数（期望 ~sqrt 量级缩减），解释为什么必须逐层扩展（一层一检查点）。
  2. 距离分布查询：「任意两人平均距离」= 抽样节点对跑双向 BFS（全对 BFS 不可行）；在真实社交图上典型结果「平均 3.5 跳、直径 8~12、度数幂律分布（少数 hubs 连接一切）」；写抽样统计脚本并画距离直方图。
  3. 工程化截断：距离 > 6 直接返回「无关联」（防极端深搜）、hubs 节点出度巨大导致 frontier 爆炸——「剪枝到 top-K 度数邻居」或改用「标志性节点锚点」近似（选 100 个地标预计算全图到地标的距离，任意两点距离 ≥ 三角不等式估计）；讨论精度换速度的取舍。
  4. laew 借鉴：地标锚点「预计算稀疏地标、查询时组合」对照项目上下文注入——为大型仓库预生成「模块级地标摘要」（入口 / 核心结构），Yolo 处理跨模块任务时用地标组合定位相关文件，而非全库逐文件读。

### CX05 中心性：找网络中的关键节点

- **预期档位**: medium~hard
- **考察维度**: 三种中心性语义 / 计算复杂度 / 场景选型
- **对话脚本**:
  1. 三种定义：度中心性（直接连接数——本地网红）、接近中心性（到全图平均最短路最短——消息扩散源头）、介数中心性（被最短路径经过次数——桥梁与瓶颈）；用 5~6 节点的手工图各算一遍并解释三种「关键」的语义差异（高介数节点移除会让网络碎裂）。
  2. 实现与复杂度：度 = O(m)；接近 = 单源 BFS 求和（每节点 O(n+m)，全图 O(n(n+m))）；精确介数 = Brandes 算法 O(nm)（前向 BFS 记路径数 + 反向累积依赖）；用 Python 实现 Brandes 并在千节点图验证与暴力 Dijkstra 路径枚举一致。
  3. 近似与场景：大图介数用「抽样源点」近似（随机取 100 个源跑部分 Brandes）；给三个业务各选一种中心性——防疫找超级传播者（度+接近）、反欺诈找资金桥（介数）、基础设施找骨干路由（介数+鲁棒性模拟）。
  4. laew 借鉴：介数中心性「被依赖最多的必经点」对照工具与 Agent 的依赖分析——若把「工具调用历史」建成图（工具→文件→Agent 节点），高介数文件（被多 Agent 多任务依赖）改动时应触发更强 QC 或提示用户影响面（联动 git 变更影响分析）。

### CX06 好友推荐：共同邻居与图嵌入

- **预期档位**: hard
- **考察维度**: 链接预测 / 相似度指标 / node2vec 思想
- **对话脚本**:
  1. 启发式指标：共同邻居数 CN、Jaccard（CN / 并集）、Adamic-Adar（CN 按「共同好友的度数」折扣——冷门共同好友信号更强 `Σ 1/log(deg(w))`）；用 Python 在小图上对「已存在的边 vs 随机不存在的边」打分验证 AUC 区分度，解释 AA 为什么惩罚「谁都认识的社交蝴蝶」。
  2. 链接预测流程：候选对生成（二跳邻域）→ 特征打分（CN/Jaccard/AA/偏好附件 `deg(u)×deg(v)`）→ 排序取 TopK → 过滤已有边与黑名单；实现端到端推荐并讨论冷启动（新用户无邻居——联动 CQ06 的内容兜底）。
  3. node2vec 思想：带偏随机游走（p 回退参数 q 前进参数控制 DFS/BFS 倾向）生成节点序列 → 按 word2vec Skip-gram 训节点 embedding → 向量近邻即结构相似；不实现完整版，而是写「DeepWalk 简化版」（纯随机游走 + Skip-gram）并用现成库跑通小图可视化。
  4. laew 借鉴：Adamic-Adar「冷门共同信号权重更高」对照历史摘要的召回价值——高频泛化经验（「先读 README」）人人都有信息量低，冷门但匹配的经验（「这个库的 v3 API 有坑」）应更高权重注入 Yolo 上下文。

### CX07 社交 Feed 流：推模式与拉模式

- **预期档位**: medium~hard
- **考察维度**: 推拉结合 / 大 V 问题 / 未读与一致性
- **对话脚本**:
  1. 两种模式：推（写扩散——发布时写入所有粉丝收件箱，读时直接拉自己收件箱，读快写炸）、拉（读扩散——读时聚合全部关注人的最新内容，写轻读重）；给「关注 200 人、粉丝 300 的普通用户」与「粉丝 1 亿的大 V」分别选模式并说明原因。
  2. 推拉结合策略：普通用户发布走推、大 V 发布走拉（在线拉取时合并）、大 V 的活跃粉丝（最近 7 天登录）可以推——「分级推拉」；实现 `get_feed(user)` 的合并逻辑（收件箱推流 + 在线拉大 V 流按时间归并去重）并写发布侧的路由决策函数。
  3. 工程细节：收件箱定长（只保最近 1000 条，更早的回源拉）、分页游标（联动 AQ04 时间戳游标）、计数与内容分离（未读数单独缓存累加）；讨论「删除/编辑推文后收件箱里的旧副本」的最终一致性处理（读时校验软删标记）。
  4. laew 借鉴：分级推拉对照 SessionContext 摘要注入——「最近 3 条」相当于收件箱定长推模式；讨论「老摘要按需拉」（用户提到上周任务时才检索归档，联动 CM07 赛季归档思想）的混合策略与触发词识别。

### CX08 图可视化：力导向布局

- **预期档位**: medium
- **考察维度**: 物理模拟布局 / 收敛控制 / 大图分级渲染
- **对话脚本**:
  1. 力导向模型（Fruchterman-Reingold 思想）：所有节点对受「库仑斥力」（防重叠）、每条边受「胡克引力」（拉近相连节点），迭代位移直到能量收敛；用 Python（或 Canvas，联动 CO 维）实现 50 节点小图的力导向并输出布局坐标动画。
  2. 收敛与扰动控制：初始随机布局 + 温度模拟退火（早期大步长后期细化）、步长上限防节点飞出、固定 seed 复现；调「理想边长」参数观察从「毛线团」到「清晰社区」的形态变化，并与 CX03 的社区着色叠加验证社区内聚性可视化。
  3. 大图处理：万级节点力导向跑不动——多级布局（先粗化图凝聚社区为超节点布局，再展开细化）、边抽取（只画重要边 / 邻居hover 时补边）、前端 Canvas 分层与 LOD；讨论「可视化目标决定抽象层级」——展示社区结构时该隐藏什么。
  4. laew 借鉴：力导向「关系自动成型」对照 Agent 协作关系可视化——Debug 报告里的「Agent 调用图」（Yolo→Main→Sub→QC 的边 + 数据流），用力导向布局生成架构快照，跨任务对比「结构漂移」（正常编排 vs 失败回流时的图形态差异）。

### CX10 图计算工程：Pregel 与批流一体

- **预期档位**: hard
- **考察维度**: BSP 超步模型 / 顶点中心编程 / 迭代到流式的迁移
- **对话脚本**:
  1. Pregel/BSP 模型：计算拆成超步（superstep）——每个顶点在超步内「收消息 → 本地计算 → 向邻居发消息」，全局屏障同步后进入下一超步，顶点可 vote_to_halt（无消息则休眠）；用「最大值泛洪」示例（每顶点把见过的最大值发给邻居，收敛于图直径轮）手推 3 个超步的消息表。
  2. 顶点中心实现：用 Rust 写单机版 Pregel 框架骨架（`trait VertexProgram { fn step(&mut self, msgs) -> Vec<(neighbor, msg)> }` + 超步循环 + halt 投票），并在此框架上重写 PageRank（联动 CX02）验证框架表达力。
  3. 工程化议题：消息聚合（combiner 减通信量——求和类消息先合并）、分区容错（检查点按超步快照，失败回滚整超步）、倾斜问题（超级节点的消息风暴用「聚合点 / 采样」缓解）；对照 docs 调研中 deepseek-harness 的 Worker 线程协议与 Pregel 的同构性。
  4. laew 借鉴：BSP「全局屏障 + 消息驱动」对照 laew 的同层并行（Semaphore 3 + 层间串行）——laew 的拓扑层就是「超步」，上游产物注入就是「消息」；讨论给 laew 加「层内消息传递」的收益（同层 SubAgent 互相可见进度）与死锁风险。
