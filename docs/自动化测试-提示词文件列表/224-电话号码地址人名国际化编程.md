### HK01 E.164 解析与格式化

- **预期档位**: medium
- **考察维度**: E.164 / 前缀处理 / 格式模板
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hk01_e164.py`：号码解析器：(a) **归一化**：去空格/连字符/括号，全角数字→半角，`00` 国际前缀→`+`，处理 `{国家码, 本国无 + 输入}` 两种缺省；(b) **国家元数据**：内置中/美/日/德/英五国 `{cc, 国家码, 移动位长, 固定位长, IDD}`（如 86 移动 11 位、1 NANP 10 位）；(c) **parse(input, default_region)** → `{e164, country, national, valid}`；(d) **格式化三态**：E.164（`+8613800138000`）/ 国际（`+86 138 0013 8000`）/ 本国（`138 0013 8000`），格式模板按国家存（NANP `(415) 555-2671`）；(e) **边界**：超长/含字母（非分机场景）/国家码不识别 → invalid 带原因码。
  2. Bash：跑 12 组样例断言：`0086138...` 与 `+86138...` 与 `138...`（default=CN）三者 e164 相同、`(415) 555-2671` 三态格式各自正确、`+999...` 报国家码不支持。
  3. Read 源码，再 Bash 断言：含全角转换、含 00→+ 归一、含五国元数据表。

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `tmpPlan/agent-test/hk04_teluri.py`：tel URI 工具：(a) **语法**：`tel:+8613800138000`（全局）与 `tel:13800138000;phone-context=+86`（本地+上下文），`ext=` 分机参数；**tel URI 不允许出现空格与可见分隔符**——格式化美观数字必须再归一；(b) **分机拨号语法对照**：PBX/手机通用 `,` = pause 2s（可叠 `,,`）、`;` = wait 确认（部分终端不支持——写兼容性注记表）；生成 `tel:+861088888888,,$EXT` 样例；(c) **SMS/mailto 双链**：`sms:+86...?body=` 的 URL 编码（中文 body 必须 percent-encode）；(d) **二维码载荷**：MECARD/vCard 中 TEL 字段格式，与裸 tel: 的差异注记（扫码场景选 vCard 可带姓名）；(e) 8 组 URI 生成 + 反向解析往返断言。
