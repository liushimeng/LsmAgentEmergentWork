# 自动化测试提示词 — 编程语言全景与多语言实战（Z01–Z10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度从 Agent 能力视角考察**多编程语言横向迁移**能力。每条挑一种语言(GO/Java/Kotlin/Swift/Ruby/PHP/Lua/Elixir/Zig/Haskell)作为载体，测试 Agent 在陌生语言生态下"读取约定 → 产出可运行产物 → 用工具验证"链路完整度。可用解释器仅 go/node/python3；不可运行的语言用 python3 写语义等价版与原版 diff 对拍。考察点覆盖跨语言类型系统、并发模型、运行时机制、元编程与构建系统。

### Z01 Go：并发抓取器 + worker pool
- **预期档位**: medium
- **考察维度**: goroutine/channel 调度 / 错误返回链
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 在 `tmpPlan/agent-test/` 下用 heredoc 生成 `urls.txt`（10 条 httpbin 风格的本地 URL 占位，但全部指向 127.0.0.1 不可达端口，用来演练错误路径）。然后写 `fetch.go`：用 `go run fetch.go urls.txt` 跑通，期望启动 5 个 worker、超时 3 秒、收集到 10 行 `<url> <bytes|err>` 输出落 `result.tsv`。
  2. Read `fetch.go` 验证 channel 关闭顺序：在 producer 写完 10 条后必须 `close(jobs)`，否则 worker 会在 range 处阻塞。跑 `go vet ./...` 与 `gofmt -d fetch.go` 自检，期望两个工具零输出。
  3. 用 Bash 故意把 `urls.txt` 删掉再跑 `go run fetch.go /no/such/file`，期望退出码非 0 且 stderr 含 `no such file`；再恢复文件，确认第二轮退出码为 0、结果文件仍可读。
  4. 把上面的 fetch 改成 worker=20 重跑，对比 `time` 输出的 wall 时长差异，写一段 `notes.md` 总结 worker 数与不可达错误路径下并发上限的实测结论（不超过 10 行）。

### Z02 Java：JVM 内存区域演示 + ThreadLocal 泄漏复现
- **预期档位**: medium
- **考察维度**: JVM 内存模型 / 工具链复现
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. 先用 `command -v java javac jcmd` 探测可用性（Java 不在白名单则降级：写 `MemModel.md` 用 ASCII 图标出堆/元空间/虚拟机栈/直接内存四区，并写 `OOMDemo.java` 保留源码不要求编译）。可用时继续：在 `tmpPlan/agent-test/` 写 `OOMDemo.java`，分别演示堆 OOM（不断 `new byte[1MB]`）与直接内存 OOM（`-XX:MaxDirectMemorySize=32m` 反复 allocate），用 `javac OOMDemo.java` 编译。
  2. 跑 `java -Xmx64m -XX:+HeapDumpOnOutOfMemoryError OOMDemo` 触发堆 OOM，期望退出码非 0、stderr 含 `java.lang.OutOfMemoryError: Java heap space`、同目录生成 `java_pid*.hprof` 文件。用 Bash 统计 hprof 文件大小（`ls -lh java_pid*.hprof`），验证非 0。
  3. Read `OOMDemo.java` 加 `ThreadLocal<Byte[]>` 缓存项 + `remove()` 修复对比版 `OOMDemoFixed.java`，两文件同时编译。先跑原版 100 次循环看 OutOfMemory 出现位置；再跑修复版同样次数，期望全程不抛 OOM。
  4. 用 Bash 写一行总结到 `oom-summary.md`：两版退出码、stderr 关键字、耗时对比表。提醒 `command -v jmap`，若可用则跑 `jcmd <pid> VM.native_memory summary` 把 native memory 章节摘录贴进 summary。
