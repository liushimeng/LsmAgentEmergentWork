# 自动化测试提示词 — 编程语言全景与多语言实战（Z01–Z10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**多编程语言生态的横向实战**能力：Go 并发模型、Java/JVM 调优、
Kotlin 协程 Flow、SwiftUI 声明式 UI、Ruby 元编程 DSL、PHP/Laravel Web 生态、
Lua 宿主嵌入、Elixir Actor 容错、Zig 手动内存管理、Haskell 类型驱动开发。
与 E 维度（Rust 编码调试）和 Q 维度（范式趣味编程）互补：E/Q 以 Rust 为主要载体，
本维度"每条一种语言"，考察语言特色特性的掌握与跨语言迁移对比能力，
覆盖"编写各种软件 / 使用各种编程语言"的全谱系需求。

### Z01 Go：并发网页抓取器与 worker pool
- **预期档位**: medium
- **考察维度**: goroutine/channel/context 并发模型
- **对话脚本**:
  1. 用 Go 写一个并发网页抓取工具：读取一个 URL 列表文件，并发抓取每个页面并统计标题与字节数。先给出整体结构与关键类型设计，不要急着写实现。
  2. 基于上面的设计，用 goroutine + channel 实现一个 worker pool，把并发度限制为 5，任务分发与结果回收都走 channel。
  3. 加上 `context` 超时与取消：单个请求 3 秒超时；收到中断信号后优雅退出，已完成的任务结果不丢失。
  4. 对比 Go 的 goroutine 编程模型和 Rust tokio 的 async/await：把这套代码迁移到 Rust，哪些部分必须重写？两边的错误处理风格差异怎么消化？

### Z02 Java：JVM 内存区域与 OOM 排查
- **预期档位**: medium
- **考察维度**: JVM 内存模型 + 排查工具链
- **对话脚本**:
  1. 一个 Java Web 服务运行三四天后抛 OOM，先讲清 JVM 运行时数据区（堆/元空间/虚拟机栈/直接内存）各自存放什么、哪些区域会引发 OOM。
  2. 给出排查路径：怎么用 `jmap`、`jstat`、`jstack` 或 arthas 判断是堆泄漏、类加载泄漏还是堆外内存问题？
  3. G1、CMS、ZGC 三款收集器的适用场景各是什么？为这个"大堆低延迟"服务写一组 JVM 启动参数并逐项解释。
  4. 写一个最小可复现的 ThreadLocal 泄漏示例，说明泄漏链路（Entry 的 key 是弱引用为什么还会漏），并给出修复后的正确写法。

### Z03 Kotlin：协程 Flow 流式日志处理
- **预期档位**: medium
- **考察维度**: 协程/Flow 操作符 + 结构化并发
- **对话脚本**:
  1. 用 Kotlin 实现：监听一个不断追加的日志文件，Flow 每 500ms 发射新增行，解析后打印等级与消息。
  2. 在这条 Flow 上组合操作符：过滤 DEBUG、异常行自动 retry 3 次、`collect` 消费，全程不阻塞主线程。
  3. 讲解结构化并发：外部作用域取消时这些子协程如何联动取消？和 Go 的 `context` 传递取消相比，谁更显式、谁更隐式？
  4. 用 `kotlinx-coroutines-test` 的虚拟时间为上面的流写单元测试，把原本 3 秒的等待压缩到毫秒级完成。

### Z04 Swift：SwiftUI 汇率换算 App
- **预期档位**: medium
- **考察维度**: 声明式 UI + 状态管理
- **对话脚本**:
  1. 用 SwiftUI 实现一个汇率换算 App：输入金额、选择币种，实时显示换算结果，先把视图结构搭出来。
  2. 讲清 `@State` / `@ObservedObject` / `@EnvironmentObject` 的边界，然后把换算逻辑抽成独立类型，按正确的属性包装器重构数据流。
  3. 为换算结果添加数字滚动动画，并适配深色模式与动态字体（辅助功能大字号）。
  4. 结合上面的实践，对比 SwiftUI、Flutter、Jetpack Compose 三者的声明式 UI diff 思路：状态变化如何映射为界面更新？各家的"身份（identity）"概念有什么差异？

### Z05 Ruby：元编程实现迷你测试框架
- **预期档位**: hard
- **考察维度**: 元编程 + DSL 设计
- **对话脚本**:
  1. 用 Ruby 写一个类 RSpec 的迷你测试框架，目标语法是 `describe "栈" do it "弹出后为空" do expect(stack.size).to eq(0) end end`。先设计整体结构（测试收集、断言、运行、报告）。
  2. 说明 `method_missing`、`define_method`、`instance_eval` 分别怎么撑起这些 DSL 关键字，并实现第一版可运行代码。
  3. 扩展框架：支持 `before/after` 钩子、收集失败用例并在结束时输出汇总报告（通过/失败/异常分列）。
  4. 讨论元编程的代价：猴子补丁污染、IDE 无法静态分析、报错栈难读。如果用 Rust 宏实现同样的框架，思路和边界会有什么不同？

### Z06 PHP：Laravel 短链接服务
- **预期档位**: medium
- **考察维度**: Web 框架工程 + 生态实践
- **对话脚本**:
  1. 用 Laravel 设计一个短链接服务：给出路由定义、Eloquent 模型和数据库迁移文件，先不写业务逻辑。
  2. 实现短码生成（Base62 + 冲突重试）与 302 跳转；访问计数写入异步队列而不是同步落库，说明为什么。
  3. 写一个限流中间件：同一 IP 每分钟最多创建 60 条短链，超限返回 429，用 Redis 实现计数窗口。
  4. 讲讲生产部署要点：opcache、队列 worker 常驻与守护、迁移执行顺序，以及 Composer 的锁文件为什么必须提交到版本库。

### Z07 Lua：给 C 程序嵌一个脚本引擎
- **预期档位**: hard
- **考察维度**: 语言嵌入 + C/Lua 交互栈
- **对话脚本**:
  1. 为什么游戏引擎和网络设备喜欢嵌 Lua 作为脚本层？讲讲 Lua 虚拟机与宿主语言之间的"交互栈"模型。
  2. 写一个最小 C 宿主程序：初始化 Lua 状态、注册 `get_config(key)` C 函数、执行一段调用它的脚本并取回结果。
  3. 反向打通：宿主读取 Lua 全局函数并调用，传入参数、取回返回值；同时把 `os`/`io` 库从沙箱里移除，解释这防住了什么。
  4. 对比用 WebAssembly 当嵌入脚本层：安全边界、启动开销、二进制体积、生态各有什么优劣？分别适合什么宿主场景？

### Z08 Elixir：GenServer 连接池与"让它崩溃"
- **预期档位**: hard
- **考察维度**: Actor 模型 + 容错监督树
- **对话脚本**:
  1. 用 Elixir 写一个 GenServer 管理数据库连接池：init 建池、handle_call 借还连接，讲清进程邮箱的串行化语义。
  2. 把它挂进 Supervisor 树，演示 one_for_one 与 rest_for_one 策略差异：兄弟进程崩溃后谁会被重启、状态怎么恢复？
  3. 用 `Task.async_stream` 并发处理一批请求：设置超时与最大并发，单个失败不拖垮整批，讲清有序性与超时语义。
  4. 讨论"让它崩溃"哲学与防御式编程的分界线；同样的连接池放在 Rust/Go 里，错误处理与恢复会怎么写？

### Z09 Zig：手动内存管理与 comptime
- **预期档位**: hard
- **考察维度**: 手动内存 + 编译期计算
- **对话脚本**:
  1. Zig 和 Rust 的内存安全哲学差异是什么？`comptime` 与 C++ 模板、Rust 泛型相比有什么独特之处？
  2. 用 Zig 实现一个动态数组：手动管理扩容（realloc 语义）、显式 destroy，接口风格对齐 `std.ArrayList`。
  3. 用 `comptime` 实现一个编译期泛型哈希表或 JSON 序列化器：类型信息在编译期展开、零运行时反射。
  4. 讲清 ArenaAllocator 与 GeneralPurposeAllocator 的适用场景；怎样用检测分配器验证上面的动态数组有没有泄漏？

### Z10 Haskell：类型驱动开发配置解析器
- **预期档位**: hard
- **考察维度**: 纯函数 + 类型建模 + 属性测试
- **对话脚本**:
  1. 用 Haskell 的 newtype + 智能构造器设计"非空用户名""正数端口"类型，让非法值在类型层面就无法构造出来。
  2. 基于这些类型写一个 INI 配置解析器：解析过程保持纯函数，用自定义 Writer 类型累积警告日志。
  3. 用 QuickCheck 为解析器写属性测试：任意合法配置序列化后再反序列化，应还原为等价配置。
  4. 讨论"纯函数 + 不可变数据"对测试与并发的意义；什么规模的工程值得引入 Haskell，什么情况下它是负担？
