### EX01 服务定义统一模型与校验器

- **预期档位**: hard
- **考察维度**: 统一建模 / 字段校验
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `ex01_model.py`：跨平台服务统一模型（name/exec/args/env/restart_policy 取 no/on-failure/always/healthcheck/log_path/user/uid）与校验器：必填、枚举、args 列表 env 字典、user 与 uid 二选一、name 匹配 ^[a-z][a-z0-9-]*$；输出规范化 JSON 供后续复用。
  2. Bash：`python3 -m py_compile ex01_model.py` 断言语法；`python3 ex01_model.py --selftest | tee ex01_run.log`（含一非法样例），`grep -F 'restart_policy' ex01_run.log` 断言点名。
  3. Read `ex01_model.py`，再 Write `ex01_services.json`：2 合法（web/api）+1 非法（restart_policy 误写 always-restart）。本轮必须显式复用第一轮的字段与枚举取值，不允许另起无关主题。
  4. Bash：`python3 -m json.tool ex01_services.json >/dev/null` 断言合法；`python3 ex01_model.py --input ex01_services.json | tee ex01_validate.log`，`grep -F 'always-restart' ex01_validate.log` 断言被拒。

### EX02 systemd unit 生成与版本兼容降级

- **预期档位**: hard
- **考察维度**: unit 生成 / 指令版本表
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `ex02_systemd.py`：从统一模型生成 unit（Description/After/ExecStart/Restart/WantedBy 等指令）仅落盘不安装；内置指令版本表（MemoryDenyWriteExecute≥231、RestrictSUIDSGID≥242、ProtectProc≥247），`--target-version`（CentOS 7 为 219）剥离不支持指令并输出降级说明与双版本 diff。
  2. Bash：`python3 -m py_compile ex02_systemd.py` 断言语法；`python3 ex02_systemd.py --selftest | tee ex02_run.log`，`grep -F 'ProtectProc' ex02_run.log` 断言命中。
  3. Read `ex02_systemd.py`，再 Write `ex02_service.json`：加固服务定义：ProtectProc=yes、RestrictSUIDSGID=yes、MemoryDenyWriteExecute=yes。本轮必须显式复用第一轮的字段与版本表结论，不允许另起无关主题。
  4. Bash：`python3 ex02_systemd.py --input ex02_service.json --target-version 219 --out ex02_v219.unit` 并同法生成 249 版 ex02_v249.unit；`if grep -q ProtectProc ex02_v219.unit; then exit 1; fi` 且 `grep -F 'ProtectProc' ex02_v249.unit` 断言 219 剥离、249 保留。

### EX05 cron 兼容层与守护包装脚本

- **预期档位**: medium
- **考察维度**: @reboot / pid 防双跑
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `ex05_cronwrap.sh`：无 systemd 退化守护（POSIX sh）：start（pid 防双跑、setsid/nohup、echo 占位）、stop（仅作用 tmpPlan 假 pid）、status（退出码 0/3）；print-cron 输出 `@reboot` 行仅打印不安装。
  2. Bash：`sh -n ex05_cronwrap.sh` 断言语法；`sh ex05_cronwrap.sh status >/dev/null 2>&1; test $? -eq 3` 断言退出码 3；`sh ex05_cronwrap.sh print-cron | tee ex05_cron.txt`，`grep -F '@reboot' ex05_cron.txt` 断言生成。
  3. Read `ex05_cron.txt`，再 Write `ex05_crontab.txt`：完整片段：头注释、SHELL/PATH 行、@reboot 启动行、每小时 status 巡检行。本轮必须显式复用第一轮的脚本与日志路径约定，不允许另起无关主题。
  4. Bash：`grep -E '@reboot|PATH=' ex05_crontab.txt` 断言结构；`test -s ex05_crontab.txt` 断言非空。

### EX06 健康检查与自愈退避

- **预期档位**: hard
- **考察维度**: 三模式探活 / 退避重启
- **工具链**: Write → Bash → Read → Write
- **对话脚本**:
  1. Write `ex06_healthcheck.py`：三模式探活：http（读模拟响应文件状态码）、process（pid 文件 os.kill(pid,0)）、heartbeat（mtime 超 timeout 判 FAIL）；失败按 1m/5m/30m 退避（dry-run 打印），超 5 次升级告警。
  2. Bash：`python3 -m py_compile ex06_healthcheck.py` 断言语法；`mkdir -p ex06_tmp && touch -d '2 hours ago' ex06_tmp/heartbeat.json` 制造过期心跳；`python3 ex06_healthcheck.py --mode heartbeat --file ex06_tmp/heartbeat.json --timeout 300 | tee ex06_run.log`，`grep -F 'FAIL' ex06_run.log` 断言触发。
  3. Read `ex06_run.log`，再 Write `ex06_conf.json`：3 服务：web（http 不存在响应文件）、worker（不存在 pid）、batch（复用第二轮过期心跳文件）。本轮必须显式复用第一轮的 mode/timeout/backoff 字段，不允许另起无关主题。
  4. Bash：`python3 -m json.tool ex06_conf.json >/dev/null` 断言合法；`python3 ex06_healthcheck.py --config ex06_conf.json | tee ex06_alerts.log`，`test $(grep -cF 'FAIL' ex06_alerts.log) -ge 3` 断言检出。
