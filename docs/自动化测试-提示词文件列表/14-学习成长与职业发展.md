# 自动化测试提示词 — 学习成长与职业发展（N01–N10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**求职面试、学习规划、职业转型、个人知识管理**等
"工作日常的个人成长侧"场景中的表现，与 A 维度（组织内的任务/协作）互补：
A 考察"把事做好"，本维度考察"把人变强"。
涵盖简历打磨、系统设计面试、行为面试、新语言学习路线、费曼学习法、
英文文档阅读、转型规划、述职谈判、知识库搭建、年度规划等主题。

---

### N01 简历项目经历打磨
- **预期档位**: simple
- **考察维度**: 结构化表达 + 量化意识
- **对话脚本**:
  1. 我简历里有一条："负责公司订单系统的开发与维护"。请指出这条描述的问题并给出改写方向。
  2. 按STAR法则（情境-任务-行动-结果）改写，数据可以合理假设但要标注"待核实"。
  3. 同一段经历要投两个岗位：电商后端开发、平台基础架构。说明两者简历侧重应有什么不同。
  4. 总结"量化成果"的五个常用维度（性能/成本/效率/质量/业务），检查改写后是否都覆盖到了。

### N02 系统设计面试：短链服务
- **预期档位**: medium
- **考察维度**: 架构推演 + 权衡表达（面试场景）
- **对话脚本**:
  1. 面试题"设计一个短链服务（如 t.cn/abc123）"，请给出第一版方案：核心接口、存储模型、生成算法。
  2. 追问：怎么保证短码唯一？哈希冲突和发号器两种路线怎么选？
  3. 追问：读多写少（100:1），怎么加缓存？热点短链被恶意刷怎么限流？
  4. 总结这类系统设计题的答题框架（澄清需求→估算→设计→深挖→权衡），并指出我刚才回答里缺的环节。

### N03 行为面试 STAR 训练
- **预期档位**: simple
- **考察维度**: 叙事结构 + 追问应对
- **对话脚本**:
  1. 行为面试题"讲一次你和同事发生分歧的经历"。先解释 STAR 法则，再给一个回答模板框架。
  2. 我按模板填了个草稿：和同事争论用同步还是异步通知。请点评这个素材是否合适、怎么强化"结果"部分。
  3. 面试官常见的 3 个追问（"如果重来会怎么做""对方为什么不认同"）该怎么准备？
  4. 提炼行为面试的三个禁忌（如编造、甩锅、无细节），说明踩雷的典型表现。

### N04 新语言学习路线设计
- **预期档位**: simple
- **考察维度**: 学习路径规划 + 迁移式学习
- **对话脚本**:
  1. 我已熟练掌握 Rust，想两周内入门 Go。请设计一个按天粒度的学习路线。
  2. 对比两种语言的三个"思维转换陷阱"（如错误处理、并发模型、无所有权），说明从 Rust 过去最容易犯什么错。
  3. 路线里安排一个练手项目：用 Go 重写一个简化版 laew 的 `-p` 单轮模式（读参数→发 HTTP→打印结果），给出项目结构建议。
  4. 学完怎么验证自己真的入门了？给一份 10 条的自测清单。

### N05 费曼学习法与技术博客
- **预期档位**: simple
- **考察维度**: 学习方法论 + 输出倒逼输入
- **对话脚本**:
  1. 什么是费曼学习法？"讲给外行听"为什么能检验理解深度？
  2. 我刚学了 Rust 生命周期，想写成博客。帮我设计文章大纲，要求假设读者只会 Python。
  3. "讲给外行听"环节：我用"图书馆借书的借阅期限"类比生命周期，这个类比哪里贴切、哪里会误导？
  4. 基于三轮讨论，把大纲扩写成 500 字左右的博客开头（含类比和一句免责说明）。

### N06 英文技术文档阅读策略
- **预期档位**: simple
- **考察维度**: 术语处理 + 阅读效率
- **对话脚本**:
  1. 读英文技术文档（如 Rust 官方 Book）最常卡在哪类内容？长难句、术语还是惯用表达？
  2. "ownership is moved, not copied"这类句子里的术语该背还是该理解？给一套技术英语词汇积累方法。
  3. 给我 10 个 Rust/编程文档高频的抽象名词（如 invariant、trait、sugar），逐个给一句话解释和一个例句。
  4. 讨论读原文和读中文翻译的取舍：什么情况必须读原文？

### N07 职业转型规划：后端转 AI 应用开发
- **预期档位**: medium
- **考察维度**: 转型路径 + 能力差距分析
- **对话脚本**:
  1. 一个五年经验的 Java 后端想转型 AI 应用开发（Agent/LLM 方向），列出能力差距清单（按优先级）。
  2. 设计一个 3 个月转型计划：每月一个里程碑，可交付、可验证。
  3. 分析他现有优势里哪些在 AI 应用开发中反而是"迁移资产"（如工程化、系统设计），如何在新简历里重新包装。
  4. 讨论转型的风险对冲：不辞职的前提下，怎么用业余项目验证这条路走不走得通？

### N08 晋升述职与薪酬沟通
- **预期档位**: simple
- **考察维度**: 自我呈现 + 沟通策略
- **对话脚本**:
  1. 晋升述职 PPT 的核心结构是什么？"罗列做过的项目"和"论证达到下一职级"的区别在哪？
  2. 我的述职主线是"从执行者到方案owner"，帮我列 3 个最能支撑该主张的案例筛选标准。
  3. 述职通过后谈调薪，HR 说"这次名额有限"。给出两套应对话术（争取本期/锁定下期承诺）。
  4. 总结与上级谈职业发展的三个时机和各自的启动话术。

### N09 个人知识管理系统搭建
- **预期档位**: medium
- **考察维度**: 知识管理方法论 + 工具落地
- **对话脚本**:
  1. 对比 PARA 和 Zettelkasten 两种知识管理法的核心思想和适用人群，我"收藏多、复习少"该选哪个？
  2. 用 Markdown + 本地文件夹设计一套最小可行的知识库：目录结构、命名规范、入口索引文件。
  3. 写出这个体系的"每日/每周维护清单"（各不超过 5 条），重点是防堆积而不是完美整理。
  4. 讨论：笔记工具换了很多个都失败的根本原因是什么？给"工具优先"派三条劝告。

### N10 年度复盘与来年规划
- **预期档位**: simple
- **考察维度**: 个人复盘方法论（与 A10 的项目复盘角度不同）
- **对话脚本**:
  1. 个人年度复盘和项目复盘（A10 那种三段式）关注点有什么不同？设计一个适合个人的五问复盘框架。
  2. 按这个框架演示一遍：假设今年"完成了一次转型尝试但没拿到结果"，怎么写才不失真也不自我否定。
  3. 基于这份复盘，制定来年的"三个结果目标 + 两个过程目标"，说明两种目标的区别。
  4. 给"年底规划年初就忘"这个经典问题设计一个可执行的提醒与回看机制。
