### BG01 写一个迷你 Redis：RESP 协议与过期淘汰
- **预期档位**: hard
- **考察维度**: RESP2/3 协议 + 内存淘汰 + 并发模型
- **对话脚本**:
  1. 用 Rust 写一个迷你 Redis 的 RESP 协议解析：支持 5 种类型——Simple String（`+OK\r\n`）、Error（`-ERR msg\r\n`）、Integer（`:123\r\n`）、Bulk String（`$5\r\nhello\r\n`）、Array（`*2\r\n...`）；用状态机逐字节读，处理 INLINE 命令（无 array header 直接发 `PING\r\n`）。
  2. 实现核心命令：`SET key val` / `GET key` / `DEL key` / `INCR key` / `EXPIRE key seconds`；数据存在 `Arc<DashMap<String, (Vec<u8>, Option<Instant>)>>`；TTL 用惰性删除 + 定期采样删除（不能每次 GET 都遍历）。
  3. 内存淘汰策略（maxmemory-policy）：实现 `allkeys-lru`（最近最少使用），用 `lru` crate 维护访问序；写满时按 LRU 淘汰直到低于上限；这是 Redis 6 大策略中最常用的一种。
  4. 给 laew 的 SessionContext Agent 设计 KV 缓存：把高频的 session 摘要按 Session ID 存到自写迷你 Redis（LRU + 1h TTL），避免每次任务都查 SQLite；启动时作为 sidecar 子进程跑在 6380 端口。

### BG02 写一个迷你 Git：对象库、索引与提交图
- **预期档位**: hard
- **考察维度**: 内容寻址 SHA-1 + zlib 压缩 + DAG 遍历
- **对话脚本**:
  1. 用 Rust 写 Git 的对象库：4 种对象（blob 存文件内容、tree 存目录结构、commit 存提交元数据、tag 存标签），都用 zlib 压缩后存到 `.git/objects/xx/yyyy...`（路径是 SHA-1 前 2 位 + 后 38 位）；写一个 `hash-object` 把任意文件存为 blob。
  2. 写 tree 对象：递归构造目录结构，每个 tree entry 格式 `<mode> <name>\0<20-byte SHA-1>`（注意 mode 是 6 位八进制如 `100644`、分隔符是 NUL 不是空格）；SHA-1 是内容寻址，同一文件只存一份。
  3. 实现 commit、log、checkout：`commit-tree` 把 tree + parent commit(s) + author/committer + message 包成 commit；`log` 用 parent 指针遍历 DAG；`checkout` 把 tree 反序列化到工作区（按 entry 写文件，处理 mode 100755 加执行权限）。
  4. 给 laew 加 `git-like undo`：当 BashTool 修改文件时，自动 commit 一份到 `.laew/snapshots/`（内容寻址 + zlib），用户 `/undo 3` 能回到 3 步前；这是 laew 从「Agent CLI」升级到「带 checkpoint 的 Agent」的 P0 功能。

### BG03 写一个迷你 Docker：namespace + cgroup + chroot
- **预期档位**: hard
- **考察维度**: Linux 三大隔离原语 + rootfs 解压
- **对话脚本**:
  1. 用 Rust 写一个迷你 Docker：用 `clone(CLONE_NEWPID | CLONE_NEWNS | CLONE_NEWUTS | CLONE_NEWIPC | CLONE_NEWNET | CLONE_NEWUSER, ...)` 创建子进程，每个 flag 对应一种 namespace 隔离；父进程用 `/proc/<pid>/ns/*` 文件描述符持有 namespace 引用。
  2. cgroup v2 限制资源：`/sys/fs/cgroup/<name>/memory.max` 写值限制内存；`cpu.max` 限制 CPU；用 `libc::setpriority` 调整进程优先级；这是 OOM-killer 触发点，要避免宿主被拖累。
  3. chroot / pivot_root：先 `mkdir rootfs` 把 Alpine 镜像解压（约 5MB），`pivot_root(rootfs, rootfs/.pivot)` 把根切换过去（比 chroot 安全，能撤销）；网络用 veth pair + bridge 配独立子网。
  4. 给 laew 的 BashTool 加沙箱模式：用户启动时 `laew --sandbox` 把所有 Bash 命令跑在自写 mini-Docker 容器里（namespace 隔离 + cgroup 限 4GB 内存），防止 `rm -rf /` 误操作；这是 laew 走向生产级 Agent CLI 的 P0 安全升级。

### BG04 写一个迷你 HTTP 服务器：解析、Keep-Alive 与静态文件
- **预期档位**: medium
- **考察维度**: HTTP/1.1 状态机 + 长连接 + MIME 探测
- **对话脚本**:
  1. 用 Rust 写 HTTP/1.1 解析器：状态机读请求行（`GET /path HTTP/1.1\r\n`）+ Headers（`Host: localhost\r\n` 多个）+ 空行（`\r\n`）+ 可选 body；用 `tokio` 异步 + `BufReader` 按行读，注意 `\r\n` 与 `\n` 都要容错。
  2. 实现路由与响应：`/` 返回 HTML；`/api/data` 返回 JSON（serde_json 序列化）；`/static/*` 返回文件（读盘 + `Content-Type` 用 mime_guess crate 探测）；状态码用 enum（200/404/500/...），body 前缀必须是 `HTTP/1.1 <code> <msg>\r\n`。
  3. Keep-Alive：HTTP/1.1 默认长连接，复用一个 TCP 连接处理多个请求；用 `Connection: close` 或请求计数（默认 100）断开；用 tokio 的 `select!` 同时监听 socket 关闭信号。
  4. 给 laew 的 Debug Agent 报告预览器：在 TUI 主屏加 `Ctrl+D` 弹出迷你 HTTP 服务器（127.0.0.1:随机端口），把最新 DebugReport 渲染成 HTML 让用户浏览器查看；复用迷你 HTTP 实现零外部依赖。

### BG05 写一个 JSON 解析器：递归下降与错误定位
- **预期档位**: medium
- **考察维度**: 递归下降 + UTF-8 验证 + 错误恢复
- **对话脚本**:
  1. 用 Rust 写一个 JSON 解析器：先词法分析切 token（`{` `}` `[` `]` `,` `:` STRING NUMBER BOOL NULL），再递归下降解析 `value → object | array | string | number | bool | null`；每个 token 带行列号用于错误定位。
  2. 数字解析细节：JSON 数字是十进制、可以有负号、小数、指数（`1.5e10`），但不允许前导零（`012` 非法）、十六进制（`0x1A` 非法）、`NaN`/`Infinity`（非标准）；用 `f64::from_str` 但要校验前缀合规。
  3. 字符串解析与转义：`\"` `\\` `\/` `\b` `\f` `\n` `\r` `\t` `\uXXXX`；`\uXXXX` 要正确处理 surrogate pair 表示的 emoji（如 `😀` = 😀）；错误信息要带「期望 `}` 但遇到 `,` 在第 5 行第 12 列」这种精确定位。
  4. 给 laew 的 ProviderForm 加 JSON 错误定位：用户粘贴的 end_point 配置如果是 JSON 格式，解析失败时在 TUI 屏下方高亮错误行列（复用迷你 JSON 解析器的错误定位），比 serde_json 的纯字符串报错体验好 10 倍。

### BG06 写一个正则引擎：NFA 构造与回溯控制
- **预期档位**: hard
- **考察维度**: Thompson NFA + 子集构造 DFA + 防 ReDoS
- **对话脚本**:
  1. 用 Rust 实现正则引擎第 1 步：解析正则字面量 `a(b|c)*d` → AST（连接、选择 `|`、Kleine 星 `*`、`+` `?`、括号）；用 Pratt parser 处理运算符优先级（`*` > 连接 > `|`）。
  2. Thompson 构造法把 AST 转 NFA：每个字符是一个状态，边是字符转移；`|` 用 ε-边分叉，`*` 用 ε-边环回；用「子集构造法」模拟 NFA 时维护当前活跃状态集合（Closure + Move）。
  3. 防 ReDoS（正则拒绝服务）：`^(a+)+$` 在输入 `aaaaX` 时回溯指数次导致 CPU 爆满；用「原子组」（atomic group）或 NFA→DFA 转换消除回溯；DFA 匹配每字符只走一步，O(n) 严格。
  4. 给 laew 的 BashTool 命令过滤加白名单正则：用户配置 `cmd_whitelist = ["^git (status|diff|log)$", "^cargo (build|test|fmt)$"]` 时用自写 NFA/DFA 引擎校验，避免引第三方 regex crate 引入 ReDoS 风险（恶意输入 `(a+)+$` 卡死 laew 进程）。

### BG07 写一个栈式虚拟机：字节码、指令集与 GC
- **预期档位**: hard
- **考察维度**: 字节码设计 + 标记清扫 GC + 调用栈
- **对话脚本**:
  1. 用 Rust 写一个栈式虚拟机（类似 JVM / CPython）：设计指令集 `PUSH i` / `POP` / `ADD` / `SUB` / `JMP offset` / `JZ offset` / `CALL func_idx` / `RET` / `LOAD n` / `STORE n` / `HALT`；字节码用 `Vec<u8>` 存，每条指令 1-3 字节。
  2. 实现执行循环：fetch-decode-execute 三阶段；操作数栈 `Vec<Value>`；调用栈帧 `Vec<Frame { locals: Vec<Value>, ret_addr: usize }>`；CALL 把当前 PC 压栈再跳，RET 弹出栈帧恢复 PC。
  3. 加垃圾回收（标记-清扫）：所有 `Value` 是 `GcRef(u32)` 索引指向堆 `Vec<GcObject>`；GC 阶段 1 从根（操作数栈 + 局部变量）递归 mark 所有可达对象，阶段 2 sweep 不可达对象；STW（stop-the-world）暂停虚拟机。
  4. 给 laew 的 SubAgent-Work 加「栈式执行沙箱」：把 BashTool 调用序列编译成自写 VM 字节码（`BASH cd /a` `BASH ls` `READ /a/main.rs` ...），VM 解释执行并能 rollback 到任意指令点（GC 即「清理已分配的临时文件描述符」），调试 SubAgent 行为更可控。

### BG08 写一个迷你数据库：B+ 树、页管理与 WAL
- **预期档位**: hard
- **考察维度**: B+ 树分裂 + 4KB 页 + WAL 崩溃恢复
- **对话脚本**:
  1. 用 Rust 写一个迷你数据库：存储分 4KB 页（与 OS page size 对齐），每页有 header（页类型 / 空闲偏移 / 单元数）；数据按 B+ 树组织（内部节点存 key + 子页指针，叶子节点存 key + value 链表）。
  2. B+ 树分裂：插入触发页满时分裂为两页，把中间 key 提到父节点；递归上溢直到根（根也满就创建新根，树增高）；删除时合并下溢；查询路径是 root → 内部节点二分查找 → 叶子节点二分查找。
  3. WAL（Write-Ahead Log）：每次修改先 append 到 `db.log`（含 redo/undo 记录），再改内存页；崩溃重启时 replay log 恢复；定期 checkpoint 把脏页刷到 `db.data` 主文件并截断 log（SQLite WAL 模式就是这样）。
  4. 给 laew 的 SQLite 升级：当前 laew 用 SQLite 直接存 session_memory / agent_memory；可以参考迷你 DB 设计加一层「表级 WAL + 异步 checkpoint」，把 SQLite I/O 从主流程异步化，让 Yolo Agent 的响应延迟降低 30%+。

### BG09 写一个协程与调度器：栈切换与任务队列
- **预期档位**: hard
- **考察维度**: 上下文切换 + 调度器 + Future 状态机
- **对话脚本**:
  1. 用 Rust 写一个迷你协程：用 `std::mem::transmute` + 一段手工分配的栈（`mmap(PROT_READ|PROT_WRITE, MAP_ANONYMOUS|MAP_STACK, -1, 0, 1MB)`）保存寄存器上下文（rip/rsp/rbp/rbx/r12-r15），实现 `swap_context()` 切换；这正是 Go goroutine 与 Rust async runtime 的底层。
  2. 调度器：N 个协程跑在 M 个 OS 线程上（M:N 模型），每个 worker 线程持有一个 ready queue；协程 `yield()` 把控制权交回调度器，调度器选下一个 ready 协程执行；用 `condvar` 实现唤醒。
  3. async/await 状态机：Rust 的 async fn 编译成 `enum Future { Pending, Ready(T) }` 状态机，每次 `poll` 推进一个状态；可以用迷你协程手动实现 `block_on(future)` 主循环，poll 嵌套 future 直到 Ready。
  4. 给 laew 的 MultiAgentOrchestrator 加协程调度：当前 SubAgent 并发用 tokio::spawn（OS 线程较重）；改造为自写协程池（N=100 协程 / M=4 OS 线程），同 Session 内 100 个 Workflow 单元切换开销从 μs 降到 ns，TUI 响应更流畅。

### BG10 写一个终端文本编辑器：gap buffer 与 undo 树
- **预期档位**: hard
- **考察维度**: Gap buffer + 撤销树 + 终端渲染
- **对话脚本**:
  1. 用 Rust 写一个终端文本编辑器（vim 简化版）：核心数据结构是 gap buffer——一个大数组 `Vec<char>`，中间留一个「gap」（光标位置），插入 = 把字符塞进 gap（O(1)），删除 = 扩大 gap（O(1)），光标移动 = 调整 gap 位置；比链表实现好 10 倍。
  2. 撤销树：传统撤销是栈（撤销 A → 撤销 B 不能回到 A），撤销树允许分支保留所有历史——节点 = 编辑操作，孩子 = 在该状态下产生的新操作；`u` 撤销到父节点，`Ctrl+R` 重做到子节点，Vim 同款设计。
  3. 终端渲染：用 crossterm 进入 raw mode + alternate screen，每帧只重绘变化行（脏行标记）；文件大时虚拟滚动（只渲染可见行）；语法高亮按 token 着色（关键字/字符串/注释 3 类就够 demo）。
  4. 给 laew 的 TUI 主屏加内嵌文本编辑器：用户输入 `/edit some_file.md` 进入编辑模式，复用 gap buffer + undo 树实现在 TUI 内修改文件；这比 `vim` 子进程更集成（保存时自动调 SessionContext Agent 生成会话摘要），是 laew 「Agent 内置编辑器」的雏形。
