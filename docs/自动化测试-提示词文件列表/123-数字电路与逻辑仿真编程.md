### DO01 布尔代数与化简：从真值表到最小电路

- **预期档位**: simple~medium
- **考察维度**: 布尔代数 / 卡诺图 / 电路最小化
- **对话脚本**:
  1. 一切组合电路的起点是真值表：把"三人表决器（≥2 人同意即通过）"写成 8 行真值表，再用布尔代数（`A·B + A·C + B·C`）表达；推导德摩根律 `!(A+B) = !A·!B` 并用它把或非结构改写为与非结构。
  2. 针对上面的代数化简，上卡诺图（Karnaugh map）：画 3 变量卡诺图圈相邻的 1，讲"圈越大项越简、圈必须为 2 的幂、边界可环绕"三条规则；用卡诺图重做表决器，比较两种方法得到的表达式与门数。
  3. 基于上面的化简，程序化最小化：Quine-McCluskey 算法思想——枚举最小项、按 1 的个数分组合并消元、素蕴含项覆盖表选择；说明为什么 QM 是"可编程的卡诺图"但变量数超过 10 后组合爆炸（这正是逻辑综合工具用启发式的原因）。
  4. 动手：实现真值表→表达式的工具：输入任意 4 变量以内真值表，输出 SOP 最简式（可先实现完全枚举化简，QM 为加分项），并用门级求值器（与/或/非门的图结构求值）验证化简前后所有输入组合输出一致。

### DO02 组合逻辑器件：多路器、译码器与七段显示

- **预期档位**: medium
- **考察维度**: MSI 器件 / 结构化建模 / 复用与译码
- **对话脚本**:
  1. 三件套标准件：**多路器 MUX**（2^n 选 1，地址端选择数据源——数据选择）、**译码器**（n 线入 2^n 线出，地址激活一根线——地址展开）、**编码器**（译码器反面）；用"单刀多掷开关"和"一排指示灯"类比讲清语义，并说明 MUX 为什么是"可编程逻辑的最小单元"（任何布尔函数都能用 MUX 树实现）。
  2. 针对上面的 MUX 万能性，做一个证明练习：仅用 4 选 1 MUX（+常量 0/1）实现三人表决器——把 AB 接地址端、数据端按真值表接 C/!C/常量；归纳"n 变量函数用 2^(n-1) 选 1 MUX 实现"的通用配方。
  3. 基于上面的器件，做七段显示译码：4 位 BCD 输入 → 7 根段输出（a~g）的真值表设计（含数字 0-9 的字形），讨论"非法输入（10-15）显示什么"的 Don't care 处理如何反过来帮助化简。
  4. 动手：用代码实现结构化门网表（Gate { op, inputs, output }）+ 求值器，把七段译码器建成门级网表，对一个 BCD 计数器（0-9 循环）驱动输出逐字符的七段 ASCII 图形（` _ |_|` 风格），验证 0-9 每个字形正确。

### DO03 加法器与 ALU：从半加器到带标志的运算单元

- **预期档位**: medium
- **考察维度**: 进位链 / 超前进位 / 标志位设计
- **对话脚本**:
  1. 一位半加器（S = A XOR B，C = A·B）→ 全加器（加入进位输入，S = A⊕B⊕Cin，Cout = AB + Cin(A⊕B)）；级联 8 个全加器构成行波进位加法器（RCA），解释"行波"的含义——最坏进位要穿过 8 级门，延迟线性增长。
  2. 针对上面的延迟，上超前进位（Carry Lookahead）：定义生成 `G=A·B` 与传播 `P=A⊕B`，推导 `C_{i+1} = G_i + P_i·C_i` 展开两层即得任意进位——延迟 O(1) 但门扇入爆炸；说明 16 位加法器为何常用"4 位 CLU 块 + 块间行波/递归"的分层结构。
  3. 基于上面的加法器，扩展成 ALU：减法用补码（B 取反加一，Sub 控制线同时控制异或与 Cin=1）；四个标志位——Zero（结果全 0 的或非）、Carry（最高进位）、Sign（最高位）、Overflow（`Cin⊕Cout` 于最高位，有符号溢出的异或判别式）——并解释 V 标志为什么不是简单取最高进位。
  4. 动手：实现 8 位 ALU 仿真器：`alu(a, b, op) -> (result, flags)`，op 含 AND/OR/XOR/ADD/SUB/SLT（比较）；用 128 + 100（无符号溢出）与 -128 + (-1)（有符号溢出）两组用例验证 C 与 V 标志的独立性，写对拍脚本与 CPU 内建加减法全组合一致。

### DO04 锁存器与触发器：状态的第一块砖

- **预期档位**: medium~hard
- **考察维度**: 电平/边沿敏感 / 时序约束 / 亚稳态
- **对话脚本**:
  1. 交叉耦合的或非门构成 SR 锁存器（S 置位/R 复位，SR=11 为非法态——两个输出同时为 0 破坏互补性）；加门控变 D 锁存器（使能有效时透明跟随），再讨论"锁存器透明期"为什么不能串两级（数据直通穿透）。
  2. 针对上面的穿透问题，讲边沿触发 D 触发器：主从两级的经典结构——主锁存器在时钟低电平跟随、高电平锁存，从锁存器相反——数据只在时钟上升沿"一次性"转移；说明"边沿敏感 = 只在跳变瞬间采样"的精确定义。
  3. 基于上面的时序，建立两大时序约束：建立时间（setup，数据须在沿前稳定 T_su）与保持时间（hold，沿后仍须稳定 T_h）；违反约束的后果是**亚稳态**——输出悬在中间电压不定时长后随机落到 0 或 1；解释"亚稳态无法根除只能概率衰减"与双触发器同步器（打两拍）降低失效率的工程实践。
  4. 动手：实现带时序检查的 D 触发器行为模型：输入数据跳变时间距时钟沿 <T_su 或 >−T_h 时按概率（比如 10%）输出 X（不定态）持续随机周期；构造异步按钮信号进入 100MHz 时钟域的仿真，对比"直接采样"与"两拍同步器"的失效率统计。

### DO05 有限状态机的电路实现：Mealy、Moore 与编码选择

- **预期档位**: medium~hard
- **考察维度**: FSM 电路化 / 状态编码 / 综合思维
- **对话脚本**:
  1. 状态机两型：Moore（输出只依赖当前状态——输出对时钟对齐、抗输入毛刺）与 Mealy（输出依赖状态+输入——少一个状态但组合路径直通输出）；用同一个"1011 序列检测器"分别设计两版，对比状态数（Moore 多一个）与输出时序差一拍。
  2. 针对上面的设计，走电路化三段式：状态寄存器（D 触发器组）+ 次态逻辑（组合，状态+输入→次态）+ 输出逻辑（组合）；说明"三段式"（寄存器/次态/输出分开写）为什么是可综合状态机的标准写法（每段职责单一便于约束与调试）。
  3. 基于上面的结构，讲状态编码的取舍：二进制（触发器最少 `log2(n)` 但译码延迟大）、one-hot（每状态一个触发器，比较逻辑退化为单比特、FPGA 上首选）、格雷码（相邻状态单比特翻转——防瞬态误码）；给出"状态数 ≤8 的 FPGA 设计默认 one-hot"的经验依据。
  4. 动手：把 1011 检测器实现为可仿真网表（D 触发器 + 组合逻辑），分别做二进制与 one-hot 两版；写测试激励（随机 200 位输入流，软件参考模型对拍）；再故意在 Mealy 版的输入路径注入一个短毛刺，观察输出毛刺如何穿透（为 DO08 的冒险话题埋伏笔）。

### DO06 用 Verilog 子集描述与仿真电路

- **预期档位**: medium~hard
- **考察维度**: HDL 思维 / 阻塞 vs 非阻塞 / 测试平台
- **对话脚本**:
  1. HDL 是"描述硬件"不是"顺序编程"：`assign y = a & b;` 描述持续生效的导线连接（组合），`always @(posedge clk) q <= d;` 描述时钟沿触发的寄存器；用"assign = 画导线、always = 造器件"的口诀建立心智模型，解释"并发"是硬件描述的默认语义（所有语句同时生效）。
  2. 针对上面的语义，深入最著名的坑——阻塞 `=` 与非阻塞 `<=`：在同一 always 块里用 `=` 的语句按序"立即生效"（可能把中间值传给下一句），`<=` 的右侧全部采样旧值、左侧统一在时钟沿末更新；用"三级移位寄存器写错成一级"的经典 bug 演示，归纳"时序逻辑用 <=、组合逻辑用 =、混用必错"的铁律。
  3. 基于上面的语义，写测试平台（testbench）：时钟发生器 `always #5 clk = ~clk;`、激励施加（initial 块分时赋值）、`$display`/波形 dump；说明仿真器如何执行（按时间槽调度事件——衔接 DO07 自研仿真器的原理）。
  4. 动手：用 Verilog 子集实现"带使能与异步复位的 4 位计数器 + 七段译码（复用 DO02 的真值表）"并写 testbench：复位后从 0 数到 9 循环，输出段码与软件参考模型逐拍对拍；用 iverilog（开源）或自写子集仿真器跑通，观察 VCD 波形中异步复位不等待时钟沿立即生效的现象。

### DO07 自研事件驱动逻辑仿真器

- **预期档位**: hard
- **考察维度**: 事件调度 / delta 周期 / 多值逻辑
- **对话脚本**:
  1. 电路仿真器的两大流派：编译驱动（把网表编译成函数直接求值循环，直到收敛——简单但难处理延迟）与**事件驱动**（只有信号变化才调度求值——真实仿真器的核心）；解释事件驱动的核心数据结构：时间轮（time wheel）+ 每时刻的事件队列。
  2. 针对上面的结构，实现零延迟收敛的细节：同一仿真时刻内信号变化触发的新求值放在 **delta 周期**（无限细分的时间片）里循环求值直到稳定——否则组合环或长组合链在同一时刻"看不到"中间结果；说明这正是 Verilog 语义中 `#0` 与 delta 的来源，以及组合环为什么会导致仿真器"不收敛"报错。
  3. 基于上面的 delta 机制，加入延迟与多值逻辑：门延迟（信号变化调度到 `t+delay` 执行）、四值逻辑 0/1/X/Z 的运算表（X 参与的与门何时确定何时传染、Z 高阻与上拉）；说明上电初始态为什么全是 X，以及复位序列在仿真中"把 X 驱逐"的意义。
  4. 动手：实现 `Simulator { schedule(time, cb), run_until(t) }` + 门级网表加载 + VCD 波形导出；跑通 DO05 的 1011 检测器（验证 delta 收敛正确）、构造组合环网表验证不收敛检测、跑 DO04 的触发器模型验证 X 传染路径；对比你的输出与 iverilog 对同一网表的 VCD 是否时序一致。

### DO08 门延迟、竞争与冒险：毛刺从哪来

- **预期档位**: hard
- **考察维度**: 延迟模型 / 竞争冒险 / 消除策略
- **对话脚本**:
  1. 理想门零延迟，真实门有惯性延迟（inertial，比门延迟窄的脉冲被"吃掉"）与传输延迟（transport，任何变化都传播）两种模型；用 `A & !A` 结构（信号经非门产生 1 门延迟差）演示输出短暂毛刺——这就是**冒险**（hazard）。
  2. 针对上面的毛刺来源，分类：功能冒险（卡诺图上相邻圈不重叠处，如 `F = AB + !AC` 在 B=C=1 且 A 翻转时）与逻辑冒险（单输入变化经不同路径赛跑）；用卡诺图**添冗余项**（`+BC`）消除逻辑冒险的几何解释——相邻 1 圈相互重叠。
  3. 基于上面的消除术，讨论系统性方案：为什么时钟同步设计（信号只在时钟沿被采样）让毛刺在稳定期内无害化、为什么"绝不把组合逻辑输出直接当时钟或异步复位"是数字设计第一军规、格雷码计数器跨时钟域单比特变化如何从根上避免多位毛刺采样错值。
  4. 动手：在 DO07 的仿真器上做实验矩阵：给同一网表的门赋不同延迟，分别用惯性/传输模型跑激励，用波形定位毛刺窗口宽度；然后 (a) 加冗余项、(b) 输出寄存一拍 两种消除方案分别验证毛刺消失，写实验报告对比两种方案的成本（门数 vs 一拍延迟）。

### DO09 流水线数据通路：把时间切成级

- **预期档位**: hard
- **考察维度**: 流水线寄存器 / 数据控制冒险 / 转发与气泡
- **对话脚本**:
  1. 把一条"取指-译码-执行-访存-写回"五段组合逻辑插上流水线寄存器，吞吐从"每 5T 出一条指令"变成"每 T 出一条"（加速比趋近级数）；画出五级时空图（横轴周期纵轴指令的错落斜线），说明为什么流水线不缩短单条延迟只提高吞吐。
  2. 针对上面的理想图，引入数据冒险：`add r1,r2,r3` 后紧跟 `sub r4,r1,r5`——sub 在第 2 级要读 r1 而 add 还没写回；两条出路——停顿（插入气泡 bubble 冲空一级）与**转发**（把执行级/访存级的结果直接拉回执行级输入的多路选择，前递网络）；写出需要转发的三种距离（1/2/3 条间隔）判别条件。
  3. 基于上面的数据冒险，补控制冒险：条件跳转在执行级才知道方向，取指级已经猜着取了两条——讨论分支预测暴论（静态预测不跳转/向后跳转）、预测错误的冲刷（flush）代价公式 `penalty = 已流过的级数`；load-use 冒险为什么转发救不了（数据在访存级末尾才就绪，必须强制一个气泡）。
  4. 动手：实现五级流水线仿真器（指令集可用 8 条简化 RISC）：结构体数组当流水线寄存器、每周期整体"往前推一格"；跑一段含相邻依赖、load-use、前跳后不跳的程序，分别统计（停顿周期/转发命中次数/预测命中）；与软件标量参考模型对拍每条指令的写回值保证功能正确。

### DO10 NAND2Tetris：用与非门搭一个 CPU

- **预期档位**: hard
- **考察维度**: 门级数据通路 / 指令译码 / 硬件软件边界
- **对话脚本**:
  1. NAND 到一切的宣言：NAND(A,A)=NOT A，NOT+AND 可造所有布尔函数——理论上整个计算机可以用一种门堆出来；规划从 Nand 开始的材料单：Not/And/Or/Xor/Mux/DFF → 位宽器件（寄存器/计数器/ALU）→ RAM（地址空间译码 + 触发器阵列）→ CPU → 计算机。
  2. 针对上面的材料单，设计 Hack CPU 的数据通路：A 寄存器（存地址/立即数）、D 寄存器（存数据）、ALU（复用 DO03 的标志位——Hack 用 zr/ng 两位标志直接参与跳转判定）、PC（按 jump 位与标志组合决定 reset/load/increment）；写出指令格式（i=0 地址指令 / i=1 计算指令 c1..c6,dest,jump 的编码表）与译码逻辑的布尔表达。
  3. 基于上面的译码，处理"指令即数据"的自修改威力：Hack 没有 PC 相对寻址，`@label` 先装入 A 再跳转——讲清为什么两段式（@xxx + 0;JMP）是它唯一的跳转方式，以及这种极简设计如何仍图灵完备（写出内存循环递增的 4 条指令程序验证）。
  4. 动手：用 DO02 的门级网表框架实现完整 Hack 计算机（CPU + 32K RAM + 屏幕/键盘内存映射），从 Nand 门出发只通过组合更高级器件；跑通"在屏幕左上角画一个方块"的机器码程序与一个乘法子程序，统计整个网表的总门数，并回答：在这台机器上，硬件与软件的分界线到底画在哪里？
