### CR01 坐标系与投影：WGS84 / GCJ02 / BD09

- **预期档位**: medium
- **考察维度**: 坐标系转换 + 中国测绘法规 + 精度陷阱
- **对话脚本**:
  1. 三个坐标系：WGS84（GPS 原始 / 国际标准）、GCJ02（国测局加密「火星坐标」，中国地图法定）、BD09（百度二次加密）；解释为什么 GPS 拿到的经纬度直接画在高德/百度地图上会偏移几百米。
  2. 写转换算法：WGS84 → GCJ02 的偏移公式（基于一组固定系数的经纬度偏移计算，业界通用近似实现），再叠加 GCJ02 → BD09；用 Rust 实现三个 `Coord` 类型并在类型系统层面禁止直接混算（newtype 包装）。
  3. 反向转换与精度：GCJ02 → WGS84 没有精确逆公式（非线性加密），用「二分逼近 / 迭代解」数值求逆，误差控制在 1e-6 度内；写迭代版本并测试往返转换（WGS → GCJ → WGS）的误差。
  4. laew 借鉴：坐标系混乱的教训是「同类数据多种编码必须类型隔离」——对照 laew 的 `provider.end_point` 尾部斜杠裁剪、`800K/1M` 写法解析这类「边界归一化」，讨论在数据入口统一归一化、内部只存标准形态的原则。

### CR02 GeoJSON 解析与校验

- **预期档位**: medium
- **考察维度**: GeoJSON 规范 + 几何校验 + 容错解析
- **对话脚本**:
  1. GeoJSON 规范：`FeatureCollection` → `Feature` → `geometry`（Point/LineString/Polygon/MultiPolygon…）+ `properties`；坐标是 `[lng, lat]`（注意不是 lat,lng）嵌套数组；用 Rust + serde 写类型定义与解析，处理「外环 + 洞」的 Polygon 结构。
  2. 几何校验：外环必须闭合（首尾点相同）、环方向惯例（外环逆时针 / 洞顺时针，RFC 7946）、经纬度范围检查（-180~180 / -90~90）、自相交检测（简单多边形才合法）；写 `validate(geojson)` 返回错误列表而不是遇到第一个错就停。
  3. 容错与修复：真实数据常有不闭合环（自动补首点）、坐标顺序写反（heuristics：|第一个数| > 90 大概率是 lat,lng）、超范围点（clamp 还是拒绝？）；讨论「修复动作要可审计」——每个修复记录进 report 而不是静默改数据。
  4. laew 借鉴：容错修复的可审计性对照 laew 的 Vault 解密优雅降级（占位符 + 日志不崩溃）——讨论统一的「输入修复报告」模式：解析层修复了多少、拒绝了多少，向上层显式可见。

### CR03 空间索引：R 树与四叉树

- **预期档位**: hard
- **考察维度**: R 树插入分裂 + 四叉树 + 范围/最近邻查询
- **对话脚本**:
  1. 问题：10 万个 POI 上做「找矩形范围内所有点 / 找最近 5 个点」，暴力 O(n) 每次查询都遍历；写暴力版作为基线与正确性参照（测试时索引结果必须与暴力一致）。
  2. R 树实现：节点存多个 (MBR, 子指针)，插入时选面积增长最小的子树、节点满时按线性/二次启发式分裂、删除后按需合并；用 Rust 写一个支持 insert / range_query / knn 的最小 R 树（kNN 用优先队列按「到 MBR 最小距离」出队）。
  3. 四叉树对比：均匀网格不适合数据分布不均（市中心密、荒野稀）——四叉树递归四分直到每叶 ≤ 8 点；对比 R 树（动态数据 / 矩形对象）与四叉树（实现简单 / 点数据）的适用面，说明为什么数据库（PostGIS GiST）选 R 树族。
  4. laew 借鉴：空间索引的「按需收敛搜索范围」对照 agent 的文件检索——如果 laew 未来加 Grep/Glob 工具，同样需要「先索引后查询」的结构（ignore 规则 + 目录树剪枝），而不是每次全盘扫描。

### CR04 地理编码与地址解析

- **预期档位**: medium
- **考察维度**: 地址分词 + 行政区划匹配 + 模糊匹配评分
- **对话脚本**:
  1. 中文地址结构：「广东省 深圳市 南山区 科技园 深南大道 9988 号 A 栋 1203」——设计解析器输出结构化（省/市/区/街道/门牌/楼栋/房间）；用「最长匹配行政区划表」（区县表 → 街道表逐级消解）实现前半段。
  2. POI 模糊匹配：地址后半段「科技园深南大道9988号」要与 POI 库匹配——n-gram 编辑距离 / Jaccard 分词重合度 / 拼音容错（z/h 不分）多种打分融合；写一个 `match_address(query, candidates) -> score` 并设计阈值。
  3. 兜底与反馈：解析失败降级到「市 + 原始串」存待人工标注，标注结果回流词典；讨论为什么地理编码系统必须有人工反馈闭环（新楼盘 / 别名 / 简称无法枚举）。
  4. laew 借鉴：地址多级消解对照 laew 的项目说明文件五级链发现（CLAUDE.md → AGENTS.md → README.md → 自动生成 → 空）——两者都是「按优先级逐级回退的发现链」；再讨论模糊匹配的多信号融合打分（编辑距离 + 分词重合 + 拼音容错）如何用于 laew 斜杠命令的「错误命令自动纠错建议」。

### CR05 距离计算与地理围栏

- **预期档位**: medium
- **考察维度**: 球面距离 + 多边形内外判定 + 围栏事件
- **对话脚本**:
  1. Haversine 公式：球面两点距离 `2R·asin(sqrt(sin²(Δφ/2) + cosφ1·cosφ2·sin²(Δλ/2)))`；用 Rust 实现，并讨论「几百米内的近距计算可以用平面近似（equirectangular）省三角函数」的优化。
  2. 点在多边形内判定：射线法（从点向右发射线数与多边形边交点奇偶性）；处理边界穿越陷阱——顶点恰好在线上、水平边、经度 180° 跨越；写鲁棒版并测试凹多边形与带洞多边形。
  3. 地理围栏服务：车辆持续上报位置，判定「进入/离开围栏」事件——缓存当前所在围栏集合，只对「候选集变化」发事件而不是每次上报全量判断；用「上一状态 + 当前状态 diff」实现事件触发（进 A 出 B），并做抖动抑制（边界 50 米内滞回）。
  4. laew 借鉴：围栏的「状态 diff 触发」对照 laew 的 Compact 触发——上下文占用跨过 80% 阈值才动作而不是每次都检查动作，讨论「带滞回的阈值触发」（80% 触发压缩、压到 60% 以下才重置）如何避免临界震荡。

### CR06 路径规划：路网建模与双向 Dijkstra

- **预期档位**: hard
- **考察维度**: 路网图构建 + 双向搜索 + 层级加速
- **对话脚本**:
  1. 路网建模：OSM 的 way → 边（按单双行拆方向）、node → 顶点、边权 = 长度 / 限速（时间权）；转向限制（禁左）建模为「点 + 进入边」组合的扩展状态；写出从 OSM 抽取数据构建邻接表的流程。
  2. 双向 Dijkstra：从起点终点同时扩展，两 frontier 相遇即停，路径长度可证不劣于单向；实现双向版并在 10 万节点路网上对比单向版（访问节点数约为 sqrt 比例）。
  3. 加速结构：A* 用「到目标的球面距离 / 最高限速」做 admissible 启发式；再讨论 Contraction Hierarchies 的思想（预处理把重要道路「收缩」成 shortcuts，查询只走层级）为什么能把全国路网查询压到毫秒级，代价是预处理小时级。
  4. laew 借鉴：双向搜索对照「Yolo 前置分类 + 用户目标后验校验」——讨论 laew 在 hard 任务上能否做「从目标倒推的 Plan 校验」（Plan 末节点必须可达用户验收标准），相当于从终点反向扩展验证规划连通性。

### CR07 地图瓦片：金字塔与 slippy tile

- **预期档位**: medium~hard
- **考察维度**: z/x/y 瓦片寻址 + 屏幕瓦片计算 + 矢量瓦片
- **对话脚本**:
  1. slippy tile 寻址：缩放级 z（0 级 1 张、每级 ×4）、`x = floor((lon + 180) / 360 × 2^z)`、`y = floor((1 - ln(tan(lat) + sec(lat)) / π) / 2 × 2^z)`（Web Mercator）；写经纬度 ↔ 瓦片号 ↔ 瓦片内像素偏移的互转函数并测试北京在 z=12 的瓦片号。
  2. 屏幕瓦片集合：给定视口（中心经纬度 / 缩放 / 屏幕尺寸）计算需要加载的瓦片范围与按距中心排序的加载优先级；处理纬度钳制（Web Mercator 在 ±85.05° 之外无定义）与跨 180° 经线的环绕。
  3. 缓存与多级回退：瓦片磁盘 LRU 缓存 + 「请求高 zoom 未命中时用低 zoom 瓦片放大顶替」的降级显示；矢量瓦片（MVT，protobuf 编码的图层/要素）对比栅格瓦片的带宽与样式灵活性，写出两者选型建议。
  4. laew 借鉴：瓦片金字塔的「按视口按需加载 + 低精度顶替」对照超长文件读取——ReadTool 读大文件时能否按「视口」（行范围）分块、先给摘要级预览（低 zoom）再按需展开细节（高 zoom）。

### CR08 OpenStreetMap 数据处理

- **预期档位**: medium~hard
- **考察维度**: PBF 结构解析 + 标签过滤 + 数据管道
- **对话脚本**:
  1. OSM 数据模型：node（点）/ way（点的序列，构成线或面）/ relation（成员组合，如公交线、行政边界）三级对象 + tag（key=value 自由标签）；解释为什么「什么是道路/建筑」没有固定 schema 而靠标签约定（highway=* / building=*）。
  2. PBF 解析：osm.pbf 是块结构（HeaderBlock / PrimitiveBlock，dense node 压缩用 delta 编码）；用 osmpbf / osmio crate 流式解析一个城市级文件（几百 MB），统计各标签数量；强调「流式 + 常数内存」与全量读入的差别。
  3. 提取管道：从城市 PBF 抽「餐饮 POI + 主干路网」——标签过滤（amenity=restaurant/cafe / highway in primary..motorway）、way 的节点引用解析（两遍扫描：先收集被引用 node 坐标再装配 way）、输出 GeoJSON（联动 CR02）；写出这个 ETL 的阶段划分与中间产物。
  4. laew 借鉴：两遍扫描（先索引引用再装配）对照 laew 的拓扑分层（`main_work::topo_layers` Kahn 分层）——两者都是「先建立依赖索引、再按依赖顺序装配」的通用模式，讨论 WorkFlow 依赖图与 OSM 引用图在数据结构上的相似性。

### CR09 等值线与热力图

- **预期档位**: medium
- **考察维度**: Marching Squares + 核密度估计 + 渲染
- **对话脚本**:
  1. Marching Squares：把标量场（规则网格值）转等值线——每个 2×2 单元按「四角与阈值的高低」查 16 种 case 生成线段，歧义 case（对角同时高/低）用中心均值消解；用 Python 实现 `marching_squares(grid, threshold) -> Vec<Segment>` 并测试同心圆场。
  2. 从散点到网格：POI 散点 → 密度场用核密度估计（KDE，高斯核求和到网格，带宽参数控制平滑度）；实现「网格 200×200 + 高斯核截断 3σ」的 KDE，讨论带宽选择对形态的影响（过小碎片化 / 过大抹平）。
  3. 渲染层：等值线分级填色（每级一个色带区间 + 图例）、热力图色带（低透明蓝 → 高不透明红）；处理「等值线标注」（沿线的数值标签放置在曲率平缓处）的简化策略。
  4. laew 借鉴：KDE「散点聚合成连续场」的思想对照 Debug 报告的统计——把离散的每轮任务耗时 / token 散点聚合成「负载热力」描述（哪个 Agent 是热点），讨论用直方图 + 分位数的组合代替裸均值。

### CR10 GIS 工程化：PostGIS 与空间 SQL

- **预期档位**: medium~hard
- **考察维度**: 空间类型与索引 + ST_ 函数 + 性能调优
- **对话脚本**:
  1. PostGIS 入门：`geometry(Point, 4326)` 类型、GiST 索引 `CREATE INDEX ... USING GIST(geom)`、`ST_Distance / ST_Within / ST_DWithin`（注意 `ST_DWithin` 走索引而 `ST_Distance < x` 不走）；建一个 POI 表并演示「找 3km 内便利店」的索引执行计划（EXPLAIN ANALYZE）。
  2. 空间 SQL 实战：按行政边界聚合（`ST_Contains` join 区县面表统计各区内 POI 数）、缓冲区分析（`ST_Buffer` 学校 500 米范围查噪音源）、面积与长度（`ST_Area(geography)` 米制 vs geometry 度制的坑）；写出三条分析 SQL 并解释 geography 与 geometry 的选择规则。
  3. 性能调优：大表空间 join 慢——先 bbox 预过滤（`&&` 操作符走 GiST）再做精确判断、简化几何（`ST_Simplify` 降低顶点数）、分区表按地理范围切；给出一个 1000 万点 × 3000 面聚合从超时到秒级的调优过程。
  4. laew 借鉴：PostGIS 把「空间能力做成 SQL 内的一等公民」对照 laew 把工具做成 Agent 的一等公民——讨论 laew 若加 SQLite 空间扩展（SpatiaLite）支持地理查询工具，工具描述里应如何声明能力边界让 LLM 正确选用。
