### CG01 实时调度理论：EDF 与 Rate-Monotonic

- **预期档位**: hard
- **考察维度**: 实时调度 + 可调度性分析 + RTOS
- **对话脚本**:
  1. 实时调度（Real-time Scheduling）是「保证任务在截止时间前完成」的调度理论。经典算法：(a) Rate-Monotonic（RM，周期越短优先级越高，静态优先级）；(b) Earliest Deadline First（EDF，截止时间越早优先级越高，动态优先级）；(c) 可调度性测试（RM 的 Liu & Layland 界限：CPU 利用率 ≤ n(2^(1/n) - 1) ≈ 69%）。请解释为什么 EDF 比 RM 更高效（EDF 可调度到 100% CPU 利用率）。
  2. 实时调度深入：(a) 硬实时（Hard Real-time，错过截止时间 = 灾难）；(b) 软实时（Soft Real-time，偶尔错过可接受）；(c) 固实时（Firm Real-time，错过结果无价值）；(d) 优先级反转（Priority Inheritance 协议解决）。请用「火星车」例子说明优先级反转：低优先级任务持有高优先级任务需要的锁。
  3. RTOS 调度实现：(a) FreeRTOS（抢占式 + 时间片）；(b) Zephyr（多调度策略）；(c) RTLinux（Linux 实时扩展）；(d) QNX（微内核 + 实时调度）。请描述 FreeRTOS 的调度策略：抢占式优先级调度 + 同优先级时间片轮转。
  4. laew 的实时调度启示：laew 的多 Agent 编排是否可以引入实时调度：(a) 紧急任务（用户等待）高优先级；(b) 后台任务（日志 / 统计）低优先级；(c) 截止时间保证（用户任务在 X 秒内响应）。讨论实时调度对 laew 用户体验的价值。

### CG02 低延迟网络：从 TCP 到内核旁路

- **预期档位**: hard
- **考察维度**: 网络延迟 + 内核旁路 + DPDK/RDMA
- **对话脚本**:
  1. 网络延迟的来源：(a) 传播延迟（光速限制，光纤 ~5μs/km）；(b) 传输延迟（数据量 / 带宽）；(c) 处理延迟（协议栈处理）；(d) 排队延迟（缓冲区等待）。请解释为什么「内核旁路」（Kernel Bypass）能显著减少延迟（跳过内核协议栈，用户态直接操作网卡）。
  2. DPDK（Data Plane Development Kit）：(a) 用户态驱动（UIO / VFIO）；(b) 轮询模式（Polling，替代中断）；(c) 大页内存（Hugepages，减少 TLB miss）；(d) 零拷贝（Zero-copy）；(e) 典型延迟：内核协议栈 ~10μs → DPDK ~1μs。请描述 DPDK 的「轮询模式驱动」（PMD）如何工作（持续检查网卡队列，无中断开销）。
  3. RDMA（Remote Direct Memory Access）：(a) 绕过远程 CPU 直接读写内存；(b) 三种协议（InfiniBand / RoCE / iWARP）；(c) 零拷贝 + 内核旁路；(d) 典型延迟：TCP ~100μs → RDMA ~1μs。请解释为什么 RDMA 对分布式系统（分布式数据库 / AI 训练）至关重要（节点间通信延迟大幅降低）。
  4. laew 的低延迟启示：laew 的 LLM API 调用延迟优化：(a) 连接池（复用 TCP 连接）；(b) HTTP/2 多路复用（并行请求）；(c) 请求流水线（不等响应就发下一个）；(d) 边缘部署（API 节点靠近用户）。讨论 laew 如何减少用户感知延迟。

### CG03 高频交易系统：纳秒级延迟的工程

- **预期档位**: hard
- **考察维度**: HFT + 低延迟工程 + 硬件加速
- **对话脚本**:
  1. 高频交易（High-Frequency Trading, HFT）是「用极低延迟执行交易策略」的领域，延迟单位是纳秒（ns）。关键指标：(a) Tick-to-trade（行情到下单的延迟）；(b) 抖动（Jitter，延迟波动）；(c) 吞吐量（每秒处理消息数）。请解释为什么「抖动」比「平均延迟」更重要（最坏情况决定盈亏）。
  2. HFT 低延迟技术栈：(a) FPGA 加速（硬件实现策略，延迟 < 1μs）；(b) 内核旁路（DPDK / Solarflare OpenOnload）；(c) 无锁数据结构（Ring Buffer / SPSC Queue）；(d) CPU 绑核（避免上下文切换）；(e) 预分配内存（无动态分配）。请描述「CPU 绑核」如何减少延迟（避免任务在不同核心间迁移 + 缓存失效）。
  3. HFT 系统架构：(a) 行情网关（接收交易所行情）；(b) 策略引擎（生成交易信号）；(c) 订单网关（发送订单）；(d) 风控系统（实时风险检查）。请解释为什么「风控」不能放在关键路径上（增加延迟），但又必须存在（防止巨额亏损）。
  4. laew 的 HFT 启示：laew 的 Agent 编排是否可以借鉴 HFT 思想：(a) 关键路径优化（用户等待的路径最短）；(b) 非关键路径异步化（日志 / 统计不阻塞主流程）；(c) 延迟预算（每个环节有明确延迟上限）。讨论 HFT 工程哲学对 laew 性能优化的启发。

### CG04 无锁数据结构：并发编程的极致性能

- **预期档位**: hard
- **考察维度**: 无锁编程 + CAS + 内存序
- **对话脚本**:
  1. 无锁数据结构（Lock-free Data Structures）是「不使用锁但保证线程安全」的数据结构。核心原语：(a) CAS（Compare-And-Swap，比较并交换）；(b) FAA（Fetch-And-Add，获取并加）；(c) LL/SC（Load-Link / Store-Conditional）；(d) 内存序（Memory Ordering，Relaxed / Acquire / Release / SeqCst）。请解释为什么「无锁」比「有锁」在高并发下性能更好（无锁无线程阻塞 + 无上下文切换）。
  2. 无锁栈（Lock-free Stack）：(a) 用 CAS 实现 push / pop；(b) ABA 问题（值从 A → B → A，CAS 误判）；(c) ABA 解决方案（Tagged Pointer / Hazard Pointer / RCU）。请描述 ABA 问题的场景：线程 1 读栈顶 A → 线程 2 pop A → push A → 线程 1 CAS 成功但栈已变。
  3. 无锁队列（Lock-free Queue）：(a) Michael & Scott 队列（经典无锁队列）；(b) 有界无锁队列（Ring Buffer + 原子索引）；(c) SPSC（单生产者单消费者）vs MPSC（多生产者单消费者）；(d) 伪共享（False Sharing）与缓存行对齐。请解释为什么「伪共享」会严重降低无锁数据结构性能（不同核心的变量在同一缓存行）。
  4. laew 的无锁数据结构启示：laew 的并发会话管理是否可以引入无锁结构：(a) 无锁会话注册表（高并发下快速查找）；(b) 无锁消息队列（Agent 间通信）；(c) 无锁统计计数器（实时性能监控）。讨论无锁编程对 laew 并发性能的提升空间。

### CG05 延迟分析：从 P50 到 P99.99

- **预期档位**: medium
- **考察维度**: 延迟分布 + 百分位 + 性能分析
- **对话脚本**:
  1. 延迟分析（Latency Analysis）是「测量、分析、优化系统延迟」的工程实践。关键概念：(a) 百分位（Percentile，P50 / P95 / P99 / P99.9 / P99.99）；(b) 尾部延迟（Tail Latency，P99+）；(c) 延迟分布（正态 / 双峰 / 长尾）；(d) 为什么 P50 不够（P50 正常但 P99 爆炸）。请解释为什么「尾部延迟」对用户体验影响最大（用户记住的是最慢的那次）。
  2. 延迟测量工具：(a) hdr_histogram（高精度直方图）；(b) Prometheus histogram / summary；(c) eBPF（内核级延迟追踪）；(d) perf（CPU 性能分析）；(e) flame graph（火焰图可视化）。请描述 hdr_histogram 的优势（固定精度 + 低内存 + 可合并）。
  3. 延迟优化方法论：(a) 找到瓶颈（Profile → 分析 → 优化）；(b) 减少系统调用（批处理）；(c) 减少内存分配（预分配 / 对象池）；(d) 减少锁竞争（无锁 / 分区）；(e) 减少 I/O（缓存 / 异步）。请讨论「阿姆达尔定律」在延迟优化中的应用（优化瓶颈环节收益最大）。
  4. laew 的延迟分析：laew 如何做延迟分析：(a) 每个 Agent 调用记录延迟；(b) 统计 P50 / P95 / P99；(c) 延迟异常告警（P99 突增）；(d) 延迟归因（哪个环节慢）。设计一个 laew 的延迟监控面板：展示哪些指标？如何可视化？

### CG06 内核旁路（Kernel Bypass）：用户态网络栈

- **预期档位**: hard
- **考察维度**: 内核旁路原理 + 实现 + 应用场景
- **对话脚本**:
  1. 内核旁路（Kernel Bypass）是「绕过内核协议栈，用户态直接操作网卡」的技术。动机：(a) 内核协议栈延迟高（多次拷贝 + 中断 + 调度）；(b) 用户态协议栈延迟低（零拷贝 + 轮询 + 无调度）；(c) 代表技术（DPDK / netmap / RDMA / io_uring）。请解释为什么「零拷贝」能减少延迟（数据不经过内核缓冲区）。
  2. DPDK 深入：(a) EAL（Environment Abstraction Layer，初始化 + 核心绑定）；(b) Mbuf（网络数据包缓冲区）；(c) Ring（无锁环形队列）；(d) PMD（Polling Mode Driver，轮询模式驱动）；(e) 应用（OVS-DPDK / VPP / Seastar）。请描述 DPDK 的「大页内存」如何减少 TLB miss（2MB / 1GB 页 vs 4KB 页）。
  3. io_uring：(a) Linux 5.1+ 新异步 I/O 接口；(b) 提交队列（SQ）+ 完成队列（CQ）；(c) 批量提交（减少系统调用）；(d) 轮询模式（无需中断）；(e) 与 DPDK 的关系（io_uring 用于磁盘 I/O，DPDK 用于网络 I/O）。请解释为什么 io_uring 比 aio 更高效（共享环形缓冲区 + 批量提交）。
  4. laew 的内核旁路启示：laew 的 I/O 密集型操作是否可以引入内核旁路：(a) 日志写入用 io_uring（批量 + 异步）；(b) 网络请求用 io_uring（减少系统调用）；(c) 文件读取用 io_uring（批量预读）。讨论内核旁路对 laew 性能优化的适用性。

### CG07 时间敏感网络（TSN）：工业实时以太网

- **预期档位**: medium
- **考察维度**: TSN 标准 + 实时以太网 + 工业应用
- **对话脚本**:
  1. 时间敏感网络（Time-Sensitive Networking, TSN）是 IEEE 802.1 标准族的扩展，为以太网增加「确定性延迟」能力。核心标准：(a) 802.1Qbv（时间门控调度）；(b) 802.1Qbu（帧抢占）；(c) 802.1AS（时间同步）；(d) 802.1Qci（流量过滤）。请解释为什么传统以太网无法保证确定性延迟（排队延迟不可控）。
  2. TSN 时间同步：(a) gPTP（generalized Precision Time Protocol，IEEE 802.1AS）；(b) 主从时钟同步；(c) 亚微秒级同步精度；(d) 同步过程（Sync → Follow_Up → Pdelay_Req → Pdelay_Resp）。请描述 gPTP 如何计算时钟偏移和路径延迟。
  3. TSN 应用场景：(a) 工业自动化（机器人协同控制）；(b) 汽车网络（ADAS / 车载以太网）；(c) 音视频制作（AVB / SMPTE ST 2110）；(d) 航空航天（AFDX）。请解释为什么「汽车 ADAS」需要 TSN（传感器数据必须在确定时间内到达）。
  4. laew 的 TSN 启示：laew 的多 Agent 协同是否可以借鉴 TSN 思想：(a) 时间同步（所有 Agent 使用统一时间）；(b) 时间门控（关键任务在确定时间窗执行）；(c) 流量整形（限制非关键任务带宽）。讨论 TSN 思想对 laew 实时 Agent 编排的启发。

### CG08 音视频实时：WebRTC 与低延迟流媒体

- **预期档位**: medium
- **考察维度**: WebRTC + 实时传输 + 延迟优化
- **对话脚本**:
  1. WebRTC 是浏览器实时通信的标准技术栈：(a) 音视频采集（getUserMedia）；(b) 编解码（VP8 / VP9 / H.264 / Opus）；(c) 传输（SRTP / SCTP）；(d) NAT 穿透（STUN / TURN / ICE）。请解释为什么 WebRTC 能做到「端到端延迟 < 500ms」（UDP + 自适应码率 + 前向纠错）。
  2. WebRTC 延迟优化：(a) NACK（丢包重传，比 TCP 更快）；(b) FEC（前向纠错，冗余数据恢复）；(c) Jitter Buffer（抖动缓冲区，平滑网络抖动）；(d) AGC / AEC / NS（音频处理：增益 / 回声消除 / 降噪）。请描述「Jitter Buffer」如何权衡延迟与流畅性（缓冲区大 → 延迟高但流畅）。
  3. 低延迟流媒体协议对比：(a) RTMP（Adobe，延迟 1-3s）；(b) HLS（Apple，延迟 6-30s）；(c) DASH（MPEG，延迟 6-30s）；(d) WebRTC（延迟 < 500ms）；(e) SRT（Haivision，延迟 200ms-1s）；(f) LL-HLS / LL-DASH（低延迟 HLS / DASH，延迟 2-3s）。请解释为什么「直播」场景倾向用 WebRTC（延迟最低）。
  4. laew 的实时通信启示：laew 的 TUI 与后端通信是否可以引入实时技术：(a) WebSocket 双向通信（替代 HTTP 轮询）；(b) Server-Sent Events（服务端推送）；(c) 流式响应（逐字输出）。讨论实时通信对 laew 用户体验的提升。

### CG10 确定性延迟：从概率保证到硬保证

- **预期档位**: hard
- **考察维度**: 确定性 + 形式化方法 + 实时验证
- **对话脚本**:
  1. 确定性延迟（Deterministic Latency）是「在最坏情况下也能保证延迟上限」的能力。与概率延迟的区别：(a) 概率延迟（P99 < 10ms，但可能偶尔 100ms）；(b) 确定性延迟（永远 < 10ms，无例外）。请解释为什么「安全关键系统」需要确定性延迟（如汽车刹车系统）。
  2. 确定性延迟的实现技术：(a) 静态调度（离线计算调度表，运行时严格执行）；(b) 时间触发架构（TTA，Time-Triggered Architecture）；(c) 资源预留（CPU / 内存 / 网络带宽预留）；(d) 最坏执行时间（WCET，Worst-Case Execution Time 分析）。请描述「时间触发架构」如何工作（所有动作在预定的时间点执行）。
  3. WCET 分析：(a) 静态分析（分析代码路径，计算最坏情况）；(b) 测量（运行最坏输入，测量最大时间）；(c) 挑战（缓存 / 分支预测 / 流水线使 WCET 难分析）；(d) 工业工具（AbsInt aiT / Rapita RVS）。请解释为什么「缓存」让 WCET 分析困难（命中 / 未命中时间差异大）。
  4. laew 的确定性延迟启示：laew 是否可以提供「延迟 SLA」：(a) 简单任务（P99 < 5s）；(b) 中等任务（P99 < 30s）；(c) 复杂任务（P99 < 5min）；(d) 超时降级（超时后返回部分结果）。讨论延迟 SLA 对 laew 用户期望管理的价值。
