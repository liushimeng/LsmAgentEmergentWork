### BA01 异步编程模型全景：回调 → Promise → async/await → 协程
- **预期档位**: medium
- **测试状态**: ✅ 已测试 (BA01_q1-q4, 通过 — mock 链路 4 轮全通; TUI 多轮 assistant 回填精简修复一并验证;详见 `tmpPlan/2026-09-11_24-BA01-CA31-自动化测试与多轮Assistant回填噪音修复方案.md`)
- **考察维度**: 异步模型演进史 + 范式对比
- **对话脚本**:
  1. 异步编程的五代演进：回调地狱（Callback Hell）→ Promise/Future → async/await → 协程（Coroutine）→ 结构化并发（Structured Concurrency）。
  2. CPS（Continuation-Passing Style）与直接风格（Direct Style）的本质差异：为什么 async/await 被称为"语法糖"——背后的状态机展开原理。
  3. 对比 Rust tokio / Go goroutine / Node.js libuv / Java Virtual Thread / Kotlin coroutine 五种实现的「颜色」（有栈 vs 无栈）与调度模型。
  4. 写一个最小跨语言对照示例：HTTP 客户端发起 10 个并发请求，每个延迟 100ms，统计 5 种实现的代码行数与真实耗时。

### BA02 Rust 异步运行时深潜：tokio 与 async-std
- **预期档位**: hard
- **考察维度**: Rust Future 状态机 + Pin + Waker
- **对话脚本**:
  1. Rust 的 `Future` trait 本质：「惰性求值 + 拉模型（Pull-based）」与 JavaScript Promise「推模型」的对比，`poll` 方法的两次唤醒机制。
  2. `Pin<&mut T>` 为什么是异步编程的基石？自引用结构（self-referential struct）在状态机中的内存安全问题与 `!Unpin` 的设计意图。
  3. tokio 调度器架构：worker thread 池 + 单线程（current_thread）+ 多线程（multi_thread）模式，task 队列与 steal 算法的负载均衡。
  4. 在 laew 的 `MultiAgentOrchestrator` 中，`Semaphore::acquire().await` 背后的资源获取与取消传播链路是怎样的？写出从用户 `/exit` 到 task 优雅退出的完整信号传播代码。

### BA03 Go 协程模型：goroutine 与 GMP 调度
- **预期档位**: medium
- **考察维度**: goroutine + GMP + channel
- **对话脚本**:
  1. goroutine 与 OS 线程的本质差异：初始栈 2KB vs 8MB、用户态调度 vs 内核调度、G-M-P 三层调度模型（M 线程 / P 处理器 / G goroutine）。
  2. channel 的四种用法：无缓冲同步、有缓冲异步、单向只读只写、`select` 多路复用，写出一个生产者-消费者的完整示例与背压机制。
  3. goroutine 泄漏的常见模式：未接收的 channel、无限循环无退出条件、`context` 未传递取消信号。给一个 `pprof` 抓泄漏 goroutine 的排查流程。
  4. 对比 Go 与 Rust 在并发原语上的哲学差异：「通过通信共享内存（CSP）」vs「通过所有权共享内存」，给同一生产者-消费者问题的两种实现。

### BA04 Node.js 事件循环：libuv 与微任务队列
- **预期档位**: medium
- **考察维度**: 事件循环阶段 + 微任务优先级
- **对话脚本**:
  1. Node.js 事件循环的 6 个阶段：timers → pending callbacks → idle/prepare → poll → check → close callbacks，每阶段的具体任务与回调来源。
  2. 微任务（microtask）vs 宏任务（macrotask）的执行顺序：`process.nextTick` > `Promise.then` > `setImmediate` > `setTimeout`，给一个混合示例的执行顺序推演。
  3. Node.js 单线程模型的瓶颈与解法：worker_threads（CPU 密集）、cluster 模块（多进程）、child_process（隔离进程）、N-API（C++ 扩展）的选型矩阵。
  4. 设计一个 Node.js 高并发 I/O 服务：accept 10000 个长连接、用 stream 推数据、heartbeat 检测、对慢客户端断连——写出关键代码与内存监控要点。

### BA07 Reactive Streams：响应式编程背压模型
- **预期档位**: hard
- **考察维度**: Publisher/Subscriber/背压策略
- **对话脚本**:
  1. Reactive Streams 规范的四大接口：`Publisher` / `Subscriber` / `Subscription` / `Processor`，请求模型（`request(n)`）与背压（backpressure）的关系。
  2. 三大主流实现对比：Reactor（WebFlux）/ RxJava 3 / Mutiny（Quarkus），操作符丰富度、调度模型、与 Kotlin/Scala 的互操作差异。
