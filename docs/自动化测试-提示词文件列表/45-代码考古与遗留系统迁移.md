# 45 代码考古与遗留系统迁移

> 编号段 AT01–AT10 · 聚焦遗留代码阅读、重构策略、绞杀者模式、数据迁移与系统现代化

### AT01 遗留代码第一课：建立心智模型
- **预期档位**: medium
- **考察维度**: 遗留代码理解 + 文档反推
- **对话脚本**:
  1. 接手一个 10 万行的遗留 Java 系统，第一周应该做什么？列出 10 个具体动作（git log、IDE 工具、Coverage 图、依赖图）。
  2. 用 jdeps / dependency-cruiser / importlinter 等工具生成模块依赖图，怎么识别循环依赖、孤儿模块、热点模块？
  3. 现有文档不足时，怎么从代码反推架构？举出"按包结构反推模块边界、按测试反推契约、按 commit message 反推演进"三种方法。
  4. 写一份"遗留系统现状评估报告"模板：技术债清单、风险等级、业务关键度、改造优先级。

### AT02 重构基石：测试先行与特性标志
- **预期档位**: medium
- **考察维度**: 安全重构前提
- **对话脚本**:
  1. Michael Feathers《Working Effectively with Legacy Code》的"接缝（Seam）"概念是什么？识别接缝的 5 种方法。
  2. 没有测试的遗留代码怎么改？用 Approval Tests、Sprout Method、Wrap Class 三种技巧给一个具体例子。
  3. Feature Flag（特性标志）在重构中的作用：怎么让代码与功能开关解耦？launchdarkly / Unleash / 自研方案对比。
  4. 重构的"童子军军规"（Leave the campground cleaner than you found it）如何落地？每次 PR 顺手做的小改进清单。

### AT03 绞杀者模式：渐进式替换
- **预期档位**: hard
- **考察维度**: Strangler Fig + 流量切换
- **对话脚本**:
  1. Strangler Fig Pattern（绞杀者无花果模式）由 Martin Fowler 提出，核心思想是什么？画出 5 年替换路线图。
  2. 用 API 网关实现流量切分：旧系统 vs 新系统的双写、灰度、切流策略，权重从 1% → 100% 怎么平滑过渡？
  3. 数据双写期间的"乱序"与"不一致"怎么处理？Saga 模式、最终一致性、TCC 各自适用什么场景？
  4. 给一个真实案例：单体 Java ERP 拆分为微服务，关键路径与依赖图怎么画？给出 12 个月分阶段方案。

### AT04 数据库迁移：在线与离线
- **预期档位**: hard
- **考察维度**: 数据迁移 + 零停机
- **对话脚本**:
  1. 数据库迁移的两种策略：停机迁移 vs 在线迁移的对比，画出时间线与风险矩阵。
  2. 在线迁移的四个阶段：双写（Dual Write）→ 数据校验（Reconciliation）→ 切流（Cutover）→ 清理（Decommission），每个阶段的关键指标。
  3. 用 Flyway / Liquibase / sqitch 做 schema 迁移：版本号命名、回滚策略、零停机变更的禁忌。
  4. 大表（10 亿行）加索引或修改字段怎么平滑？gh-ost、pt-online-schema-change、Facebook OnlineSchemaChange 原理对比。

### AT05 框架升级：从 JDK 8 到 JDK 21
- **预期档位**: hard
- **考察维度**: 长期版本演进
- **对话脚本**:
  1. Java 大版本升级（JDK 8→17→21）通常踩哪些坑？模块化、反射、序列化、Sun 包、内部 API 各有什么影响？
  2. 用 OpenRewrite / jdeps 评估升级风险：哪些依赖用了 sun.misc.Unsafe、哪些用了已废弃 API？
  3. Python 2 → 3 迁移的真实案例：print 语句、整数除法、unicode、xrange 都怎么兼容？给出 6to5 / futurize 工具链。
  4. 前端框架升级（AngularJS → Angular、React 16 → 18）通常怎么渐进完成？混合运行期（Codemod + shim）的实现细节。

### AT06 单体拆分：何时拆、怎么拆
- **预期档位**: hard
- **考察维度**: 微服务拆分决策
- **对话脚本**:
  1. Sam Newman《Monolith to Microservices》：什么时候不应该拆？团队规模、业务复杂度、运维能力三个维度的判断矩阵。
  2. 拆分的 5 种策略：按业务能力（Business Capability）、按子域（DDD Bounded Context）、按团队（Conway 逆推）的对比。
  3. 拆分前必须解决的数据问题：跨服务事务、跨服务 join、跨服务查询怎么改造？Saga、CQRS、事件溯源各自适用什么场景？
  4. 拆分后的可观测性：分布式链路追踪（OpenTelemetry / Jaeger）、统一日志（ELK / Loki）、指标（Prometheus）的最小可行栈。

### AT07 死代码消除与依赖瘦身
- **预期档位**: medium
- **考察维度**: 代码精简 + 依赖治理
- **对话脚本**:
  1. 怎么识别死代码（Dead Code）？IDE 警告、Coverage 工具（Scoverage/Cobertura）、git 考古（找到最后一次调用）、调用图分析（CodeScene）四类方法的精度对比。
  2. 一次大型死代码清理 PR 通常多大？怎么分批提交？举出 5 个真实工程案例与具体收益（行数、构建时间、漏洞数）。
  3. 依赖瘦身的两个方向：删除未使用的依赖、替换臃肿依赖。Dependabot / Renovate / Snyk 怎么配置与告警分级？
  4. 一个 1000 万行代码库的"清理马拉松"（Cleanup Sprint）如何组织？给一份 4 周计划与每日站会模板。

### AT08 文档抢救：从 README 到 Architecture Decision Records
- **预期档位**: simple
- **考察维度**: 文档体系重建
- **对话脚本**:
  1. 接手无文档的遗留系统，第一份文档应该是什么？（不是 README，而是"我能跑起来" + "我能改一行代码不爆炸"的最小指引）
  2. ADR（Architecture Decision Records）是什么？怎么写？给一份标准模板（Context / Decision / Status / Consequences）。
  3. 用工具链（MADR / Log4brains / adr-tools）管理 ADR：从 CI 自动渲染到 Wiki 同步的实现。
  4. C4 Model（Context / Container / Component / Code）画架构图：4 层粒度分别表达什么？用什么工具（Mermaid / Structurizr / draw.io）？

### AT09 性能债与可维护性债：识别与量化
- **预期档位**: medium
- **考察维度**: 技术债评估方法
- **对话脚本**:
  1. 技术债（Technical Debt）四象限：鲁莽 vs 谨慎、故意 vs 无意，各举例说明。
  2. 用 SonarQube / CodeScene / Better Code Hub 量化技术债：哪些指标（圈复杂度、重复率、Coverage、Code Age）最有指导意义？
  3. Tech Debt Quadrant（Martin Fowler 模型）的应用：哪些债应该立刻还、哪些应该记录但暂缓、哪些可以无视？
  4. 给技术债定优先级：业务影响 × 修复成本 × 风险的三维评分卡怎么做？给出 Excel 模板与计算公式。

### AT10 现代化决策：重写还是演进
- **预期档位**: hard
- **考察维度**: 架构决策 + 商业判断
- **对话脚本**:
  1. 经典反例："重写会更安全" —— Netscape 6、Basecamp 1→2、Windows Vista、Healthcare.gov 重写失败的真实教训。
  2. 什么时候应该彻底重写？四个判断标准：技术栈已淘汰、团队规模支持并行、业务允许灰度期、有清晰目标架构。
  3. 用"绞杀者模式 + 双写 + 切流"替代重写的真实案例：Salesforce、GitHub、Shopify、Stripe 的演进策略。
  4. 给一个具体的遗留 CRM 系统现代化决策书模板：现状、目标、路径、风险、ROI、回退方案，给出完整结构。
