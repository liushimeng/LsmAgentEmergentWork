### DF01 MIDI 文件解析与事件流

- **预期档位**: medium
- **考察维度**: MIDI 二进制格式 / delta time / 事件模型
- **对话脚本**:
  1. MIDI 不存声音存「演奏指令」：note on（哪个键多用力）/ note off / 弯音 / 控制器；文件结构 = Header Chunk（MThd + 格式 + 轨道数 + ticks per beat）+ Track Chunk（MTrk 事件序列）。
  2. delta time 与变长数：每个事件前的「距离上一事件多少 tick」用 VLQ 变长编码（最高位是续读标志）；手算一个 delta time 编码（如 0x81 0x00 = 128）。
  3. 基于上面的格式，动手写解析器：读一个 .mid 文件，输出事件列表（第几拍 / note on C4 / 力度 100）；讨论 tempo 事件（meta 0x51）怎么把 tick 换算成秒。
  4. 扩展：把解析结果渲染成钢琴卷帘（piano roll）文本图——横轴时间纵轴音高，`█` 表示发声区间；讨论多轨合并与通道（channel）的含义。

### DF02 减法合成器：振荡器 + 滤波 + 包络

- **预期档位**: hard
- **考察维度**: 数字合成 / 信号链 / 实时音频
- **对话脚本**:
  1. 减法合成器信号链：振荡器（产生谐波丰富的波形：锯齿/方波/三角）→ 滤波器（低通切掉高频「减」掉亮度）→ 放大器（ADSR 包络塑形）；为什么锯齿波适合弦乐、方波适合木管。
  2. 振荡器实现：相位累加器（phase += freq/sampleRate，波形 = f(phase)）；混叠（aliasing）问题——朴素方波高频泛音超过奈奎斯特频率折回成噪声，讲 PolyBLEP 抗混叠的思路。
  3. ADSR 包络：Attack（起音多快）/ Decay（降到持续多快）/ Sustain（按住时的音量）/ Release（松手后尾音多长）；用四段线性/指数插值实现，讨论鼓（A 快 S 零）与弦乐 pad（A 慢 S 高）的参数差异。
  4. 动手：用 Python numpy 生成一段 440Hz 锯齿波 → 一阶低通滤波 → 套 ADSR → 存 WAV 播放；改参数听出「贝斯」与「铃」的区别（需要音频环境时可只生成文件）。

### DF03 步进音序器与节拍调度

- **预期档位**: medium~hard
- **考察维度**: 定时精度 / 音序器模型 / 采样级调度
- **对话脚本**:
  1. 步进音序器（808 鼓机模式）：16 步 × N 轨的网格，每步开/关，BPM 决定步时长（120BPM 十六分音符 = 125ms）；数据结构就是二维布尔数组。
  2. 定时精度问题：用 `sleep(125ms)` 调度会漂移（sleep 不精确 + 音频生成耗时）；lookahead 调度模式——低频定时器（25ms）+ 提前排程未来 100ms 的音符到精确采样时刻（Web Audio 的调度哲学）。
  3. 摇摆感（swing）：把偶数步延迟 10~20% 产生「人性化」律动；速度变化（ritardando 渐慢）时 tick→秒的换算要积分而非乘法。
  4. 动手：用 Python 实现控制台音序器——16 步鼓机（kick/snare/hihat 三条轨用不同频率噪声/正弦近似），按 BPM 播放生成 WAV；加 swing 参数对比听感。

### DF04 FFT 频谱分析与电子调音器

- **预期档位**: medium~hard
- **考察维度**: DFT/FFT / 加窗 / 音高检测
- **对话脚本**:
  1. 傅里叶变换直觉：任何声音 = 不同频率正弦波叠加，FFT 把时域波形变频域「频率→强度」；手算一个 8 点 DFT 感受 O(n²) → FFT O(n log n) 的意义。
  2. 工程细节：窗函数（直接截断产生频谱泄漏，加 Hann 窗平滑边缘）、频率分辨率 = 采样率/窗口大小（44.1kHz 采 4096 点 ≈ 10.7Hz 分辨率，低音区分不够怎么办）。
  3. 基于上面的分辨率问题，实现调音器：找频谱最大峰 → 频率转音名（f = 440 × 2^((n-69)/12)，n 是 MIDI 音号）→ 算偏差多少音分（cent，半音=100 cent，±10 内算准）。
  4. 动手：用 numpy.fft 分析 DF02 生成的 WAV，验证主峰在 440Hz；再对混合两个频率的信号验证能分离；讨论比 FFT 更准的自相关法（YIN 算法思路）。

### DF05 节拍检测与 BPM 估计

- **预期档位**: medium~hard
- **考察维度**: onset 检测 / 自相关 / 音乐信号处理
- **对话脚本**:
  1. 节拍检测两步：先找「音符起始点」（onset——能量突增或频谱突变处），再从 onset 间隔估计 BPM；能量包络法：分帧算能量，帧间差分的峰就是候选 onset。
  2. BPM 估计：对 onset 序列做间隔直方图或对能量差分信号做自相关，峰值对应的周期就是节拍周期；讨论 120 vs 60 vs 240 的倍频歧义（人耳选哪个看音乐语境）。
  3. 基于上面的算法，讨论难点：切分音与弱拍干扰、变速音乐（live 演出）需要动态跟踪而非全局 BPM、 onset 阈值自适应（噪声门限）。
  4. 动手：用 numpy 实现 onset 检测（能量差分 + 阈值 + 最小间隔约束），对自己生成的 120BPM 鼓点 WAV 估计 BPM，验证误差 <2%；再测一段 90BPM 的。

### DF06 自动伴奏：和弦进行与配器规则

- **预期档位**: medium
- **考察维度**: 乐理规则编码 / 和弦生成 / 风格模板
- **对话脚本**:
  1. 和弦进行的规则化：C 大调常用进行 I-V-vi-IV（C-G-Am-F）为什么「好听」——功能和声（主/属/下属的 T-S-D-T 循环）；把级数进行编码成数据（`[1,5,6,4]`），转调就是级数映射到不同根音。
  2. 和弦到音符：三和弦 = 根音+三度+五度，七和弦加七度；根据级数与调式生成具体 MIDI 音高（C 大调 vi 级 = A3/C4/E4）；转位（低音不总是根音）让声部连接更平滑。
  3. 配器模板：不同风格 = 不同节奏型+音色组合（民谣：分解和弦八分音符；摇滚：强力五和弦强拍；Bossa：低音+和弦错拍）；模板 = 每拍各轨触发规则的表。
  4. 动手：写自动伴奏生成器——输入调+级数进行+风格模板，输出 MIDI 事件序列（可用 DF01 的格式反写 .mid 文件）；生成 C 大调 1645 民谣分解和弦听效果。

### DF07 五线谱渲染与 MusicXML

- **预期档位**: medium
- **考察维度**: 乐谱数据模型 / 符号布局 / MusicXML
- **对话脚本**:
  1. 乐谱的三种表示：MIDI（演奏指令，无谱面信息）、MusicXML（乐谱语义：音高/时值/声部/小节/记号）、图片/PDF（纯视觉）；MusicXML 是交换标准——解析它的 part→measure→note 层级。
  2. 五线谱布局问题：音高 → 纵坐标（每条线/间一个半音步，C4 在下加一线）、时值 → 横坐标（但不是线性——四分音符宽度≠八分两倍，排版要考虑间距比例）；符干方向规则（中线以上朝下）。
  3. 基于上面的规则，讨论复杂排版：连音线、附点、休止符、多声部同小节对齐（拍点对齐是硬约束）、歌词逐字对音符。
  4. 动手：用 Python + SVG 渲染单旋律五线谱——画五条线、按音高放符头（椭圆）、按时值画符干/符尾；输入一串 (音名, 时值) 列表输出 SVG 文件。

### DF08 音频效果器链：延迟、混响与失真

- **预期档位**: medium~hard
- **考察维度**: DSP 效果器 / 卷积 / 非线性处理
- **对话脚本**:
  1. 三类经典效果的原理：延迟（echo——环形缓冲存过去信号，衰减叠加）/ 混响（大量密集回声模拟空间——Schroeder 混响器：4 个并联梳状滤波 + 2 个串联全通）/ 失真（故意削波/非线性 tanh 软削波产生谐波）。
  2. 动手实现延迟：环形缓冲区 + feedback 系数（回声衰减）+ mix（干湿比）；讨论 feedback >1 为什么爆炸（指数增长削波）。
  3. 基于上面的延迟，实现简化混响与失真：梳状滤波器就是短延迟+反馈；失真用 `tanh(gain * x)`；讨论效果器顺序的影响（失真→混响 = 空间里的失真，混响→失真 = 失真的空间，完全不同）。
  4. 整合效果器链：把 DF02 的合成音依次过 失真→延迟→混响，存 WAV 对比每级效果；画框图说明效果器链的「单块串联」模型（吉他 pedalboard 的软件化）。

### DF09 算法作曲：马尔可夫链旋律生成

- **预期档位**: medium
- **考察维度**: 马尔可夫链 / 音乐统计 / 生成评估
- **对话脚本**:
  1. 马尔可夫链作曲：统计语料中「音 A 后面跟音 B」的转移概率，生成时按概率游走；一阶链（只看前一个音）vs 二阶链（看前两个音，更像原作但更死记硬背）。
  2. 数据准备：把 MIDI 旋律提取成音高序列（忽略节奏先）或 (音高差, 时值) 对序列；从 10 首民歌建转移矩阵。
  3. 基于上面的模型，讨论生成质量的评价困境：似然高≠好听（过拟合就是复读原曲）；引入「新颖度」指标（生成片段与训练集的最长公共子串）与人工听测；温度采样控制随机性。
  4. 动手：实现一阶马尔可夫旋律生成器——训练（统计转移计数）+ 生成（随机游走 32 音）+ 输出为 DF06 的 MIDI 事件；用不同温度（0.5/1.0/2.0）各生成 3 条对比「保守 vs 发散」。

### DF10 音频插件架构：VST 与宿主模型

- **预期档位**: medium~hard
- **考察维度**: 插件 ABI / 音频回调 / 宿主架构
- **对话脚本**:
  1. 音频插件的本质：一个导出约定入口的动态库（VST2 是 C 函数 + AEffect 结构体，VST3 是 COM 式接口，AU 是 Apple 组件）；宿主（DAW）加载插件、按块（block，如 512 采样）调它的 process() 处理音频。
  2. 实时音频的硬约束：process() 回调里禁止分配内存、禁止锁、禁止系统调用（任何阻塞都会爆音）——实时安全编程规则；插件参数变化怎么从 UI 线程安全传到音频线程（无锁队列/原子变量）。
  3. 基于上面的约束，讨论宿主架构：插件扫描（校验签名防崩溃拖垮宿主——很多宿主用独立进程跑插件）、信号流图（轨→效果器→总线，拓扑求值顺序）、插件状态保存（preset 序列化）。
  4. 动手：设计一个迷你插件接口（Python 模拟：`class Plugin: def process(self, in_buf) -> out_buf` + 参数表），写宿主把 DF08 的三个效果器当插件加载串联；讨论如果要真写成 C ABI 的 .so 要补什么。
