# 自动化测试提示词 — 游戏与趣味编程开发（Q01–Q10）

> 使用说明见同目录 `README.md`。每条提示词在同一 Session 内按轮次顺序喂入。

## 维度说明

本维度考察 Agent 在**游戏开发、编译器设计、移动端编程、嵌入式开发、
函数式编程、元编程宏系统、设计模式实战、WebAssembly、区块链应用、
物联网项目**等"趣味编程 + 深度工程"场景中的表现，
与 E 维度（通用编码调试）互补：E 考察"常规软件开发"，
本维度考察"特定编程范式与垂直领域的工程实现"。
所有主题都以"动手写代码"为核心，强调编程实战能力。

---

### Q01 用 Rust 开发一个终端贪吃蛇游戏
- **预期档位**: hard
- **考察维度**: 游戏逻辑 + TUI 实时渲染
- **对话脚本**:
  1. 我想用 Rust 在终端里做一个贪吃蛇游戏，先帮我设计核心数据结构（蛇身、食物、方向、边界）。
  2. 实现游戏主循环：每秒刷新 5 帧，键盘方向键控制蛇移动，吃到食物变长，撞墙或撞自己游戏结束。
  3. 加上计分系统（吃到食物 +10 分）和最高分记录（保存到本地文件）。
  4. 讨论：如果要改成"双人对战"模式（两条蛇），数据结构和碰撞检测要怎么改？

### Q02 从零实现一个 Lisp 解释器
- **预期档位**: hard
- **考察维度**: 编程语言实现 + 递归求值
- **对话脚本**:
  1. 我想用 Rust 实现一个极简 Lisp 解释器，先设计 Token 类型（数字、符号、括号、字符串）。
  2. 实现词法分析器（tokenizer）和语法分析器（parser），把源码转成 AST。
  3. 实现求值器（eval）：支持 `define`、`lambda`、`if`、`+`、`-`、`*`、`/` 和列表操作（`car`/`cdr`/`cons`）。
  4. 写 5 个测试用例验证解释器：阶乘、斐波那契、闭包、递归、高阶函数（`map`）。

### Q03 用 Flutter 开发跨平台待办 App
- **预期档位**: hard
- **考察维度**: 移动端开发 + 状态管理
- **对话脚本**:
  1. 我想用 Flutter 开发一个跨平台的待办事项 App，先设计数据模型（Todo 实体：id、标题、完成状态、创建时间）。
  2. 用 Provider 或 Riverpod 实现状态管理，完成"添加/删除/标记完成"三个核心功能。
  3. 加上本地持久化（用 sqflite 或 hive），App 重启后数据不丢失。
  4. 讨论：如果要支持"多列表（工作/生活/学习）"，状态管理和 UI 架构要怎么调整？

### Q04 嵌入式 Rust：Arduino 点灯与温度采集
- **预期档位**: hard
- **考察维度**: 嵌入式开发 + 硬件交互
- **对话脚本**:
  1. 我想用 Rust 在 Arduino（ATmega328P）上开发，先解释 `avr-hal` 和 `embedded-hal` 的关系。
  2. 实现一个 blink 程序：LED 每秒闪烁一次，用 `delay_ms` 控制时序。
  3. 接入 DHT11 温度传感器，每 2 秒读取一次温湿度并通过串口打印。
  4. 讨论：嵌入式 Rust 和桌面 Rust 在内存管理、错误处理、标准库使用上有什么本质区别？

### Q05 函数式编程实战：用 Rust 实现 Monad
- **预期档位**: medium
- **考察维度**: 函数式范式 + 泛型编程
- **对话脚本**:
  1. 用 Rust 解释什么是 Monad，`Option<T>` 和 `Result<T, E>` 为什么是 Monad。
  2. 用 Rust 的 `and_then`（flat_map）和 `map` 实现一个链式计算：从文件读数字 → 解析 → 翻倍 → 输出，全程用 Option/Result 处理错误。
  3. 实现一个简化的 `Future/Promise` 模拟（回调 + 状态机），解释 async/await 和 Monad 的关系。
  4. 讨论：Rust 的函数式特性（闭包、迭代器、模式匹配）和纯函数式语言（Haskell）相比，有哪些取舍？

### Q06 Rust 宏系统：声明宏与过程宏
- **预期档位**: hard
- **考察维度**: 元编程 + 代码生成
- **对话脚本**:
  1. 解释 Rust 的声明宏（`macro_rules!`）和过程宏（proc_macro）的区别，各适合什么场景。
  2. 用 `macro_rules!` 实现一个 `hash_map!` 宏，让 `hash_map!{"a" => 1, "b" => 2}` 直接生成 `HashMap`。
  3. 用 `proc_macro_derive` 实现一个 `#[derive(Builder)]` 结构体派生宏，自动生成 builder 模式代码。
  4. 讨论：宏的"卫生性（hygiene）"是什么？为什么宏调试困难，有什么最佳实践？

### Q07 设计模式在 Rust 中的实现
- **预期档位**: medium
- **考察维度**: 设计模式 + Rust 惯用法
- **对话脚本**:
  1. 选择 5 个最常用的设计模式（单例、工厂、观察者、策略、装饰器），解释各自解决的问题。
  2. 用 Rust 实现"观察者模式"：事件发布-订阅系统，支持多订阅者和异步通知。
  3. 用 Rust 实现"策略模式"：一个文本处理器，可动态切换压缩策略（gzip/zstd/snappy）。
  4. 讨论：哪些设计模式在 Rust 中"不自然"（如访问者模式）？Rust 的 trait/enum 如何替代经典 OOP 模式？

### Q08 WebAssembly：Rust 编译到浏览器
- **预期档位**: hard
- **考察维度**: WASM 跨语言互操作
- **对话脚本**:
  1. 解释 WebAssembly 是什么，为什么 Rust 是编写 WASM 的最佳语言之一。
  2. 用 `wasm-pack` 创建一个 Rust 项目，实现一个图像灰度化函数，编译为 WASM 模块。
  3. 写一个 HTML + JS 页面，加载 WASM 模块，上传图片后调用灰度化函数并显示结果。
  4. 讨论：WASM 和 JS 之间的数据传递（字符串、数组）有什么性能陷阱？`wasm-bindgen` 解决了什么问题？

### Q09 区块链应用：用 Solidity 实现简单代币
- **预期档位**: hard
- **考察维度**: 智能合约开发 + 区块链思维
- **对话脚本**:
  1. 解释 ERC-20 代币标准的核心接口（`totalSupply`、`balanceOf`、`transfer`、`approve`、`transferFrom`）。
  2. 用 Solidity 实现一个最简 ERC-20 代币合约，包含铸造（mint）和销毁（burn）功能。
  3. 用 Hardhat 或 Foundry 写测试用例：验证转账、授权、余额查询的正确性。
  4. 讨论：Solidity 的"重入攻击"是什么？你的合约有没有这个风险？怎么防？

### Q10 物联网项目：树莓派智能家居控制中心
- **预期档位**: hard
- **考察维度**: IoT 全栈开发 + 硬件集成
- **对话脚本**:
  1. 我想用树莓派搭建一个智能家居控制中心，先设计系统架构（传感器层 → 控制层 → Web 界面）。
  2. 用 Python 或 Rust 实现一个 MQTT 客户端，订阅温湿度传感器数据并打印。
  3. 实现一个 Web 控制界面（Flask 或 Axum），显示实时数据并支持远程控制继电器（模拟开关灯）。
  4. 讨论：IoT 项目的安全性怎么保障（固件签名、通信加密、OTA 更新）？你的方案有哪些安全漏洞？
