### CF01 类型系统基础：从动态类型到静态类型

- **预期档位**: medium
- **考察维度**: 类型系统谱系 + 类型安全 + 工程权衡
- **对话脚本**:
  1. 类型系统（Type System）是「定义、检查、推断程序中值类型」的形式系统。基本分类：(a) 静态类型（编译时检查，如 Rust / Java / Haskell）；(b) 动态类型（运行时检查，如 Python / JavaScript / Ruby）；(c) 强类型（不允许隐式类型转换，如 Python / Rust）；(d) 弱类型（允许隐式类型转换，如 JavaScript / C）。请解释为什么「静态类型」能在编译期捕获更多错误（类型错误在运行前暴露）。
  2. 类型安全（Type Safety）是「程序不会因类型错误而崩溃」的保证。类型安全定理：(a) 进展（Progress，良类型程序不会卡住）；(b) 保持（Preserve，求值保持类型）；(c) 合称「良类型程序不会出错」（Well-typed programs cannot go wrong）。请用 Rust 的Ownership 类型系统解释如何防止悬垂指针（Dangling Pointer）。
  3. 静态 vs 动态的工程权衡：(a) 静态类型优势（早期错误发现 / 重构友好 / IDE 支持好 / 性能优化）；(b) 静态类型劣势（学习曲线 / 编译时间 / 表达力限制）；(c) 动态类型优势（快速原型 / 表达力灵活 / 无编译等待）；(d) 动态类型劣势（运行时错误 / 重构困难 / IDE 支持弱）。请讨论 TypeScript 如何折中（静态类型层 + JavaScript 运行时）。
  4. laew 的类型系统启示：laew 的工具参数验证是「运行时类型检查」，是否可以引入「编译期类型检查」：(a) 工具 Schema 用 Rust 类型表达（而非 JSON Schema）；(b) 参数类型在工具注册时检查；(c) 类型错误在启动时发现。讨论这种「强类型工具注册」对 laew 工程质量的提升。

### CF02 Hindley-Milner 类型推断：让编译器猜出类型

- **预期档位**: hard
- **考察维度**: HM 类型系统 + 统一算法 + 多态
- **对话脚本**:
  1. Hindley-Milner（HM）类型系统是 ML 家族（OCaml / Haskell / Standard ML）的基础，核心能力是「类型推断」（无需标注类型，编译器自动推断）。HM 的核心概念：(a) 类型变量（`'a` / `'b`，未知类型）；(b) 类型方案（`forall a. a -> a`，多态类型）；(c) 统一（Unification，解类型方程）；(d) 泛化（Generalization，把类型变量泛化）。请解释为什么 HM 让 ML 代码几乎不需要类型标注。
  2. 统一算法（Unification Algorithm）：(a) 相同类型 → 统一；(b) 类型变量与具体类型 → 替换；(c) 函数类型 → 分别统一参数和返回值；(d) occurs check（防止无限类型，如 `'a = 'a -> 'b`）。请描述推断 `fun x -> fun y -> x` 类型的完整过程：`x: 'a`, `y: 'b`, 返回 `'a`, 最终 `'a -> 'b -> 'a`。
  3. 多态与 Let 多态：(a) 参数多态（Parametric Polymorphism，`id: forall a. a -> a`）；(b) Let 多态（`let id = fun x -> x in (id 1, id true)` 合法）；(c) 为什么 Lambda 多态不行（`(fun x -> x) 1, (fun x -> x) true` 不合法）；(d) 泛化发生在 Let 绑定而非 Lambda 绑定。请解释「Let 多态」为什么对 HM 的类型推断能力至关重要。
  4. laew 的类型推断启示：laew 的工具参数系统是否可以引入类型推断：(a) 常见参数类型（字符串 / 数字 / 路径）自动推断；(b) 复杂参数（JSON 对象）需要显式 Schema；(c) 类型不匹配时给出精确的错误位置。讨论这种「渐进类型」对 laew 工具定义的价值。

### CF03 泛型（Generics）：参数化多态的工程实现

- **预期档位**: medium
- **考察维度**: 泛型设计 + 单态化 + 类型约束
- **对话脚本**:
  1. 泛型（Generics）是「参数化类型」的机制，让代码适用于多种类型。实现策略：(a) 单态化（Monomorphization，Rust / C++，每个类型参数生成专用代码）；(b) 类型擦除（Type Erasure，Java / Go（1.18 前），运行时擦除类型信息）；(c) 字典传递（Dictionary Passing，Haskell，传递类型类字典）；(d) 装箱（Boxing，.NET，值类型装箱为引用类型）。请解释为什么 Rust 的单态化让泛型零成本（编译后无运行时开销）。
  2. Rust 泛型深入：(a) 结构体泛型（`struct Point<T> { x: T, y: T }`）；(b) 函数泛型（`fn identity<T>(x: T) -> T`）；(c) Trait 约束（`fn add<T: Add>(a: T, b: T) -> T::Output`）；(d) 生命周期泛型（`fn longest<'a>(a: &'a str, b: &'a str) -> &'a str`）。请写一个泛型 `max<T: Ord>(a: T, b: T) -> T` 函数。
  3. 高级泛型特性：(a) 关联类型（Associated Types，trait 内的类型占位符）；(b) 泛型关联类型（GATs，`trait LendingIterator { type Item<'a> where Self: 'a; }`）；(c) 常量泛型（const Generics，`generic_array`）；(d) 高阶类型（Higher-Kinded Types，Rust 目前不支持）。请解释「关联类型」vs「泛型参数」的区别（Iterator 的 `Item` 用关联类型更自然）。
  4. laew 的泛型应用：laew 的工具系统是否可以引入泛型：(a) `Tool<Input, Output>` 泛型 trait；(b) 类型安全的工具链（`ReadTool<FileTool<WriteTool>>`）；(c) 泛型工具组合器（`map` / `and_then`）。讨论泛型对 laew 工具架构的表达力提升。

### CF04 依赖类型：类型依赖于值的类型系统

- **预期档位**: hard
- **考察维度**: 依赖类型 + Agda/Idris + 定理证明
- **对话脚本**:
  1. 依赖类型（Dependent Types）是「类型依赖于值」的类型系统，比泛型更强大。核心能力：(a) 长度索引列表（`Vec n T`，长度在类型中）；(b) 索引类型（`Fin n`，小于 n 的自然数）；(c) 等式约束（`(a: Nat) -> (b: Nat) -> a + b = b + a`）；(d) 定理证明（Curry-Howard 同构，类型即命题、程序即证明）。请解释为什么「长度索引列表」能防止越界访问（`head: Vec (n+1) T -> T`，空列表无 `head`）。
  2. 依赖类型语言：(a) Agda（纯定理证明，无副作用）；(b) Idris（实用编程语言，支持编译执行）；(c) Coq（定理证明助手，提取 OCaml / Haskell / Scheme 代码）；(d) Lean（数学定理证明 + 编程语言）；(e) ATS（C 性能 + 依赖类型安全）。请用 Idris 写一个类型安全的 `head` 函数：`head : (xs : List a) -> {auto prf : length xs > 0} -> a`。
  3. 依赖类型的工程应用：(a) 形式化验证（CompCert 编译器 / seL4 微内核）；(b) 协议验证（会话类型）；(c) 资源跟踪（线性类型 + 依赖类型）；(d) 安全关键系统（航空航天 / 医疗）。请解释为什么「形式化验证」在安全关键系统中有不可替代性（测试无法覆盖所有情况）。
  4. laew 的依赖类型启示：laew 的工具参数验证是否可以引入依赖类型思想：(a) 路径参数类型 `Path<Exists>`（文件必须存在）；(b) 数值参数类型 `Int<Range<0, 100>>`（值在 0-100 之间）；(c) 字符串参数类型 `Str<Matches<Regex>>`（匹配正则）。讨论这种「细化类型」对 laew 工具参数安全的价值。

### CF05 线性类型与 Rust Ownership：资源管理的类型级保证

- **预期档位**: hard
- **考察维度**: 线性类型 + Ownership + 资源安全
- **对话脚本**:
  1. 线性类型（Linear Types）是「值必须恰好使用一次」的类型系统。与 Rust Ownership 的关系：(a) Rust 所有权 ≈ 仿射类型（Affine Type，值最多使用一次）；(b) 线性类型要求恰好使用一次（更严格）；(b) 借用（Borrowing）允许临时共享（`&T` / `&mut T`）；(c) 生命周期（Lifetime）跟踪借用有效期。请解释为什么线性类型能防止资源泄漏（文件 / 锁 / 连接必须显式释放）。
  2. Rust Ownership 深入：(a) 移动语义（Move，所有权转移）；(b) 借用规则（不可变借用多个 XOR 可变借用一个）；(c) 生命周期省略规则（三条自动推断规则）；(d) NLL（Non-Lexical Lifetimes，借用作用域更精确）。请描述为什么 `let s1 = String::from("hello"); let s2 = s1; println!("{}", s1);` 编译失败（`s1` 已移动）。
  3. 线性类型的现代应用：(a) Rust（内存安全 + 无 GC）；(b) Haskell Linear Types 扩展（`a %1 -> b`）；(c) Idris 2（QTT， Quantitative Type Theory）；(d) Granule（线性 +  graded 类型）；(e) Clean（唯一类型）。请解释 Granule 的「graded 类型」如何用类型跟踪资源使用次数。
  4. laew 的线性类型启示：laew 的工具执行是否可以引入线性类型思想：(a) 「一次性工具」（执行后自动销毁）；(b) 「借用工具」（临时访问权限）；(c) 「共享工具」（多个会话只读访问）。讨论这种「工具资源管理」对 laew 并发安全的价值。

### CF06 类型类（Type Class）：Haskell 的优雅多态

- **预期档位**: hard
- **考察维度**: 类型类设计 + 定律 + 工程应用
- **对话脚本**:
  1. 类型类（Type Class）是 Haskell 的「结构化多态」机制，类似 Rust 的 trait。核心概念：(a) 类型类定义（`class Eq a where (==) :: a -> a -> Bool`）；(b) 实例声明（`instance Eq Int where x == y = ...`）；(c) 约束使用（`elem :: Eq a => a -> [a] -> Bool`）；(d) 派生实例（`deriving (Eq, Show, Ord)`）。请解释为什么类型类比 OOP 接口更灵活（可以给已有类型添加实例，无需修改类型定义）。
