### CN01 体素数据结构与区块调色板压缩

- **预期档位**: medium
- **考察维度**: Chunk 内存布局 + 调色板索引压缩
- **对话脚本**:
  1. 用 Rust 定义体素世界核心数据结构：`Chunk { blocks: Vec<u16>, palette: Vec<BlockKind> }`，尺寸 16×16×16（或 32×256×32 的列式 chunk）；解释为什么 `blocks` 存的是「调色板索引」而不是 `BlockKind` 枚举本体。
  2. 调色板压缩：一个 chunk 内实际出现的方块种类通常 < 30 种，按种类数动态选择索引位宽（1 种 → 全块同值不存数组；≤16 种 → u4 打包；≤256 种 → u8）；写 `get(x,y,z)` / `set(x,y,z,kind)` 在位打包数组上的实现。
  3. 世界坐标与区块坐标换算：`chunk = world >> 4`（除以 16）、`local = world & 15`；写跨区块边界读取方块的 `world.get_block(wx, wy, wz)`，处理负坐标（Rust 中 `-1 >> 4 == -1`、`-1 & 15 == 15` 的正确性验证）。
  4. laew 借鉴：调色板思想 = 「重复内容只存一份、本体存引用」——讨论 laew 上下文中反复出现的「同一文件内容多次粘贴」是否可以做成内容寻址缓存（sha256 → 内容表），Compact Agent 压缩时把重复块替换为指针。

### CN02 贪心网格合并（Greedy Meshing）

- **预期档位**: hard
- **考察维度**: 面剔除 + 共面合并算法
- **对话脚本**:
  1. 朴素 meshing：遍历每个方块、每个方向，若相邻方块为空气则输出 1 个 quad（4 顶点 6 索引）；先写这个基线版本，统计一个 16×16×16 实心 chunk 的 quad 数量（理论 1536）。
  2. 贪心合并：把同一方向、同一方块种类、共面的相邻 quad 合并成大矩形——对每层做「二维矩阵的极大矩形合并」：从左上角开始向右扩展宽度、向下扩展高度，标记已占用格子，直到无法扩展；写出这个经典 greedy meshing 循环。
  3. 合并的正确性约束：UV 纹理重复（大 quad 需要纹理平铺，`textureSize * w`）与「不同朝向/不同 AO 不能合并」；讨论贪心不保证最优（与最优矩形划分差距通常 < 10%）为什么工程上可接受。
  4. laew 借鉴：把「贪心合并」用于 TUI 渲染引擎的 diff——`engine.rs::present()` 逐 cell 检测样式变化输出 ANSI，可否先按「行内相同样式段」合并成一段转义序列再输出，减少终端转义字节数。

### CN03 三维密度场地形生成

- **预期档位**: hard
- **考察维度**: 3D 噪声 + 密度阈值 + 生物群系
- **对话脚本**:
  1. 三维地形：体素世界不用高度图而用「密度场」——对每个体素采样 3D 噪声 `density = noise3(x,y,z) - y * gradient`，density > 0 为实心；解释这个「减去高度梯度」如何控制地表大致平整又保留洞穴。
  2. 多倍频与域扭曲：`density = fbm(octaves=4, lacunarity=2.0, gain=0.5)` 叠加细节，再做 domain warp（对采样坐标加一层低频噪声扰动）消除「网格感」；用 Rust 写 `simplex` 或 `noise-rs` 调用封装。
  3. 生物群系：用两个低频 2D 噪声（温度 / 湿度）查「群系矩阵」（沙漠 / 平原 / 雪原 / 丛林），群系决定表层方块（沙 / 草 / 雪）与地形参数（山峰倍率）；写群系采样与表层替换逻辑。
  4. laew 借鉴：种子确定性——同一种子生成同一世界，等价于「相同提示词 + 相同模型参数应产生可复现的 Agent 行为」；讨论 laew 的 Debug 报告要记录哪些「种子等价物」（模型版本 / 温度 / 工具定义 hash）才能离线复现一次任务编排。

### CN04 无限世界与区块流式加载

- **预期档位**: hard
- **考察维度**: 加载半径 + 优先级队列 + 滞后卸载 + 异步生成
- **对话脚本**:
  1. 以玩家为中心的加载半径：计算玩家所在区块，按曼哈顿/欧氏距离维护「半径 R 内区块集合」，玩家跨区块移动时计算需要加载与卸载的差集；写增量计算而不是全量重算。
  2. 滞后卸载（hysteresis）：进入半径 8 加载、超出半径 11 才卸载，防止玩家在边界反复横跳导致区块「加载-卸载-加载」抖动；讨论卸载前是否要等待 meshing 完成以及未保存修改的落盘时机。
  3. 优先级与预算：每帧只允许发起 K 个区块生成任务，按「距离玩家最近」优先（二叉堆）；生成线程池用 channel 与渲染线程解耦，完成的区块走消息回主线程上传 GPU，写这条异步管线的消息类型定义。
  4. laew 借鉴：对照 laew 的 `-f` 文件模式与项目上下文注入——「按需加载 + 滞后保留」同样适用于上下文管理：被引用过的文件内容在压缩时不要立刻丢弃（滞后卸载），避免下轮追问又要重新读盘。

### CN05 方块修改与局部重网格化

- **预期档位**: medium
- **考察维度**: 脏标记 + 跨界邻接失效
- **对话脚本**:
  1. 修改方块的管线：`set_block` → 标记所在 chunk 为 dirty → 该 chunk 重新 greedy meshing → 上传新 VBO；解释为什么「整 chunk 重网格化」（毫秒级）比「增量 patch 单个 quad」更简单可靠。
  2. 跨界失效：修改 `local_x == 0` 的方块会影响西邻 chunk 的可见面，必须把相邻 chunk 也标 dirty；写 `mark_dirty_with_neighbors(cx, cy, cz, local)` 的边界判定，并测试四个角块（同时影响 3 个邻居）。
  3. 批量修改优化：一次爆炸修改上百个方块时，先把所有 set 收集到事务里，按 chunk 分组去重后再批量重网格化，避免同一 chunk 重建多次；写 `BlockEditBatch` 的合并逻辑。
  4. laew 借鉴：对应 laew 的 `/rewind` 实现——回退轮次要「context / transcript / 累计用量」三处一致截断，与「批量修改统一失效」同构：先收集所有受影响对象再一次性应用，避免中间态。

### CN06 天光传播与顶点环境光遮蔽

- **预期档位**: hard
- **考察维度**: 光照 BFS 扩散 + 顶点 AO 查表
- **对话脚本**:
  1. 天光（Sky Light）：从区块顶部向下投射满亮度 15，遇到不透明方块衰减；然后做水平扩散 BFS——亮度每传播 1 格衰减 1，从高亮度格子向低亮度邻居扩散直到收敛；写出这个 BFS 并说明为什么要「先下投再扩散」两阶段。
  2. 块光源：火把亮度 14，同样 BFS 扩散；多个光源取 max 而不是相加（Minecraft 语义）；讨论「挖掉光源方块」时反向撤销光照的 BFS（把受影响的格子重置后从边界重算）。
  3. 顶点 AO（环境光遮蔽）：每个 quad 顶点查「相邻两侧 + 对角」三个格子的遮挡组合（经典 0~3 遮蔽等级查表），乘到顶点色上让方块夹角自然变暗；写出顶点 AO 的查表函数与四边形翻转（anisotropy 修复：a00+a11 > a01+a10 时翻转对角线）。
  4. laew 借鉴：光照「增量传播 + 局部重算」的思路对照 `agent/overflow.rs` 的三级恢复——局部变化只触发局部恢复而不是全上下文重建，讨论「排水（截短超长 tool_result）」与「撤销光照」在算法结构上的相似性。

### CN07 种子、确定性存档与版本迁移

- **预期档位**: medium
- **考察维度**: 过程生成 + 修改 diff 存储 + 存档演进
- **对话脚本**:
  1. 存档策略：地形永远由 `(seed, 算法版本)` 现场重生成，玩家修改存成「diff 记录」`HashMap<ChunkPos, HashMap<LocalPos, BlockKind>>`；解释这个设计让存档体积只与修改量相关而与探索面积解耦。
  2. 写序列化：用 serde 把 diff 与玩家状态（位置 / 背包 / 时间）写入单个文件，落盘要「写临时文件 + rename」原子替换防崩溃损坏；估算探索 1000×1000 区块、修改 5 万方块的存档体积。
  3. 算法版本迁移：地形算法升级后旧存档的地形会变（与已保存修改错位）——采用「新区块用新算法、已生成区块记录算法版本并保留」的策略，写区块元数据里的 `algo_version` 判定逻辑。
  4. laew 借鉴：对照 SQLite `providers` 表的存量库自动迁移补列回填默认值——讨论「向后兼容的版本化数据」在游戏存档与 laew DB 迁移里的共同原则（旧数据永不破坏 / 新字段必有默认值 / 版本号随数据走）。

### CN08 多线程 meshing 与渲染解耦

- **预期档位**: medium~hard
- **考察维度**: 生产者消费者 + 双缓冲 + 线程安全上传
- **对话脚本**:
  1. 管线分层：主线程（输入/摄像机）→ 生成线程池（噪声地形）→ meshing 线程池（贪心合并产顶点缓冲）→ 渲染线程（GPU 上传与绘制）；用 Rust 的 `crossbeam-channel` 或 `std::sync::mpsc` 连接各阶段，写出各队列的消息枚举。
  2. 取消与过期任务：玩家快速移动会让排队中的区块任务失效——任务带上「提交时的玩家位置」，执行前校验目标区块是否仍在加载半径内，过期直接丢弃；讨论这个「乐观提交 + 执行前校验」模式的适用面。
  3. 结果交换：meshing 完成的顶点缓冲不能边渲染边覆写——用双缓冲（pending 集合在帧末一次性 swap 进渲染可见集合），写 swap 时机与 GPU 上传批合并（一帧最多上传 N 个区块防卡顿）。
  4. laew 借鉴：与 laew 的同层 SubAgent 并行（Semaphore 上限 3）对比——体素管线是「流水线并行」而 laew 是「任务级并行」，讨论两种并行在取消传播与结果收集上的差异。

### CN09 视锥剔除、八叉树与区块 LOD

- **预期档位**: hard
- **考察维度**: 视锥剔除 + 层级包围盒 + 远景降级
- **对话脚本**:
  1. 视锥剔除：从投影矩阵反推 6 个视锥平面方程，对每个区块 AABB 做「平面-球」快速判定（区块中心 + 包围球半径）；用 Rust 写平面提取与剔除循环，统计渲染区块数量从 ~2000 降到 ~300 的效果。
  2. 八叉树剔除：把区块按空间八叉树组织，父节点包围盒整体在视锥外则整棵子树跳过；写八叉树的插入与每帧遍历，讨论静态世界（区块位置固定）为什么适合预建树。
  3. 区块 LOD：远处区块用「合并采样」（4×4×4 体素合成 1 个大块，只保留占多数的方块种类）生成低模网格，近处切换全精度；写 LOD 选择规则与距离驱动的层级切换（滞后带宽防抖动）。
  4. laew 借鉴：LOD 的「远处粗、近处细」对照 laew 的三档上下文压缩（Light/Medium/Aggressive）——距离触发阈值 + 滞后带 + 分级精度是一套通用模式，讨论它在两者中各自的「观察距离」等价物（token 占用 vs 摄像机距离）。

### CN10 联机沙盒：区块所有权与修改同步

- **预期档位**: hard
- **考察维度**: 所有权移交 + 修改广播 + 冲突解决
- **对话脚本**:
  1. 区块所有权模型：每个「活跃区块」由距离最近的玩家拥有，拥有者负责该区块的模拟（方块更新 / 重力沙子）与修改广播；写所有权再分配的触发条件（玩家移动超阈值）与移交握手消息。
  2. 修改同步：玩家挖方块 → 本地乐观应用 → 上报服务器（权威校验：权限 / 距离 / 冷却）→ 广播给订阅该区块的其他玩家；讨论乐观应用被服务器拒绝时的回滚 UI 闪烁问题与「先确认后应用」的延迟取舍。
  3. 重连追赶：迟到玩家向服务器请求「已生成区块的种子 + 修改日志」，本地重放所有修改得到一致世界；对照 CM05 的全量快照方案，解释「种子 + 操作日志重放」为什么更适合巨大世界（快照太大），代价是什么（重放耗时）。
  4. laew 借鉴：「种子 + 操作日志」与 Event Sourcing 同构——讨论 laew 的 Session 若改为「系统提示词种子 + 全部用户消息日志」的事件溯源存储，`/rewind` 与 `/fork` 的实现会简化成「重放到第 N 条」，并指出 token 重放成本这一最大代价。
