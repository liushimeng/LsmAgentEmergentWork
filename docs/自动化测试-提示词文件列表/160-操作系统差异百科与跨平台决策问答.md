### EZ01 进程创建模型差异

- **预期档位**: medium
- **考察维度**: fork/exec vs posix_spawn vs CreateProcess / 子进程继承
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ez01_qa.md`：三平台进程模型对比表（fork+exec / posix_spawn / CreateProcess：触发平台/是否复制父内存/PID 行为）；附 python3 验证本机 start-method。
  2. Bash：`python3 -c "import multiprocessing,sys; print(multiprocessing.get_start_method(),sys.platform)" | tee ez01_native.txt`；linux 下默认 fork、windows/macOS 默认 spawn；`python3 -c "import os; print(hasattr(os,'fork'))"`；`grep -F 'fork' ez01_qa.md`。
  3. Read `ez01_native.txt`，Write `ez01_parent_mem.py`：父写共享 dict → `os.fork()` → 子 `_exit(0)` 前读 dict 证明继承；`multiprocessing.Process` 跨平台验证——本机默认 fork 父子共享 fork 前变量，spawn 时子仅接收 args。本轮必须显式复用第一轮 start-method 表与对比行，不允许另起无关主题。
  4. Bash：`python3 ez01_parent_mem.py | tee ez01_run.log`；`python3 -c "import multiprocessing as m; p=m.Process(target=lambda: None); p.start(); p.join(); print('spawn_path OK')"`；`grep -F 'fork_path' ez01_run.log` 或 `grep -F 'spawn_path' ez01_run.log`（命中其一即可）。

### EZ06 信号与作业控制差异

- **预期档位**: hard
- **考察维度**: Unix 信号 vs Windows 消息 / 进程组传播
- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ez06_signal.py`：python 子进程跑 `time.sleep(60)`，父 `os.kill(pid, signal.SIGTERM)` 后 `os.waitpid(pid, 0)` 拿退出状态；输出 `{pid, sent_signal, exit_status, killed_by_signal}` JSON；Windows 端 SIGKILL 仅注释。
  2. Bash：`python3 ez06_signal.py | tee ez06_run.json`；`grep -F '"killed_by_signal": "SIGTERM"' ez06_run.json`；`python3 -m json.tool ez06_run.json >/dev/null`。
  3. Read `ez06_run.json`，Write `ez06_compare.md`：三平台信号对照——Linux/macOS：SIGINT 传播到进程组、Ctrl+C→前台进程组全员收 SIGINT；Windows：Ctrl+C 触发 CTRL_C_EVENT 仅 console 进程组、无 SIGKILL 等价物；附 nohup/setsid 在 Unix 上的去关联行为。本轮必须显式复用第一轮 killed_by_signal 字段命名与实测结论，不允许另起无关主题。
  4. Bash：`grep -F 'SIGINT' ez06_compare.md`；`grep -F 'CTRL_C_EVENT' ez06_compare.md`；`grep -F 'setsid' ez06_compare.md`；`test -s ez06_compare.md`。

### EZ07 权限模型三态对比

- **预期档位**: medium

- **工具链**: Write → Bash → Read → Bash
- **对话脚本**:
  1. Write `ez07_perm.md`：三态权限对比表（Unix rwx 9 位 + setuid/setgid/sticky；Windows ACL Allow/Deny/Inherit；macOS TCC 隐私授权）；附 chmod 位验证思路。
  2. Bash：`mkdir -p ez07_dir`；`chmod 1777 ez07_dir`；`stat -c '%a %A %n' ez07_dir | tee ez07_stat.txt`；`grep -F '1777' ez07_stat.txt`；`grep -F 'drwxrwxrwt' ez07_stat.txt` 命中 t（粘滞位）；`grep -F 'ACL' ez07_perm.md`。
  3. Read `ez07_stat.txt`，Write `ez07_bit.json`：拆解 `1777`——owner/group/other=7(=rwx)、sticky=1、setuid=0、setgid=0，输出 `{mode_octal, owner, group, other, setuid, setgid, sticky}` JSON。本轮必须显式复用第一轮字段命名与 stat 验证结论，不允许另起无关主题。
  4. Bash：`python3 -c "
m=0o1777
print({'mode_octal':oct(m),'owner':oct((m>>6)&7),'group':oct((m>>3)&7),'other':oct(m&7),'setuid':bool(m&0o4000),'setgid':bool(m&0o2000),'sticky':bool(m&0o1000)})" > ez07_auto.json`；`python3 -m json.tool ez07_bit.json >/dev/null`；`grep -F '"sticky": true' ez07_bit.json`；`python3 -m json.tool ez07_auto.json >/dev/null`。

- **工具链**: Write → Bash → Read → Bash

  2. Bash：`python3 -m py_compile ez08_lock.py`；`python3 ez08_lock.py | tee ez08_run.log`；`grep -F 'ACQUIRED' ez08_run.log`；`grep -F 'BLOCKED_OR_STALE' ez08_run.log`。
  3. Read `ez08_run.log`，Write `ez08_stale.sh`：构造 stale 场景——A 进程创建 lock 写入 `pid=99999` 后退出，B 探测到 pid 不存活（kill -0 99999 失败）自动清理 stale 并再次 O_EXCL 成功。本轮必须显式复用第一轮 O_EXCL/pid-stale 字段命名，不允许另起无关主题。
