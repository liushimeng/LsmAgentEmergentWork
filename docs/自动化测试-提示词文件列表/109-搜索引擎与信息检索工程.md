### DA01 倒排索引的构建与压缩

- **预期档位**: medium
- **考察维度**: 倒排索引结构 / 词典组织 / posting 压缩
- **对话脚本**:
  1. 搜索引擎核心是倒排索引：词项 → 出现它的文档列表（posting list）。先用一个 5 篇文档、每篇一句话的最小语料，手算完整的倒排索引长什么样（词项、docID、词频、位置）。
  2. 基于上面手算的索引，讨论词典（dictionary）怎么组织才能快速定位词项：哈希表 vs 有序数组 vs FST（有限状态转换器，Lucene 用它兼顾前缀匹配与内存）。
  3. posting list 压缩：docID 存差值（delta encoding）再用可变长编码（VByte）或 PForDelta；估算 1 亿个 docID 用差值+VB 编码后大概占多少空间。
  4. 用 Python 写 100 行以内的迷你倒排索引：建索引函数 + 两词 AND 查询的归并算法（两个有序 posting 求交集），并用上面的 5 篇语料验证结果。

### DA02 TF-IDF 与 BM25 相关性排序

- **预期档位**: medium
- **考察维度**: 排序公式 / 参数调优 / 词频饱和
- **对话脚本**:
  1. 讲清 TF-IDF 的直觉：词在当前文档出现越多越相关（TF）、在全部文档出现越少越有区分度（IDF）；写出公式并手算一个词在 3 篇文档下的得分。
  2. BM25 是 TF-IDF 的工程化改良：引入文档长度归一化（b 参数）与词频饱和（k1 参数——出现 10 次不是比 5 次好两倍）。画出 BM25 的 TF 饱和曲线，解释为什么 k1 通常取 1.2~2.0。
  3. 基于上面的公式，用 Python 实现 BM25 打分函数，对 10 篇假文档 + 查询「开源 搜索引擎」排序，对比 TF-IDF 的结果差异。
  4. 工程延伸：线上怎么调 k1/b——用人工标注的相关性样本做网格搜索；讨论为什么不能只看离线指标，还要结合点击日志（引出 DA06）。

### DA05 搜索结果高亮与动态摘要

- **预期档位**: medium
- **考察维度**: 片段抽取 / 高亮标注 / 摘要质量
- **对话脚本**:
  1. 搜索结果里标题和摘要中的查询词标红——高亮的基础实现：对命中字段做二次分词，找到查询词位置包 `<em>` 标签；讨论为什么不能直接字符串替换（大小写、词形变化、转义 XSS）。

  3. 基于上面的打分思路，讨论摘要质量细节：避免从句子中间截断、多个查询词尽量覆盖、摘要重复内容去重。

### DA06 搜索日志分析：点击率与零结果治理

- **预期档位**: medium
- **考察维度**: 日志挖掘 / CTR 分析 / 零结果率
- **对话脚本**:
  1. 搜索质量的两个北极星日志指标：点击率 CTR（用户点了第几个结果）与零结果率（多少查询啥都没搜到）；设计搜索日志表结构（query / 返回数 / 点击位次 / 时间戳）。
  2. 基于上面的日志表，讨论位置偏置（position bias）——排第一天然点击高，不能直接拿 CTR 当相关性；引入「相对 CTR」（该位置 CTR / 历史同位置平均 CTR）做修正。
  3. 零结果治理闭环：捞零结果查询 Top 100 → 分类（拼写错 / 词典缺词 / 长尾需求）→ 分别走纠错、加词、补内容；讨论这是个运维+工程混合的日常迭代。
  4. 动手：造 1000 条模拟搜索日志（含查询、点击位次），用 SQL 或 Python pandas 算出各位置 CTR 与零结果率 Top 10 查询。

### DA07 搜索质量离线评估：MAP、MRR 与 NDCG

- **预期档位**: medium~hard
- **考察维度**: 评估指标 / 标注体系 / A/B 实验
- **对话脚本**:
  1. 离线评估三剑客的定义与差异：MAP（平均准确率均值，适合二值相关/不相关）、MRR（倒数排名，适合导航型查询）、NDCG（折损累计增益，支持分级相关度 0~3）；各手算一个 5 结果的小例子。
  2. 基于上面的指标，讨论标注体系：怎么组织人工标注（每个查询标注前 10 结果的相关度）、标注一致性怎么保证（多人标注取仲裁）、标注集多久刷新一次。
  3. 离线指标与线上体验的鸿沟：NDCG 提升 2% 用户可能无感；所以离线过门槛后还要线上 A/B 实验看 CTR/留存；讨论实验分流与显著性检验的最小样本量。
  4. 动手：用 Python 实现 dcg@k 与 ndcg@k 两个函数，用一组理想排序 vs 实际排序验证函数正确性。

### DA08 索引实时更新与段合并策略

- **预期档位**: medium~hard
- **考察维度**: 近实时索引 / LSM 式段合并 / 删除标记
- **对话脚本**:
  1. 新文档多久能被搜到？全文重建索引不可行，Lucene 的思路：新文档先进内存 buffer，定期 flush 成不可变小段（segment），查询时合并所有段的结果——这就是「近实时 NRT」。
  2. 基于上面的段模型，讨论段越积越多的问题与合并策略（tiered merge：小段并中段、中段并大段），类比 LSM-tree 的 compaction；合并的写放大代价怎么权衡。
  3. 更新与删除怎么落地：段不可变，所以删除是「标记删除」（bitset），更新 = 删旧插新；查询时过滤掉标记删除的 docID；讨论标记删除对召回统计的影响。
  4. 动手：给 DA01 的迷你索引加「段」概念——支持追加新文档生成新段、查询时跨段归并、删除标记过滤，观察三次 flush 后的段文件结构。

### DA09 多字段与多语言搜索

- **预期档位**: simple~medium
- **考察维度**: 字段权重 / 多语言分词 / 混合排序
- **对话脚本**:
  1. 电商搜索一个查询要同时命中标题、类目、详情、评论——多字段搜索的两种策略：字段分别打分再加权（title^3 + category^2 + detail^1）vs 字段合并成一个大字段；各自的召回/精度特点。
  2. 基于上面的加权思路，讨论跨字段打分归一化问题：标题天然短、BM25 分高，直接相加会让标题主导一切；引入 per-field 归一或 dis_max（取各字段最高分）的必要性。
  3. 多语言搜索：中日韩没有空格需要分词（CJK analyzer）、德语复合词拆分、阿拉伯语形态归一；讨论一套索引支持多语言的两种布局——单索引多字段（title_zh/title_en）vs 按语言分索引。
  4. 动手：给一个 20 条商品数据建「标题+详情」双字段迷你索引，实现字段加权的 BM25 排序，对比单字段与加权多字段的结果差异。
