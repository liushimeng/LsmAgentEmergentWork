### IB01 Yolo 分类与路由

- **预期档位**: medium
- **考察维度**: Yolo 三档分类(simple/medium/hard) / 目的→目标→意图三步分析
- **工具链**: Yolo(分类) → Read(分类结果)
- **对话脚本**:
  1. 输入超大工程任务(如「开发一个含前端+后端+数据库+测试+部署的完整 Web 应用」)。
  2. Yolo 执行 目的→目标→意图 三步分析 → 分类为 hard → 激活 Plan Agent。
  3. 断言:分类结果=hard,理由包含「多组件/多人协作/超大规模」,路由到 Plan Agent。

### IB02 Plan Agent 方案生成

- **预期档位**: medium
- **考察维度**: Plan Agent 生成 Markdown 方案 / 落到 `plans/{session_id}-{seq}.md`
- **工具链**: Plan(生成方案) → Read(plans/)
- **对话脚本**:
  1. Plan Agent 接收 Yolo 分类结果(hard) + 任务描述。
  2. 生成 Markdown 方案含:目标拆解/Phase 列表/依赖图/Squad 分配/风险点/验收标准。
  3. 方案落到 `plans/{session_id}-01.md`,断言:文件存在/含 Phase 列表/含依赖图/含 Squad 分配。

### IB03 WorkFlow Agent Phase 拆解

- **预期档位**: hard
- **考察维度**: WorkFlow 从方案拆解 Phase DAG / Goal 创建
- **工具链**: WorkFlow(拆解) → Read(GoalStore)
- **对话脚本**:
  1. WorkFlow Agent 读取 Plan 方案 → 拆解为 5 个 Phase(P1→P2→P3, P4→P5 并行)。
  2. 创建 Goal 状态机(Pending→Pursuing),Phase 依赖图写入 GoalStore。
  3. 断言:Goal.state=Pending,Phase 数量=5,依赖关系正确(P1 入度 0/P2 入度 1/P3 入度 1/P4 入度 0/P5 入度 1)。

### IB04 Main-Work 编排与 Squad 派发

- **预期档位**: hard
- **考察维度**: Main-Work 拆解 WorkFlow / Squad 派发 SubAgent + WindowUse
- **工具链**: Main-Work(编排) → SubAgent-Work + WindowUse
- **对话脚本**:
  1. Main-Work 读取 WorkFlow Phase 列表 → 按 Phase 派发 Squad。
  2. Squad 1(P1):SubAgent-Work 实现后端 API; Squad 2(P2):SubAgent-Work 实现前端 UI; Squad 3(P3):WindowUse 操控浏览器测试。
  3. 断言:3 个 Squad 派发,成员角色正确(SubAgent-Work + WindowUse),AgentMessage 消息桥建立。

### IB05 SubAgent-Work 并行执行

- **预期档位**: hard
- **考察维度**: 同层 SubAgent 并行(tokio::spawn + Semaphore 上限 3) / 跨层串行
- **工具链**: SubAgent-Work(并行执行) → Read(产物)
- **对话脚本**:
  1. P1→P2→P3 串行:P1 完成 → P2 开始;P2 完成 → P3 开始。
  2. P4→P5 并行:P4 和 P5 同层无依赖,并行执行。
  3. 断言:P1→P2→P3 顺序执行,P4/P5 并行执行(总耗时 ≈ max(P4,P5)),Semaphore 上限 3 不超。

### IB06 WindowUse 桌面操控集成

- **预期档位**: hard
- **考察维度**: WindowUse 在 WorkFlow 中操控桌面 / 跨应用数据搬运
- **工具链**: WindowUse(操控) → AgentMessage(桥) → SubAgent(处理)
- **对话脚本**:
  1. WindowUse Phase:打开浏览器 → 访问 localhost:3000 → 截图验证 UI。
  2. 跨应用:从 VS Code 读取 API 代码 → AgentMessage → SubAgent 生成测试用例 → WindowUse 写入浏览器执行。
  3. 断言:WindowUse 操作序列正确,AgentMessage 消息桥传递数据,跨应用数据不丢失。

### IB07 Quality-Check 全链路质检

- **预期档位**: medium
- **考察维度**: 每个 Phase 完成后 QC / 每个 Squad 完成后 QC / Goal 完成 QC
- **工具链**: Quality-Check(质检) → Read(QualityReport)
- **对话脚本**:
  1. P1 完成 → QC 检查后端 API 代码 → Pass。
  2. P2 完成 → QC 检查前端 UI 代码 → Fail(retryable) → 重试 → Pass。
  3. P3 完成 → QC 检查浏览器测试截图 → Pass。
  4. Goal 完成 → 最终 QC → Pass。
  5. 断言:每个 Phase 1 份 QualityReport,Phase 2 重试 1 次后 Pass,Goal 最终 Pass。

### IB08 Compact Agent 自动压缩

- **预期档位**: medium
- **考察维度**: 上下文 80% 触发压缩 / 三档选档 / 保护段保留
- **工具链**: Compact(压缩) → Read(压缩后上下文)
- **对话脚本**:
  1. 超大工程执行后上下文膨胀 → 估算 token 达到 context_max_size × 0.8。
  2. Compact Agent 自动触发 → 选档(如 Medium ≈50%) → 压缩非保护段历史。
  3. 保护段:项目上下文/历史摘要/已压缩标记 + 最近 4 条消息不压缩。
  4. 断言:压缩后 token ≤ 原 50%,保护段完整,带 `<<<LAEW:COMPACTED_CONTEXT>>>` 标记。

### IB09 SessionContext 摘要生成

- **预期档位**: medium
- **考察维度**: 任务完成后生成 Markdown 摘要 / 写入 `session_memory` 表
- **工具链**: SessionContext(生成摘要) → Read(session_memory)
- **对话脚本**:
  1. 超大工程全部完成 → SessionContext 生成摘要。
  2. 摘要包含:任务目标 / 执行结果 / 质检结论 / 重试次数 / 总耗时 / token 用量 / 产物列表。
  3. 写入 `session_memory` 表,下次任务时 Yolo 注入最近 3 条历史摘要。
  4. 断言:摘要非空,包含所有必填字段,写入成功,下次任务可注入。

### IB10 Debug Agent 全链路评估

- **预期档位**: hard
- **考察维度**: -debug 模式下 Debug Agent 评估全链路 trace / 生成报告
- **工具链**: Debug(评估) → Read(DebugReport)
- **对话脚本**:
  1. 超大工程在 `-debug` 模式下执行 → 采集各 Agent 输入输出/性能/质量 trace。
  2. Debug Agent 评估后生成报告含:任务评估 / 质量报告 / 问题报告(P0-P2)/ 优化建议。
  3. 报告写入**根目录** `DebugReport/debug_report_{YYYYMMDD}_{HHMMSS}_{随机6位}.md`。
  4. 断言:报告四章节完整,P0 问题无,P1/P2 问题有明确优化建议,metrics 数据准确。
