### CH01 语言谱系：从 Fortran 到 Rust 的 70 年演进

- **预期档位**: medium
- **考察维度**: 语言历史 + 谱系关系 + 演进规律
- **对话脚本**:
  1. 编程语言 70 年演进：(a) 第一代（1950s，Fortran / COBOL / LISP / ALGOL）；(b) 第二代（1960s-70s，C / Pascal / Smalltalk / Prolog / ML）；(c) 第三代（1980s-90s，C++ / Perl / Python / Ruby / Java / JavaScript）；(d) 第四代（2000s+，Go / Swift / Rust / Kotlin / TypeScript）。请解释为什么「ALGOL 60」被称为所有现代语言的祖父（BNF 语法 / 块结构 / 递归）。
  2. 语言谱系树：(a) ALGOL → Pascal → Ada / ALGOL → C → C++ / Java / Go；(b) LISP → Scheme → Clojure / LISP → Common Lisp；(c) Smalltalk → Objective-C / Smalltalk → Java / Ruby；(d) ML → OCaml → Rust / ML → Haskell。请描述 C 语言谱系如何从 ALGOL 演化而来（ALGOL 60 → ALGOL 68 → CPL → BCPL → B → C）。
  3. 语言演进的动力：(a) 硬件演进（从巨型机到云到边缘）；(b) 应用演进（科学计算 → Web → 移动 → AI）；(c) 范式演进（命令式 → 面向对象 → 函数式 → 多范式）；(d) 工程演进（从单人到团队协作到开源社区）。请解释为什么「硬件演进」驱动语言设计（如 Rust 的内存安全适配系统编程需求）。
  4. laew 的语言选择启示：laew 用 Rust 实现，为什么 Rust 是 2020s 的语言：(a) 内存安全（无 GC + 无悬垂指针）；(b) 并发安全（Ownership + Send / Sync）；(c) 性能（零成本抽象）；(d) 生态（cargo / crates.io）。讨论 laew 如果早 10 年开发会选什么语言（C++ / Go / OCaml）。

### CH02 范式融合：现代语言如何兼收并蓄

- **预期档位**: medium
- **考察维度**: 多范式 + 范式融合 + 现代语言设计
- **对话脚本**:
  1. 编程范式（Programming Paradigm）是「编程的基本风格与哲学」。主要范式：(a) 命令式（Imperative，告诉计算机怎么做）；(b) 声明式（Declarative，告诉计算机要什么）；(c) 面向对象（OOP，对象 + 消息）；(d) 函数式（FP，函数 + 不可变）；(e) 逻辑式（Logic，事实 + 规则）。请解释为什么「范式」不是互斥的（现代语言多范式融合）。
  2. 多范式语言案例：(a) Scala（OOP + FP，JVM 上最函数式的 OOP 语言）；(b) Rust（命令式 + FP + 泛型 + 所有权）；(c) Kotlin（OOP + FP + 协程）；(d) Swift（OOP + FP + Protocol）；(e) Python（OOP + FP + 命令式）。请描述 Scala 如何融合 OOP 和 FP（case class + pattern matching + higher-kinded types）。
  3. 范式融合的设计挑战：(a) 语法冲突（FP 的简洁 vs OOP 的冗长）；(b) 类型系统冲突（FP 的高阶类型 vs OOP 的子类型）；(c) 运行时冲突（FP 的不可变 vs OOP 的可变状态）；(d) 社区冲突（FP 开发者 vs OOP 开发者）。请讨论 Rust 如何平衡命令式与函数式（鼓励不可变 + 支持可变借用）。
  4. laew 的范式融合启示：laew 的提示词模板系统是否可以多范式：(a) 声明式模板（描述要什么）；(b) 函数式模板（组合小模板）；(c) 逻辑式模板（规则驱动生成）。讨论多范式对 laew 提示词系统表达力的提升。

### CH03 语言设计哲学：为什么语言这样设计

- **预期档位**: medium
- **考察维度**: 设计取舍 + 哲学差异 + 工程影响
- **对话脚本**:
  1. 语言设计是「在多个相互冲突的目标之间取舍」。经典取舍：(a) 简洁 vs 表达力（C 简洁但表达力弱，C++ 表达力强但复杂）；(b) 安全 vs 性能（Java 安全但有 GC 开销，C 性能高但不安全）；(c) 灵活 vs 规范（Python 灵活但易出错，Go 规范但受限）；(d) 创新 vs 兼容（Python 3 不兼容 Python 2 引社区分裂）。请解释为什么「没有完美的语言」（所有设计都是取舍）。
  2. 语言设计哲学案例：(a) Python 之禅（「简单优于复杂」「可读性很重要」）；(b) Go 哲学（「少即是多」「组合优于继承」）；(c) Rust 哲学（「零成本抽象」「 fearless concurrency」）；(d) Haskell 哲学（「纯函数式」「类型驱动开发」）。请对比 Python 与 Go 的设计哲学差异（Python 灵活 vs Go 规范）。
  3. 语言设计的「意外后果」：(a) JavaScript 的 `==` 隐式转换（设计仓促导致混乱）；(b) Java 的 checked exception（设计初衷好但实际被滥用）；(c) C++ 的「未定义行为」（性能优化但安全灾难）；(d) Python 的 GIL（简化实现但限制并发）。请讨论如何从「意外后果」中学习（语言设计的经验教训）。
  4. laew 的设计哲学：laew 的设计哲学应该是什么：(a) 「Agent 优先」（所有设计围绕 Agent 编排）；(b) 「用户透明」（Agent 内部对用户可见）；(c) 「渐进复杂度」（简单任务简单处理，复杂任务有高级功能）；(d) 「工程务实」（不追求理论完美，追求实用）。讨论 laew 的设计哲学如何指导功能取舍。

### CH04 语言消亡与复兴：从 COBOL 到 Smalltalk

- **预期档位**: simple
- **考察维度**: 语言生命周期 + 消亡原因 + 复兴现象
- **对话脚本**:
  1. 编程语言也有生命周期：诞生 → 成长 → 成熟 → 衰退 → 消亡 / 稳定。消亡原因：(a) 技术过时（Pascal 被 C 取代）；(b) 生态崩溃（Flash / ActionScript）；(c) 商业失败（Delphi / Visual Basic）；(d) 社区分裂（Python 2 vs 3）。请解释为什么「COBOL」至今未完全消亡（金融系统替换成本太高）。
  2. 语言复兴案例：(a) JavaScript（从「玩具语言」到全栈之王）；(b) Lisp（AI 寒冬后通过 Clojure 复兴）；(c) Fortran（科学计算领域依然强大）；(d) Smalltalk（通过 Pharo 和 InspireTalk 复兴）。请描述 JavaScript 复兴的关键节点（Ajax → Node.js → npm → TypeScript）。
  3. 语言消亡的警示：(a) 依赖单一语言的风险（生态变化）；(b) 学习可迁移的技能（范式 / 算法 / 设计）；(c) 多语言能力的重要性（不同场景用不同语言）；(d) 语言只是工具（解决问题才是目的）。请讨论为什么「学习多种范式」比「学习多种语言」更重要。
  4. laew 的语言选择风险：laew 用 Rust 实现，Rust 会消亡吗：(a) Rust 的优势（性能 + 安全 + 生态）；(b) Rust 的风险（学习曲线 / 编译时间 / 新语言竞争）；(c) 替代语言（Zig / Carbon / Mojo）；(d) laew 如何降低语言绑定风险（核心逻辑与语言解耦）。讨论 laew 的多语言绑定策略。

### CH10 编程语言的「为什么」：深入理解语言设计

- **预期档位**: medium
- **考察维度**: 设计原理 + 深层理解 + 批判思维
- **对话脚本**:
  1. 学习编程语言不仅是「怎么用」，更是「为什么这样设计」。经典问题：(a) 为什么 C 的数组不从 1 开始（历史原因 + 指针算术）；(b) 为什么 Java 的 `String` 是不可变的（安全 + 哈希缓存 + 字符串池）；(c) 为什么 Python 有 GIL（简化实现 + C 扩展兼容）；(d) 为什么 Rust 没有异常（错误是值 + 显式处理）。请解释「为什么」学习法如何加深理解。
  2. 语言设计的「为什么」案例：(a) 为什么 Go 没有泛型（1.18 前，设计哲学是简洁）；(b) 为什么 JavaScript 有 `this`（原型继承需要）；(c) 为什么 Haskell 用空格缩进（Off-side rule，类似 Python）；(d) 为什么 Lisp 用 S-表达式（同像性 + 宏）。请讨论「为什么」学习法对语言选择的指导意义。
  3. 批判性思维：(a) 质疑「最佳语言」（没有最佳只有最适合）；(b) 质疑「新语言一定好」（新语言有创新但也有未知风险）；(c) 质疑「流行语言一定对」（流行不等于正确）；(d) 质疑「我的习惯一定好」（习惯不等于最优）。请讨论批判性思维如何帮助语言学习。
  4. laew 的「为什么」学习：laew 如何帮助用户理解「为什么」：(a) 解释 Agent 决策（为什么选择这个工具）；(b) 解释分类逻辑（为什么是 hard 不是 medium）；(c) 解释编排策略（为什么并行而非串行）；(d) 解释错误原因（为什么失败 + 如何避免）。讨论「为什么」解释对 laew 用户信任的价值。
