## 三、总体设计：三个正交维度

控制权是**第三个正交维度**，与已有的两个并列：

```
┌───────────────────────────────────────────────────────────────────────┐
│ 维度 A 浏览器可见性 BrowserMode（已有）                                │
│   headed（macOS/Windows 有 GUI）/ hidden（管道/CI/服务器）              │
├───────────────────────────────────────────────────────────────────────┤
│ 维度 B 控制权 ControlOwnership（本轮新增 · 任务级长态）★                │
│   agent = Agent 控制状态 │ user = 用户控制状态                        │
│   —— 两态**互斥**，切换是原子替换；蒙层在位 ⇔ 控制权在 Agent           │
├───────────────────────────────────────────────────────────────────────┤
│ 维度 C 人工介入窗口 HITL（已有 · 动作级短态）                          │
│   request_human 期间强制 B=user，收口恢复原态                          │
└───────────────────────────────────────────────────────────────────────┘
```

**为什么 B 必须独立于 A**：headed 窗口人工**看得见**但**不一定能碰**。
把「可见性」和「能不能碰」混成一个开关，就只能二选一 —— 要么全程放任人工乱点
（防交叉操作失效），要么全程锁死（人工想自己登录都不行）。

**为什么 B 必须独立于 C**：HITL 是分钟级的**临时窗口**，控制权是任务级的**长期归属**。
二者耦合会导致「问完一句就还回控制权，人工还没操作完就被抢走」。

## 四、控制权状态机

### 4.1 状态定义

| 状态 | 蒙层 | 输入闸 | 人工可操作页面 | Agent 可写页面 |
| ---- | ---- | ------ | -------------- | -------------- |
| `agent` **Agent 控制状态** | **在位** | **拦截** | ❌ | ✅ |
| `user` **用户控制状态** | 撤除 | 放行 | ✅（Chrome 真能点；Lsm 看帧窗口只能看） | ❌（错误码 `4004`） |

### 4.2 两条铁律

1. **蒙层在位 ⇔ 控制权在 Agent**。`agent` 态必有蒙层（人工点不动），
   `user` 态必无蒙层（人工可自由操作）。这不是约定，是实现里的不变量。
2. **用户控制状态下 Agent 的页面写操作一律拒绝**（`4004`）。
   人机抢同一块页面是最难排查的一类故障，从工具层机械拦住，
   **不给模型「再点一次说不定就成了」的机会**。观测类动作
   （`inspect` / `screenshot` / `wait` / `list`）始终放行。

### 4.3 状态转移

```
open(url)                              → agent（新建页默认；复用页沿用既有状态）
control(set_control_state, state=user) → user（撤蒙层 + 放行输入闸）
control(set_control_state, state=agent)→ agent（挂蒙层 + 拦截输入闸）
control(request_human, ...)            → user（自动移交，收口自动恢复原态）
close(page_id)                         → 清除该页记录（防状态泄漏）
```

### 4.4 唯一真源

`src/agent/web_control.rs` —— 进程内单例注册表
`Mutex<HashMap<(Engine, page_id), ControlRecord>>`：

- 与 `web_activity.rs`（task_local 活动台账）**互不干扰**：活动台账回答
  「谁在干什么」，本注册表回答「页面归谁管」；后者必须**跨任务可见**
  （人工在弹窗里操作时，Agent 进程内任意路径都要读得到）。
- 按 `(引擎, page_id)` 分别记账：两个引擎的 page_id 空间独立
  （Chrome `c_xxxxxxxx`、Lsm `p_xxxxxxxx`）。
- 记录含 `state` / `note`（≤60 字符，给人工看）/ `reason` / `since_ms`。

### 4.5 写操作闸的判定

`web_control::guard_agent_write(engine, page_id, action)`：

- `agent` 态 → 一律放行；
- `user` 态 → **观测类动作**（`screenshot` / `wait` / `inspect` / `heartbeat` / `list`）
  与**控制权动作**（`set_control_state` / `set_guard` / `set_overlay`）放行，
  其余全部拒绝并回 `4004` + 可执行提示
  （「先用 `set_control_state` 取回控制权」）。
- **`eval_js` 归为写操作**：它能在页面上下文里改页面，人机同时在场时
  与「人工点了一下」等价，必须一并拦住；观测请走 `inspect`（两工具的
  `inspect` 覆盖 url/title/text/html/elements/screenshot 等维度，足够）。

拒绝信封示例：

```json
{"code": 4004,
 "message": "控制权当前在用户手上,Agent 不能改变页面(可先取回控制权)",
 "data": {"control_state": "user", "action": "click", "page_id": "c_00000001",
          "engine": "chrome", "note": "人工介入中(captcha);完成后由 Agent 取回控制权",
          "hint": "当前是用户控制状态…先用 control(control_action=set_control_state, params={\"state\":\"agent\"}) 取回控制权…"}}
```

## 五、蒙层实现（两引擎各一套）

### 5.1 Chrome：`src/agent/chrome_browser/control_mask.rs`

两层结构：

| 层 | 机制 | 为什么 |
| -- | ---- | ------ |
| **L1 视觉蒙层** | JS 注入全屏 `rgba(15,23,42,0.30)` 遮罩 + 顶部/底部蓝色边条，`pointer-events:none` | **不参与 hit-test** → 页面脚本枚举不到、Agent 的 JS 点击（`el.click()`）不受影响 |
| **L2 输入闸** | CDP `Input.setIgnoreInputEvents(ignore=true)` | 浏览器级丢弃该 target 的全部真实用户输入；target 级全 frame 一致、跨导航持久 |

**为什么不用 `pointer-events:auto` 的整页 DOM 蒙层拦输入**（归档实测结论，
`reference实现归档/src/agent/browser_overlay.rs:39-43`）：CDP 合成输入与真实输入在
hit-test 层不可区分（`isTrusted` 均为 true），整页 DOM 蒙层会把 Agent 自己的点击
一并吃掉；且「挂起标志」跨域 iframe 读不到。

**为什么 L2 会拦到 Agent 自己**：`Input.setIgnoreInputEvents` 是浏览器输入管线的
一刀切，**实测同时拦截 CDP 合成输入**（`Input.dispatch*`）。因此 Agent 自己的
输入类动作必须**「先解后锁」**：

| 动作 | 通道 | 是否需解锁 |
| ---- | ---- | ---------- |
| `click`（默认）/ `eval_js` | JS `el.click()` / 脚本 | **否**（不进输入管线） |
| `click_real` / `hover` / `double_click` / `right_click` | CDP `Input.dispatchMouseEvent` | **是** |
| `key_press` / `type`+submit | CDP `Input.dispatchKeyEvent` | **是** |
| `scroll` | CDP 输入 | **是** |

解锁窗口是毫秒级（`with_control_gate` 包裹动作派发，动作结束立即复锁）。
JS 通道的动作**不开窗**，避免无谓地放宽输入闸。

**输入闸只在 headed 模式生效**：hidden（无头/管道/CI）没有人工在看页面，蒙层没有
意义；更要紧的是 `Input.setIgnoreInputEvents` 会把 **Agent 自己的 CDP 合成输入**
一起拦下 —— 无头模式下没有人工需要保护，却把 Agent 自己锁死，任务全废。
因此 `apply_state` 与「先解后锁」包裹都先判 headed。

**蒙层的其它约束**（沿用 `status.rs` 的实测教训）：

- 顶层 frame 门（`window.top === window`）—— 跨域挑战 iframe 内不渲染，
  否则会把滑块控件罩死；
- closed Shadow DOM —— 品牌文本留在 light DOM 会被页面 `innerText` 采集
  （实测京东风控据此判自动化）；
- `data-<随机ns>agent="1"` —— `inspect(elements/dom)` 提取时过滤掉；
- `addScriptToEvaluateOnNewDocument` 挂载 —— 导航后自动重挂；
- `MutationObserver` DOM 自愈 —— SPA 整树替换冲掉 host 时重建；
- **文案不放蒙层里** —— 档位文案归状态栏（归档第 171 轮「告知性 UI 外迁」）。

### 5.2 Lsm：`src/agent/browser/page_bars.rs`（帧合成层）

进程内内核**不走页面注入**（注入 DOM 会触发 MutationObserver、污染页面脚本可见
状态、进截图证据），因此蒙层画在**查看器帧合成层**，与两条告知栏同层：

- `agent` 态 → 整页半透明遮罩（`rgba(15,23,42,0.30)`）+ 顶部/底部蓝色边条
  + 居中提示胶囊「Agent 控制中 · 人工请勿操作页面」；
- `user` 态 → 不画。

**取证截图永远干净**：`screenshot_locked` 路径不经过帧合成层，
蒙层与两条告知栏都不会进证据图（与告知栏同款保证）。

Lsm 侧**没有真实人工输入**（查看器是被动帧显示窗），所以蒙层是**视觉声明**；
真正的闸门在工具层（第 4.2 节铁律 2），两引擎语义一致。

### 5.3 状态栏同步

两条告知栏的状态栏第②行**如实反映控制权状态**：

| 引擎 | `agent` 态 | `user` 态 |
| ---- | ---------- | --------- |
| Chrome | 🔒 Agent 控制中 · 人工请勿操作页面 | 🔓 用户控制中 · 人工可直接操作 |
| Lsm | Agent 控制中 · 蒙层在位,人工请勿操作页面 | 用户控制中 · 控制权已交还人工 |

## 六、视口与窗口自适应

### 6.1 Lsm 查看器（本轮最大改造）

**问题**：查看器窗口可拖动，但内容**不跟随** —— macOS 的 `NSImageView` 保持初始
frame（图片缩在左上角，其余留白）；Windows 的 `StretchDIBits` 把 1280×720 的 DIB
**拉伸变形**；且**宿主完全不知道窗口真尺寸**（帧协议里没有尺寸回传）。

**方案**：新增**查看器 → 宿主**的尺寸回传命令，复用既有的 stdout 行 JSON 通道：

```json
{"cmd":"resize","w":1920,"h":1042}
```

- `w` = 窗口内容区宽；`h` = 内容区高 **减去工具栏高度**（即真实视口高）；
- 同时接受 `"width"`/`"height"` 别名；两者缺一不可；范围 `1..=7680` / `1..=4320`；
  非法值整行忽略（不 panic）。

| 侧 | 实现 |
| -- | ---- |
| **macOS** | 100ms `NSTimer` tick 里读 `[[window contentView] frame]` 的 size，与基线比对；变了则重排 `NSImageView`（`ns_rect(0,0,cw,ch-TOOLBAR_H)`）+ 4 个按钮 + 地址栏，再上报 |
| **Windows** | `WM_SIZE` → `GetClientRect` → `MoveWindow` 重排工具栏子控件 → 上报；`WM_PAINT` 由 `StretchDIBits` 拉伸改为 **1:1 绘制**（不拉伸、不变形） |
| **宿主** | `ViewCommand::Resize` → 取前台页 → 视口 clamp 到 `320..7680`/`240..4320` → `relayout_tab`（与 `set_viewport` 同路径）→ `push_frame` 推新尺寸 PNG → 查看器 1:1 铺满 |

> **铁律例外说明**：`human_ui` 有「永不回读窗口 frame」的布局铁律（针对 HITL 弹窗
> 自身的重排）。本处读回内容区尺寸是「让内容跟着窗口走」的**必需**输入，
> 已在 `view/macos.rs::content_size` 的注释里写明理由。

**默认视口**：`1280×720` → **`1920×1080`**（1080p 缺省）。

**小屏夹紧（headed）**：查看器窗口按视口开（内容区 = 视口 + 工具栏），
屏幕比 1080p 小的时候窗口会超出屏幕 → 底部区域人工根本看不到。
因此 **headed 模式**把视口按主显示器可用区夹紧（`browser/screen.rs::fit_viewport_to_screen`，
留白 48px、先扣工具栏 38px）；**hidden 模式不夹**（没有窗口，逻辑视口与物理屏无关，
夹了反而影响站点布局）。

**屏幕探测取「逻辑点」而非物理像素**（`src/agent/display_size.rs`）：
macOS Retina 主屏物理像素是逻辑的 2 倍（3200×1800 逻辑 / 6400×3600 物理），
而窗口/视口尺寸全是 DIP —— 拿物理像素去比会判成「屏幕够大」，夹紧直接失效。
macOS 用 `CGDisplayBounds`（逻辑点），Windows 用 `GetSystemMetrics`。

### 6.2 Chrome 窗口

- **初始尺寸**：`--window-size` 1920×1080，**按主显示器可用区域夹紧**
  （`window_fit::fit_to_screen`，留白 48px）—— 屏幕比 1080p 小的时候窗口不再溢出
  屏幕（这正是「缺区域」的来源）。
  屏幕探测：macOS `CGMainDisplayID` + `CGDisplayPixelsWide/High`；
  Windows `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)`；探测不到则不夹紧（宁大不缺）。
- **定位**：headed 模式开页后经 CDP `Browser.getWindowForTarget` +
  `Browser.setWindowBounds` 把窗口摆到屏幕左上并按夹紧后的尺寸摆好。
- **拖动后自适应**：headed 模式**不下发** `Emulation.setDeviceMetricsOverride`
  （第 161 轮已改），页面视口 = 窗口内容区，**Chrome 原生重新布局**，天然铺满、
  不变形、不缺区域。
- **hidden 模式**：`Emulation.setDeviceMetricsOverride` 1920×1080（沿用）。

## 七、标签页治理

| 手段 | Chrome | Lsm |
| ---- | ------ | --- |
| 复用 | `open` 同 URL **自动复用无主页面**（`adopt_orphan`）；换 URL 用 `control(navigate)` | `open(reuse=true)` 同 URL/同站复用（`browser_reused`）；换 URL 用 `control(navigate)` |
| 感知 | `list` 返回**注册表页 + 真实 Chrome 标签页**（CDP `Target.getTargets`）——人工自己开的、`window.open` 派生的页一并列出（`external_tabs`，标 `managed:false`） | `list` 返回全部页签 + 各自 `control_state` |
| 关闭 | `close(page_id=具体 id)` —— **真关掉 Chrome 标签页**（CDP `Target.closeTarget`），不再只删注册表条目 | `control(close_tab)` / `close(page_id)` |
| 提示 | 页数 ≥4 时回 `tabs_hint`；有外部页签时回 `tabs_hint` | 页数 ≥6 时回 `tabs_hint` |
| 危险操作 | `close(all)` 连带回收整个 Chrome 进程；并行单元有兄弟页时**被拒绝**（所有权守门，第 181 轮） | `close(all)` |

## 八、工具契约

### 8.1 新增 `control_action=set_control_state`

两工具一致：

```
control(page_id?, control_action="set_control_state",
        params={ state: "agent" | "user", note?: "≤60 字符" })
```

响应：

```json
{"code":0,"message":"ok","data":{
  "page_id":"c_00000001","control_action":"set_control_state",
  "control_state":"user","control_state_label":"用户控制状态",
  "result":{"control_state":"user","mask_active":false,
            "hint":"已交还控制权:蒙层撤除,人工可自由操作页面;Agent 的页面写操作会被拒绝(4004),直到再次 set_control_state=agent"}}}
```

- `page_id` 可省略（只有一个存活页时自动选中，信封回 `page_id_auto=true`）。
- `state` 非法 → `1001` + `allowed` 清单。
- 接受中文别名（`用户`/`人工` → `user`，`代理`/`智能体` → `agent`）。

### 8.2 `request_human` 的自动移交

两工具一致：提问**前**自动切 `user`（撤蒙层、放行输入闸），收口
（应答 / 超时 / 取消 / 弹窗不可用）**自动恢复提问前的状态**。
响应回写真值 `data.control_state`。

> 顺带修掉一处历史不一致：Lsm 侧的 `request_human` 此前**不走共享实现**，
> 自由文本 reason（如「京东要求登录后才能访问」）不归一 → 判非法返 `1001`；
> 现统一走 `human_assist::normalize_reason`。

## 十二、边界（如实记录）

1. **Chrome 的浏览器 chrome 不拦**：地址栏/标签栏/窗口拖动人工始终可用 ——
   DOM 蒙层只覆盖页面内容区。人工在 Agent 控制状态下仍能改地址栏导航走页面。
   要连 chrome 一起拦需要 `Input.setIgnoreInputEvents` 之外的窗口级手段，
   本轮不做（会连「看现场」都断掉）。
2. **Agent 控制状态下人工不能滚动**：`Input.setIgnoreInputEvents` 是页面级一刀切，
   滚轮一起拦。归档第 155 轮曾为此改用 DOM 选择性输入闸（放行滚轮），
   但那套需要跨 frame 传递「挂起标志」，跨域 iframe 读不到 ——
   本轮选了确定性更高的 CDP 闸。需要人工自由浏览时切 `user` 态即可。
3. **Lsm 侧人工无法真正操作页面**：查看器是被动帧显示窗，`user` 态只是
   「控制权语义 + 视觉」层面的人工接管；Lsm 内核没有真实输入通道，
   人工的实际动作仍要靠 `request_human` 弹窗传达。
4. **控制权是任务级、不是跨任务持久**：进程重启后回到默认 `agent` 态。
5. **`LAEW_WEB_CONTROL=off` 是逃生阀**：关掉后人工可直接操作 Chrome 窗口，
   Agent 写操作也不再被拦（回到改造前行为）。
6. **只按主显示器夹紧**：多屏场景下窗口可能被放到副屏（副屏更小）而溢出 ——
   `Browser.setWindowBounds` 固定摆到 (0,0)（主屏左上），人工可自行拖到副屏。
7. **Lsm 视口夹紧只在 headed 生效**：headless/CI 下逻辑视口恒为 1920×1080，
   与物理屏无关（这是刻意的：夹紧会改变站点布局，headless 无窗口可夹）。
