# 新工具 Edit / Glob / Grep 与沙箱 Hook 设计

## 1. 背景与目标

### 1.1 现状
当前 `laew` Agent 拥有三个内置工具：
- `Read` — 读取文件
- `Write` — 覆盖写入文件
- `Bash` — 执行 shell 命令

缺乏高效的**代码导航**与**精准编辑**能力，导致 Agent 在处理中型以上代码库时效率低下（需通过 Bash 调用 grep/glob，精度差、上下文浪费严重）。

### 1.2 目标
新增 3 个工具 + 1 个沙箱拦截层：

| 工具/模块 | 作用 | 类比 |
|-----------|------|------|
| `Edit` | 精准字符串替换(必须提前 Read 过) | Claude Code 的 Edit |
| `Glob` | 快速文件模式匹配（跨大规模代码库） | Claude Code / opencode 的 Glob |
| `Grep` | 快速内容搜索（正则 + ripgrep 风格） | Claude Code 的 Grep |
| `sandbox-hook` | 写操作沙箱拦截（工作目录 + 系统临时目录） | Claude Code 的 sandbox |

## 2. 工具设计

### 2.1 Edit 工具

**功能**：在文件中执行精准字符串替换。

**参数**：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | ✅ | 待修改文件路径（绝对或相对工作目录） |
| `old_string` | string | ✅ | 需要被替换的原文（必须与文件内容完全一致，含缩进） |
| `new_string` | string | ✅ | 用于替换的新文本（必须与原文不同） |
| `replace_all` | boolean | ❌ | 是否替换所有匹配项，默认 `false` |

**行为约束**：
- `old_string` 在文件中必须**唯一匹配**（除非 `replace_all=true`），避免误改
- 编辑前**建议**先 Read 该文件（不强制，但提示词要说明）
- 受 `sandbox-hook` 拦截：目标路径必须在工作目录或系统临时目录下

**错误情况**：
- 文件不存在 → 报错
- `old_string` 未找到 → 报错（明确提示"未找到匹配内容，请先 Read 文件"）
- `old_string` 出现多次且 `replace_all=false` → 报错（提示使用 `replace_all` 或缩小 `old_string`）
- `new_string == old_string` → 报错
- 沙箱拦截 → 报错（说明允许的目录）

### 2.2 Glob 工具

**功能**：快速文件模式匹配，返回匹配路径列表。

**参数**：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | ✅ | glob 模式，如 `**/*.rs`、`src/**/*.ts` |
| `path` | string | ❌ | 搜索根目录，默认工作目录 |

**行为约束**：
- 使用 `walkdir` + `globset` 实现纯 Rust 匹配（不依赖系统 find）
- 结果按**修改时间倒序**排列（最新的在前，便于 Agent 优先处理近期文件）
- 默认跳过隐藏文件/目录（以 `.` 开头的）与常见忽略目录（`target/`、`node_modules/`、`.git/`）
- 结果上限默认 200，超出时截断并提示

### 2.3 Grep 工具

**功能**：快速内容搜索（基于 `regex` + `walkdir`）。

**参数**：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | ✅ | 正则表达式 |
| `path` | string | ❌ | 搜索目录/文件，默认工作目录 |
| `glob` | string | ❌ | 过滤文件名模式，如 `*.rs`、`*.{ts,tsx}` |
| `output_mode` | enum | ❌ | `content`/`files_with_matches`/`count`，默认 `files_with_matches` |
| `context` | integer | ❌ | 匹配前后各显示 N 行（类似 `-C`） |
| `before_context` | integer | ❌ | 匹配前 N 行（类似 `-B`） |
| `after_context` | integer | ❌ | 匹配后 N 行（类似 `-A`） |
| `-i` | boolean | ❌ | 不区分大小写 |
| `head_limit` | integer | ❌ | 结果上限，默认 200 |
| `multiline` | boolean | ❌ | 多行模式（跨行匹配），默认 false |

**行为约束**：
- 二进制文件自动跳过（检测 null 字节）
- 大文件（>1MB）按行流式读取，避免爆内存
- 忽略 `.git/`、`target/`、`node_modules/` 目录
- 结果格式：`path:line_num:content`（content 模式）

## 3. 沙箱 Hook 设计

### 3.1 目标
限制 `Write` 和 `Edit` 工具的写入范围，防止 Agent 误改系统关键文件：
- ✅ 允许：**工作目录**（启动 `laew` 时所在目录，递归子目录）
- ✅ 允许：**系统临时目录**（`/tmp`、`%TEMP%`、`env::temp_dir()`）
- ❌ 拒绝：其他任意绝对路径（如 `/etc/passwd`、`/usr/bin/...`、家目录等）

### 3.2 架构

```
┌─────────────────────────────────────────────┐
│  Agent::run_session                          │
│  ┌─────────────────────────────────────────┐ │
│  │ tool.execute(args)                      │ │
│  │   ↓                                     │ │
│  │ [sandbox_hook::check_write_path()]      │ │
│  │   ├─ 解析路径 → 绝对路径                │ │
│  │   ├─ 白名单比对                         │ │
│  │   │   ├─ work_dir 前缀 → ✅             │ │
│  │   │   ├─ temp_dir 前缀 → ✅             │ │
│  │   │   └─ 其他 → ❌ 返回拦截错误         │ │
│  │   └─ 通过 → 继续原工具逻辑             │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

### 3.3 模块结构

```
src/agent/sandbox-hook/
├── mod.rs          # SandboxHook 主体 + check_write_path 入口
├── paths.rs        # 路径规范化与白名单匹配
└── tests.rs        # 单元测试
```

### 3.4 核心接口

```rust
/// 沙箱配置
pub struct SandboxConfig {
    pub work_dir: PathBuf,    // 工作目录（必传）
    pub temp_dir: PathBuf,    // 系统临时目录（默认 env::temp_dir()）
}

/// 检查工具是否允许在指定路径写入
pub fn check_write_path(
    cfg: &SandboxConfig,
    tool_name: &str,
    target_path: &str,
) -> Result<()>;
```

### 3.5 错误反馈

拦截时返回结构化错误，让 Agent 理解原因并调整：
```
[沙箱拦截] 工具 {tool} 无法写入路径 "{path}"。
允许范围：
  - 工作目录: {work_dir}
  - 系统临时目录: {temp_dir}
请调整目标路径或联系管理员修改沙箱配置。
```

## 4. 工具注册表规划

| Agent 角色 | 工具集 | 说明 |
|-----------|--------|------|
| Yolo | Read | 不变（只读理解） |
| Plan | Read, Write, Edit, Glob, Grep | 规划时可调研代码 |
| Main-Work | Bash, Read, Glob, Grep | 流程层可检索，不可写文件 |
| SubAgent-Work | Bash, Read, Write, Edit, Glob, Grep | 执行层全套工具 |
| Quality-Check | Read, Glob, Grep | 质检时可检索与读取 |
| SessionContext | (无) | 不变 |

> 注：`Write` 和 `Edit` 仅在 Plan 与 SubAgent-Work 中启用，因为它们会修改文件。

## 5. 工具提示词优化

为减少 Agent 误调用，每个工具描述中包含：
- **使用场景**（何时用）
- **限制**（何时不该用 / 大小限制）
- **沙箱提醒**（Write/Edit 中说明只能在工作目录 / 临时目录操作）

系统提示词追加沙箱说明块：
```
[沙箱规则]
Write 与 Edit 工具仅可在以下目录写入：
  - 当前工作目录: {work_dir}
  - 系统临时目录: {temp_dir}
尝试写入其他路径将被拒绝。请在规划阶段就使用合规路径。
```

## 6. 技术选型

| 需求 | 方案 | 理由 |
|------|------|------|
| glob 匹配 | `walkdir` + `globset` | 纯 Rust、无系统依赖、支持 `**` |
| 内容搜索 | `regex` + `walkdir` | regex 是行业标准；walkdir 内存友好 |
| 路径规范化 | `std::fs::canonicalize` + `dunce` | 跨平台；dunce 处理 Windows 长路径 |
| 二进制检测 | 前 8KB 检测 `\0` 字节 | 快速、低误判 |

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| Grep 大文件耗时 | Agent 超时 | 流式读取 + 单文件 >1MB 时截断 + 设置超时 |
| glob 跨度过大 | 返回过多结果 | 默认 limit=200，提示 Agent 缩小 pattern |
| 沙箱路径解析不一致 | 绕过或误拦截 | 使用 canonicalize 解析后再匹配前缀 |
| Edit 误改多处 | 代码被破坏 | 强制 old_string 唯一性；replace_all 需显式开启 |
