# 数据库代码重构与 Provider 导入/导出命令设计

## 1. 背景与目标

### 1.1 现状
- 数据库相关代码全部位于 `src/config/mod.rs`，包含 `Paths`、`Protocol`、`ProviderRecord`、`Db` 等核心结构
- Provider 的增删改查逻辑直接实现在 `Db` 结构体方法中
- CLI 命令在 `src/main.rs` 中通过 `Cmd::Provider(ProviderCmd)` 子命令管理

### 1.2 目标
1. **数据库代码重构**：将数据库相关代码从 `src/config` 迁移到 `src/database` 模块
2. **新增导入命令**：`laew -inprovider <文件路径>` 从 JSON 配置文件批量导入 Provider
3. **新增导出命令**：`laew -outprovider <文件路径>` 将数据库中所有 Provider 导出为 JSON 配置文件

## 2. 数据库代码重构设计

### 2.1 模块拆分

```
src/database/
├── mod.rs              # 模块入口，重导出核心类型
├── schema.rs           # 数据库 Schema 初始化
├── provider.rs         # Provider 表的 CRUD 操作
├── paths.rs            # 路径解析（从 config 迁移）
└── models.rs           # 数据模型（Protocol, ProviderRecord 等）
```

### 2.2 迁移内容对照

| 原位置 (`src/config/mod.rs`) | 新位置 (`src/database/`) |
|------------------------------|--------------------------|
| `Paths` 结构体 | `paths.rs` |
| `Protocol` 枚举 | `models.rs` |
| `ProviderRecord` 结构体 | `models.rs` |
| `Db` 结构体 | `mod.rs` |
| `ConfigError` 枚举 | `mod.rs` |
| `init_schema()` | `schema.rs` |
| Provider CRUD 方法 | `provider.rs` |

### 2.3 兼容性处理
- `src/config/mod.rs` 保留为薄封装，重导出 `database` 模块的公共类型
- 现有代码中的 `use lsm_agent::config::{Db, Paths, Protocol}` 无需修改
- `agent_memory.rs` 和 `session_memory.rs` 保留在 `config` 模块中（它们与 Provider 无关）

## 3. Provider 导入/导出命令设计

### 3.1 命令格式

```bash
# 导入
laew -inprovider ./providers.json
laew -inprovider /absolute/path/to/providers.json

# 导出
laew -outprovider ./backup.json
laew -outprovider /absolute/path/to/backup.json
```

### 3.2 JSON 配置文件格式

#### 3.2.1 单条记录格式
```json
{
  "protocol": "anthropic",
  "provider_name": "Anthropic官方",
  "model_name": "claude-3-5-sonnet-20241022",
  "end_point": "https://api.anthropic.com",
  "api_key": "sk-ant-xxxxx"
}
```

#### 3.2.2 批量导入格式（数组）
```json
[
  {
    "protocol": "anthropic",
    "provider_name": "Anthropic官方",
    "model_name": "claude-3-5-sonnet-20241022",
    "end_point": "https://api.anthropic.com",
    "api_key": "sk-ant-xxxxx"
  },
  {
    "protocol": "openai",
    "provider_name": "OpenAI官方",
    "model_name": "gpt-4o",
    "end_point": "https://api.openai.com/v1",
    "api_key": "sk-xxxxx"
  }
]
```

#### 3.2.3 导出格式（带元数据）
```json
{
  "version": "1.0",
  "exported_at": "2026-09-08T12:00:00+08:00",
  "count": 2,
  "providers": [
    {
      "id": 1,
      "protocol": "anthropic",
      "provider_name": "Anthropic官方",
      "model_name": "claude-3-5-sonnet-20241022",
      "end_point": "https://api.anthropic.com",
      "api_key": "sk-ant-xxxxx",
      "is_active": true,
      "created_at": "2026-09-08 10:00:00"
    }
  ]
}
```

### 3.3 导入去重策略

#### 3.3.1 去重键
使用数据库 UNIQUE 约束：`(protocol, provider_name, model_name, end_point)`

#### 3.3.2 去重行为
- **遇到重复时**：跳过该记录，输出警告信息，继续处理其他记录
- **导入结果统计**：输出成功数、跳过数、失败数

#### 3.3.3 实现方式
使用 `INSERT OR IGNORE` 或先查询后插入，确保幂等性。

### 3.4 路径处理
- 绝对路径：直接使用
- 相对路径：基于**工作目录**（`std::env::current_dir()`）解析
- 导入：读取文件路径
- 导出：写入文件路径（父目录不存在时自动创建）

## 4. 错误处理

### 4.1 导入错误
| 错误场景 | 处理方式 |
|---------|---------|
| 文件不存在 | 报错并退出 |
| JSON 格式错误 | 报错并退出 |
| 缺少必填字段 | 报错并退出 |
| protocol 无效 | 报错并退出 |
| 记录重复 | 跳过并警告 |
| 数据库写入失败 | 报错并退出 |

### 4.2 导出错误
| 错误场景 | 处理方式 |
|---------|---------|
| 数据库读取失败 | 报错并退出 |
| 父目录不存在 | 自动创建 |
| 文件写入失败 | 报错并退出 |

## 6. 数据模型定义

### 6.1 导入用结构体
```rust
#[derive(Debug, Deserialize)]
pub struct ProviderImport {
    pub protocol: String,
    pub provider_name: String,
    pub model_name: String,
    pub end_point: String,
    pub api_key: String,
}

#[derive(Debug, Deserialize)]
#[serde(untagged)]
pub enum ImportInput {
    Single(ProviderImport),
    Batch(Vec<ProviderImport>),
}
```

### 6.2 导出用结构体
```rust
#[derive(Debug, Serialize)]
pub struct ExportRecord {
    pub id: i64,
    pub protocol: String,
    pub provider_name: String,
    pub model_name: String,
    pub end_point: String,
    pub api_key: String,
    pub is_active: bool,
    pub created_at: String,
}

#[derive(Debug, Serialize)]
pub struct ExportData {
    pub version: String,
    pub exported_at: String,
    pub count: usize,
    pub providers: Vec<ExportRecord>,
}
```

## 7. 安全考虑

1. **API Key 明文存储**：导入/导出文件中 API Key 以明文存储，用户需注意文件安全
2. **文件权限**：导出文件建议设置合适的文件权限（由用户自行控制）
3. **路径遍历**：导入/导出路径基于工作目录解析，避免路径遍历攻击
