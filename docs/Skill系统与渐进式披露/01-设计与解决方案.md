> **轮次**:2026-09-23 第 126 轮
> **状态**:✅ P0 已落地(单测 38 项 + e2e 225 全过)
> **对应知识库 gap**:L1051-L1065 段(第十六轮登记的「权限/工具/压缩/记忆/MCP/Skill」15 gap 中的 Skill 部分)

## 1. 问题与目标

### 1.1 现状问题

本轮之前,laew 的 SubAgent-Work / Main-Work 工具面**零 Skill 系统**(对照表登记 L1051-L1065 ⏳ 未实现)。每次 LLM 调用 system prompt 都是**同一份固定工具说明**(`sub_agent_tools_hint()` / `main_work_tools_hint()`),导致三类问题:

1. **上下文膨胀**:每次 LLM 调用都重复「Bash/Read/Write/MCP_Web_Use/SubAgent…可用工具清单」,即便任务只是「看一下 README」也带 600+ 字符的工具面提示。
2. **能力即代码**:用户想加「PDF 转 Markdown」「arXiv 检索」「PR Review 模板」这类领域知识/流程模板,只能改 Rust 重编译。
3. **没有「目录」概念**:LLM 看不到「哪些是可重用的指令集」、看不到「应该先用哪个 skill」,只能盲目调工具。

### 1.2 目标:渐进式披露 = Skill 分层加载

**渐进式披露(Progressive Disclosure)的语义**(用户需求原文):

> 启动仅预加载技能元信息(名称、简短描述),让模型判断是否启用该技能,不灌入完整内容。任务需要时,再读取技能主体规则;复杂场景按需加载引用资料。避免一次性塞满上下文,降低 token 开销、提升缓存命中率。Agent 循环按需探查,增量读取代码与文档,平衡上下文窗口限制与信息完备度,减少冗余,提升长代码库任务稳定性。

**业界共识**(六工程共同底层哲学):claudecode / atomcode / pi / opencode / deepseek-harness / openclaw 都用同一模式——

```
catalog(名字 + 短描述,800B~8KB)  →  始终在 system prompt
   ↓ LLM 决策「描述匹配」
skill tool / use_skill / read  →  加载完整 body(5-50KB)
   ↓ 跟随 body 内的 SOP
shell / bash / scripts/  →  执行具体步骤
```

**本轮落地 laew 自己的 Skill 一等公民(MiniPoC)**,对齐 atomcode + pi + openclaw 三家最佳实践。

### 1.3 P0 范围

1. **数据模型 + 全字段 frontmatter**(含嵌套 metadata)
2. **3 源发现链**(`{cwd}/.laew/skills` + `{cwd}/.agents/skills` + `~/.laew/skills` + bundled)
3. **`render_catalog` 8KB 字节预算**(对齐 atomcode `CATALOG_BYTE_BUDGET=8000`)
4. **`UseSkill` + `ListSkills` 两个 Tool**(挂 SubAgent-Work + Main-Work)
5. **catalog 注入 system prompt**(`sub_agent_work()` / `main_work()` 末尾,挂 rules 段 cache 复用)
6. **TUI `/skill` `/skills` builtin slash 命令**
7. **3 个内置 skill**(`git-commit` / `code-review` / `test-runner`)证明可用
8. **`$ARGUMENTS` / `$1..$9` / `${CLAUDE_SKILL_DIR}` / `!`cmd`` 变量替换**
9. **单元测试 ≥ 25 项**(实际 38 项)
10. **e2e 不回归**(实际 PASS=225 FAIL=0)

**显式不做**(留后续轮次,避免 scope creep):
- skill-creator / Workshop 自演化 / ClawHub 远程分发 / atomic 版本切换 / 描述优化循环
- conditional paths(Read/Write/Edit 时按 frontmatter paths 模式激活)
- dynamic discovery(运行时按 file path 向上扫描)
- chokidar 热重载
- Skill 评测集 + Grader + Analyst
- 安全扫描器(L1208 Prompt 注入防护已覆盖 SKILL.md 文本输入)

### 3.2 Skill 数据模型

**frontmatter 全字段**(用户决策:全部字段含嵌套 metadata):

```rust
pub struct SkillFrontmatter {
    pub name: Option<String>,
    pub description: String,         // 必填(可由 fallback_description 兜底)
    pub version: Option<String>,
    pub license: Option<String>,
    pub compatibility: Option<String>,
    pub allowed_tools: Vec<String>,
    pub user_invocable: bool,        // 默认 true
    pub source: Option<String>,      // 跨引擎标识
    pub metadata: SkillMetadata,     // 嵌套 metadata
}

pub struct SkillMetadata {
    pub flat: HashMap<String, String>,                            // emoji / homepage / os
    pub nested: HashMap<String, HashMap<String, String>>,          // requires.bins / install.kind
    pub lists: HashMap<String, Vec<String>>,                       // tags / categories
}
```

**解析策略**:
1. 先用 `crate::frontmatter::parse` 取顶层 `key: value` 平面 map(与 D2 命令 / D11 自定义子 Agent **共用同一模块**,第 115 轮已抽公共)
2. 顶层白名单直接落入 `SkillFrontmatter`
3. 嵌套 `metadata.<key>.<sub>` 走简化二级解析
4. `tags` / `categories` 走单值列表解析(支持 `[a, b, c]` 风格)
5. 其它未知顶层 key 静默忽略

**不做 `serde_yaml` 依赖**(约 200KB),自实现简化 YAML 子集,语义与 `frontmatter.rs` 一致。

### 3.3 变量替换

对齐 atomcode `skill.rs:32-92` 的 `match_substitution`:

| 占位符 | 语义 |
|---|---|
| `$ARGUMENTS` | 全量参数 |
| `$1`..`$9` | 位置参数(`$10` 原样保留,避免 `$1`+`0` 歧义) |
| `${CLAUDE_SKILL_DIR}` | skill 文件目录 |
| `${LAEW_SKILL_DIR}` | 同上(laew 别名) |
| `` !`cmd` `` | shell 注入(信任 Skill 作者,用户授权) |

**atomcode 行为**:body 不含 `$ARGUMENTS` 时若带参数,末尾追加 `ARGUMENTS: <参数>` 块(与 D2 自定义命令 `$ARGUMENTS` 行为对齐)。

**单遍左到右扫描**:替换值不二次展开(避免 `$1` 参数被再次展开成 `$2`)。

**shell 注入失败**:`[shell error: exit ...]` 就地插入,不阻断后续替换(对齐「fail-open, 让 LLM 看到真实失败」)。

### 3.4 Skill 注册表(3 源发现)

```rust
pub struct SkillRegistry {
    skills: BTreeMap<String, Arc<Skill>>,   // BTreeMap → 字节稳定 → prefix cache
    stats: Arc<Mutex<SkillLoadDiagnostics>>, // 加载诊断(ignored + loaded)
}
```

**发现链**(后赢覆盖):

| 序 | 路径 | 来源 |
|---|---|---|
| 1 | `{cwd}/.laew/skills` | Project(随仓库提交,优先级最高) |
| 2 | `{cwd}/.agents/skills` | CrossAgent(对齐 pi/opencode/openclaw) |
| 3 | `~/.laew/skills` | User(个人偏好兜底) |
| 4 | bundled(`include_str!`) | Bundled(编译期嵌入,始终可用) |

**扫描规则**:
- 顶层 `<name>.md` 平铺
- 子目录 `<name>/SKILL.md` 包式(递归深度 ≤ 4)
- 忽略 `.git` / `node_modules` / `__pycache__` / `target` / `.DS_Store`
- 同目录 `.gitignore` 文件名级过滤(简化,完整语义留 P2)

**诊断不静默**(对齐 pi):命名非法/描述超长/文件读取失败 → `SkillLoadDiagnostics.ignored`,由 `/skills` 列出。

### 3.5 Catalog 渲染(8KB 预算)

```rust
pub const CATALOG_BYTE_BUDGET: usize = 8000;
pub const PER_SKILL_DESC_CAP: usize = 1024;
pub const CATALOG_HEADER: &str = "=== AVAILABLE SKILLS ===";
pub const CATALOG_GUIDANCE: &str = "Skills are reusable instruction templates... ...never invent or guess a skill name...";
```

**渲染流程**:
1. BTreeMap 已保字节稳定(调用方不再重排)
2. 头 `=== AVAILABLE SKILLS ===` + GUIDANCE 强约束段(对齐 atomcode `render.rs:35`)
3. 每条 `- {name}: {desc}`,description 截到 1024 字符
4. 整体字节超 8000 → 归入 `... and {N} more skill(s) omitted; call \`list_skills\` for full list.`

**Anthropic prefix cache 复用**:catalog 文本**字节级稳定**(同 registry 同顺序),挂 rules 段(第 3 段,带 cache_control),跨 SubAgent/Main-Work 实例复用最大化。

### 3.6 工具挂载(用户决策范围)

**挂载**:SubAgent-Work + Main-Work + 动态子 Agent 类型
**不挂**:Yolo / Plan / QC / SessionContext / Debug / Compact(入口/规划/质检/会话/调试/压缩层不需要领域 Skill;会污染 catalog,触发不必要的 `use_skill` 调用)

```rust
// 关闭语义(对齐 register_mcp_use 惯例)
pub fn skills_enabled() -> bool {
    !matches!(env::var("LAEW_SKILL_DISABLED")...., Some("on"|"1"|"true"|"yes"))
}

pub fn register_skill_tools(reg, skills, session_id) -> ToolRegistry { ... }
pub fn sub_agent_work_registry_with(skills, session_id) -> ToolRegistry { ... }
pub fn main_work_registry_with(skills, session_id) -> ToolRegistry { ... }
```

**`UseSkillTool`**:
- `name()` = `"use_skill"`
- `parameters()` = `{name, arguments?}`
- `parallel_safe()` = `false`(改了 user context 边界)
- 找不到 skill → `AgentError::ToolExecution` 报「可用列表 + 不要猜名字」
- 变量替换走 `spawn_blocking`(shell 注入 fork 子进程会阻塞)
- 输出信封 `<<<LAEW:SKILL_LOADED ... >>>` 标记,便于日志 grep + 防误当指令执行

**`ListSkillsTool`**:
- `name()` = `"list_skills"`
- `parameters()` = `{}`
- `parallel_safe()` = `true`(只读)
- 返回 `Available skills (N):` + 每条 `- {name}: {desc}  [{source}]`
- 尾部注释:若 `diagnostics().ignored` 非空,提示「ignored N invalid skill(s)」

### 3.7 Profile 装配(builder 模式)

**关键约束**(Explore 反馈):`Agent` profile 是私有字段,无 `with_profile` builder;改 `SystemPrompt::sub_agent_work()` 工厂即可,所有 SubAgent 实例共享同一 catalog 字符串。

新增 profile 工厂:
```rust
pub fn sub_agent_work_profile_with_skills(skills, session_id) -> Self { ... }
pub fn main_work_profile_with_skills(skills, session_id) -> Self { ... }
```

**装配顺序**(两者一致):
1. `SystemPrompt::sub_agent_work()` / `main_work()` 基础 prompt
2. `skill_catalog::append_to(...)` 追加 Skill catalog 段(8KB 预算)
3. `*_registry_with(skills, sid)` 注册 UseSkill/ListSkills 工具
4. `build_self_aware_prompt` 加自感知段(动态子 Agent 等)

**`SubAgentRunner` / `MainWorkRunner` builder**:
```rust
SubAgentRunner::new(llm, db).with_skills(skills, sid).with_max_iterations(n)
MainWorkRunner::new_with_skills(llm, db, Some(skills), Some(sid))
```

`new(llm, db)` 保留零参版(动态子 Agent / 单元测试不感知 SkillRegistry)。

### 3.8 Orchestrator 顶层构造(单例)

**单次目录发现**(`MultiAgentOrchestrator::with_config`):
1. `SkillRegistry::load(paths.root_dir, paths.work_dir)` — 3 源 + bundled
2. `Arc<SkillRegistry>` 共享给 `sub_agent` / `main_work`
3. 提 `skill_registry` / `skill_session_id` 到 `MultiAgentOrchestrator` 字段,TUI 从 `orchestrator.skill_registry()` 拿同一 Arc

跨 runner 零重复扫描,目录发现开销仅 1 次进程生命周期。

### 3.9 TUI 集成

**`/skills`** — 列出全部可见 skill + 加载诊断(ignored 非空时打印警告)
**`/skill <name> [args]`** — 展开 SKILL body 并预览(不直接触发 agent loop,避免误触发)

**Builtin 注册**(`completion.rs` + `commands.rs::BUILTIN_NAMES`):
```rust
SlashCommand::builtin("skills", &[], "列出已加载的 Skill(渐进式披露)", "/skills"),
SlashCommand::builtin("skill", &[], "展开 SKILL body 预览", "/skill <name> [args]"),
```

**`/skill` 预览语义**:对齐 atomcode「Skill 是工具,不是用户手势」——真正让模型按 SKILL 执行由 SubAgent-Work 主动调 `use_skill` 完成;`/skill` 用于用户自己预览 body 内容。

## 4. 关键实现细节

### 4.1 避开 `with_self_awareness` fn pointer 限制

`AgentProfile::with_self_awareness` 要求 `registry: fn() -> ToolRegistry`(无捕获 fn pointer)。Skill profile 必须捕获外部 `Arc<SkillRegistry>` 本地变量,无法通过 fn pointer 表达。

**解法**:`sub_agent_work_profile_with_skills` / `main_work_profile_with_skills` **直接装配** AgentProfile,不走 `with_self_awareness`(自感知段由 `build_self_aware_prompt` 手动调用)。

### 4.2 `register_skill_tools` 开关模式

```rust
// 关闭语义:LAEW_SKILL_DISABLED=on|1|true|yes → 不注册
pub fn skills_enabled() -> bool { ... }
```

对齐 `register_mcp_use` / `register_subagent` 既有惯例,严格向后兼容(不挂开关时默认开启)。

### 4.3 Shell 注入信任边界

`!`cmd`` 信任用户写入的 SKILL.md(对齐 atomcode「Skills are TRUSTED, user-authored content」注释)。**前提**:
- Skill 文件来源可信(user/project/cross-agent 都是用户自己放的)
- Prompt 注入防护 L1208(14 种正则模式)对 SKILL.md 文本输入已覆盖

本轮不做 skill 独立 scanner(留 P1)。

### 4.4 `Agent::llm()` 暴露 builder 装配

`SubAgentRunner::with_skills` 重建 Agent 时需要复用原 llm:
```rust
self.agent = Agent::new(self.agent.llm(), profile);
```
`Agent::llm()` 已是 pub(crate)(161 行),直接用。

## 9. 关键决策与理由

| 决策 | 理由 |
|---|---|
| BTreeMap 而非 HashMap | 字节级稳定 → Anthropic prefix cache 跨实例复用最大化 |
| 8KB 字节预算 | 对齐 atomcode `CATALOG_BYTE_BUDGET`,防信号稀释(catalog 过大反而干扰模型) |
| 3 源发现(而非 6 源) | 对齐 pi 简化版,项目级 > 跨 agent > 用户级,覆盖真实场景;不做 managed / dynamic / additional paths |
| 不挂 serde_yaml(200KB 依赖) | 自实现简化 YAML 子集,与 `frontmatter.rs` 语义一致,零新增依赖 |
| `use_skill` + `list_skills` 两工具 | 对齐 atomcode `use_skill.rs` 最简可用;`list_skills` 解决 8KB omitted 后模型看不到全貌 |
| 挂 SubAgent-Work + Main-Work(用户决策) | 执行层 + 编排层都需要 Skill 领域知识;入口/规划/质检/会话/调试/压缩层不需要 |
| `with_skills` builder 而非改 `new` 签名 | 零侵入,动态子 Agent / 单元测试不受影响 |
| SkillRegistry 单例 | 顶层构造一次,跨 runner 共享,目录发现零重复 |
| `/skill` 预览而非直接触发 loop | 避免误触发;真正加载由 SubAgent 主动调 `use_skill`(对齐「Skill 是工具不是手势」) |
| 无占位符追加 ARGUMENTS | 对齐 atomcode 行为,与 D2 自定义命令行为一致 |
| 不挂 `LAEW_SKILL_DISABLED` 关闭时不注入 catalog | 与工具注册同步归零,严格向后兼容(对齐 MCP_Use 开关模式) |
