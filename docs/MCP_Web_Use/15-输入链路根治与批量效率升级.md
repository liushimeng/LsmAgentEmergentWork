# 15 · 输入链路根治与批量效率升级（第 157 轮）

唯一最新版。根因全部来自 2026-10-12 文心一言实测（`laew --debug`，79 分钟未收口）
的 7.5MB DEBUG 日志实锤，方案全文见
`tmpPlan/2026-10-12_MCP_Web_Use输入链路根治与批量效率升级方案.md`。

## 事故复盘（四个根因）

1. **input_text 全链路 `TypeError: Illegal invocation`**（日志 29 处）：旧 JS
   「`HTMLInputElement.prototype` 短路 `|| textarea`」恒真短路 —— 对 textarea
   （文心 `#chat-textarea` 正是 textarea）永远拿到 input 的 `value` setter，
   品牌校验抛 Illegal invocation。`clear_input` 同款。连锁反应：
   LLM 抄同款写法到 eval_js → 也炸；LLM 漏传 `use_js`（默认 `true` 是坑默认值）
   → 以为在用 CDP 实际又走 JS → 又炸；QC 两次打回。
2. **LLM 错误归因 → 自行开 guard**：输入全挂后 LLM 误判「页面 locked 拦截了
   输入」→ `set_guard(open)`（12:36:30 日志实锤）→ 用户看到「屏蔽失效、可编辑、
   无提示」。wf-4 三烧 953 秒投放轮次为 0。
3. **press_sequence 静默空打**：旧实现忽略 `selector`（LLM 传了
   `#chat-textarea`），按键打进失焦页面，回显 `ok` 但输入框为空；
   整句中文 token 落入 Char 分支触发 CDP `Invalid 'text' parameter` 黑话。
   `key_press key="enter"`（小写）同理：不在白名单 → Char 分支 5 字符非法。
4. **sequence/batch 整批全灭**：顶层传了 `page_id`、steps 内逐步漏传 →
   每步 `1001 缺少 page_id`；loop 只替换字符串占位符、从不注入 `step.page_id`。

## 方案

### A. 输入链路根治（`input_ctl.rs`，control.rs 拆分 + 重写）

- **A1 原生赋值通用化**：沿元素自身原型链 `getOwnPropertyDescriptor(p,'value')`
  逐级查找访问器（`el` → `getPrototypeOf` 链），命中 accessor 用 `d.set.call(el,v)`，
  data descriptor / 未命中回退 `el.value=v`；contenteditable 走 `textContent`。
  input/textarea/select/contenteditable 全覆盖，与页面自定义类无关。
- **A2 input_text 自动阶梯**：`use_js` 缺省 = `auto`：① JS 原生赋值 →
  **页内回读校验**（比对 `el.value`/`innerText`，只回 len/match/head100）→
  未生效降级 ② CDP sendkeys（click 聚焦 + type_str）→ 回读 → 未生效降级
  ③ human_input 慢速逐字。响应带 `mode`/`applied`/`value_after`/`fallbacks`
  如实汇报；三级全灭时报错带归因与 inspect 建议。显式 `use_js=true/false`
  强制单路径（向后兼容）。
- **A3 键名规范化**：`key_code_tuple` 大小写不敏感 + 别名层
  （enter/esc/space/del/ins/pgup/方向键/f1-f12）；`key_press` 支持组合写法
  `ctrl+a`/`cmd+v`（按最后 `+` 拆，尾部 `+`/非单字符后半不拆，防 `C++` 误拆）；
  Char 分支单字符防护，未知键明确报错列别名（不再透传 CDP 黑话）。
- **A4 press_sequence 聚焦 + 逐字**：支持 `selector`（先 click 聚焦再逐键，
  click 走既有动作路径、守卫让路由外层 dispatch 承载）；多字符文本 token
  （整句中文）自动逐字 Char 事件；响应带 `pressed_count`/`focused`。
- **A5 clear_input**：复用 A1 setter + 回读（`len_after` 佐证）。

### B. sequence/batch 一次交互更多消息（`mod.rs`）

- step 缺 `page_id` 自动继承（顶层 → 上一步 → 派生页），显式优先。
- 批量结果瘦身：成功步 message 截 300 字符、失败步截 2000（2002 的
  ExceptionDetails 巨串实测 ~1KB/个，逐步原样回填反复灌爆上下文）。

### C. guard 档漂移自愈（`browser_overlay.rs`）

- **脚本版本化重装**：模板头部 `if (window.__laewGuardRev >= REV) return;`，
  `guard_script` 以全局 `AtomicU64` 单调递增烘焙 REV；高版本先调旧实例
  `window.__laewGuardOff()`（卸载输入闸监听器 + 滚动/resize 调度 + MutationObserver
  句柄 + 蒙层/状态条/盾区元素）再重装 —— 同一页面多次注册（重复 open / rearm
  重注入）后「先注册旧档脚本抢先安装、后注册新档被 early-return」的漂移根治。
- **apply_page_guard 档位复核 rearm**：locked 应用后探测 `__laewGuardMode`，
  不符则重注入最新脚本并再应用，响应带 `rearmed:true`。eval 级开销，fail-open。

### D. 感知与提示

- `set_guard(open)` 响应附 note：页面已开放 + 完成人工操作后建议
  `set_guard(mode="locked")` 收口 + 「locked 不拦 Agent 输入（动作期自动挂闸）」
  纠偏提示（本轮事故 LLM 误判链的针对性提示）。
- 工具描述同步：input_text auto 阶梯/回读（不再需要 use_js）、key_press 别名/
  组合键、press_sequence selector 聚焦、sequence steps 可省略 page_id、
  2002 对策改写。
