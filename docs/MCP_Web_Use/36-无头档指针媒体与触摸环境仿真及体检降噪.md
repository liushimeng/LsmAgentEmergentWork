## 一、背景与真机基线（本轮一切判据的来源）

第 35 轮把体检面扩到 20 项，其中 7 项（`pointer_mq` / `screen_orientation` / `color_depth` /
`hw_params` 等）按「178 轮教训」一律**只观测不回填**，等真机基线钉死。本轮在本机
（Windows 11 / Chrome 155，laew 完整启动参数集 + 视口/screen 策略逐参数镜像
`browser.rs` 的 launch 路径）做了有头/无头双档基线采集（工具：
`cargo run --release --example stealth_baseline_probe -- headed|hidden`，
跑的是生产探针 `fingerprint::PROBE_JS`），结果：

| 向量 | 有头档（真值） | 无头档（裸读数） | 判别力 |
|------|----------------|------------------|--------|
| `matchMedia('(hover:hover)')` | `true` | `false` | 零假阳性 |
| `matchMedia('(pointer:fine)')` | `true` | `false` | 零假阳性 |
| `matchMedia('(any-hover:hover)')` | `true` | `false` | 零假阳性 |

| `screen.colorDepth` vs `pixelDepth` | `24`/`24` | `24`/`24` | 双档一致，防御性保留 |

| `window.chrome` 三件套 | 齐全 | 齐全 | 无头档也齐全，旧判据不触发 |

其余第 35 轮观察项经双档基线确认「有头/无头读数一致」，保留为防御性观测，不回填不升级。

## 二、处置：原生 CDP 环境仿真（非 JS 注入）

新增 `browser_env_emulation::apply_pointer_env_emulation(page, stealth_mode, browser_mode)`（从 `browser_ns.rs` 拆出独立模块，该文件已达临界行数）：

- **`Emulation.setEmulatedMedia`** 下发四元媒体特性
  （`hover:hover` / `any-hover:hover` / `pointer:fine` / `any-pointer:fine`）——
  与 Playwright `page.emulateMedia({pointer,hover})` 同源机制，直接改写页面媒体特性
  求值结果；
- **`Emulation.setTouchEmulationEnabled(false)`** 把 `maxTouchPoints` 归零；
- 真机验证：无头档下发后四元全 `true`、`maxTouchPoints=0`，与有头档基线**逐一对齐**
  （`MQ4: {"hover":true,"fine":true,"any_hover":true,"any_fine":true}`）。

**为什么走 CDP 仿真而不是 JS 覆写**（与 26 轮「注入面即签名」的总纲一致）：
零注入面 —— 不碰 `window.matchMedia`，无 `Function.prototype.toString` 登记负担、
无描述符形态风险、不进 `patched_fn_leak` 登记面；服务端也看不到任何差异。

门控（`pointer_env_action` 纯函数，单测锁死）：

| 档 | 有头 | 无头 |
|----|------|------|
| fidelity / hardened | **Skip**（原生即真值；不动触控屏本机的 `hover:none` 真实形态，强制 `fine` 反而是伪造） | **Apply** |
| off | Skip | **Reset**（清空仿真特性 + 恢复触摸缺省态，`set_stealth(off)` 排障后不留残余处置） |

接入点（与 `inject_stealth` / `screen_sync` 同批，全部幂等）：
`new_page_impl` 首航、`heal_page` 自愈、`adopt_spawned_pages` 派生收编、
`set_stealth` 运行时切档（升档即时仿真、降 off 复位）、
`browser_spawn_arm` 派生页早期武装（②b，与 screen_sync 同批下发）。
connect 模式零注入契约不变（调用点全部在 launch 路径内，watcher 只服务于 launch 实例）。

全部 CDP 调用 5s 有界超时 fail-open（同 `apply_screen_sync_override` 语义）：
仿真缺失只损反检测收益，绝不拖住导航。

## 三、体检降噪：`notification_denied` 退出 suspicious

真机双档实测：laew 启动参数集自带 `--deny-permission-prompts`（治理原生权限气泡，
162 轮 GEO 治理的同族参数），**有头/无头两档** `Notification.permission` 恒读
`denied`。这是我们自己启动参数造成的**诚实状态**——真实用户拒绝通知后读数完全
相同，该告警在 laew 环境下零判别力、只产噪声（每条 open 响应常年挂一条 warn）。
且 `FIDELITY_JS` ⑤（176 轮精确映射）已保证 `permissions.query` 与之一致
（`denied↔denied`），经典「单侧 denied 矛盾组合」并不成立。

处置：`notification_denied` 从 `classify()` 的 suspicious 中**移除**，降级为
`build()` 顶层观测字段 `notification_permission`（可见性不丢，人工/QC 仍可对账），
不进 suspicious、不抬 `risk_tier`。

## 四、自检语义升级与新增判据

- `pointer_media_headless`（35 轮 warn 保留）：基线钉死后从「待观测」升级为
  **处置失效自检** —— launch 无头档仍命中即说明仿真没下发（`stealth=off` 或
  CDP 超时 fail-open）；connect 模式命中则该用户环境本就如实（远程桌面/触控板）。
- 新增 `touch_points_headless`（warn）：桌面 UA + `maxTouchPoints>0` 命中；
  移动 UA 不误伤（`desktop_ua` 纯函数抽出共用，UA 为空 fail-open 不猜测）；
  仿真生效后读 0 自然消失（同为处置失效自检）。
- `build()` 顶层新增观测字段 `max_touch_points`；note 同步第 182 轮口径。
- 两个新判据按 178 轮教训**保持 warn 不进 HARD_CODES**（双档基线只证明「无头裸
  读数恒假」，但 connect 模式/触控设备的真值多样性未穷尽，硬判据留给零假阳性的
  stack/document 令牌类）。

## 五、验证

1. **单测**（`cargo test --lib` 全绿，2421 passed）：
   - `browser_ns::指针环境仿真门控`：有头恒 Skip / 无头 Apply / off Reset 九组合锁死；
   - `fingerprint::桌面UA下触摸点非零命中`：命中/归零/移动 UA/缺测四分支；

   - `硬判据集合只收零假阳性` 增补 `touch_points_headless` 不得进集合。
2. **真机端到端**（`stealth_baseline_probe` 走**生产函数**
   `apply_pointer_env_emulation`）：无头档四元全 true、`maxTouchPoints=0`，
   与有头档基线逐一对齐。
3. **回归**：`stealth_reveal_smoke`（服务端取证 + 回填替身差分，3 用例）全绿。
   已知遗留（先存于 main，本轮未触碰）：`stealth_first_document_single_load_smoke`
   在 Windows 全文件连跑时偶发 req#1 带 `HeadlessChrome` 令牌（干净 HEAD 三轮一败
   复现，UA 覆盖与首请求的毫秒级竞态），单跑恒过。与本轮改动无关，记入待办。

## 六、诚实边界（不变）

本轮仍是「移除自动化环境的泄漏读数」：仿真的四元媒体特性与触摸归零，是**桌面
指针环境的真值**（本机有头档实测），不是凭空伪造身份。Canvas/字体伪造、行为仿真、
IP 代理、打码、协议逆向依旧一律不做；被拦时的唯一合规改道仍是
`open(reuse_existing=true)` 接管用户已登录的真实浏览器。
