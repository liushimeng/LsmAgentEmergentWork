# MCP_Web_Use 22 · 多窗口并行(双站同时工作)

> 方案:`tmpPlan/20261013_125114_多窗口并行双站同时工作方案.md`
> 状态:已实现并真浏览器冒烟通过(`tests/web_use_smoke.rs::mcp_web_use_multi_window_parallel_smoke`)。

## 1. 解决什么问题

「天猫 + 京东双站比价」类任务需要**两个站点同时活跃工作**。但 Chrome 一个窗口
只有一个激活标签页,其余转后台挂起(渲染暂停 / rAF 停摆 / 定时器节流,见
`18-多标签页感知与后台挂起治理`),Agent 只能串行切换前台,后台站点实际停摆。

## 2. 方案:单浏览器进程 · 多窗口

不新起浏览器进程(`BrowserManager::global()` 被 overlay/focus/blocker/HITL/
watchdog 等 20+ 处引用,多实例重构风险大),而是利用 Chrome 单实例原生支持的
多窗口:CDP `Target.createTarget(newWindow:true)` 起独立可见窗口,各窗口的
激活页在互不遮挡时 `visibilityState` 均为 `visible`,真正并行;单 profile,
登录态 / HITL / 下载 / guard / 焦点租约等全部现有机制零改造复用。

**关键风险与对策**:Chrome occlusion tracking 会把被完全遮挡的窗口标记
occluded 并节流渲染(与后台 Tab 同病)。因此每当 Agent 窗口数 ≥2,自动把
所有 Agent 窗口**横向平铺**进屏幕工作区(`tile_window_plan` 纯函数,按工作区
等分,互不遮挡),后续新窗口打开时重新平铺。人工拖动窗口后不强制拉回。

## 3. 工具面

| 入口 | 说明 |
|------|------|
| `open(url, new_window=true)` | 独立新窗口打开;跳过同 URL 复用探测;响应 `data.new_window` + `data.windows` 平铺报告 |
| `control(new_window, params={url})` | 同上等价入口,与 `new_tab` 同级,走完整 open 语义(锚点守卫/管控/台账/健康诊断/geo),直接返回新 page_id |
| `list` | 每页附 `window_id`(CDP windowId),`data.windows` 报去重窗口数 —— 多窗口并行工作面板 |

限制(均返回 1001 说明,不静默降级):
- 仅 headed 模式(hidden/new_headless 没有「同时显示」概念,headless shell 不支持 newWindow);
- connect 模式(接管用户浏览器)不支持 —— 不开新窗口干预用户浏览器;
- 与 `reuse_existing` 互斥;
- 窗口数上限 `LAEW_WEB_MAX_WINDOWS`(默认 4,按去重 windowId 计;同窗口多 Tab 不占额度)。

## 4. 实现分布

| 位置 | 内容 |

| `src/agent/browser.rs` | `new_page` 拆出 `new_page_impl(..., new_window)`;`new_page_in_new_window` 公开入口(connect 恒 None);`CreateTargetParams.new_window(true)` 建页,其余 launch/注入/清扫逻辑逐行复用 |

| `src/agent/tools/mcp_web_use/mod.rs` | `run_open` 互斥校验;`run_open_new_window` 校验链(connect→headed→上限→建页→平铺收尾);`run_list` window_id;schema/描述【多窗口并行】段 |
| `src/agent/tools/mcp_web_use/control/mod.rs` | `new_window` 早退分支(在 6002/4003/6003/guard 让路之前 —— 开新窗口不操作当前页,全部闸门不适用);加入任务锚点 6001 守卫清单 |

## 5. 兼容矩阵

| 机制 | 多窗口下的行为 |
|------|----------------|
| 6003 后台闸 | 另一窗口的页 visibilityState=visible,天然不命中;人工最小化窗口才标 background(正确语义) |
| guard 三档 / 蒙层 / 输入闸 | 按页面注入,窗口间互不影响 |
| HITL / request_human | 按 page_id 工作,`unlock_page` 只开对应窗口的洞 |
| 焦点租约 keep 档 | 抬升不抢焦 per 进程;平铺后所有窗口本就可见,不依赖精确抬升 |
| close(page_id) | 窗口内最后一页关闭时 Chrome 自动收窗;`close(all)` 回收进程 |
| adopt 派生页 / 访问台账 | `browser.pages()` 跨窗口返回全部 target,机制不变 |

## 6. SubAgent 分工(自感知)

多站点并行任务的推荐编排:Main-Work 把「站点 A 调研」「站点 B 调研」拆成同层
WorkFlow 单元(或父 Agent 用 SubAgent 工具分工),每个子 Agent 的 task 文本
写明「用 `open(new_window=true)` 打开 X 站,该窗口页面由你专属」。两个窗口
同时前台可见,子 Agent 天然并行互不阻塞;收口比价在父层汇总。
