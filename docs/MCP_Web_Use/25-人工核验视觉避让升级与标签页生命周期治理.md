# 25 - 人工核验视觉避让升级与标签页生命周期治理

> 2026-10-14。本文档是 `docs/MCP_Web_Use/` 系列最新一篇，覆盖两类问题：
>
> 1. **人工核验窗口被「LAEW Agent 控制中」视觉屏蔽** —— 网站风控弹出人工核验
>    （滑块/图片语义题等）时，屏蔽页面状态栏（右上角，第 171 轮接管原徽标位）
>    以 `z-index:2147483646` 的不透明黑盒叠在挑战层之上，把弹窗控件与提示罩死。
> 2. **Chrome Tab 页签只开不关** —— Agent 打开新 Tab / 点击按钮派生新 Tab 后
>    没有收口机制，同站点页签越堆越多；同站 Tab >3 时 Agent 无感知。
>
> 前置修复（同轮在途，见 `browser_status.rs` REV 2 与 `hitl_ctl.rs`）：
> - 状态栏注入脚本会进**每个新文档（含跨域 iframe）**，baxia 挑战 iframe
>   （~390px 宽）内也长出状态栏把滑块罩死 → REV 2 加 `window.top === window`
>   顶层门，子 frame 一律不渲染两条栏。
> - `request_human(unlock_page=true)` 提问期间 `apply_hitl_unlock` 挂起两条栏，
>   收口/恢复屏蔽/中继 session_end 复显。
>
> 本文档在其上补两个缺口：**挑战弹窗在顶层 frame（非 iframe）时无任何避让**、
> **页签生命周期全靠 LLM 自觉 close**。

## 一、问题分析

### 1.1 人工核验弹窗视觉遮挡

三层视觉注入的 z-index 现状：

| 层 | host z-index | 元素 z-index | 说明 |
|---|---|---|---|
| 状态栏/进度栏（`browser_status.rs`） | 2147483644 | 2147483646 | 右上角/左下角常驻告知栏 |
| guard 蒙层+盾区（`browser_overlay.rs`） | 2147483647 | 2147483646 / 2147483645 | 三档管控 |
| 高亮蓝框（`browser.rs`） | — | 2147483647 | 选中边框 |

站点风控挑战弹窗（天猫 baxia、京东老虎图、豆包图片语义题）通常用很高的
z-index（1000~2147483647 不等），且 baxia 类挑战是**顶层 frame 的模态遮罩**
（不是 iframe）——REV 2 的 iframe 顶层门对它无效。状态栏的不透明黑盒
（`background:rgba(15,23,42,0.86)`）叠在弹窗右上角，人工看不到弹窗关闭按钮/
提示文字；`pointer-events:none` 所以不挡点击，但**视觉遮挡**足以让人工以为
「弹窗被屏蔽了」。

已有的避让通道只有两条，都有缺口：
- HITL 解锁挂起：只有走 `request_human(unlock_page=true)` 才触发；**6002 硬闸/
  收尾探针只回提示载荷**（批内/无 GUI/hub 忙）的场景不挂起。
- 截图避让 `guard_suspend_visuals`：只在 screenshot/ocr 瞬间挂起，拍完即复显。

### 1.2 Tab 页签只开不关

现状：提示词层有「资源释放」软引导（`system_prompt/mod.rs` 资源释放条款），
工具 description 有【标准作业顺序】收尾建议，`list` 在 ≥6 页时附 `tabs_hint`。
**没有任何程序级机制**：

- `open` / `control(new_tab)` / 点击派生（`adopt_spawned_pages` 收编）都只进不出；
- 编排器任务收口（`orchestrator`）不摸浏览器；TUI 任务间浏览器 keep-alive，
  页签跨任务累积；
- `close` 只有三种形态：单页 / `"all"`（连浏览器一起回收）/ `"background"`
  （后台批量）。**没有「关掉除当前页以外的全部」** —— 而这是最常见的收口诉求；
- 同站点 Tab >3 时无任何感知（`tabs_hint` 阈值是全局 ≥6，且只看总数不看
  单站堆积——同站 5 个 Tab 多是同一路由反复打开，是最典型的失控形态）。

## 二、解决方案

### 2.1 挑战层驱动：状态栏自动避让（probe-driven suspend）

核心思路：**blocker_probe 已经每次动作收尾都在探测挑战弹窗**（`probe_alert`），
把探测结果直接接到状态栏显隐上 —— 探测驱动、自愈恢复，不新增任何探测开销。

```
探测命中（blocker_alert） ──► challenge_suspend(page, true)  ──► 两条栏挂起
探测转干净（下一轮 probe） ──► challenge_suspend(page, false) ──► 两条栏复显
```

- 新增 `browser_status.rs::challenge_suspend(page, page_id, suspend)` +
  `challenge_suspended(page_id)`：以 `static Mutex<HashSet<String>>` 记账
  （本机制自己挂起的页才由本机制恢复，不抢 HITL/截图挂起的主导权）。
- `blocker_probe.rs::probe_alert` 包壳：`probe_alert_impl`（原逻辑零改动）→
  命中即挂起；转干净且**本机制挂起中**才复显。复显前检查
  `HumanAssistHub::is_pending()` —— 人工正在 HITL 弹窗里处理挑战时不提前复显。
- 与 HITL 挂起的交会：HITL 收口 `set_suspended(false)` 后若挑战仍在场，下一轮
  probe 命中会重新挂起（幂等记账保证收敛）；挑战清除后本机制正常复显。

这样顶层 frame 的 baxia 模态、批内（sequence 上下文不回 auto-HITL 只回载荷）
的挑战弹窗，状态栏都会自动让位；页面干净后自动回来，零人工干预。

### 2.2 标签页生命周期治理

四件套：

**① `close(page_id="others", keep="<page_id>")`** —— 关闭除 `keep` 外全部页面。
`keep` 必须是存活 page_id（否则 1001）。收口最常见诉求「留一个前台页关掉其余」
一条命令完成；实现走 `BrowserManager` 公共 API 逐页 `close_page`
（最后一页关闭自动回收浏览器的语义不变，`keep` 存活保证不会触底）。

**② 任务收口自动清后台新页** —— 编排器任务边界治理：

- 新增 `src/agent/tab_ledger.rs`：`begin_task()` 在任务开始时快照基线
  （当时存活的全部 page_id）；**零 browser.rs 改动** —— 不用埋点记录谁开的页，
  收口时 `list_pages` 现取与基线 diff，本任务新开的页自然现形
  （新开/点击派生/JS window.open 收编全部覆盖）。
- `page_activity.rs::finalize_task_tabs()`：对 diff 出的新页逐页探测前后台，
  **后台 → close，前台/探测失败 → 保留**（前台页人工可能正在看；探测失败
  fail-safe 不杀）。返回 `{opened, closed, kept, skipped}` 摘要。
- 挂载点：`MultiAgentOrchestrator::handle_cancellable_with_progress` —
  `handle_inner` 前 `begin_task()`，其后 `finalize_task_tabs()`（tracing 落摘要）。
  TUI 每轮任务与 `-p` 单轮模式同一收口路径。
- 杀开关 `LAEW_WEB_TAB_AUTOCLOSE=off`；connect 模式（接管用户浏览器）同样生效
  —— 只关本任务新开的 Tab，不动用户原有的页签。

**③ 单站点 Tab >3 感知（origin_tabs_alert）** —— `run_list` 按 URL host 分组
（复用 `browser_pace::host_of`），任一同源 Tab 数 >3 时响应附：

```json
"origin_tabs_alert": {"host": "detail.tmall.com", "tabs": 4,
  "page_ids": ["p_xxx", ...],
  "hint": "同站点页签堆积:多为重复打开同一路由;请及时 close(page_id) 收口,保留 1 个前台页后可用 close(page_id=\"others\", keep=...) 一次清掉其余"}
```

与既有 `tabs_hint`（全局 ≥6）互补：一个看单站堆积，一个看总量。

**④ 提示词/工具面同步**：`MCP_WEB_USE_PROMPT_SECTION` 资源释放条款改写 —
— 说清「任务结束编排器自动关闭本任务新开的**后台**页签（前台页保留），但
执行中同站 Tab >3 就应立即主动收口，不要等任务结束」；工具 description 的
close 说明与【多标签页与后台挂起】第③条同步 `others`/`origin_tabs_alert`/
自动收口语义。
