## 一、背景与目标

### 1.1 现状问题

第 61 轮引入的 **Chromium-WebUse Agent**(`LsmAgentEmergentWork-Chromium-WebUse`,第 11 角色)
为网页操控单独设立了一个执行层角色:

- 独立 Runner(`src/agent/web_use.rs::WebUseRunner`,999 行)+ 独立 profile + 独立系统提示词;
- 独立工具面 5 件套(BrowserNew / BrowserList / BrowserClose / BrowserControl / BrowserInspect,
  `src/agent/tools/browser.rs`,1396 行);
- 编排链路为它开专线:Yolo `suggested_delegate="webuse"` → simple 档 `resolve_simple_delegate`
  特判路由 → medium 档 `run_wf_unit` match 分支 → Main-Work `delegate_to="webuse"` →
  `infer_delegate_to` 关键词纠正 → QC WebUse 专项文案 → TUI WebUse 诊断分支;
- 为治「首迭代纯文本空转」引入首迭代强制工具(`with_first_iter_forced_tool`)、
  WebUse nudge 多轮文本、出口 page_id/page_reply 兜底等一整套补丁链。

实际运行证明:**专项角色带来的复杂度大于收益**——工具能力(CDP 驱动浏览器)与
执行编排(多轮 Agent 循环)本可以解耦;与第 84 轮删除 WindowUse Agent 的结论一致。

### 1.2 目标

1. **彻底删除** Chromium-WebUse Agent 实现:Runner、profile、系统提示词、`AgentRole::WebUse`、
   编排路由分支、Yolo/Main-Work 关键词特判、QC 专项文案、首迭代强制工具机制、
   相关代码注释与文档;
2. 浏览器操控能力**降级为 Agent Tools 中的单一 MCP 风格工具 `MCP_Web_Use`**:
   单工具 + `action` 枚举分发,结构化 JSON 入参/出参,由持有该工具的 Agent
   (SubAgent-Work 全套工具面)在自身多轮对话循环中反复调用;
3. 「MCP 服务」实现 = CDP 驱动层 `src/agent/browser.rs::BrowserManager`(进程内单例 +
   `page_id` 页面注册表 + Console/Network 环形缓冲 + 派生标签页 adopt + 生命周期回收),
   **原样保留,零改写**;
4. `page_id` 全生命周期管理:open 拿 id → 多轮 control/inspect 反复复用 →
   点击链接/新开标签页返回 `spawned_page_id` → close 释放;任务完成后页面可跨任务复用,
   进程退出时统一回收。

### 1.3 非目标

- 不改变 `BrowserManager` 的任何运行时行为(启动模式三档 / connect_url 接管 /
  事件缓冲 / cleanup_sync 多层防御全部保留);
- 不引入真实 MCP 协议进程(与 MCP_Window_Use 同为「MCP 风格」进程内工具);
- 不改变 Quality-Check / SessionContext / Debug / 取消 / 并行调度链路(全部自动复用
  SubAgent 既有路径)。

### 2.2 工具面设计

**单工具名**:`MCP_Web_Use`。

**action 枚举(5 个,替代原 5 件套工具)**:

| action | 替代的原工具 | 职责 | 关键参数 |
| --- | --- | --- | --- |
| `open` | BrowserNew | 启动/接管浏览器并打开页面,返回 `{page_id,title,final_url,mode,next_steps}` | `url*` `mode?` `connect_url?` `user_agent?` `wait_until?` |
| `list` | BrowserList | 列出存活页面(顺带清理失效 entry) | 无 |
| `close` | BrowserClose | 关闭指定 page_id;最后一个页面关闭时回收浏览器进程。幂等 | `page_id*` |
| `control` | BrowserControl | **全部写操作统一入口** | `page_id*` `control_action*` `params?` |
| `inspect` | BrowserInspect | **全部只读观察统一入口** | `page_id*` `info*` `params?` |

命名对齐 MCP_Window_Use:`action` 是工具级分发动作,`control_action` 是 control 内的
具体写操作(原 BrowserControl 的 `action` 字段更名,避免与工具级 action 撞名),
`info` 沿用原 BrowserInspect 枚举名。

**control_action 枚举(34 个,与原 BrowserControl 完全一致)**:
click / human_click / right_click / double_click / hover / scroll / scroll_to / key_press /
press_sequence / input_text / human_input / clear_input / upload_file / select_option /
new_tab / close_tab / navigate / back / forward / reload / wait / eval_js / set_cookie /
delete_cookie / set_storage / clear_storage / set_viewport / screenshot / heartbeat /
drag / focus / blur / mouse_move / dispatch_event。

覆盖用户要求的全部能力:鼠标点击(click)、右键点击(right_click)、滚轮滚动(scroll)、
键盘按键(key_press / press_sequence)、输入文本(input_text)、上传文件(upload_file)、
打开新 Tab(new_tab;点击链接派生页经 `spawned_page_id` 回传)、截图(screenshot)、
Console / Network / Elements / DOM / localStorage 查看(inspect 各 info)。

**info 枚举(14 个,与原 BrowserInspect 完全一致)**:
console / network / elements / dom / localstorage / sessionstorage / cookies / screenshot /
page_meta / viewport / url / title / ping / image_urls。

**page_id 生命周期(用户核心诉求)**:

```
open(url) ──► {page_id: "p_ab12cd34", next_steps:[...4 步引导]}
   │
   ├─► control(page_id, control_action=click, params={selector:"a.news"})
   │       └─► 响应携带 spawned_page_id:"p_ff00ee11"(新标签页自动 adopt 注册)
   │
   ├─► inspect(page_id, info=elements/console/network/dom/localstorage...)
   │
   └─► close(page_id)  ──► 释放;最后一个页面关闭 → 浏览器进程 + 临时 profile 回收
```

- `page_id` 对 LLM 不透明(`p_` + 8 位 hex),跨工具调用、跨 WorkFlow 单元、跨任务存活;
- 多轮复用:SubAgent Runner 入口探测存活页面,非空时向 prompt 注入
  「已打开的浏览器页面」提示块(第 79 轮能力平移,见 §2.4);
- 兜底回收:`main.rs` 退出路径 `BrowserManager::shutdown()` + atexit
  `cleanup_sync()`(第 78 轮多层防御,零改写保留)。

**统一 JSON 信封(错误码语义零变化)**:

`{code, message, data}` —— 0 成功 / 1001 参数错误 / 2000 page_id 失效 / 2001 断连 /
2002 动作失败 / 2003 页面崩溃 / 3001 未检测到浏览器。Agent 据错误码机械决策
(2000 → action=list 重新同步;2002 → 换 selector 或 use_js 路径;3001 → 如实告知用户)。

### 2.5 系统提示词注入(无平台门控)

`SystemPrompt::sub_agent_work()` 末尾追加 `MCP_WEB_USE_PROMPT_SECTION`(常量),
内容精炼自原 WEB_USE_BASE_PROMPT 的作业规范:

- 标准作业顺序:open 拿 page_id → control/inspect 多轮操作 → close 释放;
- 页面复用:输入含「已打开的浏览器页面」列表时优先复用;
- spawned_page_id 纳入页面索引;
- 错误码对策表(1001/2000/2001/2002/3001);
- 中文输入 use_js 优先、复杂页面先 inspect(elements) 探测真实 DOM;
- 安全红线:支付/删除/确认类按钮禁止无把握点击;凭证只用用户提供的;只读优先;
- 反伪造红线(对齐第 87 轮 MCP_Window_Use):禁止 Bash/Write 伪造本应由工具产出的证据。

与 MCP_Window_Use 段的区别:**无平台门控**——CDP 三平台(Windows/macOS/Linux)行为一致,
未装浏览器时返回结构化 3001 而非崩溃,因此全平台注册、全平台注入说明。

## 三、关键实现

### 3.1 工具 Schema(单工具)

```json
{
  "action": "open | list | close | control | inspect",
  "url": "open 必填:目标网址",
  "mode": "hidden | new_headless | headed(默认 hidden)",
  "connect_url": "open 可选:接管 --remote-debugging-port 浏览器",
  "user_agent": "open 可选:覆盖 UA",
  "wait_until": "open 可选:load | domcontentloaded | networkidle",
  "page_id": "close/control/inspect 必填",
  "control_action": "control 必填:34 个写操作枚举",
  "info": "inspect 必填:14 个观察枚举",
  "params": "control/inspect 可选:动作参数对象(selector/text/key/timeout_ms/...)"
}
```

`additionalProperties: false`;`required: ["action"]`。

### 3.2 分发骨架(mod.rs)

```rust
pub struct McpWebUseTool;
pub const MCP_WEB_USE_TOOL_NAME: &str = "MCP_Web_Use";

#[async_trait]
impl Tool for McpWebUseTool {
    async fn execute(&self, args: Value) -> Result<String> {
        let action = require_str(&args, "action", self.name())?;
        match action {
            "open"    => run_open(args).await,      // mod.rs
            "list"    => run_list(args).await,      // mod.rs
            "close"   => run_close(args).await,     // mod.rs
            "control" => control::run(args).await,  // control.rs
            "inspect" => inspect::run(args).await,  // inspect.rs
            other => envelope(1001, "未知 action", json!({"action": other})),
        }
    }
}
```

`control.rs` 内部 `control_action` match 与原 `act_*` 函数**逐行一致**
(仅入参从 `args.action` 改为 `args.control_action`);`inspect.rs` 同理。

### 3.3 注册(tools/mod.rs)

```rust
pub fn builtin_registry() -> ToolRegistry {
    ... Bash/Read/Write/Edit/Glob/Grep
        .register(Arc::new(mcp_window_use::McpWindowUseTool))  // 平台门控
        .register(Arc::new(mcp_web_use::McpWebUseTool))        // 全平台
}
```

`web_use_registry()` 删除;SubAgent-Work(sub_agent_work_registry → builtin_registry)
即获得浏览器操控能力;Yolo/Plan/Main-Work/QC 等注册表不变(权限面不扩大)。

### 3.4 SubAgent Runner 增强(subagent.rs)

```rust
async fn run_unit_inner(...) {
    // ★ 多轮页面复用:存活页面探测 + 提示块注入(冷启动零开销)
    let live_pages = BrowserManager::global().list_pages().await;
    let mut prompt = input.to_user_prompt();
    if let Some(hint) = build_existing_pages_hint(&live_pages) {
        prompt.push_str("\n\n"); prompt.push_str(&hint);
    }
    ... run_session_cancellable ...
    // ★ 出口兜底:MCP_Web_Use 抓取的真实页面文本追加到终答
    let text = append_page_reply_if_needed(text, sub_session.context());
}
```

### 3.5 agent_loop 引导钩子参数化

- post-open 引导:`name == "MCP_Web_Use" && args.action == "open" && !is_error`
  → 解析信封 `data.page_id` + `data.next_steps` → 注入四步引导 user message;
- 失败学习:`name == "MCP_Web_Use"` 且 is_error → selector 键取 `params.selector`,
  同键连败 ≥2 次追加换姿势提示;
- `extract_page_id_from_text` 从 web_use.rs 平移到 mcp_web_use 模块(pub(crate))。

### 3.6 存量数据兼容

- `AgentRole::from("webuse")` / serde `#[serde(rename="webuse")]` → 归并 `SubAgent`
  (与第 84 轮 "windowuse" 处置完全一致);
- `lenient_delegate_to`:`"webuse" | "browser" | "web" | "浏览器"` 等别名 → `SubAgent`;
- ExecutionTrace 删除 `forced_tool_effective` 字段:旧 trace JSON 含该字段时
  serde 忽略未知字段,反序列化不受影响;
- `session_memory` / `agent_memory` 存量行 role="webuse" → 读回 SubAgent。

## 六、影响面与风险

| 风险 | 评估 | 缓解 |
