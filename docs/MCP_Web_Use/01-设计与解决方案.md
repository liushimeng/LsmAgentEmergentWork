# MCP_Web_Use 浏览器操控工具设计与解决方案

> 版本:2026-09-20(本目录唯一有效文档)
> 适用平台:macOS / Windows / Linux
> 实现入口:`src/agent/tools/mcp_web_use/` + `src/agent/browser.rs`
> 技术参考:`docs/浏览器CDP工具/Rust操作Chrome浏览器CDP完整技术方案.md`

## 1. 定位与架构

`MCP_Web_Use` 是 SubAgent-Work 的浏览器操控工具,采用**进程内 MCP 风格服务**:LLM 只见
单工具 + action discriminator,协议细节、浏览器生命周期与页面注册表全部封闭在 CDP 驱动层。

```text
SubAgent-Work(LLM 多轮 Agent Loop)
    └── Tool::execute(MCP_Web_Use)
            ├── action 参数校验与结构化 JSON 信封
            ├── open / list / close / control / inspect / sequence
            └── BrowserManager(chromiumoxide CDP)
                    └── Chrome / Edge / Chromium / Brave
```

设计原则来自外部 Agent 源码调研:

1. 单工具 action 分发优于多个细粒工具,可减少 Schema token 并提升协议缓存命中;
2. 浏览器自动化必须形成「探索 → 操作 → 验证」闭环,DOM/Elements 优先,截图只作兜底;
3. page_id 是唯一页面句柄,点击或 `window.open` 派生的新页必须回传新句柄;
4. 所有结果使用统一信封,便于 Agent 按错误码机械恢复,避免崩溃或伪造结果。

## 2. 能力总览

| action | 语义 | 关键返回 |
| --- | --- | --- |
| `open` | 启动/接管浏览器并打开页面 | `page_id` / `title` / `final_url` / `next_steps` |
| `list` | 列出存活页面并清理失效 entry | `pages[]` |
| `control` | 全部写操作统一入口,35 个 `control_action` | 动作结果 / `spawned_page_id` |
| `inspect` | 全部只读观察统一入口,14 个 `info` | Console / Network / DOM / Storage 等 |
| `sequence` | 连续执行最多 24 步动作链 | 逐步结果 / `failed_at` / 最终 `page_id` |
| `close` | 关闭页面;最后一个页面关闭时回收浏览器 | `closed` |

`control_action` 能力组:

- 鼠标:`click` / `human_click` / `right_click` / `double_click` / `hover` /
  `scroll` / `scroll_to` / `drag` / `mouse_move`;
- 键盘与输入:`key_press` / `press_sequence` / `input_text` / `human_input` /
  `clear_input` / `focus` / `blur`;
- 文件:`upload_file` / `download`;
- 标签页与导航:`new_tab` / `close_tab` / `navigate` / `back` / `forward` / `reload`;
- 状态与浏览器:`wait` / `eval_js` / `set_cookie` / `delete_cookie` / `set_storage` /
  `clear_storage` / `set_viewport` / `screenshot` / `heartbeat` / `dispatch_event`;
- 窗口可视化(详见 `02-人工介入与窗口可视化方案.md` §3.3):
  `set_window` / `sync_viewport` / `set_highlight`;
- 人工介入 HITL(详见 `02-人工介入与窗口可视化方案.md` §3.1 与
  `03-扩展场景与覆盖增强方案.md`):`request_human`,
  9 个合法 reason = `captcha / sms / qr_login / login / real_name / two_factor /
  oauth / manual_verify / custom`(后三个为第 117 轮扩展)。

`inspect(info)` 能力组:

`console` / `network` / `elements` / `dom` / `localstorage` / `sessionstorage` /
`cookies` / `screenshot` / `page_meta` / `viewport` / `url` / `title` / `ping` /
`image_urls` / `ocr`(截图+OCR 一步读取,详见 §14.1) /
`blockers`(启发式检测验证码/短信/扫码/登录墙/实名/2FA/OAuth 7 类人工拦截,
返回 `blockers[]` + `suggested_action` + `available_reasons`,
详见 `02` §3.2 与 `03` §4)。

## 3. 浏览器生命周期

- 首次 `open` 启动浏览器。默认 `mode=hidden`,使用 `--headless=new` 与一次性
  user-data-dir,不干扰用户日常浏览器;`mode=headed` 用于可见窗口调试;
  `connect_url` 可接管已开启 `--remote-debugging-port` 的浏览器;
- 浏览器探测顺序:`LAEW_BROWSER_PATH` → Chrome → Edge → Chromium → Brave →
  chromiumoxide 默认检测;未安装时返回 `code=3001` 与安装引导;
- `page_id` 形如 `p_ + 8 位 hex`,对 LLM 不透明;
- 点击链接、中键打开、`window.open`、`new_tab` 后,BrowserManager 通过页面差集 adopt
  新 target,并在响应中返回 `spawned_page_id`;
- 页面注册表跨任务存活,SubAgent 任务入口会注入「已打开的浏览器页面」提示,可复用登录态;
- `close` 幂等;launch 模式最后一个页面关闭后回收浏览器进程、handler 与临时 profile。

## 4. 两种工作模式

### 4.1 单步执行模式(默认)

一次调用一个动作,适合未知页面探索、selector 调整、Console/Network 调试、下载目标确认,
以及支付、删除、确认提交、登出等高风险操作。

```json
{
  "action": "inspect",
  "page_id": "p_ab12cd34",
  "info": "elements",
  "params": {"selector": "textarea", "include_text": true}
}
```

推荐路径:

```text
open → inspect(elements/dom) → control(input/click/wait) → inspect 验证 → close
```

### 4.2 连续执行模式

先在单步模式下探索结构,再把已经明确的动作链交给 `sequence` 一次执行。适合稳定表单、
多页浏览、采集、输入→提交→等待→提取等流程。

```json
{
  "action": "sequence",
  "page_id": "p_ab12cd34",
  "stop_on_error": true,
  "steps": [
    {"action":"control","page_id":"$page_id","control_action":"input_text",
     "params":{"selector":"textarea","text":"你好 laew","use_js":true}},
    {"action":"control","page_id":"$page_id","control_action":"click",
     "params":{"selector":"button[type=submit]"}},
    {"action":"control","page_id":"$page_id","control_action":"wait",
     "params":{"selector":"[class*=result]","timeout_ms":60000}},
    {"action":"inspect","page_id":"$page_id","info":"elements",
     "params":{"selector":"[class*=result]","include_text":true}}
  ]
}
```

规则:

- `steps` 为 1~24 个对象,每项结构与单步调用一致,禁止嵌套 `sequence`;
- `stop_on_error=true`(默认)失败即停止;`false` 可采集全量执行报告;
- 响应逐步返回 `{index,action,code,message,data}`,顶层返回 `completed`、
  `failed_at`、最终 `page_id` 与最近 `spawned_page_id`;
- 两种模式可任意混合、多次调用;
- 不可逆或高风险动作不得进入批处理,必须单步执行并在动作后检查页面状态。

### 4.3 page_id 占位符

连续模式支持递归字符串替换:

| 占位符 | 语义 |
| --- | --- |
| `$page_id` / `${page_id}` | 当前页面 |
| `$spawned_page_id` / `${spawned_page_id}` | 最近派生页面 |

`open` 返回的 `page_id` 成为当前页;响应携带 `spawned_page_id` 时默认自动跟随新页,
保证「点开链接 → 在新页继续操作」。若需留在原页,该步骤可设置
`follow_spawned=false`,此时仅记录 `$spawned_page_id`,不切换当前页。

## 5. 下载管理

### 5.1 调用

```json
{
  "action": "control",
  "page_id": "p_ab12cd34",
  "control_action": "download",
  "params": {
    "url": "https://example.com/report.pdf",
    "save_dir": "downloads/report",
    "filename": "report.pdf",
    "timeout_ms": 120000
  }
}
```

`url` 与 `selector` 二选一:

- `url`:页面内注入一次性隐藏 `<a download>` 触发;
- `selector`:点击页面既有下载链接或按钮,适合前端脚本生成地址。

参数约束:

- `save_dir` 相对路径以工作目录为基准,目录自动创建并 canonicalize;
- `filename` 仅允许文件名,自动 `file_name()` 归一化,禁止路径穿越;
- `timeout_ms` 缺省/0 为 120000,范围 1000~300000。

### 5.2 CDP 链路

```text
Browser.setDownloadBehavior(allowAndName, downloadPath, eventsEnabled=true)
→ 注册 Browser.downloadWillBegin / downloadProgress
→ selector click 或隐藏 anchor 触发
→ 按 guid 过滤 begin/progress
→ 等待 completed
→ 校验文件真实存在
→ filename 存在则安全重命名
→ stat 返回绝对 save_path 与 byte_size
```

成功数据包含 `guid`、`url`、`suggested_filename`、`save_path`、`byte_size`、
`received_bytes`、`total_bytes`、`state`、`elapsed_ms`。不得凭 HTTP 200 或点击成功
推断文件已落盘,必须以 CDP completed 事件和文件存在为准。

## 6. 统一信封与错误恢复

所有 action 返回:

```json
{"code":0,"message":"ok","data":{}}
```

| code | 含义 | Agent 策略 |
| --- | --- | --- |
| 0 | 成功 | 读取 data / page_id |
| 1001 | 参数错误 | 修正 action、必填字段或枚举 |
| 2000 | page_id 失效 | `action=list` 重新同步 |
| 2001 | 浏览器断连或启动失败 | 重新 `open`;无浏览器则报告安装引导 |
| 2002 | 动作失败 | 换 selector / `use_js` / 等待策略;下载失败检查地址与目录 |
| 2003 | 页面崩溃 | 重新打开页面 |
| 3001 | 未检测到浏览器 | 如实告知用户安装 Chrome/Edge/Chromium,不重试 |

Agent Loop 已内置浏览器辅助:

- `open` 成功后注入 `next_steps` 四步引导;
- 同 selector 连续失败 ≥2 次注入换姿势提示;
- SubAgent 出口解析真实页面文本,避免只输出「已提取 N 字符」占位;
- System Prompt 强制反伪造:禁止用 Bash/Write 伪造截图、下载文件或网页抓取证据。

## 7. 安全边界

1. 登录凭证只能使用用户明确提供的值,不得编造;
2. 只读可回答的问题优先 `inspect`,不做写操作;
3. 支付、删除、确认提交、登出、批量发送等不可逆动作必须单步执行并二次验证;
4. `eval_js` 与 `dispatch_event` 只用于当前页面任务,不得绕过用户意图修改外部状态;
5. 下载路径和文件名受限,最终文件必须来自受限目录并真实存在;
6. 大 DOM / 截图沿用截断与自动落盘策略,避免 tool_result 撑爆上下文。

## 14. 第 99 轮(2026-09-20):验证码 OCR / eval_js 容错 / 页面卫生 / QC verdict 修复

> 背景:云智眼预发布环境登录任务(10.255.159.58:20122)实测三次单元执行累计 550s+
> 未完成登录(迭代黑洞:140KB 验证码 data-url 反复 Bash/Read 解码;`download
> url=about:blank` 挂 120s;eval_js `return` 语句 SyntaxError;QC JSON 缺 `verdict`
> 白耗重试;三次 open 泄漏 3 个页面)。方案全文:`tmpPlan/2026-09-20_01-MCP_Web_Use效率与验证码OCR根治方案.md`。

### 14.1 截图即文字:OCR 能力(A/C)

- **`inspect info=ocr`**(新增第 15 个只读维度)= 截图 + OCR 一步:响应带
  `ocr_text` / `ocr_block_count` / `save_path`;
- `control(screenshot)` 新增 `params.ocr=true`(同上)+ `params.region{x,y,width,height}`
  (OCR 词块过滤,落盘仍为整帧)+ `params.return_base64=true`(显式内联,默认不返回);
- **screenshot 一律落盘**(save_path 指定,否则临时目录),不再内联 base64 ——
  文本模型无法消费图片,base64 内联纯属上下文浪费;
- 实现复用 `agent::window::macos_vision_ocr`(Vision 框架,`ocr_png_file` 新入口);
  图像来自 CDP 截图字节,**不触碰 CGWindow,无需屏幕录制权限**;非 macOS 返回
  结构化 `ocr_error` 引导(如实上报等待人工,禁止猜验证码)。

### 14.2 eval_js 容错与结果净化(B)

- 参数别名:`expression` 之外接受 `function` / `js` / `code`(含 `_b64` 变体);
  缺参错误列出全部合法名(根治 LLM 参数名摸索,实测连续 4 次迭代猜 `function`);
- **`return` / 多语句容错**:首次按原样评估;失败且表达式非函数形态时自动包
  IIFE(`await_promise` 时 async IIFE)重试一次,响应 `wrapped_iife:true`;
- **大结果净化**:`data:` URL 或 >2000 字符字符串自动落盘(临时目录),响应改给
  `result_head`(160 字)+ `result_len` + `saved_to` + 引导 hint —— 根治 140KB
  验证码 data-url 灌爆上下文,及其连锁反应(download 参数超限被截断 → schema 校验失败)。

### 14.3 download 快速失败与 data: 直存(D)

- `data:` URL 直接解码落盘(base64 / 百分号编码载荷),不走 CDP 下载事件
  (Chrome 对 data: 锚点不产生可靠下载事件);响应 `mode:"data_url"`;
- `about:` / `blob:` / `javascript:` 立即结构化报错并给出替代指引 —— 根治
  `download url=about:blank` 白等 120s。

### 14.4 页面卫生(E)

- **open 同 URL 复用**:已存在同 URL 存活页面时默认导航刷新并返回同一 page_id
  (`reused:true`;URL 归一化 = 去尾部 `/` 与 `#fragment`),`reuse:false` 强制新开
  —— 根治「局部重试/重复 open 泄漏页面」(实测 3 次尝试泄漏 3 页);
- **`close page_id="all"`** 一键关闭全部页面并回收浏览器(任务收尾清场)。

### 14.5 QC verdict 语义修复(F,`agent/quality.rs`)

- `repair_quality_json`:反序列化前按信号推断补 `verdict`(`pass` bool →
  `result`/`status`/`conclusion` 字符串关键词 → `issues` 非空 → Fail),无信号
  保持 fail-closed;`source` 缺失用调用方补齐(`serde_json::to_value` 互逆保证);
  `retryable` 缺失按 verdict 推断;
- 三个 QC 提示词(单元/Main-Work/Plan)统一追加 `QC_JSON_SHAPE_HINT`
  (「第一个字段必须是 verdict」+ 完整 JSON 示例),提示词 + 解析端双保险。

### 14.6 作业规范与 TUI 可观测性

- SubAgent 系统提示词 MCP_Web_Use 段:第 6 条重写(截图=OCR,严禁 Read 图片/
  Bash 解码)、新增第 13 条(验证码标准链:读码后禁止刷新页面/点击验证码图,
  仅验证码错误时才点图刷新重读)、第 14 条(eval_js 用法/大结果引用 saved_to)、
  第 15 条(页面卫生 + 登录标准链 ≤6 次调用 + 迭代预算意识);

## 15. 第 117 轮(2026-09-22):HITL 扩展场景与覆盖增强

> 背景:第 100 轮 HITL 闭环上线后,实际业务(金融/政务/企业 SaaS)暴露出三类高频
> 人工阻断场景仅有 `manual_verify` 兜底,标签与文案都不可精准定位;
> 同时 LLM 反复在工具 description 中死记 reason 列表, prompt cache 命中率受冲击。
> 详细方案见 `03-扩展场景与覆盖增强方案.md`。本节仅列决策点与变更摘要。

### 15.1 增量 reason 与 blockers 关键词

- `request_human` 新增 3 个 reason:`real_name`(实名/认证/人脸核身)、
  `two_factor`(2FA/TOTP/邮箱验证码)、`oauth`(第三方授权/SSO);
- `inspect(info=blockers)` 模式表追加对应关键词,共覆盖 7 类人工拦截
  (原 4 类 + 新 3 类);
- 合法 reason 集中收口为常量 `HUMAN_ASSIST_ALLOWED_REASONS`,
  顺序 = 推荐使用顺序:高频 → 兜底。

### 15.2 `available_reasons` 公开合法 reason

- `inspect(info=blockers)` 响应新增 `data.available_reasons`(9 项),
  LLM 拿到 blockers 后可直接复用构造 `request_human.reason`,
  避免死记硬背 / prompt cache 失效;
- 非法 reason 错误响应增加 `data.allowed` 字段,
  LLM 在 1001 时可直接挑选下一个合法值。

### 15.3 三处对齐保证

- `src/agent/tools/mcp_web_use/control.rs`:`human_assist_defaults` 加 3 个 reason;
- `src/tui/dispatch.rs`:`human_assist_kind_label` 加 3 个 TUI 标签;
- `src/agent/system_prompt/mod.rs`:SubAgent-Work 第 16 条作业规范同步扩展。
- 单测断言:`human_assist_allowed_reasons_covers_extensions` 锁住顺序;
  `human_assist_reasons_doc_lists_all_variants` 锁住错误消息覆盖。
