# 18 - 多标签页感知与后台挂起治理

> 2026-10-13 · 实现:`src/agent/tools/mcp_web_use/page_activity.rs`(策略层唯一事实源)
> + `control.rs`/`inspect.rs`/`mod.rs`(list/close)接线;`browser.rs` 零改动。

## 1. 背景与问题

Agent 在真实 Chrome(headed / connect 接管用户浏览器)中工作时会不断产生标签页:

| 途径 | 既有处理 |
|------|----------|
| 主动开页:`open` / `control(new_tab)` | 注册表登记 page_id |
| 被动派生:点击 `target=_blank`、页面 JS `window.open`、按钮跳新页 | `adopt_spawned_pages` 收编 + `spawned_page_id` 回传;噪声页(about:blank / new-tab-page)自动关闭 |
| 人工开页 / 手动切换激活标签页 | **无感知**(异步发生) |

Chrome 的硬性行为:**一个窗口只有一个激活标签页,其余全部转后台挂起** ——
渲染暂停(截图 = 最后一次前台渲染的旧帧/空白)、`requestAnimationFrame` 停摆、
IntersectionObserver 不触发(懒加载内容不加载)、定时器被节流(launch 模式已带
`--disable-background-timer-throttling` 等参数缓解;connect 模式接管用户的浏览器
没有这些参数)。

此前 Agent 对「哪些页在后台」零感知:对后台页 `screenshot` 拿旧图当证据用;
`list` 只有 url/title 没有前后台状态;也没有「这页还要不要」的中间收口手段
(只有逐个 `close` 与 `close("all")` 两个极端)。

## 2. 设计

### 2.1 前后台探测(唯一事实源:页面自己报告,不缓存)

对目标页执行一次轻量 JS(正常毫秒级,2s 超时兜底,失败 fail-open 返回 None):

```js
JSON.stringify({v: document.visibilityState, f: document.hasFocus()})
```

`visibilityState === "visible"` ⇒ 该页是其窗口的当前激活标签页(前台);`"hidden"`
⇒ 后台挂起。要点:

- **不做缓存**:人工手动切页后,下一次操作/`list` 的即时探测立即反映新事实;
- 多窗口时每窗口各有一个前台页,均为 visible,如实呈现;
- headless 两档页面对 CDP 恒 visible ⇒ 闸门自然零命中,不添噪声。

### 2.2 后台挂起闸(6003)

`gate_visual_action` 是 control 与 inspect 视觉维度共用的闸门,决策序:

```
开关关闭 / 元操作 / 页面取不到 / 探测失败 / 已前台 ⇒ 放行(不标)
后台 + params.focus=true    ⇒ 先 Page.bringToFront 前台化,放行并标 brought_to_front
后台 + 视觉类 + 无 focus/force ⇒ 6003 拦截(动作不执行)
后台 + 非视觉类             ⇒ 放行,响应附 data.page_background 提示
```

- **视觉证据类**(`action_needs_foreground` / `info_needs_foreground`):
  `control(screenshot)`、`inspect(screenshot|ocr)` —— 截图依赖真实渲染,后台
  必然失真,属「运行正确性约束」,硬闸;
- **非视觉类**:DOM 读写 / CDP 输入 / 滚动等在后台页仍正确,放行 + 附提示
  (rAF/懒加载/定时器节流风险、超时时先 `bring_to_front`);
- **元操作永不闸**(`action_bypasses_gate`):`bring_to_front`(解法本身)、
  `set_guard`/`set_overlay`/`set_highlight`/`auto_follow`/`heartbeat`(状态设置)、
  `close_tab`(收口)、`request_human`(自带窗口置前);
- 逃生口:`params.focus=true`(自动前台化后执行)/ `params.force=true`(确认
  后台截图可用时强制,与 6002/4003 同款约定);
- 6003 信封 data 附 `page_background{visibility,focused,note}` +
  `required_action`(三选一对策)+ `human_note`(切换前台对人工观感的影响)。

**闸门顺序**:6002(人工核验硬闸)→ 4003(HITL 挂起)→ **6003(本闸)** ——
人工核验与页面所有权优先于前后台事实。

### 2.3 感知面(响应标注)

| 场景 | 标注 |
|------|------|
| 派生新标签页抢走前台,原页转后台 | 动作响应自动附 `data.page_background`(「新派生标签页已接管前台…」),Agent 当轮即知 |
| 非视觉动作落在后台页 | `data.page_background`(节流风险 + bring_to_front/focus 对策 + close 收口建议) |
| `focus=true` 前台化后执行 | `data.page_background.brought_to_front=true` |
| `list` | 逐页 `foreground: bool\|null`(即时探测)+ 顶层 `count`;页数 ≥6 附 `tabs_hint` 收口提醒 |

### 2.4 收口手段

- `close(page_id)`:既有,单页关闭;
- **`close(page_id="background")`**(新):批量关闭全部后台页。安全阀:
  - 探测失败的页**不可判定,跳过不关**(fail-safe);
  - **一个前台页都没探测到时整体拒绝**(窗口全最小化/主线程全卡死时防止一锅端);
  - 至少保留一个前台页,正常不会触发「最后一页回收浏览器」;
- `close(page_id="all")`:既有,全清场;
- `control(bring_to_front)`(新):标签页级前台化(`Page.bringToFront` + 复核
  `visibility_after`),与元素级 `focus`(聚焦页内输入元素)刻意区分。

### 2.5 与既有机制的正交性

- **guard 三档**:前后台是浏览器事实,管控是注入策略,互不干扰;`bring_to_front`
  只激活标签页,不触碰管控状态;人工切到 locked 页仍只能看不能点(设计行为);
- **HITL**:`request_human(bring_to_front=true)` 的窗口置前逻辑不变;4003 优先;
- **blocker_probe**:6002 硬闸在前;`page_background` 只是 data 字段,不参与
  blocker 判定;
- **adopt_spawned_pages**:噪声页关闭逻辑不变,本轮只加「原页转后台」标注。

## 3. 环境变量

| 变量 | 取值 | 行为 |
|------|------|------|
| `LAEW_WEB_BACKGROUND_GATE` | `off`/`0`/`false`/`no` | 关闭治理:6003 拦截、`page_background` 标注、`list` 的 foreground 探测与 tabs_hint 全部关闭(`bring_to_front` 动作与 `close(background)` 是纯能力,保留) |
| 未设置 | 默认开启 | 如上 |

## 4. 错误码

`6003` 归 6xxx「范围/人工核验约束」段(6001 任务锚点 / 6002 人工核验同家族):
不是页面出错(2xxx),而是「页面在后台,视觉证据必然失真」的硬事实 —— 模型
需要的不是换 selector 重试,而是前台化或收口。
