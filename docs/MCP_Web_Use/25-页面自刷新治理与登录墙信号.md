# 页面自刷新治理、登录墙信号与反爬指纹体检（第 172 轮）

> 场景来源：BOSS 直聘遍历任务实测（2026-10-14，`tmpPlan/20261014_164500_BOSS直聘页面自刷新与反爬识别治理方案.md`）
> 范围：`MCP_Web_Use` 工具面（open/navigate/inspect/control/request_human）+ 浏览器实例健康 + 隐身注入

## 一、问题

站点对「一次性全新 profile + 自动化浏览器」执行自杀式反爬：页面被**原地 reload** 或抹成空白页。实测证据：

- 页面静置 30s（期间零工具动作，仅一条 `control(wait, 30000)`）后 `performance.timeOrigin` 变化、页面全局标记丢失，URL/标题不变；
- 人工在 HITL 弹窗里输入的字符随文档销毁 → 连续 3 次 `request_human` 都被回「页面还是一直在刷新」；
- 用完全相同启动开关、**不接任何 CDP** 的纯 Chrome 同样被抹除，排除我方工具链与 CDP 附着。

叠加两个缺陷让 Agent 空转：

1. `control(navigate)` 只回报**请求** URL，服务端把页面 302 到登录页 / 302 回首页完全不可见（实测请求 `/web/geek/job?query=AI` 落地 `/web/user/`；请求 SEO 类目页落地首页，Agent 把首页推荐位卡片当职位列表抓取）；
2. 连接级失败（`oneshot canceled`）直泄漏给模型；且一次失败的 connect 会把「HTTP 探得到、WebSocket 已死」的实例写进全局单例，之后**连冷启动 `open` 也一律全灭**。

## 二、四个通用信号

| 信号 | 载体 | 触发 | 处置指引 |
| --- | --- | --- | --- |
| 登录墙 | `data.login_wall` | URL 登录语义 token（`/login` `/web/user` `/passport` `/authorize` `redirect=` …）或 DOM 登录形态（密码框 / 登录按钮文案且无会话标记） | 直接 `request_human(reason="login")`，禁止反复 navigate 试探 |
| 落地透明 | `requested_url` / `final_url` / `redirected` | navigate/back/forward/reload 恒附带 | 落地≠请求即 `redirected=true`，先读 `final_url` 再决策 |
| 页面不稳定 | `data.page_liveness` | 90s 滚动窗口内**站点自发**重载 ≥3 次，或 30s 内 ≥2 次 | 换稳定页面登录，或 `open(reuse_existing=true)`，**不要反复 reload** |
| 指纹体检 | `data.fingerprint.suspicious` | WebGL 兜底串 / `webdriver` 漏压 / 插件或语言为空 / `chrome.runtime` 缺失 / 通知权限异常 | 关键任务优先用真实浏览器指纹 |

## 三、关键设计点

1. **自发 vs 主动分离**：`page_liveness` 只统计「非 Agent 导航导致的文档身份变化」。`open`/`navigate`/`back`/`forward`/`reload` 收尾调 `enrich_after_navigation`（记主动），`inspect`/只读动作调 `enrich_after_read`（记自发）。否则站点本就爱 reload 的域会把自己的反爬 reload 误记到我方，统计失真。
2. **采样必须便宜**：单条 `eval_js` 读 `performance.timeOrigin` + `location.href`，每页 5s 节流；指纹全静态，同页 30s 采一次；全部 fail-open（超时/解析失败/页面不存在一律静默）。
3. **单次重载不告警**：站点正常的一次 SPA 重定向不该被打成不稳定，否则人工介入被无谓告警。阈值见 `page_liveness::judge`（纯函数，单测锁死）。
4. **告警必须出现在人工看得见的地方**：仅在响应里附带不够——HITL 是本页最需要准确判定的时刻，`request_human` 发出前采样一次，不稳定时把 ⚠️ 提示**前置到弹窗正文首行**（含改道建议），这一条直接消灭「输入不了」的体感。
5. **死句柄预防**：`new_page_impl` 入口对已注册句柄先活探（判据与 `browser_handle_alive` 一致，避免两套语义分叉），死了就地 `purge_browser`（`drop_dead_browser` 与此共用同一份清理语义），保证本次调用走真正的 launch/connect。
6. **连接级失败归一**：`is_connection_level_failure` 把 `oneshot canceled` / `Session with given id not found` / `Target closed` / `WebSocket` 等归一为可行动中文文案 + `retryable` + `remedy`，并就地 `drop_dead_browser()`，使「原样重试一次」真正能恢复。动作级失败（缺参数、page_id 失效、导航超时）不误判，避免徒增冷启动。
7. **指纹保真只补不改**：隐身脚本（第 174 轮起为 `browser_ns::FIDELITY_JS` 块，按档组合，见 `docs/MCP_Web_Use/26`）新增 WebGL 回填，**仅当页面读数是自动化兜底串**（`WebKit*` / `SwiftShader` / `software*` / 空）时才替换为与本机平台一致的 Apple/ANGLE/D3D11 串；读到真实串一律原样放行。只影响 `getParameter` 的字符串，不改渲染、不碰验证码与风控判定逻辑。杀开关 `LAEW_WEB_FINGERPRINT=off`。

## 四、明确不做（诚实边界）

- **不做验证码/打码平台绕过**：验证码是站点的访问控制手段，一律走 `request_human` 人工核验。
- **不做住宅代理池 / IP 轮换**：目的是规避第三方服务的 IP 级封禁判定。
- **不做协议逆向直调后端签名接口**：绕过客户端采集与访问控制。
- **不硬编码 zhipin.com**：全部判据均为形态级（URL token、DOM 结构、自重载节奏）。

被拦截时的合规改道只有两条：`open(reuse_existing=true)` 接管用户已登录的真实浏览器（connect 模式零注入、真实指纹），或请人工登录。
