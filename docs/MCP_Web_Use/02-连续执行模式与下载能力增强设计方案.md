## 1. 背景与调研结论

第 89 轮已经将 Chromium-WebUse Agent 降级为进程内 MCP 风格单工具:

```text
SubAgent-Work(LLM 多轮循环)
    └── MCP_Web_Use(action=...)
            └── BrowserManager(chromiumoxide / CDP)
                    └── Chrome / Edge / Chromium / Brave
```

外部 Agent 源码调研的两个关键结论在本轮继续成立:

1. **单工具 + action discriminator** 优于为每个浏览器动作注册独立工具。Hermes
   `computer_use`、OpenClaw/Playwright MCP 均采用类似范式,可降低 Schema token、
   提升缓存命中率,并把协议细节封在驱动层。
2. **浏览器自动化必须形成「探索 → 操作 → 验证」闭环**。a11y/DOM 快照优先,
   坐标与截图只作兜底;每一步副作用后要有 Console/Network/DOM/页面标题等证据。
   laew 当前没有独立 a11y snapshot 层,本轮以 `inspect(elements/dom/page_meta/
   console/network)` 作为等价探索面,并保持 selector 优先。

现状能力盘点:

| 能力 | 第 89 轮状态 | 本轮处理 |
| --- | --- | --- |
| Chrome/Edge/Chromium/Brave 启动与 CDP 接管 | 已有 | 保留 |
| 鼠标左键/右键/双击/拖拽/悬停/移动/滚动 | 已有 | 保留 |
| 键盘按键、组合键、顺序输入、文本输入 | 已有 | 保留 |
| 新 Tab、导航、历史、等待、eval_js | 已有 | 保留 |
| DOM / Elements / Console / Network / Storage / Cookie | 已有 | 保留 |
| 截图、上传、视口、事件分发 | 已有 | 保留 |
| `page_id` 与 `spawned_page_id` 生命周期 | 已有 | 连续模式自动传递与跟随 |
| 下载文件并返回真实落盘路径 | 缺失 | 新增 `control_action=download` |
| 一次执行明确动作链 | 缺失 | 新增 `action=sequence` |

## 2. 目标与非目标

### 2.1 目标

1. 保持现有单步调用协议完全兼容,不拆分工具、不更换依赖;
2. 增加 `control_action=download`,支持 URL 直下与点击页面下载控件两种触发方式,
   返回 CDP 事件确认后的绝对路径、字节数、guid、耗时;
3. 增加 `action=sequence`,支持最多 24 步批内执行,逐步返回结果;
4. 批内自动维护 `page_id` / `spawned_page_id`,支持 `$page_id`、`${page_id}`、
   `$spawned_page_id`、`${spawned_page_id}` 占位符;
5. 明确两种工作模式及混用策略,并把高风险动作排除在批处理外;
6. 单元测试 + 本地 Chrome 真浏览器冒烟测试覆盖。

### 2.2 非目标

- 不引入真实 JSON-RPC MCP 子进程,继续采用进程内 MCP 风格服务边界;
- 不替换 chromiumoxide,不自研 CDP WebSocket 层;
- 不在本轮新增浏览器 a11y tree/ref 体系,避免与现有 CSS selector 协议发生两套定位语义;
- 不提供下载文件内容自动总结,Agent 可用已有 Read 工具按返回路径读取;
- 不做支付/删除等高危操作自动审批,批处理提示词采取禁止策略。

## 3. 工作模式设计

### 3.1 单步执行模式(默认)

一次调用一个动作,适合:

- 未知页面第一次探索;
- selector 不确定、需要观察 DOM 后调整;
- 登录、支付、删除、确认提交、登出等高风险操作;
- 下载前需要确认目标链接语义;
- 调试 Console/Network/Storage。

```json
{
  "action": "open",
  "url": "https://example.com/",
  "mode": "hidden"
}
```

```json
{
  "action": "control",
  "page_id": "p_ab12cd34",
  "control_action": "click",
  "params": {"selector": "a.download"}
}
```

### 3.2 连续执行模式

先用单步 `inspect(elements/dom/console/network/page_meta)` 探索页面,再提交一批
已经确定的动作。适合:

- 流程稳定的表单填写与提交;
- 多页浏览、采集、截图;
- 输入 → 点击 → 等待 → 提取的固定链路;
- 需要减少 LLM 往返次数、提高执行效率的任务。

```json
{
  "action": "sequence",
  "stop_on_error": true,
  "steps": [
    {"action": "open", "url": "https://example.com/"},
    {"action": "inspect", "page_id": "$page_id", "info": "elements",
     "params": {"selector": "textarea", "include_text": true}},
    {"action": "control", "page_id": "$page_id", "control_action": "input_text",
     "params": {"selector": "textarea", "text": "你好 laew", "use_js": true}},
    {"action": "control", "page_id": "$page_id", "control_action": "click",
     "params": {"selector": "button[type=submit]"}},
    {"action": "control", "page_id": "$page_id", "control_action": "wait",
     "params": {"selector": "[class*=result]", "timeout_ms": 60000}},
    {"action": "inspect", "page_id": "$page_id", "info": "elements",
     "params": {"selector": "[class*=result]", "include_text": true}}
  ]
}
```

执行规则:

- `steps` 为 1~24 个对象,每项结构与单步调用一致;
- 禁止嵌套 `sequence`,避免不可控的指数级展开;
- `stop_on_error=true`(默认)时失败即停止;`false` 用于采集全量执行报告;
- 每步返回 `{index,action,code,message,data}`,顶层返回汇总、`failed_at`、
  最终 `page_id` 与最近 `spawned_page_id`;
- 步骤级 `follow_spawned=false` 可保持原标签页;默认点击派生新页后自动跟随,
  保证「点开链接 → 在新页继续操作」的连贯性。

### 3.3 混合使用

两种模式没有会话状态隔离,可以任意交替:

```text
单步 open → 单步 inspect(elements) → sequence(输入/点击/等待/提取)
          → 单步 inspect(network) → sequence(翻页采集)
          → 单步 close
```

当 `sequence` 中某一步失败,Agent 应读取该步 `data` 与页面状态,退回单步模式
修正 selector 或等待条件;修正后再提交新的批处理。

## 4. page_id 连贯性协议

`page_id` 是 LLM 可见但不透明的页面句柄,真实目标由 BrowserManager 注册表维护。

```text
open(url)
  └─ data.page_id = p_current

control(click / new_tab / target=_blank)
  ├─ 原页仍可继续使用 page_id=p_current
  └─ data.spawned_page_id = p_spawn

sequence
  ├─ $page_id          → 当前页(默认自动跟随 p_spawn)
  ├─ $spawned_page_id  → 最近派生页
  └─ data.page_id      → 批处理结束时的当前页
```

具体规则:

1. `open` 成功后,响应中的 `data.page_id` 成为批内当前页;
2. 普通动作未派生页面时当前页不变;
3. 动作响应携带 `spawned_page_id` 时记录最近派生页;默认当前页切换为该新页,
   下一步 `$page_id` 自动指向新页;
4. 该步骤设置 `follow_spawned=false` 时只记录 `$spawned_page_id`,不切换当前页;
5. `new_tab` 由 control 动作后 adopt 差集产生 `spawned_page_id`,同样遵循上述规则;
6. 关闭当前页后当前句柄清空;关闭非当前页不影响当前句柄;
7. 连续模式顶层最终返回 `page_id`,Agent 必须把它与 `action=list` 的页面索引合并。

## 5. 下载能力设计

### 5.1 API

```json
{
  "action": "control",
  "page_id": "p_ab12cd34",
  "control_action": "download",
  "params": {
    "url": "https://example.com/file.pdf",
    "save_dir": "/absolute/or/relative/dir",
    "filename": "report.pdf",
    "timeout_ms": 120000
  }
}
```

`url` 与 `selector` 二选一:

- `url`:在当前页面注入一次性隐藏 `<a download>` 并触发,适合已知下载地址;
- `selector`:点击页面上的下载链接或按钮,适合 URL 由前端脚本生成的场景。

参数:

| 参数 | 说明 |
| --- | --- |
| `save_dir` | 可选;相对路径以当前工作目录为基准,目录不存在自动创建;默认工作目录 |
| `filename` | 可选;仅允许文件名,自动取 `file_name()` 归一化,禁止路径穿越 |
| `timeout_ms` | 可选;0/缺省为 120000,范围 1000~300000 ms |

成功响应:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "guid": "...",
    "url": "https://example.com/file.pdf",
    "suggested_filename": "file.pdf",
    "save_path": "/absolute/path/report.pdf",
    "byte_size": 123456,
    "received_bytes": 123456,
    "total_bytes": 123456,
    "state": "completed",
    "elapsed_ms": 321
  }
}
```

### 5.2 CDP 实现链路

```text
1. 解析/创建 save_dir → canonicalize
2. Browser.setDownloadBehavior({
       behavior: "allowAndName",
       downloadPath: save_dir,
       eventsEnabled: true
   })
3. 注册 Browser.downloadWillBegin / Browser.downloadProgress 监听
4. selector.click() 或注入隐藏 anchor 触发下载
5. 等待 begin.guid
6. 过滤同 guid 的 progress,直到 completed/canceled 或超时
7. 校验 progress.filePath 或派生路径真实存在
8. filename 存在则安全重命名
9. stat 文件并返回绝对路径 + byte_size
```

关键防御:

- 先注册事件再触发,避免下载完成事件竞态丢失;
- `guid` 过滤,忽略并发浏览器下载;
- 下载状态非 completed 直接返回 2002,不以 HTTP 请求已发送冒充成功;
- Chrome 报告 completed 后仍必须检查文件存在;
- 自定义文件名只保留 `file_name()`,不允许 `../`、绝对路径或盘符穿越;
- CDP 返回路径优先,避免从 `suggestedFilename` 猜测 `allowAndName` 的 GUID 文件名。

## 6. 安全与稳定性

1. **批处理风险边界**:sequence 提升效率但不提升权限。支付、删除、确认提交、
   登出、批量邮件发送等不可逆动作必须单步执行并在动作后 inspect 验证。
2. **下载边界**:下载目录由调用参数显式指定;最终路径必须来自 CDP 或受限目录拼接。
   Agent 终答必须报告 `save_path` 与 `byte_size`,不得编造文件内容。
3. **页面句柄安全**:占位符只替换字符串字段,不执行表达式,不存在模板注入;
   `sequence` 不做递归展开。
4. **输出预算**:步骤上限 24;DOM/截图等高输出动作仍沿用原有截断与自动落盘策略。
5. **失败恢复**:单步失败保持现有错误码;连续模式逐步保留失败上下文,
   `stop_on_error=false` 时可完整观察哪些步骤成功、哪些失败。
6. **跨平台**:路径处理使用 `PathBuf`/`canonicalize`,CDP 事件与 chromiumoxide
   均适用 macOS/Windows/Linux;浏览器探测沿用既有 Chrome→Edge→Chromium→Brave 链。

## 7. 测试方案

### 7.1 无浏览器单元测试

- action 枚举包含 `sequence`;
- control_action 枚举包含 `download`,总数 35;
- 缺少 `steps`、空 `steps`、嵌套 `sequence` 均返回 1001;
- `$page_id` / `${page_id}` / `$spawned_page_id` / `${spawned_page_id}`
   递归替换正确;
- Schema 包含 `execution_mode`、`steps`、`stop_on_error`。

### 7.2 真浏览器冒烟测试

显式执行:

```bash
cargo test --test web_use_smoke -- --ignored
```

覆盖:

1. open/inspect/control 原有能力不回归;
2. sequence 批内输入、点击、等待、标题验证;
3. 本地 HTTP 服务返回 `Content-Disposition: attachment`;
4. `download` 通过 CDP 下载事件得到真实文件路径;
5. 自定义 `filename` 生效,文件内容与字节数准确;
6. close 幂等与浏览器回收不回归。
