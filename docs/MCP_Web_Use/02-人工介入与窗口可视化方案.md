# MCP_Web_Use 人工介入(HITL)与浏览器窗口可视化方案

> 版本:2026-09-22(第 100 轮基线 + 第 117 轮扩展场景)
> 适用平台:macOS / Windows(可视化桌面);Linux 行为一致(无桌面时人工介入退化为 TUI 问答)
> 实现入口:`src/agent/human_assist.rs` + `src/agent/browser.rs` + `src/agent/tools/mcp_web_use/`
> 关联文档:`01-设计与解决方案.md`(MCP_Web_Use 基础架构)

## 1. 背景与目标

Agent 用 MCP_Web_Use 自动化网页任务时,存在三类无法纯自动闭环的场景:

1. **人工验证阻断**:图形验证码、滑块拼图、短信验证码、扫码登录、人脸核身等,
   Agent 不应也不允许伪造或绕过;
2. **窗口可视化缺失**:默认 `hidden` 模式无窗口,人工想接管时看不到页面;
   可视化任务需要 1080p 窗口、可自由拖动改尺寸且渲染自适应、不缺区域;
3. **浏览器重复打开**:重试/多轮任务误启多个浏览器进程,干扰用户桌面。

本方案在既有单工具 action 架构上叠加**人工 + Agent 协同闭环**,参考外部调研
(`docs/Agent源码调研/专题/专题-第八轮-Tool权限策略引擎与沙箱设计深度对比.md` §8 HITL):

- atomcode `AskUserQuestion`:结构化问题(标题/选项/自由文本)→ 本方案 `request_human`;
- opencode `WorkerPendingPermission`:会话级请求队列防并发弹窗 → 本方案单 pending 槽位;
- claudecode 超时语义(默认 120s/上限 600s)→ 本方案默认 300s/上限 1800s;
- deepseek 4-outcome 审计 → 本方案 answered / timeout / cancelled / unavailable 四态。

## 2. 总体架构

```text
TUI(dispatch 阶段进度协程)                     Agent(SubAgent-Work LLM Loop)
  │ 250ms 轮询 poll()                            │ control_action=request_human
  │◄──────────────────────────────┐              │   bring_to_front + HumanAssistHub.request()
  │ 打印请求块(标题/说明/选项/页面)  │              │        │ oneshot 挂起等待
  │ stdin 读一行(cooked mode)      │              │        ▼
  │ respond(id, Some/None) ────────┼──────────────┘ tool_result 信封
  └ 任务结束后 cancel_pending() 兜底                code=0 answered / 4001 超时 / 4002 人工取消
```

关键决策:

- **进程内全局枢纽 `HumanAssistHub`**(OnceLock 单例)而非把 TUI 句柄传入工具层 ——
  Tool trait 无法感知调用方是否在 TUI 上下文,全局枢纽 + `attach()` 标记把
  「交互式 TUI」与「-p 管道模式」自然区分;
- **单 pending 槽位**:同一时刻最多一个人工请求;后到请求排队(等待前者 respond),
  对齐 opencode 队列语义的简化版,避免终端提示互相踩踏;
- **非 TTY(-p / 管道)fail-fast**:未 attach 时 `request` 立即返回不可用,
  工具回 `code=4001`,System Prompt 指引 LLM 终答告知用户改用 TUI 交互模式;
- **超时兜底**:默认 300s、上限 1800s(clamp);超时同 4001;
  TUI 侧阻塞读 stdin 可能残留(等待用户下一次输入时被消费并丢弃),属可接受的 v1 折衷。

## 3. 工具面新增能力

### 3.1 control_action=request_human(人工介入请求)

```json
{
  "action": "control",
  "page_id": "p_ab12cd34",
  "control_action": "request_human",
  "params": {
    "reason": "captcha",
    "message": "页面出现滑块验证,请人工完成验证后告诉我",
    "options": ["我已完成验证,继续", "跳过此页面", "取消任务"],
    "timeout_ms": 300000,
    "bring_to_front": true
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `reason` | 9 个合法值:captcha(图形/滑块) / sms(短信验证码) / qr_login(扫码登录) / login(账密墙) / **real_name(实名/认证/人脸核身,第 117 轮新增)** / **two_factor(2FA/TOTP/邮箱验证码,第 117 轮新增)** / **oauth(第三方授权/SSO,第 117 轮新增)** / manual_verify(人工核验) / custom(自定义)。决定默认文案与 TUI 标签。完整列表见 `inspect(info=blockers)` 响应字段 `available_reasons`(LLM 拿到后可直接复用,避免死记硬背)。 |
| `message` | 给人看的具体说明(缺省按 reason 生成默认文案) |
| `options` | 1~6 个选项;TUI 渲染编号列表,回车默认选 1 |
| `timeout_ms` | 默认 300000,clamp 10s~1800s |
| `bring_to_front` | 默认 true:先 `Page.bringToFront()` 把浏览器标签页/窗口带到前台,人工可见 |

返回信封:

| code | 语义 | Agent 策略 |
| --- | --- | --- |
| 0 | `data.human_response` 为人工输入(选项文本或自由文本,如短信验证码数字) | 按回答继续任务(填入验证码 / 检查页面状态) |
| 4001 | 无人应答(超时 / 非 TUI 交互模式) | 如实告知用户「请在 laew TUI 交互模式下重试」,不得伪造结果 |
| 4002 | 人工明确取消(输入 q/取消) | 终止该浏览器路径,汇总已完成部分向用户报告 |

### 3.2 inspect info=blockers(阻断自动检测)

启发式扫描 `document.body.innerText`(截取前 20k 字符),Rust 侧模式表匹配:

| 模式 | kind |
| --- | --- |
| captcha / 验证码 / 滑块 / 拖动滑块 / puzzle / reCAPTCHA | captcha |
| 短信验证码 / 手机验证码 / 手机验证码 / sms code | sms |
| 扫码 / 二维码 / QR Code 登录 | qr_login |
| 请登录 / 登录后查看 / sign in / 逐梦正常登录 | login |
| 实名认证 / 身份认证 / 人脸核身 / 上传身份证 / kyc(第 117 轮新增) | real_name |
| 两步验证 / 双重验证 / 2FA / TOTP / 邮箱验证码 / google authenticator(第 117 轮新增) | two_factor |
| 微信授权 / github 授权 / 使用 github / continue with / sso 登录(第 117 轮新增) | oauth |

返回 `{blockers:[{kind,snippet}],suggested_action:"request_human"}`,
作为 SubAgent 判定「无法自动跳过 → 请求人工」的确定性依据(LLM 仍可结合上下文覆盖)。

### 3.3 窗口与视口(control_action 扩展)

| control_action | 参数 | 说明 |
| --- | --- | --- |
| `set_window` | `width`/`height`/`left`/`top`/`window_state`(normal/maximized/fullscreen) | CDP `Browser.getWindowForTarget` + `Browser.setWindowBounds` 运行时调整真实窗口;调整后自动清除视口覆盖,保证渲染=窗口、不缺区域 |
| `sync_viewport` | 无 | `Emulation.clearDeviceMetricsOverride` + 回读 innerWidth/innerHeight;人工拖动窗口大小后调用,使视口自适应窗口,消除黑边/缺区域/渲染不全 |
| `set_highlight` | `enabled`(默认 true) | 运行时开关 Agent 高亮蓝框 |

`open` 新参数:

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `window_width` / `window_height` | headed=1920×1080(1080p),hidden=1440×900 | 启动时 `--window-size`(clamp 320~7680 / 240~4320);浏览器已存在时仅记录请求值,响应带 hint |
| `highlight` | true(仅 headed 生效) | 注入 Agent 高亮蓝框(见 §4) |

浏览器生命周期强化(**不重复打开浏览器**):

- BrowserManager 进程内单例 + 单浏览器实例语义保持;`open` 时若浏览器已存在,
  **永远复用同一实例**(同 URL 页面还走既有 reuse 复用),响应新增 `browser_reused:true`
  与实际 `mode`;请求 mode 与现有实例不一致时不新启进程,返回 `mode_hint` 说明;
- 需要从 hidden 切换到 headed 可视化时:Agent 先 `close(page_id="all")` 回收浏览器,
  再以 `mode=headed` 重开;`request_human` 的 System Prompt 指引已包含该路径。

## 4. Agent 高亮蓝框(可视化标识)

人工介入场景下,桌面上可能有多个浏览器窗口,人必须一眼识别「哪个窗口被 Agent 控制」。
headed 模式注入页面级 overlay(`Page.addScriptToEvaluateOnNewDocument` + 立即执行,
派生/adopt 的新标签页同样注入):

- `#__laew_agent_frame__`:fixed inset:0、`box-shadow: inset 0 0 0 3px #1a73e8`
  (Chrome 品牌蓝)、`pointer-events:none`、`z-index:2147483647`、`data-laew-agent="1"`
  —— 页面四周一圈蓝色选中效果,不拦截任何鼠标/键盘事件,渲染与普通浏览器一致;
- `#__laew_agent_badge__`:右上角「LAEW Agent 控制中」小徽标,蓝底白字,
  `pointer-events:none`;
- `elements`/`dom` 提取自动过滤 `[data-laew-agent]` 子树,不污染 Agent 的 DOM 观察;
- 截图/OCR 保留蓝框(人视场景需要;LLM 视觉路径不受影响的优先级低于人工识别)。

## 5. TUI 交互流程(dispatch 集成)

阶段进度协程(`dispatch_prompt` 内)新增 250ms 轮询分支:

```text
┌─ 🔐 人工介入请求 ────────────────────────────────
│ 类型: 图形/滑块验证码   页面: https://xxx/login
│ 说明: 页面出现滑块验证,请人工完成验证后告诉我
│ 选项:
│   1. 我已完成验证,继续
│   2. 取消任务
└──────────────────────────────────────────────
请输入选项编号或直接输入内容(回车=1,q=取消):
```

- 终端此时处于 cooked mode(任务执行期 InputHandler 未占用 stdin),直接行读;
- 映射:空回车 → 选项 1;数字 → 对应选项;`q`/`取消` → respond(None)(→4002);
  其余原文作为自由文本返回(短信验证码数字即走此路径);
- 任务结束(无论成败)调用 `cancel_pending()` 兜底,防挂起请求跨任务泄漏。

## 7. System Prompt 作业规范(摘录)

第 100 轮基线:打开页面后如遇登录/验证墙,先 `inspect(info=blockers)` 判定;OCR 可读的图形验证码走既有第 13 条自动链;**滑块/短信/扫码/人脸等无法自动完成的,必须 `control_action=request_human`(可视化场景建议先 open mode=headed 让人工看到窗口),严禁伪造或跳过**;`code=0` 用 `human_response` 继续;`4001` 如实报告需 TUI 交互模式;`4002` 终止路径;可视化任务用 `mode=headed` + 1080p,人工拖动窗口后 `sync_viewport` 自适应,蓝框高亮标识 Agent 窗口不要尝试移除;需要窗口切换 hidden→headed 时:close all → headed 重开(登录态丢失需重新处理)。

第 117 轮扩展:除原有 reason(captcha/sms/qr_login/login)外,以下三类场景
必须走对应专用 reason,不要退化到 `manual_verify`:

- **实名/人脸核身** —— `reason=real_name`;可视化场景必开 headed(摄像头/上传
  控件在页面)。
- **2FA / TOTP / 邮箱验证码** —— `reason=two_factor`;人工拿到动态码后直接在 TUI
  自由文本回复,Agent 走 `input_text` 填入。
- **第三方 OAuth / 授权** —— `reason=oauth`;Agent 先 `bring_to_front` 让授权页可见,
  人工点"授权/Agree"后 `inspect` 验证 URL 是否回到预期域名。

合法 reason 列表以 `inspect(info=blockers).available_reasons` 为准,避免硬编码。


真浏览器人工验证(macOS/Windows):

1. `open(url, mode=headed)` → 窗口 1920×1080、四周蓝色高亮、右上角徽标;
2. 人工拖动窗口 → `control(sync_viewport)` → viewport=窗口内容区,截图无缺区域;
3. `control(set_window, width=1280,height=720)` → 窗口真实缩放;
4. 触发滑块/短信页 → `control(request_human)` → TUI 出现选择块 → 输入 → Agent 继续;
5. 连续 `open` 多次 → `browser_reused:true`,系统仅一个浏览器进程;
6. `set_highlight(enabled=false)` → 蓝框消失。
