## 1. 注入 JS 两处恒 SyntaxError(W1/W2)

| 缺陷 | 形态 | 修复 |
|---|---|---|
| `control(wait, selector=…)` | 模板生成 `async () => {…}()` —— 箭头函数块体后紧跟调用括号是 JS 语法错误,**每次** wait(selector) 都 2002 `SyntaxError: Unexpected token '('` | 整体包裹 `(async () => {…})()`;抽纯函数 `control.rs::wait_selector_js` |
| `inspect(info=dom)` 全量树 | 对象字面量内 `attributes: {};` 多一个分号,**每次**都 2002 `SyntaxError: Unexpected token ';'` | 去分号;抽纯函数 `inspect.rs::dom_tree_js` |

两处均有字符串级单测锁死(`tests.rs::wait_selector_js_is_wrapped_arrow_call` /
`dom_tree_js_no_stray_semicolon_in_literal`)。云智眼复测:wait 返回正常超时语义、
dom 返回 `{"document":{…},"node_count":1}`。

## 2. 首启空标签页(W4)

launch 不带初始 URL,Chrome 必开一个 `about:blank`/`chrome://newtab` 初始页签 ——
用户看到「先空页签后目标页签」;残留页后续还会被 `adopt_spawned_pages` 收编成伪
`spawned_page_id`(142751 日志 line 123/131,reload 后多出 `chrome://new-tab-page` 页)。

修复:`BrowserManager::new_page` 在**首次 launch**(launch 模式,connect 不碰用户标签页)
注册完本页后清扫:浏览器内不在注册表且 `is_noise_url` 命中(URL 判定,**不看标题** ——
初始页签加载早期 URL 可能还是 about:blank、标题已非空,走 `is_noise_page` 的标题豁免
会漏杀)的 target 直接 close。真实站点 URL 永不命中 `is_noise_url`,无误伤面。
清扫结果(含 `target_count`)写 INFO 日志可对账;CDP `/json` 复测浏览器内只剩目标页。

## 3. 空白页根因分析(W3 + W6,回答「是否自签名证书/自定义域名有关」)

逐层排除后的结论:**与自签名证书、自定义域名、LNA 拦截均无关,是站点 WAF 对自动化
客户端返回 HTTP 400 + 空 HTML**。证据链:

1. 文档 `readyState=complete` 但 `head:"" / bodyLen:0 / scripts:0 / title:""`;
2. 启动参数已剔除 `--enable-automation`(chromiumoxide DEFAULT_ARGS 携带,
   `navigator.webdriver=true` 是 WAF 反爬首选指纹)+ `--disable-blink-features=AutomationControlled`
   + `--ignore-certificate-errors`(排除证书 interstitial)+ `--disable-features` 禁
   LocalNetworkAccess/PrivateNetworkAccess 系列(排除 Chrome 154「公网域名→私网 IP」
   子资源静默拦截)——页面依旧 400 空;
3. **主文档请求进 Network 缓冲后证据直接可见**:`GET /yunzhiyan-manager/login →
   response status:400, mime:text/html`(第 159 轮前 goto 之后才 enable Network,
   主文档请求完全不可见,Agent 只能猜「服务端返回空」烧掉十几轮迭代)。

配套能力:
- **启动参数矩阵重构**(全模式 `disable_default_args` + 自选集,详见
  `browser.rs` launch 段注释):反自动化指纹 + 证书宽松 + LNA/PNA 禁用一次到位;
  hidden 模式原有 `--disable-gpu/--no-sandbox/--disable-dev-shm-usage/--hide-scrollbars` 保持。
- **Network 域先于 goto 开启**:`new_page` 中 enable Runtime/Network + 挂监听移到
  `goto` 之前,主文档的请求/响应/失败从第一跳就进环形缓冲。
- **`Network.loadingFailed` 采集**(W6):事件缓冲新增该监听(`error_text`/
  `blocked_reason`/`canceled`),LNA/客户端拦截类空白页从此有直接证据可报。

## 4. 页面句柄自愈(W5,人工地址栏导航后「全面失效」根治)

注册表里的 `PageEntry.page` 是一次性握手句柄;人工在地址栏回车导航等场景会让 CDP
会话掉线(`Session with given id not found` 类),旧实现后续所有 control/inspect
永久 2002。

- `BrowserManager::ensure_page_alive(page_id)`:先探活(`page.url()`,不经过页面
  主线程),失效走 `heal_page`;
- `heal_page`:按 `target_id` 重新 `browser.pages()` 解析同 target,重建 entry
  (Runtime/Network 域 + 事件监听 + 高亮/管控/跟随器按实例期望态重注入),target
  已不存在返回 None(沿用 2000「page_id 不存在」);
- 工具层 `ensure_page` 改走 `ensure_page_alive`,全部 control/inspect/sequence
  动作自动获得自愈。
