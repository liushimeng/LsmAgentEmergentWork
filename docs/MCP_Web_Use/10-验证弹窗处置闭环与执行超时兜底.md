# 10 — 验证弹窗处置闭环与执行超时兜底(第 150 轮)

> 事故:`--debug` 实测豆包任务(`llaew_20261010_163036.log`),发送对话消息后豆包弹出
> **拖拽图片人工验证**,Agent 无感知继续批量输入,随后整个 `MCP_Web_Use sequence`
> **56 秒无返回**,用户 Ctrl-C 后进程又卡 10 秒被终端守卫强杀。
> 方案:`tmpPlan/2026-10-10_01-验证弹窗处置闭环与执行超时兜底.md`。

## 1. 三层根因

| # | 根因 | 位置 |
|---|------|------|
| R1 | `eval_js` 裸 await 零超时:验证弹窗拖住页面主线程后 `Runtime.evaluate` 响应永不返回 | `control.rs::act_eval_js`、`mod.rs::eval_js_string` |
| R2 | `sequence` 无步级防护:步间不查取消、单步无时长预算、`blocker_alert` 被吞在卡死的整批里不可见 | `mod.rs::run_sequence` |
| R3 | 拖拽类验证探针盲区:canvas 渲染的主文档拼图验证,旧打分制无 canvas 结构信号(2 分 < 阈值 3) | `blocker_probe.rs::detect_challenge` |

## 2. 四层设防(F1–F4)

### F1 eval 统一超时兜底(治 R1)

- `eval_js_string`:包 `tokio::time::timeout`,默认 **30s**,
  环境变量 **`LAEW_WEB_EVAL_TIMEOUT_MS`** 可覆盖(0/非法回退默认)。
- `act_eval_js`:支持显式 **`params.timeout_ms`**(上限 120s,对齐 `wait` 的 120s 上限);
  缺省按 `await_promise` 分档(true=60s / false=30s)。
- 超时错误统一附处置指引(`EVAL_TIMEOUT_HINT`):inspect(blockers) / screenshot(ocr) /
  request_human(reason=captcha) —— 把模型推回「感知-人工」闭环而不是原地重试。

### F2 sequence 步级防护(治 R2)

- **步间取消探测**:每步执行前查 `shutdown::global().is_triggered()`(同步零成本),
  命中即中断整批,返回 `code=4999` 取消信封(SIGINT 止血,不等外层 select drop)。
- **单步时长预算**:每步包 `tokio::time::timeout(150s)`(最后防线);
  **`request_human` 步豁免**(人工介入合法长等待,HITL 自身 30 分钟上限)。
  超时按步骤错误(2002)处理,尊重 `stop_on_error`。
- **blocker_alert 立即中断**(优先级高于 `stop_on_error`):任一步数据带
  `blocker_alert` 即停止后续步骤,顶层 data 透出 `interrupted_by:"blocker_alert"`
  + `blocker_alert` / `human_assist` / `next_action` 完整载荷 —— LLM 当轮即见
  「发起 request_human → 人工完成验证 → 交棒后续跑」。

### F3 拖拽类验证探针补强(治 R3)

- `detect_challenge` 打分新增:**`canvas_count ≥ 1` → +2**(主文档 canvas 拼图/滑块);
  弱词表补「拖拽」。命中组合:canvas(2)+弱词(1)=3;canvas 单独(2)不命中;
  广告负信号 −3 压制不变(防 canvas 抽奖转盘误报)。

### F4 工具说明与处置闭环引导

- description 补充:eval_js `timeout_ms` 参数与分档超时;sequence 的
  blocker_alert 中断语义与「收到即 request_human」要求;引导用 `control(wait)`
  等待 AI 站点回复,禁止无超时轮询堆批。

## 3. 边界(不改什么)

- HITL 弹窗本体、页面管控三档、blocker 探针推送时机(第 147 轮语义)不动。
- `request_human` 不进步长预算;`wait` 的 30s/120s 语义不动。
- 外层 `exec_tool_call` 的取消竞争保留 —— F2 的步间探测是不依赖 drop 的第二道。

## 4. 实测要点(本轮事故对照)
