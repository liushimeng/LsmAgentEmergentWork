# 39 — 首航 UA 裸令牌竞态根治：启动期产品名切换 + 无探针通道 + 结算闸（第 185 轮）

## 一、背景

第 178 轮（doc 32）把建页起点改成 `about:blank` + goto 单加载，根治了「目标 URL 被
请求 2 次、首个文档全程裸奔」的首文档盲区；第 183 轮（doc 37）给 UA 去令牌的
`Skipped` 分支补了落地后兜底。第 36 号文档 §五记录了一个**已知遗留**：

> `stealth_first_document_single_load_smoke` 在 Windows 全文件连跑时偶发 req#1 带
> `HeadlessChrome` 令牌（干净 HEAD 三轮一败复现，UA 覆盖与首请求的毫秒级竞态）。

本轮把该遗留从「记录待办」打到「根因定位 + 分层处置」。

## 二、根因（真机二分实证）

对压测失败现场逐层插桩 + 裸 repro 对照（同机 Chrome 155 / new headless），事实链：

1. **getVersion 产品名存在启动期切换**：launch 后立即读恒为
   `HeadlessChrome/155.0.0.0`（裸 repro 12/12）；安静环境 ~1s 后切换为常规
   `Chrome/…`（干净）；**Chrome 启停背靠背时切换可被拖长甚至超过 11s**。
   「new headless 永久掩码」与「永久裸令牌」两种推测均被推翻——它是**时间窗**。
2. **切换前发出的主文档请求一律裸令牌**，且与 CDP 命令序无关：同页同会话、
   `setUserAgentOverride` ack 后（甚至二次覆盖、插 renderer 结算评估、插拒连结算
   跳转后）立刻 goto，req#1 仍偶发 `HeadlessChrome`——仿真覆盖的浏览器侧落位与
   启动期繁忙管道竞争，ack ≠ 网络层生效；页面侧 `navigator.userAgent` 已干净而
   网络侧缺席的「两层管道分叉」实测存在（覆盖/不覆盖 A/B 矩阵：不覆盖 0/8、
   覆盖 4/8~8/12，随覆盖前管线工作量递增）。
3. **测试连跑的诱发环境是启停竞争**：断言失败 → 孤儿 Chrome → 下一用例在其
   进程收尾中启动 → 切换窗口被拖长。串行安静跑 6/6 恒过。

结论：req#1 UA 由「产品名切换窗口 + 仿真覆盖网络层落位」两个浏览器内部异步事件
决定，CDP 命令排序无法约束；**能确定性控制的是时序——等切换完成再导航**。

## 三、设计（分层处置）

1. **启动期切换等待（根治层，launch 块）**：轮询 `Browser.getVersion` 直至 UA 不再
   含无头令牌（切换完成）再放行后续导航。切换后 UA 本就干净，去令牌各通道**零
   动作零伪造**；这是唯一确定性 layer。预算 ~11s（90 × 1s 有界 + 100ms），常态
   <1s。预算耗尽仍带令牌（老式无头/极端竞争）才进入兜底链。
2. **首航无探针剥离通道（兜底层，第 180 轮通道扩展）**：`first_nav_ua_strip` 纯函数
   用缓存的浏览器级 UA 预剥离令牌（字面替换，零伪造），goto 前**同步 await** 下发
   string-only 覆盖；不再依赖 about:blank 页面探针（其 `Runtime.evaluate` 排在
   handler 事件循环上，冷启动/竞争下实测拖到超时 → Skipped → req#1 裸奔）。缓存
   缺失时现场补探（3 × 3s，不依赖页面上下文）。
3. **页面可见结算闸（观测层，`await_ua_override_visible`）**：覆盖下发后轮询
   `navigator.userAgent` 直至干净（12 × 1s + 50ms 预算，fail-open 放行）。渲染进程
   消费仿真状态滞后于 ack，此闸保证 document-start 的页面侧读数（风控 SDK 采样
   源）干净；同时它天然的 renderer 往返为网络层落位争取时间。
4. **网络侧结算导航（冲刷层）**：string-only 覆盖后、真实 goto 前，向
   `127.0.0.1:1`（无监听，连接即拒，<100ms，对目标站点不可见）发一次结算跳转，
   冲刷 NetworkContext 管道。压测实测将其从 3/10 提升到 7/10（未根治，但与 1/2/3
   叠加后作为纵深保留）。
5. **落地后 Full 补全（178 轮链路不变）**：安全上下文探真值 → 品牌表
   `userAgentMetadata` 补全，同样过结算闸。

测试侧配套（`stealth_reveal_smoke.rs`）：首文档用例改为**先收口后断言**（断言失败
也绝不留孤儿 Chrome 诱发下一用例的启停竞争），全部用例 `close(all)` 后
`quiesce_after_browser_close()` 静默 3s，把用例间浏览器生命周期彻底隔开。

## 四、验证

1. **单测**（`cargo test --lib`）：2433 全绿，新增
   `stealth::首航无探针剥离三态`（带令牌→剥离串/干净→None/无缓存→None）。
2. **A/B 矩阵**（插桩二分 + 裸 repro 12 实例，同机 Chrome 155）：完全不覆盖 0/8、
   仅字符串覆盖 4/8、覆盖+页面可见结算闸 6/8、再叠加拒连结算跳转 7/10、二次覆盖
   无增量（8/12，已回退）——证明网络层落位竞争无法靠重复下发根治，时序等待才是
   确定性手段。
3. **终态实测**（`cargo test --test stealth_reveal_smoke -- --ignored`）：串行
   （`--test-threads=1`）**4/4 通过**（req#1 UA 干净、页面侧读数干净、其余三用例
   全绿）；默认并行测试连跑（启停竞争环境）2/3，唯一失败样本为 req#1 裸令牌 ——
   即 §五记录的 Chrome 内部竞态残差。修复前同环境基线为「干净 HEAD 三轮一败」。
4. **环境守卫**：首文档用例断言全部后置到 `close(all)` 之后（失败不留孤儿
   Chrome），用例间静默 3s，`eval_js` 空结果有界重试 3 次；页面被系统回收
   （2002 环境性页面死亡）时跳过页面侧断言并留痕，请求级断言始终严格。

## 五、诚实边界（不变）

仍是「移除自动化环境的泄漏读数」：剥离规则是字面替换，取值全部真值；等待切换
窗口是时序治理，不是伪造。Canvas/字体伪造、行为仿真、IP 代理、打码、协议逆向
依旧一律不做；被拦时的唯一合规改道仍是 `open(reuse_existing=true)` 接管用户
已登录的真实浏览器。**已知残差**：启停背靠背竞争（测试连跑/同机多浏览器同时启停）把产品名切换
窗口与仿真覆盖的网络层落位同时拖入长窗时，req#1 仍可能裸令牌（终态实测并行
连跑 2/3，串行 4/4）——根因在 Chrome 浏览器进程内部异步时序，CDP 层无确定性
手段，与 36 §五「毫秒级竞态」同一性质，已从「无解偶发」收敛为「已知窄环境
残差」。生产形态（单浏览器长会话、分钟级启停间隔）不触发该环境。测试侧已做
环境守卫（断言后置/用例间静默/空结果重试/环境性页面死亡跳过），失败样本可
一眼归类。devicePixelRatio 与 `screen.avail*`、派生页首文档 document-start
提交门等历轮残差不增不减。
