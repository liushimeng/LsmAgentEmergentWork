## 2. 屏蔽完整性(`browser_overlay.rs`)

### 2.1 锁定态 CSS 层

`AGENT_GUARD_JS_TEMPLATE` 新增 `applyLockCss()`:`mode==='locked' && !视觉挂起 && !输入挂起`
时给根元素加 `__laew_locked__` class 并注入 `<style id="__laew_guard_style__">`:

```css
html.__laew_locked__ *{cursor:not-allowed !important;user-select:none !important;-webkit-user-select:none !important;}
```

- **悬停任何组件光标 ⃠**:按钮/链接的 `cursor:pointer` 被 `!important` 盖掉 —— 「不可点击」视觉态;
- **禁选**:拖选、双击选、Ctrl+A 一律失效;`GATE_EVTS` 增 `selectstart` 作事件层双保险;
- **挂起联动**:`__laewGuardInputSuspend`(Agent 输入动作「先解后锁」)/`__laewGuardSuspend`(截图避让)都会调 `applyLockCss()` 复算 —— Agent 操作期间 CSS 锁与事件闸同步放开,收口自动复锁(需求 2);
- open/partial 不上全局锁;partial **盾罩** cssText 增 `cursor:not-allowed`(悬停盾区=不可点光标),白名单洞内保持原生交互;
- `__laewGuardOff` 卸载时移除 style 元素与 class(与既有版本化重装兼容)。

与 locked 滚动观看(doc 13)正交:`wheel/scroll/mousemove` 仍不拦,人工照常翻阅;`LAEW_WEB_LOCKED_SCROLL=off` 回退 CDP 拦截时 CSS 锁照常生效(选中/光标层与输入拦截层正交)。

## 3. 焦点租约(`browser_focus.rs`)

### 3.1 洞察与策略

CDP 操作**全部不需要 Chrome 有 OS 键盘焦点** —— `Page.bringToFront` 连带激活窗口抢焦点是副作用。`LAEW_WEB_FOCUS` 三档:

| 档 | 行为 |
|----|------|
| `keep`(**缺省**) | 借焦速还:置前走「抬升不抢焦」;open / bring_to_front / 6003 focus=true / request_human 四处自动抢焦点点位走 `FocusLease`(动作前快照前台应用 → 收口归还) |
| `always` | 旧行为:`Page.bringToFront` 置前激活、不归还(适合全程盯屏观看) |
| `never` | 完全不碰焦点(`request_human` 的 bring_to_front 仍执行 —— 人工要能看到页面) |

**自平衡性质**:快照的是「抢焦前的前台应用」——用户本来就在盯 Chrome 时快照=Chrome,归还=无操作;用户在微信打字时快照=微信,Chrome 办完事立刻把键盘焦点还回去。

### 3.2 实现要点

- **快照/归还**:macOS `osascript System Events`(与 `macos_legacy::bring_to_front` 激活原语同款);Windows PowerShell `GetForegroundWindow`/`SetForegroundWindow` 一行式;Linux no-op(fail-open)。全走系统工具子进程、零新 crate、不做 cfg 门控 FFI(ring 阻断 msvc 交叉 check,门控 FFI 无法在本机编译验证 —— 「cargo fix 跨平台陷阱」教训)。
- **抬升不抢焦** `raise_window_no_activate(pid)`:macOS `System Events … AXRaise`(只调窗口层级不激活应用);Windows `SetWindowPos(HWND_TOP, SWP_NOACTIVATE)`。失败 fail-open,**不回退成抢焦点**(`always` 档才走激活)。pid 来自 `browser::peek_browser_pid()`(launch 模式登记;connect 模式零干预不抬升)。
- **租约接入点**:
  | 点位 | 时机 |
  |------|------|
  | `run_open`(含 reuse/connect 分支) | 入口 capture → 全链收口 release(覆盖 Chrome 启动抢焦 + F2 置前) |
  | `browser_window::activate_headed_window` | keep=抬升不抢焦 / always=现行为 / never=跳过 |
  | `control(bring_to_front)` | capture → 前台化 → 复核 → release,响应附 `focus_restored` |
  | 6003 `params.focus=true` | capture → 前台化 → release(后续截图不耗焦点,借焦窗口≈百毫秒),note 附 `focus_restored` |
  | `act_request_human` | bring 前 capture;**提问结束**(outcome 到手 + 管控恢复完)release —— 提问期间焦点归弹窗/人工 |
- 全部 fail-open:焦点归还失败只 debug,不改变任何工具 code/语义。

### 3.3 取舍(明确的边界)

归还焦点会激活原应用,其窗口盖回 Chrome(z-order)。「人工全程盯屏观看」与「人工在别处打字不被打断」在 macOS 窗口模型下不可兼得,本设计按用户需求 3/4 取后者;要看页面用 `LAEW_WEB_FOCUS=always` 或人工自己点一下 Chrome(此后快照=Chrome,归还无操作)。macOS 抬升需辅助功能权限(System Events),无权限时窗口可能不开在最前 —— fail-open,不抢焦点。

## 4. 操作节奏(提示词层)

- `MCP_WEB_USE_DESCRIPTION` 增【焦点与操作节奏】:CDP 操作不需要键盘焦点,日常不调 bring_to_front;置前/人工介入是注意力被占用时刻,先 explore/inspect 规划、再 sequence/batch 一次打包,避免逐步置前逐步试错打断人工。
- `system_prompt/mod.rs` MCP_WEB_USE 段增第 21 条「焦点纪律」(中等刚性:默认如此 + 例外需理由;不写禁令式措辞、不写轮次沿革)。
