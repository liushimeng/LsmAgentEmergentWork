# 06 复用已登录浏览器会话(connect 模式增强,第 142 轮)

> 状态:2026-10-10 实现。关联文档:`01-设计与解决方案.md`(工具主设计)、
> `docs/浏览器CDP工具/Rust操作Chrome浏览器CDP完整技术方案.md`(launch vs connect
> 原始技术方案)。实现:`src/agent/browser_reuse.rs` + `src/agent/browser.rs`
> (connect 分支) + `src/agent/tools/mcp_web_use/mod.rs` (`run_open_reuse`)。

## 1. 背景与问题

### 1.1 场景

macOS / Windows 上,用户已在本机 Chrome 打开某网站并**账号密码登录完毕**
(邮箱、电商后台、AI 网站、内部系统等)。随后用户给 Agent 一个任务,需要
操作这些**已登录**的页面。

### 1.2 现状与缺口

`MCP_Web_Use` 的 CDP 驱动层(`src/agent/browser.rs`)早有 connect 分支:
`open` 传 `connect_url` 时走 `Browser::connect()` 接管外部浏览器,不拥有
进程、`close` 只断连。但存在四个缺口:

1. **无自动探测**:`connect_url` 要 LLM 显式传 `http://127.0.0.1:9222`,
   而 LLM 不知道用户是否已用 `--remote-debugging-port` 启动 Chrome,几乎
   从不主动传;探测逻辑完全缺失。
2. **无引导**:探测/连接失败只返回 2001 错误文本,Agent 不知道「用户需要
   用调试参数重启 Chrome」这一步,只能如实报告失败。
3. **Chrome 136+ 默认 profile 限制**:Chrome 136 起 `--remote-debugging-port`
   在**默认 user-data-dir 上被静默忽略**(安全策略)。用户日常 Chrome 用
   默认 profile,直接加调试端口无效;必须用独立 `--user-data-dir`,而独立
   profile **没有登录态**——这是「复用已登录浏览器」的核心矛盾。
4. **接管场景的注入语义未定义**:connect 模式若按默认参数注入可视化蒙层
   (overlay),会**锁定用户自己正在使用的浏览器输入**;`mode` 字段也应是
   「接管外部浏览器」而非请求值。

### 1.3 设计目标

- 用户已用调试参数启动 Chrome → Agent **零配置探测接管**,登录态完整保留。
- 用户没启动调试参数 → 工具返回**结构化引导**(平台相关精确命令),Agent
  可转述用户执行,或经用户授权后 `auto_relaunch=true` 由工具自动完成
  「退出 Chrome → 复制登录态 → 调试重启 → 接管」全流程。
- Linux 服务器(无 GUI)行为不变:内存无头浏览器,无登录态可复用,登录类
  操作走 `request_human`。

## 2. 三档能力

### 2.1 档位一:自动探测接管(默认路径)

`open(reuse_existing=true)`(不传 `connect_url` 时):

1. 读调试端口:环境变量 `LAEW_CHROME_DEBUG_PORT` → 缺省 `9222`。
2. 依次探测 `GET {base}/json/version`(1.5s 超时),`base` 候选:
   `http://localhost:{port}` → `http://[::1]:{port}` → `http://127.0.0.1:{port}`。
   **Chrome 154+ 的 DevTools HTTP 端点只服务 IPv6 loopback(`::1`)连接,
   IPv4 连接返回 404**(实测 2026-10,Chrome 154.0.8037.98);`localhost`
   在多数系统优先解析到 `::1` 故放首位,后两候选兜底旧版本/异常
   解析顺序。解析 `webSocketDebuggerUrl` 与 `Browser` 版本串。
3. 命中 → 等价于 `connect_url={实际命中的 base}` 走既有 connect
   分支(`Browser::connect()`),响应附加:

   | 字段 | 含义 |
   | ---- | ---- |
   | `reuse_existing_chrome` | `true` = 本次 open 接管了用户外部浏览器 |
   | `debug_port` | 实际探测成功的端口 |
   | `browser_version` | 外部浏览器版本串(如 `Chrome/131.0.6778.87`) |
   | `connect_mode` | `true`(launch 模式为 `false`)——`close` 只断连不关浏览器 |

4. 同 URL 页面复用语义不变:若 laew 之前已接管并打开过同 URL 页面,
   仍走「导航刷新 + 同一 page_id」复用路径(登录态在浏览器 profile 里,
   页面刷新不丢)。

### 2.2 档位二:结构化引导(探测失败,默认响应)

探测失败(端口无监听 / 非 CDP 服务 / 超时)且未传 `auto_relaunch` 时,
返回 **code=3002** 信封:

```json
{
  "code": 3002,
  "message": "未检测到可复用的浏览器(调试端口未开启)",
  "data": {
    "debug_port": 9222,
    "chrome_running": true,
    "relaunch_command": "/Applications/Google\\ Chrome.app/Contents/MacOS/Google\\ Chrome --remote-debugging-port=9222 --user-data-dir=/Users/xxx/.laew/chrome_debug_profile",
    "auto_relaunch": true,
    "hint": "把 relaunch_command 转述给用户执行(或经用户同意后以 auto_relaunch=true 重试);Chrome 136+ 默认 profile 上调试端口会被忽略,必须用独立 --user-data-dir"
  }
}
```

- `chrome_running`:是否检测到 Chromium 系浏览器进程(macOS/Linux `pgrep`,
  Windows `tasklist`)。Agent 据此区分「Chrome 没开」与「开了但没调试
  端口」两种引导话术。
- `relaunch_command`:平台相关的**完整可复制命令**(见 §4),用户执行后
  重新 `open(reuse_existing=true)` 即可接管。
- 3002 是**确定性失败**:Agent 不要反复重试 open,按 data 引导用户。

### 2.3 档位三:自动重启接管(auto_relaunch=true)

`open(reuse_existing=true, auto_relaunch=true)` 且探测失败时,工具自动
执行(每步 fail-open,失败回落 3002 + 原因):

1. **退出用户 Chrome**(若 `chrome_running`):macOS `pkill -x`、Windows
   `taskkill /IM ... /F`、Linux `pkill -f`;轮询等进程消失(≤5s)。
2. **复制登录态**(仅 macOS/Windows;Linux 服务器无登录态可复制,跳过):
   把默认 profile 的 `Cookies` / `Cookies-journal` / `Local Storage/` /
   `Session Storage/` / `Login Data` / `Web Data` / `Local State` 复制到
   调试 profile 目录(先清空目标)。Chrome 必须先完全退出再复制
   (SQLite WAL / 文件锁),故在第 1 步之后。
3. **以调试参数启动 Chrome**:`detect_browser()` 拿可执行文件,spawn
   `--remote-debugging-port={port} --user-data-dir={调试 profile}`;
   无 GUI 会话(Linux 服务器)追加 `--headless=new --no-sandbox
   --disable-gpu`。
4. **等端口就绪**:轮询 `/json/version`(300ms 间隔,≤15s),成功后走
   connect 分支接管,响应同档位一(附加 `auto_relaunch:true`)。

> **侵入性说明**:第 1 步会退出用户当前 Chrome。Chrome 默认恢复上次
> 会话,标签页不丢;但未保存的表单内容可能丢失。因此 `auto_relaunch`
> 必须由 LLM 显式传参(触发条件 = 用户明确要求复用浏览器),工具层
> 不默认开启。

## 3. 参数与错误码

### 3.1 open 新增参数

| 参数 | 类型 | 默认 | 说明 |
| ---- | ---- | ---- | ---- |
| `reuse_existing` | bool | `false` | `true` = 复用用户已登录浏览器:自动探测调试端口并接管;与 `connect_url` 并存时 `connect_url` 优先(跳过探测) |
| `auto_relaunch` | bool | `false` | `reuse_existing=true` 且探测失败时,自动执行「退出 Chrome → 复制登录态 → 调试重启 → 接管」;显式 opt-in,不默认开启 |

既有 `connect_url` 保留:显式指定接管地址(高级用法,如非默认端口),
行为不变。

### 3.2 新错误码 3002

| code | 语义 | Agent 对策 |
| ---- | ---- | ---------- |
| 3002 | 复用浏览器不可用(调试端口未开启) | 把 `data.relaunch_command` 转述用户执行;或经用户同意以 `auto_relaunch=true` 重试;**不要反复重试 open** |

错误码段位:1xxx 参数 / 2xxx 浏览器与页面 / **3xxx 环境缺失(3001 未装浏览器、3002 不可复用)** / 4xxx 人工介入 / 6xxx 范围约束。

### 3.3 环境变量

| 变量 | 取值 | 行为 |
| ---- | ---- | ---- |
| `LAEW_CHROME_DEBUG_PORT` | 正整数(默认 `9222`) | 覆盖复用探测的调试端口;非法值回退默认 |

## 4. 平台行为矩阵

| 平台 | 探测端口 | 退出 Chrome | 登录态复制 | 重启形态 | 说明 |
| ---- | -------- | ----------- | ---------- | -------- | ---- |
| macOS | 9222(可 env 覆盖) | `pkill -x "Google Chrome"` 等 4 个进程名 | 复制默认 profile(`~/Library/Application Support/Google/Chrome`)关键文件到 `~/.laew/chrome_debug_profile` | headed(有 GUI) | 调试端口只绑 127.0.0.1;`pkill` 后轮询确认进程消失再复制 |
| Windows | 同上 | `tasklist` 检测 + `tasklist /IM chrome.exe /F` 等 | 复制 `%LOCALAPPDATA%\Google\Chrome\User Data` 关键文件 | headed(交互式终端) | 路径含空格时 spawn 参数数组天然处理,无需引号转义 |
| Linux | 同上 | `pkill -f` 匹配 | **跳过**(服务器无登录态) | 无 GUI 会话 → `--headless=new` | 内存无头实例,行为与既有 hidden 模式一致;登录走 `request_human` |

调试 profile 目录统一为 `~/.laew/chrome_debug_profile`(跨平台),首次
启动为空白页,用户需登录一次;此后 profile 持久保留登录态,且每次
`auto_relaunch` 会从默认 profile 复制最新状态覆盖。

## 5. Chrome 136+ 默认 profile 限制与登录态复制

### 5.1 限制

Chrome 136(2024-03)起,`--remote-debugging-port` 与**默认 user-data-dir**
同时使用时端口被静默忽略(防恶意网站经调试协议窃取会话)。因此:

- 用户日常 Chrome(默认 profile)**无法**通过「加个调试端口」复用;
- 必须用独立 `--user-data-dir`,而独立 profile 是全新的、无登录态。

### 5.2 复制清单(最小登录态集)

`copy_profile_secrets(src, dst)`(best-effort,单个文件失败跳过):

| 相对路径 | 类型 | 内容 |
| -------- | ---- | ---- |
| `Default/Cookies`(+`-journal`) | 文件 | Cookie(登录态核心) |
| `Default/Local Storage/` | 目录 | localStorage(站点会话令牌常见载体) |
| `Default/Session Storage/` | 目录 | sessionStorage |
| `Default/Login Data`(+`-journal`) | 文件 | 已保存密码(可选,复制无害) |
| `Default/Web Data` | 文件 | 自动填充等 |
| `Local State` | 文件 | os_crypt 元数据 |

加密兼容性:macOS 上 Cookies 用 Keychain「Chrome Safe Storage」密钥
加密(同机同用户可解密);Windows 上 DPAPI 绑定当前用户(同用户可解密);
Linux 服务器场景不复制。复制前 Chrome 必须完全退出(文件锁 + WAL
一致性)。

### 5.3 为什么不用「默认 profile + 调试端口」

Chrome 136+ 直接忽略,端口不监听,探测必然失败——这是 Chrome 的强制
安全策略,无解。独立 profile + 登录态复制是唯一能「既开调试端口、又
保留登录态」的路径(与 Playwright/Puppeteer 社区对 Chrome 136 的适配
结论一致)。

## 6. 生命周期与关闭语义

| 行为 | launch 模式(laew 自有浏览器) | connect 模式(接管用户浏览器) |
| ---- | ---------------------------- | ---------------------------- |
| 启动 | 一次性临时 profile,无登录态 | 用户已启动的 Chrome,登录态完整 |
| `close(page_id)` | 关页面;末页回收浏览器进程 | 关页面;末页**只断连,不关用户浏览器** |
| `close(page_id="all")` | 关全部页面 + 杀浏览器 + 删临时 profile | 关全部页面 + 断连;用户 Chrome 继续运行 |
| 进程退出 | watchdog + cleanup_sync 兜底回收 | 不拥有外部进程,无回收动作 |
| 蒙层(overlay) | 默认随 `LAEW_WEB_OVERLAY` | **强制 false**——不锁用户输入;需要时 `control(set_overlay, enabled=true)` 手动开 |
| 高亮蓝框 | headed 下默认注入 | 同 launch(纯视觉标识,`pointer-events:none`) |
| `mode` 响应字段 | 真实启动模式 | 固定 `headed`(接管外部浏览器的常态;无头启动的外部浏览器忽略此字段) |

connect 模式判定对工具层可见:`BrowserManager::is_connect_mode()`,
open 成功响应带 `connect_mode` 字段供 LLM 对账。

## 7. 安全边界

- 调试端口只绑 loopback(Chrome 默认 `127.0.0.1` + `::1`),不暴露公网;
  **不要**指导用户加 `--remote-debugging-address=0.0.0.0`。
- Chrome 154+ 的 HTTP 端点进一步收紧为**只服务 IPv6 loopback 连接**
  (§2.1),IPv4 连接 404;WebSocket 连接同样走 `localhost` 主机名。
  这是 Chrome 的 DNS-rebinding 防护,工具侧用多候选地址适配(不绕过)。
- 复制登录态文件只在**本机同用户**内进行,不外传、不落盘到工作目录。
- `auto_relaunch` 退出用户 Chrome 前不二次确认(参数本身即授权),但
  系统提示词要求 LLM 仅在用户明确要求复用浏览器时传该参数。
- 接管外部浏览器后,任务锚点(6001)、网页取证纪律等既有安全机制
  全部照常生效(connect 只是换浏览器来源,不改安全语义)。

## 8. 提示词与工具描述接线

- **工具描述**(`MCP_WEB_USE_DESCRIPTION`):open 参数列表加
  `reuse_existing` / `auto_relaunch`;错误码对策加 3002;connect_url
  说明补「reuse_existing=true 会自动探测默认端口,无需显式传本参数」。
- **系统提示词**(`MCP_WEB_USE_PROMPT_SECTION` 第 20 条):触发条件
  (用户说「我已经登录了 X 网站」「用我打开的 Chrome」「复用我的浏览器/
  登录态」)→ `open(reuse_existing=true)`;3002 → 转述
  `data.relaunch_command` 或经同意后 `auto_relaunch=true` 重试;
  connect 模式 close 只断连;Linux 服务器无登录态可复用,登录走
  `request_human`。
- **单测**:`sub_agent_prompt_mcp_web_use_all_platforms` 断言提示词含
  `reuse_existing`。
