# MCP_Web_Use 人工介入(HITL)弹窗 UI 动态加载方案

> 版本:2026-10-08(第 130 轮)
> 适用平台:**macOS / Windows 可视化桌面弹窗**;Linux / 无桌面环境退化为 TUI 问答(既有行为)
> 实现入口:`src/agent/human_ui/`(弹窗 UI 层)+ `src/agent/human_assist.rs`(枢纽接线)
> 关联文档:`02-人工介入与窗口可视化方案.md`(HITL 闭环基线;本文是其「前端呈现层」扩展)、
> `01-设计与解决方案.md`(MCP_Web_Use 基础架构)

## 1. 背景与目标

第 100 轮 HITL 闭环的呈现端只有 **TUI 终端问答**(阶段协程渲染蓝框 + 行读 stdin)。
实测暴露的问题:

1. **提醒强度不足**:Agent 长任务期间 TUI 停在 `[waiting]` spinner,人工介入请求块
   混在滚动输出里,用户离开终端就完全错过;验证码/扫码/人脸等流程一旦错过窗口期,
   只能等超时重来;
2. **焦点不持续**:TUI 提示是「一次性打印」,用户切走到浏览器/其它窗口后没有任何
   把注意力拉回来的机制;而人工介入恰恰要求「人到浏览器前操作」,人离开终端是常态;
3. **信息不全面**:TUI 蓝框只有类型/说明/选项,没有「提出时间 / 已处理时长 /
   超时截止时刻」等时间轴信息,用户不知道还剩多久;
4. **非 TUI 模式完全不可用**:`-p` 单轮 / 管道模式下 request_human 直接 4001,
   桌面明明可以弹窗却用不上。

目标:在 **macOS / Windows** 上为 `request_human`(9 个 reason 全覆盖:captcha /
sms / qr_login / login / real_name / two_factor / oauth / manual_verify / custom)
增加**桌面弹窗 UI**,持续获取焦点、完整展示时间轴、支持文本回填(短信/2FA 动态码)
与选项点击;UI 脚本**运行时动态加载**可替换,通用适配各种人工介入场景。

## 2. 总体架构

```text
SubAgent-Work(LLM)control_action=request_human
        │
        ▼
HumanAssistHub::request()  ←── 全局单例不变(02 §2)
        │ 注册 pending 槽位时同步判定呈现端:
        │   gui_enabled = human_ui::enabled()
        │   ├─ 是 → 槽位标记 via=gui,spawn 弹窗呈现任务 ──┐
        │   └─ 否 → 仅 TUI 轮询(既有路径)                │
        ▼                                                  ▼
oneshot 等待人工回答                            human_ui::present(display)
        ▲                                       (动态加载脚本 → 起平台弹窗进程)
        │                                                  │
        │        respond(id, Some/None) ◄──────────────────┤ 点击选项/输入文本/取消
        │        (弹窗应答 / TUI 行读应答 二选一,          │ 超时/脚本失败 → 降级 TUI
        │         respond 幂等,后到者拿 false)            │
        └──────────────────────────────────────────────────┘
```

三层职责严格分离:

| 层 | 模块 | 职责 |
| --- | --- | --- |
| **枢纽层**(不变) | `human_assist.rs` | pending 槽位 / oneshot / 超时 clamp / 四态结局;呈现端只经 `respond` 回填 |
| **呈现层**(本方案) | `human_ui/` | 能力探测 + 脚本动态加载 + 平台弹窗进程管理 + 结果解析;失败 fail-open 降级 |
| **呈现层(兜底)** | `tui/dispatch.rs` | 弹窗不可用/弹窗脚本失败时,沿用 TUI 蓝框行读;弹窗接管时仅打印通知行 + 结果事件 |

## 3. 关键决策

1. **弹窗不进 Tool trait、不进 TUI,而是独立呈现层挂在 Hub 上**:Tool trait 不知道
   调用方形态,TUI 又只在交互模式存活;Hub 是唯一汇聚点,`request()` 入位时统一决定
   「弹窗 + TUI 谁接管」,`-p`/管道模式同样能弹(把 HITL 可用性从「TUI 专属」提升为
   「桌面会话专属」)。
2. **平台脚本运行时动态加载,不编译进逻辑**:macOS 走 JXA(JavaScript for Automation
   + AppKit NSAlert),Windows 走 PowerShell WinForms —— 两者都是系统自带解释器,
   **零新 crate、零编译期平台耦合**。脚本正文按查找序加载:
   `LAEW_HUMAN_UI_SCRIPT`(显式路径)→ `{工作目录}/.laew/human_ui/` →
   `{根目录}/.laew/human_ui/` → `~/.laew/human_ui/` → 内置默认(`include_str!`)。
   用户改脚本即生效(每次呈现重读,不缓存),「各种情况的通用性」通过替换/扩展脚本实现。
3. **弹窗进程化而非 FFI GUI**:osascript / powershell 子进程崩溃、卡死、被杀都不影响
   Agent 主进程;`kill_on_drop` + 槽位释放监听保证「TUI 先答了 → 弹窗立刻被回收」,
   不留孤儿窗口。
4. **弹窗应答与 TUI 行读互斥**:弹窗接管期间 TUI **不读 stdin**(避免阻塞读残留吃掉
   用户后续输入);弹窗脚本启动失败时 `mark_gui_failed(id)` 降级,同一请求无缝改由
   TUI 行读接管。`respond` 幂等(后到者返回 false),双前端不可能双回填。
5. **时间轴三要素进弹窗**:提出时间(`started_at` 本地时刻)、已等待/处理时长(1s 粒度
   动态刷新)、超时截止时刻与剩余倒计时(动态刷新,归零自动以 timeout 收口);
   同一 payload 字段供 macOS/Windows 脚本共用,两平台信息面一致。
6. **持续获取焦点**:macOS `NSTimer` 周期 `activateIgnoringOtherApps` + 窗口
   `makeKeyAndOrderFront` + `NSFloatingWindowLevel`;Windows `TopMost=$true` + 定时
   `Activate()`。人切走后每隔数秒被拉回,保证介入实时性。
7. **fail-open 三重降级链**:弹窗脚本缺失/解析失败/进程启动失败 → TUI 行读 →
   两者皆无(非 TTY 且无桌面)→ 既有 4001 不可用语义。任何一级失败都不阻断任务主流程。

## 4. 弹窗 UI 规格(两平台同构)

### 4.1 内容区(自上而下)

| 区块 | 内容 | 说明 |
| --- | --- | --- |
| 标题栏 | `🔐 人工介入 · {kind_label}` | kind_label 与 TUI 蓝框同一映射表(9 reason + custom 兜底) |
| 说明区 | `message` | LLM 传入的具体说明(缺省按 reason 生成默认文案),自动换行 |
| 页面区 | `页面: {url}` / `页面ID: {page_id}` | url 超长截断保尾;hidden 模式 url 可能为空,空则省略 |
| **时间轴** | 提出时间 / 已等待(Ns,动态) / 超时剩余(Ns,动态) / 超时截止(HH:MM:SS) | 全部本地时区;「已等待」即人工处理时长 |
| 输入区 | 单行文本框 | 短信验证码/2FA 动态码/自由说明直接输入;可留空只点选项 |
| 操作区 | 选项按钮(1~6)+ `[ 取消 ]` | 选项按钮文案 = `options[]`;`[ 取消 ]` 独立常驻(= 4002);Esc 等效取消 |

### 4.2 应答语义(与 TUI 行读映射表对齐)

| 人工动作 | 结果 | 工具信封 |
| --- | --- | --- |
| 点选项按钮 N(文本框空) | `Answered("N. 选项文本")` | `code=0` + `human_response` |
| 输入文本 + 点任意按钮/回车 | `Answered(原文)`(短信验证码数字即此路径) | `code=0` + `human_response` |
| 点 `[ 取消 ]` / Esc / 关窗 | `Cancelled` | `code=4002` |
| 倒计时归零(弹窗自灭) | `Timeout` | `code=4001` |
| 脚本失败/进程崩溃 | 降级 TUI;无 TUI 则 `Unavailable` | `code=4001` |

### 4.3 进程契约(脚本 ↔ Rust)

输入:命令行参数 = payload JSON 临时文件路径。payload 字段:

```json
{
  "id": 3,
  "kind": "sms",
  "kind_label": "短信验证码",
  "message": "页面要求短信验证码……",
  "options": ["我已完成人工操作,继续", "取消任务"],
  "url": "https://example.com/login",
  "page_id": "p_ab12cd34",
  "started_at": "2026-10-08 14:32:05",
  "started_at_ms": 1759991525000,
  "timeout_ms": 120000
}
```

输出:stdout 最后一行 JSON(`status` ∈ `answer|cancel|timeout|error`):

```json
{"status":"answer","text":"482913"}
{"status":"cancel"}
{"status":"timeout"}
{"status":"error","text":"原因说明"}
```

退出码 0 = 正常收口(含 timeout);非 0 = 脚本级失败(降级 TUI)。

**JXA 实现陷阱(2026-10-08 真机实测踩坑)**:JXA 桥接 ObjC **零参方法必须用属性
访问式调用**(`timer.invalidate;` / `$.NSApp.abortModal;`),写成 `timer.invalidate()`
在部分桥接版本报 `TypeError: … is not a function`。第一版脚本因此把「倒计时归零
自动收口」吞成 `error`(抛错点在 abortModal 之后的清理段,污染了已置好的 timeout
结果)。修复约定:①零参方法一律属性式;②timer 回调带 `done` 守卫;③收口清理
`try/catch` 包裹,绝不让辅助清理失败污染主结果;④`result.status` 判定先于一切
清理调用。Windows PowerShell 无此陷阱(常规方法调用)。

## 5. 能力探测与开关

| 判定 | 依据 |
| --- | --- |
| 平台门控 | 仅 `target_os=macos` / `target_os=windows` 注册弹窗后端;Linux `enabled()` 恒 false |
| 解释器存在 | macOS `osascript`;Windows `powershell.exe`/`pwsh`。探测失败 → TUI 降级 |
| 总开关 | `LAEW_HUMAN_UI`:`off/0/false/no` 关闭(强制 TUI);`tty` 同关闭;缺省自动 |
| 脚本覆盖 | `LAEW_HUMAN_UI_SCRIPT=/path/to/script` 显式指定(调试/企业定制) |
| 测试钩子 | `human_ui::set_test_override()`(单测互斥全局态用,生产代码不触达) |

与既有行为的兼容矩阵:

| 模式 | 改造前 | 改造后 |
| --- | --- | --- |
| TUI(TTY) + macOS/Windows | TUI 蓝框行读 | **弹窗优先**,TUI 只打通知行;弹窗失败降级行读 |
| TUI(TTY) + Linux | TUI 蓝框行读 | 不变 |
| `-p`/管道 + macOS/Windows | 4001 不可用 | **弹窗可用**(桌面在即可介入) |
| `-p`/管道 + Linux / 无桌面 | 4001 不可用 | 不变(4001,hint 指引换 TUI) |
| `LAEW_HUMAN_UI=off` | — | 全部回退改造前行为 |

## 6. 弹窗呈现层模块(`src/agent/human_ui/`)

```
human_ui/
  mod.rs        门面:enabled() / present() / 结果枚举 / 时间格式化 / 测试 override
  script.rs     脚本动态加载(查找序 + 内置回退)+ payload 落盘/清理
  macos.rs      cfg(macos):osascript -l JavaScript 起 JXA 脚本,捕获 stdout JSON
  windows.rs    cfg(windows):powershell -STA -File 起 WinForms 脚本,同上
  scripts/
    macos_dialog.js    内置默认 JXA 弹窗(NSAlert + 时间轴 NSTimer + 焦点保持)
    windows_dialog.ps1 内置默认 WinForms 弹窗(TopMost + 时间轴 Timer + 焦点保持)
  tests.rs      payload 构建/解析/脚本查找序/降级链 单测
```

Hub 接线(`human_assist.rs` 增量,枢纽语义零改动):

- `request()` 入位后:`human_ui::enabled()` 为真 → 槽位打 `via=gui` 标记并
  `tokio::spawn` 呈现任务;呈现任务 `select!` 弹窗结局 / 槽位释放(释放即 drop
  弹窗 future → 子进程 kill_on_drop 回收);
- 新增 `mark_gui_failed(id)`:弹窗启动失败时清 gui 标记,TUI 轮询下一轮(≤250ms)
  自动改走行读;若本就无 TUI,槽位保持 pending 由既有超时收口;
- 事件环 `AssistEvent{GuiLaunched/GuiFailed/Answered/Cancelled}`:TUI 轮询时
  `take_events()` 打印结果行(「已收到人工输入(弹窗)」/「人工已取消(弹窗)」)。

## 7. TUI 侧行为(tui/dispatch.rs 增量)

弹窗接管时(槽位 `via=gui`):

```text
  [laew] 🖥 已弹出人工介入弹窗(macOS),请在弹窗中作答
  [laew]   类型: 短信验证码 | 提出 14:32:05 | 超时 14:34:05(剩余 120s)
  [laew]   (弹窗未出现时可等其自动降级为终端作答,或重启时设 LAEW_HUMAN_UI=off)
```

- **不读 stdin**(弹窗是唯一应答通道,杜绝阻塞读残留);
- 250ms 轮询继续:弹窗应答后经事件环打印结果行;弹窗失败(`GuiFailed`)同 id
  无缝切换既有行读流程(倒计时/映射/取消语义全保留);
- 任务收尾 `cancel_pending()` 兜底同时回收弹窗进程(槽位释放监听)。

## 8. System Prompt 与工具描述增量

- `request_human` 工具描述补一句:「macOS/Windows 桌面会自动弹出人工介入窗口
  (持续置顶 + 倒计时),人工在弹窗输入/点选即可;`-p` 模式同样可弹;Linux 回退 TUI」;
- HITL 作业规范(02 §7)不变——reason 语义、严禁伪造、4001/4002 对策与弹窗无关;
- blockers → request_human 链路不变,弹窗只是「人看到并作答」这一环的体验升级。
