# 09 - 自动阻断感知与语义挑战检测(第 147 轮)

> 唯一最新版。实现:`src/agent/tools/mcp_web_use/blocker_probe.rs`(探针 + 打分纯函数 +
> 响应附加)+ `control.rs`(动作收尾接线)+ `inspect.rs`(blockers 双通道升级)。
> 事故输入:`llaew_20261010_142603.log`(豆包多轮对话任务)。

## 1. 事故与根因

### 1.1 事故现象

豆包多轮对话提取系统提示词任务(`laew --debug`),wf-3 阶段 Agent 在豆包页面循环
「输入消息 → Enter → wait → 读会话」,豆包风控中途弹出**图片选择类人机验证**
「在公园能看到(的事物或动物)」——弹窗在页面上持续存在,Agent 全程零感知,
换措辞连发 16+ 轮消息,直到用户 Ctrl-C 手动终止(SIGINT 14:50:25)。
日志全文零次「公园/人机验证/captcha」命中。

### 1.2 四条根因

| # | 根因 | 定性 |
|---|------|------|
| R1 | **语义挑战检测盲区**:`inspect(blockers)` 纯关键词匹配,图片选择题题面「选出在公园能看到的事物」一个词都不命中,当场调 blockers 也返回 clean | 结构性 |
| R2 | **阻断感知是拉取式一次性动作**:blockers 只在 LLM 主动调用时检测;wf-3 仅 iter=0 探过一次,弹窗出现后 20+ 轮零复检,没有工具层推送机制 | 结构性 |
| R3 | **wait 参数别名缺口**:`act_wait` 纯睡眠只读 `duration_ms`,LLM 全程传 `{"ms":12000}` → 每次「等 12 秒」实际只睡 500ms,回复/弹窗没来得及渲染就被读取 | 参数性 |
| R4 | **停滞无差异化信号**:发消息 DOM 操作永远 code=0,「发出没回复」与「被验证挡住」不可区分;措辞各不同 = LoopGuard 进展键不同,无进展止损也不触发 | 行为性(R1+R2 修复后消解) |

## 2. 方案总览

两条互补通道 + 两个参数性修复:

```
┌─ 拉取式(升级)────────────────┐   ┌─ 推送式(新增)────────────────────┐
│ inspect(info=blockers)          │   │ control 动作收尾(Ok/Err 双路)      │
│   ├ 全文关键词(第100轮语义不变)│   │   输入类20个 + wait + 导航类         │
│   └ 弹层语义挑战(新增)         │   │   → 一次探针 eval(~ms,fail-open)   │
│        ↓ 同一探针/同一判定口径 ↓  │   │   → 命中才附 data.blocker_alert     │
│                    blocker_probe::analyze                           │
│                    (detect_blockers ∪ detect_challenge,同 kind 去重) │
└──────────────────────────────────┴───┴─────────────────────────────────┘
```

- **语义挑战检测**(`detect_challenge`):题面无「验证码」关键词的风控弹窗,靠
  弹层**结构**识别 —— 高 z-index 模态覆盖层 + 九宫格小图 / 验证码尺寸 iframe /
  验证类文案,打分制;
- **推送式自动感知**(`attach_if_blocked`):输入类动作 / wait / 导航类动作完成后
  工具层自动探测,命中把 `data.blocker_alert` + `next_action` + `human_assist`
  载荷(第 131 轮惯例)附进响应,LLM 照抄即可发起 `request_human`。

## 3. 弹层语义挑战检测

### 3.1 探针(一次 eval)

- 全文:`body.cloneNode` 剥离 `[data-laew-agent]`(Agent 蒙层/徽标不参与判定)后
  `innerText` 前 20000 字,与 blockers 原路径同源;
- 弹层候选:`dialog[open] / [role=dialog] / [aria-modal=true] /
  [class*=modal|dialog|popup|mask|overlay|captcha|verify|challenge i]`,
  可见 + `position:fixed|absolute` + 覆盖视口 ≥6% + ≥200×120;取 **z-index 最大
  (同 z 取 DOM 更深)** 者为「当前弹层」;
- 弹层元数据:`text`(≤600 字)、`grid_imgs`(48~240px 近方形小图数)、
  `iframe_like`(160≤w≤480 且 120≤h≤640 且宽高比 0.5~1.9 的 iframe ——
  火山引擎/reCAPTCHA/hCaptcha 常见形态)、`canvas_count`、`input_count`、
  `buttons`(≤6 个按钮文本)、面积比。

### 3.2 打分表(Rust 纯函数)

| 信号 | 分值 |
|------|-----|
| `grid_imgs ≥ 4`(九宫格选择题) | +2 |
| `iframe_like`(验证码尺寸 iframe) | +2 |
| 弹层文本强验证词(验证码/人机验证/安全验证/身份验证/滑动验证/拖动滑块/请完成验证/真人/robot/human verification/captcha) | +4 |
| 弹层文本弱指令词(点击/选择/选出/按顺序/依次/包含/拖动/滑动/拼图/图片/图中/下方图片/符合/哪一个/哪个) | +1 |
| 刷新词(换一张/刷新/看不清;文本或按钮) | +1 |
| 广告负信号(广告/跳过/skip/sponsored/advertisement) | −3 |

**≥3 分判定为语义挑战**,产出 `{kind:"captcha", matched:"challenge_overlay",
snippet:弹层文本前120字, evidence:{score,grid_imgs,iframe_like,buttons,area_ratio}}`。

阈值设计:iframe 形态(+2)与九宫格(+2)单独都不够 —— 防视频嵌入/广告位/图库
弹窗误报;强验证词(+4)单独即命中;**任一结构信号 + 任一文案信号**是最小可靠组合。
豆包案:题面在跨域 iframe 内主文档读不到 → `iframe_like`(+2)+ 壳层「安全验证」
类强词(+4)命中;若站方壳层零文案,`iframe_like` + 弱词兜底;极端「纯 iframe 零文案」
接受漏报(告警文案注明「疑似」并给 screenshot 确认路径,宁少报不误报)。

### 3.3 与关键词通道合并(`analyze`)

`detect_blockers(全文)`(第 100 轮语义不变)∪ `detect_challenge(弹层)`;
同 kind(仅 captcha 可能重叠)去重,**保留带 evidence 的挑战条目**(对账价值更高)。

## 4. 推送式自动感知(control 收尾接线)

- **探测动作集**(`action_needs_probe`):复用第 141/143 轮 `action_dispatches_input`
  白名单(click/human_click/right_click/double_click/hover/scroll/scroll_to/
  key_press/press_sequence/input_text/human_input/clear_input/upload_file/
  select_option/download/drag/focus/blur/mouse_move/dispatch_event)+ `wait` +
  `navigate/back/forward/reload`;
- **Ok 路附加,Err 路(wait)也附加**:wait 失败(多为等待超时)恰是
  「回复没来 + 弹窗在场」的最强复合信号,只挂 Ok 路会丢掉它;其它动作仅 Ok 路;
- **命中才附加,干净零噪声**:`data.blocker_alert{kind,matched,snippet,evidence,hint}` +
  顶层 `next_action="request_human"` + 完整 `human_assist` 载荷(`merge_hint`
  惯例,已有 next_action 不覆盖);
- **sequence/batch 自动覆盖**:步骤逐个递归 `McpWebUseTool.execute` → 每步自带探测;
- **成本与 fail-open**:每次探测 = 1 次 Runtime.evaluate(本地 ~2-5ms,远轻于第 146 轮
  已消除的 pages() 巡检);2s 超时 / 页面失效 / JS 异常一律当干净,**绝不阻断动作语义**。

### 4.1 时序论证(为什么「动作后立即探测」够用)

验证弹窗是**服务端风控决策后异步出现**(发送后 0.3~2s)且**出现后持续存在**:
发送动作后的立即探测大概率扑空,但弹窗不会消失 —— Agent 循环里的**下一个输入类
动作**或 **wait 结束点**(R3 修复后 wait 真的等了)必然探测命中,感知延迟 ≤1~2 个
迭代;对比现状(零感知直到人工 Ctrl-C)是数量级改善。纯 eval_js 只读循环不探测
(高频通道,逐次探测只翻倍 CDP 往返不增信号),且该形态下 Agent 并未与页面交互,
风控弹窗不会出现。

## 5. 参数性修复(同轮)

- **wait `ms` 别名**(`wait_sleep_ms` 纯函数):`duration_ms` 与 `ms` 取较大者,
  缺省 500,上限 10s→30s(AI 类网站回复 30-60s 常见,第 82 轮;selector 等待本就
  允许 120s);返回 `slept_ms` 如实回报;
- **sequence 步骤 action 推断**(`infer_step_action` 纯函数):缺 `action` 时
  `control_action` → `"control"`、`info` → `"inspect"` 并回写进步骤(实测 LLM 常写
  `{"control_action":"wait",...}` 漏 `action:"control"`,整步 1001 白烧迭代),
  与第 99/135 轮「参数别名容错」哲学一致。

## 6. 开关与回退

| 环境变量 | 行为 |
|----------|------|
| `LAEW_WEB_BLOCKER_PROBE=off/0/false/no` | 关闭推送式自动探测;`inspect(blockers)` 回退第 100 轮纯关键词行为(严格向后兼容) |

    "blocker_alert": {
      "kind": "captcha", "matched": "challenge_overlay",
      "snippet": "安全验证 请选出在公园能看到的事物或动物",
      "evidence": {"score": 6, "grid_imgs": 9, "iframe_like": false,
                    "buttons": ["刷新", "换一换"], "area_ratio": 0.23},
