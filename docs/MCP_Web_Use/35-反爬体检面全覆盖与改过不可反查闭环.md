# 反爬体检面全覆盖与「改过不可反查」闭环（第 181 轮）

> 2026-10-18 · 承接 [26-反检测档位与非侵入式侵入式模式设计](./26-反检测档位与非侵入式侵入式模式设计.md)
> §一「可检测面」表 1–10 与 [34-派生页首文档早期武装](./34-派生页首文档早期武装.md) §七。
>
> **本轮主线**：把 26 §一 的「可检测面」从**已处置的 10 项**扩到**可观测的 20 项**，
> 并补上侵入式档「改过不可反查」登记表的最后一类漏登记（**对象值里的嵌套函数**）。
> 两档（非侵入式 `fidelity` / 侵入式 `hardened`）语义不变、诚实边界不变；
> 本轮新增的检测向量**一律先只体检不回填**，等真机基线钉死再决定是否处置。

## 一、问题：体检面只看得见「我们已经修过的」

### 1.1 体检面与处置面同构，盲区等于零可见性

`data.fingerprint`（`src/agent/fingerprint.rs`）的探针表与 26 §一 表 1–10 **一一对应**：
webdriver / WebGL 兜底串 / plugins / languages / chrome.runtime / Notification /
Headless UA / 注入层命名空间 / 被改写函数身份 / 描述符形态。

问题是：**体检只覆盖已经做过处置的项**。风控实际还会采一批我们既没处置、也看不见的信号。
「被拦时如实上报并交还人工」是 26 §三 给出的唯一可持续路线，而这条路的前提是
**看得见自己被拦在哪儿** —— 盲区即「不知道该改道 `reuse_existing` 还是继续调参」。

真机复核（Chrome 155）已确认下列向量在裸环境下读数与真实桌面 Chrome 存在差异或形态破绽，
但当前 `PROBE_JS` 一个都没采：

| # | 检测向量 | 风控常见度 | 当前状态 |
| - | -------- | ---------- | -------- |
| 11 | `Error().stack` 里的自动化框架/驱动令牌 | 高（CreepJS/瑞数系直接比对 stack 形状） | **完全未采** |
| 12 | `document` 上的 `$cdc_` / `$chrome_asyncScriptInfo` 遗留 | 高（chromedriver 系硬判据） | 只扫了 `window` 自有键，`document` 未扫 |
| 13 | `window.chrome` **在场但三件套缺失**（`app`/`csi`/`loadTimes`） | 中高（真机恒三件套，缺一即非真 Chrome） | 只判断 `runtime` 且明确不告警 |
| 14 | `matchMedia('(hover:hover)')` / `(pointer:fine)` 双 false | 高（无头典型读数，桌面 UA 下必可疑） | **完全未采** |
| 15 | `screen.colorDepth` ≠ `screen.pixelDepth` | 中 | **完全未采** |
| 16 | `screen.orientation` 缺失 | 中 | **完全未采** |
| 17 | `hardwareConcurrency` / `deviceMemory` 为 0 | 中 | **已采字段但从未判定、也不回报** |
| 18 | `navigator.platform` 与 UA 声明的 OS 不一致 | 中 | **已采 `ua_platform` 但未交叉判定** |
| 19 | `getOwnPropertyDescriptor(navigator,'webdriver')` 非空（应只在原型上） | 中高（defineProperty 打错目标即可被一行识破） | **完全未采** |
| 20 | `navigator.maxTouchPoints` 与桌面形态不符 | 低中 | **已采字段但从未判定** |

### 1.2 侵入式档有一类函数永远登记不上

「改过不可反查」靠 `PRELUDE_JS` 的 `reg()` 登记 + `HARDENED_JS` 读表把函数身份原生化。
跨档升级（保真→侵入）时上一轮的改写由 `__adoptAll()` **重新认领**。

但 `__adopt(obj, key)` 只认领**该属性值本身是函数**或**该属性是 getter**：

```js
const __adopt = (obj, key) => {
    const d = Object.getOwnPropertyDescriptor(obj, key);
    if (typeof d.get === 'function') reg(d.get, 'get ' + key);
    if (typeof d.value === 'function') reg(d.value, key);   // ← 对象值直接跳过
};
```

而 `FIDELITY_JS` ④ 在 `window.chrome` 缺失时造的是**对象**：

```js
Object.defineProperty(window, 'chrome', { value: { app, csi, loadTimes }, ... });
```

于是 `__adoptAll()` 里的 `__adopt(window, 'chrome')` **一个函数都登记不上**。
`chrome.csi` / `chrome.loadTimes` / `chrome.app.install` 这些我们自己装的函数，
在跨档升级后 `Function.prototype.toString` 会吐出我们的源码。

这与第 177 轮修掉的**迭代器漏登记**是同一类问题（`next` / 自反方法每次现造、
原型上无引用可认领），当时只补了迭代器这一条，没有把「对象值的嵌套函数」作为
**一整类**收口。本轮补的是类，不是点。

### 1.3 两档共用同一套体检口径，噪声淹没有效信号

`patched_functions_visible` / `patched_function_source_visible` 在**保真档命中属设计取舍**
（该档本来就不改函数身份，26 §二 分界线），却与「注入坏了」同权重计入 `risk_tier`。
结果是：跑非侵入式档时 `risk_tier` 常年被这两条抬成 `warn`，真正值得看的
`webgl_default_strings` / `automation_global_leak` 反而被淹没。

## 二、方案

### 2.1 体检面补齐（审计只读，零伪造）—— `fingerprint.rs`

`PROBE_JS` 新增探针、`classify()` 新增告警码。**一律 fail-open**（缺测量返回 `null` 不告警），
**一律不改页面任何读数** —— 本轮只做「看得见」，不做「改得掉」。

| 探针字段 | 告警码 | 定级 | 判据 |
| -------- | ------ | ---- | ---- |
| `stack_automation_tokens` | `stack_trace_automation_tokens` | **high** | `Error().stack` 命中自动化令牌（`cdc_`/`$chrome_asyncScriptInfo`/`__puppeteer`/`__playwright`/`pptr`/`puppeteer`/`playwright`/`_phantom`/`__nightmare`/`__selenium`） |
| `document_automation_globals` | `automation_doc_leak` | **high** | `Object.getOwnPropertyNames(document)` 命中 `$cdc_` / `$chrome_asyncScriptInfo` |
| `chrome_shape` | `chrome_api_incomplete` | warn | `window.chrome` **在场**却缺 `app`/`csi`/`loadTimes` 任一（真机恒三件套） |
| `webdriver_own_property` | `webdriver_own_property` | warn | `getOwnPropertyDescriptor(navigator,'webdriver')` **非空**（原生只挂在 `Navigator.prototype`，实例自有属性恒 undefined） |
| `pointer_mq` | `pointer_media_headless` | warn | 桌面 UA 下 `(hover:hover)` 与 `(pointer:fine)` **双双 false** |
| `color_depth` | `color_depth_mismatch` | warn | `screen.colorDepth !== screen.pixelDepth` |
| `screen_orientation` | `screen_orientation_missing` | warn | `screen.orientation` 缺失或无 `type` |
| `hardware_params` | `hw_params_unset` | warn | `hardwareConcurrency === 0` 或 `deviceMemory === 0` |
| `platform_ua` | `platform_ua_mismatch` | warn | `navigator.platform` 与 UA 声明的 OS 交叉不一致（如 `Linux` + `Windows NT`） |

**定级原则**：只有「零假阳性」的才进 `HARD_CODES`（`stack_trace_automation_tokens`、
`automation_doc_leak`）；其余一律 `warn`。第 178 轮的教训是把推断当硬判据会
常年误报（`focus_visibility_mismatch`、`languages_frozen` 两条都栽过），
**新增项在真机基线钉死前一律不上 `HARD_CODES`**，只有 stack / document 遗留
这两条是「本机绝对不该出现」的硬证据。

**不做（本轮）**：`Notification.permission` vs `permissions.query` 的交叉判定需要
`await_promise`（`eval_js_string` 是同步求值），改动面比收益大，留待后续；
`navigator.connection` / `storage` / `getBattery` / `mediaDevices` 版本差异大、
假阳性高，只在文档留档不采。

### 2.2 「改过不可反查」闭环 —— `browser_ns.rs`

1. **`__adoptDeep(obj)`**：递归认领**对象值的自有函数属性**（深度上限 2，跳过
   原型链与循环引用）。`__adoptAll()` 对 `window.chrome` 改走它 —— 一并认领
   `chrome.app` / `chrome.csi` / `chrome.loadTimes` 与其内部函数。
2. **chrome 形态补全**：`window.chrome` **在场但三件套不全**时，只补缺失项
   （还原真机形态，不是伪造；真机 `Object.keys(chrome)` 恒为 `[app,csi,loadTimes]`）。
   补出的函数一律 `reg()` 登记，跨档升级由 `__adoptDeep` 接住。
3. **自证入口表补全**：`patched_fn_leak` 的 `sites` 增 `chrome_csi` / `chrome_loadTimes`
   / `chrome_app` 三条 —— 登记漏网必须在 `data.fingerprint` 里点名，不能靠人肉对账。

### 2.3 档位感知的体检口径 —— `stealth.rs` + `fingerprint.rs`

`build(fp, mode)` 接收当前生效档位（`attach_fingerprint` 从 `BrowserManager::stealth_mode()` 取）：

- **保真档**：`patched_functions_visible` / `patched_function_source_visible` 照常回报，
  但标 `by_design: true` 且**不计入 `risk_tier`**（这是该档的语义，不是环境缺陷）。
  advice 明确指「升 hardened 消除」。
- **侵入式档**：同类命中是**登记表漏网的真故障**，正常计入 `risk_tier`，advice 指「查注入」。
- **关闭档**（`off`）：全部照常计入（排障对照要看到全貌）。

`data.stealth` 增 `covered` 清单（本轮处置覆盖的表项编号），供 QC / 人工一眼对账
「表 1–20 里哪些已处置、哪些只是可见」。

## 三、诚实边界（与 26 §三 完全一致，本轮零扩张）

- **不做** Canvas/字体指纹伪造、行为轨迹仿真、IP 代理池、打码平台、协议逆向。
- 新增探针**只观测不回填**：`pointer_mq` / `color_depth` / `screen_orientation` /
  `hardware_params` 在真机基线确认「无头确实报错值」之前，一律只告警。
  真机读数为准、不以 mock 垫片为准（31 §七 铁律）。
- chrome 三件套补全**不是伪造身份**：`app`/`csi`/`loadTimes` 是 Chrome 的 API 面，
  真机恒有；补的是被无头/降级环境抹掉的**形态**，与 WebGL UNMASKED 回填同性质。
  **仍然不补 `chrome.runtime`**（175 轮结论：全新 profile 的真机没有它）。
- 缺测量一律 fail-open：探针抛错返回 `null`，不告警、不猜测。

## 五、验证

1. `cargo test --lib`：`fingerprint` 纯函数单测（新增告警码逐条）+ `browser_ns`
   模板单测（`__adoptDeep` 存在、chrome 补全分支存在、新自证入口存在）。
2. `cargo build` 通过。
3. 真机冒烟（`#[ignore]`，需本机 Chrome）：
   - `stealth_selfcheck_smoke`：hardened 档下 `chrome.csi.toString()` 必须报 `[native code]`
     （本轮核心回归点，此前会吐源码）；`data.fingerprint` 不得出现 `stack_trace_automation_tokens`。
   - `stealth_native_shape_baseline_smoke`：裸环境基线钉死 `chrome` 三件套、
     `navigator` 无自有 `webdriver`、`colorDepth === pixelDepth` 等新形态。
4. 手工对照：`stealth=off` 与 `hardened` 两档跑同一页面，`data.fingerprint.suspicious`
   差分只应出现「我们已处置项」的差异，不得新增假阳性。

## 六、遗留与下一步

1. **新增体检项的真机基线**：`pointer_mq` / `color_depth` / `screen_orientation` /
   `hardware_params` 需在无头 / 有头 × 缺省 / `off` 四档下实测读数，确认
   「无头确实报错值」后才决定是否纳入 `FIDELITY_JS` 回填，以及是否升级 `HARD_CODES`。
   在此之前它们只作 `warn` 可见性信号。
2. **`Notification.permission` vs `permissions.query` 交叉判定**：需要 `await_promise`
   的异步探针，与 `eval_js_string` 同步求值契约冲突，单独立项。
3. **`navigator.connection` / `storage` / `getBattery` / `mediaDevices`**：版本差异大、
   假阳性高，本轮只留档不采；若后续真机证明确为无头差异再补。
4. 34 §七 第 1 条（派生页首请求 UA 令牌 / document-start 取样需 fork CDP 客户端）
   与第 2 条（`outer_equals_inner` 软提示升级需重设计视口高度）不变。
