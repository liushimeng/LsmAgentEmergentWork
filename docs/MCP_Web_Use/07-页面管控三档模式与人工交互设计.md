## 1. 需求原文(2026-10-10)

1. macOS/Windows 上 `MCP_Web_Use` 启动 Chrome 用**有窗口可视化模式**(人工可见);
2. Linux 等服务器(无 GUI)上启动 Chrome 用**内存无头非可视化模式**;
3. 可视化模式下,Web 页面添加**半透明蒙层**,人工**不可点击/操作**页面(防交叉操作),
   该形态称为**屏蔽模式**;
4. 可视化模式下 Agent 可操作 `MCP_Web_Use` 支持**屏蔽模式 / 非屏蔽模式 / 部分屏蔽模式**,
   非屏蔽的部分用户可以操作;
5. Agent 能根据用户提示词**分析**应启动/使用哪一档模式,并与用户进行相关交互;
6. 支持 Agent 判断并给出相应 UI 界面提示,让**人工先自己用 Chrome 登录**,再由 Agent
   用 `MCP_Web_Use` 完成 Web 端操作;
7. 与既有工作模式全部兼容,给出各权限工作模式的设计、启动/激活/使用方式、
   以及与人工交互页面相关的设计。

## 3. 总体设计:页面管控(Page Guard)统一概念

把第 141 轮的「蒙层开/关」布尔量升级为**页面管控三档枚举**,与「浏览器可见性」
(BrowserMode)、「人工介入」(HITL)三个正交维度构成完整的人工协同模型:

```
┌────────────────────────────────────────────────────────────────────┐
│ 维度 A:浏览器可见性(BrowserMode,第 139 轮,不改)                     │
│   headed(macOS/Windows 有 GUI 缺省)/ hidden(Linux 服务器自动回退)    │
├────────────────────────────────────────────────────────────────────┤
│ 维度 B:页面管控(PageGuard,本轮新增,仅 headed 有意义)               │
│   locked 屏蔽模式 | open 非屏蔽模式 | partial 部分屏蔽模式             │
├────────────────────────────────────────────────────────────────────┤
│ 维度 C:人工介入窗口(HITL,第 100/130 轮)                             │
│   request_human(unlock_page=true):分钟级临时放行,收口自动恢复        │
│   (第 144 轮:优先 partial 凭证区挖洞,探测不到才整页 open)           │
└────────────────────────────────────────────────────────────────────┘
```

- **B 是任务级长期态**(open 出来的页面在整个任务期间保持开放),**C 是动作级短期窗口**
  (提问期间解锁、应答即复锁);locked 模式下的人工操作走 C,open/partial 模式下人工
  平时就能操作、只在需要传话(验证码数字/确认继续)时走 C。
- hidden 模式无窗口无人工,B 无意义:不注入任何脚本、不设 CDP 输入拦截(与第 141 轮同款门控)。
- connect 模式(第 142 轮接管用户浏览器)B 强制 `open`:不锁用户自己正在使用的浏览器,
  也不向用户页面注入任何视觉元素。

### 3.1 三档语义总表

| 档位 | 名称 | 人工可看 | 人工可操作 | CDP 输入拦截 | 视觉呈现 | 典型场景 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| `locked` | 屏蔽模式 | ✅ | ❌(全部拦截) | ✅ `ignore=true` | 半透明蒙层 + 「🔒 已锁定」状态条 | 缺省;含支付/删除等高风险动作的自动任务;防交叉操作 |
| `open` | 非屏蔽模式 | ✅ | ✅(全部放行) | ❌ `ignore=false` | 「🔓 页面开放·人工可直接操作」状态条 | 人工要亲自操作/演示跟看+交互;人工在 Agent 浏览器里登录(需求 6) |
| `partial` | 部分屏蔽模式 | ✅ | ⭕(盾区外放行) | ❌ `ignore=false` | 危险区域红色盾罩(🔴🔒)+「🛡 部分锁定」状态条 | 人工操作登录表单的同时 Agent 处理其余区域;放行视频区锁住支付按钮 |

### 3.2 关键决策:partial 为什么用「DOM 盾区」而不是事件拦截

第 141 轮已实测论证(05 §4.1):CDP 合成输入与真实输入在 hit-test 层不可区分
(`isTrusted` 均 true),主 frame 的「挂起标志」跨域 iframe 读不到。因此:

- **locked** 沿用 CDP `Input.setIgnoreInputEvents` 浏览器级硬闸门(正确层级);
- **partial** 不可能在输入管线层做「按区域放行」(CDP 没有区域粒度),改为
  **DOM 盾区**:在受保护区域上覆盖 `pointer-events:auto` 的半透明盾罩,吞掉落在
  盾内的人工点击/输入;盾罩全部带 `data-laew-agent="1"`(提取/取证过滤)。
- 代价与对策:盾罩同样会吞掉 Agent 的 CDP 点击(不可区分),因此 partial 模式下
  Agent 的**输入类动作**沿用既有「先解后锁」模式升级为「**先隐盾后复盾**」
  (动作前 `__laewGuardSuspend(true)` 隐藏全部盾罩 → 动作 → 恢复),毫秒级窗口,
  与 locked 的 CDP 解锁窗口同构(见 §5.4 生命周期)。

### 3.3 partial 的两种圈定方式

| 方式 | 参数 | 语义 | 实现 |
| ---- | ---- | ---- | ---- |
| 白名单 | `allow_selectors` | **只有**命中选择器的区域人工可操作,其余全部屏蔽 | 允许区并集在视口内做「垂直条带分解」求补集(深色矩形盾拼出整屏罩+洞;纯矩形零兼容性依赖) |
| 黑名单 | `block_selectors` | 命中选择器的区域人工**不可**操作,其余放行 | 每个命中元素一个独立红调盾罩(`position:fixed` 跟随元素矩形) |

> **为什么不用 `clip-path: path(evenodd, …)` 挖洞**:真浏览器集成验证实测,本机
> Chrome 对 `clip-path: path("evenodd", …)` 赋值后 computed 归 `none`(赋值被拒),
> 整屏盾会退化成全页锁死或全放开,不可靠;条带分解(x 去重分条带 → 条带内 y 区间
> 合并求补)只产出普通矩形盾,与黑名单共用同一套 `pointer-events:auto` 机制,
> 任何 Chromium 版本行为一致。

- 两组互斥(同时给出 → 1001 参数错误);`guard=partial` 必须给出其中一组(否则 1001)。
- 选择器上限:每组 ≤ 8 条、每条 ≤ 160 字符(防 LLM 塞整页选择器列表)。
- 选择器按 **frame 各自生效**:注入脚本运行在页面所有 frame,各 frame 用选择器查自己的
  DOM(跨域 iframe 内的匹配元素同样能罩住,因为脚本在 iframe 自己的文档里执行——
  这是相对「主 frame 挂起标志」方案的结构优势)。**第 144 轮补充**:该规则对
  **黑名单**完整保留;对**白名单**增加子 frame fail-open —— 白名单选择器通常只
  描述主文档区域,子 frame 零命中时若整 frame 加盾,会把主文档挖好的洞从 iframe
  内部锁死(跨域验证码 iframe 人工点不到 reCAPTCHA 复选框)。因此白名单模式下
  子 frame 零命中 → 该 frame 不加盾;iframe 只能落在主文档矩形内,洞外区域由
  主文档条带盾照拦,安全性不降(详案 `08` §4.3)。
- 盾罩矩形随滚动/缩放/DOM 变化自动重算(rAF 节流的 scroll/resize/MutationObserver);
  盾罩「🔒 已锁定(仅 Agent)」标签有数量预算(≤6),选择器命中大量元素时不满屏小标签。

## 4. 三档模式详解

### 4.1 locked 屏蔽模式(= 第 141 轮蒙层,缺省)

行为与第 141 轮完全一致(双层:CDP 输入拦截 + JS 半透明蒙层 + 「🔒 页面已锁定(仅观看)」
状态条;Agent 输入动作先解后锁;截图避让;HITL 解锁/复锁;导航 re-assert)。
本轮唯一变化:状态条从蒙层子元素改为独立元素(三档共用,见 §7),蒙层本身不变。

### 4.2 open 非屏蔽模式(新晋一等模式)

- CDP `Input.setIgnoreInputEvents(false)`(显式放行,幂等),无蒙层、无盾区;
- 左下角常驻「🔓 页面开放 · 人工可直接操作」状态条:人工**明确知道**现在可以上手,
  且知道操作完应通过「人工介入」弹窗告知 Agent(状态条副文案);
- Agent 侧提示词同步:open 模式下 Agent 操作页面与人工存在真实的并发可能,要求
  Agent 在关键写操作前 `inspect` 校验现场,发现页面状态与预期不符时先与用户对齐
  (而不是盲目重试);
- 用途:需求 3 的反面(人工全程参与)、需求 6 的登录先行流(§6)。

### 4.3 partial 部分屏蔽模式(全新)

- CDP `Input.setIgnoreInputEvents(false)`(输入管线放行,靠 DOM 盾区拦截);
- 盾区视觉:红色调半透明盾罩(`rgba(185,28,28,.18)` + 虚线边框)+ 盾罩上沿
  「🔒 已锁定(仅 Agent)」小标签;白名单形态为条带分解出的整屏深色罩+洞;
- 状态条:「🛡 部分锁定 · 盾区不可操作 / 其余区域人工可直接操作;需要调整范围请告知 Agent」;
- Agent 输入动作「先隐盾后复盾」(§3.2);截图/OCR 自动避让盾区(证据干净);
- 用途:人工与 Agent **同页分区协作**——典型如「人工填登录表单,Agent 同时处理页面
  其它部分」「放行视频播放区,锁住支付/删除按钮」。

## 5. 启动 / 激活 / 使用方式

### 5.1 启动时指定:`open` 新参数

```
open(url, guard?="locked"|"open"|"partial",
     allow_selectors?=[...], block_selectors?=[...], guard_note?="...",
     /* 既有 */ mode?, overlay?, highlight?, ...)
```

- `guard` 缺省解析链:`open 显式 guard` > **legacy `overlay` 布尔**(true→locked /
  false→open,第 141 轮参数完全兼容)> `LAEW_WEB_GUARD` 环境变量 > `LAEW_WEB_OVERLAY=off`
  (legacy,→open)> 缺省 `locked`;
- `guard_note`(≤60 字符):状态条第三行的自定义提示,三档通用——需求 6 的关键载体,
  例如 `guard="open", guard_note="请登录后应答弹窗,Agent 将接管后续操作"`;
- 响应新增 `data.guard = {mode, allow_selectors, block_selectors, note, input_locked,
  visual_mask, shields_active, hint}`;legacy `data.overlay` 字段保留(由 guard 派生,
  `enabled ≡ mode==locked`),既有提示词/测试零破坏。

### 5.2 运行时切换:`control(set_guard)`(第 41 个写操作)

```
control(page_id, control_action="set_guard",
        params={ mode?: "locked"|"open"|"partial",
                 allow_selectors?: [...],   // 提供即整体替换;缺省保持现值
                 block_selectors?: [...],
                 note?: "..." })            // 空串=清除
```

- 任一字段缺省 = 保持现值,只传要改的;`mode` 与选择器联合校验同 open;
  **切到 locked/open 时自动清除上一 partial 档遗留的选择器**(「保持现值」语义下
  存量选择器会让档位校验卡死,真机端到端实测踩中后修正);
- 镜像 `set_highlight` 语义:更新实例期望态 + 立即对指定 page 应用;
- 响应 `{mode, allow_selectors, block_selectors, note, input_locked, visual_mask,
  shields_active, visuals_applied, hint}`;
- legacy `set_overlay(enabled)` 保留为别名:`true→set_guard(locked)`、`false→set_guard(open)`,
  响应附 `deprecation` 提示指向 `set_guard`。

### 5.3 环境变量

| 变量 | 取值 | 行为 |
| ---- | ---- | ---- |
| `LAEW_WEB_GUARD`(新) | `locked`(缺省)/ `open` | open 启动缺省管控档(级联在 open 参数与 legacy overlay 之后) |
| | `partial` | **不支持**(环境变量无选择器载体),解析为空走下一级并 warn |
| `LAEW_WEB_OVERLAY`(legacy) | `off/0/false/no` | → 缺省 `open`;其余 → 缺省 `locked`(第 141 轮语义原样保留) |

### 5.4 生命周期总览(三档通用)

```
open(guard=X) ──► new_page:存实例期望态 inner.guard ──► 注入管控脚本(烘焙 X)
                    └─ headed && 非 connect 才注入;apply_page_guard(X):
                       CDP ignore 按 X + JS __laewGuardSet(X)
Agent 输入动作(20 个白名单,§5.5)
  ├─ locked: 解锁(ignore=false) → 动作 → 复锁(ignore=true)      [ms 级]
  └─ partial: 隐盾(suspend=true) → 动作 → 复盾(suspend=false)    [ms 级]
导航类动作(navigate/back/forward/reload/new_tab)与 open 同 URL 复用
  └─ 完成后 re-assert:按实例期望态重新 apply_page_guard(两层/盾区收敛)
截图(screenshot / ocr / HITL 附图)
  └─ 挂起视觉(suspend:蒙层+盾区+状态条全隐)→ 拍摄 → 恢复        [证据干净]
request_human(unlock_page=true,locked/partial 下)
  └─ 第 144 轮:优先 partial 凭证区挖洞(allow_selectors 显式 > 自动探测
      账号/密码/验证码输入区,见 unlock_zone)→ 探测不到才整页 open;
      提问期间主 frame 导航自动重放放行态(登录→2FA 不断链)
      → 弹窗提问(人工只能在放行区域操作,状态条🛡明示)→ 应答/超时/取消
      → 回收重放协程 + 按实例期望态恢复 apply_page_guard(原档位)      [分钟级]
点击派生新页(adopt_spawned_pages)
  └─ 按实例期望态注入 + 应用(新页同权)
set_guard(...) / set_overlay(...)
  └─ 更新期望态 + 对指定页应用
人工自己新开的标签页
  └─ 无注入无锁(人工自己的页面;Agent 下一个动作 adopt 时才注入)
```

### 5.5 注入脚本 JS API(测试锚点)

`Page.addScriptToEvaluateOnNewDocument(run_immediately:true)` 挂载,全 frame 生效,
导航自动重注入。暴露:

| API | 语义 |
| ---- | ---- |
| `window.__laewGuardSet(mode, allow[], block[], note)` | 运行期全量设置(Rust `apply_page_guard` 调用) |
| `window.__laewGuardSuspend(bool)` | 挂起/恢复全部视觉(蒙层+盾区+状态条);不动 CDP |
| `window.__laewOverlaySet(bool)` | legacy 兼容:true→locked,false→open(第 141 轮路径/单测锚点) |

元素锚点:`#__laew_overlay__`(蒙层)/ `#__laew_overlay_hint__`(状态条,主文档 only)/
`#__laew_guard_shields__`(盾区容器);全部 `data-laew-agent="1"`,`page_state` 的
window 探测排除 `__laew*` 前缀(既有卫生规则,新键天然覆盖)。

## 6. Agent 自主判定与人工交互(需求 5/6)

### 6.1 模式判定决策表(注入系统提示词 §17)

| 用户提示词信号 | 推荐档位 | 依据 |
| ---- | ---- | ---- |
| (缺省)/ 自动采集 / 含支付·删除·提交等高风险动作 | `locked` | 防交叉操作是安全基线 |
| 「我自己操作 / 我来点 / 我先登录 / 你看着 / 演示时我也要动手」 | `open` | 人工声明要亲自操作 |
| 「我操作 XX 部分 / 你管其它的 / 锁住支付按钮 / 只让我动登录框」 | `partial` + 对应选择器 | 分区协作 |
| 「用我登录好的浏览器 / 复用登录态」 | `reuse_existing=true`(第 142 轮) | 人工已完成登录 |
| 信号不明确 | `locked` 起步,需要人工参与时经 `request_human` 询问 | 宁可保守 |

切换时机(运行中):任务进入「等待人工完成某步」阶段 → `set_guard(open, note=指引)`
或 HITL 临时解锁;人工完成后应答 → `set_guard(locked)` 回到防交叉基线。

### 6.2 人工登录先行流(需求 6)两条通道

**通道 A —— 用户自己的 Chrome 已登录(第 142 轮,零改动)**:
`open(reuse_existing=true)` 自动探测调试端口接管,登录态完整保留。

**通道 B —— 在 Agent 启动的浏览器里人工登录(本轮成型)**:

```
① open(url, guard="open", guard_note="请登录本站;完成后应答弹窗,Agent 将接管后续操作")
② control(request_human, reason="login",
          message="请在浏览器窗口中完成登录(页面已开放人工操作),完成后点「已完成」",
          options=["已完成登录,继续", "登录遇到问题", "取消任务"])
    └─ 提问期间本就解锁;open 档人工全程可操作;状态条+note 即 UI 引导
③ 人工在页面里输入账号/密码/验证码 → 弹窗点「已完成登录,继续」
④ control(set_guard, mode="locked")   ← 收口:回到防交叉基线
⑤ Agent 继续任务(inspect 验证登录态 → 后续操作)
```

- 通道 B 的 UI 提示 = 状态条(guard_note 自定义行),不额外造弹窗(人工介入弹窗
  本身就是传话通道);
- 若登录表单只占页面局部、Agent 还要同时干别的,②可改 `guard="partial",
  allow_selectors=["form.login", "#login-box"]`(人工只能在登录区操作,Agent 的动作
  由「先隐盾后复盾」保障)。

## 7. UI 交互设计(状态条 / 盾区 / note)

### 7.1 状态条(三档共用,主文档唯一)

`position:fixed; left:18px; bottom:18px`,深色圆角胶囊(与第 141 轮同款视觉),
两行主文案 + 可选第三行 note:

| 档位 | 标题行 | 副行 |
| ---- | ---- | ---- |
| locked | 🔒 LAEW Agent 控制中 · 页面已锁定(仅观看) | 人工操作已拦截;如需介入请应答「人工介入」弹窗 |
| open | 🔓 页面开放 · 人工可直接操作 | Agent 协同中;人工完成操作后应答「人工介入」弹窗告知 |
| partial | 🛡 部分锁定 · 盾区不可操作 | 其余区域人工可直接操作;需要调整范围请告知 Agent |
| +note | (任意档位) | `guard_note` 原文(浅色第三行,≤60 字符) |

- 状态条是 `pointer-events:none` 纯视觉,不挡任何点击;
- 截图/OCR/HITL 附图采集期间随挂起通道整体隐藏(证据干净);
- 状态条从第 141 轮的「蒙层子元素」改为独立元素:蒙层只在 locked 显示,而状态条
  三档都要在(开放档也要让人工知道「可以操作」)。

### 7.2 盾区视觉(partial)

- 黑名单盾:`rgba(185,28,28,0.18)` 红调半透明 + 1.5px 虚线边框,盾罩上沿外侧
  「🔒 已锁定(仅 Agent)」小标签(深红底浅红字,white-space:nowrap);
- 白名单盾:`rgba(15,23,42,0.30)` 深色调矩形盾条带拼合(允许区透亮可见,形如整屏罩挖洞);
- 全部 `data-laew-agent="1"`、`pointer-events:auto`、`z-index:2147483645`
  (低于蒙层 2147483646 与高亮蓝框 2147483647);
- 滚动/缩放/DOM 变化时 rAF 节流重算;MutationObserver 忽略自身节点的变更(防自激循环)。

## 11. 边界(如实记录)

- **浏览器 chrome 不拦**(同第 141 轮):地址栏/标签栏/窗口拖动人工仍可操作;
- **partial 盾区是 DOM 级**:页面自身 JS 仍可编程改变被盾元素(盾拦的是人工输入,
  不是页面逻辑);盾罩跟随 rAF 重算,极端高频动画下有 ≤1 帧视觉滞后;
- **白名单挖洞走矩形条带分解**:不依赖 `clip-path`(实测部分 Chrome 版本拒绝
  `path(evenodd,…)` 语法,已弃用该方案),任何 Chromium 版本行为一致;
- **open/partial 下人工与 Agent 真并发**:Agent 关键写操作前需 inspect 校验(提示词
  约束),工具层无法完全消除竞态——这是「人工可操作」需求的固有代价;
- **hidden / connect 模式不注入管控脚本**:无窗口 / 用户自己的浏览器,任何视觉与
  输入拦截都不适用(connect 档位强制 open 且零注入)。
