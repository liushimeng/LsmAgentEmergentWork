# MCP_Web_Use 可视化模式页面蒙层与人工操作拦截方案(第 141 轮)

> 关联:`01-设计与解决方案.md`(总设计,§21 索引)、`02-人工介入与窗口可视化方案.md`(HITL,
> 本轮为其补 §13「HITL 期间页面自动解锁」)、`browser_mode.rs`(第 139 轮可见模式统一)。
>
> 需求原文(2026-10-09):
> 1. macOS/Windows 上 `MCP_Web_Use` 启动 Chrome 用**有窗口可视化模式**(人工可见);
> 2. Linux 等服务器(无 GUI)上启动 Chrome 用**内存无头非可视化模式**;
> 3. 可视化模式下,Web 页面添加**半透明蒙层**,人工**不可点击/操作**页面(防交叉操作),
>    但**可以实时观看**页面变化;人工与 Web 的功能交互一律通过**「人工介入」弹出式菜单**完成。

## 1. 背景与问题

第 139 轮起浏览器默认可见(headed):人工能看见 Agent 控制的窗口(蓝色选中边框 +
「LAEW Agent 控制中」徽标),但也**能直接点击页面**。实测风险:

- **交叉操作**:Agent 正在填表单/滑滑块,人工同时点页面 → 两路输入互相覆盖,页面状态
  与 Agent 认知脱节,QC 对账全错;人工误触「支付/删除/退出登录」类按钮更是不可逆事故;
- **取证失真**:人工动过的 DOM 与 Agent 轨迹混在一起,Debug 报告无法归因;
- **焦点抢占**:人工点击把焦点移走,Agent 后续 `key_press` 输入到错误元素。

蓝色边框只是「标识」不是「锁」(`pointer-events:none` 明确不拦截任何事件)。本轮补上「锁」。

## 2. 需求 1/2 的现状确认(零代码变更,第 139 轮已覆盖)

| 环境 | 模式 | 决策点 |
| ---- | ---- | ---- |
| macOS/Windows(有 GUI 会话) | `Headed` 可见窗口 | `BrowserMode::DEFAULT = Headed` + `has_gui_session()` |
| Linux 服务器(无 `DISPLAY`/`WAYLAND_DISPLAY`) | `Hidden` 内存无头 | `has_gui_session()` 自动回退(`CI`/`SSH`/`launchctl` 非 Aqua 同) |
| 强制切换 | 任一 | 工具参数 `mode` > `LAEW_BROWSER_MODE` > GUI 探测 |

唯一真源 `src/agent/browser_mode.rs`,本轮不改。本文档余下部分全部针对**需求 3**。

## 3. 总体设计:双层「锁 + 蒙」

```
┌─ Chrome 窗口(headed)──────────────────────────────────────┐
│  浏览器 chrome(标签栏/地址栏/滚动条)── 不拦(页面级拦截的天然边界) │
│ ┌─ 页面内容区 ──────────────────────────────────────────┐ │
│ │  L2 视觉蒙层(JS):rgba(15,23,42,.22) 半透明遮罩 + 锁定提示条 │ │
│ │     pointer-events:none,纯视觉,零 hit-test 参与        │ │
│ │  ────────────────────────────────────────────────────  │ │
│ │  页面本体(人工实时可见,Agent 全权操作)                  │ │
│ └───────────────────────────────────────────────────────┘ │
│  L1 输入拦截(CDP):Input.setIgnoreInputEvents(ignore=true)  │
│     浏览器级丢弃全部真实用户输入(鼠标/滚轮/键盘/触摸),全 frame │
└──────────────────────────────────────────────────────────┘
```

| 层 | 手段 | 拦真实输入 | 拦 CDP 合成输入 | 跨 frame | 跨导航 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| L1 输入拦截 | CDP `Input.setIgnoreInputEvents` | ✅(浏览器输入管线) | ⚠️ **也拦**(实测,见 §4) | ✅ target 级 | ✅ 持久(实测) |
| L2 视觉蒙层 | 注入 JS `position:fixed` 遮罩 | ❌(纯视觉) | ❌ | ✅ 每文档注入 | ✅ 自动重注入 |

**分工**:L1 负责「锁」(人工进不来),L2 负责「蒙 + 说明」(人工知道为什么点不动、该去哪交互)。

## 4. 关键决策与实测证据

### 4.1 为什么不用 DOM 蒙层拦截输入(`pointer-events:auto`)

CDP 合成输入与真实输入在**hit-test 层不可区分**(`isTrusted` 均为 `true`,这是 CDP 输入
注入的设计目标)。`pointer-events:auto` 的全屏蒙层会把 Agent 自己的 `click` 一并吃掉;
且蒙层的「挂起」标志(供 Agent 操作时临时放行)放在主 frame `window` 上,**跨域 iframe
读不到**——Agent 点击跨域 iframe 区域(嵌入视频/验证码组件/评论区)会被误拦,且无法从
主 frame 解除。CDP 输入拦截是 target 级、全 frame 一致、不参与 DOM hit-test 的正确层级。

### 4.2 `Input.setIgnoreInputEvents` 行为实测(本机 Chrome,headless=new 探针)

| 实验 | 结果 | 结论 |
| ---- | ---- | ---- |
| 基线:CDP 点击计数 | 1 | 探针有效 |
| `ignore=true` 后 CDP 点击 | **仍为 1(未+1)** | **CDP 合成输入同样被拦** |
| 跨导航后再 CDP 点击 | 0(仍被拦) | **标志跨导航持久** |
| `ignore=false` 后 CDP 点击 | +1 | 可恢复,开关语义正常 |

推论:**Agent 自己的每一个输入类动作必须「先解后锁」**(动作前 `ignore=false`,动作后
`ignore=true`)。窗口极短(ms 级),与「人工介入期间长时解锁」(§7)语义分明。

### 4.3 视觉蒙层形态

- 全屏 `position:fixed; inset:0; z-index:2147483646`(高亮蓝框 2147483647 仍在其上,
  徽标不被蒙层盖住);`pointer-events:none`;`background:rgba(15,23,42,0.22)` —— 22%
  深色半透明,内容、图片、动效全部实时可见,但「明显有一层东西」;
- 主文档(`window.top === window`)左下角锁定提示条:「🔒 LAEW Agent 控制中 · 页面已锁定
  (仅观看)/ 人工操作已拦截,如需介入请应答『人工介入』弹窗」;iframe 只铺蒙层不重复文案;
- `data-laew-agent="1"` 标记:`blockers` 的正文扫描(克隆 body 后剥 `[data-laew-agent]`)
  天然排除提示条文本;`elements/dom` 提取沿用同一过滤;
- 注入通道与高亮蓝框同款:`Page.addScriptToEvaluateOnNewDocument(run_immediately:true)`
    —— 导航/派生新页自动重注入,所有 frame 各自生效。

### 4.4 截图避让(蒙层不进证据链)

蒙层在页面里,`Page.captureScreenshot` 会把它拍进去:Agent 看图/OCR 会被 22% 遮罩 +
提示条干扰(HITL 验证码附图尤其不能带蒙层)。所有截图路径统一「**拍前隐藏 → 拍完恢复**」
(gate 在 `BrowserManager::overlay_active()`,蒙层未启用时零开销):

- `control(screenshot)` / `inspect(screenshot|ocr)`(同走 `act_screenshot`);
- HITL 附图自动采集 `captcha_crop::capture_hitl_screenshot`(独立 `page.screenshot` 路径)。

### 4.5 `page_state` window 全局键探测的卫生

蒙层脚本在 `window` 上挂 `__laewOverlayInstalled/__laewOverlayOn/__laewOverlaySet`
(高亮脚本此前已挂 `__laewAgentHighlight*`)。`page_state` 的 `probe_window` 扫 `__` 前缀
键,本轮统一加 `!n.startsWith('__laew')` 排除,顺带修掉高亮脚本的既有污染。

## 5. 工具面变化

### 5.1 `open` 新参数 `overlay`

| 项 | 值 |
| ---- | ---- |
| 类型 | boolean,默认 `LAEW_WEB_OVERLAY`(未设置=on) |
| 生效条件 | 仅最终 `mode == headed`(hidden/new_headless 忽略,无窗口无人工可拦) |
| 响应 | `data.overlay = {enabled, input_locked, visual_mask, hint}` |

### 5.2 `control_action=set_overlay`(新增,第 40 个)

`set_overlay(enabled)`:运行时开关,镜像 `set_highlight` 语义(更新实例级期望态 +
对指定 page 应用)。两层同开同关。

### 5.3 `control_action=request_human` 新参数 `unlock_page`

默认 `true`:**提问前自动解锁**(输入放行 + 蒙层隐藏,人工看到干净页面),人工应答 /
超时 / 取消后**自动恢复锁定**。理由:HITL 是「该人工操作」的时刻——滑块要拖、扫码页要看、
登录页要填,保持锁定会让 HITL 形同虚设;这也是需求 3「人工通过人工介入弹出式菜单和
Web 端界面进行功能交互」的落地:弹窗应答 + 弹窗期间直接操作页面。
`unlock_page=false` 保留纯问答场景(如「确认继续?」)不开放页面。

### 5.4 Agent 输入动作「先解后锁」白名单

`action_dispatches_input`(蒙层激活时每个动作 2 次 CDP 往返,~ms 级;未激活零开销):

```
click / human_click / right_click / double_click / hover / scroll / scroll_to /
key_press / press_sequence / input_text / human_input / clear_input / upload_file /
select_option / download / drag / focus / blur / mouse_move / dispatch_event
```

保守圈定「可能经 CDP `Input.dispatch*` 或 chromiumoxide `Element::click()/type_str()`
注入输入」的全部动作(部分默认走 JS 路径,如 `input_text(use_js=true)`,多解锁一次无害)。
`wait / eval_js / inspect / set_* / screenshot / heartbeat / navigate 类`不注入输入事件,不解锁
(长动作期间保持锁定,避免「等待 30s 页面裸奔」)。导航类动作(`navigate/back/forward/
reload/new_tab` 与 open 复用路径)完成后 **re-assert**:CDP 标志实测持久,JS 蒙层新文档
按注入时烘焙的初始态重建,若运行期 `set_overlay(false)` 后发生导航,re-assert 使两层收敛。

### 5.5 环境变量 `LAEW_WEB_OVERLAY`

| 取值 | 行为 |
| ---- | ---- |
| `off`/`0`/`false`/`no` | 缺省关闭(不注入、不锁,与第 140 轮行为一致) |
| 未设置(默认) | 缺省开启(headed 生效) |

单次任务级覆盖:open(overlay=false)。与 `LAEW_BROWSER_MODE` 同构的灰度/回退开关。

## 6. 生命周期总览

```
open(mode=headed, overlay=on)
  └─ new_page:存实例期望态 inner.overlay → 注入蒙层脚本(烘焙 initial=on)
      → Input.setIgnoreInputEvents(true) → 响应 data.overlay
Agent 输入动作(5.4 白名单)
  └─ 解锁(ignore=false) → 动作 → 复锁(ignore=true)     [每动作,ms 级窗口]
导航类动作 / open 同 URL 复用
  └─ 完成后 re-assert(蒙层显示 + ignore=true)           [两层收敛]
request_human(unlock_page=true)
  └─ 解锁(ignore=false + 蒙层隐藏) → 弹窗提问(人工此时可直接操作页面)
      → 应答/超时/取消 → 复锁(蒙层恢复)                  [人工窗口,分钟级]
截图(screenshot/ocr/HITL 附图)
  └─ 蒙层隐藏 → 拍摄 → 蒙层恢复                          [证据干净]
点击派生新页(adopt_spawned_pages)
  └─ 按实例期望态注入蒙层 + 加锁                          [新页同权]
set_overlay(enabled)
  └─ 更新期望态 + 对指定页应用(CDP+JS 两层)
人工自己新开的标签页
  └─ 无蒙层无锁(人工自己的页面;Agent 下一个动作 adopt 时才注入)
```

## 7. 边界(如实记录,不夸大能力)

- **浏览器 chrome 不拦**:地址栏导航 Agent 标签页、拖动/缩放窗口、新开标签、关闭标签,
  人工仍可做——页面级拦截的天然边界。彻底物理隔离需要窗口级方案(macOS
  `NSWindow.ignoresMouseEvents` / Win32 `WS_EX_TRANSPARENT`),侵入私有 API、脆弱且会把
  「人工查看」一起废掉,不采纳;
- **键盘拦截范围**:页面内键盘输入全拦;浏览器级快捷键(⌘T/⌘W/Ctrl+F 等)不受影响——
  这恰好保留人工「查看」手段(浏览器查找栏),符合「可看不可动页面」;
- **无头模式无蒙层**:hidden/new_headless 无窗口无人工,注入无意义且污染 DOM,跳过
  (与高亮蓝框同款门控);`connect_url` 接管的外部浏览器同样按最终 mode 判定。

## 9. 提示词增补(§17 节选)

> **页面蒙层与人工操作拦截(第 141 轮)**:headed 模式下页面默认被半透明蒙层锁定
> (「🔒 LAEW Agent 控制中 · 页面已锁定」),人工只能观看不能操作——这是设计行为,
> 不是页面故障,不要尝试移除蒙层。Agent 自己的 click/input 等输入动作会自动「先解后锁」,
> 无须关心。需要人工直接操作页面(拖滑块/扫码/登录)时走 `request_human`
> (默认 `unlock_page=true`:提问期间自动解锁页面,人工应答后自动复锁);
> 纯问答场景可传 `unlock_page=false`。运行时开关用 `control(set_overlay, enabled)`。
