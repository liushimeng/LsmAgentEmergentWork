# 16-自定义下拉控件与级联选择器操作能力

> 第 158 轮 · 2026-10-12
> 实测触发：闲鱼（goofish.com）城市选择器卡 263s / 24 轮迭代

## 1. 问题背景

### 1.1 实测现象

Agent 在闲鱼执行「交易地区筛选为北京」时，卡在城市选择器上长达 **263.6 秒**（24 轮迭代、23 次工具调用），最终靠 Agent 自己用 `eval_js` 手写 JS 拼凑完成。

### 1.2 根因

闲鱼的城市选择器是 **Ant Design Cascader 自定义级联选择器**，不是原生 `<select>` 元素：

```
面板结构（从日志 iter=12 的 eval_js 回读）：
div.areaWrap--KaVEpxtC (ant-popover-open)
├── 第一列（省级）：div.provItem--gG8I2YJh → "全国" | "北京"(provItemActive) | "天津" | ...
├── 第二列（区级）：div.cityItem → "全北京" | "东城区" | "西城区" | "朝阳区" | ...
└── 操作：点省级「北京」仅高亮 → 必须再点二级「全北京」才提交筛选
```

### 1.3 现有 `select_option` 的局限

| 缺陷 | 影响 |
|------|------|
| 只支持原生 `<select>`（依赖 `el.options`/`el.selectedIndex`） | 自定义控件完全无法操作 |
| `el.options` 在自定义控件上为 `undefined` → JS 异常 → `code=2002` | Agent 收到 JS 黑话，无法据此改路 |
| 无回读校验 | 不知道是否真的选中了 |
| 无级联支持 | 闲鱼需要两级点击（省→市/区），`select_option` 无法表达 |
| `inspect(info=elements)` 默认选择器不覆盖自定义下拉 | Agent 只能靠 `dom` 或 `eval_js` 自行探索 |

## 2. 解决方案

### 2.1 新增 `select_dropdown` action

**参数设计**：

```json
{
  "control_action": "select_dropdown",
  "params": {
    "option_text": "北京",
    "trigger_text": "区域",
    "cascader_text": "全北京",
    "wait_ms": 800,
    "selector": "div.areaWrap"
  }
}
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `option_text` | 是 | 第一级选项文本（如"北京"） |
| `trigger_text` | 否 | 触发器文本（如"区域"），点击展开面板 |
| `cascader_text` | 否 | 级联第二级选项文本（如"全北京"） |
| `wait_ms` | 否 | 等待面板出现的时间（毫秒），默认 800 |
| `selector` | 否 | 面板容器选择器，用于限定查找范围 |

**返回结构**：

```json
{
  "code": 0,
  "data": {
    "selected": true,
    "option_text": "北京",
    "cascader_text": "全北京",
    "trigger_clicked": true,
    "clicked_texts": ["区域", "北京", "全北京"],
    "value_after": "北京 全北京",
    "mode": "custom_dropdown"
  }
}
```

**实现逻辑**：

1. 如果传了 `trigger_text`，查找包含该文本的可见叶子节点并点击（展开面板）
2. 等待 `wait_ms`（默认 800ms）
3. 在 `selector` 范围（或整个页面）内查找 `option_text` 匹配的可见叶子节点并点击
4. 如果传了 `cascader_text`，再等待 `wait_ms`，然后查找并点击 `cascader_text`
5. 用 `eval_js` 回读面板当前文本或触发器文本，返回 `value_after`

**核心 JS 逻辑**（`pick_element_js` 函数生成）：

```javascript
(() => {
    const vis = e => { const r = e.getBoundingClientRect(); return r.width > 0 && r.height > 0; };
    const target = "北京";
    const scope = document.querySelector("div.areaWrap") || document.body;
    const candidates = [...scope.querySelectorAll('span,div,a,li,label,button,i,p')]
        .filter(e => e.children.length === 0 && vis(e));
    let el = candidates.find(e => (e.innerText || e.textContent || '').trim() === target);
    if (!el && true) {
        el = candidates.find(e => (e.innerText || e.textContent || '').trim().includes(target));
    }
    if (!el) return JSON.stringify({ ok: false, found: candidates.length });
    el.scrollIntoView({ block: 'center' });
    el.click();
    return JSON.stringify({ ok: true, tag: el.tagName, text: (el.innerText || '').trim() });
})()
```

### 2.2 增强 `select_option` 的自定义控件兼容

在 `act_select_option` 中添加**自定义控件回退路径**：

- 当 `selector` 指向的元素**不是**原生 `<select>`（即 `el.options` 为 `undefined`）时，自动回退到 `select_dropdown` 的文本匹配逻辑
- 检测方式：`eval_js` 检测 `el.tagName === 'SELECT' && el.options`
- 回退时需要 `text` 参数；无 `text` 则报错引导使用 `select_dropdown`

### 2.3 扩展 `inspect(info=elements)` 默认选择器

```css
/* 旧 */
input,button,select,textarea,a,[role=button],[role=link],[contenteditable=true]

/* 新 */
input,button,select,textarea,a,[role=button],[role=link],[contenteditable=true],
[role=combobox],[aria-haspopup=listbox],
[class*=select],[class*=Select],[class*=dropdown],[class*=Dropdown],
[class*=cascader],[class*=Cascader]
```

## 4. 与现有功能的关系

| 功能 | 适用场景 | 操作对象 |
|------|----------|----------|
| `select_option`（现有） | 原生 `<select>` 元素 | `el.options` / `el.selectedIndex` |
| `select_dropdown`（新增） | 自定义 JS 下拉/级联选择器 | 文本匹配 + 点击叶子节点 |
| `select_option`（增强后） | 原生 `<select>` + 自定义控件回退 | 自动检测，非原生 select 时走文本匹配 |
| `click` + `eval_js`（现有） | 通用兜底 | Agent 手写 JS（不再需要） |

## 5. 白名单联动

`select_dropdown` 已自动接入以下白名单（通过 `action_dispatches_input`）：

- 蒙层让路（`guard_lift_for_input` / `guard_restore_after_input`）
- HITL 挂起闸（`hitl_guard.rs::should_suspend`）
- 阻断感知硬闸（`blocker_probe.rs::action_needs_probe` + `input_gate`）
- 派生页巡检（`action_may_spawn_page`）

## 6. 通用性保证

- **不针对闲鱼定制**：`pick_element_js` 是通用的文本匹配 + 点击逻辑，适用于所有 Ant Design / Element UI / 自研组件库
- **精确匹配优先**：先 `===` 精确匹配，失败后 `includes` 模糊兜底
- **范围限定**：`selector` 参数可限定查找范围，避免全局误匹配
- **回读校验**：`value_after` 回读面板文本，Agent 可确认操作是否生效
- **错误引导**：找不到元素时返回明确错误信息，引导 Agent 改用 `select_dropdown` 或 `inspect` 探测
