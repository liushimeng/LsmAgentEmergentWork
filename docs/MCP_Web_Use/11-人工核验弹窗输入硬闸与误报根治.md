## 2. 四层设防(F1–F4)

### F1 关键词通道整词边界(治 R1,`inspect.rs`)

- 新增 `ascii_keyword_boundary_find`:**纯 ASCII 关键词**要求命中位置前后字符都不是
  `[0-9a-zA-Z]`(小写化后判定)。`"2fa"` 在 `…002Fae…`(前字符 `0`)、`"sms"` 嵌
  十六进制哈希均被拒;`「请开启 2FA 验证」`/`"enter the TOTP code"` 等真命中
  (前后是空格/中文/行首尾)不受影响。
- 含 CJK 的关键词(「验证码」「扫码登录」等)保持子串匹配 —— 中文词不会以 URL
  子串形态出现,无需收紧。
- 效果:页面干净期假告警归零,`blocker_alert` 恢复「出现即真」的可信度。

### F2 eval_js 纳入推送探针(治 R2,`blocker_probe.rs`)

- `action_needs_probe` 增加 `"eval_js"`:无论读写,动作收尾统一探测一次(一次 eval
  往返,健康页面 ~10-50ms;fail-open 2s 超时语义不变)。长轮询返回时刻 = 弹窗出现后
  的第一个检查点。
- 新增纯函数 `eval_expression_mutates(expr)`:小写包含 `execcommand` / `inserttext` /
  `dispatchevent` / `keyboardevent` / `mouseevent` / `.click(` / `.focus(` / `.submit(` /
  `location.href` / `location.assign` / `location.replace` / `window.open` /
  `document.write` 之一即视为可变更页面,供 F3 硬闸圈定「可变更 eval」。

### F3 输入前置硬闸 6002(治 R3,`blocker_probe.rs::input_gate/challenge_gate`)

- **接入点**:`control::run` 在 guard_lift(先解后锁)**之前**调用
  `blocker_probe::input_gate(id, action, params)`;`Some` = 拦截信封直接返回,
  动作不执行。被拦下的动作不触碰「先解后锁」时序。
- **覆盖动作面**:输入类 20 动作(`action_dispatches_input` 白名单)+ 可变更 eval_js
  (`eval_expression_mutates` 判定)。
- **判定口径**:`challenge_gate` 只认 `detect_challenge` 的**弹层结构证据**(九宫格/
  背景图网格/iframe_like/canvas/验证文案打分 ≥3),**不认关键词通道** —— 关键词命中
  (如页面常驻的「请登录」文案)可能长期在场,作硬闸会把输入永久锁死。
- **信封**:`code=6002`(归 6xxx「范围/人工核验约束」段,与 6001 任务锚点同家族),
  data 携带 `blocker_alert`(含 evidence + hint)+ `next_action="request_human"` +
  完整 `human_assist` 载荷(message 带题面 snippet,人工在 HITL 弹窗即知要验证什么)
  + `force_hint` 逃生口说明。
- **逃生口**:`params.force=true` 跳过本次硬闸(应对极小概率结构误判,保 Agent 自主性)。
- **sequence 自动接管**:6002 步的 data 带 `blocker_alert` → 第 150 轮整批中断逻辑
  生效,顶层透出 `interrupted_by:"blocker_alert"` + human_assist。
- **语义**:不是解锁制 —— 人工完成验证、应答弹窗后页面干净,下一个动作自然通过,
  无需任何解锁操作。

### F4 探针识别面与告警文案补强(`blocker_probe.rs`)

- **bg-image 九宫格信号**:部分挑战格不用 `<img>` 而用 CSS `background-image` 渲染,
  `PROBE_JS` 补计 `bg_imgs`(overlay 内计算样式含背景图、尺寸 48~240 且宽高比
  0.5~1.6 的元素,遍历上限 600 节点防大弹层拖慢);打分制 `grid_imgs + bg_imgs ≥ 4 → +2`,
  evidence 同步带出。
- 弱指令词补「翻转」「找出」「图标」。
- `probe_alert` / 硬闸的 human_assist **message 带题面 snippet(≤60 字)**:
  「页面弹出人工验证挑战「选出卧室家具…」,请在浏览器窗口完成验证,完成后回弹窗点
  『提交 / 继续』(也可在输入框输入文字与 Agent 交互)」—— 人工不用猜要验证什么;
  HITL 弹窗第 145 轮「提交 / 继续」双语义天然支持「输文字交互 / 点继续交棒」两种意图。

## 3. 边界(不改什么)

- HITL 弹窗本体(第 137/145 轮)、页面管控三档(第 143 轮)、eval 超时兜底与
  sequence 步级防护(第 150 轮)语义全部不动。
- `LAEW_WEB_BLOCKER_PROBE=off` 仍是总杀开关:推送探测、输入硬闸、双通道 blockers
  全部归零回退(硬闸依赖探针,探针关则闸亦关,无独立环境变量)。

- 6002 只拦「结构判定」的挑战弹窗;关键词命中仍走附注式 `blocker_alert`(第 147 轮
  语义),不升级为硬拦截。
