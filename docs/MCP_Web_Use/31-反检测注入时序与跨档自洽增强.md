## 一、定位：本轮的判据是「时序」与「跨轮」

前三轮的判据统一是**空间维度**的：「这个字段回填得像不像原生」。它们没能覆盖两类
完全不同的问题——

| 维度 | 问题形态 | 前三轮的判据能否发现 |
| ---- | -------- | -------------------- |
| 空间 | 字段值/对象形态不像原生 | ✅ 能（第 175/176 轮全部在此维度） |
| **时序** | 处置发生在**读取之后**，读取时环境还是裸的 | ❌ 不能 |
| **跨轮** | 处置在第 1 轮生效，第 2 轮（换文档/换档）把它覆盖或遗弃 | ❌ 不能 |
| **漏检** | 我们没测到的检测面（第三方自动化痕迹等） | ❌ 不能 |

本轮四组改动分别落在这三个新维度上。**没有新增任何反检测技术栈**——本轮不碰
Canvas/字体伪造、不碰行为仿真、不碰代理池、不碰验证码与协议逆向（边界同 §三）。

## 二、缺口 1（最高价值）：隐身脚本注册在**导航之后**，首个文档全程裸奔

### 现状（`browser.rs::open`）

```
apply_screen_sync_override(...)          // 屏幕几何（导航前）
page.goto(url)                            // ← 导航发生
... apply_ua_destealth 在此之前（正确）...
inject_stealth(&page, mode)               // ← 在 goto 之后
inject_agent_highlight / inject_agent_guard ...
```

`inject_stealth` 走 `Page.addScriptToEvaluateOnNewDocument { run_immediately: true }`。
这个参数只对**当前文档**补执行，对**未来文档**才是 document-start 语义。于是：

- 首个文档的页面脚本在 document-start 已经跑完，读到的是**未处置**的
  `navigator.webdriver === true` 与 `navigator.plugins.length === 0`；
- 站点风控 SDK 恰恰是在文档最早期采指纹并立即上报（aplus / um / jdfacter / geetest
  / baxia 等一律如此），所以**处置永远晚于采集**；
- 同一页面第二次导航起才真正享受 document-start 语义 —— 于是这个缺陷表现为
  「首航必被拦、刷新反而好转」，很容易被误诊为站点随机风控。

代码里那句注释「第 169 轮:隐身覆写最先注入(document-start 执行序 = 注册序)」与
实际调用序是矛盾的：注册序确实最前，但它排在 `goto` 之后。

### 处置

把 `inject_stealth` 移到 `apply_screen_sync_override` 之后、`page.goto` 之前，与
UA 清理同批。这样首个文档从第一行脚本起就是处置过的环境。connect 模式零注入契约
不变，`goto` 之后不再重复注册（重复注册没有意义，还多一次 CDP 往返）。

单测 `隐身脚本注册早于首次导航` 用源码顺序断言锁死，并额外断言「首次导航与下一次
导航之间不得重复注册」。

## 三、缺口 2：跨档升级时身份登记表失忆（上一轮改写全部退回可读源码）

### 现状

身份登记表 `__fd` 是脚本内的**闭包常量**（`const __fd = new WeakMap()`）。这不是
随手选的——挂到 `window` 会新增一个 `getOwnPropertyNames` 可见的全局键，而那本身
就是签名，所以闭包是对的。

问题出在**跨重注入**：`__fd` 每次重注入都是新表。运行时 `control(set_stealth)`
从保真档升到侵入档时：

1. 旧的幂等闸是**单一 rev 整数**（保真=1 / 侵入=2），`rev` 变大就整脚本重跑 →
   保真块的 `getParameter` 被**套两层**包装，且第二份表看不见第一份的函数；
2. 原生化块用**新表**去问「这个函数登记过吗」，对第 1 轮注入的每一个函数答案都是
   「没有」→ 全部报出可读源码。**升档反而短暂变差**（比不升档还差，因为多套了一层）。

### 处置

**① 幂等闸改块位掩码**（`core=1 / fidelity=2 / hardened=4`）

`window.<ns>StealthRev` 的值从版本号变成已装块的位集合，`__need = want & ~cur`。
跨档升级时已置位的块不再重跑——保真→侵入只有原生化块执行，既不叠加包装，
上一轮的保真产物也原样保留（替身对象引用不变，不会被重建）。

**② 原生化前先「重新认领」**（`__adoptAll`）

新表看不见旧函数，就把「页面能拿到引用的那一组固定位置」重新扫一遍登记进新表：
`Navigator.prototype` 的 `webdriver/plugins/mimeTypes/languages`、`window.chrome`、
`Permissions.prototype.query`、两级 `WebGL*Context.prototype.getParameter`，以及回填
替身各层中间原型上的 `item/namedItem/refresh/Symbol.iterator`。

**③ 迭代器：认领不到就重装**

迭代器的 `next` / 自反方法是**每次调用现造的新对象**，原型上根本没有引用，认领
机制对它无效。解法不是往原型上挂状态（那会新增可枚举痕迹），而是把迭代器工厂
**重装**一遍：把工厂抽成前置块共用的 `__mkIterator(items)`，装原生化时对三个数组体
（`plugins` / `mimeTypes` / 每个插件的 `mimeTypes`）用原生 `item()` 逐位反查回 items
并重新 `defineProperty(Symbol.iterator)`，这样**此后每次迭代产出的函数都登记在当前表里**。

重装**只作用于自造的中间原型**（`proto === PluginArray.prototype` 等真原型一律跳过）：
在真实插件存在的环境（Linux 发行版、装了 PDF 插件的 Chrome）替换原生迭代器是把好
环境改坏，属于「为了藏自己而制造更大破绽」。

## 四、缺口 3：两处改写函数从未登记（保真档就漏）

原生化此前只登记了「我们主动包的那一层」，两处漏网：

| 位置 | 原形态 | 页面一行即可识破 |
| ---- | ------ | ---------------- |
| `Permissions` 一致性里 `PermissionStatus.state` 的改写 | `get: () => want`（**未登记箭头**） | `Object.getOwnPropertyDescriptor(st,'state').get.toString()` |
| `plugins[Symbol.iterator]()` 返回的迭代器 | `next: () => …` + 裸 `iter[Symbol.iterator] = function () {…}`（均未登记） | `String(it.next)` / `String(it[Symbol.iterator])` |

两处都已改为经 `reg()` 登记。对应自证项 `patched_fn_leak` 会把这类入口点名回报。

## 五、缺口 4：`Plugin.mimeTypes` 整个字段缺失（回填替身自相矛盾）

原生 `Plugin` 实例必带 `mimeTypes`。我们的回填替身没有这个字段，于是同一页面上：

```js
navigator.mimeTypes.length            // 2
navigator.plugins[0].mimeTypes        // undefined   ← 与上一行直接矛盾
```

一行即可判定替身是假的——比「插件为空」这种弱信号强得多（正常浏览器不会造出这种
自相矛盾的对象）。本轮补齐：每个插件各持一份**独立的** `MimeTypeArray` 视图
（原生亦如此：`plugins[0].mimeTypes !== plugins[1].mimeTypes`），元素仍是同一批
按 type 去重后的 `MimeType` 实例，这样 `mimeTypes[0].enabledPlugin === plugins[0]`
的回指语义才成立。为此把 `makeArrayLike` 上移到 `NAMES.forEach` 之前（`Plugin` 的
中间原型是循环内才拿得到的）。

## 六、漏检面：`data.fingerprint` 新增四项自证 + 一个收敛信号

新增探针字段（全部 fail-open，缺测不告警）：

| 字段 | 判据 | 新增告警码 |
| ---- | ---- | ---------- |
| `automation_globals` | `Object.getOwnPropertyNames(window)` 命中已知自动化框架前缀（`cdc_` / `domAutomation` / `__selenium` / `__playwright` / `__pw` / `__puppeteer` / `_phantom` / …） | `automation_global_leak` |
| `patched_fn_leak` | 逐个已知改写入口问 `toString`，非 `[native code]` 即漏登记 | `patched_function_source_visible` |
| `focus_visibility` | `visibilityState=visible` 却 `document.hasFocus()=false`（真机前台页二者一致） | `focus_visibility_mismatch` |
| `plugin_mimetypes_shape` | `plugins[0].mimeTypes` 的 present/length/tag/instanceof | `plugin_mimetypes_shape_mismatch` |
| `injected_ns_keys` | 注入层 ns 全局键数量 | **只观测不告警** |

`automation_global_leak` 之所以是硬判据：我们经 CDP 驱动**不会产生**这些键，命中
即说明页面上还有第三方自动化痕迹（或站点自己埋了同名脚本）。

`injected_ns_keys` 刻意**不告警**。ns 全局键（`__lznXXXXXXXXStealthRev` 等）
不可枚举但 `getOwnPropertyNames` 可见，彻底消除只能让 `window` 变成 Proxy——
不可行。如实回报数量让 QC 与人工知道有这一层痕迹，比假装没有强。

### `risk_tier`：把一长串 suspicious 收敛成一个可执行信号

`suspicious` 最长能到十几条，模型容易逐条读、逐条慌，却拿不到「该怎么办」。
新增顶层字段把判据压成三档（`fingerprint.rs::HARD_CODES` + `risk_tier`）：

- `ok` —— 无告警；
- `warn` —— 只有软项（如保真档的 `patched_function_source_visible`），
  可 `control(set_stealth)` 升档或复核；
- `high` —— 命中硬判据，**别在拉起环境上继续调参了**，直接
  `open(reuse_existing=true)` 接管用户已登录的真实浏览器。

工具描述（`MCP_Web_Use` schema）已改为「先看 risk_tier」，并修正了此前把
`default` 写成 `fidelity` 的过时描述（缺省自 2026-10-16 起是 `hardened`）。

## 七、验证

### 7.1 Rust 单测（`cargo test --lib`，2393 项全绿）

新增/改写的关键用例：

- `隐身脚本注册早于首次导航` —— 源码顺序断言（注册 < 首次导航，且期间不重复注册）；
- `幂等闸按块位掩码而非单一版本号` —— 位常量、缺位计算、零缺块早退、每块带位闸、
  标记键只出现读+写两处（不新增全局键）；
- `原生化前先重新认领上一轮改写` —— 认领早于原生化，八个认领位置一个不少，
  getter/value 两种形态都覆盖，中间原型也在内；
- `迭代器跨档靠重装而非认领` —— 真原型必须跳过、items 由原生 `item()` 反查、
  三个数组体都重装；
- `插件迭代器自反且迭代器本身已登记` / `插件替身补齐mimeTypes子对象` ——
  `makeArrayLike` 必须在 `forEach` 之前定义（否则 TDZ 报错）；
- `自动化全局泄漏命中且给出具体键名` / `改写函数源码可见命中` /
  `焦点可见性不自洽命中` / `插件子对象形态失配命中` / `风险档三档收敛` /
  `新自证项回报到build` —— 每条告警的正例、反例与缺测 fail-open 都锁死。

### 7.2 真实 JS 引擎复核（Node，仓外脚本）

字符串断言只能证明「代码写了这句话」，证明不了「这段 JS 跑起来对不对」。故把
渲染后的脚本导出后在 Node 里配最小 DOM 垫片真跑一遍
（`cargo test --lib js_dump -- --ignored` 导出 `target/stealth_{fidelity,hardened}.js`）：

- `node --check` 两档脚本均通过语法解析；
- 保真档：plugins/mimeTypes 的 tag / `instanceof` / `namedItem` / 可展开性 /
  `done` 序列 / `own` 键构成（方法在原型上而非实例上）逐项对齐原生；
- 侵入档：全部改写入口（含迭代器 `next`）报 `[native code]`，`toString.toString()`
  自反闭合；
- **跨档路径**：同一文档先注保真档 → 同档重复注入（验证零动作：替身对象引用不变）
  → 再注侵入档（验证重新认领 + 迭代器重装后全部原生化，且替身未被重建）。

## 八、不改动的部分（防回退）

- 不碰验证码/风控判定逻辑本身；不做打码平台、住宅代理池、协议逆向（同 §三）；
- 不做 Canvas/字体指纹伪造、行为轨迹仿真、屏幕几何伪造（取值只来自页面自报值）；
- 不凭空补本机没有的身份信息（第 175 轮删掉的空 `chrome.runtime` 不恢复）；
- 不覆盖页面读到的**真实值**（所有回填仍只在兜底值/空值时触发）；
- connect 模式（接管用户浏览器）**零注入契约不变**；
- `LAEW_WEB_FINGERPRINT=off` / `LAEW_WEB_STEALTH` 的既有语义不变；
- 幂等标记仍是同一个不可枚举 window 键，位掩码化**不新增全局键**。

## 九、遗留与下一步

1. **真机复核**：本轮全部改动经 Node 真实引擎验证，但窗口/屏幕几何、`hasFocus()`
   在真机 headed 下的实际读数仍需真机冒烟（`tests/web_use_smoke.rs` 的
   `#[ignore]` 用例）确认 `focus_visibility_mismatch` 不误报。
2. **注入层 ns 全局键**：只能观测不能消除（需 window 变 Proxy）。
   若日后要进一步收敛，唯一方向是减少 ns 全局的数量而不是改命名。
3. **`automation_globals` 前缀表**是启发式白名单，会随第三方框架演进而老化；
   定位是「有则加分、无比扣分」，不追求完备。
