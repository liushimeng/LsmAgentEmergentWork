# Anthropic 协议系统提示词三段式重构

## 背景

参考 Claude Code CLI (`anthropic-messages` 协议) 的抓包可见,所有 Agent 请求体 `system`
字段采用**三段式**结构:

```json
"system": [
  {"type":"text","text":"x-anthropic-billing-header: cc_version=2.1.278.acd; cc_entrypoint=cli; cc_is_subagent=true;"},
  {"type":"text","text":"You are a Claude agent, built on Anthropic's Claude Agent SDK.","cache_control":{"type":"ephemeral"}},
  {"type":"text","text":"<完整指令集 / 工具边界 / 输出规范>","cache_control":{"type":"ephemeral"}}
]
```

三段分工:

1. **计费元数据头(billing header)** —— 单行 `x-anthropic-billing-header: …`,携带 SDK
   版本/调用入口/子代理标记等链路信息,供 Anthropic 内部计费与调用追踪,**不参与模型行为**。
2. **基础身份声明(identity)** —— 一句话身份 + SDK 行名,搭配 `cache_control: ephemeral`,
   **实现首轮起即缓存**,后续复用零成本。
3. **核心行为规则(core rules)** —— 完整指令集(工具边界/任务执行准则/输出规范/权限约束),
   同样 `cache_control: ephemeral`,**整段复用零前缀浪费**。

## 现状(laew 第 121 轮前)

`src/llm/anthropic.rs::convert_system_blocks` 把 `system: String` 整体切为**单条** text 块:

```rust
vec![json!({ "type": "text", "text": system })]
```

该块由 `apply_cache_policy` 在末尾追加 `cache_control`,但**整段串成一个块**,
语义无分层。计费元数据头、身份声明、核心规则三者混在一起,既无法精准控制缓存粒度,
也无法把 SDK 链路信息单独暴露给上游计费。

## 目标

按 Claude Code 范式重构 laew 全部 8 角色(Yolo / Plan / Main-Work / SubAgent-Work /
Quality-Check / SessionContext / Debug / Compact;WorkFlow 同第 10 角色)的 Anthropic
system 字段为三段式:

- **第 1 段 计费头**(无 cache_control):`x-anthropic-billing-header: cc_version=…; cc_entrypoint=cli; cc_is_subagent=…`
  - `cc_version` = `CARGO_PKG_VERSION + "-" + LAEW_GIT_HASH`(`build.rs` 已注入 `LAEW_GIT_HASH`)
  - `cc_is_subagent` = `true`(Yolo / Plan / Main-Work / SubAgent-Work / Quality-Check /
    SessionContext / Compact / WorkFlow 全部是子 Agent);`false` 留给将来顶层 Agent 模式
  - 整段不携带 `cache_control`(Anthropic 计费头不参与缓存,文档 §4.3 行为)
- **第 2 段 身份声明**(缓存粒度:每次会话固定展开)~ base 段,Yolo / Plan / ... 各自一行
  `"你是 LsmAgentEmergentWork-{Name},  …"`;携带 `cache_control: ephemeral`
- **第 3 段 核心规则**(缓存粒度:每次会话固定展开)~ 工具说明 + 协议尾 + 完整指令集,
  携带 `cache_control: ephemeral`

OpenAI 协议**不受影响**(保持单条 `system` 字符串,`openai.rs::convert_messages` 不变)——
三段式仅 Anthropic 协议 wire。

## 关键设计

### A. 三段分桶:SYSTEM_BILLING / IDENTITY / RULES 三个静态常量

`src/agent/system_prompt/mod.rs` 暴露新 API:`SystemPrompt::prompt_segments(protocol)` →
`Option<PromptSegments>`。当 protocol ≠ Anthropic 时返回 `None`,继续走原
`render(protocol) -> String` 单字符串路径。

`PromptSegments` 结构(仅 Anthropic 路径返回):

```rust
pub struct PromptSegments {
    pub billing: String,   // 第 1 段,无 cache
    pub identity: String,  // 第 2 段,带 cache
    pub rules: String,     // 第 3 段,带 cache
}
```

### B. 计费头拼接(每 Agent 一份)

billing 头静态常量按 8 角色各生成一份(差异只在 `cc_is_subagent` 字段),
模板(参考 Claude Code 抓包):

```text
x-anthropic-billing-header: cc_version={VER}; cc_entrypoint=cli; cc_is_subagent=true;
```

- `VER` = `{CARGO_PKG_VERSION}-{LAEW_GIT_HASH}`,如 `0.1.0-9dd28de`,
  两个 `env!()` 已在 `build.rs` 注入,直接 `concat!()` 拼接;
- 字段顺序对齐 Claude Code 抓包(`cc_version` → `cc_entrypoint` → `cc_is_subagent`);
- 计费头不含模型可感知的指令文本,纯机器字段;Anthropic 内部按规则解析**,对模型行为零影响**。

### C. identity 段

身份声明从原 `YOLO_BASE_PROMPT` 第一句「你是 LsmAgentEmergentWork-Yolo,用户对话的
第一层入口 Agent。」里抽出,做小幅精简(去掉「核心职责」后的内容,只保身份 + 一句话职责)。
8 角色统一句式:

```text
你是 LsmAgentEmergentWork-{Name},{一句话职责}。
```

### D. rules 段

包含**其余全部内容**:核心职责 / 工具说明 / 协议尾 / MCP_Window_Use / MCP_Web_Use
章节。3 段拼接后,**内容完全等价于原单字符串 prompt**(行为零变更)。

### E. Anthropic wire 层

`src/llm/anthropic.rs::convert_system_blocks` 改为接收 `Option<PromptSegments>`:

```rust
fn convert_system_blocks(seg: &Option<PromptSegments>) -> Vec<Value> {
    let Some(s) = seg else { return Vec::new() };
    let mut out = vec![
        json!({"type":"text","text": s.billing}),  // 不打 cache_control
    ];
    if !s.identity.is_empty() {
        out.push(json!({"type":"text","text": s.identity}));
    }
    if !s.rules.is_empty() {
        out.push(json!({"type":"text","text": s.rules}));
    }
    out
}
```

`apply_cache_policy` 仅给 system 数组末尾的 block 标 `cache_control`(现有逻辑),
而我们**让 rules 段始终是数组末尾**,自然只给 rules 加 cache。**但 identity 段也需
cache**——所以改为给 rules 末尾打 + identity 末尾也打;改造方案:

**最简实现**:在 `convert_system_blocks` 末尾**主动**给 identity / rules 两块都标
`cache_control`,然后让 `apply_cache_policy` 跳过 system 的 cache 写入
(因为已有显式 cache_control)。或者更简洁:让 `apply_system_cache` 单独负责——
但本期选择最小改动:**取消 `apply_cache_policy` 对 System 的自动打标,改为
`convert_system_blocks` 自身给 identity + rules 末尾各打一份 `cache_control`**。

### F. OpenAI 协议不动

`src/llm/openai.rs::convert_messages` 仍按 `system: &str` 单字符串消费。
`LlmClient::complete(system: &str, ...)` 签名**保持不变**——`system` 参数是**拼接后
的字符串**(identity + rules,不含 billing)。billing 头只在 Anthropic 路径注入到
system 数组的第 1 段。**OpenAI 网关天然不解析 `x-anthropic-billing-header`,即使
注入也是字符串噪音,反而会让模型误读,所以仅 Anthropic 路径生效**。

## 风险

- **OpenAI 兼容性**:三段拆分只在 Anthropic wire 拼装,`system: &str` 仍是 identity + rules
  拼接字符串。OpenAI 路径行为零变化(`grep -n "convert_system_blocks" src/llm/openai.rs`
  应无结果)。
- **cache_control 数量**:Anthropic API 4 断点 cap,本期 system 段占 2 个(identity + rules),
  tools 1 个,user message 1 个,共 4 个——刚好命中 cap。`apply_cache_policy` 已实现
  `try_consume` + dropped 计数,本改造后 system 段不再被其打 cache,**改由
  `convert_system_blocks` 直接静态打**。
- **空 system 路径**:当某个 Agent 无 prompt(如某些内部调用),三段均为空 → emit 空
  数组 → `AnthropicRequest.system: None`(现有 skip_serializing_if 逻辑保留)。
- **跨角色一致性**:8 角色 1:1 走同一 `convert_system_blocks`,差异仅在
  `PromptSegments` 的内容(identity 一行 / rules 多行)。`Debug` / `Compact` 等无 tools_hint
  的 Agent,`render()` 仅返回 identity 段,identity + rules 同一字符串也能正确显示。

## 已知 trade-off

- 把 `convert_system_blocks` 拆成 3 段后,**Identity 段只有一行,缓存粒度很细**——
  Anthropic cache 按前缀匹配,这一行的复用率为 100%(后续轮次 system 数组前两段不变,
  billing 头不变,identity 也不变;只有 rules 可能因 runtime hints 注入而变化)。
- billing 头是 Anthropic 私有约定,**非 Anthropic 端点(自建网关 / DouBao / LongCat)**
  不会解析;但作为无害字符串注入也无副作用,模型看到「`x-anthropic-billing-header: …`」
  是机器字段不会当指令。
