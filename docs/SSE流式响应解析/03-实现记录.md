## 2. 关键决策点(对照 02-技术设计)

### 2.1 关于"是否引入 `futures-util`"

**最终决策**:不引入。改用 `reqwest::Response::chunk()` 同步循环读字节块喂给 `SseStream::push(&[u8])`。

**原因**:

- CLAUDE.md "不引入新 crate"。
- `chunk()` 内部仍是异步 + tokio,不损失并发能力。
- 我们对每个字节块的处理是 O(N) 字符串扫描 + 一次性 emit 事件,放在 `async` 内同步完成即可。

### 2.2 关于 `ParseSink::feed` 的"最近一个 in_flight"

为简化实现,把 `ParseSink` 内部维护的 `in_flight` 设计为 `VecDeque<(idx, InFlightToolCall)>` 而不是 `HashMap`:

- Anthropic 严格按 `index` 单调递增;`feed(ToolCallStart)` push 到队尾。
- OpenAI 的 `chunk.tool_calls[].index` 在一次回合里也保持稳定;OpenAiParser 自己负责把 `index → in_flight` 拼好后,**在流结束时**由 `OpenAiParser::finish_into_sink` 一次性 emit `ToolCallStart / ToolCallJsonDelta / ToolCallEnd` 给 sink,让 sink 看到的也是顺序的。

这样 sink 的 `feed` 只需要看"队尾"即可,逻辑极简。

### 2.3 关于 OpenAI 的 usage 时机

两种可能:

- 客户端不发 `stream_options.include_usage=true`:尾部 chunk 的 `usage` 为 `null`,usage 全为 0。
- 客户端发:尾部 chunk 有 `usage` 字段,`choices: []`。

我们在 `OpenAiRequest` **始终**带 `stream_options: {include_usage: true}`,保证能拿到用量。

### 2.4 关于 Anthropic `output_tokens` 覆盖

`message_delta.usage.output_tokens` 是**累计值**,可能多次出现(尤其是 thinking 模式)。`ParseSink` 直接覆盖,不维护 delta。

### 2.5 关于 `run_session` 签名变化

```rust
pub async fn run_session(&self, session: &mut Session) -> Result<(String, Usage)>
pub async fn run_once(&self, user_input: &str) -> Result<(String, Usage)>
```

3 处调用全部同步修改:`agent/mod.rs` 内部 + `tui/mod.rs::handle_user_input` + `main.rs::run_one_shot`。

## 3. 出错时的体验

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| 上游 `event: error` | (N/A,旧路径不读 SSE) | 立即返回 `AgentError::Llm("upstream SSE error: ...")` |
| 网络中断 | `resp.text()` 中断,无法定位 | `SSE 传输中断: <原因>` |
| `data:` 非 JSON | 整段失败 | 单事件 skip + `tracing::warn!`,流继续 |
| 工具 JSON 解析失败 | 旧:`{ "_raw": ... }` 兜底 | 同样保留兜底 |
| 缓冲超过 64 KiB | (N/A) | `SSE 事件超过 64 KiB 缓冲上限` |

## 5. 复盘

**做得好的**:

- 解析引擎协议无关,两协议共享 `ParseSink`,新增第三种协议(Gemini / Cohere)只需写一个 Parser。
- `Completion` 仅追加字段,不影响协议无关的 Agent 循环。

**可以更好**:

- 没做流式回显(US-1 / US-2);留给后续 PR。
- `NoopLlm::complete` 没显式设置 `usage`,靠 `Completion::default()` 兜底 — 后续可以把 `Default` 改进为 `#[derive(Default)]` 之外的更友好构造。
- 没做超时(每个 `chunk()` 默认 reqwest 的 timeout=无);若上游 5 分钟不发字节会卡住。可以加 `tokio::time::timeout` 包一层,留给下一期。
