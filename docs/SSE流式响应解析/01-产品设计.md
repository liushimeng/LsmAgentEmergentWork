# SSE 流式响应解析 — 产品设计

> 适用对象:LLM Agent CLI `laew`
> 关联协议:Anthropic Messages (含 stream) / OpenAI Chat Completions (含 stream)
> 配套文档:`02-技术设计.md` / `03-实现记录.md`

## 1. 背景与目标

### 1.1 现状

当前 `laew` 在 `src/llm/{anthropic,openai}.rs` 中以**整段请求 + 整段解析**的方式与上游 LLM 通信:

- `complete()` 调一次 `reqwest::send().await`,然后 `resp.text().await` 读完全部响应再一次性 `serde_json::from_str`。
- 没有 `Accept: text/event-stream`,没有 `stream: true`,HTTP body 一次性消费到底。
- 输出体验:模型在"思考"期间用户看不到任何字符,要等十几秒到几十秒才一次性看到一整段答复。

### 1.2 痛点

1. **首字延迟高(TTFT)**:长上下文(几十万 token)、大输出(数千 token)场景下,等待整段响应完成才有任何反馈,体感差。
2. **无法流式打印**:Agent 拿到完整 Completion 才能写库/打印,无法在生成过程中同步落盘/同步给用户。
3. **无法中途取消**:用户无法在中途 `Ctrl-C` 取消一次正在生成的回合。
4. **Token 用量黑盒**:虽然上游响应里有 `usage.input_tokens / output_tokens`,但目前只解析了 `content`,usage 字段被丢弃,Agent 与 TUI 都不知道一次调用花了多少 token。
5. **错误恢复弱**:HTTP 连接中途断(网络抖动 / 上游超时)只能整段失败;解析失败时无法定位是哪个事件出错。

### 1.3 目标

在不改变现有 `LlmClient::complete()` 公开签名语义、不破坏 `agent/` `tui/` `tool/` 任何上层的前提下,完成以下 4 项:

1. **两协议统一走 SSE**:`AnthropicClient` / `OpenAiClient` 在请求中加 `stream: true` 并设置 `Accept: text/event-stream`,按事件流消费。
2. **增量解析引擎**:新增 `src/llm/sse.rs`,提供通用的 `SseStream`(字节流 → 事件流)和协议无关的 `ParseSink`(事件流 → Completion 增量)。两协议各自的 wire 解析器把事件喂给 `ParseSink`,由 `ParseSink` 聚合成 `Completion`。
3. **Completion 携带 usage**:`Completion` 新增 `usage: Usage { input_tokens, output_tokens, cache_read_input_tokens?, cache_creation_input_tokens? }`,SSE 解析过程中通过 `message_delta.usage` (Anthropic) / 尾部 `chunk.usage` (OpenAI) 填入。
4. **TUI 同步展示**:TUI 主屏在流式过程中逐 token 刷新屏幕(不强制要求 — 本期以**最终用量统计**展示为主,流式回显留给后续 PR;落地点放在 TUI 屏底部"本次调用用量: in=… out=…"。

> 不在本期范围:多模态流式(图片块 / 音频块增量);Anthropic Extended Thinking 的 `thinking_delta` / `signature_delta` 内容回显(本期仅作占位,不在主屏打印);OpenAI `n>1` 多 choice。预留扩展口但不在本期实现。

## 2. 用户故事

| # | 故事 | 验收标准 |
|---|------|----------|
| US-1 | 用户在 TUI 中输入长 prompt,看到模型**逐字**打字回显 | 主屏 `[assistant]` 行实时刷新(本期可仅在 `--print` 调试模式生效) |
| US-2 | 模型首次返回 token 后,屏幕立即可见字符 | TTFT ≤ 网络 RTT + 模型首个 chunk 延迟(本地度量) |
| US-3 | 用户在生成中按 `Ctrl-C` 能立刻取消 | 中断后回主屏,不阻塞(本期不强制;仅在已实现的能力内最优) |
| US-4 | 用户每次回合结束后看到 token 用量 | 主屏底部显示 `本次用量: input=… output=…` |
| US-5 | 上游 SSE 流中混入空行 / 注释 / 多行 `data:` 时仍能正确解析 | 单元测试覆盖 `data:` 拼接、心跳、retry 注释 |
| US-6 | 协议差异(Anthropic / OpenAI)对上层透明 | `LlmClient::complete()` 签名不变,Agent 与 TUI 不改 |
| US-7 | 上游 HTTP 错误(401 / 429 / 500)依然按现有方式报错 | HTTP 状态非 2xx 时从 body 提取错误信息返回 `AgentError::Llm` |

## 3. 非功能性需求

- **零新增依赖**:基于现有 `reqwest` + `tokio`(已经有 `stream` 能力,`reqwest::Response::bytes_stream()` 可直接拿到字节流)。
- **零增量内存**:SSE 解析器必须支持**有界内部缓冲**,不因上游畸形包把内存吃光(默认缓冲上限 64 KiB,超过即报错)。
- **向后兼容**:现有 61 个单元测试 + `testReport/run_e2e.sh` 全部通过;`Completion` 新增字段都设默认值,不破坏既有序列化路径。
- **可观测**:`tracing` 记录 SSE 事件数、首 chunk 延迟、最终 usage;e2e 中可观测。

## 4. 行为设计

### 4.1 请求侧

| 项 | Anthropic | OpenAI |
|----|-----------|--------|
| 端点 | `POST {end_point}/v1/messages` | `POST {end_point}/chat/completions` |
| Body 新增 | `"stream": true` | `"stream": true` |
| Header 新增 | `Accept: text/event-stream` | `Accept: text/event-stream` |
| Header 备注 | Anthropic 还可发 `anthropic-beta: messages-2023-12-15` 之类的版本头(本期沿用现有头) | — |

> 兼容性:多数中转网关(例如兼容 OpenAI 协议的 LongCat)在 `stream: true` 时也能返回 SSE,且不响应 `Accept` 头 — 保留 `Accept` 仅作礼貌标识,解析器不强依赖。

### 4.2 响应侧(SSE wire)

#### Anthropic Messages stream

事件按行传输,每条事件格式 `event: <type>\ndata: <json>\n\n`。关键事件:

| event type | 关键字段 | 用途 |
|------------|----------|------|
| `message_start` | `message: { id, model, usage:{input_tokens,output_tokens,cache_…} }` | 记录输入侧 tokens |
| `content_block_start` | `index, content_block:{ type: "text"\|"tool_use"\|"thinking", id?, name? }` | 标志一个内容块开始 |
| `content_block_delta` | `index, delta:{ type: "text_delta"\|"input_json_delta"\|"thinking_delta", text?, partial_json? }` | **核心**:文本 / JSON 增量拼接 |
| `content_block_stop` | `index` | 标志一个内容块结束 |
| `message_delta` | `delta:{ stop_reason, stop_sequence }, usage:{ output_tokens }` | 终止原因 + 输出 token 增量更新 |
| `message_stop` | — | 整体结束 |
| `ping` | — | 心跳,忽略 |
| `error` | `error:{type,message}` | 中途错误 |

`output_tokens` 是**累计值**,每个 `message_delta` 都给一个递增数字;解析时直接覆盖即可(Anthropic 文档保证单调递增)。

#### OpenAI Chat Completions stream

每行 `data: <json>` 即一个 chunk,**没有 `event:` 字段**;`[DONE]` 标记结束。

| chunk 字段 | 用途 |
|-----------|------|
| `choices[].delta.role` | 通常仅首个 chunk 出现 `assistant` |
| `choices[].delta.content` | 文本增量,**字符串片段**,需要拼接 |
| `choices[].delta.tool_calls[]` | 工具调用增量:`id` 仅首片出现,`function.name` 仅首片,`function.arguments` 是**部分 JSON 字符串**需要拼接 |
| `choices[].finish_reason` | `stop` / `tool_calls` / `length`,在最后一条出现 |
| `usage`(可选,需 `stream_options: {include_usage: true}`) | 出现在最后一条 chunk(且 `choices` 为空) |

> OpenAI 也可通过 `stream_options.include_usage=true` 让 `usage` 在最后一条单独出现。本期实现:无论是否带该选项,只要遇到 `usage` 字段就采集;否则 usage 全 0。

#### 数据流总览

```
HTTP body bytes
    │  reqwest::bytes_stream()
    ▼
SseStream (按 \n 切行,按 \n\n 切事件)
    │ 逐个 SseEvent { event: Option<String>, data: String }
    ▼
协议 parser (anthropic_parser / openai_parser)
    │ 把 SseEvent 解成统一的 DeltaEvent
    ▼
ParseSink (内部维护 Completion 状态: text / tool_calls / usage / stop_reason)
    │ 当遇到终止事件 → 输出最终 Completion
    ▼
LlmClient::complete() → Completion
```

### 4.3 错误处理

| 情况 | 行为 |
|------|------|
| HTTP 非 2xx | 现有逻辑:`resp.text()` 拿错误体,包装为 `AgentError::Llm("HTTP {status}: {body}")` |
| 上游发送 `event: error` (Anthropic) | 立即终止流,返回 `AgentError::Llm("upstream error: …")` |
| 中途网络断开 | `bytes_stream` 返回 Err,包装为 `AgentError::Llm("SSE 传输中断: …")` |
| `data:` 字段不是合法 JSON | 跳过该事件,记录 `tracing::warn!`;不立即失败(容错) |
| 内部缓冲超过 64 KiB | 返回 `AgentError::Llm("SSE 事件超过 64 KiB 缓冲上限")` |
| `tool_calls.arguments` 拼接后非法 JSON | 保留现状(OpenAI parser 已实现):`{ "_raw": "<原文>" }` 兜底 |

### 4.4 Token 用量展示(TUI)

`LlmClient::complete()` 仍只返回 `Completion`(新增 `usage` 字段)。`tui/mod.rs` 在主屏打印 assistant 文本后,如有 `usage` 数据,在其下方打印:

```
  本次用量: input=… output=…  (cached=…)
```

格式与 `theme.rs` 现有颜色风格保持一致。

### 4.5 协议切换的可观察变化

- `laew -p "..."` 单轮模式:输出尾部追加一行 `本次用量: …`,其它不变。
- `laew` TUI 模式:同上,且不影响斜杠命令流程。
- `e2e` 脚本:20 项 e2e 全部通过,验证 `usage` 在 `--print` 调试模式下能输出。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 某些中转网关在 `stream: true` 时仍返回非 SSE(整段 JSON) | 解析失败 | 解析前先尝试按整段 JSON parse;失败再按 SSE parse |
| OpenAI chunk 顺序非严格(部分实现里 `arguments` 可能跨 chunk 跨 id) | 工具调用 id/name/arguments 错位 | 以 `(index, id)` 为 key 维护 HashMap,允许乱序;兜底按 `index` 排序拼接 |
| 上游 chunk 大小变化大 | 内存波动 | 字节流 → 行缓冲的内部限制 64 KiB |
| `tracing` 日志量暴涨(每个 chunk 都打) | 日志爆炸 | chunk 级日志在 `trace!` 级别;info 仅打事件计数 + 首 chunk 延迟 |
