## 1. 背景与问题

### 1.1 第 90 轮遗留的不一致

第 90 轮设计了「鼠标键盘同时操作」的修饰键能力(`modifiers` 字段,按住 ctrl/shift/alt/win
同时执行鼠标操作),并在 `ClickPoint` / `DoubleClickPoint` / `RightClickPoint` /
`DragPoint` 四个变体上完整实现。但 `MiddleClickPoint` 中键点击作为后来补漏的变体,
**三平台实现均硬编码「无修饰键」**,形成不一致:

| 位置 | 代码 | 问题 |
|------|------|------|
| `control_action.rs` | `MiddleClickPoint { x: i64, y: i64 }` | 无 `modifiers` 字段 |
| `windows.rs:731` | `click_point_ex(..., Middle, 1, &[])` | 硬编码 `&[]` |
| `macos_legacy.rs:1607` | `cg_click_at_ex(..., Middle, 1, 0)` | 硬编码 `0` |
| `fallback.rs:161-170` | `xdotool click 2` 前无 keydown | 无修饰键包裹 |
| `input_batch.rs:251` | `ControlAction::MiddleClickPoint { x, y }` | 丢弃 step 的 modifiers |

**中键 + 修饰键**在桌面软件中有真实用例:
- **浏览器**: ctrl+中键点击链接 = 新标签打开并聚焦;shift+中键 = 新窗口打开
- **CAD/3D 视图**: shift+中键 = 平移;ctrl+中键 = 旋转(Blender / Fusion 360)
- **文件管理器**: ctrl+中键 = 复制到新位置

缺失修饰键支持会让 Agent 在中键相关场景被迫降级到多次调用(先 send_keys ctrl down →
click → ctrl up),引入焦点竞态,与第 90 轮「同时操作」的设计意图矛盾。

### 1.2 `macos_legacy.rs` 超 1800 行红线

`src/agent/window/macos_legacy.rs` 已 2030 行,违反「单源码文件 ≤1800 行」强制规范。
第 90 轮已备案「CGEvent 输入底座(`cg_*` 家族)应拆到独立子模块」,本轮落地。

## 2. 设计总览

### 2.1 `MiddleClickPoint` 增加 `modifiers` 字段

`ControlAction` 枚举变更(`src/agent/window/control_action.rs`):

```rust
// 修改前
MiddleClickPoint { x: i64, y: i64 },

// 修改后(与 ClickPoint 同源)
MiddleClickPoint {
    x: i64,
    y: i64,
    modifiers: Option<String>,
},
```

`parse_ext` 在 `middle_click_point` 分支透传 `modifiers.clone()`。

### 2.2 三平台驱动补齐

| 平台 | 修改 |
|------|------|
| Windows | `windows.rs:730-733` 解析 `modifier_vks(modifiers.as_deref())?` 传入 `click_point_ex` |
| macOS | `macos_legacy.rs:1606-1611` 解析 `cg_mod_flags(modifiers.as_deref())?` 传入 `cg_click_at_ex` |
| Linux | `fallback.rs:161-170` 用 `xdotool_mod_names` + `with_mods` 包裹中键点击 |

### 2.3 `input_batch` 中键步骤透传 modifiers

`input_batch.rs:251` 丢弃 `step_str(step, "modifiers")` → 读取并传入
`ControlAction::MiddleClickPoint { x, y, modifiers }`。

### 2.4 `macos_legacy.rs` 拆分(`macos/` 目录化)

按「单文件 ≤1800 行拆分规范」目录化(`macos_legacy.rs` → `macos_legacy/mod.rs` + 子模块):

```
src/agent/window/macos_legacy/
  mod.rs            再导出 + WindowDriver 实现入口(约 600 行)
  cg_event.rs       CGEvent 输入底座(`cg_*` 家族):move/click/drag/scroll/key(约 350 行)
  ax_ui.rs          AX 控件树遍历/属性/动作(约 500 行)
  act_dispatch.rs   act() match 分发(约 400 行)
  tests.rs          原 tests 搬入
```

- `mod.rs` 保留结构体定义 + `pub use` 再导出,外部路径 `crate::agent::window::macos_legacy::*` 零改动;
- 原私有项搬入子模块标 `pub(super)`;
- 代码逐行机械搬移零改写;
- 测试搬 `tests.rs` 并对账。

## 6. 风险与取舍

- **中键修饰键的应用兼容性**:多数应用中键+修饰键无自定义语义,此时修饰键被忽略(等价
  纯中键);不构成行为回退,因为此前根本调不了中键+修饰键组合。
- **macOS `ax_ui.rs` 拆分边界**:AX 错误处理辅助(`ax_error_text` / `ax_permission_hint`)
  被 `act_dispatch.rs` 与 `mod.rs` 共同依赖 → 放 `mod.rs` 标 `pub(super)`,两子模块
  `use super::*` 取用。
- **不影响第 90 轮已通过的 1197 个单测**:本轮为纯增量(中键 modifiers 字段默认
  `None`,旧调用点不传 modifiers 时行为不变)。
