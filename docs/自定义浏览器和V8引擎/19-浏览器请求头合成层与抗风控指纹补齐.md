# 19 - 浏览器请求头合成层(抗风控指纹补齐)

**轮次**:2026-10-22 第 174 轮(百度地图公共交通路线规划任务实测驱动)
**方案**:`tmpPlan/baidu_map_transit_route_20261022_115240.md`

## 一、问题与定位

`laew --debug -f prompt.md` 跑百度地图路线规划任务,Agent 反复重试 3 轮
(1796s / 120k input tokens)找不到「路线规划」入口,最终因
`WorkFlow 拓扑错误: wf=wf-2 依赖未知 wf=wf-1` 整条任务失败,产物空白。

逐层下探后的**根因链**:

1. 页面 UI 全是「无文本图标按钮」(`div.route-button[data-title=路线]` + CSS 背景图),
   `inspect(text)` 只回 4 个字;
2. 点击路线按钮后页面零变化 —— 站点自身的 XHR/JSONP 被**百度风控拦截**;
3. **决定性对照实验**:用内核 `HttpClient` 打同一组接口,裸请求
   `zt.baidu.com/activity/api/config/get?...&callback=jsonp1` 返回
   **403 Forbidden**(nginx);带上 `Referer: https://map.baidu.com/` 后返回
   **200** `jsonp1({"errno":0,...})`;
4. 站点 JS 线程里的 `fetch/XHR` 走 `script/runtime.rs::blocking_fetch`,
   **连 `User-Agent` 都不带**(`build_blocking_client` 未设 UA),更无
   `Referer`/`Origin`/`Accept`/`Sec-Fetch-*`;
5. 站点拿到 403/HTML 后解包失败,抛 `TypeError: cannot convert 'null' or
   'undefined' to object`(console 里 `xhr rs: ...`)→ 路线面板 widget 永不挂载。

**结论**:内核 HTTP 客户端缺一整套「浏览器指纹头」,不是地图渲染(白屏)问题。

## 二、方案:请求头合成层(`src/agent/browser/reqctx.rs`)

按 Chrome 语义,按**请求目的地**(`Dest::{Document,Script,Style,Image,Xhr,Font,Other}`)
合成:`User-Agent` / `Referer` / `Origin` / `Accept` / `Accept-Language` /
`Sec-Fetch-Site` / `Sec-Fetch-Mode` / `Sec-Fetch-Dest`。

合成规则要点:

| 头 | 规则 |
|----|------|
| `user-agent` | 页面 UA(默认 UA 也发,不再"等于默认就省略") |
| `referer` | 页面 URL;**跨源只发 origin**(`strict-origin-when-cross-origin`) |
| `origin` | 仅 XHR/fetch:跨源,或方法非 GET/HEAD |
| `sec-fetch-site` | 同源 `same-origin` / 同站 `same-site` / 跨站 `cross-site` / 导航 `none` |
| `sec-fetch-mode` | document→`navigate`;script/style/image→`no-cors`;xhr→同源 `same-origin`、跨源 `cors` |
| `sec-fetch-dest` | document→`document`;script→`script`;style→`style`;image→`image`;xhr→`empty` |
| `accept` | 按目的地(document 用完整 HTML Accept 串,style 用 `text/css,*/*;q=0.1`) |
| `accept-language` | `zh-CN,zh;q=0.9,en-US;q=0.8,en;q=0.7`(`LAEW_WEB_ACCEPT_LANGUAGE` 可覆盖) |

**合成头是兜底**:调用方显式给出的同名头优先,不被覆盖(`merge_headers`)。

## 三、接入点(5 条子资源通道全部覆盖)

| 通道 | 位置 | Dest |
|------|------|------|
| 主文档导航 | `browser/mod.rs::fetch_main` / `navigate_locked` | Document(**不带 Referer**) |
| 外链脚本 | `script/mod.rs::run_pipeline` | Script |
| 样式表 | `resources.rs::load_stylesheets` | Style |
| 图片 | `images.rs::load_images` | Image |
| 页面 XHR/fetch | `script/runtime.rs::blocking_fetch` | Xhr(**补上了此前完全缺失的 UA**) |

`net::FetchRequest` 增加 `context: Option<RequestContext>`;`HttpClient::fetch`
在用户显式头之后追加合成头。页面 XHR 通道(`blocking_client`)不走
`HttpClient`,单独合成同一套头(`REQ_ENV` 增加 `user_agent` 字段)。

## 四、附带通用修复(同轮落地)

### 4.0 CSS `background` 简写丢 `url(...)`(同轮最高价值)

`style/values.rs` 的 `"background"` 分支此前**只取颜色**、`url(...)` 一律丢弃:

```rust
"background" => {
    if (value == "none" | "transparent") { st.background = None; }
    else if let Some(Some((rgb, alpha))) = parse_color(value) { st.background = Some(...); }
}
```

而 Web UI 的图标/按钮/精灵图普遍写简写
`background: url(sprite.png) no-repeat -15px -136px` —— 整页 UI 因此渲染成空白
(实测百度地图:搜索框、路线按钮全是背景图精灵,截图一片白)。

修复:
- 简写按记号拆分(`split_bg_tokens`,括号内不拆,`url(...)` 保持完整),分别取
  `url(...)` / 颜色 / 位置 / 尺寸;
- 规范语义:简写会**重置** `background-image` / `position` / `size`(无 url 即清空);
- `background-position` / `background-size` 长写与简写同源解析
  (`parse_background_position` / `parse_background_size`),方位关键字
  (`left|center|right|top|bottom|middle`)归一为百分比;
- 布局层 `background_paint` 按 `background-size` 决定 fit(`auto` → 固有尺寸,
  **精灵图取块语义**;`cover`/`contain` 沿用),并按 CSS 公式
  `offset = (盒尺寸 - 图尺寸) * 百分比` 解析像素偏移;
- 渲染层 `draw_image` 增加 `off_x/off_y`,裁剪区仍是元素盒。

实测:修复后百度地图搜索按钮的蓝色背景图正确绘制(修复前为空白框)。

### 4.1 window 代理 `set` 陷阱对只读访问器抛 TypeError

站点反爬脚本(百度 heicha/acs)会做
`Object.defineProperty(window,'eval',{get:...,configurable:false})` 用来侦测页面
是否调用 `eval`。我们的 `window` 是 Proxy,而 Proxy [[Set]] 的**后置校验**在目标
是「非可配置的只读访问器」时抛 `TypeError: Proxy trap set unexpected accessor descriptor`
—— 一次 `window.X = ...` 赋值就把整段站点初始化打断。浏览器语义是**静默失败**
(sloppy)/ 抛 TypeError(strict),不是抛 Proxy 错。修复:`set` 陷阱检测到该形态
时返回 `false`,退化为浏览器的「静默失败」语义。



1. **缺失标准全局**(`script/env_js.rs` / `script/prelude.rs`):
   `NodeFilter`(站点 polyfill 的 `createTreeWalker` 普遍引用其常量)、
   `NodeIterator`、`document.createElementNS` / `createSVGElement`
   (SVG 站点至少不崩)。
2. **事件委托匹配**(`script/prelude.rs`):元素包装器补 `matches` /
   `matchesSelector` / `closest`(含动态节点宽松匹配 `__lsmDynMatch`)——
   jQuery `$(document).on('click', sel, fn)` 委托 handler 依赖它们,
   缺失则「点击无反应」。
3. **可访问名**(`browser/document.rs::accessible_name`):
   `inspect(elements)` 每项新增 `label` 字段,推导序
   `aria-label > data-title > title > alt > placeholder > value > label[for]`。
   无文本图标按钮(百度地图路线按钮 `data-title=路线`)由此可被 Agent 识别。
4. **WorkFlow 未知依赖降级**(`main_work/topo.rs::topo_layers_lenient`):
   档位级重试时 Main-Work 局部重拆,后发单元引用已完成的前置单元产生
   悬空边;严格 topo 报「依赖未知」整份计划作废、整条任务终止(实测烧 3 轮
   重试 120k tokens)。宽容模式**丢弃未知依赖边并警告**,循环依赖仍是硬错误。
   `plan_validate` 与执行层(`orchestrator/workflows.rs`)统一接入。

## 4.7 Boa VM panic:`new Function` 函数体含 `class` 声明

实测任务中途 `lsm-page-js` 线程崩溃(CrashReport 记录):

```
消息: must be declarative environment
位置: boa_engine-0.20.0/src/vm/opcode/define/mod.rs:108
路径: EnvironmentStack::put_lexical_value ← PutLexicalValue ← Context::run
```

最小复现:`new Function("class C {} return 1;")()` 必 panic。边界实测:

| 形态 | 结果 |
|------|------|
| `new Function` 函数体含 `class`(**被执行**) | **panic** |
| `new Function` 函数体含 `let` / `const` | 正常 |
| `new Function` 里定义含 class 的函数但**不调用** | 正常(编译不炸,执行才炸) |
| 间接 eval `(function(){ class C{} return 1; })()` | **正常** |
| 间接 eval `class E {} ; 1` | 正常 |

修复两处:

1. `__lsmEvalUser` 的 `return` 分支从 `new Function(src)()` 改为
   **间接 eval 包 IIFE**(`(0,eval)("(function(){\n"+src+"\n})()")`)。
2. `thread_main` 的 panic 恢复:此前**直接重建 Context**,等于把页面几百个脚本
   跑出来的全局状态(map 实例 / 模块注册表 / 事件总线)全丢掉、整页失忆。改为
   先做最小求值健康检查,能跑就保留旧 Context,真坏了才重建。
