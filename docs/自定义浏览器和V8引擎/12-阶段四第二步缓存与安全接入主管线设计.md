# 阶段四第二步：缓存与安全接入主管线

> 状态标记：✅ 已实现；🟡 部分实现/有边界；⏳ 未实现。
> 前置：阶段四基础框架（11 号文档）已交付 `cache`/`resource`/`security` 三模块与单测，
> 但它们是「库代码」——主管线（导航、样式预取、脚本管线、fetch/XHR）没有调用它们。
> 本轮把缓存与安全真正接进页面加载与脚本执行路径，并收尾 Phase 3 的区域截图。

## 一、现状分析（接入前）

| 模块 | 已实现能力 | 接入状态 |
| --- | --- | --- |
| `cache::HttpCache` | 强缓存（Cache-Control/Expires）、LRU 淘汰、128MB 上限、统计 | ⏳ 未接入：`load_locked`/预取路径均直接走网络 |
| `cache::policy` | Cache-Control 解析（no-store/no-cache/max-age…） | ✅ 被 HttpCache 内部使用 |
| `cache::validation` | ETag/Last-Modified 协商缓存原语 | ⏳ 未接入请求侧（本轮不做，见 §六边界） |
| `security::SecurityContext` | 页面源、CORS/CSP 缓存、混合内容开关 | ⏳ 未实例化：`TabState`/`Inner` 均无该字段 |
| `security::cors` | 简单请求/预检校验、响应头解析 | ⏳ 未执行：`blocking_fetch` 不检查 CORS |
| `security::csp` | script-src/style-src/img-src/connect-src/default-src、'self'/'unsafe-inline'/host/通配符 | ⏳ 未执行：脚本管线不检查 CSP |
| `security::mixed_content` | HTTPS 页禁 HTTP 资源判定 | ⏳ 未执行 |
| `resource::ResourceLoader` | 优先级调度、并发控制、去重 | ⏳ 未接入（面向批量异步管线，与现有顺序加载路径不匹配，保留给未来预取管线，见 §六） |

已接入项（前序轮次）：Cookie SameSite（`storage.rs` CookieJar 请求构造）、整页截图（`full_page` 参数）、
CSP/CORS/混合内容的**代码全部就绪但零调用点**。

## 二、本轮目标

1. **HttpCache 接入主管线**：主文档导航与子资源（CSS/JS）加载走全内存缓存，重复访问命中强缓存跳过网络；
2. **CSP 接入脚本管线**：主文档响应头 `Content-Security-Policy` 解析后，内联脚本默认拒绝（除非
   `'unsafe-inline'`）、外链脚本 URL 受 `script-src` 约束、fetch/XHR 受 `connect-src` 约束；
3. **CORS 接入页面 fetch/XHR**：跨域响应无合法 `Access-Control-Allow-*` 头时按浏览器语义失败；
4. **clip 区域截图**（Phase 3 收尾）：`screenshot` 支持 `{x,y,width,height}` 文档坐标裁剪；
5. **可观测**：网络台账标记 `from_cache`，`inspect(network)` 输出缓存统计。

**验收**：mock 站点第二次导航命中缓存（网络零请求）；CSP `script-src 'self'` 页面内联脚本不执行；
跨域 fetch 无 CORS 头时 JS 侧收到错误；clip 截图输出裁剪后 PNG。

## 三、详细设计

### 3.1 数据结构变更

```rust
// mod.rs — Inner 增加进程级缓存
pub struct Inner {
    ...
    /// 全内存 HTTP 缓存（阶段四第二步接入）。
    pub http_cache: cache::HttpCache,
}

// mod.rs — TabState 增加每页安全上下文
pub struct TabState {
    ...
    /// 安全上下文（CORS/CSP 缓存、页面源）。
    pub security: security::SecurityContext,
}

// mod.rs — NetworkRecord 增加缓存命中标记
pub struct NetworkRecord {
    ...
    /// 是否来自全内存 HTTP 缓存（命中强缓存时 elapsed_ms=0）。
    pub from_cache: bool,
}
```

### 3.2 HttpCache 接入（`load_locked` 主文档路径）

```
load_locked(inner, ..., method=GET):
  1. cache_enabled = env LAEW_WEB_CACHE != off
  2. 若 method=GET 且 cache_enabled：
       if let Some(entry) = inner.http_cache.get(url):
           构造 FetchResponse{ final_url: url, status: entry.status,
                              headers: entry.headers, bytes: entry.bytes,
                              redirect_chain: vec![], elapsed_ms: 0 }
          台账记 from_cache=true；跳过网络请求与样式预取/脚本管线
          中的子资源网络请求（子资源同样先查缓存，见 3.3）
  3. 未命中 → 现有网络路径；响应为 2xx GET 时：
       inner.http_cache.put(CacheEntry::new(url, status, headers, bytes, now_ms))
```

**边界**：
- 只缓存 GET；表单提交（`submit_form`）不读不写缓存；
- `Cache-Control: no-store` 的响应不入缓存（`CacheEntry::new` 解析 policy 后判断 `no_store`）；
- `is_expired()` 已在 `get()` 内处理强缓存过期；协商缓存（ETag/Last-Modified）本轮不发
  `If-None-Match`/`If-Modified-Since` 请求——`validation.rs` 原语已备好，下一迭代接入请求侧；
- 缓存键为请求 URL（规范化后）；`data:`/`about:`/`file:` 本地协议不缓存。

### 3.3 子资源缓存（CSS 预取 + 外链脚本）

- `resources::load_stylesheets`：每个 `<link>` 先查 `inner.http_cache`，命中直接用其
  `(headers, bytes)` 构造 CSS 文本（`content-type` 头已在 entry 内，经 `urlutil::decode_body`
  解码）；未命中走原 fetch 路径，成功后 `put`。
- `script::run_pipeline` 外链脚本：同上，命中缓存的脚本内容进入 `ScriptSource{kind:"external"}`
  执行路径（CSP 校验照常）；未命中 fetch 后 `put`。
- 图片子资源（`images.rs`）**不接入 HttpCache**：图片已有独立的 `ImageStore`（URL → RGBA8
  全内存缓存，带尺寸/数量限额），两套缓存职责不重叠。

### 3.4 CSP 接入脚本管线与 fetch/XHR

**解析**：`load_locked` 拿到主文档响应后：
```rust
tab.security.set_page_origin(&resp.final_url);
if let Some(csp_header) = header_value(&resp.headers, "content-security-policy") {
    if !security::csp::CspPolicy::is_report_only(csp_header) {
        tab.security.cache_csp(&resp.final_url, security::csp::CspPolicy::parse(csp_header));
    }
}
```

**脚本执行门禁**（`run_pipeline`，每轮脚本执行前）：
```rust
let csp = tab.security.get_csp(base_url);
let inline_ok = csp.map(|p| p.is_script_allowed("inline", true)).unwrap_or(true);
let external_ok = |url: &str| csp.map(|p| p.is_script_allowed(url, false)).unwrap_or(true);
```
- 内联脚本被拒 → 跳过执行 + `console.warn("CSP 阻止内联脚本")`；
- 外链脚本被拒 → 不 fetch + `console.warn("CSP 阻止脚本 {url}")`；
- 无策略 → 全部放行（fail-open，与既有站点兼容）。

**connect-src 门禁**（`blocking_fetch`，跨域请求响应返回前）：
```rust
if let Some(csp) = req_env.csp {  // REQ_ENV 增加当前页 CSP 快照
    if !csp.is_connect_allowed(target.as_str()) {
        return json!({"error": "CSP connect-src 阻止请求"});
    }
}
```

### 3.5 CORS 接入页面 fetch/XHR（`blocking_fetch`）

跨域响应（target origin ≠ base_url origin）在返回 body 前：
```rust
let cors = security::cors::CorsHeaders::from_headers(&headers);
let origin = origin_of(&base_url);           // Url::origin().ascii_serialization()
match security::cors::check_simple_request(&origin, &method, &cors, false) {
    CorsResult::Allowed | CorsResult::SameOrigin => { /* 正常返回 */ }
    CorsResult::Denied(why) => {
        record_network(...);
        return json!({"error": format!("CORS 策略阻止:{why}")});
    }
}
```
- 同源请求跳过（`check_simple_request` 首行即判）；
- 非简单请求（方法非 GET/POST/HEAD 或带自定义请求头）：本轮与简单请求同一校验通道
  （`allows_headers` 为 None 时拒绝带自定义头的请求，fail-closed）；真实浏览器先发 OPTIONS
  预检——本内核无预检通道，文档标注边界，服务端正确配置 `Access-Control-Allow-*` 的站点不受影响；
- CORS 拒绝 → JS 侧 `fetch()` Promise 走 error 通道（与浏览器 `Failed to fetch` 语义一致）。

### 3.6 clip 区域截图（Phase 3 收尾）

`screenshot` 新增参数 `clip = {x, y, width, height}`（**文档坐标**，数值；`full_page=true` 时
相对整页，否则相对视口）：
1. 渲染出完整 pixmap（现有 `render()` 不变）；
2. 裁剪：边界 clamp 到 pixmap 范围，构造新 `Pixmap`，逐行复制像素
   （`PremultipliedColorU8` 为 4 字节 RGBA，`pixels()` 切片按行复制）；
3. 输出裁剪后 PNG，响应回显 `clip` 实际生效值。

### 3.7 可观测

- `inspect(network)`：每个事件加 `from_cache` 字段；输出顶层加
  `cache_stats: {hits, misses, size_bytes, entry_count}`（`inner.http_cache.stats()`）；
- 缓存命中时 `elapsed_ms=0` 且 `redirect=false`。

### 3.8 开关

`LAEW_WEB_CACHE=off` 关闭缓存读写（命中也不读，响应也不写）；其余行为不变。

## 四、测试计划

### 4.1 单元测试
- `mod.rs`：缓存命中构造 `FetchResponse` 形状（status/headers/bytes 与 entry 一致）；
- `run_pipeline`：CSP `script-src 'self'` 页面内联脚本被拒并产生 console warn；
  `unsafe-inline` 页面内联脚本放行；外链脚本 URL 不在白名单被拒；
- `blocking_fetch`：跨域响应无 CORS 头 → error；有 `Access-Control-Allow-Origin: *` → 放行；
- clip：裁剪像素正确性（小尺寸 pixmap 纯函数测试）。

### 4.2 集成测试（`tests/web_use_engine.rs`，mock HTTP）
- 带 `Cache-Control: max-age=60` 的页面第二次 `navigate` 命中缓存（mock 服务计数=1）；
- CSP `script-src 'self'` 的页面：内联脚本不执行（正文不含脚本注入内容），console 有 warn；
- 跨域 fetch 无 CORS 头：脚本侧收到 error；有头：正常返回。

## 五、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 强缓存命中导致页面不刷新 | 用户需最新内容 | `no-store` 不入缓存；协商缓存下一迭代接入；必要时 Agent 可清缓存 |
| CSP 误伤内联脚本 | 动态站不可用 | fail-open：无 policy 全放行；report-only 不执行；console warn 可观测 |
| CORS 无预检通道 | 非简单跨域请求被拒 | fail-closed + 错误信息明确；文档标注；下一迭代加 OPTIONS 预检 |
| clip 坐标歧义 | 截图区域错位 | 文档坐标单一语义（scroll 后相对整页），响应回显实际生效值 |

## 六、边界（本轮不做）

1. **协商缓存请求侧**：`If-None-Match`/`If-Modified-Since` 请求构造与 304 处理（`validation.rs`
   已备原语，下一迭代接入）；
2. **OPTIONS 预检**：CORS 预检通道（当前 fail-closed 拒绝非简单请求）；
3. **ResourceLoader 批量预取**：优先级调度面向未来 `<link rel=preload>` 管线；现有
   `load_stylesheets` 顺序加载 + HttpCache 已覆盖本轮需求；
4. **下载管理增强**（进度/暂停/重试）、**字体 @font-face 加载**、**剪贴板 API**、
   **原生窗口（headed）**：维持 ⏳，按路线图排期；
5. **IndexedDB / Worker / Shadow DOM / Canvas**：Phase 5 范围。
