## 二、五根因与修复(全部为通用内核缺陷,无站点特判)

### 根因 1:动态 `<link rel=stylesheet>` 不装载、`onload` 不派发 → **登录页白屏**

webpack 5 的 CSS chunk 装载完全依赖运行期动态创建的 `<link>`:

```js
var c = document.createElement("link"); c.rel = "stylesheet";
c.onerror = c.onload = function(_){ "load" === _.type ? resolve() : reject(...) };
c.href = cssUrl; document.head.appendChild(c);
```

内核 PRELUDE 的 `appendChild` 只调 `__lsmRegisterScriptLoad`,而它 `if (tag !== "script") return;`
—— 动态 `<link>` 既不取回也不派发 onload。入口的
`Promise.all([… c.e("src_common_css_antd-common_less") …]).then(c.bind(c, 24985))`
因此永不 resolve → 入口模块永不执行 → React 永不 mount → 整页白屏。

修复:

- PRELUDE 新增 `__lsmRegisterStyleLoad(el)`:线程内 `__lsmFetchNative(url, {…, style:true})`
  取回 → 推 `append_style` 动作交宿主原位内联为 `<style data-lsm-href=…>`(与静态外链样式
  同一真源、同层级联序)→ 派发 `onload`(失败派 `onerror`,**两者互斥**);
- 触发点:通用属性反射的 `href` setter(`t === "link"`)+ `appendChild`/`insertBefore`;
- 宿主 `dom_ops.rs` 新增 `append_style` 动作:插到 `<head>` 末尾(动态样式晚于静态样式,
  与浏览器级联序一致);
- 原生 fetch 增加 `style:true` → 请求上下文走 `Dest::Style`,响应体预算与 CORS 跳过
  与动态脚本一致(站点 CSS chunk 动辄数百 KB,XHR 的 2MB 上限会截断)。

### 根因 2:半透明 `background-color` 在计算样式阶段被压到白底 → **页头空白**

站点 CSS:`#framework-pc-header-container{background-color:#212329}` +
`.header-theme-guest-top{background-color:rgba(33,35,41,.05)}`,
导航文字 `color:#fff`。真实浏览器里页头是 5% 暗色半透明叠在深蓝 banner 上,白字可读。

内核 `style/values.rs::resolve_color` 把带 alpha 的颜色**在计算样式阶段按白底合成**
(`blend_on_white`)→ `rgba(33,35,41,.05)` 算成 `rgb(244,244,244)`(实测值)。
于是页头变成不透明浅灰,把 `z-index:3` 的 banner 整条盖住,白字页头彻底消失。

修复(渲染层 `raster.rs::draw_background` 本来就有 `blend_pixel` 合成能力,缺的是把
alpha 一路带到绘制项):

- `ComputedStyle` / `ElementBox` 新增 `background_alpha: u8`(默认 255);
- `resolve_color` 改为返回 `(rgb, alpha)` 不再压白底;`background-color` 与 `background`
  简写把 alpha 落到 `background_alpha`;
- `BgFill::Solid([u8;3])` → `Solid([u8;3], u8)`,`draw_background` 用
  `alpha * item.opacity` 合成;
- `getComputedStyle().backgroundColor` 在 alpha<255 时输出 `rgba(r, g, b, a)`(浏览器一致)。

> 半透明 **文字色** 仍未建模(继续按白底合成),见「边界」。

### 根因 3:内在尺寸测量把居中偏移当成内容宽 → **条目被撑到 5 万**

flex 条目的基础宽在 `MAX_CONTENT_WIDTH = 100000` 语境下量 max-content。
`.login-type-tab-item` 有 `text-align:center` → 行内文字的行起点被摆到
`(100000-64)/2 ≈ 49968` 处,而 `resolve_base` / `layout_abs` 用 `l.x + 文本宽` 当内容宽
→ 条目基础宽 ≈ **50032px**;`login-content-box` 的收缩宽度被同样撑到 1920(填满包含块),
登录框被推到屏幕右侧。

修复:`LayoutCtx` 新增 `intrinsic` 标志,`measure_content` 以 `MAX_CONTENT_WIDTH`
为语境时置真;`inline.rs::commit_line` 在该语境下**不对齐偏移**(max-content 宽度与
`text-align` 无关 —— 居中文字不会把块的固有宽度撑大)。

### 根因 4:快照节点缺 `style` + 动态元素查不到自身 innerHTML 子树 → **React 渲染期抛错**

- 快照节点(`document.body` / `documentElement` / 普通元素)只有 `__newEl` 造的动态节点
  有 `style`,于是 nprogress 的 `apply(document.documentElement, {transform:…})` 走到
  `e.style[t] = n` 时抛 `cannot convert 'null' or 'undefined' to object`,页面初始化链断掉;
- `document.createElement('div')` 的 `innerHTML` 解析出 `__htmlKids`,但动态元素的
  `querySelector` 只查「已挂载动态节点注册表」(`__lsmDynById`),detached 元素及其
  `__htmlKids` 子树完全查不到 —— nprogress 的
  `t.querySelector('#nprogress .bar')` 返 null,随后 `bar.style[...] = v` 同样抛错。

修复:

- `__mk()` 快照包装器补 `style: __mkStyle(...)`(读写落到 `__attrs.style` 并回写宿主);
- PRELUDE 新增 `__lsmDynSubtreeQuery(sel, rootEl)` 遍历 `__htmlKids` + `__kids`,
  动态元素的 `querySelector`/`querySelectorAll` **先查自身子树**再查注册表,
  两路结果按对象同一性去重。

### 根因 5:定位元素与裁剪/绘制序 → **登录弹层只剩白板**

- **定位元素绘制层**:CSS 2.1 附录 E 第 8 步要求定位元素及其子树绘制在常规流内容之上。
  此前显示列表只按 `(z, seq, rank)` 排序,定位元素若在 DOM 顺序上靠前会被后面的常规流
  背景/图片整块盖住(实测登录框被 hero 背景图覆盖)。
  修复:`DisplayItem` 新增 `layer`(0=常规流,1=定位),`LayoutCtx::positioned_layer`
  在布局定位元素子树时置 1,排序键改为 `(z, layer, seq, rank)`。
- **裁剪窗口不随变换走**:`clip` 记录的是变换前的裁剪窗口,项的画布位置却由 transform 决定
  → `translate(-50%,-50%)` 后白色面板被留在原位的裁剪窗口整个裁掉(只剩边框)。
  修复:`scissor_for` 把 clip 矩形随项的 transform 一起变换。
- **自身视觉画在子树之上**:`layout_abs` 在测量子树**之后**才取 `seq`,绝对定位元素自己的
  背景 seq 更大 → 画在子树之上,把子树整块盖住。
  修复:`seq` 在测量子树**之前**预分配(浏览器语义:背景画在内容之下)。

### 根因 6:缺失标准全局

`MessageChannel`/`MessagePort`(postMessage 入队,事件循环每轮排空,React 18 scheduler
走这条通道)、`DOMRect`/`DOMRectReadOnly`、`AbortController`/`AbortSignal`、`File`、`Blob`、
`Worker`(占位 + 明确告警)、`customElements`、`WebSocket`、`EventSource`、
`CanvasRenderingContext2D`。全部以裸标识符可见(`__lsmExportGlobals` 二次导出)。

### 根因 7:工具契约与实现不一致(浪费 Agent 迭代)

| 现象 | 修复 |
| --- | --- |
| `inspect(info="html")` 被拒 3 次(描述里一直宣传) | 枚举补 `html`,实现为整页/子树 HTML 源码 |
| `inspect(elements)` 只回单个元素,模型反复试探「弹层不存在」 | 新增 `params.list=true` 列表模式(配 `params.max`) |
| `explore` 只传 url 报 `explore 需要 queries`(形状未说明) | 报错给出形状示例;`queries` 元素形状写进 schema description |
| 描述里 `links/forms` 与枚举不符 | 描述与枚举对齐 |

### 根因 8:`request_human` 无人应答被判「人工取消」

`macos_dialog` 的 AppKit `run` 循环在无头/自动化环境提前返回时,兜底
`.unwrap_or_else(|| "cancel")` 报「人工取消」→ 编排器把整个任务判死。

修复:窗口意外关闭(`on_window_will_close`)与 run 循环意外返回一律报 `closed`;
`parse_result` 把 `closed` 映射为 `UiResult::Error("弹窗意外关闭(未收到应答)")`
→ 上层按「通道不可用」(4001)诚实收口。**只有「取消任务」按钮仍产生 `cancel`**。
