# 34 - 首屏加载可见性与登录前置误判修复

> 场景：百度地图公共交通路线任务，LsmAgentBrowser 有头窗口与真实页面截图。
> 方案：`tmpPlan/20261029_092117_百度地图公交路线显示与浏览器功能回归.md`

## 一、实测结论

- 百度地图首屏的栅格瓦片、道路与地名能够完整铺满 1920×1080 视口；搜索框及后退、前进、刷新、主页、地址栏均可见。未发现需要再次修改瓦片原点或工具栏布局的证据。
- 真站探针对照宿主 `inspect(elements)` 与页面 `eval_js`：`body`、`#MapHolder`、`#user-center`、搜索输入框的矩形一致，`outerHTML` 完整，未修复 JS 几何层。
- 原生窗口在 `open` 返回前不可见；两次完整任务中的 `open` 分别约 124.9s、124.7s。用户在这段时间无法确认浏览器是否已启动。
- 原提示“登录后的网站，才有一些复杂功能”被转成“用户显式登录前置”硬约束，导致 WorkFlow 禁止在登录验证前搜索，路线步骤没有开始。
- 按用户要求停止后续真站测试；本文不宣称公交路线任务已经端到端完成。

## 二、根因与修复

### 1. 首帧创建晚于整段脚本管线

`browser/mod.rs` 原先在 `script::run_pipeline`、图片加载和最终布局全部完成后才调用 `ensure_view`。重站点脚本预算为 120s，窗口也随之延迟。

修复：

- `view/bridge.rs` 增加 `ensure_loading_view`，在首屏脚本管线前创建查看器并推送“正在打开网页”帧；真实页面完成后沿用既有 `ensure_view` 替换。
- 加载页复用 Document、Layout、FontSet 和 PNG 渲染管线，不新增第二套 UI 绘制实现，也不缩短脚本预算。
- 抽出 `ensure_view_process`，加载帧与真实帧共用同一进程和命令通道，后退/前进/地址栏实现不重复。
- `ViewSink::is_alive` 识别写通道已关闭的句柄，后续 `ensure_view_process` 不再把失效句柄当成可复用进程。

### 2. “登录后”被机械等同于“先登录”

`agent/task_prerequisites.rs::requires_login_first` 原先只要文本包含“登录后/登录之后/登录成功后”等子串就返回 true，无法区分顺序指令和能力说明。

修复后：

- “先登录”仍直接命中。
- “登录后/登录之后/登录完成后/登录成功后”必须接续“再/才”及明确的后续动作，或直接接续搜索、采集、规划、打开等动作。
- “登录后的网站才有复杂功能”“登录之后可使用更多功能”“登录成功后会显示昵称”不再注入登录硬前置。

该判定仍按“误阻断的代价高于漏识别”保守设计；是否确实需要登录由页面与模型在具体任务中判断。

## 三、回归验证

- 新登录回归在旧实现上按预期失败，失败输入为用户原句；修复后 `task_prerequisites` 3 项测试通过。
- 新增加载首帧 PNG 解码及尺寸断言，验证 640×360 非空帧可生成。
- 新增 `ViewSink` 写通道关闭后的存活状态测试。
- 重基到最新 `main`（含并行布局/渐变修复）后，全量单元测试 2636 项中 2629 通过、7 忽略、0 失败；`web_use_engine` 23 项全部通过。
- Windows `x86_64-pc-windows-msvc` 交叉检查受本机工具链限制：`ring` 构建脚本缺少 `assert.h`，`VCINSTALLDIR=None`，未完成编译验证；Linux 无本机实机验证。
- 最终真站路线验收按用户要求停止，未生成路线结果文档，不宣称端到端任务完成。

## 四、边界

- 本次没有修改百度站点专用分支，所有修改均为通用任务前置和浏览器查看器语义。
- canvas 2D 仍为空实现、WebGL 不可用；栅格底图可见不代表路线矢量折线也能绘制。
- 加载首帧只解决“脚本执行期间没有窗口”，不等于缩短页面脚本执行时间，也不保证复杂站点一定完成初始化。
