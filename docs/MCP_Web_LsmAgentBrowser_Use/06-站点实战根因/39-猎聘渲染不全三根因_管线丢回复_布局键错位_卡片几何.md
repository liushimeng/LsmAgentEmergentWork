## 二、三根因与修复(全部通用内核缺陷,无站点特判)

### 根因 1:脚本管线超时后**丢弃线程已完成的整轮回复**

机制:管线每轮 `RunScripts` 用 `recv_timeout(剩余墙钟+2s)` 等回复,超时即记错误并 `break`;
JS 线程**继续跑完该轮**(174 轮起超时不清句柄),但完成时 `tx.send(reply)` 的接收端已 drop,
`let _ = tx.send(out)` 静默丢弃 —— 该轮全部 DOM 动作(模块挂载写入)永久丢失。后续
`run_pending_scripts` 只补「尚未执行」的脚本,已执行但动作丢失的模块不会重跑(webpack 模块表
已注册)→ 线程里挂载完成、宿主 HTML 里永远没有。Boa 下重站单轮可达分钟级,管线 120s 预算
内常超时 → 高频触发。

修复(两层):
1. **宽限续等**:`JsHandle::request_with_grace`(常规预算超时后同一 channel 续等
   `grace_ms()`,默认 60s,`LAEW_WEB_SCRIPT_GRACE_MS`);管线 RunScripts 与 eval_js
   (默认 30s,`LAEW_WEB_EVAL_GRACE_MS`)都改走宽限;
2. **回复邮箱**:线程侧发送失败(宿主已放弃)的回复压入 `pending_replies`(上限 8 条),
   下一个任意请求的回复经 `merge_pending_into` 合并带回 —— 旧动作/日志/网络**拼在前面**
   (时序正确),标量取当前值。eval/事件分发超时丢动作的路径同样被覆盖。

### 根因 2:JS 桥几何全 0 —— eval 超时**静默回退阶段一桥** + 桥本身是零值桩

机制(两层):
- `act_eval` 在 JS 线程忙碌超时(事件循环排定时器,单轮数十秒)时返回 None → **静默回退
  阶段一快照桥** —— 那是另一套语义环境(独立 Context、独立 document);
- 阶段一桥的 `getBoundingClientRect` 是**硬编码全零桩**,且整族几何属性
  (`clientWidth/offsetWidth/...`)缺失 → 页面脚本测量全 0/undefined,二维码 canvas
  定尺寸、地图容器测量、ResizeObserver 类组件全断链。

修复:
- 阶段一桥 `__mk` 的 `getBoundingClientRect` 改读快照 `n.rect`,补齐
  `clientWidth/clientHeight/offsetWidth/offsetHeight/scrollWidth/scrollHeight/offsetLeft/offsetTop`
  (与 `__geo1(n)` 同源)—— 即便回退也不再撒谎;
- `js_eval_thread` 区分三种结局(`ThreadEval::{Reply,NoThread,Busy}`):**忙碌不再静默回退**,
  返回 2002「线程忙碌,wait 1-3 秒后重试」;只有无线程(`LAEW_WEB_SCRIPT=off`/线程退出)
  才回退阶段一桥;`js_condition`(wait 的 js 条件)忙碌时判「未就绪」继续等;
- **「快照×布局」一致性守卫**:`TabState` 增加 `html_rev/layout_rev`(所有运行期
  `tab.html` 写入走 `set_html` 自增),`ensure_layout_locked` 在 eval/dispatch/screenshot/
  inspect 入口发现两者不一致即重算布局 —— 根治「html 已被脚本改写、rect_map 仍是旧布局」
  导致的 `:nth-of-type` 位置键整体漂移(快照与 rect_map 键错位,rect 全 None)。

### 根因 3:flex 条目子代 `height:100%` 解析不了 → 定高卡片内容溢出被裁

机制:`measure_content` 测量语境恒 `UNKNOWN_CB_H`,flex 行向条目(显式 `height:192px`)
的子代 `.seo-jobcard2-common{height:100%}` 相对未知高 → 按 auto 走内容高(叠加内容行高
虚胀)→ 溢出 `overflow:hidden` 裁剪窗 → 公司行 + logo 整行被裁(**全站 logo 不可见的
直接根因**)。显式 `height:22px` 的行盒被内容撑到 37.4 是同一测量语境的下游症状。

修复:`measure_content_with_cb_h(node, w, style, depth, Some(条目内容高))` —— flex 行向
条目高度确定(显式 height / 容器确定交叉上的百分比)时,子代百分比高度相对条目**内容高**
求解(CSS 语义);嵌套 flex/grid 容器保持内容驱动。单测
`猎聘卡片_height100链与显式行高不被内容撑破`(真实 DOM+CSS)断言:seo 卡 192、labels 22、
公司行整行落在裁剪窗内。
