# 54 - 闲鱼(goofish)渲染链多根因修复:Cookie 令牌往返 / 观察者同名遮蔽 / open 原地导航 / DOM_TRACE 截断崩溃

> 2026-11-05 真机任务触发:闲鱼品类调研(Agent 全程 `MCP_Web_LsmAgentBrowser_Use`)。
> 现象四联:首页骨架永不填充、搜索页卡「加载中」、登录页 DOM 重复堆叠 10+ 份、Canvas QR 无像素;
> 复现排障时 `LAEW_DOM_TRACE=2` 直接 panic 崩溃。
> 修复后:首页商品流完整渲染(卡片/价格/想要人数/图片)、登录页单副本 + QR 真实出图(fillRect 像素)、
> 搜索页正确呈现登录墙(站点行为)。

## 现象 → 根因对照表

| 现象 | 根因 | 修复 |
| ---- | ---- | ---- |
| mtop 接口 200 但 `FAIL_SYS_TOKEN_EMPTY` 死循环 20+ 次 | Set-Cookie 回传断链(两处) | `__lsmCookieApply` 回传 `set_cookie` 动作;`native_fetch` 用 `opts.cookies` |
| 首页骨架永不填充 / 搜索页卡加载中 | 同上(数据拿不到) | 同上 |
| 登录页组件重复 11~28 份、布局混乱 | `__lsmIsDescendant` 同名遮蔽,MutationObserver subtree 派发整链抛错中断 | 对象版改名 `__lsmNodeInSubtree` |
| 观察者派发失败 ×168 无法定位 | 错误只打 `String(e)` 或只打 stack | 消息体 + 堆栈都要 |
| `open(page_id, 新URL)` 后「页面跳走」 | run_open 忽略 page_id,悄悄另开新页 | `new_page_in(prefer_page)` 原地导航 |
| `LAEW_DOM_TRACE=2` 进程崩溃 | 字节截断切中 UTF-8 字符边界 | `chars().take(100)` |

## 根因一:Set-Cookie 回传断链(mtop 令牌拿不到)

阿里系 mtop H5 网关的令牌协议:首个请求无 `_m_h5_tk` → 响应体 `FAIL_SYS_TOKEN_EMPTY` +
`Set-Cookie: _m_h5_tk=...; Domain=.goofish.com` → SDK 读 `document.cookie` 取令牌重签 → 成功。
内核里这条链断在两处:

1. **JS 侧 → 宿主 CookieJar 不回传**:fetch/XHR 收到 `setCookie` 后 `__lsmCookieApply` 只改
   JS 侧 `__lsmCookie` 字符串;而每轮 `__lsmRefresh` 用宿主 jar **整串覆盖** `__lsmCookie`
   —— 刚拿到的令牌下一轮被静默清掉,永远令牌为空。
2. **批内快照过期**:`native_fetch` 的 Cookie 头取 `REQ_ENV.cookies`(begin_request 时的快照),
   忽略 JS 侧每次传的 `opts.cookies`(最新值)—— 同一批次内「先收令牌→立刻重试」也发不出令牌。

**修复**:
- `__lsmCookieApply` 对每条 Set-Cookie 追加 `__push({type:"set_cookie", value: 原行})`
  (整行原样,含 Domain/Path/Max-Age;宿主 `set_from_headers` 已有完整解析);
  `document.cookie` setter 的重复 push 移除,统一在 apply 内做。
- `native_fetch` 解析 opts,`opts.cookies` 非空优先于 REQ_ENV 快照。

**验证**:`tests/web_cookie_roundtrip.rs::xhr收到的set_cookie必须随下一次请求回发且落入宿主jar`。
真机:首页 `request_loop=null`(此前 20+ 次同路径重试),商品流完整渲染。

## 根因二:同名函数遮蔽,MutationObserver subtree 派发整链中断

PRELUDE 拼接顺序(prelude.rs `PRELUDE` 常量):

```
PRELUDE_BODY + CANVAS_JS + SELECTOR_JS(env_js) + GLOBALS_JS(env_js)
```

env_js 的 SELECTOR_JS 里有**索引版** `__lsmIsDescendant(idx, rootIdx)`(配 `__parent`),
PRELUDE_BODY 里有**对象版** `__lsmIsDescendant(node, root)`(配 `__lsmKey/__lsmDetachedHas`)。
函数声明提升,后拼接的索引版遮蔽对象版 → `__lsmMutMatches` 把元素对象传进索引版 →
对象参与数值比较抛 `TypeError: cannot convert 'null' or 'undefined' to object` →
`__lsmFlushObservers` 外层 catch 吃掉 → **subtree 观察者的回调永不派发**。

站点侧后果:havana-login 等 React 组件靠 MutationObserver 推进挂载状态机,收不到通知就
走错误路径反复重挂载 → 登录页同一组件堆 11~28 份、布局混乱。

**修复**:对象版改名 `__lsmNodeInSubtree`(定义 + 唯一调用点),注释里写明禁止回归同名;
另修 `__lsmHasAncestorSel` 只走快照链、不认动态节点 `__parentDyn/__parentStatic` 混合父链的问题
(动态子树内部的嵌套变更对 subtree 观察者可见)。

**教训**:
- 跨文件拼接的 JS 共享一个全局作用域,**任何新增顶层函数都要先 grep 同名**(本例 105+17 个函数里恰好撞了一个);
- 观察者测试要覆盖「目标是观察节点的**后代**」的路径 —— 直接命中(目标=观察节点本身)不走
  subtree 分支,此前的测试恰好只测了直接命中(`mutation_observer_子节点变更触发回调`)。

**验证**:`script/tests.rs::mutation_observer_后代嵌套变更subtree派发不中断`(修复前该用例计 1,修复后 2)。
真机:登录页 console 错误 126 → 7,`短信登录` 11 份 → 单副本。

## 根因三:open(page_id, 不同 URL) 静默另开新页

`run_open` 从不消费 `page_id`;`new_page` 的 `find_reusable` 按 URL/站点全局匹配,
URL 换 host 不命中 → 新建页签。模型把 `page_id` 当「在这个页里打开」用,后续 inspect/control
全打在旧页上,表现为「页面跳走/操作不生效」(与查看器多窗口层叠误判同症不同因)。

**修复**:`new_page` 拆 `new_page_in(prefer_page, …)`;显式 page_id 且存活时优先承载
(同 URL 廉价复用、不同 URL 原地导航);`run_open` 透传。

**验证**:`tests/web_cookie_roundtrip.rs::open带page_id与不同url时必须在该页原地导航`;
真机 probe:open 返回后 40s+ tab 稳定停在登录页、页面总数 1。

## 根因四:诊断代码自身崩溃 + 诊断信息缺消息体

- `dom_ops.rs` DOM_TRACE 打印 `&a.value[..len.min(100)]` 字节截断,中文 HTML 切中多字节边界 →
  panic 全进程(开 DOM_TRACE 排障时必崩)。改 `chars().take(100)`。
- 「观察者派发失败 / script onload 失败 / dyn listener load」三处 `String(e)` 或 `String(e.stack)`
  二选一;Boa 的 stack 不含 message 首行,只打 stack 会丢最关键的 TypeError 文案。统一「消息体 @ 堆栈」。
- 导航类动作(click/navigate/new_tab/submit/back/forward/reload)不进 `dom_ops::apply`,
  DOM_TRACE 对其不可见;`append_reply` 在 DOM_TRACE 开启时补打 `[domtrace] nav-action` 行
  (本轮靠它排除了「站点脚本推 navigate 回首页」的假设,最终用 `list` 双页真相定位根因三)。

## 排障方法沉淀

1. **截图字节级对比**:`cmp` 两张截图完全相同 ⇒ 页面状态根本没变,先怀疑「看的不是同一页」,
   再怀疑渲染(`action=list` 列全部页签的 URL/title)。
2. **mtop 类接口 200 ≠ 成功**:必须看响应体的 `ret:["FAIL_SYS_…"]`;curl 重放(带 URL 参数 + body)
   可独立验证服务端行为,把「内核侧问题」与「站点侧行为」切开。
3. **console 错误计数是健康度的粗粒度信号**:修复前后 126 → 7 的变化比逐条读更快定位主矛盾。
