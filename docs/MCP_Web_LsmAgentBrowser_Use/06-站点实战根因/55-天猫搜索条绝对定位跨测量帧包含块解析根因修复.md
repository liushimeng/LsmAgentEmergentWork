## 现象(真机 1920×1080)

天猫首页搜索条:红底「搜索」按钮**跑到搜索框左侧**,与框体分离。

```
inspect(elements, .btn-search) → rect = {x:615, y:53, w:72, h:36}
正确值 = #J_Search.padding_box.x(528) + width(1112) - right(2) - width(72) = 1566
```

按钮**背景**与按钮内**文字**分别落在不同坐标,文字溢出盒体左边界。

## 根因

天猫搜索条 DOM 是一条 **flex 链**:

```
.tbh-search(flex) > .search-wrap(flex) > #J_Search(position:relative, flex item)
  > form(flex) > .search-button(flex item, width:0) > button.btn-search(position:absolute;top:2px;right:2px)
```

`.btn-search` 的包含块 = 最近定位祖先 `#J_Search` 的 padding 盒。但 `#J_Search` 是 **flex 条目**:

1. flex 引擎只在 `emit_item()`(条目定位**之后**)才把条目盒写进 `ctx.boxes`;
   条目内容测量期(`measure_content_with_cb_h` / `measure_content`)盒表为空;
2. 块级流有 `PositionedPad` 先序登记兜底,但 **flex/grid 引擎没有对应机制**;
3. 于是 `nearest_positioned_cb()` 回退到调用方携带的包含块 —— 在条目测量帧里那是
   **条目自身的局部临时盒**,宽度退化为 `.max(1.0)` 的 **1px**;
4. `right:2px` 反向锚定:`bx = cx + cw - r - bw = 0 + 1 - 2 - 72 = **-73**` → 负坐标;
   叠加条目片段平移(+528)→ 实测 x=615(正确值 1566)。

### 并发问题:解析失败后继续上溯

原实现沿 DOM 上溯时,最近的定位祖先拿不到几何就**继续找更外层的定位祖先**,
直到命中一个盒表/登记。CSS 语义是「包含块由**最近**的定位祖先决定」——
继续上溯会拿到更大的包含块,把元素锚到错误位置。
实测:grid 条目内 `position:absolute;right:2px` 元素被锚到 **grid 容器右缘**
而不是**条目右缘**。

## 修复

### 1. 包含块解析:命中即止

`nearest_positioned_cb()` 走到第一个定位祖先:
- 盒表 / `PositionedPad` 命中 → 返回几何,`resolved=true`;
- 未命中 → **回退调用方包含块,`resolved=false`**,不再继续上溯。

### 2. 延后解析(flex/grid 条目内)

包含块的几何要到**条目定位后**才确定(Chrome 对「flex 容器内 abspos」也是两趟布局)。
内核此前没有等价能力位,本轮补上:

- `LayoutCtx` 新增 `abs_pending: Vec<PendingAbs>`(待二次解析的 abs 元素)与
  `abs_defer: bool`(当前处于 flex/grid 条目内容测量语境);
- `layout_abs()`:`ctx.abs_defer && !resolved` 时**不就地布局**,压入 `abs_pending`;
- flex/grid 在条目测量前后对 `abs_pending` 做**区间快照**,条目独占自己窗口内的新增项;
- `emit_item()`(条目坐标已定)用**容器自身的包含块**(容器外最近定位祖先的 padding 盒,
  坐标系 = 容器坐标系)重放:
  - 最近定位祖先就是条目自身 → 用条目内容盒;
  - 否则 → 容器包含块。
  重放发生在条目片段注入之前,坐标直接落在容器坐标系,无需片段平移补偿;
- 容器**直属**的绝对定位子元素若被延后,由容器自身认领重放(不能留给外层容器 ——
  会用到外层的包含块);
- 顶层布局收尾兜底:未被任何容器认领的残留用初始包含块补画,
  **「延后解析」不得退化为「元素丢失」**。

### 3. 为什么不选另外两条路

| 备选 | 否决理由 |
| --- | --- |
| 给 flex/grid 条目也注册 `PositionedPad` | 条目**位置**在测量期未知(flex 算法尚未分配主轴位置),登记不出真实几何 |
| 引入「帧跳过」计数(`frame_skip` 字段 + 改写 translate 语义) | 要给 TextLine/ElementBox/PaintBox/BorderDraw/ShadowDraw/DisplayItem 六个几何结构体加字段,改动面与回归风险远大于延后解析 |

## 指纹速查

| 现象 | 指纹 | 根因 |
| --- | --- | --- |
| `right`/`bottom` 反向锚定的元素整体偏移数百像素,甚至出现在父容器左侧 | `cb=(0,0,1,UNKNOWN_CB_H)` + 负 bx | 包含块退化成条目自身 1px 临时盒(本号修复) |
| 条目内 abs 元素被锚到**外层容器**边缘而不是条目边缘 | 上溯链命中更外层的定位祖先 | 包含块解析失败后继续上溯(本号修复) |
| abs 元素「不见了」 | `abs_pending` 有残留 | 容器认领遗漏(顶层兜底已补) |
