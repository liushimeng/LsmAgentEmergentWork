# 47 - 京东首页渲染不全与页脚布局爆炸根因(2026-10-30 实测)

- 时间:2026-10-30
- 场景:`MCP_Web_LsmAgentBrowser_Use` 打开 `https://www.jd.com`(1920×1080,hidden 探针)
- 现象:首页只剩服务器静态壳「显示不全、布局混乱」;页脚被拉成 5777px 高;
  首屏脚本管线在 240s 预算处被截断;`pc-tk.js` 单脚本离线跑 300s 不返回。
- 结论:显示问题不是单一布局 bug,而是「脚本管线被 Canvas 编码拖死」+
  「行内排版模型缺陷」叠加;JSONP cleanup TypeError 是噪声(数据回调已先执行),不是渲染阻断点。
- 与 [46-京东显示不全布局混乱七处通用根因修复.md](46-京东显示不全布局混乱七处通用根因修复.md)
  同批排查:**46 号是主修**(box-sizing 初始值 / `*` 通配 / 管线收尾 / 缺字形 pen /
  懒加载 / 横向滚动 / 整页截图宽),本篇只收 46 号未覆盖的**脚本运行时与排版**根因,
  两者互补不重复。

## 1. 根因链

```
pc-tk.js 指纹采集 getCanvasFp
  └→ 创建 2000×200 canvas,toDataURL()
       └→ JS 侧逐字节 String.fromCharCode + btoa 拼 1.6MB 字符串(Boa O(n²))
            └→ 单次 toDataURL >50s,pc-tk 整脚本 >300s
                 └→ 首屏脚本管线 240s 预算耗尽 → 动态主内容全不渲染(显示不全)
动态 <script> 同步 eval
  └→ JSONP 回调在 appendChild 返回前触发
       └→ 回调末尾 cleanup 读未赋值的闭包元素 → TypeError
            └→ 仅清理失败,数据回调已先执行(console 有噪声,不影响渲染)
行内文本把源码换行当硬换行
  └→ 页脚每个 <a> 之间的缩进换行各起一行
       └→ 版权区高度 4881px,整页 5777px(布局混乱)
行内盒 reserve_height 双计基线
  └→ 普通 <a> 既按字号算 ascent 又按盒高预留
       └→ 每个 <li> 行高 45px(应为 22px)
       └→ 现由 46 号的「行内块独立格式化上下文」+ `reserve_height` 口径统一承担
inline-block 内部 line-height 泄漏
  └→ 认证图标 line-height:1000px 进入外层共享行盒
       └→ 每个图标独占 500px 行
       └→ 同上,盒子高度改由盒内独立缓冲的内容高决定,不再进外层行盒
```

## 2. 修复清单

| # | 位置 | 修复 |
|---|------|------|
| 1 | `script/runtime.rs` | 新增 `__lsmCanvasPngRaw(width,height,Uint8Array)` 原生入口,宿主直接读 TypedArray 字节编码 PNG;`canvas_js.rs` 用 `new Uint8Array(pixels.buffer,...)` 走原始通道,旧 btoa 路径仅作回退 |
| 2 | `script/prelude.rs` | 动态 `<script>` 保持**线程内同步执行**(经典 `<script src>` 语义)。JSONP 回调末尾 `cleanup()` 读未赋值的闭包元素会抛 TypeError,但数据回调已先执行;异步化会打乱装载器时序、丢首屏楼层,故不做 |
| 3 | `script/mod.rs` | 管线到点时若仍有待取回脚本,顺延 60s(最多 2 次),避免 UI chunk 被定时器/广告空转挤掉 |
| 3b | `script/runtime.rs` + `script/prelude.rs` | 首屏加载轮定时器回调预算 64 → 4,且**同一到期时刻的批次按剩余预算截断**(React 首屏 mount 常有上百个同到期定时器,一次 tick 全跑完会让 cap 形同虚设);脚本取回/执行与动画帧交替推进 |
| 3c | `script/runtime.rs` | 加载轮 `event_loop` 增加 **10s 墙钟总闸**(`event_wall_ms`,排水轮不设闸)。定时器回调在 Boa 里单个可达 20s+,单轮把管线剩余预算吃光后,后续 chunk 轮次拿到的等待预算极小 → 被宿主判超时 → 整条装载链中断(京东停在骨架屏的根因之一) |
| 4 | `layout/inline.rs` | `white-space:normal/nowrap` 的源码换行/连续空白折叠为单空格(仅 ASCII 空白,NBSP 保留) |
| 5 | `layout/inline.rs` | 行内块盒高与基线口径交给 46 号的独立格式化上下文;`reserve_height` 保持 `size=8`(占位 ascent 不压过同行文本 run),避免「占位 ascent + 文本 ascent」双计把行高抬到 `盒高 + 字号` |
| 7 | `layout/grid.rs` | 负网格线 `-1` = 末端线(补 `+1`),`grid-column:1/-1` 正确跨满全部列 |
| 8 | `style/values.rs` | 支持 `place-items` / `place-content` 简写;`inspect` 的 computed style 增加 `transform` 序列化 |
| 9 | `script/runtime.rs` | 新增 `LAEW_JS_TIMING=1` 单脚本耗时台账 |
| 10 | `layout/inline.rs` | 新增 `LAEW_LINE_TRACE=1` 行盒诊断(行宽/基线/首段文本) |
| 11 | `tool_exec.rs` | 两浏览器工具的通用超时下限 = 脚本管线预算 + 顺延 + 60s(未显式配置 `LAEW_TOOL_TIMEOUT_SECS` 时),避免重站 `open`(实测 268s)被 300s 挂死保护误杀 |

## 4. 边界与后续

- `box-sizing` 缺省已由 46 号改为 CSS 初始值 **content-box**(与 Chrome 一致),
  本篇不再涉及。
- 首屏仍可能触及 240s 管线预算(重站脚本 + 广告接口)。已通过「加载轮定时器
  预算 4 + 同到期批次截断 + 待取回脚本顺延 60s×2」降低占比;后续可做
  「首屏先返回、动态 chunk 后台补齐」的异步打开模型。
- Canvas 仍只支持基础 RGBA 矩形/像素;路径/文字/渐变不参与指纹像素(与既有
  能力边界一致)。

### 结论与待办

1. **登录前置是任务级硬阻断**:未登录时 JD 首页只给静态壳 + 骨架屏,任务必须走 HITL;
   HITL 弹窗、控制权移交、终止回收链路本次全部正常。
2. **主楼层骨架屏的剩余根因**:管线能在预算内跑完(271s,未截断),但页面仍无
   `api.m.jd.com` 数据请求 —— 应用初始化链在「发数据请求」之前停住,与排版无关。
   下一步需要**完整管线下的 console 台账**(本次因按纪律终止未取到),建议:
   - 用 `LAEW_PROBE_FAST=1` 探针在无内存压力时复跑,取 `inspect(console)` 与 `inspect(network)`;
   - 重点看 `index.chunk.js` 初始化是否卡在 `document.readyState`/`load` 事件时序、
     `requestIdleCallback`、或 WebGL 能力探测失败后的静默降级。
3. **debug 档放大了耗时**:整页重排/光栅化在未优化构建下可达分钟级,`inspect text`
   与整页截图都受影响;发布档需复测耗时占比。
