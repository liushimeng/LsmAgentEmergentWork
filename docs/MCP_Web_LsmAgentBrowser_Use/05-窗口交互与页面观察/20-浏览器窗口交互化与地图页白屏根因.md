# 20 - 浏览器窗口交互化与地图页白屏根因

**轮次**:2026-10-22(百度地图路线规划任务实测驱动)

## 一、两条主线

本轮同时收口两件事:

1. **有头窗口从「显示器」升级成「浏览器」** —— 之前 `laew __browser-view` 只把宿主
   推来的 PNG 帧贴到 `NSImageView` / GDI `StretchDIBits`,窗口里没有地址栏、没有
   前进/后退/刷新,也不能交互。
2. **查清「页面只剩几个色素块」的根因** —— `https://map.baidu.com/` 在本引擎里
   渲染成一块浅灰底 + 一条搜索框 + 一个蓝按钮,没有地图、没有文字。

## 二、窗口形态:真浏览器(工具栏 + 地址栏 + 画面)

### 2.1 协议

| 方向 | 载体 | 载荷 |
|------|------|------|
| 宿主 → 查看器 | stdin(长度前缀帧) | `'i'` PNG 帧 / `'t'` 标题 JSON / `'u'` **地址栏状态 JSON** / `'c'` 关闭 |
| 查看器 → 宿主 | stdout(按行 JSON) | `{"cmd":"navigate","url":...}` / `back` / `forward` / `reload` / `home` |

`'u'` 帧载荷:`{"url": "...", "can_back": true, "can_forward": false}`。
引擎在每次推帧时同步当前页 URL 与历史栈可前进/后退状态。

### 2.2 引擎侧

* `LsmBrowserManager` 持有 `view_cmd_tx`;`ensure_view` 首次启动查看器时建通道并
  `tokio::spawn` 一个命令处理任务(命令 → `navigate` / `history_nav`)。
* 命令作用于**前台标签页**(`foreground_page_id`)。
* `refresh_view` 只在 `tab.mode.is_headed()` 时推帧——无头任务不会被凭空拉起窗口。
* `new_arc()` 构造 `Arc<Self>` 并写入自身弱引用,供命令任务回到引擎
  (`new()` 保持原签名,单测直接用不影响)。

### 2.3 macOS(AppKit FFI)

* 工具栏:`NSButton` × 4(后退/前进/刷新/首页)+ `NSTextField` 地址栏,
  挂在 `contentView` 上(**未挂 `contentView` 的控件不绘制**——踩过:按钮建好
  但窗口里看不见)。
* 回车:`NSTextField` 委托实现 `control:textView:doCommandBySelector:`,
  收到 `insertNewline:` 时读 `stringValue` 回传 `navigate` 命令。
  `class_addMethod` 的 IMP 形参类型不统一,声明改成 `*const c_void` 后按需转型。
* 编辑中(`controlTextDidBeginEditing:`)宿主不再覆盖地址栏文本。
* 前进/后退按钮按 `can_back/can_forward` `setEnabled:`。
* `LAEW_BROWSER_VIEW_ACTIVATE=1`:查看器 `activateIgnoringOtherApps:` 抢到前台
  (默认不抢,避免打断 TUI 焦点)。
* **地址栏不自动抢焦点**:可编辑的 `NSTextField` 默认会成为窗口的第一响应者,
  外部误入的按键(Agent 的物理按键注入会打到前台应用)会写进地址栏,把宿主
  下发的 URL 顶掉(实测地址栏显示成 "dan")。修复:窗口初始第一响应者置空 +
  地址栏失焦时回填宿主 URL(Windows 侧同语义:`SetFocus` 给主窗口 +
  `WM_KILLFOCUS` 回填)。

### 2.4 Windows(Win32)

* 工具栏:`BUTTON` × 4 + `EDIT` 子控件;`WM_COMMAND` 处理 `BN_CLICKED`;
  地址栏用 `SetWindowSubclass` 捕 `WM_KEYDOWN`/`VK_RETURN`。
* `WM_TIMER` 轮询里同步地址栏(焦点在编辑框时不覆盖文本)。
* **顺带修好 windows-rs 0.58 的 API 形态**:原 `view/windows.rs` 在 Windows 上
  **编译不过**(`InvalidateRect(Some(hwnd))`、`DeleteObject(brush.into())`、
  `CreateWindowExW` 返回 `Result`、`GetModuleHandleW` 返回 `HMODULE` 等),
  已按 0.58 的 `Param<T, CopyType>` 约束逐个改正。windows-only 模块 macOS 侧
  零编译,改动用 scratch crate 做 `cargo check --target x86_64-pc-windows-msvc` 验证。

## 三、「只有几个色素块」的根因链

### 3.1 实测对照

* 真 Chrome(headless,同 IP 同 URL):**完整矢量底图**正常渲染,
  瓦片是 `<img>` 元素(经典 BMap `tilesDiv.appendChild(s.img)`)——
  内核的图片管线本来就支持 `<img>` 瓦片,不是渲染器能力问题。
* 本引擎:页面只剩背景色块。

### 3.2 链路(逐环实测)

```
① 页面注入风控脚本 https://dlswbr.baidu.com/heicha/mw/abclite-2059-s.js
② 该脚本在本引擎抛 TypeError: cannot convert 'null' or 'undefined' to object
   (LAEW_JS_DIAG=1 定位到 polyfill 语句;但语句内各子表达式单独求值全部正常)
③ 脚本没走到 window.__abbaidu_2059_cb → BMAP_SECKEY 缺失
④ window.SECKEY = "<abvk>,-1" → 站点算出的 auth 无效
⑤ 服务端对地图数据请求回 {"bdErrCode":"-2"}
   (qt=ssn / qt=subwayscity;同 IP 用 Chrome 正常)
⑥ 地图初始化回调拿不到 content → 同一个 ToObject
⑦ 瓦片层(#platform / tilesDiv)未创建 → 无 <img> 瓦片 → 只剩背景色块
```

### 3.3 为什么脚本会失败

风控脚本要采集浏览器指纹:`canvas.getContext('2d')` 是空实现、
`getContext('webgl')` 返回 null、`navigator.plugins` 等能力缺失,
脚本在中途抛 ToObject。**这是反爬(风控),不是普通页面兼容问题**——
按既定处理:如实报告 + 定位根因,不硬绕。

排查用过的手段(留作后续复用):

| 手段 | 作用 |
|------|------|
| `LAEW_JS_DIAG=1` | 语句级定位抛错语句(前一轮已具备) |
| `LAEW_JS_TRACE_TOOBJ=1` | 记录 null/undefined 参与 ToObject 的内建调用点(本轮补了 `getPrototypeOf/create/entries/values/fromEntries` 五个入口) |
| 插桩法 | 把真站脚本拷到本地、在关键位置插 `__cerror` 探针(用 `__lsmMeta` / 解码表反推脚本语义) |
| `LAEW_JS_FORIN_GUARD=off` | 排除 `for...in` 源码级守卫改写造成的误伤(本轮新增;开关开/关错误一致,可排除) |
| `boa_parser` 词法探针 | 定位 `abrupt end` 类解析失败的确切列(`boa_parser::lexer::Lexer`) |

### 3.4 顺带修掉的通用缺陷

| # | 缺陷 | 影响 | 修复 |
|---|------|------|------|
| A | `location.protocol` 缺结尾冒号 | 站点拼 `protocol+'//'+host` → `https//host`,百度 `qt=ssn`/`qt=subwayscity` **404** | `split_url` 返回 `scheme+":"` |
| B | `appendChild(已有节点)` 只搬文本 | 控件子树全丢 | 新增 `append_node`/`insert_node` 动作,宿主按真实 `outerHTML` 搬 |
| C | 游离元素 `className` 不落 `__attrs` | 序列化丢类名 | `className` 写通 `class` |
| D | 游离元素 `cloneNode()` 返回空元素 | 克隆出的控件是空壳 | 深拷贝(属性/innerHTML 原文/子树) |
| E | `for...in` 守卫无开关 | 无法排除源码改写误伤 | `LAEW_JS_FORIN_GUARD=off` |
| F | Windows 查看器编译不过 | Windows 工程构建失败 | 按 windows-rs 0.58 约束改正调用形态 |
| G | `<canvas>` 区域完全透明 | 只看到"几个色素块" | 渲染层画虚线框 + 说明文字 |

### 3.5 canvas 区域占位

渲染层对可见的 `tag == "canvas"` 盒画:淡底 + 灰色虚线边框 + 居中说明
「canvas 区域:内核未实现 2D/WebGL 像素渲染(此区域无内容)」。
把"看不见"变成"看得懂的能力边界"——用户一眼知道是内核缺能力,不是页面没加载。

## 四、调试开关

| 开关 | 作用 |
|------|------|
| `LAEW_BROWSER_VIEW_ACTIVATE=1` | 有头查看器抢到前台(默认不抢焦点) |
| `LAEW_JS_FORIN_GUARD=off` | 关闭 `for...in` 守卫的源码级改写(诊断用) |

## 五、遗留缺口

1. **WebGL / 2D canvas 像素渲染**:底图/图表/游戏类内容仍无像素。
   实现 WebGL 需要软件光栅化 + GLSL 编译链,属独立大工程;
   百度底图走的是 WebGL(tangram),不解决它则地图瓦片画不出来。
2. **反爬脚本兼容**:风控脚本要的指纹面(canvas/WebGL/plugins/navigator 细节)
   补齐后可能自愈,也可能仍被服务端判为异常环境。
3. **Windows 端工具栏**:已实现但**未在真机验证**(本机只有 macOS)。
