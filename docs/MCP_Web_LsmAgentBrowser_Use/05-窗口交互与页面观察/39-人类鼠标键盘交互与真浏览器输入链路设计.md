# 39 - 人类鼠标键盘交互与真浏览器输入链路设计

> 状态:**阶段一(P0)+ 阶段二(P1)+ P2a(文本光标/选区/编辑语义)+ P2b(页面级选区与光标脚本化)已实现** · 2026-11-03 · 配套内核模块 `src/agent/browser/human_input/`(`mod.rs` 鼠标/命中 + `keyboard.rs` 键盘/剪贴板 + `text_edit.rs` 编辑纯逻辑)
> 上游依赖:`14-有头帧查看器`(帧协议/命令通道)、`20-浏览器窗口交互化`(工具栏/地址栏)、`docs/双浏览器工具架构/03-浏览器控制权状态机与视口自适应.md`(user 态放行)

## 1. 背景与目标

有头查看器(`laew __browser-view`)此前是**被动帧显示窗**:人工能看、能用工具栏/地址栏导航,
但**页面区域内没有任何键鼠通道**——`ViewCommand` 只有 `navigate/back/forward/reload/home/resize`
六个命令,人工点不动页面里的按钮、也打不了字。控制权状态机的 `user` 态对 Lsm 引擎只是
"视觉 + 语义"层面的人工接管(蒙层撤了,但没东西可点)。

本轮补齐:**人工在查看器窗口页面区内的真实鼠标/键盘操作**,与 Chrome 有头窗口的人工介入能力
对齐。目标:

1. 人工可点击(单击/双击/右键/中键)、滚轮滚动、拖拽滑块、悬停高亮;
2. 人工可键盘输入(可打印字符、Enter/Tab/Esc/Backspace/Space/方向键/PageUp·Down/Home·End);
3. 控制权铁律不变:`agent` 态(蒙层在位)人工输入被忽略,`user` 态放行——闸门在宿主输入管线;
4. 复用既有 Agent 侧交互管线(`api.rs::click_inner` / JS 事件派发 / 控件原生语义 / 导航),
   **不另造第二套事件系统**。

## 2. 总体设计:四层输入链路

```
┌─ 查看器子进程 ────────────┐   ┌─ 宿主引擎(内核进程) ──────────────────────┐
│ macOS: LsmBrowserPageView │   │ view::parse_command → ViewCommand::Input   │
│  (NSImageView 子类,捕获   │──▶│ view::bridge::handle_view_command          │
│   mouse/key/wheel 事件)   │stdout│   └▶ human_input::handle(目标页, 事件)  │
│ Windows: WndProc 消息分支 │按行 │       ├ 控制权闸门(agent 态→忽略+台账)    │
│  (WM_LBUTTON*/WM_KEY* 等) │JSON │       ├ hit_test(视口坐标→元素)          │
└───────────────────────────┘   │       ├ 复用 api.rs:click_inner/key/scroll  │
  协议:{"cmd":"input","act":…} │       └ relayout_and_push(推新帧回查看器)  │
                                 └────────────────────────────────────────────┘
```

### 2.1 查看器 → 宿主输入协议(stdout 按行 JSON,`cmd:"input"`)

| act | 字段 | 语义 |
| --- | --- | --- |
| `move` | `x`,`y`(视口坐标,已换算) | 指针移动(查看器侧 ≥30ms 节流 + 位移 ≥1px 才发) |
| `down` | `x`,`y`,`btn`(`left`/`right`/`middle`) | 按下 |
| `up` | `x`,`y`,`btn` | 抬起(宿主侧合成 click/dblclick) |
| `wheel` | `x`,`y`,`dx`,`dy` | 滚轮;`dy>0` = 向上滚(两平台语义已归一) |
| `key` | `key`(特殊键名或单字符),`mods`(`shift/ctrl/alt/meta`) | 键按下(查看器侧合并 keyup 不再单独上报,宿主按键均为"完成态"语义) |

非法行(缺字段/坐标越界)整行忽略,不打断通道——与 `resize` 同一容错口径。

**阶段二新增命令**(同通道,`cmd` 取值):
`{"cmd":"clip","act":"copy|cut|paste"}`(控件级剪贴板)、`{"cmd":"new_tab"}` /
`{"cmd":"close_tab"}` / `{"cmd":"next_tab"}`(标签页快捷键:⌘/Ctrl+T、⌘/Ctrl+W、Ctrl+Tab,
最后一个标签关闭改为打开空白页以保活查看器)。

**事件载荷(阶段二)**:宿主 → JS 线程的 `Dispatch` 请求带可选 `payload`,
PRELUDE `__lsmDispatch(sel, type, detail)` 把它**浅合并**进事件对象——键盘事件有
`e.key/e.keyCode/e.which/e.charCode/e.shiftKey…`,鼠标事件有
`e.clientX/clientY/pageX/pageY/button/buttons/detail`;页面脚本按 DOM 直觉可读。

### 2.2 宿主输入管线(`src/agent/browser/human_input/`)

- `mod.rs`:事件枚举 `HumanInput` + JSON 解析 + `LsmBrowserManager::handle_human_input(page_id, ev)`
  + 鼠标管线(按下定位光标/拖选/连击);`keyboard.rs`:键盘路由 + 控件级剪贴板;
  `text_edit.rs`:光标/选区/编辑纯逻辑(编辑运算/词界/光标映射/撤销重做);
- 按键会话态(进程级 `Mutex`):`HumanSession{ press, last_click(count 连击计数), hover, last_js_move,
  text_drag, edits }`——按下目标、连击检测(**1500ms/6px 窗口按事件到达时刻计**,2=双击 3=三击;
  窗口取 1500 而非浏览器常见的 500:点击处理链延迟会拉长相邻点击的到达间隔)、hover 去重、
  mousemove 派发节流(100ms)、单控件撤销/重做历史;
- **文本光标/选区态(P2a)**:`TabState.form_caret`(运行时覆盖层,与 `form_values` 同族)→
  `document::apply_caret_state` 落 `data-lsm-caret`/`data-lsm-sel` → `layout/widgets.rs`
  画光标条与选区高亮(与控件文本绘制同一字体度量/裁剪几何,逐像素对齐);
- **控制权闸门**:`web_control::enabled() && !is_user_control(Lsm, page)` → 忽略;首次命中在
  进度栏事件时间线落一条"人工输入被忽略(Agent 控制中)",之后每 50 次落一条(防刷屏);
  `LAEW_HUMAN_INPUT=off` 全关(查看器侧停止上报,宿主侧同时拒绝,双保险);
- **坐标命中 `hit_test`**:`layout.boxes`(元素盒,页坐标)双假设命中——`position:fixed`
  子树按视口坐标、常规流按 `视口+scroll` 换算成页坐标;候选按
  **顶层浮层(展开 select 面板/open dialog 子树)优先 → 面积最小 → z_index 高 → DOM 靠后**
  排序取首个;`display:none`/不可见盒剔除。近似边界:不做祖先 overflow 裁剪交集、
  不做 transform 逆映射(脱流元素坐标已是定位后的最终值);
- **鼠标**:down = hover 链 + `:active` + JS `mousedown` + 可聚焦元素聚焦;
  up = 同目标且位移 <6px → 走 `click_inner(kind="human")`(完整复用:JS click 派发 +
  preventDefault + 链接导航/新标签 + 表单提交 + select 面板/option + details + checkbox/radio +
  reset 本地重置 + light dismiss);`Cmd/Ctrl+点击链接` → `force_target=_blank` 新标签;
  双击(500ms/6px)→ 追加 JS `dblclick`;右键 → JS `contextmenu`(无原生菜单);
  中键点链接 → 新标签;拖拽 = 按住移动,命中 `input[type=range]` 时按 x 比例实时设值;
- **滚轮**:命中元素向上找最近可滚容器(`scroll_max>0`)→ 元素内滚动;否则视口滚动
  (`scroll_y -= dy*48`,步长 48px);推新帧;
- **键盘**(详见 §3)。

### 2.3 与控制权状态机的联动

- `user` 态(蒙层撤除)→ 人工输入放行,这才是 `request_human` 自动移交 user 态的完整含义:
  人工真的能在窗口里操作了;收口自动取回 `agent` 态后输入重新被忽略;
- `agent` 态蒙层直接烘在帧像素里(`page_bars::draw_control_veil`),宿主闸门是第二道防线,
  查看器无需感知控制态(协议零新增帧类型);
- Agent 写操作闸(4004)在工具层,与本管线(内核直驱)互不干扰:人工输入不走工具层。

## 3. 键盘语义(P0 → P2a 演进)

| 键 | 行为 |
| --- | --- |
| 可打印字符(无 ctrl/meta) | **插入聚焦文本控件的光标处**(替换选区)→ JS `input` 事件 → 重排推帧(P2a 起;P0 为尾部追加) |
| Backspace | 有选区删选区;否则删光标前一字符(0 处 no-op)。`Ctrl+Backspace` = 删词(P2a) |
| Delete | 有选区删选区;否则删光标处字符(P2a;P0 为 no-op) |
| Enter | 聚焦 textarea → 光标处换行;聚焦表单控件 → `resolve_submit` 表单提交(submit 事件可拦截);聚焦 button → 点击 |
| Tab / Shift+Tab | 焦点循环移动(文档序可聚焦元素:`a[href]`/input/select/textarea/button/`[tabindex]`,取有布局盒者) |
| Esc | 关闭顶层 dialog → 收起展开的 select 面板 → 无浮层时忽略(与 `act_key_press` Esc 链一致) |
| Space | 聚焦 button → 点击;聚焦 checkbox/radio → 切换;聚焦文本控件 → 光标处输入空格;无聚焦 → 视口下翻一页(85%) |
| ←/→ | 聚焦 range → 步进;**聚焦文本控件 → 光标左右移动**(有选区无 Shift 折叠到近端,`Shift` 扩选,`Ctrl` 词跳);select 多选列表 → 移动选中行;无聚焦 → 视口小步滚动(48px) |
| ↑/↓ | 聚焦 select → 上/下一项;聚焦 range → 步进;**textarea → 按渲染同源折行行移动(Shift 扩选)**;单行 input → 值首/值尾;无聚焦 → 视口小步滚动 |
| Home/End | **聚焦文本控件 → 行首/行尾(`Ctrl` = 文首/文尾,`Shift` 扩选)**;无文本聚焦 → 视口滚到顶/底 |
| PageUp/PageDown | 无聚焦控件时视口大步滚动 |
| ⌘/Ctrl+C / X / V | **控件级剪贴板**(P1;P2a 起选区化):有选区 = 复制/剪切选区、粘贴替换选区;无选区 = 复制整值、剪切清空、光标处粘贴。平台实现 macOS `pbcopy/pbpaste`、Windows PowerShell、Linux `xclip`,无第三方 crate |
| ⌘/Ctrl+A / Z / Y | **全选 / 撤销 / 重做**(P2a;`Ctrl+Shift+Z` 亦为重做)。撤销历史按控件存于人工会话(双栈 100 条),Agent 侧编辑不入栈 |
| 查看器级快捷键 | `Cmd/Ctrl+R` 刷新、`Cmd/Ctrl+[`/`]` 后退/前进、`⌘/Ctrl+T` 新标签、`⌘/Ctrl+W` 关标签、`Ctrl+Tab` 切标签、`F5` 刷新——查看器侧直接拦截转命令,不进页面 |
| 右键原生菜单 | 双平台原生菜单(后退/前进/刷新/首页/复制/粘贴);`LAEW_HUMAN_RMENU=off` 回退 contextmenu 事件路径(页面自定义菜单可用) |
| JS keydown/keyup | **带载荷派发**(阶段二):页面可读 `e.key/e.keyCode/修饰键`;keyup 在原生语义收尾后尽力补发(导航换页后自然 no-op) |
| HTML5 drag 近似 | 按住移动超 6px → `dragstart`(源)→ `dragover`(节流)→ 抬起时 `drop`(命中他者)+ `dragend`(源);**文本控件内拖动 = 选区拖选,不触发 drag 事件**(P2a,浏览器语义);**无 dataTransfer 模型**(页面拿不到拖拽数据,阶段三) |

**鼠标侧文本编辑(P2a)**:单击按字体度量定位光标(点击→char 索引映射与控件文本绘制
同源:`FontSet::char_spans`/`wrap_text_rows`,password 按等宽子弹串映射);`Shift+点击` 扩选;
按住拖动 = 拖选(收尾不合成 click);双击选词(词界:字母数字下划线连跑、CJK 按字类连跑,
点空白向右优先选相邻词);三击全选;光标条(聚焦时)与选区高亮直接绘制在控件内
(静态条,无闪烁动画)。

**P2b 前的边界**(部分已在 P2b 移除,见 §3「P2b 落地」):
无输入法组合(IME 中文输入,需 NSTextInputClient/TSF,后续阶段)、
无浏览器级缩放重排(Ctrl±,需样式引擎 zoom 因子)、单行超宽文本无横向滚动可见性
(越界光标/选区段夹到可视右缘)。

**P2b 新增边界**:`Selection`/`Range` 全 API 未建模(只有 `getSelection().toString()`
与文本控件的 `selectionStart/End`/`setSelectionRange`/`select()`;页面自管选区的
富文本编辑器仍不可用);跨元素选区**只画首尾元素内区段**(中间整元素不画高亮,
文本仍按两端之间全部计算 —— 两者可能不完全重合);`setSelectionRange` 的
`direction` 参数接受但不建模;`user-select:none` 只读内联样式(样式引擎未建模该属性,
外链样式表里的声明不生效)。

## 3.1 P2b 落地:光标/选区脚本化与页面级自由选区(2026-11-03 第四轮)

### 两本账

光标/选区有**两个独立模型**,职责不同、互不干扰:

| 模型 | 位置 | 索引空间 | 用途 |
| --- | --- | --- | --- |
| `CaretState` | `TabState.form_caret` | 控件的 `value`(单值字符串) | 控件内光标/选区(P2a) |
| `PageSelection` | `TabState.page_sel` | **元素可见文本**(`document::node_text`) | 页面级跨元素自由选区(P2b) |

不复用 `form_caret` 的原因:跨元素选区的字符索引必须带**元素身份**(稳定选择器),
否则 DOM 一变就错位;且 `getSelection().toString()` 的语义优先返回页面自由选区。

### 读路径(宿主 → 页面脚本)

```
TabState.form_caret ──┐
                      ├─▶ api::fill_selection_env ──▶ PageEnv{carets, caret_text, page_sel_text, focused}
TabState.page_sel ────┘                                        │
快照 SnapshotNode.sel_start/sel_end ────────────────────▶ build_meta_json("carets"/"pageSelText"/"caretText"/"focused")
                                                             │
                                                    PRELUDE __lsmRefresh
                                                             ├─▶ el.selectionStart / el.selectionEnd(文本控件)
                                                             └─▶ document.getSelection().toString()
```

- 快照新增 `selStart`/`selEnd` 字段(`document.rs` `snapshot_walk` 从
  `data-lsm-caret`/`data-lsm-sel` 读);`el.selectionStart/End` 的 getter 走
  `__lsmCarets[sel]`,非文本控件返回 `null`(与 Chrome 一致)。
- **规范属性是唯一推荐路径**;快照里的 `data-lsm-caret`/`data-lsm-sel` 私有属性
  仅供调试(PRELUDE 注释写明)。

### 写路径(页面脚本 → 宿主)

```
el.setSelectionRange(a, b) / el.selectionStart = v / el.select()
  └─▶ __lsmSetSel:乐观更新 __lsmCarets + __push({type:"set_selection", key:start, value:end})
        └─▶ dom_ops::apply → ApplySummary.form_selections
              └─▶ api::apply_js_reply → tab.form_caret → relayout_and_push(重绘高亮)
```

`set_selection` 动作与 `set_value` 同构(复用 `__push`/`apply_dom_actions`/
`apply_js_reply` 全链路,零新增管线);`start` 走动作的 `key` 位、`end` 走 `value` 位。

### 页面级自由选区手势

1. **按下**:命中元素非文本控件、在可选标签白名单内(`p`/`span`/`h1..h6`/`li`/`td`/
   `th`/`label`/`a`/…,**不含 `div`/`body`/`html`** —— 它们的文本是子代之和,
   索引空间会与渲染错位)、且非 `user-select:none` → 武装 `page_drag`;
2. **移动**:越过 6px 阈值后**每次移动都刷新头端**(索引映射是纯几何计算,不碰
   DOM 重排),只有头端元素变化才 `relayout_and_push`(与 hover 去重同口径);
3. **抬起**:已越阈值 → 落 `page_sel` 收口;未越阈值 → 清掉半提交痕迹,回落既有
   click 语义。

`page_text_caret_at` 与 `text_caret_at` 同构(复用 `FontSet::char_spans` 度量),
但取的是**元素可见文本**而非控件 value。

### 渲染近似

`layout/page_sel.rs::emit_page_sel_overlay` 读 `data-lsm-page-sel`
(`"start,end"`,`end < 0` = 到文本末尾),按**单行**近似画高亮(与控件内选区同色
`[60,130,235]` alpha 110)。**只画首尾两端元素内区段**,中间整元素不画。

### 顺带补齐(P2b)

| 项 | 落点 | 说明 |
| --- | --- | --- |
| `disabled` 点击闸 | `human_down` | `is_disabled_control` + `control_disabled`:不分发 JS、不聚焦(与 `click_inner` 同语义) |
| 模态 dialog 遮罩点击关闭 | `human_up` | 命中元素**不在** open dialog 子树内(或**无命中**)→ 关掉顶层模态框;走与 `dialog.close()` 相同的 DOM 动作路径 |
| `Ctrl+L` 聚焦地址栏 | 双平台查看器 | macOS 拦 `⌘L`(keyCode 37)、Windows 拦 `Ctrl+L`(0x4C)→ `{"cmd":"focus_addrbar"}` → `makeFirstResponder:`+`selectAll:` / `SetFocus`+`EM_SETSEL` 全选 |

### 能力缺口如实上报

`inspect(page_health)` 新增 `selection_note`:说明 Selection/Range 全 API 未建模、
跨元素高亮只画首尾元素内区段 —— 免得 Agent 对着「选区没生效」反复重试。

## 7. 风险与边界

1. **性能**:hover/typing 每次重排重渲染 1920×1080。缓解:查看器侧 move 节流(30ms/1px)、
   宿主 hover 目标去重(同元素不重排)、JS mousemove 派发 100ms 节流;
2. **命中近似**:无 overflow 裁剪交集/transform 逆映射——极端布局下可能命中"被裁剪但仍
   有盒"的元素;浮层(顶层)优先排序缓解大多数遮罩场景;
3. **文本编辑近似(P2a)**:光标/选区是**内核私有态**,`selectionStart/End` 未暴露页面脚本,
   页面自管选区的编辑器(富文本)不可用——`page_health` 能力缺口机制如实暴露;单行超宽
   文本无横向滚动可见性;光标条静态不闪烁;词界/折行与渲染同源近似;
4. **连击窗口取 1500ms**:浏览器常见 500ms 在本管线(命中+重排+JS 派发可达数百毫秒)下
   会把正常双击/三击判成单击(窗口按事件到达时刻计,自动化串行投递与人工事件积压同样
   受处理延迟影响);
5. **Windows 侧未经真机验证**:消息分支与坐标换算与 macOS 同构,构建期编译校验 + 后续
   真机回归;
6. **并发**:人工输入与 Agent 动作可能交错(同一 tab)。控制权两态互斥已保证"同一时刻
   只有一方写";user 态下 Agent 写被 4004 拒,agent 态下人工写被本管线忽略——不存在双写。
   多 `LsmBrowserManager` 实例(测试)页 id 已按管理器分段防撞号(撞号曾让并行用例
   在全局 web_control 注册表互相清态,偶发 agent_control 误拦)。
