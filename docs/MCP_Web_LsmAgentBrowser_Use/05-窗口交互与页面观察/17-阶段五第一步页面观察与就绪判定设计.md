### 1.2 三个真实缺口

**G1 · MutationObserver 是空壳。**
`env_js.rs` 的 `GLOBALS_JS` 里 `MutationObserver` / `IntersectionObserver` / `ResizeObserver`
只有「构造即注册、回调从不触发」的桩。真实站点的前端框架(Vue/React/Ant Design/Element)
普遍用 `new MutationObserver(...)` 观察容器变化来驱动二次渲染;桩实现下:
回调永不触发 → 框架停在「等 DOM 变化」状态 → 页面骨架在、交互层不出现。
这与 16 号文档记录的百度地图「widget 层整层不出现」是同一类症状的另一个成因。

**G2 · `wait` 只能等「元素可见」,且状态语义有 bug。**
`api.rs::act_wait` 现有判定:

```rust
state != "visible" || state == "attached" || document::is_visible(n)
```

- `state="hidden"` → 恒为真(元素还没出现就判「已隐藏」);
- `state="detached"` → 恒为真(同���);
- 只有 `visible` / `attached` 语义正确。

且只支持 `selector` 一种条件,不支持「等文本出现」「等 JS 条件成立」「等网络空闲」。
Agent 在动态站点上的典型卡点正是这三类:异步渲染的列表项、脚本埋点置位的标志位、
XHR 轮询驱动的增量刷新。

**G3 · 宿主侧变更对页面脚本不可见。**
页面脚本只能看到自己这一侧的动作(`appendChild`/`innerHTML=`/`setAttribute`),
Agent 侧的动作(`input_text` 写入值、`click` 引发的跳转后 DOM 重建)在下一轮快照里
才出现,但页面脚本收不到任何「DOM 变了」的通知,只能靠轮询。

## 二、总体设计:三层观察与等待框架

```
┌──────────────────────────────────────────────────────────────┐
│ L3 Agent 就绪判定原语(Rust)                                   │
│    control(wait): selector/state/text/js/network_idle 组合判定  │
│    → 复用 L2 的网络台账 + L1 的页面 JS 线程                    │
├──────────────────────────────────────────────────────────────┤
│ L2 宿主侧变更 diff(Rust 快照 ↔ JS 镜像)                       │
│    __lsmRefresh: 与上一轮快照比对 → 合成 mutation 记录          │
│    → 解决 G3:Agent 动作造成的 DOM 变化对页面脚本可见            │
├──────────────────────────────────────────────────────────────┤
│ L1 页面观察者(JS 层 PRELUDE v3)                               │
│    MutationObserver / IntersectionObserver / ResizeObserver     │
│    → 解决 G1:真实派发语义 + 阈值/子树/过滤选项                 │
└──────────────────────────────────────────────────────────────┘
```

**关键设计约束**:观察者全部在 **JS 层**实现(与真实浏览器一致——站点代码只看见标准 API),
宿主只负责把「快照变化」翻译成 mutation 记录喂进去;Rust 侧不新增页面状态机,
保持「全内存、无外部进程、契约不变」的工程约束。

## 三、L1 观察者详细设计(PRELUDE v3)

### 3.1 节点身份键

快照节点每轮 refresh 会被重新包装(`__mk` 每次新建对象),对象同一性不可用于跨轮比较。
引入稳定键:

| 类型 | 键 | 说明 |
| --- | --- | --- |
| 快照节点 | `s<index>` | `__lsm_node.i`,跨 refresh 稳定 |
| 动态创建节点 | `d<uid>` | `__newEl` 分配自增 `__lsmUid` |

子树判定 `__lsmIsDescendant(node, root)`:
- 快照 ↔ 快照:沿 `__lsmNodes[i].parent` 上溯(限 128 层);
- 动态 ↔ 动态:递归 `__kids` 身份比对;
- 混合:不成立(动态节点不在快照树内)。

### 3.2 MutationObserver

**记账点**(PRELUDE 内全部 DOM 变更入口):

| 类别 | 记账点 | 记录 type |
| --- | --- | --- |
| 属性 | `setAttribute` / `removeAttribute` | `attributes` |
| 属性 | `className` setter / `classList.add|remove` | `attributes`(name=`class`) |
| 属性 | `style` Proxy set | `attributes`(name=`style`) |
| 属性 | `value` / `checked` setter | `attributes` |
| 子树 | `appendChild` / `insertBefore` / `removeChild` / `remove` | `childList` |
| 子树 | `insertAdjacentHTML` / `innerHTML` setter | `childList` |
| 文本 | `textContent` setter | `characterData` |

**记录结构**(对齐标准 `MutationRecord`):
`type` / `target` / `addedNodes` / `removedNodes` / `attributeName` /
`attributeOldValue` / `oldValue` / `timeStamp`(虚拟时钟)。

**选项语义**(对齐标准):
`childList` 默认 true;`attributes` 仅在显式 true 或给出 `attributeFilter`/`attributeOldValue` 时为真;
`characterData` 仅在显式 true 时为真;`subtree` 决定是否匹配后代;
`attributeFilter` 为白名单;`attributeOldValue`/`characterDataOldValue` 决定是否带旧值。

**派发**:微任务检查点 —— `__lsmFlushMutations()` 在三处触发:
`__lsmTick()`(定时器/rAF 驱动的 SPA)、`__lsmCollect()`(每个宿主请求收口)、
`__lsmFlushObservers()`(组合入口)。回调异常只记 console,不打断管线。

**递归上限**:观察者回调若再次改动 DOM,最多递归 8 轮、单轮最多 32 批,超出即丢弃,
防止「回调写 DOM → 又触发回调」的自激循环。

### 3.3 IntersectionObserver

- 目标矩形取 `getBoundingClientRect()`(快照布局矩形,**文档坐标**);
- 根矩形 = 视口,按滚动偏移换算到文档坐标:`(scrollX, scrollY, scrollX+W, scrollY+H)`;
- 交集矩形 = 两矩形求交;`intersectionRatio = 交集面积 / 目标面积`(目标面积为 0 时按 1/0 处理);
- 阈值:`options.threshold`(数字或数组,默认 `[0]`);ratio 跨越任一阈值即产生 entry;
- `isIntersecting` 变化等价于跨越阈值 0;
- 首次观察产生一条初始 entry(与真实浏览器一致)。

**边界**:`root`/`rootMargin` 仅接受 viewport 根(其他根记录但不生效),
页面无布局矩形时目标不产生相交。

### 3.4 ResizeObserver

- 观察目标的矩形宽高,跨 flush 比较;
- 尺寸变化产生 entry:`contentRect` / `borderBoxSize` / `contentBoxSize` /
  `devicePixelContentBoxSize`(均为数组形式,对齐标准);
- 首次观察产生初始 entry。

### 3.5 与宿主侧变更的对接(L2)

`__lsmRefresh(nodes, meta)` 在替换 `__lsmNodes` 之前保存上一轮快照索引
`{key → {attrs, text, value, checked, kids}}`,替换之后做差分:

| 差分项 | 合成记录 |
| --- | --- |
| 新出现的节点 | `childList`(target = 父节点) |
| 属性值变化 / 属性消失 | `attributes`(带 `attributeOldValue`) |
| 文本变化 | `characterData`(带 `oldValue`) |
| 子节点数量变化 | `childList` |

首轮 refresh(页面初始解析)只建立基线,不产生记录(与真实浏览器一致)。

## 四、L3 `wait` 就绪判定原语

### 4.1 参数

| 参数 | 含义 |
| --- | --- |
| `selector` | 目标元素选择器 |
| `state` | `visible`(默认)/ `hidden` / `attached` / `detached` |
| `text` | 元素文本需包含该子串 |
| `js` | 页面 JS 表达式求值为真(`!!(expr)`) |
| `network_idle` / `network_idle_ms` | 网络静默窗口(毫秒,默认 800) |
| `timeout_ms` | 总超时(默认 30000,上限 120000) |
| `duration_ms` | 无条件时纯等待毫秒数(保持旧语义) |

多个条件同时给出时取 **AND**;典型用法:`{selector: ".result-item", state: "visible", network_idle: 800}`
=「结果项出现 **且** 网络已静默」——这正是异步列表页的判定式。

### 4.2 状态语义修正

| state | 判定 |
| --- | --- |
| `attached` | 元素存在 |
| `detached` | 元素不存在 |
| `visible` | 存在 **且** 可见(`document::is_visible`) |
| `hidden` | 存在 **且** 不可见 |

### 4.3 实现要点

- 轮询间隔 100ms,总预算 `timeout_ms`;
- `js` 条件走页面 JS 线程(`js_eval_thread`),表达式包一层 `!!(...)` 取真值;
- `network_idle` 读标签页网络台账末条 `at_ms`,与当前 `now_ms()` 比较;
- 全部条件满足即返回,附各条件实际状态与耗时;超时返回错误并附各条件最后状态。

## 六、验收标准

1. `new MutationObserver` + `observe(body,{childList:true,subtree:true})` 在页面脚本
   `appendChild` 后收到一条 `childList` 记录,`target` 可定位;
2. Agent 侧 `input_text` 造成的属性变化,在下一轮请求被页面脚本的观察者收到;
3. `IntersectionObserver` 对「视口内元素」产出 `isIntersecting=true` 的 entry;
4. `ResizeObserver` 在矩形宽高变化时产出 entry;
5. `wait {selector, state:"hidden"}` 在元素从可见变不可见后返回(修复前的恒真 bug);
6. `wait {selector, text:"合计"}` 在文本出现后返回;
7. `wait {js:"window.__ready===1"}` 在条件成立后返回;
8. `wait {network_idle: 500}` 在网络静默后返回;
9. `cargo test` 全绿;`./rebuild_restart_app.sh` 通过。

## 七、Phase 5 后续路线(本轮排期,不实现)

| 顺序 | 事项 | 收益 | 成本 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | **Shadow DOM 穿透**(`attachShadow` + 选择器/文本抽取下沉 shadow root) | 现代站点(组件库)内容可读 | 高 | 需 DOM 树多根与选择器跨 shadow 边界 |
| 2 | **WebSocket / SSE 页面侧** | 实时应用、增量刷新站点 | 中 | 需线程内长连接 + 事件回传 + 关闭语义 |
| 3 | **Canvas 2D 最小集**(fillRect/fillText/measureText + 位图导出) | 图表站点可截图 | 中 | 需像素后端与 JS 绘图 API |
| 4 | **Observer 家族补全**(PerformanceObserver / VisualViewport) | 性能观测 | 低 | 本轮框架已就位,增量小 |
| 5 | **Worker / MessageChannel** | 重计算站点 | 高 | 需多线程隔离与消息通道 |
| 6 | **IndexedDB / Cache Storage 简化实现** | 离线型应用 | 中 | 全内存实现即可 |
| 7 | **V8 后端**(`rusty_v8`) | JS 兼容性与性能 | 高 | 受网络可达性约束 |

**优先级说明**:Shadow DOM 排在首位——它是「读懂页面」的硬缺口(内容在 shadow root 里时
当前 `select`/`text` 全部读不到),收益高于实时通信与画布。
