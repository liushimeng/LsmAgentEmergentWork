## 0. 一句话

把「只挂 pointerenter/mouseenter 的悬停菜单」「setPointerCapture 的 d3-drag」
这两类静默断链补通;跨元素拖选的中间元素整片点亮;页面脚本终于能读
`select.value`;顺带 F11 全屏、Shift+滚轮横向滚动、number 微调箭头点击。

## 1. 七项落地

### 1.1 边界事件:pointerenter/leave + mouseenter/leave(不冒泡)

**根因**:P2d 的 hover 切换只派发 out/over 两对(冒泡),而
Bootstrap dropdown / AntD Tooltip / jQuery `mouseenter` 恰好只挂 enter/leave
—— 整条链静默失效。Chrome 完整顺序(hover 链 old → new):

```
pointerout(old) → pointerleave(被离开链,自内向外) →
pointerover(new) → pointerenter(新进入链,自内向外) →
mouseout(old) → mouseleave(同 leave 集) → mouseover(new) → mouseenter(同 enter 集)
```

- **跨越边界集 = 链差集**:`left = chain(old) − chain(new)`、
  `entered = chain(new) − chain(old)`(target→root 序);**公共祖先不派发**
  (同一祖先内移动不触发它的 enter/leave —— 菜单语义的根基);
  移入后代:old 在新链内 → 只发 out 不发 leave;移入祖先:反向对称;
  自空白进入 / 退到空白:整条链 enter / 只剩 out+leave;
- **不冒泡派发**:PRELUDE 新增 `__fireNoBubble(sel, type, detail)` —— 只命中
  精确挂在目标元素上的监听(静态按 `L.sel === sel`,动态按 `data-lsm-id`
  反查的动态对象**自身**);若复用 `__fire` 的祖先链匹配,mouseleave 会
  误触发公共祖先上的监听,恰好破坏菜单最依赖的语义;
- **单次往返**:新 `JsRequest::DispatchMulti`(每事件自带 selector+不冒泡位)
  + PRELUDE `__lsmDispatchMulti`。旧 out/over 两对要 2 次往返,新方案
  8~N 个事件 **1 次往返**(比 P2d 更省);api 侧 `js_dispatch_multi_bounded`
  (2s 上限同口径);会话态 `PageInputState.hover_chain` 存祖先链。

### 1.2 pointer capture 真语义(d3-drag / ECharts brush 可用)

**根因**:P2d 的 `setPointerCapture` 是防崩 no-op —— d3-drag 在 pointerdown 里
捕获后**只监听捕获元素的 pointermove/pointerup**,拖两下就"丢"。

- **写路径**:PRELUDE `setPointerCapture` → `__push({type:"pointer_capture",
  selector, key:"set"})`;`dom_ops` 新动作 → `ApplySummary.pointer_capture`
  → `apply_js_reply` 落 `TabState.pointer_capture: Option<String>`;
- **读路径**:`PageEnv.pointer_capture` → meta `"pointerCapture"` →
  PRELUDE `hasPointerCapture(sel)` 读 `__lsmMeta`;动态节点以挂载后的快照
  sel 为准(未挂载退 `@dyn:` 键,派发自然落空);
- **重定向**:`human_move`/`human_up` 的 pointer+mouse 兼容对派发目标 =
  **捕获元素优先于命中元素**(单次往返);原生手势(文本拖选/滑块)仍按
  命中,页面自定义拖拽与原生手势互不干扰;
- **生命周期**:pointerup 隐式释放(Chrome 语义)+ `lostpointercapture`;
  捕获建立/换目标由手势处理器 reconcile(对比 JS 派发前后态,转换点补发
  `got/lostpointercapture`,常态零开销);捕获目标 == 按下目标且位移小 →
  click 照常合成且 **pointerup 不双发**(click_inner 不再补发 —— 双发会
  扰动 d3 的拖拽结束判定);导航换页 TabState 重建,捕获自然清零。

### 1.3 跨元素选区整片高亮(渲染近似收敛)

P2b 起只画首尾两端,视觉上「选了三段只有头尾亮」。本轮 `apply_page_sel`
按起止元素**先序遍历收集中间叶子文本元素**(与 `collect_page_sel_text`
同一套「叶子才计数」口径,父元素文本已含子代;script/style/head 已被
`node_text` 排除),每个中间叶子落 `data-lsm-page-sel = "0,-1"`(全段)
—— **渲染层零改动**(`0,-1` 语义既有)。单行近似边界不变。
`inspect(page_health)` 的 `selection_note` 同步改口径,并新增 `page_sel`
观测字段:`{active, start, end, marked_elements}`。

### 1.4 select 读值桥(56 号文档缺口的闭环)

快照 `SnapshotNode` 此前 `value` 取 `attrs["value"]`,select 无此属性 →
`select.value` 恒空串(多选用例只能绕行断言)。本轮:

- **快照侧**(`document.rs::snapshot_walk`):tag=select 时 `value` 按
  「首个 selected option,缺省回落首项」物化(运行时值经
  `apply_widget_state` 已物化成 option 的 `selected` 属性,快照读到的就是
  运行时选中值,与 `selected_option` 同口径);新增 `selected_index`
  (无 option = −1)与 option 的 `selected` 布尔;
- **PRELUDE 侧**:select 定义 `selectedIndex`(setter 按 option 序号回写
  `set_value`)、`selectedOptions`(过滤 `option.selected`)、`options`
  (每次读现算,含 optgroup 内的项,近似活集合);`value` 读写走既有
  define("value") 通道(写 = `set_value` 动作 → form_values 物化 selected,
  Chrome 语义:脚本赋值不发 change);option 定义 `selected`(读真值,
  写近似为直接置/撤 `selected` 属性)。

### 1.5 F11 全屏切换(双平台查看器)

- macOS:`on_pv_key_down` 拦键码 103 → 对所在 window `toggleFullScreen:`
  (AppKit 原生动画与还原);不进页面;
- Windows:`forward_key` 拦 VK_F11(0x7A)→ 记录原 style/rect → `WS_POPUP`
  无边框铺满所在显示器(`MonitorFromWindow` + `GetMonitorInfoW`),再按还原;
  客户区变化经既有 `WM_SIZE` 链重排工具栏并上报宿主新视口。
  交叉验证:windows-rs 0.58 的 `Get/SetWindowLongPtrW` 接**裸 i32**
  (无 `WINDOW_LONG_PTR_INDEX` 新类型包装),scratch 壳工程
  `cargo check --target x86_64-pc-windows-msvc` 把关。

### 1.6 Shift+滚轮横向滚动(Windows 补齐)

- Windows:`WM_MOUSEWHEEL` 分支按 `MK_SHIFT`(0x0004)转横,方向取反号
  (Chrome 语义:上滚 = 向左滚);系统触控板横滚原生走 `WM_MOUSEHWHEEL`
  不经此分支;
- macOS:AppKit 对 Shift+滚轮原生输出 deltaX(触控板/鼠标均转换),宿主
  dx 通道既有,零改动 —— 如实记录;
- 边界不变:元素级滚动仍是纵向一本账(`scroll_offsets`),Shift+滚轮命中
  可滚元素时按视口横向滚动兜底。

### 1.7 number 微调箭头点击步进

`human_input::number_spinner_hit`(纯函数):点击落在 `input[type=number]`
盒**右端 13px**(与 `layout/widgets.rs::SPINNER_W` 同源)→ 上半 `+step`、
下半 `−step`,复用键盘 `step_number`(min/max 钳制、空值从 0 起步、派发
`input`);spinner 区点击不放光标、不进 datalist 展开逻辑。

## 3. 边界(如实,不做静默近似)

- enter/leave 的 `relatedTarget` 不建模(out/over 同边界);
- capture 只对单鼠标指针(pointerId 恒 1)成立;捕获元素被页面从 DOM 摘除后
  派发自然落空(`__lsmFindBySel` 返 null);
- 捕获目标 ≠ 按下目标时不合成 click(Chrome 的 click 目标是两者的共同
  祖先,这里按拖拽收尾);
- mousemove 兼容对随 pointermove 一起重定向到捕获元素(Chrome 亦如此;
  文本拖选/滑块等原生手势仍按命中);
- 中间叶子整段高亮仍是单行近似(多行块元素每段按一行画,同首尾口径);
- `select.value = x` 无匹配 option 时 Chrome 置 selectedIndex=−1,本实现
  保持原值不动(setter 只在命中时回写);
- F11 在 macOS 由 AppKit 动画接管,Windows 为瞬切无边框;系统「显示桌面」
  等手势优先时 F11 不达(用户设置);
- Windows 全屏/Shift+滚轮/查看器侧改动经交叉编译验证,真机行为待回归
  (与既有 Windows 待验口径一致)。
