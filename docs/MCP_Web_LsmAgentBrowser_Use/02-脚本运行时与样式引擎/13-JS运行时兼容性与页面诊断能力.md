# JS 运行时兼容性与页面诊断能力（第 174 轮）

## 一、背景

第 174 轮用 `https://map.baidu.com/` 跑"公共交通路线规划"实测，任务未达成。逐层排查后定位到
**不是任务难度问题，而是内核在真实站点上的一串兼容性缺陷**：页面脚本跑不动 → 主内容保持
`display:none` → 布局剪枝整棵子树 → 截图空白 / OCR 空 / 无法交互。

本文登记这轮修掉的缺陷、通用修复原则，以及仍未覆盖的边界。问题分析与逐条清单见
`tmpPlan/174-百度地图MCP_Web_LsmAgentBrowser_Use问题分析与解决方案_20261020_184300.md`。

## 二、三条通用原则

### 1. 选择器"要么命中、要么不命中"，绝不静默退化成"匹配全部"

快照桥的选择器引擎（`script/env_js.rs`，阶段一/阶段二共用）遇到不支持的语法（未知伪类、
状态类伪类）一律**不匹配**。此前 `div:hover` 会返回页面里全部 `div`，Agent 拿到一堆无关
节点却以为命中了目标 —— **比报错更危险**。

同一套选择器必须在 `inspect(elements)`（宿主 kuchikiki 真 CSS 引擎）与 `eval_js`
（快照桥近似引擎）里指向同一个元素；两边语义对齐是硬要求。

### 2. 可见性判定与布局剪枝必须同一套规则

`StyleEngine::is_rendered(node)` 沿祖先链判 `display:none`。元素不再"自报 `visible:true`
却给不出矩形"。`rect` 侧用 `laid_out` 区分"没有布局盒"与"有盒子但尺寸为 0"，
被剪枝时附 `render_blocked_by`。

### 3. 诊断能力是产品能力，不是调试开关

`inspect(info="page_health")` 把"渲染空白"翻译成可执行结论（`diagnosis` + `hint`），
让 Agent 能判断"这页是 JS 驱动的、内核没渲染出来"，从而改走该站点的非 JS 入口取证，
而不是在一张空白截图前反复重试。

## 三、JS 运行时兼容性清单

| 项 | 修复 | 文件 |
| --- | --- | --- |
| `window` 只是普通对象 | 改为全局对象的门面（Proxy）：`window.foo = fn` 同步为全局标识符 | `script/prelude.rs`、`js.rs` |
| 缺常见标准全局 | 补 `URL`/`URLSearchParams`/`Event`/`CustomEvent`/`Node`/`Element`/`performance`/`TextEncoder`/`crypto`/`Blob`/`FormData`/`structuredClone`/`queueMicrotask`/... | `script/env_js.rs::GLOBALS_JS` |
| 阶段二丢 `el.title` | 补 `title`/`alt` | `script/prelude.rs` |
| 选择器引擎退化 | 重写为共享引擎，支持组合器/伪类/属性运算符，未知语法不匹配 | `script/env_js.rs::SELECTOR_JS` |
| 元素查询扫全文档 | `el.querySelectorAll` 限定后代子树 | 同上 |
| 缺 AMD 装载器 | 最小同步装载器（`define`/`require`/`requirejs.config`/`resourceMap`） | 同上 |
| **内核抢定义 `requirejs`** | **刻意不定义**：页面自带 requirejs 有 `if (isFunction(requirejs)) return;` 守卫 | 同上 |
| `createElement` 属性丢失 | `src`/`href`/`type`/... 反射到 `__attrs`，序列化出真实标签 | `script/prelude.rs` |
| 动态脚本无 `load` 事件 | 宿主执行完外链脚本后触发 `__lsmFireScriptLoad(src_url)` | `script/prelude.rs`、`script/runtime.rs` |
| 脚本轮次不足 | `MAX_ROUNDS` 3 → 24 + 20s 墙钟预算 | `script/mod.rs` |
| 错误无法定位 | 页面脚本改在宿主侧求值，错误带脚本 URL 与 Boa 错误信息 | `script/runtime.rs` |
| 阶段一 `new Function` panic | 改直接 `eval`（Boa 0.20 在"嵌套箭头 + 内层 const"上进程级 panic） | `js.rs` |

## 四、快照桥的取舍（`document.rs`）

快照是**只读、一次性、不回写**的 JSON 镜像，不是真实 DOM：

- **起点用 `html` 而非 `body`**：`document.documentElement`/`document.head` 必须是真实节点，
  站点脚本常往 head 里插脚本/样式。
- **`script`/`style`/`svg` 入快照但文本置空、子树不展开**：`document.getElementsByTagName("script")[0]`
  要拿得到锚点，同时 `innerText` 不能被脚本源码污染。
- **属性白名单 + 全量 `data-*`/`aria-*`**：站点把可见文案大量放在 `data-title` 一类属性上。
- **文本收集跳过 `<script>`/`<style>`**：`text_contents()` 会把 JS 源码算进 `body.innerText`。

## 五、布局引擎的边界（`layout/`）

- **行内元素自身也建盒**：交互元素 / `inline-block` / 带显式尺寸的行内元素各生成近似矩形，
  供 `inspect(elements)` 的 `rect` 与坐标点击使用。
- **百分比长度按包含块求解**：`width_percent`/`height_percent` 在 `ComputedStyle` 留痕，
  布局层按父内容宽解析；百分比高度在父高未知时按 `auto`（CSS 语义）。
- **显式高度参与占位**：`height:300px` 的块盒按声明值推进流。
- **`<canvas>` 无绘制路径**：软件渲染只覆盖 DOM 文本/背景/图片，画布与 WebGL 瓦片不会出现在
  截图里。这是能力边界（见 `../01-总体设计与架构/07-全功能浏览器能力矩阵与后续阶段实施方案.md`）。

## 六、仍未覆盖（如实登记）

1. **重度 SPA 的运行时模块装载**：requirejs 的模块需要"注入 `<script>` → 等 load → 继续"
   的多轮异步循环；本轮补齐了轮次与 load 事件，但百度地图 widget 层仍依赖更多运行时条件。
2. **`alog.min.js` 类埋点脚本**：自身依赖更复杂的装载语义，会在 console 留错误，不影响主功能。
3. **内置语义差异**：Boa 与 V8 在 `Object.keys(null)` 等处的报错文案不同（都是报错，无碍）；
   遇到"Node 不报、Boa 报"的差异时，用差分探针定位（`examples/lsm_probe.rs`）。

## 七、诊断入口

```bash
cargo run --example lsm_probe -- <url> [selector]
LAEW_PROBE_JS='<脚本>' cargo run --example lsm_probe -- <url>
```

对同一页面依次看：`inspect(elements)` 的 `rect.laid_out` → `inspect(page_health)` 的
`console_errors`/`blank_page` → `inspect(console)` 的具体报错。三层下来就能区分
"DOM 没建出来"、"建出来了但被剪枝"、"渲染出来了但截图没画"。
