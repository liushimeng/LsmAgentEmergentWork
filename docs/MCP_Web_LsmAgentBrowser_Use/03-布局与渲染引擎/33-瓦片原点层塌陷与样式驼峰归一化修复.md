# 33 - 瓦片原点层塌陷与样式驼峰归一化修复

> 对应方案:`tmpPlan/20261028_152644_百度地图瓦片原点塌陷与查看器地址栏编辑.md`
> 场景:第 176 轮真机(`Dir_LsmAgentBrowser_baidu_01`,`--debug -f` 百度地图公交路线规划)。
> 症状:Lsm 查看器里百度地图瓦片只画左上一角、下半屏空白(第 175 轮修复容器几何后的残留);
> 另有查看器地址栏不支持复制/粘贴。

## 一、根因与证据(全部真机探针实证)

### 1. `insertAdjacentHTML` 伪元素壳吞掉真元素(主根因)

百度地图建瓦片图层用 `co` 辅助函数(initmap_a678ab3.js 逆向):

```js
function co(t, e) { return t.insertAdjacentHTML("beforeEnd", e), t.lastChild }
// 用法:瓦片原点层 = co(platform, '<div style="position:absolute;z-index:0"></div>')
//       随后对返回值写 display='' / left=中心x / top=中心y
```

瓦片 `<img>` 的坐标系原点就是这个「原点层」:瓦片 `left/top` 是相对地图中心的
负偏移(实测 `-248.10250000000815px` 这类分数像素),原点层 `position:absolute`
+ `left/top=视口中心` 把它平移到视口中心。

**我们的缺陷**:PRELUDE 两条 `insertAdjacentHTML`(快照元素 + detached 元素)都把
HTML 包进一个**伪元素壳**再挂载,`t.lastChild` 取回的是壳:

- `LAEW_DOM_TRACE=2` 全量账本现场:
  `append_html → <div data-lsm-id="d22"><div style="position:absolute;z-index:0"></div></div>`
  (真元素被裹进壳)→ `set_attr d22 style=display:;left:960.10px;top:539.94px;`
  (页面把中心坐标写到**无 position 的壳**上,静态元素 left/top 被忽略);
- 结果:原点塌到 (0,3),瓦片栅格整体偏移(偏移量随中心坐标小数变化,呈「每轮随机」观感),
  实测栅格 bbox y∈[-633,647],下半屏 430px 无瓦片;
- Chrome `--disable-webgl` 地面真值:同一层 = `position:absolute; z-index:0;
  left:960.102px; top:496.946px`(Chrome 993 高视口,中心即 left/top),
  瓦片直接挂在该层下,坐标系成立。

**修复**(prelude.rs,两条路径同修):`__parseHtml` 解析出**顶层节点直接入子**
(detached → `__kids` + `__lsmPushDynChild` 回写宿主;快照 → `dynKids` + push
`append_html/insert_html`,value 用 `__serEl(kid)` 串接保 `data-lsm-id` 几何回认),
`lastChild/firstChild/children` 从此取到真元素;空串/解析失败退回旧伪元素路径。
`co` 模式(insertAdjacentHTML + lastChild)是站点通用辅助函数模式,受益面远不止百度地图。

### 2. `style.zIndex` 驼峰名原样序列化(独立根因)

`el.style.zIndex = 5` 经 `__mkStyle.set` 把 `zIndex:5` 原样写进 style 属性字符串,
宿主 CSS 解析器只认 `z-index` → 声明死亡。实测 platform `zIndex:5`、图层
`zIndex:200/50`、mask 的 `WebkitUserSelect` 全部中招(z-index 层叠丢失)。

**修复**:新增 `__cssPropName` 归一化(WebIDL 语义):`zIndex→z-index`、
`cssFloat→float`、`Moz*/Webkit*/O*` 大写开头通用转换天然出 `-moz-*` 等、
`ms*` 小写开头特判补前导短横;set/get/getPropertyValue/setProperty 四路统一走归一化。

### 3. 查看器地址栏不支持复制/粘贴

`__browser-view` 子进程没有 NSMenu,⌘C/⌘V/⌘X/⌘A 的 key equivalent 依赖
「菜单项 → responder chain → first responder(地址栏)」系统路径,无菜单条不可用。
第 139 轮给 HITL 弹窗装过 `install_main_menu`,查看器漏装。
**修复**(view/macos.rs):移植同款主菜单(LAEW 浏览器应用菜单 + 编辑菜单:
剪切/复制/粘贴/全选),AppKit 另会自动补文件/显示/窗口标准菜单。

### 4. 「窗口自动跳走只看到安全验证」(非缺陷)

本会话日志全程 0 次 navigate;同刻另一并行会话的 zhipin 查看器窗口(标题即
「安全验证 - BOSS直聘」)晚 1 秒启动并自前置前盖住了百度窗口——用户看到的是
**多会话窗口层叠**,不是页面跳转。跨进程抢前台无法根治,窗口标题已含
`page_id · 页面标题 — URL` 供区分;测试并行时需知悉此观感。

## 二、修复效果(真机验证)

- 原点层与 Chrome 地面真值逐字一致:`position:absolute;z-index:0;display:;left:960.1025px;top:539.9458px;`
- platform/mask/图层样式全部中划线化:`z-index:5/9/200/50`、`-webkit-user-select:none`;
- 瓦片栅格 bbox 从 [-1016,-633,1032,647] → **[-56,-93,1992,1187]**,
  全覆盖 1920×1080 视口;单瓦片屏幕位置 (712,419) = 原点 (960.1,539.9) + 相对 (-248.1,-123.9) 精确吻合;
- 有头查看器人工确认:瓦片铺满全窗、左侧搜索栏/右侧路线规划面板正常渲染、
  菜单栏出现「LAEW 浏览器 | 编辑」(⌘C/⌘V 可用);
- 新增单测 6 例(co 模式快照/动态双路径、多顶层节点保序、驼峰归一化 JS/宿主双侧),
  全量 `cargo test --lib` 2618 通过(macos_ax_smoke 1 例本机 AX 环境存量失败放行)。

## 三、通用性说明

- 两项 PRELUDE 修复均为**通用浏览器语义**,零站点特判;
- `LAEW_DOM_TRACE` 升级支持 `2`/`full` 全量动作账本(本轮定位根因的关键工具,
  默认每批 25 条采样会漏掉后段动作),已同步 CLAUDE.md。

## 四、诚实边界

- canvas 2D/WebGL 仍是空实现:百度地图走**降级栅格瓦片**路径(无 WebGL 时的
  官方降级),`capability_gaps` 继续如实上报;矢量标注层(canvas)内容仍画不出;
- platform 的 40×3 幻影最小尺寸保留:不影响瓦片定位(瓦片按 left/top 绝对定位逃逸);
- `display:;` 空值声明我们保留(Chrome 序列化会丢),CSS 解析层无害。
