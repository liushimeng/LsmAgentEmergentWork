# 49-图片 object-position/alt 占位、表格间距/caption-side、列表倒序、表单禁用继承与 label 转发

> 2026-11-03 | `src/agent/browser/layout/`、`src/agent/browser/style/values.rs`、`src/agent/browser/api.rs`
>
> 本轮只补「可见显示异常」与「控件状态可见性」，不引入结构性大项
> （Shadow DOM / CSS 动画帧同步 / 完整层叠上下文仍列为后续路线）。
> 每项都给出落点、边界与测试，并在知识库标注完成状态。

## 一、问题现象

复核《Web 端控件全量清单与渲染设计要点》后，以下缺口在知识库中已明确标注为
⛔/🟡，但代码长期未补：

| # | 现象 | 旧行为 | 根因 |
| --- | --- | --- | --- |
| 1 | `<img>` 内容不跟随 `object-position` | 恒居中 | `DisplayKind::Image.off_x/off_y` 恒 0，样式层无 `object-position` |
| 2 | 图片加载失败后一片空白 | 无任何像素 | 未加载分支直接跳过绘制 |
| 3 | 表格 `border-spacing` 无效 | 单元格紧贴 | `table.rs` 文件头「仍不实现」 |
| 4 | `caption-side: bottom` 无效 | 标题恒在上方 | `layout_caption` 只在内容前调用 |
| 5 | `ol reversed` 不倒序 | 恒 1/2/3 | `ol_index` 只处理 `start` |
| 6 | `fieldset[disabled]` 内控件仍显示可用 | 文字不灰、可点击 | `is_disabled` 只看自身属性 |
| 7 | 点击 `label` 无反应 | 走 label 自身的空点击 | `click_inner` 无 label 分支 |

## 二、本轮落地

### 2.1 `object-position`

- `ComputedStyle` 新增 `object_position: Option<BackgroundPosition>`，复用
  `parse_background_position`（关键字/`px`/`%`，1-2 值）；缺省 `None` = `50% 50%`。
- `LayoutCtx::content_image_paint`：`fit_rect` 对 `contain/cover` 返回居中偏移
  `(default_ox, default_oy)`，期望偏移 `desired = pos.resolve(box, drawn)`，
  令 `off = desired - default`，使最终绘制点 = 内容盒 + 期望位置。
- 五处内容图发射点（块级替换 / 行内原子盒 / absolute / flex / grid）统一走
  该方法，避免各算一套偏移。

### 2.2 `<img>` 加载失败 alt 占位

- `LayoutCtx::emit_img_alt`：仅当标签为 `img`、未加载且 `alt` 非空时，
  在内容盒内左上角画灰色（`[117,117,117]`）单行文本，`DisplayItem.clip`
  限定在内容盒内；按字体度量逐字符截断。
- 五处内容图发射点在「未加载」分支调用该方法。

**边界**：不画破图图标；`alt=""` / 无 `alt` 不画；无尺寸的未加载图片盒为
`0×0`（`replaced_size` 既有语义），没有可画区域故不画。

### 2.3 表格 `border-spacing`

- `ComputedStyle` 新增 `border_spacing: (f64, f64)`；解析
  `border-spacing: <h> [<v>]`（1 值两轴同值，2 值水平/垂直）。
- `layout_content`：列宽预算扣除 `(n_cols + 1) * h_space`（外侧也留间距，
  与 Chrome separated borders 一致）；单元格 x 加 `h_space + col * h_space`，
  行 y 加 `v_space + row * v_space`；行盒宽与返回内容高均含外侧间距。
- `border-collapse: collapse` 时间距强制为 0（与 CSS 一致）。

### 2.4 表格 `caption-side`

- `ComputedStyle` 新增 `caption_side: String`（默认 `"top"`）。
- `layout_container`：`top` 先画 caption；`bottom` 先跑 `layout_content`，
  手动推进内容高度后再画 caption。
- **顺带修复**：`layout_content` 不推进全局游标（既有设计），旧代码在
  `caption-side: top` 下把 caption 高**重复计两次**（`layout_caption` 推进
  一次、末尾 `advance_y(content_h)` 再一次）。本轮改为按「已推进量」补差，
  caption 后的兄弟元素位置不再被多推一个 caption 高。

### 2.5 `ol reversed` 倒序

- `Marker.index` 由 `usize` 改为 `i64`。
- `ol_index`：普通列表首项 = `start`（缺省 1），逐项递增；`reversed` 首项 =
  `start`（缺省 = 列表项总数），逐项递减，**可为 0/负数并原样显示**。
- 字母/罗马数字只对正序号有定义，递减到 0/负数时回落十进制。

实测 Chrome 对照（`reversed` / `reversed start=5` / `start=3` /
`reversed start=1` / `reversed start=10`）→ `3,2,1` / `5,4,3` / `3,4,5` /
`1,0,-1` / `10,9,8,7`，本实现与之一致。

### 2.6 `fieldset[disabled]` 控件禁用继承

- `is_disabled` 扩展：自身 `disabled` 为真，**或**任一祖先
  `fieldset[disabled]`（且当前控件不在该 fieldset 的**首个 legend** 子树内）。
- 渲染侧 `control_text_color` / `accent_color` / `emit_meter_like` 经
  `is_disabled` 自动获得继承禁用态（灰化）。
- 交互侧 `click_inner` 的 `disabled` 判定同步走该辅助方法。

### 2.7 `label` 点击转发到关联控件

- `api.rs::resolve_label_control`：`label[for]` → 同文档 `id` 匹配的**可标注
  元素**（`input`/`select`/`textarea`/`button`/`meter`/`output`/`progress`）；
  无 `for` → label 内第一个可标注后代（DFS 文档序）。
- `click_inner` 解析到节点后，若为 `label` 且命中关联控件，则把点击目标替换
  为该控件（`hover_chain` 等后续逻辑随之作用于控件，与浏览器一致）。
- 命中失败（无关联控件）按普通点击处理；只转发一次，不递归。

## 四、边界与后续

- `object-position` 只覆盖 `<img>` 内容图；背景图仍走 `background-position`。
- alt 占位不做破图图标、不做无尺寸图片的 inline 化（盒 0×0 时不画）。
- `border-spacing` 只覆盖 separated 模型；嵌套表联合求解仍不做。
- `reversed` 的字母/罗马负数回落十进制（浏览器无标准定义）。
- `label` 转发只处理可标注元素；`label` 嵌套 `label` 非法，不处理。

后续路线：

1. `position: sticky` 真实吸附（需把 `scroll_y` 传入布局并处理包含块约束）。
2. `inline-grid` / `inline-table` 的独立格式化上下文（需样式层保留行内级语义）。
3. 行内块的 `box-sizing: content-box` 口径统一。
4. `datalist` 联想弹层、`output[for]` 即时计算、`dialog` 焦点圈禁/遮罩点击关闭。
5. 完整层叠上下文（`opacity`/`transform` 建上下文）、CSS transition/@keyframes。
6. Shadow DOM / slot 分发。
