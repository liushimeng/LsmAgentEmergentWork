## 二、缺陷与修复

### R1（P0）截图 `ocr:true` 静默不落盘

- **位置**：`src/agent/browser/mod.rs::screenshot_locked`
- **现象**：Agent 调 `screenshot(params={full_page:true, ocr:true, save_path:...})`
  返回 `code:0`，但 `ls` 验证文件不存在 → wf-2 直接被判死。
- **根因**：`if ocr { ...; return Ok(...) }` 在渲染分支**之前** return，
  PNG 分支被整段跳过。`ocr` 被当成了「只给文字」而不是「顺带给文字」。
- **修复**：OCR 块只算不返回，渲染+落盘照走，OCR 字段事后并入返回。
  同修：`full_page=true` 时 `scroll_y` 归零（旧实现整页画布仍按 `tab.scroll_y`
  上移内容，滚动过的整页截图顶部被切、底部留白）。

### R2（P0）动态元素几何恒 0 → 地图无法自量尺寸

- **位置**：`src/agent/browser/script/prelude.rs::__newEl`
- **现象**（真站探针，`map.baidu.com`，1280×720）：
  - `document.querySelectorAll('*')` = 146~158（真实浏览器数千）
  - `canvas` 数量 = **0**，`#MapHolder` 之外的地图层全部缺位
  - `body > *` 已布局盒仅 1 个（1264×17 的薄盒），其余全是 `position:fixed` 推广位
  - 页面只有 11 个可见文本字符（搜索框 placeholder）
- **根因**：`__newEl` 把 `clientWidth/clientHeight/offsetWidth/offsetHeight/
  scrollWidth/scrollHeight/offsetLeft/offsetTop` 写死为 0，
  `getBoundingClientRect()` 恒返回全零。站点地图/路线面板的容器由 JS 建出
  （`createElement` + 设尺寸 + `appendChild`），读到 0×0 就不装载。
- **关键观察**：宿主**其实已经**把这些动态子树重新解析进 DOM 并参与布局
  （`script/mod.rs` 用 `snapshot_nodes_with_rects` 回传 rect）——
  几何**就在快照里**，只是 JS 侧没有按节点认回来。**纯 JS 侧闭环，宿主零改动。**
- **修复**（三步闭环）：
  1. `__serEl` 给动态节点输出 `data-lsm-id="d<uid>"`（宿主 `common_attrs`
     全量保留 `data-*`，属性随快照回流）；
  2. `__lsmRefresh` 扫描快照里带 `data-lsm-id` 的节点，把 `rect` 写进
     `__lsmDynGeom[key]`，并把动态对象**收养**到该快照节点
     （回填 `__lsm_node`/`__lsm_idx`）；
  3. `__newEl` 的几何属性改为 getter，按 `__lsmKey` 实时查表；未挂载时
     仍按 `display:none` 语义取 0。
- **真站前后对照**：`document.createElement('div')` 设 400×250 挂载后次轮回读
  —— 修复前 `cw:0, ow:0, rect 全零`；修复后 **`cw:400, ch:250, ow:400, oh:250`**。

### R3（P1）动态元素 `addEventListener` 是空实现 → 面板按钮点了没反应

- **位置**：`prelude.rs::__newEl`（`addEventListener: function () {}`）
- **修复**：注册进 `__lsmListeners`（带 `node` 对象引用）；
  `__fire` 新增 `__dynChainOf(node)` 动态冒泡链——宿主点击落在被收养的
  快照节点上时，沿 `__parentDyn` 上溯命中注册在动态对象上的监听；
  另补 `__fireDyn` 供 `el.click()` 自触发。`appendChild/insertBefore/append/
  prepend` 同步维护 `__parentDyn`，`remove()` 真正摘链。

### R4（P1）`position: fixed` 随页面滚动

- **位置**：`layout/position.rs`（fixed 包含块已正确取视口 `(0,0,vw,vh)`）×
  `render/raster.rs`（`scroll_y` 对**所有**项无条件相减）
- **根因**：fixed 的盒坐标是**视口系**，普通项是**页面系**；光栅化统一减
  `scroll_y`，固定控件一滚就跑位（地图缩放控件/比例尺/工具栏全是 fixed）。
- **修复**：`DisplayItem` 增 `fixed: bool`；`layout_abs` 对 fixed 子树
  `fixed_depth += 1`，发射的项全部带标；`raster::rasterize` 对带标项把
  本项滚动量归零（含 `clip`）。

### R5（P1）无层叠上下文 → z-index 只对自身生效

- **位置**：`layout/mod.rs::apply_group`（只传播 transform/opacity/clip，不传播 z）
  × `render/display.rs`（全局按 `(z, seq, rank)` 排序）
- **根因**：父 `z-index:9999` 的整棵子树，会被一个无关兄弟节点 `z-index:1` 压住
  （百度地图 `#platform`/`#mask`/瓦片层/控件层层叠全乱）。
- **修复**：`LayoutCtx` 增 `z_floor`；`emit_element` 取 `max(自身 z, z_floor)`，
  `apply_group` 把子树项抬到 `max(项 z, max(自身 z, z_floor))`。
- **近似边界**：真实 CSS 还需 BFC/transform/opacity<1/flex-grid 条目等条件才创建
  层叠上下文；负 z-index 子级压在父背景之下的语义不在近似内。

## 四、本轮明确「不做」与原因

**百度底图（tangram）走的是 WebGL**（20 号文档 §5 既有结论），`getContext('webgl')`
在内核返回 `null`、`getContext('2d')` 是空实现。软件 WebGL（光栅化 + GLSL 编译链）
属**独立大工程**，本轮不碰。因此 Lsm 侧**地图底图仍不会出现在截图里**——
本轮修的是「显示不全/布局混乱」中**可修且影响任务达成**的部分
（骨架挂载、容器尺寸、控件定位、层叠、截图落盘），底图留作后续专项。
这正是双浏览器工具架构的意义：Chrome 达成任务，Lsm 反-反爬场景兜底。
