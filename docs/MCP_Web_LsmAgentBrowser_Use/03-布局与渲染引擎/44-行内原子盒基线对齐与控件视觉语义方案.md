# 44-行内原子盒基线对齐与控件视觉语义方案

## 一、背景与根因(实测)

第 40/41/42 轮把「表单运行时状态 → 样式 → 布局 → 显示列表 → 像素 → 交互重排」的垂直闭环打通,
控件内置 UI、运行时伪类、顶层浮层、表格格式化上下文、列表 marker 都已有像素与测试。

但复核《Web 端控件全量清单与渲染设计要点》第一条渲染要点时发现:**行内排版这一层仍是旧模型**,
控件与替换元素根本不参与行盒,派生出一整类「显示不全 / 垂直错位」:

| # | 症状 | 实测(第 44 轮探针) | 根因 |
| --- | --- | --- | --- |
| 1 | 段首凭空多出一个空洞 | `<p>Hello <a>link</a> World</p>` 的文字整体**下沉 23.2px**(纯文本段落为 16px) | 行内盒登记进行内台账 `max_bottom`,块游标在文本 flush **之前**被推下去 |
| 2 | 控件压住前面的字 | `<p>Hello <input> World</p>` 的 input 盒画在 x=8(行首),与「Hello 」完全重叠 | 控件盒 x 用收集期的 `line_x`,**宽度不占位**、不参与断行 |
| 3 | 控件独占一行 | 同一例中「Hello World」被挤到 y=39.2(控件下方)单独成行 | 控件高度经行内台账把块游标推下去 |
| 4 | 垂直不对齐 | 控件与同行文字**顶对齐**,无基线 | 无基线概念;文本基线只是「行顶 + 字号」的近似 |
| 5 | 行内图片不随行走 | 行内 `<img>` 只抬高行高,宽度不占位,换行后仍停在段首 | 走 `reserve_height` 占位 run,无宽度参与 |

根因是**行内排版模型缺一层**:第 40~42 轮做的都是「盒内」的事(控件画什么、状态怎么变),
但**盒与行盒的关系**没动 —— 行内盒不占宽、不参与断行、不按基线对齐。

本轮把这一层补上,并顺手补齐控件视觉语义与两处交互语义缺口。

### F1 行内原子盒

新增 `layout/inline_atomic.rs`,定义**行内原子盒**(inline atomic box):一个**叶子**的、不可再分的
行内盒 —— 替换元素(`img`/`svg`/`canvas`/`iframe`)与表单控件
(`input`/`select`/`textarea`/`button`/`progress`/`meter`)。

原子盒在行内**占宽、参与断行、按基线对齐**,并在**行提交时**才发射盒与显示项
(此时最终位置已确定,不需要事后平移显示项)。

关键改动(`layout/inline.rs`):

1. `InlineBuf` 新增 `atomics: Vec<InlineAtomic>` 与**共享收集序号** `order`;
   `InlineRun` 新增 `order` 与 `sealed`(原子盒**封口**其前文本 run,
   否则「文本 → 原子盒 → 文本」合并后会丢掉先后位置)。
2. `flush_inline` 把文本 run 与原子盒按 `order` 合并成**一条事件流**:
   - 文本 run:原断行逻辑不变,行宽改为「流位置 - 行首」;
   - 原子盒:占位宽 = `margin_left + padding_left + w + margin_right`,
     放不下先断行,再推进流位置。
3. `commit_line` 先算基线,再落位:
   - 基线 = 行顶 + **基线以上高度**;
   - 文本段 y = 基线 - 字号(渲染层再加字号得基线,与旧口径在无原子盒时**逐像素一致**);
   - 原子盒按 `vertical-align` 落位。
4. `emit_atomic` 统一发射:盒 + 边框/阴影 + 背景 + 内容图 / 控件内置 UI。

**基线分解口径**:

| 原子类别 | 基线以上 | 基线以下 | 依据 |
| --- | --- | --- | --- |
| 替换元素 | 盒高 | 0 | CSS 2.1 §10.8.1:替换元素的底边贴基线 |
| 表单控件 | 盒高 × 0.8 | 盒高 × 0.2 | 浏览器经验值:控件底边略低于行内文字基线,控件内部文字基线与行内文字基本对齐 |

**边界**:行内块(`display:inline-block`)与普通行内元素(`a`/`span`/`label`)仍走「子内容进共享行内
缓冲」的旧路径 —— 它们的文本参与段落断行是对的,但元素自身的背景盒位置只是**近似**(画在行首),
且行内块尚未获得「盒宽包住文字」的独立格式化上下文(见后续路线)。

### F2 基线分解与 `vertical-align`

- 样式层新增 `vertical-align` 计算值(`style/values.rs`):此前该属性落进未建模表 `extra`,
  布局层**完全不可见**;现归一为关键字或长度原值。
- 布局层解析(`layout/inline_atomic.rs::parse_valign`):支持
  `baseline`(缺省)/`middle`/`top`/`bottom`/`sub`/`super` 与长度/百分比。
- 行盒高度改为「基线以上 + 基线以下」两段:
  - 文本段:基线以上 = 字号,基线以下 = `line-height - 字号`;
  - 原子盒:按类别给出(见上表);`top` 对齐的原子盒只贡献下半段。

**兼容性**:无原子盒时,行盒高度与旧口径(`max(line-height)`)在绝大多数场景**逐像素一致**;
仅当「最大字号段」与「最大行高段」不是同一段时,行盒高度相差数像素(旧口径偏小)。

## 四、显示异常排查映射(本轮更新)

| 现象 | 优先检查 |
| --- | --- |
| 段首多出一个空白 / 文字整体下沉 | 行内盒是否仍登记进 `max_bottom`(`float.rs::register` vs `register_band`) |
| 控件压在文字上 | 原子盒是否走了 `push_atomic`;占位宽是否计入 `occupied_width()` |
| 控件把后面的文字挤到下一行 | 是否仍在用 `reserve_height` 占位(应为原子盒占宽) |
| 控件与文字高度不齐 | `commit_line` 的基线分解;控件 ascent/descent 比例(0.8/0.2) |
| 行内图片不随行走 / 换行后停在段首 | 是否走 `collect_inline` 的替换元素原子盒分支 |
| `vertical-align` 无效 | `style/values.rs` 是否解析该属性;`parse_valign` 的关键字映射 |
| 勾图元颜色不对 | `DisplayKind::WidgetGlyph.color`;`accent_color()`(禁用态优先灰化) |
| meter 颜色不对 | `low`/`high`/`optimum` 三区口径(最优值居中 = 中绿两红) |
| progress 不确定态没画 | 是否有 `value` 属性(无 = 不确定态) |
| select 列表形态不铺开 | `select_is_list()`:`size>1` 或 `multiple` |
| 点击 reset 没恢复默认值 | `reset_form_controls` 是否清掉 `form_values`;是否被 `preventDefault` |
| Esc 关不掉 dialog | 是否存在带 `open` 的 dialog;`close_top_dialog` 的文档序选取 |
