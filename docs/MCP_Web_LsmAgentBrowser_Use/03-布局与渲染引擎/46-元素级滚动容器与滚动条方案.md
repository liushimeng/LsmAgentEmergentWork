# 46-元素级滚动容器与滚动条方案

## 一、背景与根因

《Web 端控件全量清单与渲染设计要点》第五节「显示不全问题核心排查方向」第 2 条写的是
**溢出规则失效**。第 41~45 轮把「浮层逃出祖先裁剪」(`top layer` + `position:fixed`)
这一类补齐了,但还有一类没动:**元素级滚动容器**。

现状(第 46 轮探针):

```html
<div style="overflow:auto;height:60px">
  <p>第一段</p> … <p>第四段</p>
</div>
```

- `overflow:auto` 被归一成与 `overflow:hidden` **完全相同**的布尔裁剪开关
  (`style::values.rs::parse_overflow`),内容超出盒高即被裁掉;
- 内核**没有元素级滚动状态**(`TabState` 只有页面级 `scroll_x/scroll_y`),
  滚动的量无处安放;
- 元素级 `scrollTop`/`scrollLeft` 在 JS 垫片里恒为 0;
- 没有滚动条,Agent 与人都看不出「这里还有内容」。

结果:凡是用了 `overflow:auto` 的面板(筛选栏、聊天窗、代码块、表格容器),
超出部分**永久不可见** —— 这正是「显示不全」里最难自查的一类。

本轮把元素级滚动容器补成可滚动、可观测、可被 Agent 操作的一等能力。

## 二、本轮实施项总览

| 编号 | 主题 | 落点 | 状态 |
| --- | --- | --- | --- |
| F1 | `overflow:auto\\|scroll` 归一为**可滚动容器** | `style/values.rs::overflow_scroll` | 🆕 |
| F2 | 元素级滚动状态(运行时偏移) | `TabState::scroll_offsets` + `document::apply_scroll_state` | 🆕 |
| F3 | 布局:内容按偏移上移 + 越界裁剪 + 滚动条 | `layout/mod.rs` | 🆕 |

### F1 样式层

`overflow` 的归一从「一个布尔裁剪开关」拆成两个:

| 属性 | 含义 |
| --- | --- |
| `overflow_clip` | `hidden`/`clip`/`scroll`/`auto`/`overlay` 均裁剪(既有行为不变) |
| `overflow_scroll` | 仅 `auto`/`scroll`/`overlay` 为真 —— **可滚动容器** |

`overflow-x`/`overflow-y` 任一为可滚动关键字即置位(与裁剪开关同口径)。

### F2 运行时状态

滚动量沿用第 41~42 轮「运行时状态 → 临时解析树属性」的既有通路:

```
TabState.scroll_offsets: HashMap<String, f64>   // key = stable selector
        │
        ▼  Document::apply_scroll_state(...)
   临时解析树写入 data-lsm-scroll-top="<px>"
        │
        ▼  布局层读取该属性
```

**为什么不直接进 `form_values`**:滚动量不是表单值,语义不同;
沿用属性覆盖层可以复用「不污染 `tab.html`」这条铁律(内核私有标记,不入页面 HTML)。

### F3 布局

可滚动容器且**高度确定**时:

1. 内容按 `data-lsm-scroll-top` 上移(游标在子代布局前减去偏移);
2. 越界部分由既有裁剪链裁掉(`apply_group` 的 padding 盒裁剪 —— 裁剪矩形是
   **盒的 padding 盒**,与滚动无关,所以「内容移动、裁剪框不动」天然成立);
3. 内容真实高 = 可见高 + 偏移;超出盒高时:
   - 登记 `Layout::scroll_max[selector] = 内容高 - 盒内容高`(供工具层钳制);
   - 画**滚动条**:右侧竖条(轨道浅灰 + 拇指深灰),拇指高度按可见比例、
     位置按滚动比例。

**边界**:高度 auto 的容器不滚动(盒高随内容长,没有可滚空间)——
与浏览器一致。

### F4 工具动作

`control(scroll, params={selector, delta_y})` → **元素内滚动**;
`control(scroll, params={selector})`(不带滚动量)保持原语义「滚到视口可见处」。
两者共用一个动作、靠参数区分,**工具契约不变**。

返回:`{mode:"element_scroll", selector, scrollTop, maxScroll}`。

## 三、控件矩阵更新(容器与布局能力)

| 能力 | 状态 | 说明/边界 |
| --- | --- | --- |
| `overflow:hidden/clip` | ✅ | 只裁剪,不滚动(既有行为) |
| `overflow:auto/scroll` | ✅🆕 | 可滚动容器:内容按偏移上移 + 越界裁剪 + 滚动条 |
| 元素级滚动状态 | ✅🆕 | `TabState.scroll_offsets` → `data-lsm-scroll-top` |
| 元素级滚动条 | ✅🆕 | 右侧竖条(轨道 + 拇指),按可见比例与滚动比例定位 |
| 元素内滚动动作 | ✅🆕 | `control(scroll, selector=…, delta_y=…)` |
| 最大滚动量可观测 | ✅🆕 | `Layout::scroll_max`,动作返回 `maxScroll` |
| 元素级 `scrollTop`/`scrollLeft` 读写(JS) | ⛔ | JS 垫片仍恒为 0;水平滚动未建模 |
| `scrollIntoView` 跨嵌套滚动容器 | ⛔ | 只滚页面级视口 |
| 滚动条样式/自动隐藏 | ⛔ | 恒显(确定性优先),不做 macOS 覆盖式滚动条 |
| `overscroll-behavior` / 滚动吸附 | ⛔ | 未建模 |

## 四、显示异常排查映射

| 现象 | 优先检查 |
| --- | --- |
| `overflow:auto` 容器的内容被截断且看不到滚动条 | `style.overflow_scroll` 是否置位;盒高是否确定(`height:auto` 不滚动) |
| 内容整体上移但位置不对 | `data-lsm-scroll-top` 的偏移量;容器内容盒起点 |
| 滚动条位置不对 | `Layout::scroll_max` 与偏移比例;拇指高度 = 盒高 × 可见比例 |
| 元素滚不动 | 动作是否带了 `delta_y`;`maxScroll` 是否为 0(内容没超出) |
| 滚动后内容被裁掉一半 | 裁剪矩形是 padding 盒(既有语义),不是内容盒 |
