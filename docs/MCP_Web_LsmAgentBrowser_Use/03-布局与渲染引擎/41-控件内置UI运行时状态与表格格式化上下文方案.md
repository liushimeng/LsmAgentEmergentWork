# 41-控件内置 UI、运行时伪类状态与表格格式化上下文方案

## 背景

第 40 轮建立了「Web 控件全量能力矩阵」并打通了「表单运行时值 → 样式/布局 → 显示列表 → 像素」的垂直闭环。
本轮按《Web 端控件全量清单与渲染设计要点》的五大类渲染要点逐条比对内核现状,补齐**四类结构性缺口**:

1. **内置 UI 布局偏差**：`input[type=range|color|date|time|file|number]` 等控件在 `emit_form_control_text` 里落到
   `_ => {}` 分支,**完全不绘制**——页面上是一条空白边框,不是控件。
2. **状态重绘机制**：`checked/disabled` 已由属性覆盖驱动,但 `:hover/:focus/:focus-visible/:active`
   在两个选择器引擎里都**恒不匹配**(`style/selector.rs` 归入 `Pseudo::Never`,`script/env_js.rs` 直接 `return false`),
   交互态样式是**死代码**。
3. **浮层层级处理**：内核**没有 top layer**——`dialog[open]`、`select` 展开面板这类顶层浮层 UI
   与普通流内容同层竞争;`position:fixed` 子树也无法逃出祖先 `overflow:hidden` 的裁剪。
4. **列表与表格布局**：`list-style-type` 只区分 `none` 与「父标签是 ul/ol」,`list-style-position` 完全不存在;
   表格缺 `caption`/`colgroup`/`col`/`border-collapse`/`table-layout:fixed`/百分比列宽。

本轮目标:把上述四类缺口补到「有像素、有几何、有测试」的程度,并在文档中把**已实现**逐条标出,防止重复开发。

**基线与占位铁律**:内置 UI **只发射显示项,不改变控件盒几何**——控件盒尺寸仍由

否则相邻元素会因状态切换而抖动(见 F2「状态只重绘不重排」)。

### F2 运行时伪类状态

**机制选择:属性覆盖(与 `form_values` 同构)**。`TabState` 已有 `form_values` / `widget_open`
两套「运行时覆盖 → 临时解析树属性 → 样式引擎」通路,本轮沿用同一模式新增第三套:

```
TabState.pseudo_states: HashMap<String, PseudoFlags>   // key = 稳定选择器
        │
        ▼  Document::apply_widget_state(..., pseudo_states)
   临时解析树写入属性 data-lsm-hover / data-lsm-focus / data-lsm-focus-visible / data-lsm-active
        │
        ▼  style/selector.rs::pseudo_matches
   Pseudo::Hover 等变体读属性判定命中
```

- **为什么不用「样式引擎持状态表」**：样式引擎的 `computed()` 与选择器匹配都在**热路径**上,
  每次匹配都要由节点反查状态键会引入 O(深度) 的额外开销;属性覆盖把状态查找降到 O(1) 属性查表,
  且与 `:checked`/`:disabled` 的既有实现路径完全一致(可复用同一套 `apply_widget_state` 覆盖逻辑)。
- **为什么不污染 `tab.html`**：`apply_widget_state` 只改**临时 `Document`**,不回写源 HTML——
  `data-lsm-*` 是内核私有的运行时标记,不会被序列化回页面。
- **特异性**：`:hover`/`:focus`/`:focus-visible`/`:active` 按 CSS 规范计入**伪类列**(+1),
  不再落进 `Pseudo::Never` 的「零特异性」黑洞(现状 `a:hover` 特异性等同裸类型选择器,可被属性选择器压过)。

**交互入口**(`api.rs`):

| 动作 | 语义 | 是否触发重排 |
| --- | --- | --- |
| `control(hover=<selector>)` | 置 `hover` 态(并清掉旧的 hover) | 是 |
| `control(mouse_move, selector=…)` | 同上(按选择器移动指针) | 是 |
| `control(focus=<selector>)` | 置 `focus` + `focus-visible` 态 | 是 |
| `control(blur)` | 清 `focus` / `focus-visible` | 是 |
| `control(click=<selector>)` | 置 `hover` + `active`(点击语义) | 是 |

**「状态只重绘不重排」的落实**:状态变化走 `relayout_and_push`(全量重排 + 推帧),但
**控件占位尺寸与状态无关**——`inline_box_size` 的固有尺寸分支只读 `value`/`min`/`max`/`type`,
不读任何状态标记;`:hover` 样式即便改了 `border-width`,也只影响边框绘制宽度,
不改 `ElementBox.w/h`。这条铁律在本轮由单测 `伪类状态切换不改变控件占位尺寸` 固化。

### F3 表格格式化上下文增强

在 `layout/table.rs` 上补五项(其余算法不动):

| 能力 | 语义 | 状态 |
| --- | --- | --- |
| `caption` | 表格**上方**的标题块(居中、`caption-side: top` 语义),参与表格总高 | 🆕 |
| `colgroup`/`col` | `<col width>` / `<col style="width:Npx">` 指定列宽,优先级高于内容自适应 | 🆕 |
| 百分比列宽 | 单元格 CSS `width:30%` → 相对表格内容宽;与 `col` 百分比同解 | 🆕 |
| `border-collapse: collapse` | 相邻单元格共享边框(右/下边框由相邻格承担),消除双线 | 🆕 |
| `table-layout: fixed` | 列宽只由 `col`/首行单元格决定,**不再**被内容撑开 | 🆕 |

**列宽优先级**(本轮统一口径,与浏览器一致):

```
colgroup/col 显式宽度  >  首行单元格宽度  >  内容 max-content 自适应
```

`normalize_columns` 的「填满可用宽 / 超宽按比例缩」保持不变,只是输入列宽的来源更丰富。

### 交互入口(工具层 `control_action`)

| 动作 | 参数 | 语义 |
| --- | --- | --- |
| `hover` | `selector` | 置 `hover` 状态(清掉旧的 hover)→ `:hover` 命中 → 重排重绘 |
| `mouse_move` | `selector` 或 `x`/`y` | 带 `selector` 时等价于悬停该元素 |
| `focus` | `selector` | 置 `focus` + `focus-visible` 状态 |
| `blur` | `selector` | 清 `focus` / `focus-visible` |
| `click` | `selector` | 置 `hover` + `active` 状态(点击语义) |
| `open_dropdown` | `selector` | 展开 `<select>` 的浮层 option 面板(顶层绘制层) |
| `close_dropdown` | `selector` | 收起该面板 |

**JS 桥同步**:`script/env_js.rs` 的选择器引擎同步支持 `:hover`/`:focus`/`:focus-visible`/`:active`

`document.querySelector(':hover')` 与样式引擎口径一致。`el.indeterminate = true`
经 `set_attr`/`remove_attr` 回写宿主 DOM。

### F4 顶层(top layer)与浮层逃逸

CSS 的**顶层**(`top layer`)概念:`dialog[open]`、`popover` 等脱离常规层叠上下文,
**不受祖先 `overflow` 裁剪**,永远画在普通内容之上。本轮落地:

| 能力 | 语义 | 状态 |
| --- | --- | --- |
| `display: none` → 顶层 | `dialog[open]` 以 `position: fixed` 语义居中于视口 | 🆕 |
| `::backdrop` | 仅 `showModal()` 产生的模态标记(`data-lsm-modal`)铺半透明黑色遮罩;普通 `open` 是非模态 | 🆕 |
| 顶层绘制层 | `DisplayItem.layer` 扩展第三档 `2 = top layer`,排序键在定位层之上 | 🆕 |
| 裁剪逃逸 | `position:fixed` 子树与顶层项**不参与**祖先 `overflow:hidden` 的裁剪交集 | 🆕 |
| `select` 展开面板 | 展开态在控件下方铺浮层面板,最多列出 8 行 option(无滚动) | 🆕 |

**裁剪逃逸的实现**:`apply_group` 的裁剪交集循环里跳过 `it.fixed || it.layer >= 2` 的项。
`fixed` 标记已存在(`position.rs` 的 `fixed_depth` 机制),`layer` 已是 `u8`——
**不新增 `DisplayItem` 字段**,零显示列表结构变更。

## 三、显示异常排查映射(本轮更新)

| 现象 | 优先检查 |
| --- | --- |
| 滑块/颜色/日期控件是一条空白框 | `layout/widgets.rs` 是否命中 `input[type]` 分支;是否落进 `_ => {}` |
| `:hover` 样式完全不生效 | 状态是否进 `TabState.pseudo_states`;`apply_widget_state` 是否写入 `data-lsm-hover` |
| 状态切换后控件尺寸抖动 | `inline_box_size` 是否读了状态标记(不应读) |
| `dialog[open]` 被父容器裁掉 / 被内容盖住 | 是否走顶层分支;`layer` 是否为 2;祖先裁剪是否跳过顶层项 |
| `position:fixed` 浮层被 `overflow:hidden` 裁掉 | `apply_group` 裁剪交集是否跳过 `it.fixed` |
| 表格列宽不按 `col`/百分比 | `table.rs` 列宽优先级;`table-layout:fixed` 是否误吞自适应 |
| 表格相邻格边框是双线 | `border-collapse` 是否为 `collapse`;相邻格边框分配是否生效 |
| `caption` 不显示 | `table.rs` 是否收集 `<caption>`;是否被当作普通块丢弃 |
| 列表 marker 类型不对 | `list-style-type` 是否进了 `style.extra`;`layout/list_marker.rs` 类型映射 |
| `list-style-position: inside` 文字被 marker 压住 | `li` 子内容右移量是否生效 |
