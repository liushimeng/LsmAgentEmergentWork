# 47-行内块独立格式化上下文与行内片段盒方案

## 一、背景与根因(实测)

第 40~46 轮把「表单运行时状态 → 样式 → 布局 → 显示列表 → 像素 → 交互重排」的
垂直闭环打通,控件内置 UI、运行时伪类、顶层浮层、表格格式化上下文、列表 marker、
元素级滚动容器都已有像素与测试。第 44 轮补齐了**行内原子盒**(替换元素/表单控件
占宽、参与断行、按基线对齐)。

但复核《Web 端控件全量清单与渲染设计要点》第二节「行内 / 块级排版规则」与
第四节「盒模型精度」时发现:**行内排版还剩一整层没动** —— 普通行内元素与
行内块容器的盒模型。四类症状:

| # | 症状 | 实测(第 47 轮探针) | 根因 |
| --- | --- | --- | --- |
| 1 | 行内块包不住自己的内容 | `<span style="display:inline-block;width:60px">one two three…</span>` 的子代文本**漏进父行**,定位取 `flow_x.max(run.x)`,段中链接前的文字把 `flow_x` 推过盒左缘后,子代文本落到盒外 | 行内块的子代进**父级共享行内缓冲**,没有独立格式化上下文 |
| 2 | 行内块多行内容溢出盒外 | 同上,盒高恒为 `font-size × 1.45`(**一行高**),子代折行后整块溢出盒底 | 盒高来自 `inline_box_size` 的近似,不看内容 |
| 3 | 链接/标签背景画在行首 | `<p>Hello <a style="background:#f00">link</a> World</p>` 的红色背景整块盖在 **Hello** 上;多行链接只有第一行有背景 | 盒在**收集期**由 `emit_inline_box` 画在 `line_x`(行首),恒一行高 |
| 4 | 窄容器文字从第二行起逐字断行 | `<p style="width:80px">one two three four five six</p>` 折成 `"one two th"` / `"r"` / `"e"` / `"e"` … **每行一个字** | `flush_run` 的 `seg_w`(待入段宽)在断行后**未清零**,下一行拿上一行的累计宽当基数 |
| 5 | 断行在词中截断 | 修复 #4 后变成 `"one two th"` / `"ree four f"` / `"ive six"` —— 词被劈开 | 断行判定只有「字符累计宽」,没有词界回退 |
| 6 | `<br>` 是静默 no-op | `<div>a<br>b</div>` 的 b 紧接 a 不换行 | `<br>` 只在 `collect_inline_children`(嵌套进行内元素时)被识别;块容器直接子级走 `collect_inline` 入口,无 `<br>` 分支 |

#4 影响面最大:凡是宽度收窄的容器(侧栏、药丸标签、代码块、表格单元格、
卡片标题)里的文字,**从第二行起全部塌成单字竖排** —— 这是「显示不全」里
最难自查的一类,且长期被当作「站点自己的样式问题」。

本轮把这六条一次补齐,并把「已实现」逐条标出,防止重复开发。

### F1 行内块容器的独立格式化上下文

`display:inline-block` / `inline-flex` 是**行内级盒但建立独立格式化上下文**(BFC):
子代不得漏进父行,盒高由内容决定。本轮落地:

```
collect_inline(own_box 分支)
        │  is_inline_block_container(style)
        ▼
layout_inline_block_ctx_at(node, style, bx, by, cw, tf, depth)
        │  ① 预留盒视觉 seq(保证盒画在子代内容之下)
        │  ② 新建独立 InlineBuf + 独立 InlineRow
        │  ③ self.y = by;collect_inline_children(..., avail_w = cw)
        │  ④ flush_inline_floor(buf, cw, 8.0)   ← 换行下限 8px,不用常规行内的 80px
        │  ⑤ 内容底 = max(flush 游标, 独立行内浮动底)
        │  ⑥ 盒高 = 显式 height ?? 内容底 - by(再经 min/max-height 钳序)
        │  ⑦ 发射几何寻址盒 + 边框/阴影 + 背景/渐变
        ▼
      返回 (内容底, 盒高);全局游标**不**因盒高推进
```

**为什么全局游标不推进**:盒高由 `reserve_height` 经行盒的基线分解承担
(与第 44 轮行内原子盒、第 175 轮行内盒同口径)。再推一次会让段首凭空下沉
一个盒高 —— 本轮由单测 `行内块_段首不因盒高下沉` 固化(修复前实测文字下沉 23px)。

**换行下限为什么是 8px 而不是 80px**:`flush_inline` 的老下限是 80px
(`max_w.max(80.0)`),服务于「常规行内容器不会窄于 80px」的假设。行内块容器
按**盒内容宽**换行,60px 宽的药丸标签里的文字若按 80px 换行就会溢出盒外 ——
正是本轮要消灭的那类显示不全。故新增 `flush_inline_floor(buf, max_w, floor)`,
行内块路径传 `floor = 8.0`。

**浮动的行内块**:`layout_inline_float` 同样走独立上下文(百度地图搜索卡片的
`#content` 是 `display:inline-block` + 内部两个 `float:left`),盒高由内容底收编
(含内部浮动),`row.note_bottom` 同步占用账。

### F2 行内片段盒

CSS 2.1 §10.6.1 的**行内非替换元素**盒模型:

- 左右内边距只在**首末片段**各出现一次;
- 上下内边距**每段都有**,但**不影响行高**(行盒高度已由 `line-height` 决定,
  垂直内边距只是让背景上下溢出);
- 多行时**每行一段**,每段画完整四边(浏览器「逐行片段续画边框」语义)。

**机制选择:文本 run 携带属主(与 `text-shadow` 同构)**。

```
TabState 无新增;纯布局期机制
        │
        ▼  collect_inline_children(node, style, ...)
   inline_fragment_owner(node, style) → Option<InlineOwner>
        │  (普通行内元素 且(绘制了盒视觉 或 需要几何寻址))
        ▼
   InlineRun.owner: Option<InlineOwner>   (选择器 + 标签 + 计算样式快照)
        │
        ▼  commit_line(每段落逐个 segs 发射文本时)
   emit_inline_fragment(owner, x, w, text_top, line_height, first, last, tf)
        │
        ▼
   ElementBox(几何寻址) + push_border_and_shadow(旧五表) + emit_element_tf(显示列表)
```

**为什么不在收集期发射**:行盒的最终位置(行首 x、基线、是否换行)只有在
`flush_inline`/`commit_line` 之后才知道。此前在收集期发射,只能拿 `line_x`
当盒的 x、拿一行高当盒的高 —— 位置与高度双重错误。

**为什么用「属主快照」而不是「样式引擎持状态表」**:与第 41 轮运行时伪类
状态覆盖、第 44 轮行内原子盒的取舍一致 —— 状态由 run 携带,行提交期 O(1)
取用,不引入「节点反查状态键」的额外开销,也不污染 `tab.html`。

**属主命中条件**:`is_plain_inline(style)`(`display:inline` 且无显式尺寸)
且(`inline_paints(style)`(背景/背景层/边框/外阴影) **或** `inline_box_worthy`
(交互元素/带 id/显式尺寸))。命中失败的行内元素(纯 `<b>`/`<i>`)不携带属主:
它们不画盒、也不需要逐元素寻址。

**空行内元素**(0×0,无文本可挂片段)退回单盒路径 `emit_inline_box` ——
保住第 175 轮「空锚点仍发射寻址盒」的语义,行盒仍不产生。

**`emit_element_tf`**(F7):片段盒在**行提交期**才发射,此时元素自身早已离开
收集栈,祖先链变换只能由 `InlineRun::transform` 携带过来。新增
`emit_element_tf(seq, style, tag, x, y, w, h, inherited_tf)`,原 `emit_element`
委托为 `None` 调用,零行为变更。

### F3 断行后清零待入段宽

`flush_run` 的 `seg_w`(待入段宽)声明在字符循环**外**,断行后未清零 ——
下一行的判定 `line.flow_x - line.origin_x + seg_w + w > max_w` 会拿上一行的
累计宽当基数,于是**每行只放得下一个字符**。两处断行点(`'\n'` 与换行分支)
均补 `seg_w = 0.0`。

### F4 词界回退断行

字符源从 `for ch in run.text.chars()` 改为**可回插的队列**
(`VecDeque<char>`)。命中断行判定且非 `pre` 时:

1. 在 `seg_text` 里 `rfind` 最后一个空白(`k > 0`);
2. 截断到 `k`,尾段 `trim_start` 后**交还队列**;
3. 触发断行的那个字符**属于下一行**,排在尾段之后一并交还;
4. 按「尾段 + 本字符」的**逆序** `push_front`,保证队列顺序正确。

单个词长于容器宽时找不到空白 → 不回退,按字符硬断(与浏览器一致)。
`pre`/`nowrap` 不做回退(前者不换行,后者不断)。

### F5 `<br>` 作为块容器直接子级

`collect_inline` 入口补 `<br>` 分支(`collect_inline_children` 早有)。
`InlineBuf::force_break` 在**无 run 可追加**时插入一个只含 `'\n'` 的占位 run ——
否则行首 `<br>` 的换行被静默吞掉。

### 模块拆分(单文件 ≤ 1800 行规范)

`layout/mod.rs` 在第 41 轮拆分后一路增长到 **1872 行**(已超线),本轮再
+29 行。按规范把**自由辅助函数**这一簇机械搬进新子模块:

| 模块 | 职责 | 行数 |
| --- | --- | --- |
| `layout/helpers.rs`(新) | 几何防御性钳制、边框/阴影指令入队、标签类别判定、控件显示文本、高度钳序、相对偏移、外边距折叠判定 | 258 |
| `layout/mod.rs` | 结构体定义 + `LayoutCtx` + 布局主流程(本轮压回 **1658 行**) | 1658 |
| `layout/inline.rs` | 行内格式化上下文(本轮主战场) | 1366 |

搬移口径:代码**逐行原样搬运零改写**,仅新增模块文档头与 `use super::*;`;
`mod.rs` 以 `use helpers::*;` 重导入,外部 `crate::…::layout::X` 路径与兄弟
模块 `use super::*` 取用**零改动**。原私有项(`sanitize_layout_geometry`/
`resolved_border_colors`/`collapse_margin`/`contains_child_margins`)在子模块
标 `pub(super)`。

### F6 行内块 shrink-to-fit 宽度

`inline_box_size` 对 `is_inline_block_container` 的元素改用
`inline_container_max_content(node, style)`:沿 DOM 子树按**行内累加**
(文本按字号折算 / 替换元素取固有宽 / 显式宽直接采用 / 控件取
`inline_box_size` 口径 / 其余递归),**不铺开布局、不发射任何几何**。

此前取 `node.text_contents()` 的文本宽,漏掉图标/控件等兄弟盒 ——
猎聘行业 tab(图标 20 + 间距 8 + 文本)的盒宽少 28px,子代在盒内换行溢出。
`pen` 推进(供后续兄弟/浮动排布)与盒宽同源,不再各算一套。

**边界**:`inline-grid`/`inline-table` 在样式层被归一成 `grid`/`table`
(见 `style::values::normalize_display`),布局层无法识别,仍走老的单盒近似。

## 五、显示异常排查映射(本轮更新)

| 现象 | 优先检查 |
| --- | --- |
| 行内块(药丸/标签/图标+文字)的文字溢出盒外 | 是否走 `layout_inline_block_ctx_at`;`flush_inline_floor` 的 `floor` 是否被 80px 老下限盖过 |
| 行内块盒只有一行高,内容溢出盒底 | `inline_box_size` 是否仍按 `font-size × 1.45` 给高(应走内容高) |
| 行内块的 `pen` 推进与盒宽不一致 | `inline_container_max_content` 与盒宽是否同源 |
| 段首凭空下沉一个盒高 | 行内块路径是否**没有**推进全局游标(只 `reserve_height`) |
| 链接/标签背景盖住前一个词 | 是否仍走收集期 `emit_inline_box`(应走片段盒);`InlineRun.owner` 是否带上 |
| 链接背景只有一行高 / 多行时只有一行有背景 | `commit_line` 是否对每个 seg 都调 `emit_inline_fragment` |
| 链接上下内边距没让背景变高 | `box_h = padding_top + line_height + padding_bottom` |
| 链接垂直内边距把段落撑高了 | 行盒高度只由 `line-height` 决定(内边距不进 `commit_line` 的 ascent/descent) |
| 窄容器(侧栏/药丸/代码块)文字从第二行起逐字断行 | `flush_run` 断行后是否 `seg_w = 0.0`(第 47 轮前是存量 bug) |
| 折行把词劈成两半 | `flush_run` 的词界回退是否生效(`rfind(char::is_whitespace)`) |
| 折行丢字 / 字符重复 | 回插队列的顺序(「尾段 + 触发字符」按逆序 `push_front`) |
| `<div>a<br>b</div>` 不换行 | `collect_inline` 入口是否补了 `<br>` 分支 |
| 行首 `<br>` 被吞 | `InlineBuf::force_break` 无 run 时是否插入 `'\n'` 占位 run |
| 变换祖先里的行内元素背景位置错 | `emit_element_tf` 是否透传了 `InlineRun::transform` |
