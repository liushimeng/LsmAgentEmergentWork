# 22 - 专业渲染引擎重构设计与实现（显示列表架构 + 圆角/渐变/模糊阴影/透明度/溢出裁剪）

> 阶段六第一步。目标：把 LsmAgentBrowser 的渲染层从「五张平铺指令表 + 固定 z 通道」升级为
> **专业渲染引擎的显示列表（Display List）架构**，并补齐真实页面（反爬取证截图）视觉保真度
> 最关键的五项能力：`border-radius`、`linear/radial-gradient`、`box-shadow` 真高斯模糊、
> `opacity` 连续透明混合、`overflow:hidden` 内容裁剪。跨平台（macOS / Windows / Linux）零新增
> 系统依赖，保持离线可编译铁律。

## 一、背景与问题

现状（`render.rs`，fontdue + tiny-skia CPU 光栅化）：

1. **渲染数据模型是五张彼此独立的平铺表**（`shadows` / `boxes`(背景) / `borders` / `paints`(图片) /
   `lines`(文本)），渲染器按固定通道顺序整通道叠画：阴影→背景→边框→canvas 占位→图片→文字。
   任意两个元素的视觉层级关系被通道顺序绑架——后出现的兄弟元素背景永远画在先出现元素的
   边框/文字**之下**，重叠布局（卡片叠放、悬浮层）层级错误。
2. **视觉能力缺口**（均为现代 Web UI 高频特性）：
   - `border-radius`：不绘制（直角方块）；
   - `linear-gradient` / `radial-gradient`：样式层直接丢弃（`渐变暂不绘制`），整块区域退化为
     无背景/白块；
   - `box-shadow` 的 `blur`：解析后丢弃，渲染为「偏移+扩散实心矩形」，卡片阴影变成生硬色块；
   - `opacity`：只有 `>0` 的二值可见性，`0.5` 透明度渲染为完全不透明；
   - `overflow:hidden`：完全不裁剪，内容溢出父盒直接画出。
3. **绘制指令产出缺口**：flex 条目、grid 条目、absolute/fixed 定位元素的**边框与外阴影从未
   产出绘制指令**（`push_border_and_shadow` 只在块级/行内路径调用），这些元素上写的
   `border` / `box-shadow` 静默丢失。

## 三、总体架构

```
样式(style/)                布局(layout/)                    渲染(render/)
┌──────────────┐   ┌───────────────────────────┐   ┌─────────────────────────┐
│ ComputedStyle │──▶│ LayoutCtx(DFS 遍历)        │──▶│ rasterize()             │
│ +GradientSpec │   │  · 平铺五表(几何/寻址,保留) │   │  · 遍历已排序显示列表     │
│ +CornerRadius │   │  · DisplayItem 列表(新增)  │   │  · 逐项: 圆角/渐变/模糊/  │
│ +overflow_clip│   │    · (z, seq, rank) 排序键  │   │    透明度/裁剪/图片/文本  │
└──────────────┘   │    · 组效果 mark-回补        │   │  · 空列表回退旧管线      │
                   └───────────────────────────┘   └─────────────────────────┘
```

### 3.1 显示列表数据模型（`render/display.rs`）

```rust
pub enum DisplayKind {
    Background { fill: BgFill },               // BgFill::Solid([u8;3]) | BgFill::Gradient(Arc<GradientSpec>)
    Border    { widths: [f64; 4], colors: [([u8; 3], u8); 4] },
    Shadow    { dx, dy, blur, spread, color }, // blur 真实生效(不再近似 0)
    Image     { src, fit, off_x, off_y },
    Text      { text, size, color, bold },
    CanvasNote,                                 // canvas 占位说明块
}
pub struct DisplayItem {
    pub kind: DisplayKind,
    pub x: f64, pub y: f64, pub w: f64, pub h: f64,   // 页坐标(border box)
    pub radius: [CornerRadius; 4],                     // tl/tr/br/bl
    pub z: i64,          // z-index(与旧语义一致:同上下文内按 z 分层)
    pub seq: u64,        // DFS 先序序号(同 z 内恢复 DOM 顺序)
    pub rank: u8,        // 同元素同 seq 内的通道序: Shadow0<Bg1<Border2<Image3<CanvasNote4<Text5
    pub opacity: f64,    // 自身×祖先组透明度(发射期折叠)
    pub clip: Option<ClipRect>,  // 祖先 overflow:hidden 链的交集(发射期折叠)
}
```

设计要点：

1. **自包含绘制项**：每项自带透明度与裁剪（祖先链在布局发射期**折叠**进项内），光栅化器
   无需树结构、无需压栈——这是把「组效果」塞进平铺模型的经典手法（SVG/Skia deck 同构）。
2. **三元排序键 `(z, seq, rank)`** 一次稳定排序得到正确绘制序：
   - `z` 分层（沿用现有 z-index 语义）；
   - `seq` = 元素 DFS **先序**进入序号（块级分支进入时分配；文本行在 flush 时取新 seq，
     与「文本晚于其前面的块级兄弟、早于其后面的块级兄弟」的本引擎 flush 时机精确吻合）；
   - `rank` 保证同一元素的 shadow→bg→border 按序、文字盖在自身背景上。
3. **平铺五表保留不动**：`boxes/rect_map/inspect` 继续服务几何寻址与坐标点击；显示列表只
   服务「画」。两套模型各司其职（真实引擎同样是 layout tree 与 display items 分离）。

### 3.2 组效果的 mark-回补（retro-patch）

块级 / flex / grid / absolute 元素布局完成后（高度已知）：

```text
mark = display.len()            // 元素子树发射前记下
<递归布局子树>(子树项陆续入表)
apply_group(mark, style, 盒矩形):
    if style.opacity < 1.0  → display[mark..].opacity *= style.opacity   // 子树整体透明
    if style.overflow_clip  → display[mark..].clip ∩= padding 盒矩形      // 子树整体裁剪
emit_element(seq, style, tag, 盒矩形)   // 自身 shadow/bg/border/canvas,不含自身 clip(背景边框不裁自身)
```

- 自身背景/边框**不受自身 overflow 裁剪**（CSS 语义：overflow 裁内容不裁自身框），
  自身透明度**直接乘入自身项**（发射时 `opacity = style.opacity`）。
- 嵌套自然复合：内层组的回补作用于已含外层效果的快照之上。
- 延后处理的 absolute/fixed 子树在**父级块分支退出前**完成注入（`layout_deferred` 在
  `layout_children` 尾部执行），落在 mark 区间内，照常被回补覆盖。
- 已知近似（记录在案）：跨 z-index 的裁剪（子项 z 高于组主 z 时按 CSS 会脱离该组裁剪，
  本实现仍裁剪——安全方向：多裁不漏画）；组透明度逐项近似而非真离屏合成（重叠子项
  交叠处略有偏差）。

### 3.3 新绘制能力

| 能力 | 实现要点 |
| --- | --- |
| `border-radius` | 样式层解析简写（1-4 值 + `/` 椭圆取水平半径 + `%`），`CornerRadius::{Px,Pct}`；光栅化按盒尺寸归一（`r ≤ min(w,h)/2`，`Pct × min/2`）。背景/边框/阴影/裁剪共用同一套圆角几何；手写圆角矩形逐像素填充（凸区域逐行精确跨度，天然支持任意矩形裁剪交，不依赖 tiny-skia 的 mask 能力）。 |
| `linear-gradient` / `radial-gradient` | 样式层新增 `style/gradient.rs`：解析 `-webkit-` 前缀、`to <side>` 关键字与 `Ndeg` 角度（CSS 标准：0deg=向上、顺时针）、色标（`#hex/rgba/named [pos%]`、双位置语法、缺省均匀分布）、`radial-gradient(circle/ellipse [size] [at center])`（size 近似为 farthest-corner / farthest-side，位置非 center 近似为 center）。光栅化自绘（线性：像素在梯度线上的投影参数 t；径向：归一距离），sRGB 直插值 + Pad 钳位，与逐项透明度/裁剪同一代码路径。`repeating-` 前缀按普通渐变处理（Pad 近似）。多背景层取首层。背景色与渐变同写时按 CSS 语义色在渐变下（两条目同 seq 同 rank，发射序保证）。 |
| `box-shadow` 真模糊 | 阴影 alpha 蒙版（圆角矩形含 spread 扩张 + dx/dy 偏移）→ **三趟盒式模糊近似高斯**（σ = blur/2，滑动窗口 O(n)）→ 按颜色 alpha × 项透明度着色合成。蒙版像素总量与模糊半径设上限（4M px / 48px），超限退化为实心近似（现行为），杜绝超长页面内存/耗时失控。多层阴影逐层独立绘制。 |
| `opacity` | `0 < opacity < 1` 连续透明：逐项 alpha 乘法（实心填充、字形 coverage、图片采样、阴影蒙版四条路径全打通）；组透明经 mark-回补折叠（见 3.2）。 |
| `overflow:hidden` | 解析 `overflow/overflow-x/overflow-y`（hidden/clip/scroll/auto 均裁剪）→ 组裁剪矩形（padding 盒）→ 逐项 scissor（与视口边界再取交）。 |
| flex/grid/absolute 边框阴影 | `emit_element` 统一发射器覆盖全部建盒点（块级/行内/替换元素/flex 容器与条目/grid 容器与条目/absolute/fixed），修复这些路径边框与阴影静默丢失的缺口。 |

### 3.4 渲染层文件拆分（≤1800 行规约）

```
render.rs(789 行) → render/
  mod.rs        FontSet + render/render_pixmap 入口 + crop_pixmap + is_image_path + 再导出
  display.rs    DisplayItem/DisplayKind/BgFill + 排序键 + build_legacy(旧管线回退合成器)
  raster.rs     光栅化主体(圆角填充/渐变求值/边框环带/阴影蒙版/图片/文本) + scissor 工具
  blur.rs       三趟盒式模糊(近似高斯)
  tests.rs      原 render.rs 全部单测搬迁对账 + 新能力像素断言
```

**兼容性回退**：`render_pixmap` 优先消费 `layout.display`；显示列表为空（手构 `Layout`、
旧调用路径）时由 `build_legacy` 从五张平铺表**按旧通道顺序**合成显示列表，输出与重构前
逐像素一致——既有单测（含手构 `Layout` 的图片测试）与集成测试零改动通过。

**对外 API 零变化**：`FontSet::render/render_pixmap`、`crop_pixmap`、`MCP_Web_LsmAgentBrowser_Use`
兼容层、查看器帧协议、截图取证路径全部不动。

## 四、跨平台与性能

- 零新增 crate、零系统依赖：全部能力落在现有 tiny-skia / fontdue / 自研代码上，
  macOS / Windows / Linux 渲染结果逐像素一致（软件光栅化的固有优势）。
- 模糊/渐变均为 O(像素) 且带硬上限；圆角填充是逐行跨度解析（凸区域解析解），无逐像素
  三角函数。typical 页面（数百项）全页光栅化在既有耗时量级内。
- 字体：维持单字体 + 双重绘制加粗近似；文本整形（复杂文种/连字）列路线图。

## 六、边界与路线图

**本轮明确不做**（记录原因，防止误判为缺陷）：2D/3D `transform` 光栅化（平移类已由定位层
吸收）、`text-shadow`、多背景层、椭圆（双半径）圆角、斜切圆角、组透明度真离屏合成、
`backdrop-filter`、canvas/WebGL、GPU（wgpu）后端、文本整形、增量（脏矩形）光栅化。

**路线图**（按收益排序）：显示列表 diff + 脏区域局部重光栅 → GPU 后端 feature 门控
（wgpu offscreen → readback，显示列表架构不变）→ 文本整形与字体栈 → transform 矩阵
逐项仿射 → 增量布局脏标记。
