## 二、根因(三条,互相独立)

### 根因 A(核心):`getElementsByTagName` 返回静态数组,不是浏览器的**实时集合**

真实浏览器的 `getElementsByTagName` 返回**活集合**(live `HTMLCollection`):
取到集合 → 改 DOM → 再读集合,内容随之变化。

Lsm 的 DOM 桩返回**一次性数组快照**。百度地图的 CSS 注入器
(`/wolfman/static/common/js/libs/mod_5dbb339.js` 的 `require.loadCss` → 内部函数 `n(e)`)
恰好依赖这个语义:

```js
function n(e){                                   // ← 栈帧 at n (eval at :1:18080)
  var t=document, r=e, i=u, n=i.getElementsByTagName("style");
  if(0==n.length) {                              // ← 快照期 head 里还没有 <style>(宿主动作还没回写)
    var a=t.createElement("style"); a.setAttribute("type","text/css"); i.appendChild(a);
  }
  var o=n[0], s=o.getAttribute("media");         // ← n 是静态数组 → o === undefined → TypeError
  ...
}
```

Lsm 里 `n` 是数组快照,`appendChild` 之后 `n[0]` 仍是 `undefined`
→ `o.getAttribute("media")` 抛 `TypeError` → `dataCopyRight` 模块工厂失败
→ `setCurCity → init → setStatus` **整条地图初始化链断掉**
→ 地图面不出图、路线面板不出、页面只剩搜索框。

**证据(逐层核对)**:
- 栈:`at n (eval at :1:18080)` → `at <main> (eval at :1:19864)`(= `require.loadCss` 里的 `n(e.content)`)
  → `at <main> (eval at :4:632)`(= `ctrl-pkg_f8e331f.js` 第 4 行的 `dataCopyRight` 模块体 `a.loadCss({...})`)。
- 偏移核对:`mod_5dbb339.js` 里 `function n(e)` 在 **18060**,`require.loadCss` 在 **19792**,
  `n(e.content)` 在 **19856 / 19882**;`ctrl-pkg_f8e331f.js` 第 4 行整行就是 `dataCopyRight` 模块体(4516 字符)。
- **Boa 的报错文案有歧义**:`undefined.foo()` 与 `Object.keys(null)` **同一句**
  `cannot convert 'null' or 'undefined' to object`。所以上一轮把它记成「ToObject 错误」是误判;
  实测确认这里读的是 `undefined` 上的属性。`LAEW_JS_TRACE_TOOBJ` 开关(只包内建函数)因此定位不到,
  本篇一并把它改成「**只在真抛错时记录 + 带 JS 栈**」(此前是「调用即记」,压缩脚本里
  `Object.create(null)` 这类正常调用一轮刷 300+ 条,把真正的抛错点挤到采集上限之外)。
- 复现:页面**加载完成后**再 `eval_js require.loadCss({content:'body{color:red}'})` 返回 `ok`
  —— 因为那时 head 里已经有 `<style>`,走不到崩溃分支;只有**首屏管线期**(宿主动作尚未回写)才炸。

### 根因 B:布局引擎的**视口高度写死 720**

`MediaCtx::new(width, 720.0)` 在 **8 处**把视口高度写死成 720:

```
src/agent/browser/api.rs:227 / 373 / 607
src/agent/browser/mod.rs:689 / 727 / 993 / 1025 / 1334
```

`MediaCtx.viewport_height` 一路流到 `LayoutCtx.viewport_h`(`layout/mod.rs:207`),
`height:100%` / `100vh` / `@media (max-height)` 全部按 720 解析。

后果(实测):视口 1920×1080 时,`#MapHolder` 高度算成 **720**(而不是 1080)
→ 页面底部 360px 全空白(**显示不全**);`page_height` 报 757.4 而不是 1080;
BMap 读 `clientHeight` 拿到 720,按 720 铺图,再叠一层尺寸错。

### 根因 C:运行时注入的 CSS **落不了地**

`document.createTextNode()` 产出的是普通对象 `{nodeType:3, textContent, data}`;
快照元素的 `appendChild` 只对「detached 元素」和「快照节点」推宿主动作,
**文本节点两个分支都不落** → `require.loadCss` 注入的 CSS 到不了宿主 DOM
→ 站点动态样式全丢(**布局混乱**)。

落地动作用的是**新增的 `append_text`** 而不是 `set_text`:浏览器的
`appendChild(textNode)` 是**追加**,而 `set_text` 的语义是「把元素子节点整体换成
一个文本节点」——用它落地会误删元素原有内容。

### 设计约束

- **零新依赖**:活集合用 `Proxy`(Boa 0.22 支持 `get/has/ownKeys/getOwnPropertyDescriptor` +
  `Symbol.iterator`;同仓库 `__mkStyle` 已在用同一手法)。
  「length」在 Proxy 目标数组上是非配置自有属性,报成 `writable:true` 才满足 Proxy 不变式。
- **向后兼容**:活集合的 Proxy 目标是数组,`Array.isArray` 仍为 `true`;
  拿不到 `Proxy` 时**回退成普通数组快照**(老行为,不崩)。
- **只改内核语义,不改工具契约**:`action`/`control_action`/`info`/参数/信封一律不动
  (唯一的 schema 变化是删掉一个本就无效的 `auto_expand_viewport`)。

## 五、遗留(内核边界,不在本轮范围)

- **canvas 像素绘制**:Lsm 的 `canvas.getContext('2d')` 是**空实现**(`prelude.rs:__mkCanvas2d`),
  矢量笔画(路线折线、POI 标注)画不出像素;栅格瓦片是 `<img>`,能画。
- **百度地图底图 = WebGL 专用**:站点侧 `initmap_a678ab3.js` 的能力判定是
  `aA.ifEnableWebGLMap()`(要 `window.WebGLRenderingContext` + `getContext('webgl')` 成功)
  与 `aA.ifEnableCanvas2dMap()`(**恒返回 false**)。Lsm 无 WebGL → 站点**没有任何可用渲染器**
  → 底图必然留空(只画出站点自己叠的 DOM 控件)。
  **这不是内核 bug,是 GPU 后端缺失**;因此本轮的核心交付是「**如实告知**」(D1),
  让 Agent 一次性切到 `MCP_Web_Chrome_Use`,而不是对同一片空白反复截图重试。
- **路线面板未在 Lsm 侧打开**:点「路线」按钮后,FIS 的 `require.async` 确实把路线模块取回来了
  (网络台账里出现 `route-icon_41d3af5.png` / `route_3e6e18f.png` 图标请求),
  DOM 动作账本里也出现 `ul > li:nth-of-type(2)` 的样式写入,
  但最终快照里仍看不到 `公交/驾车/步行/骑行` 那一行。属于路线 widget 的 DOM 落地路径问题,
  与本轮三条根因独立,留作下一轮专项。

## 七、给后续的提示

1. **Boa 报错文案有歧义**:`undefined.foo()` 与 `Object.keys(null)` 同句。
   以后在 Boa 里看到 `cannot convert 'null' or 'undefined' to object`,
   **先怀疑「读 undefined 的属性」**,再怀疑 ToObject。
2. **压缩站点脚本的报错定位**:`LAEW_JS_TRACE_TOOBJ=1` 现在只在真抛错时打印并带 JS 栈,
   可以直接照着栈里的 `eval at :行:列` 去对应脚本文件按偏移核对
   (本篇就是这么把 `mod_5dbb339.js:18060` 和 `ctrl-pkg_f8e331f.js` 第 4 行对上的)。
3. **DOM 动作账本**:`LAEW_DOM_TRACE=1` 打印每轮 JS→DOM 动作,
   排查「模块跑了但 DOM 没了」先看账本里有没有对应的 `append_html`/`set_text`,
   再看宿主动作是否落地。
