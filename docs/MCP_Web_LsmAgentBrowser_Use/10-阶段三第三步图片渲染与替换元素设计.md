# 阶段三第三步:图片渲染与替换元素设计

> 本文是 `07-全功能浏览器能力矩阵与后续阶段实施方案.md` 中 **Phase 3** 的第三轮落地设计。
> 本轮交付:**图片子资源加载器(宿主预取 + 解码 + 全内存缓存)+ 替换元素(`<img>`)排版
> + `object-fit` 渲染 + `background-image` 基础绘制**。
> 原生窗口、overflow 裁剪、区域截图在后续轮次按 08/09 号文档预留接口落地。
>
> 状态标记:✅ 本轮实现;🟡 部分实现/有边界(边界逐条列出);⏳ 未实现(后续轮次)。

## 一、目标与范围

Agent 场景的痛点(承 09 号文档):商品图、封面图、头像、二维码、验证码图片构成页面
的绝大部分可见面积。此前内核**完全不加载图片**——`inspect(elements)` 的矩形里没有
图片,截图里图片位置是空白,坐标点击落在图片上等于点空。

本轮目标:

1. **资源层**:新增 `browser/images.rs`,宿主预取 `<img src>` 与 CSS `url(...)` 背景图,
   复用主文档网络栈(Cookie/重定向/SSRF/TLS 策略一致),解码为 RGBA8 **全内存**缓存;
2. **样式层**:`ComputedStyle` 增加 `object-fit` 与 `background-image`,级联与
   `getComputedStyle` 全程可见;
3. **布局层**:`<img>` 作为**替换元素**参与排版(固有尺寸、HTML 属性宽高、CSS 宽高、
   宽高比推导),块级/行内/Flex/Grid 四条路径都能成盒;
4. **渲染层**:按 `object-fit` 语义把解码结果贴进目标矩形(双线性采样),背景图与内容图
   分层绘制;
5. **契约不变**:`MCP_Web_LsmAgentBrowser_Use` 的 action/参数/信封/错误码零改动;观测只在既有维度
   (`image_urls` / `elements`)上做**增量**补充。

非目标(明确不做):`srcset` 多候选、`picture`/`source` 媒体查询、SVG 矢量渲染、
CSS 渐变背景、`image-set()`、图片懒加载占位骨架、`<canvas>` 位图、EXIF 方向、
渐进式 JPEG 解码、色彩管理。

## 二、资源层设计(`browser/images.rs`)

### 2.1 数据结构

| 类型 | 职责 |
| --- | --- |
| `DecodedImage` | 解码结果:`width`/`height` + `rgba: Vec<u8>`(行优先 RGBA8) |
| `ImageStore` | `HashMap<绝对URL, Arc<DecodedImage>>`,随标签页生命周期存在 |
| `ImageSizes` | `HashMap<绝对URL, (f64,f64)>`:布局期只读的固有尺寸索引 |
| `LoadedImage` | 单张图片台账:字节数、状态码、宽高、是否 `data:` 内联 |
| `ImageLoadOutcome` | 一次加载的产出:store + sizes + 网络台账 + console + 跳过原因 |

`ImageStore` 挂在 `TabState.images` 上;`ImageSizes` 由 store 派生
(`ImageSizes::from_store`),视口变化重排时直接复用,不必重新解码。

### 2.2 收集规则

| 来源 | 规则 |
| --- | --- |
| `<img src>` | 相对地址按页面最终 URL 解析;`http/https/data:` 才发起加载;去重保序 |
| `<style>` 文本 | 抽取 `url(...)`(去引号),相对地址按页面 URL 解析 |
| 内联 `style` 属性 | 同上 |
| `srcset` / `picture` | ⏳ 本轮不解析(见边界) |

`data:` 图片直接本地解码(`base64` 与百分号编码两种),不发网络请求。

### 2.3 加载与限额

- 复用 `net::HttpClient`(同一套 Cookie Jar / 重定向 / SSRF / TLS 宽松策略);
- 单图字节上限默认 12MB(`LAEW_WEB_MAX_IMAGE_BYTES`),单页图片数默认 48
  (`LAEW_WEB_MAX_IMAGES`),单页总字节 48MB,单图像素上限 40MP(解码炸弹防护);
- **单页图片加载总预算默认 20 秒**(`LAEW_WEB_IMAGE_BUDGET_MS`):预算耗尽即跳过
  剩余图片(避免多图/坏链站点拖垮导航),单图超时取"参数上限 / 预算剩余"较小值;
- `Content-Type: text/html` 的响应判为错误页,跳过解码;
- 解码失败(格式不支持/超限)只记 console 警告,**不阻断页面**;
- `LAEW_WEB_IMAGES=off` 关闭图片加载(页面照常打开,只是没有图)。

### 2.4 加载时机

| 时机 | 行为 |
| --- | --- |
| `open` / `navigate` | 主文档 → 外链样式 → 页面脚本 → **图片预取** → 布局 |
| 页面脚本回写 DOM 后 | 比对已有缓存,**只补抓新增图片**并重排(JS 动态插入 `<img>` 也能出图) |
| 视口变化 | 复用已有 `ImageSizes` 重排,不重新下载 |

> 顺序说明:图片放在脚本之后预取,是为了拿到**脚本改写后的最终 DOM**;
> 代价是脚本里同步依赖图片尺寸的场景仍按 0 尺寸参与首次布局(浏览器会等图片加载)。

## 三、样式层设计

| 属性 | 计算值 | 说明 |
| --- | --- | --- |
| `object-fit` | `fill`(默认)/`contain`/`cover`/`none`/`scale-down` | 非法值回落 `fill`;非继承 |
| `background-image` | `Option<String>`(URL 原文) | 只取单个 `url(...)`;`none` → `None`;非继承 |

两者都进入 `to_map()`,`getComputedStyle` 与 `inspect(include_style=true)` 可见。

背景图 URL 在**布局期**才解析成绝对地址(样式层不感知页面 URL),与 `<img src>` 共用
同一套解析规则。

## 四、布局层设计

### 4.1 替换元素尺寸规则

```
w = CSS width  ??  HTML width 属性  ??  固有宽
h = CSS height ??  HTML height 属性 ??  固有高
只给一个维度时,按固有宽高比推导另一个(固有尺寸未知时不推导)
```

固有宽高来自已解码图片(自然尺寸);未加载图片宽高为 0(与浏览器"未加载无固有尺寸"一致)。

### 4.2 四条排版路径

| 路径 | 处理 |
| --- | --- |
| 块级流(块容器的直接子节点) | 独占一行:清空行内缓冲 → 成盒 → 推进游标 |
| 行内流(段落/行内元素内) | 成盒 + **预留行高**(占位 run 撑开所在行);x 取行首(不参与行内推进,见边界) |
| Flex 条目 | 基准主尺寸取固有宽;绘制按**最终条目尺寸**(grow/shrink/stretch 之后) |
| Grid 条目 | max-content / min-content 走固有宽;绘制按最终网格区域 |

### 4.3 绘制指令(`PaintBox`)

布局层不持有像素,只产出绘制指令:

```rust
pub struct PaintBox {
    pub src: String,      // 绝对 URL(缓存键)
    pub x: f64, pub y: f64, pub w: f64, pub h: f64,  // 目标矩形(页坐标)
    pub fit: String,      // object-fit
    pub kind: PaintKind,  // Content | Background
    pub visible: bool,
    pub z_index: i64,
}
```

- `Layout.paints` 收集全部绘制指令;绘制序 = `z-index` 稳定排序,同 `z` 时
  **背景图先于内容图**;
- 未解码的图片不产出绘制指令(渲染层按缓存键查不到即跳过);
- 背景图的绘制矩形 = 元素盒(背景色之上、文字之下),`fit` 固定 `cover`。

## 五、渲染层设计

### 5.1 `object-fit` 语义

| 取值 | 绘制矩形 | 说明 |
| --- | --- | --- |
| `fill`(默认) | 目标矩形 | 拉伸铺满(忽略宽高比) |
| `contain` | 等比内缩居中 | 完整可见,留白 |
| `cover` | 等比放大居中 | 铺满目标盒,超出部分裁剪 |
| `none` | 原始尺寸左上对齐 | 超出部分裁剪 |
| `scale-down` | `none` 与 `contain` 取小 | 原始尺寸能放下就不放大 |

裁剪区恒为**目标盒**;绘制矩形与目标盒求交后逐像素采样。

### 5.2 采样与混合

- 双线性采样(源坐标为像素中心偏移的连续坐标),避免放大时的锯齿;
- 源像素按直通 alpha 与目标像素做 src-over 混合(与既有字形混合路径一致);
- 绘制顺序:元素背景色 → 图像(背景图 + 内容图) → 文字;
  文字在图像之上,避免内联图片压住正文。

### 5.3 绘制指令来源

| 来源 | 说明 |
| --- | --- |
| `<img>` | 元素内容盒(去掉 padding) |
| `background-image` | 元素盒(背景色之上) |

## 七、已知边界(🟡)

1. **行内图片不参与行内推进**:x 取行首,同行后续文字会与图片重叠(行内盒模型本身
   仍是简化实现);
2. **`srcset` / `picture` / `<source>` 不解析**:只取 `<img src>`;
3. **背景图只取首个 `url()`**:多背景与渐变丢弃;CSS 背景图按"全页收集"预取,
   可能加载实际被覆盖的背景图(有数量上限兜底);
4. **无 `alt` 文本占位**:图片加载失败不画破图图标;
5. **不解码 SVG**:SVG 走 DOM 可见但无矢量渲染;
6. **无动画/过渡**:`object-fit` 变化不产生过渡;
7. **首屏图片尺寸为 0**:脚本内同步依赖图片尺寸的场景,首次布局按 0 参与
   (图片预取在脚本之后);
8. **解码阻塞导航**:图片预取在导航路径内同步等待(单图 15s 超时、总量上限与
   20s 总预算兜底);
9. **EXIF 方向不处理**:带旋转标记的 JPEG 按原始像素方向绘制;
10. **无色彩管理**:不做 ICC 转换。
