# 16 · JS 桥元素几何属性与渲染整像素对齐

**日期**:2026-10-21 · **背景**:百度地图路线规划任务实测(`laew --debug -f`,Dir04)。
上一轮(R1-R12,见 `14-有头帧查看器与真实站点JS启动链路修复.md`)修通了 BMap 全局与
静态层;本轮接续修 widget 层(搜索框/路线面板)启动链路,并顺手根治 main 上
screenshot 测试的 debug 断言回归。

## 一、问题

### P1 JS 桥读不到元素几何(widget 层启动中断)
页面脚本 `el.clientWidth/clientHeight/offsetWidth/offsetHeight/scrollWidth/
scrollHeight/offsetLeft/offsetTop/clientLeft/clientTop` 与
`el.getBoundingClientRect()` 在 JS 桥(PRELUDE `__mk`)上全部 undefined/全零。
实测百度地图:BMap 初始化读容器 `#MapHolder.clientWidth` → undefined → NaN 在
初始化链深处传播 → 某处对 undefined 派生值取属性 → Boa `to_object` 抛
`TypeError: cannot convert 'null' or 'undefined' to object` → 异常穿透 AMD 装载器
(getjsmods 返回的 requirejs 本体接管 `define` 后,工厂异常不打断继续上抛)→
`define('tangram', factory)` 级联中断 → statCode/init/searchBox 等 widget 模块
永不注册 → 页面停留在初始 HTML 骨架(路线面板、结果面板全无)。

### P2 debug 构建下截图 panic(tiny-skia hairline 断言)
`explore_批量观测与截图落盘` 在 `cargo test`(debug)稳定 panic:
`tiny-skia/src/scan/hairline_aa.rs:124 debug_assert!(false)`。
根因:亚像素定位的 1px 宽绘制条(实测 x=91.476562、宽恰 1.0)经 tiny-skia
FDot16 抗锯齿取整后 `right - left == 0`,`LengthU32::new(0)` 拒绝 → 断言
(release 编译掉断言,表现为静默丢绘)。

## 二、方案

### F1 快照携带布局矩形
- `document.rs::SnapshotNode` 增加 `rect: Option<(x, y, w, h)>`,`to_json` 增发
  `rect` 键;
- `snapshot_nodes_inner` 增加 rects 参数(选择器 → 矩形映射),新公开方法
  `snapshot_nodes_with_rects(viewport, rects)`。

### F2 Layout 全量矩形映射
`layout/mod.rs::Layout::rect_map()`——与 `rect_for` 同源,`boxes` 按
`ElementBox.selector` 建映射。

### F3 管线前预布局
`open`/`navigate` 在 `run_pipeline` 之前对(样式内联后的)HTML 跑一次
`layout::compute_full`(空 `ImageSizes`):容器 CSS 定宽场景不依赖图片固有尺寸,
预布局足够供 JS 桥几何;管线后仍有正式布局(含图片)供渲染。

### F4 管线与交互路径统一注入
- `script/mod.rs::run_pipeline` 每轮快照用 `snapshot_nodes_with_rects`;
- `api.rs` 三处(eval/dispatch/其余 refresh)用 `tab.layout.rect_map()`
  (动作应用后 `mod.rs` 会重算 tab.layout,交互期几何保持新鲜)。

### F5 PRELUDE 几何属性
- `__mk`:rect 存在 → 六个宽高属性取整值、offsetLeft/Top 取坐标、clientLeft/Top=0、
  `getBoundingClientRect` 返回真实矩形;`html` 无 rect 时兜底视口宽高
  (真实浏览器 `documentElement.clientWidth` 语义);
- `__newEl`(未挂载):全 0——与 `display:none` 语义一致。

### F6 渲染整像素对齐(修 P2)
`render.rs` 背景/边框/阴影三处 `fill_rect` 输入经 `fill_snap()`(f64 →
`v.round() as f32`)对齐。绘制语义不变(亚像素 AA 损失对 1px 边框不可辨),
彻底规避 FDot16 取整出 0 宽/高的路径。

## 三、验证
- 集成测试 `js渲染_元素几何属性可读_定宽容器`(web_use_engine):mock 页
  300×200 定宽容器 + 绝对定位盒子,页面脚本读 clientWidth/clientHeight/
  getBoundingClientRect 经 `setAttribute` 持久化,eval_js 断言 300/200/120/40,
  且交互期读 clientWidth 同样命中矩形;
- `cargo test` 全绿(lib 2292 / web_use_engine 16 / 其余集成全过),
  含原先 panic 的 `explore_批量观测与截图落盘`;
- 真实站点探针:`#MapHolder.clientWidth = 1264`(修复前 undefined)。
