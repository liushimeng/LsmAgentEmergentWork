# 任务锚点(TaskAnchor)与防目标漂移——设计与解决方案

> 跨角色机制(输入层 / Yolo / Main-Work / 工具 / QC 五处联动),不属于单一工具范畴,
> 故独立成文;`docs/MCP_Web_Use/01-设计与解决方案.md` §17 只保留工具侧视角并互引。

> 详细方案原稿(根因分析 / 双层防御 / 实施顺序):`tmpPlan/2026-09-24_03-任务锚点与防目标漂移根治方案.md`

## 1. 一句话总览

把用户原文里的目标标识(URL / 域名 / 路径 / 应用名)**机械抽取**成**任务锚点**,
跨五层强制,**宁可失败,不可替换**——用户原话「**可以失败,不可以乱跑**」是本设计的取舍锚点。

```text
用户原文
   │
   ├─[L0 输入保真] 粘贴窗口加宽(15/2/8 ms → 40/3/20 ms)+ prompt_lines/prompt_chars 提交留痕
   │
   ▼
TargetAnchor::extract_from_text() / extract_from_context()       ← 纯函数,正则,零 LLM 成本
   │  hosts=[anthropic.com]  raw_urls=[…]  unresolved_reference=false
   │
   ├─[L1 决策门]  Yolo `target_status="unresolved"` 或 机械通道命中「指代 + 零主机」
   │              → OrchestrationOutcome::DirectAnswer,回问用户,**不进 WorkFlow**
   │
   ├─[L2 编排门]  Main-Work 第六条约束 + `plan_validate.rs` 澄清单元阻断
   │              (DAG 单元无法暂停等待用户,拆了必被秒级打回)
   │
   ├─[L3 工具门]  MCP_Web_Use action=open/navigate/new_tab 显式 URL 越界 → code=6001
   │              + 存活页面提示锚点化:非 anchor 页面标 ⚠ 禁止复用
   │
   └─[L4 验收门]  QC 目标一致性硬门(与第 109 轮桌面目标保真同形态)
                  + `ExecutionTrace.target_drift` 强信号(scan tool_call_log args_json)
```

## 2. 与既有机制的关系

| 既有 | 关系 |
| --- | --- |
| **SSRF 防护**(`url_safety`) | 关注「这个 end_point 是不是私网」—— 防止打到内网 metadata。本轮关注「这个 URL 是否属于用户指定的目标站点」—— 防止漂移到别的站点。两者职责互不重叠,各自独立运行 |
| **人类介入 HITL**(`human_assist`) | 4xxx = 「需要人帮忙完成」(验证码/短信/扫码等页面阻断)。本轮 6xxx = 「这件事本身越界」。两者段位区分,语义不混 |
| **自签名 TLS**(`LAEW_TLS_INSECURE`) | 让请求能到目标(基础设施)。本轮确保请求落到**正确的**目标(语义) |
| **桌面目标保真**(第 109 轮 QC) | 「用户要桌面软件,执行却落在网页版」。本轮把这一**单维度保真**扩展为通用**目标一致性**(站点/路径/应用通用) |
| **doom_loop → ask**(第 120 轮 loop_guard) | 「原地打转 → 升级到人」。本轮在更上游位置把无进展挡住:目标本身就不可解析 |

## 3. 与外部知识库的对齐

| 本轮设计 | 知识库出处 | 要点 |
| --- | --- | --- |
| L1 澄清门 | `专题/专题-第三轮-系统提示词工程真实体验深度分析.md:605`(pi) | 「Resolve discoverable facts by inspection. Use ask_user_question only for **user-owned choices** or material ambiguity that inspection cannot answer.」—— 「用户指哪个网站」属 user-owned choice,非 discoverable fact |
| L1 澄清在规划层而非执行层 | `专题/专题-Yolo目标意图识别与目标规划深度分析.md:421-435`(claude-code Plan Mode V2) | Phase 3 `Review → AskUserQuestion`,澄清位于写 plan / ExitPlanMode **之前** |
| RC-3 伪澄清单元 | `claudecode.md:1465`(`src/constants/tools.ts:36-46`) | `ALL_AGENT_DISALLOWED_TOOLS` 显式把 `AskUserQuestion` 禁用于子 Agent,「**防止递归与状态破坏**」 |
| L3 工具门:空 allowlist = 不限制 | `专题/专题-沙箱设计深度分析.md:1973-1994`(`NetworkAcl`) | `if !self.allowed_domains.is_empty() && !self.allowed_domains.contains(host)` —— 语义完全对齐 |
| L3 域名作为一等参数 | `专题/专题-第七轮-Web检索与网络访问深度对比.md:37-78` | WebSearch schema 直接带 `allowed_domains`/`blocked_domains`;WebFetch 与 WebSearch 是两个不同交互协议 |
| 无进展 → 升级到人 | `专题/专题-沙箱设计深度分析.md:891`(opencode `agent.ts:121`) | 默认 `"*": "allow"` 但 `doom_loop: "ask"` —— 唯一默认收紧的就是原地打转 |
| fail-closed → 问用户 | `专题/专题-权限管控深度分析.md:369` | 「解析失败 → 当作不安全 → 询问用户 → 多一次交互但不放过风险」 |

**知识库缺口**(本轮自研,无先例):

1. 从用户原文**机械抽取**目标锚点并跨 Agent 透传(外部 allowed_domains 全是静态配置或 LLM 传参)
2. **存活浏览器页面提示的锚点化**(把上一轮失败遗留页面标 ⚠ 禁止复用)—— 外部项目无多轮页面复用机制
3. QC 层**目标一致性**硬门(retryable=false)—— 外部 verifier 只判「任务是否完成」,不判「是否在做同一个任务」
