# 自签名证书 TLS 适配 —— 设计与解决方案

日期:2026-09-10

关联问题:IP + 自签名证书的 HTTPS API 服务无法访问(`error sending request for url (https://<IP>:<port>/.../v1/messages)`)

## 1. 问题分析

laew 的 LLM HTTP 客户端统一由 `src/llm/mod.rs::build_http_client()` 构造,
使用 `reqwest 0.12 + rustls 0.23`(纯 Rust TLS,无系统 OpenSSL 依赖)。
rustls 默认执行严格的证书链校验:

- 自签名证书不在系统/内置根证书库中 → `unknown issuer` 校验失败;
- 内部网关常给 IP 地址签发自签名证书(公共 CA 不为裸 IP 签发),必然触发该失败。

典型场景:企业内网 / 自建网关(如 `https://8.130.85.252:29003/Anthropic/v1/messages`)。
报错为 reqwest 的连接期错误,在 TLS 握手阶段即失败,与协议层(Anthropic/OpenAI)无关。

## 2. 需求

1. HTTPS + IP 地址 + 自签名证书的 API 服务可直接使用,无需用户手工导证书;
2. Windows / macOS / CentOS 7 / Ubuntu 等系统编译产物行为一致
   (rustls 纯 Rust 实现天然跨平台,不依赖各系统 OpenSSL / Schannel / Secure Transport);
3. 不全局放松 TLS 安全基线:公网域名 Provider 仍严格校验;
4. 提供显式开关,允许用户强制全局宽松或全局严格。

## 3. 方案设计

### 3.1 三级 TLS 校验策略

在 HTTP 客户端构造点(`build_http_client`)按环境变量 + endpoint 主机类型决策:

| 环境变量 `LAEW_TLS_INSECURE` | 行为 |
| ---------------------------- | ---- |
| `1` / `true` / `yes` / `on`  | 全局宽松:所有 endpoint 跳过证书校验(调试用) |
| `0` / `false` / `no` / `off` | 全局严格:所有 endpoint 严格校验(安全基线) |
| 未设置(默认)                 | 自动模式:endpoint 主机为 IP 地址(IPv4/IPv6)时自动跳过证书校验;域名主机仍严格校验 |

自动模式的理由:IP 直连的 HTTPS 服务几乎只能是自签名证书(公共 CA 不为裸 IP 签发,
私有 CA 证书也不会预置在客户机),因此对 IP 主机放宽不影响公网域名场景的安全基线。

### 3.2 实现位置

- `src/llm/mod.rs`
  - `build_http_client(end_point: &str)`:签名增加 endpoint 参数;命中宽松策略时
    调用 `reqwest::ClientBuilder::danger_accept_invalid_certs(true)`
    (rustls 后端下同时跳过证书链与主机名校验,reqwest 0.12 支持)。
  - `tls_insecure_for(end_point)`:三级策略判定(环境变量优先,IP 自动)。
  - `endpoint_host_is_ip(end_point)`:用 `url` crate 解析 host,
    `str::parse::<IpAddr>()` 判定 IPv4/IPv6(含 `[::1]` 字面量)。
- `src/llm/anthropic.rs` / `src/llm/openai.rs`:构造客户端时传入 `end_point`。
- 命中宽松策略时 `tracing::warn!` 输出一次提醒(不含 api_key 等敏感信息)。

### 3.3 跨平台一致性

- TLS 栈为 rustls(纯 Rust),证书校验行为不随 OS 变化;
  Windows(Schannel)/ macOS(Secure Transport)/ Linux(OpenSSL)差异被完全屏蔽。
- `danger_accept_invalid_certs` 为 reqwest 统一抽象,rustls 后端下
  Windows / macOS / Linux 行为一致。
- CentOS 7 等老系统无需升级系统 OpenSSL / CA 证书包。

### 3.4 安全边界

- 仅"跳过证书校验",仍走 TLS 加密传输,不降级为明文 HTTP;
- 自动模式只对 IP 主机生效,域名 Provider(公网官方 API)仍严格校验,防 MITM;
- 环境变量为显式开关,写入本设计文档,避免"隐式全局宽松"。

## 4. 验证方案

1. 单元测试:
   - `endpoint_host_is_ip`:IPv4 / IPv6 / 域名 / 非法 URL 四类用例;
   - `tls_insecure_for`:环境变量三态(unset / 1 / 0) × IP/域名组合矩阵。
2. 编译验证:`cargo build` + `cargo test` 全绿。
3. 集成验证:`./rebuild_restart_app.sh` 重新构建后,对 IP + 自签名证书的
   Provider 发起真实请求,确认不再报 `error sending request`。

## 5. 影响面

- 仅 HTTP 客户端构造路径(`llm/mod.rs` + 两个协议客户端构造器);
- 不动 Agent 循环 / 工具层 / 配置层(DB schema 不变);
- 无新增 crate(`url` 已是依赖,D9-7 SSRF 防护引入)。
