# Agent 系统提示词与工具架构重构 —— 设计与解决方案

## 1. 背景与目标

### 1.1 现状

当前工程（`laew`）的 Agent 架构存在几个结构性问题:

1. **系统提示词硬编码为字符串**:`AgentProfile.system_prompt` 是 `String`,直接由 `tool::builtin_system_prompt()` 生成,与工具定义散落在 `src/tool/mod.rs` 中,无法按协议(Anthropic/OpenAI)差异化,也无法为多 Agent 提供独立提示词。
2. **工具定义与 Agent 解耦不足**:`src/tool/` 是独立模块,定义了 `Tool` trait、`ToolRegistry` 与 `builtin_system_prompt()`,但工具本质上是 Agent 的能力延伸,应归属 `agent` 域。
3. **多 Agent 扩展口不完整**:虽注释预留了「多 profile 切换」,但 `AgentProfile::new()` 仍需外部拼好完整 `system_prompt`,没有提示词组合/分层能力。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 系统提示词独立模块 | 归入 `src/agent/system_prompt/`,职责单一 |
| 多协议差异化 | 同一 Agent 可根据当前 LLM 协议(Anthropic/OpenAI)渲染不同的系统提示词 |
| 多 Agent 预留 | 每个 Agent 持有独立的 `AgentProfile`,包含独立名称 / 提示词 / 工具集 |
| 工具归属 Agent 域 | `src/tool/` 整体迁移到 `src/agent/tools/`,`Tool` trait 与 `ToolRegistry` 不再独立成顶模块 |
| 零行为变更 | 现有默认 Agent(`LsmAgentEmergentWork`)行为、测试、CLI 交互完全兼容 |

## 2. 总体架构

### 2.1 重构后 `src/agent/` 目录

```
src/agent/
  mod.rs                  # Agent 核心循环(协议无关)
  profile.rs              # AgentProfile(名称 / SystemPrompt / ToolRegistry)
  system_prompt/
    mod.rs                # SystemPrompt 结构体 + 默认提示词工厂
  tools/
    mod.rs                # Tool trait + ToolRegistry + builtin_registry()
    bash.rs               # BashTool
    read.rs               # ReadTool
    write.rs              # WriteTool
```

### 2.2 模块职责

| 模块 | 职责 |
|------|------|
| `agent::system_prompt` | 系统提示词的组合 / 渲染 / 默认生成(含工具说明) |
| `agent::tools` | 工具抽象、注册表、内置工具实现 |
| `agent::profile` | Agent 身份档案,组合 `SystemPrompt` + `ToolRegistry` |
| `agent` (mod) | 持有 `Arc<dyn LlmClient>` + `AgentProfile`,驱动规划-执行循环 |

### 2.3 关键设计决策

#### 决策 1:SystemPrompt 持有工具引用,延迟渲染

`SystemPrompt` 不直接内嵌 `String`,而是持有「基础文本 + 工具列表引用 + 协议标记」。在 Agent 循环调用 `llm.complete()` 时,根据当前 LLM 客户端的协议类型渲染最终字符串。

```rust
pub struct SystemPrompt {
    /// 基础提示词(身份 / 行为准则 / 输出风格)
    base: String,
    /// 工具说明生成策略(默认内置工具)
    tools_hint: ToolsHint,
    /// 协议特定后缀(如 OpenAI 需要额外说明 tool calling 格式)
    protocol_tail: HashMap<Protocol, String>,
}
```

渲染时:`base + tools_hint.render() + protocol_tail(当前协议)`。

#### 决策 2:LlmClient 暴露协议类型

为让 Agent 在调用 `complete()` 前渲染协议特定的系统提示词,`LlmClient` trait 新增:

```rust
fn protocol(&self) -> Protocol;
```

`AnthropicClient` 返回 `Protocol::Anthropic`,`OpenAiClient` 返回 `Protocol::OpenAi`。这让 Agent 循环保持协议无关(不 match 具体类型),同时能按协议渲染。

#### 决策 3:工具模块整体迁移

- `src/tool/mod.rs` → `src/agent/tools/mod.rs`
- `src/tool/{bash,read,write}.rs` → `src/agent/tools/{bash,read,write}.rs`
- 删除 `src/tool/` 目录
- `src/lib.rs` 移除 `pub mod tool;`
- 所有 `crate::tool::*` 引用改为 `crate::agent::tools::*`

#### 决策 4:向后兼容的默认行为

- `AgentProfile::default_profile()` 行为不变:名称 `LsmAgentEmergentWork` + 默认系统提示词 + 内置工具
- 默认 `SystemPrompt` 不区分协议(协议 tail 为空),保证现有行为零变更
- 多 Agent 扩展通过 `AgentProfile::with_system_prompt()` 等构造器实现

## 3. 数据模型

### 3.1 SystemPrompt

```rust
use std::collections::HashMap;
use crate::config::Protocol;
use crate::agent::tools::ToolRegistry;

pub struct SystemPrompt {
    base: String,
    tools_hint: ToolsHint,
    protocol_tail: HashMap<Protocol, String>,
}

pub enum ToolsHint {
    /// 从给定的 ToolRegistry 动态生成工具说明
    Registry(std::sync::Arc<ToolRegistry>),
    /// 静态工具说明文本(默认内置)
    Static(String),
    /// 不附带工具说明
    None,
}
```

**渲染逻辑**:

```rust
impl SystemPrompt {
    /// 按协议渲染最终系统提示词
    pub fn render(&self, protocol: Protocol) -> String {
        let mut out = String::new();
        out.push_str(&self.base);
        out.push('\n');
        match &self.tools_hint {
            ToolsHint::Registry(reg) => {
                out.push_str(&render_tools(reg));
            }
            ToolsHint::Static(s) => out.push_str(s),
            ToolsHint::None => {}
        }
        if let Some(tail) = self.protocol_tail.get(&protocol) {
            out.push('\n');
            out.push_str(tail);
        }
        out
    }
}
```

### 3.2 AgentProfile

```rust
pub struct AgentProfile {
    pub name: String,
    pub system_prompt: SystemPrompt,  // 由 String 改为 SystemPrompt
    pub tools: ToolRegistry,
}
```

**构造器**:

| 构造器 | 用途 |
|--------|------|
| `default_profile()` | 默认 Agent,内置工具 + 默认提示词 |
| `new(name, system_prompt)` | 自定义名称与提示词,仍用内置工具 |
| `with_tools(name, system_prompt, tools)` | 完全自定义(多 Agent 扩展) |

### 3.3 Agent 循环变更

```rust
// 变更前
let completion = self.llm
    .complete(&self.profile.system_prompt, session.context(), &tool_defs, &meta)
    .await?;

// 变更后
let protocol = self.llm.protocol();
let system = self.profile.system_prompt.render(protocol);
let completion = self.llm
    .complete(&system, session.context(), &tool_defs, &meta)
    .await?;
```

## 4. 协议差异处理

### 4.1 当前差异(已封闭在 llm/ 层)

| 差异点 | Anthropic | OpenAI |
|--------|-----------|--------|
| 系统提示词传递 | 顶层 `system` 字段 | `messages` 中 `role: "system"` |
| 工具定义格式 | `tools[].{name, description, input_schema}` | `tools[].{type:"function", function:{...}}` |
| 元数据 | `metadata.user_id` | 无 |

### 4.2 系统提示词层新增差异

默认不引入差异(保持行为一致)。`protocol_tail` 为扩展口:

```rust
// 示例:未来可按需添加
let mut prompt = SystemPrompt::new("你是一个 Agent...");
prompt.set_protocol_tail(
    Protocol::OpenAi,
    "\n[OpenAI 兼容] 请严格使用 function calling 格式返回工具调用。",
);
```

## 5. 多 Agent 扩展路径

当前单 Agent,未来扩展步骤:

1. **定义多 Profile**:在 SQLite `agents` 表存储多份 profile(名称 / 基础提示词 / 工具集配置)
2. **切换命令**:TUI 内 `/agent switch <id>` 切换当前 Agent
3. **独立上下文**:每个 Agent 可绑定独立 Session(已通过 `Session` 支持)
4. **协议特定提示词**:通过 `protocol_tail` 为同一 Agent 在不同协议下微调

本次重构完成第 1、4 步的数据结构准备,第 2、3 步在后续迭代实现。

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 渲染后提示词变化影响模型行为 | 默认 `protocol_tail` 为空,`render()` 输出与原 `builtin_system_prompt()` 完全一致 |
| 循环引用(SystemPrompt 持有 ToolRegistry) | 使用 `Arc<ToolRegistry>` 弱引用,或延迟渲染时传入引用 |
| 迁移遗漏引用 | 全局 grep `crate::tool` 确认清零 |
