# CronCreate 工具定义
```json
{
    "name": "CronCreate",
    "description": "设置定时指令，在指定时间将任务加入执行队列，支持周期性重复任务与一次性提醒任务。

    采用用户本地时区的标准五字段 Cron 表达式：分钟 小时 每月日期 月份 星期。例如 \"0 9 * * *\" 代表本地时间上午9点，无需做时区转换。

    ## 一次性任务（recurring: false）
    适用于「在指定时间提醒我」「到时间执行某项操作」这类需求，任务执行一次后自动删除。
    需将分钟、小时、每月日期、月份设为固定值：
      “今天下午2点30分提醒我检查部署” → Cron表达式：\"30 14 今日日期 今日月份 *\"，recurring: false
      “明天早上执行冒烟测试” → Cron表达式：\"57 8 明日日期 明日月份 *\"，recurring: false

    ## 周期性任务（recurring: true，默认值）
    适用于「每N分钟」「每小时」「工作日上午9点」这类循环需求：
      \"*/5 * * * *\"（每5分钟执行一次）、\"0 * * * *\"（每小时执行一次）、\"0 9 * * 1-5\"（本地时间工作日上午9点执行）

    ## 任务时间错开原则（条件允许时，避开整分与30分节点）
    大量用户设置「上午9点」都会使用 `0 9`，设置「每小时执行」都会使用 `0 *`，会造成同一时刻大量请求集中访问接口。若用户给出的是大致时间，**请勿使用0分或30分**：
      “每天早上9点左右” → 改为 \"57 8 * * *\" 或 \"3 9 * * *\"（不要用 \"0 9 * * *\"）
      “每小时执行一次” → 改为 \"7 * * * *\"（不要用 \"0 * * * *\"）
      “大约一小时后提醒我” → 使用当前实际分钟数，不要取整

    仅当用户明确指定精确时间时，才可使用0分或30分（例如“准9点”“半点”“配合会议时间”）。若不确定，将时间前后微调几分钟，对用户无影响，还能有效分流请求。

    ## 持久化配置
    默认配置（durable: false）：任务仅存在于当前会话，不写入磁盘，会话关闭后任务立即消失。
    设置 durable: true 会将任务写入 .claude/scheduled_tasks.json 文件，重启后依然保留。**仅在用户明确要求任务长期生效、跨会话保留时开启**。大部分短时提醒（如5分钟后、一小时后提醒）仅保留在当前会话即可。

    ## 运行规则
    定时任务仅在交互终端空闲（无正在处理的查询）时触发。
    持久化任务会写入配置文件，会话重启后自动恢复；终端关闭期间错过的一次性持久任务，重启后会自动补执行。非持久化任务会随进程一同销毁。
    系统会在设定时间基础上增加小幅随机偏移：周期性任务最多延后周期时长的10%（最大延迟15分钟）；设定在0分、30分的一次性任务最多提前90秒执行。优先错开整分节点，分流效果会更明显。

    周期性任务最长有效期为7天，到期前会最后执行一次，随后自动删除，以此控制会话生命周期。创建周期性任务时，需告知用户该7天时限。

    本工具会返回任务ID，可用于调用定时任务删除工具。",
```
