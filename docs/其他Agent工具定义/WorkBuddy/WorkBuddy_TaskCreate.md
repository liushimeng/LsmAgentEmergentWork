# TaskCreate 工具定义
```json
{
  "type": "function",
  "function": {
    "name": "TaskCreate",
    "description": "使用此工具为当前的编码会话创建结构化的任务列表。这有助于跟踪进度、组织复杂任务，并向用户展示工作的全面性。
它还有助于用户了解任务的进度以及其请求的总体进度。

## 何时使用此工具

在以下场景中主动使用此工具：

- 复杂的多步骤任务 - 当任务需要 3 个或更多不同的步骤或操作时
- 非平凡且复杂的任务 - 需要仔细规划或多个操作的任务
- 计划模式 - 使用计划模式时，创建任务列表以跟踪工作
- 用户明确要求任务列表 - 当用户直接要求您使用任务管理时
- 用户提供多个任务 - 当用户提供一列要做的事情（编号或逗号分隔）时
- 收到新指令后 - 立即将用户要求记录为任务
- 当您开始处理任务时 - 在开始工作之前将其标记为 in_progress
- 完成任务后 - 将其标记为已完成，并添加实施过程中发现的任何新的后续任务

## 何时不使用此工具

在以下情况下跳过使用此工具：
- 只有一个单一的、简单的任务
- 任务微不足道，跟踪它没有组织效益
- 任务可以在不到 3 个简单的步骤内完成
- 任务纯粹是对话性或信息性的

请注意，如果只有一个微不足道的任务要做，则不应使用此工具。在这种情况下，直接执行任务会更好。

## 任务字段

- **subject**: 一个简短的、以命令式形式的可操作标题（例如，“修复登录流程中的身份验证错误”）
- **description**: 需要做什么的详细描述，包括上下文和验收标准
- **activeForm**: 任务 in_progress 时在微调器中显示的现在进行时（例如，“正在修复身份验证错误”）。这在您处理任务时显示给用户。

**重要**：任务描述必须有两种形式：
- subject: 描述需要做什么的命令式形式（例如，“运行测试”，“构建项目”）
- activeForm: 执行期间显示的现在进行时（例如，“正在运行测试”，“正在构建项目”）

## 示例

### 为多步骤功能创建任务
````json
{
    \"subject\": \"在设置页面添加深色模式切换\",
    \"description\": \"在设置页面实现一个切换组件，允许用户在浅色和深色模式之间切换。应将偏好设置持久化到 localStorage。\",
    \"activeForm\": \"正在向设置页面添加深色模式切换\"
}
````

### 为运行测试创建任务
````json
{
    \"subject\": \"运行测试并确保它们通过\",
    \"description\": \"执行测试套件并验证所有测试是否通过。在继续之前修复任何失败的测试。\"
}
````

## 提示

- 创建具体的、可操作的条目
- 将复杂任务分解为更小的、可管理的步骤
- 使用清晰、描述性的任务名称
- 创建任务后，使用 TaskList 验证您的任务列表
- 开始工作时使用 TaskUpdate 将任务标记为 in_progress，完成时标记为 completed
