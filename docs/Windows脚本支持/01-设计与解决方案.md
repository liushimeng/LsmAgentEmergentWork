# Windows 脚本支持（bat 移植）— 设计与解决方案

> 版本：2026-09-12　|　状态：已定稿并落地（含实测回归）
> 产物：根目录 `rebuild_restart_app.bat`（编译安装）+ `AutoTestAndDebug.bat`（一体化测试入口）
> 　　　+ `AutoTestAndDebug.windows.md`（Windows 版执行提示词）
> 上游：`rebuild_restart_app.sh` / `AutoTestAndDebug.sh` / `AutoTestAndDebug.md`
> 　　　（Linux 版，设计见 `docs/自动化测试与Debug一体化/01-设计与解决方案.md`）

---

## 1. 背景与目标

工程现有两条自动化脚本链路只支持 Linux/macOS（bash）：

| 脚本 | 职责 |
| ---- | ---- |
| `rebuild_restart_app.sh` | cargo 编译 → 产物拷贝到根目录 `./laew` → 版本哈希校验 → 远端对比 → PATH 提示 |
| `AutoTestAndDebug.sh` + `AutoTestAndDebug.md` | 随机选一个编程 Agent CLI（claude/codex/opencode），一次会话内完成「同步 → 感知 → 实测 → 方案 → 修复 → 收尾」一体化闭环 |

开发机为 Windows 11（`D:\MyLocalGit\LsmAgentEmergentWork`），Windows 上缺原生入口。本方案产出**同名 `.bat` 脚本**：

1. `rebuild_restart_app.bat` —— 与 `.sh` 等价的编译安装链（产物为 `laew.exe`）；
2. `AutoTestAndDebug.bat` —— 与 `.sh` 等价的一体化入口（选 Agent / 守门 / 防重入 / 后台脱离 / 日志体系）；
3. `AutoTestAndDebug.windows.md` —— Windows 适配版执行提示词（Agent 会话按它干活）。

设计原则：**bat 层只做确定性工程，智能决策全部留在 Agent 提示词层**（继承上游验证过的分工）。

## 2. 输入脚本分析（移植输入）

### 2.1 `rebuild_restart_app.sh` 处理流程

```
解析参数(--debug/--force/--help) → cd 脚本目录 → mkdir testReport
→ [--force] touch build.rs 穿透 cargo 增量缓存
→ cargo build --<profile> 2>&1 | tee testReport/build.log
→ install_bin：pgrep 检测运行中的 laew → 旧产物 mv 为 laew.old（绕开"运行中二进制不可覆盖"）
   → cp 新产物 → chmod +x → rm laew.old
→ 版本校验：git rev-parse --short=8 HEAD vs ./laew --version 解析出的 git 哈希
   不一致 → touch build.rs 强制重编 → 再校验 → 仍不一致 exit 1
→ 远端对比：5s 超时 git fetch --depth=1 → origin/main 哈希 vs HEAD
   （merge-base --is-ancestor 区分"本地待推送"与"远端领先"）
→ 展示 git log -1 + ./laew --version → PATH 解析命中提示
```

关键细节：哈希统一 `--short=8` 与 `build.rs` 对齐；`--version` 输出格式
`0.1.2 (build <时间>, git <hash>)`（`src/main.rs` 的 `VERSION_INFO`）。

### 2.2 `AutoTestAndDebug.sh` 处理流程

```
清理过期日志(find -mtime +30 -delete)
→ 三层定位提示词(脚本目录 → ./ → $PWD)
→ 守门条款检查(必须含「绝对禁止修改 `CLAUDE.md`、`AGENTS.md`」，否则 exit 2)
→ 工程结构预检(Cargo.toml + src/，否则 exit 4)
→ 选 Agent：AGENT_CLI 强制 > 可用候选(claude/codex/opencode)随机；无可用 exit 3
→ AGENT_SMOKE=1：前台冒烟(微型提示词 → Agent 应答 SMOKE_OK → 退出码透传)
→ 完整模式：
   启动日志头 + 运行索引(start)
   → nohup setsid bash -c "..." & 后台脱离：
       flock -n 防重入 → best-effort git pull --ff-only(timeout 60s)
       → run_agent_with_prompt(Agent 放开权限跑提示词)
       → 运行索引(agent_done/done)
   → 打印日志路径后立即返回(调用者不阻塞)
```

Agent 非交互调用方式（上游实测）：

| Agent | 命令 | 提示词传递 |
| ---- | ---- | ---- |
| claude | `claude --dangerously-skip-permissions -p "<prompt>"` | argv |
| codex | `codex exec --dangerously-bypass-approvals-and-sandbox -` | stdin |
| opencode | `opencode run --auto -m <provider/model> "<prompt>"` | argv（模型从 `~/.config/opencode/config.json` 推导） |

### 2.3 日志体系（两脚本共用约定）

- 单次运行日志：`logs/auto_testdebug_<Agent>_<时间戳>.log`（冒烟为 `smoke_testdebug_*`）；
- 运行索引：`logs/auto_run_index.log`，每次运行追加 `[时间] key=value ...` 单行
  （键：script/agent/event/pid/exit/log；事件：start/launched/agent_done/skip_locked/
  smoke_start/smoke_done/done/error_*）；
- 过期清理：保留 30 天（`LOG_RETAIN_DAYS` 覆盖），索引永久保留。

## 4. Linux → Windows 原语映射

| 能力 | Linux（sh） | Windows（bat） | 说明 |
| ---- | ---- | ---- | ---- |
| 脚本目录 | `$(cd "$(dirname ...)" && pwd)` | `%~dp0`（去尾 `\`） | 任意路径调用均定位根目录 |
| 时间戳 | `date +%Y%m%d_%H%M%S` | `powershell Get-Date -Format` | PS 输出区域无关 |
| 环境探测 | `uname -s/-r` | `ver` | 提示词层 OS 适配 |
| 进程检测 | `pgrep -x laew` | `tasklist /FI "IMAGENAME eq laew.exe"` | 仅提示不阻塞 |
| 覆盖运行中二进制 | `mv` 旧文件（inode 不受影响）再 `cp` | `move /y laew.exe laew.old.exe` 再 `copy` | Windows 同卷重命名运行中的 exe 合法；`del laew.old.exe` 失败静默 |
| `chmod +x` | 需要 | 不需要 | — |
| `tee` | `cmd 2>&1 \| tee log` | PS `StreamWriter` 边写文件边回显 | §5.2 |
| `timeout 60 <cmd>` | GNU timeout | PS `Start-Process` + `WaitForExit(60000)` + `Kill()` | 看门狗模式 |
| `flock -n` | 文件锁（进程退出自动释放） | `md` 原子建目录 + `pid.txt` + `tasklist` 存活探测 | best-effort，§6.3 |
| 后台脱离 | `nohup setsid bash -c &; disown` | PS `Start-Process -WindowStyle Hidden cmd /c <包装脚本>` | §6.4 |
| `find -mtime +N -delete` | find | `forfiles /D -N /C "cmd /c del @path"` | 多掩码各跑一遍 |
| 随机数 | `$(( RANDOM % n ))` | `%RANDOM%` | `set /a IDX=%RANDOM% %% n + 1` |
| 命令存在性 | `command -v` | `where <name>` | 多行命中即可用 |
| grep 精确串 | `grep -qF '...'` | PS `Select-String -SimpleMatch -Quiet -Encoding UTF8` | 中文守门串经 `[char]` 码构造（§8.2） |
| 提示词传 Agent | claude/opencode 用 argv | **三者统一 stdin**：`type 提示词 \| agent ...` | cmd 单命令行上限 8191 字符，提示词 ~16KB 必须走管道 |
| `export -f` 函数给后台子 shell | `export -f` | **bat 自重新调用**：后台进程再次运行自身并带 `--bg-run` 内部参数 | 环境变量天然继承 |
| `mktemp` | /tmp 模板 | `%TEMP%\laew_..._%RANDOM%%RANDOM%.md/.cmd` | — |
| `touch` | touch | `copy /b "build.rs"+,,` | 更新 mtime 穿透 cargo 缓存 |
| git 哈希/祖先判断 | `git rev-parse` / `merge-base --is-ancestor` | 相同（cmd 调 git） | `--short=8` 对齐 build.rs |

## 5. `rebuild_restart_app.bat` 设计

### 5.1 流程（与 .sh 逐步对齐）

```
参数解析(--debug/--force/--help;P4 模式,见 §8.3) → cd 根目录
→ [--force] touch build.rs
→ cargo build(PS StreamWriter:输出实时上屏 + 写 testReport\build.log,UTF-8)
→ install_bin：tasklist 提示运行中 laew.exe → 旧产物改名 laew.old.exe → copy 新产物 → del 旧
→ 版本校验：git rev-parse --short=8 HEAD vs「PS 正则从 laew.exe --version 提取 git <hash>」
   不一致 → touch build.rs 重编(日志追加) → 重装 → 再校验 → 仍不一致 exit 1
→ 远端对比：PS 5s 看门狗 git fetch --depth=1 → origin/main vs HEAD
   cat-file + merge-base --is-ancestor 区分「本地待推送」/「远端领先」(嵌套 if 实现,无 goto)
→ 展示 git log -1 + laew.exe --version → where laew PATH 命中提示 → 完成
```

### 5.2 编译日志的 tee 实现

cmd 无 tee；重定向到文件会丢失实时输出。采用 PS 管道一行式：

```powershell
$a = ($env:BUILD_APPEND -eq '1')                       # 0=覆盖 / 1=追加
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false
$w = New-Object System.IO.StreamWriter('<log>', $a, (New-Object System.Text.UTF8Encoding $false))
cmd /c 'cargo build <args> 2>&1' | ForEach-Object { $w.WriteLine([string]$_); $_ }
$w.Close(); exit $LASTEXITCODE
```

- `cmd /c '... 2>&1'` 让 stderr 在 cmd 层合并，PS 侧全部是普通字符串（规避 PS5.1 原生
  stderr 的 ErrorRecord 包装）；
- `ForEach-Object` 中 `$_` 回显到控制台（实时），`StreamWriter` 落盘（UTF-8 无 BOM）；
- `exit $LASTEXITCODE` 透传 cargo 退出码。

### 5.3 产物哈希解析与 profile 映射

- `laew.exe --version` 输出形如 `0.1.2 (build 2026-09-12 08:00:00, git 3e6c8018)`，PS 正则
  `git ([0-9a-zA-Z]+\)` 提取（`[0-9a-zA-Z]+` 同时覆盖十六进制哈希与 `unknown`）；
- **本机 cargo 不接受 `cargo build --debug`**：`--debug` 参数映射为 `CARGO_ARGS=`（空，
  cargo 默认即 debug），默认 `CARGO_ARGS=--release`；产物路径 `target\%PROFILE%\laew.exe`
  逻辑不变。

### 5.4 与 .sh 的差异点

| 差异 | 原因 |
| ---- | ---- |
| 产物为 `laew.exe` / 旧产物 `laew.old.exe` | Windows PE 命名；`.gitignore` 已补充 |
| `--help` 输出固定用法文本 | bat 无 sed；帮助文案内联 |
| `cargo build --debug` → 无 flag | 本机 cargo 版本不接受该 flag |
| 远端 fetch 看门狗用 PS | 原生兼容；不依赖 Git Bash 的 GNU timeout |
| 提示消息为英文 | §8.1 纯 ASCII 策略 |

## 6. `AutoTestAndDebug.bat` 设计

### 6.1 总体架构（自重新调用模式）

`.sh` 用 `nohup setsid bash -c "<整段后台脚本>"` + `export -f` 复用函数；bat 无法把函数导出给
新进程，改为**后台进程重新运行脚本自身**：

```
┌───────────────── 前台段（调用者所在控制台）─────────────────┐
│ 清理过期日志 → 定位提示词 → 守门 → 预检 → 选 Agent            │
│ → [AGENT_SMOKE=1] 前台冒烟：微型提示词 → Agent → 退出码透传    │
│ → [完整模式] 日志头+索引(start)                               │
│   写临时包装脚本 logs\bg_wrapper_<ts>.cmd：                   │
│       call "<本bat>" --bg-run >> "<运行日志>" 2>&1            │
│   PS Start-Process -WindowStyle Hidden cmd /c <包装脚本>       │
│   → 取 PID → 索引(launched) → 打印路径 → 立即返回 0           │
└────────────────────────────┬───────────────────────────────┘
                             ▼ 环境变量继承（LAEW_BG_AGENT/PROMPT/LOG）
┌───────────────── 后台段（隐藏 cmd，`--bg-run` 分支）──────────┐
│ 目录锁防重入 → 60s 看门狗 git pull --ff-only                   │
│ → 调用 :invoke_agent（type 提示词 | Agent CLI）                │
│ → 索引(agent_done/done) → 释放锁 → 包装脚本自删除              │
└──────────────────────────────────────────────────────────────┘
```

入口分发用**两段式 if**（第二行在 call 返回后才能取到新 `!ERRORLEVEL!`）：

```bat
if /i "%~1"=="--bg-run" call :bg_run
if /i "%~1"=="--bg-run" exit /b !ERRORLEVEL!
```

### 6.2 Agent 调用（`:invoke_agent`）

1. 生成临时执行脚本 `%TEMP%\laew_exec_<rand>.cmd`（内容为静态管道命令，规避 cmd 变量
   展开后管道符不再解析的陷阱）：
   ```bat
   @echo off
   pushd "<工程目录>"
   type "<提示词>" | "<Agent二进制全路径>" <参数...>
   exit /b %ERRORLEVEL%
   ```
2. Agent 二进制先经 `:resolve_bin` 解析为**带扩展名的全路径**（`where` 多行命中中优先
   `.cmd/.exe/.bat`，用 `%%~xb` 判扩展名，避免命中 npm shim 的无扩展名 sh 版本）；
3. 三种 Agent 的参数（Windows 统一 stdin 传提示词）：

   | Agent | 命令 | 说明 |
   | ---- | ---- | ---- |
   | claude | `claude --dangerously-skip-permissions -p` | `-p` 无参时从 stdin 读提示词 |
   | codex | `codex exec --dangerously-bypass-approvals-and-sandbox -` | 与 Linux 相同 |
   | opencode | `opencode run --auto -m <provider/model>` | 无位置参数时从 stdin 读；模型推导同 .sh（`%USERPROFILE%\.config\opencode\config.json` 的 `model` 字段，无 `/` 时补 `model/model`，缺省 `liusm191-server-model/liusm191-server-model`） |

4. 执行方式二选一：
   - **冒烟（前台）**：PS `StreamWriter` 包装执行临时脚本——输出实时上屏 + 追加运行日志
     （UTF-8），退出码透传；
   - **后台**：`call` 临时脚本，输出自然继承（包装脚本已把整段 stdout/stderr 重定向进运行日志）。

### 6.3 防重入（目录锁，best-effort）

`flock` 在 cmd 无等价物；利用 **`md` 的原子性**（目录已存在即失败）+ 标志变量平铺判断：

```
md logs\auto_testdebug.lock
├─ 成功 → 持锁执行
└─ 失败 → 读 pid.txt(存在时) → tasklist /FO CSV 解析该 PID 是否存活(无管道,§8.3)
    ├─ 存活 → bg_log「another instance is running」+ 索引 skip_locked → 退出 0
    └─ 不存活(陈锁) → rd 删除重建 → 持锁
结束 → rd /s /q 释放
```

工作进程 PID 取法：后台段内 PS
`(Get-CimInstance Win32_Process -Filter ('ProcessId=' + $PID)).ParentProcessId`
（PS 的父进程即持锁的 cmd 工作进程；WQL 的 `=` 用字符串拼接传入，避开 cmd 对 `=` 的
token 切分）。

**已知局限**（相对 flock 的降级）：进程被强杀后靠 PID 存活探测清陈锁，存在理论上的 PID
复用误判窗口；锁释放依赖正常路径 `rd`，崩溃后由下一次运行自愈。

### 6.4 后台脱离

- `Start-Process -FilePath cmd.exe -ArgumentList '/c','<包装脚本>' -WindowStyle Hidden -PassThru`
  创建**独立隐藏控制台**的新 cmd 进程：不弹窗、不随调用者控制台关闭而终止、可取 PID；
- 输出重定向写在包装脚本里（bat 写 bat，无跨 shell 引号转义问题）；
- 包装脚本尾部 `del %~f0` 自清理；异常崩溃可能残留无害的 `.cmd`（`logs/` 已 gitignore），
  主流程启动时用 `forfiles /D -1` 清理一天以上的陈旧包装（正在运行的 worker 只有分钟级
  年龄，不会被误删）。

### 6.5 日志与索引

- 与 .sh 同名同结构：`logs/auto_testdebug_<Agent>_<时间戳>.log`、
  `logs/auto_run_index.log`、`smoke_testdebug_*`；
- `forfiles /D -<LOG_RETAIN_DAYS>` 清理三种掩码（`*_testdebug_*` / `*_test_*` / `*_debug_*`）；
- `bg_log` 带时间戳前缀；前台模式双写（控制台+文件），后台模式只 echo（输出已被包装脚本
  重定向到文件，避免双写）；
- 编码：bat 自身输出行为 GBK（控制台原生）；PS 写入的段落（编译日志/冒烟 Agent 段）为
  UTF-8；ASCII 关键字（`SMOKE_OK`/事件名/键值）在两种编码下均可 grep（§8.4）。

### 6.6 退出码（与 .sh 对齐）

| 退出码 | 含义 |
| ---- | ---- |
| 0 | 正常（完整模式=已后台启动；冒烟=Agent 应答成功） |
| 1 | 提示词文件找不到 |
| 2 | 提示词缺守门条款 |
| 3 | 无可用 Agent / AGENT_CLI 强制指定不可用 |
| 4 | 工程结构预检失败 |
| 5 | 后台段缺环境变量（内部错误） |
| 64 | invoke_agent 未知 Agent / 提示词不存在 |
| 其它 | Agent 进程退出码透传（冒烟） |

### 6.7 环境变量

| 变量 | 取值 | 行为（与 .sh 一致者不注） |
| ---- | ---- | ---- |
| `AGENT_CLI` | claude\|codex\|opencode | 强制指定 |
| `AGENT_SMOKE` | 1 | 前台冒烟 |
| `CLAUDE_BIN` / `CODEX_BIN` / `OPENCODE_BIN` | 路径/命令名 | 二进制覆盖 |
| `OPENCODE_MODEL` | provider/model | — |
| `LOG_RETAIN_DAYS` | 天数（缺省 30） | — |
| `PROMPT_FILE_OVERRIDE` | 提示词路径 | **Windows 版新增**：存在时优先于内置候选（不存在则回落内置候选）；定向调试/单元测试用 |

### 6.8 提示词定位顺序（Windows 适配）

```
PROMPT_FILE_OVERRIDE(存在时) → <脚本目录>\AutoTestAndDebug.windows.md → <脚本目录>\AutoTestAndDebug.md
→ <当前目录>\AutoTestAndDebug.windows.md → <当前目录>\AutoTestAndDebug.md
```

`.windows.md` 优先：Windows 上自动选到适配版；删掉 windows 版则回落共享版（守门条款同样生效）。

## 7. `AutoTestAndDebug.windows.md` 提示词适配

以 Linux 版 `AutoTestAndDebug.md` 为基线（§0~§7 结构、硬约束、时间盒、终止条件全部保留，
**守门条款原文保留**），仅适配执行环境：

| 节 | Linux 版 | Windows 版 |
| ---- | ---- | ---- |
| §0 环境探测 | `uname -s && uname -r` | `cmd /c ver` / `systeminfo`；Agent 可用 PowerShell 或 Git Bash（后者提供 grep/sed/timeout/shuf） |
| §2 OS 适配过滤 | 跳过 Windows/macOS 专属主题 | **反转**：跳过 macOS/Linux 专属主题，**纳入** `125-Windows*`，跨平台保留 |
| §2 随机选条 | `ls ... \| shuf -n 6` | PowerShell `Get-Random` 或 Git Bash `shuf` |

## 8. 编码与 cmd 解析器策略（本项目最重要的踩坑产出）

> 本章结论来自本机 2026-09-12 的系统化实验（约 20 个最小复现用例），是 bat 移植能否
> 存活的分水岭；**后续维护这两个 .bat 前必读**。

### 8.1 文件编码：纯 ASCII（最终方案）

先后实验并**否决**了两个直觉方案：

| 方案 | 现象 | 否决原因 |
| ---- | ---- | ---- |
| UTF-8 + 第 2 行 `chcp 65001` | 小文件可用；中文密度升高后 cmd 的文件位置跟踪漂移——行被从中间腰斩执行（如把 `rem ...rebuild_restart_app.sh` 的尾部当命令）、`goto`/`call` 标签落点错位；偏移随 CJK 内容累积，**不可预测** | 解析器在代码页切换后按旧解码重算字节偏移，CJK 越多漂移越大 |
| GBK(ANSI) + 不切码页 | 小文件可用；复杂结构（括号块/管道/PS 一行式并存）后同样出现行腰斩 | cmd 的行缓冲按块读取，多字节字符跨界 + 特殊 ASCII 字节组合仍可失步 |

**结论：cmd.exe 对「结构复杂 + 含多字节字符」的 bat 没有可靠解析路径。两个 .bat 最终为
纯 ASCII（英文消息）+ CRLF 行尾**——这是所有实验中唯一零异常的形态。中文留在 `.md`
文档与提示词层（UTF-8），bat 中的中文文档指针写成 `docs/Windows*` 通配形式。

英文消息与「注释/文案中文」约定的偏离已在本文记录原因：**可靠性优先**——脚本消息面向
自动化日志与开发者控制台，不面向最终用户；中文语义完整保留在 `AutoTestAndDebug.windows.md`
与本文档。

### 8.2 中文守门串的运行时构造

守门条款必须匹配中文原文「绝对禁止修改 `CLAUDE.md`、`AGENTS.md`」，但 bat 内不能出现
中文。解法：PS 一行式用 `[char]` 码点在运行时拼出 Unicode 串再匹配：

```bat
powershell -NoProfile -Command "$p = [string]::Concat([char]0x7EDD,[char]0x5BF9,[char]0x7981,[char]0x6B62,[char]0x4FEE,[char]0x6539,[char]0x20,[char]0x60,'CLAUDE.md',[char]0x60,[char]0x3001,[char]0x60,'AGENTS.md',[char]0x60); if (Select-String -LiteralPath '<file>' -Pattern $p -SimpleMatch -Quiet -Encoding UTF8) { exit 0 } else { exit 1 }"
```

实测：对含/不含守门串的 UTF-8 提示词分别返回 0/1，完全可靠。冒烟提示词为英文
（断言串 `SMOKE_OK` 本就是 ASCII），无编码依赖。

### 8.3 cmd 解析器坑位清单（每条都有最小复现）

| # | 规则 | 现象 |
| - | ---- | ---- |
| P1 | **LF-only 行尾的 bat 标签全部失效** | `goto`/`call` 找不到标签、行错位执行；必须 CRLF |
| P2 | **for 块（≥3 行）内 `exit /b N` 丢退出码** | 块内以 `exit /b 2` 终止后 `cmd /c` 返回 0；两行块反而正常——不可依赖，统一「标志变量 + 循环后顶层退出」 |
| P3 | **带 `else` 的块内 `exit /b N` 丢退出码** | `if a ( ... if b ( ... exit /b 3 ) ) else (...)` 返回 0；无 else 的形状实测正常，但统一避免块内退出 |
| P4 | **块内管道使后续语句在子上下文执行** | `echo x \| findstr ... >nul && set Y=1` 在 for/if 块内时 `set` 只发生在子进程，父进程看不到；管道两端的 `&&`/`exit` 同理。解法：临时文件承接 + `findstr <file>`、`for /f` 解析 `%%~xb`、`tasklist /FO CSV` 列解析——全部无管道 |
| P5 | **块内 echo 文本含 ASCII 括号** | `)` 提前闭合块，其后文本被当命令（`此时不应有 xxx`）；中文全角括号安全但最终随 ASCII 策略一并弃用括号——**bat 文本零括号** |
| P6 | **块内引用动态值必须 `!VAR!`** | `%VAR%` 在块解析期展开（旧值）；需 `setlocal EnableDelayedExpansion` |
| P7 | **`if defined X > file echo Y` 的中置重定向不可靠** | 触发后续行解析异常；改为 `if defined X ( > file echo Y )` |
| P8 | **PS 命令行内 `=\"key=$PID\"` 的 `=` 被 cmd 吞** | WQL 过滤串变成 `ProcessId $PID`；改为 `('ProcessId=' + $PID)` 拼接 |
| P9 | **cmd 单命令行 8191 字符上限** | 16KB 提示词不能走 argv；统一 `type 提示词 \| agent`（stdin） |
| P10 | **npm shim 同时存在无扩展名 sh 文件** | `where` 第一命中可能是不可执行的无扩展名文件；`:resolve_bin` 按 `%%~xb` 优先 `.cmd/.exe/.bat` |
| P11 | **for /f 命令串内的 `=` 会吞掉后续参数** | `for /f ... in ('git rev-parse --short=8 HEAD')` 实际丢了 `HEAD`（报 Needed a single revision）；必须写成 `--short^=8` |
| P12 | **`find` 在 Git Bash 继承的 PATH 下被 GNU find 遮蔽；且管道首 token 不能是带引号路径** | `tasklist \| find /I ...` 误走 GNU find；改 `findstr /I`（System32 且无遮蔽）；带引号的 `System32ind.exe` 全路径作管道首元素会报「文件名语法不正确」 |
| P13 | **`git fetch --depth=1` 会把 `origin/main` 截成浅历史，破坏后续 `git pull --ff-only` 的合并基** | 本机实测：浅拉取后 `merge-base HEAD origin/main` 为空、`rev-list --count origin/main`=1；bat 的 `remote_hash` 已改为普通 fetch + 5s 看门狗；**上游 `rebuild_restart_app.sh` 同样存在此缺陷**（本轮未改 .sh，仅登记）；受影响仓库用 `git fetch --unshallow origin` 自愈 |

两个 bat 的文件头都有对应提醒注释；**改动后必须回归 §9 的测试矩阵**（全部路径可在
1 分钟内跑完，除真实 Agent 调用与编译外）。

### 8.4 日志编码模型（混合编码，务实取舍）

| 来源 | 编码 | 说明 |
| ---- | ---- | ---- |
| bat 自身 echo（日志头/bg_log/索引/控制台） | GBK | 控制台原生显示正常（中文 Windows 默认 cp936） |
| PS `StreamWriter` 段落（编译日志/冒烟 Agent 段） | UTF-8 无 BOM | `[Console]::OutputEncoding=UTF8` 保证子进程输出按 UTF-8 解码 |
| Agent 原始输出（后台模式直通重定向） | 原样字节（claude 为 UTF-8） | 与 .sh 行为一致 |

ASCII 关键字（`SMOKE_OK`、事件名、`key=value`）在两种编码下均可直接 grep；查看中文段落
用 `iconv -f GBK -t UTF-8`（bat 段）即可。Linux 侧 `.sh` 日志为 UTF-8——两平台日志编码
不同，属已知差异。

## 10. 已知限制与后续方向

1. **bat 消息为英文**（§8.1 的工程取舍）；
2. **目录锁非内核级**：PID 复用存在误判窗口（§6.3）；
3. **控制台代码页不还原**：脚本不切码页（纯 ASCII 无需），无副作用；
4. **git pull 看门狗的 Kill 不级联 ssh 子进程**：极端网络挂死可能残留 ssh 进程，属
   best-effort（与 .sh 的 timeout 行为一致）；
5. **`rebuild --force` 强制重编路径**未在真实 mismatch 下触发（正常流程版本即一致），
   逻辑与 .sh 同构；
6. **Windows Defender 实时扫描竞态**：新机首次编译时，`quote` / `zerocopy` 等 crate 的
   build-script 刚链接完成即被执行会被「拒绝访问 (os error 5)」拦截——这是 AV 扫描锁，
   **重跑一次即过**（实测第二次失败换了一个 crate、第三次通过）；根治需对
   `target\` 目录加 Defender 排除（需管理员，未自动执行）；
7. **禁止在 bat 运行期间编辑它**：cmd 逐行惰性读盘，中途改动会使后续行按漂移偏移执行；
8. 后续若引入 PowerShell 7+ 常驻环境，可将 bat 逐步升级为 `.ps1`（本方案刻意仅依赖
   系统自带 PS 5.1，零额外安装）。
