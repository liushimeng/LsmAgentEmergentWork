# WindowUse 多轮对话与 Agent 间通信增强 —— 设计与解决方案

> 2026-09-14 新增。基于 `docs/WindowUse桌面窗口操控Agent/01-设计与解决方案.md`(第 9 角色初版)增强。
> 目标:让 WindowUse Agent 具备**跨用户轮次的会话连续性**、**操作某个/多个软件的连续性**,
> 以及**与其他 Agent(SubAgent-Work / Main-Work)的结构化通信能力**。

## 1. 需求与现状分析

### 1.1 当前缺口

| 缺口 | 现状 | 影响 |
|------|------|------|
| **无跨轮窗口状态** | 每次 `WindowUseRunner::run_unit` 创建全新 `Session::new()`,不记得上次操作的 window_id / 控件路径 | 用户每轮都要重新描述「那个记事本窗口」,无法说「再向刚才的窗口输入一段」 |
| **无操作历史** | 控件路径缓存、动作历史不持久化 | 路径失效后无法回溯「上次哪个 path 有效」,无法做增量操作 |
| **Agent 间无直接通信** | 仅靠 `SubFlowInput.depends_on_outputs: Vec<String>` 传文本 | WindowUse 读到一段文本后无法直接「交给」SubAgent 处理,必须经 Orchestrator 中转 |
| **跨应用操作断裂** | 两个窗口间的「从 A 读 → 向 B 写」需拆成两个无状态 WorkFlow | 中间数据丢失,无法在 B 失败时保留 A 的读取结果 |
| **无窗口上下文注入** | 系统提示词是静态的,不携带「当前桌面状态」 | LLM 无法感知「用户刚才是操作哪个窗口」,容易误操作其他窗口 |

### 1.2 外部 Agent 参考(已调研 `docs/Agent源码调研/` 15 工程)

| 工程 | 借鉴点 | 借鉴方式 |
|------|--------|---------|
| **claudecode** | `SessionMemory` 会话摘要 + `ExtractMemories` 记忆提取 + `ForkedAgent` 上下文 fork | 引入「窗口会话状态」表,每次单元结束后快照窗口上下文;下一轮注入 |
| **claudecode** | `Task` 系统 7 种任务类型 + `ProgressTracker` 进度追踪 | 窗口操作任务可追踪进度(已枚举/已检视/已操作) |
| **deepseek-harness** | `ralph` 模式:每轮 fresh child + 文件系统承载状态 + ≤16384 字符结构化 handoff | 窗口状态作为 handoff 载体,跨单元传递 |
| **deepseek-harness** | `ContinuableSubAgent` 可续子代理 + `ContinuationManager` | 窗口操控支持「可续」模式:同一 window_id 多轮操作不重建上下文 |
| **openclaw** | `turn-interruption` 显式中断轮次 + 合成「被打断」user 消息注入下一轮 | 窗口操作被打断时,合成「上次操作到哪」消息注入下一轮 |
| **openclaw** | `Lane` 调度器 + `Command Queue` Turn 锁 | 多窗口并发操作时的互斥(避免同时操作同一窗口) |
| **pi** | `Session Backends` 多后端 + `resultEntryId` 预分配 | 窗口状态可持久化到 SQLite / JSONL 多后端 |
| **atomcode** | `ActiveChatRegistry` 实时同步 + `LiveViewHub` | 窗口状态变更可广播给其他 Agent |

### 1.3 设计目标

| 目标 | 说明 |
|------|------|
| **跨轮窗口状态持久化** | 每次 WindowUse 单元结束后,快照当前窗口上下文(最后操作 window_id / 有效 path / 操作历史)写入 SQLite;下一轮自动注入 |
| **窗口上下文注入系统提示词** | 系统提示词动态携带「当前桌面状态摘要」,LLM 无需用户重复描述即可继续操作 |
| **Agent 间结构化消息通道** | 引入 `AgentMessage` 消息类型,WindowUse 可直接向 SubAgent 传递「窗口数据 / 控件引用 / 操作结果」 |
| **跨应用操作连续性** | 支持「从 A 读 → 向 B 写」的端到端连续操作,中间状态在 WorkFlow 间传递 |
| **窗口操作历史回溯** | 记录每次 WindowAction 的 (window_id, path, action, result),失败时可回溯有效路径 |
| **幂等与安全** | 状态注入幂等(标记探测);路径失效时自动重新检视而非盲重试 |

```
WindowState (per session_id, 单条记录, 每轮覆盖更新)
  │
  ├─ 创建:首次 WindowUse 单元开始时(若不存在)
  ├─ 更新:每次 WindowAction 工具调用成功后(追加操作历史,更新最后 window_id)
  ├─ 快照:WindowUse 单元结束时(完整写入 window_state 表)
  ├─ 注入:下一轮 WindowUse 单元开始时(读取 → 写入 prompt)
  └─ 清理:Session 结束时(可选保留供下次恢复)
```

### 3.1 窗口状态模型 (`agent/window_state.rs`)

```rust
/// 窗口操作历史单条记录
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WindowActionRecord {
    pub timestamp: String,
    pub window_id: String,
    pub window_title: String,
    pub path: String,              // 控件路径 /0/2/1
    pub action: String,            // click / set_text / get_text / ...
    pub result_summary: String,    // 操作结果摘要(≤100字符)
}

/// 已知窗口快照(避免每轮重新枚举)
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WindowSnapshot {
    pub window_id: String,
    pub title: String,
    pub process_name: String,
    pub pid: u32,
    pub last_inspect_path: Option<String>,  // 上次检视的根路径
    pub known_controls: Vec<(String, String)>, // (path, role) 已发现的控件
}

/// 窗口会话状态(核心 —— 每 session_id 一条,跨轮持久化)
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct WindowSessionState {
    pub session_id: String,
    /// 最后操作的窗口(用户大概率继续操作它)
    pub last_window: Option<WindowSnapshot>,
    /// 最近操作历史(保留最近 10 条,防止膨胀)
    pub action_history: Vec<WindowActionRecord>,
    /// 已知窗口列表(最近一次 WindowList 结果缓存)
    pub known_windows: Vec<WindowSnapshot>,
    /// 用户自定义别名(如 "我的记事本" → window_id)
    pub window_aliases: HashMap<String, String>,
    /// 跨应用操作的中间数据(从 A 读到的文本,待写入 B)
    pub pending_data: Option<PendingData>,
    /// 状态版本(每次更新 +1,用于冲突检测)
    pub version: u64,
    pub updated_at: String,
}

/// 跨应用操作的中间数据
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PendingData {
    pub source_window_id: String,
    pub source_path: String,
    pub content: String,           // 读取到的文本内容
    pub target_window_id: Option<String>,  // 待写入的目标(可能还未打开)
    pub created_at: String,
}
```

pub struct WindowUseRunner {
    agent: Agent,
    db: Arc<Db>,
    max_iterations: usize,
    /// ★新增:状态管理器
    state_mgr: WindowStateManager,
}

impl WindowUseRunner {
    async fn run_unit_inner(&self, input: &SubFlowInput, session_id: &str, cancel: Option<&CancelToken>) -> Result<SubFlowOutcome> {
        // ★1) 加载窗口状态
        let mut win_state = self.state_mgr.load(session_id).await
            .unwrap_or_default();
        win_state.session_id = session_id.to_string();

        // ★2) 构造带窗口上下文的 prompt
        let mut prompt = input.to_user_prompt();
        let state_prompt = self.build_window_state_prompt(&win_state);
        if !state_prompt.is_empty() {
            prompt.push_str(&format!("\n\n【窗口会话上下文(系统注入,非用户输入)】\n{state_prompt}"));
        }
        prompt.push_str(WINDOW_USE_OPERATION_RULES);

        // ★3) 注入待处理的 Agent 消息(如有)
        if let Some(msg) = self.peek_agent_message(session_id, AgentRole::WindowUse).await {
            prompt.push_str(&format!("\n\n【来自其他 Agent 的消息】\n{}\n请基于此消息继续操作。", msg.hint()));
        }

        // 4) Agent 循环(现有逻辑)
        let mut sub_session = Session::new();
        sub_session.context_mut().push(ChatMessage::user(&prompt));
        sub_session.id = session_id.to_string();

        // ★5) 在工具调用回调中捕获窗口状态变更
        let state_mgr = self.state_mgr.clone();
        let sid = session_id.to_string();
        let (text, usage, mut trace) = match self.agent.run_session_cancellable(&mut sub_session, cancel).await {
            Ok((t, u, tr)) => (t, u, tr),
            // ... 现有早终止处理 ...
        };

        // ★6) 从 trace 中提取窗口状态变更,更新 win_state
        self.extract_window_state(&trace, &mut win_state);
        win_state.version += 1;
        win_state.updated_at = now();
        self.state_mgr.save(session_id, &win_state).await.ok();

        // ★7) 如果读到文本且 SubAgent 可能需要,发送 Agent 消息
        if let Some(pending) = &win_state.pending_data {
            self.send_agent_message(session_id, AgentRole::WindowUse, AgentRole::SubAgent,
                MessagePayload::WindowTextRead { ... }).await.ok();
        }

        // 8) 写 Agent-Memory(现有)
        // ...
    }

    /// 构建窗口状态注入 prompt
    fn build_window_state_prompt(&self, state: &WindowSessionState) -> String {
        let mut out = String::new();
        if let Some(w) = &state.last_window {
            out.push_str(&format!("上次操作窗口: {} (id={}, 进程={})\n", w.title, w.window_id, w.process_name));
            if let Some(p) = &w.last_inspect_path {
                out.push_str(&format!("上次检视路径根: {p}\n"));
            }
        }
        if !state.action_history.is_empty() {
            out.push_str("最近操作历史(新→旧):\n");
            for (i, rec) in state.action_history.iter().rev().take(5).enumerate() {
                out.push_str(&format!("  {}. [{}] {} → {} → {}\n",
                    i + 1, &rec.timestamp[11..19], rec.window_title, rec.action, rec.result_summary));
            }
        }
        if let Some(pending) = &state.pending_data {
            out.push_str(&format!("待处理数据: 已从 {}({}) 读取 {} 字符内容,待写入目标\n",
                pending.source_window_id, pending.source_path, pending.content.len()));
        }
        out
    }
}

### 3.8 跨应用操作连续性

对于「从 A 读 → 向 B 写」场景,设计两种模式:

**模式 1:单 WorkFlow 内连续操作(推荐)**
- Main-Work 把「读 A + 写 B」拆成一个 WorkFlow 的多个 steps
- WindowUse 在一个 `run_unit` 内完成全部操作(利用现有多轮循环)
- 中间数据保存在 `WindowSessionState.pending_data`

**模式 2:跨 WorkFlow 状态传递**
- WorkFlow A: WindowUse 读取,结果写入 `dep_outputs` + 更新 `window_state.pending_data`
- WorkFlow B: WindowUse 从 `window_state.pending_data` 取数据,写入目标窗口
- 通过 `depends_on` 保证顺序

## 4. 安全与边界

1. **状态注入幂等**:窗口状态消息带 `<<<LAEW:WINDOW_STATE>>>` 标记,`is_window_state_injected()` 探测,防止重复注入
2. **状态大小限制**:`WindowSessionState` 序列化后 ≤ 8KB(约 200 条操作历史),超出裁剪旧记录
3. **路径失效处理**:状态中的 path 仅作参考,工具调用失败时仍优先重新 WindowInspect
4. **权限隔离**:窗口状态按 `session_id` 隔离,不同 Session 不共享
5. **消息消费幂等**:`agent_messages` 表的 `consumed` 标记防止重复处理
6. **安全红线不变**:禁止无确认点击支付/删除/发送类按钮的规则仍然生效,状态注入不降低安全标准
