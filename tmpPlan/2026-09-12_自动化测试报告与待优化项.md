### 2.2 已知的 5 项失败（SIGINT 取消传播）

| 失败项 | 原因 | 严重度 |
|--------|------|--------|
| 取消后进程及时退出(15s 内) | Windows SIGINT 语义与 Linux 不同；mock --delay-ms 期间主线程阻塞在 read | P2 |
| 输出含「已取消」 | Windows 无 SIGINT 信号量机制，laew 的 ctrlc hook 未触发 | P2 |
| 退出码 130(实际 137) | Windows 进程被 TerminateProcess 硬杀，无 128+signal 惯例 | P2 |
| 总耗时 17s < 6s | 同上 | P2 |
| mock 仅收到 4 次角色请求 | 取消前未完成全链路 | P2 |

**结论**：这 5 项是 Windows 平台信号处理的已知差异，非 laew 逻辑 bug。Windows 无 POSIX 信号机制，ctrlc crate 的 handler 在子进程场景下行为与 Linux/macOS 不一致。**优先级 P2（平台适配），不影响核心功能。**

## 四、Prompt Router 机制问题与修复

### 4.1 路径问题

**问题**：`--prompt-router-file /tmp/xxx.json` 在 Windows 上失败，因为 Windows 无 `/tmp/` 目录。

**修复**：router 文件放在项目目录内（如 `testReport/router_xxx.json`），mock server 从项目根目录启动可正确加载。

### 4.2 UTF-8 BOM 问题

**问题**：PowerShell `Out-File` 默认写入 UTF-8 with BOM，Python json.load 报 `Unexpected UTF-8 BOM`。

**修复**：使用 `[System.IO.File]::WriteAllText(path, content, [System.Text.UTF8Encoding]::new($false))` 写入无 BOM 的 UTF-8。

### 4.3 工具 call_no 匹配逻辑

**发现**：SubAgent 的 call_no 是实例内相对序号（首调用=0），不是全局累计。router 中 `call_no:1` 对应首次 SubAgent 工具调用。
