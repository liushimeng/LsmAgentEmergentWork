- 决策 4:fleet_inspect.sh 不把 ISO8601 时间戳写入 JSON 行内(避免污染 diff),而是另写一行注释 `# captured_at: 2026-09-11T16:50:00+08:00` 追加到 JSONL 末尾——满足任务步骤 2「末尾追加时间戳」要求又不影响漂移对齐

## 四、风险与缓解

- 风险 1:fleet_inspect.sh 并发输出 JSON 行序非确定,xargs -P 多进程完成顺序随机,导致每次跑 baseline.jsonl 与 current.jsonl 行序可能不同,影响 diff 可读性
  - 缓解:在 `xargs` 前对主机名 `sort` 一次(`ls "$hosts_dir" | sort | xargs …`),并在 collect 函数内每条 JSON 行尾加 `\n` 但不加任何序信息;或更稳妥地——在 collect 内 `printf` 完不直接写,而通过 `awk 'NR==h{print}'` 后处理统一排序(取舍:选择更轻量的「collect 内不引入排序依赖,后续 diff 加 --speed-large-files 即可」)
- 风险 2:h3 sshd_config 修改用 `sed -i` 在不同 BSD/GNU sed 下语法差异(本机 GNU sed 支持 `-i` 无备参,但 macOS BSD sed 要求 `-i ''`)
  - 缓解:本任务在 Linux x86_64 + Ubuntu 环境,GNU sed 是默认;方案中明确写 `sed -i 's/原/新/'`;若 QC 阶段发现环境为 BSD,自动改为 `sed -i '' 's/原/新/'`
- 风险 3:历史 `tmpPlan/agent-test/dj06/` 已存在,新写 `dj06_real/` 时若 shell glob 误用(比如 `ls hosts/h*/` 命中两个目录的混合),会污染产物
  - 缓解:fleet_inspect.sh 与 gen_local_fleet.sh 均显式 `cd "$(dirname "$0")"` 切到脚本自身所在目录,确保 `hosts/` 解析到 dj06_real/hosts 而非 dj06/hosts
- 风险 4:`jq` 未安装时 `jq -c . current.jsonl | wc -l` 校验失败
  - 缓解:`jq` 在 Ubuntu/Debian 默认安装;若失败,fallback 到 `grep -c '^{' current.jsonl` 行数统计(5 行 JSON 每行都以 `{` 开头)
- 风险 5:drift_report.txt 中 `grep 'h3'` 默认是 Basic 正则,若 h3 行被 diff 拆到上下文 `@@ -1,5 +1,5 @@` 不含 h3 字段,可能断言失败
  - 缓解:在生成 drift_report 时用 `diff -u baseline.jsonl current.jsonl` 后,再前置一行 `=== sshd_config changed: h3 ===` 注释头,确保 `grep h3` 首行必命中;同时挑的 sed 修改点保证 h3 行本身必有差异
- 风险 6:并发进程数 -P 5 在 5 主机场景下其实就是串行,无法体现并发收益
  - 缓解:本任务为「离线等价物 + 演示」性质,不强调 wall-clock 收益;在报告第 3 章明确指出「-P 5 在 5 主机场景下并发数=主机数,效果等同全并发,但 xargs 的进程槽模型在主机数 > 并发数时才有节流价值」
